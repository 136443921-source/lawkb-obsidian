# 法条银行搭建建议方案（v1.0 · 2026-09-22）

> **一句话结论**：法条银行已从「法律法规库」更名成型（80 篇 / 10 域 / P0 缺口已补），当前最大短板不是"量"而是**元数据一致性治理**——frontmatter schema 三套并存、慈善法版本存疑、覆盖台账缺失。建议以「统一 Schema + 版本双证 + 覆盖台账」三件套收口，零成本优先。

---

## 一、跨对话演进复盘

### 1.1 更名与定位
- `法律法规库/` → `法条银行/`（用户 09-21 后更名）。
- **定位**：知识飞轮 / 文书起草 / LTI 门禁的**唯一本地法条权威源**。对外引用一律走本地，禁止凭记忆灌条文正文。

### 1.2 跨对话固化下来的设计原则（来自 memory 沉淀）
| 原则 | 当前落地情况 |
|---|---|
| 本地源引证铁律：`statute_text_pending:true` 一律拦截，未建库法规标「待回源」绝不冒充引证 | ✅ LTI 门禁已挂，但本地 schema 不统一拖累检索 |
| 绝不凭记忆灌条文，必须本地权威源 verbatim 回填 | ✅ 补全清单重申；部分节选文件未标节选范围 |
| 版本指纹 + 有效性标注（`sxx`/现行有效） | ⚠️ 字段名不统一（民法典用 `version_*`，慈善法用 `sxx`） |
| pkulaw（北大法宝）主源核验；元典 / 企查查为核填通道 | ✅ 民法典已双证一致 |
| 民法典后条号重排常态，新旧条号双检索 | ✅ 原则明确，落地靠人工 |
| 公众号转载法规禁止条号级引用 | ✅ 原则明确 |
| 积分治理→本地化停烧（`top_k` 是计费主杠杆） | ✅ P0 补完即停烧，缺口从 24 项收敛 |

### 1.3 最近一次实质工作（补全清单 09-21）
- 审计基准：`法律法规库/` 75 篇 → 对照 R-PI/R-HT/R-CF 域 + 19 张 `statute_text_pending` 待回填卡，得出 **24 项缺口（P0–P2）**，并给出零成本施工图。
- **现状核对**：P0 四项（保险法 / 消法 / 人损解释 / 技术合同解释）现已入库，库容升至 80 篇；贵州高院分项限额通知（本地司法文件）仍缺。

> ⚠️ **说明**：本轮 server 端历史对话检索未命中（09-15~09-22 区间 0 条），复盘依据以**本地沉淀产物（补全清单 09-21）+ 已固化的设计原则（memory）**为准，不依赖口头叙述。

## 二、09-22 实地核查：6 项问题

| # | 问题 | 证据 | 严重度 | 建议 |

| 1 | frontmatter schema 三套并存 | 民法典用 `version_*` 族；慈善法用 `sxx`+`version_mismatch`；指导案例用中文键（`标题/创建日期`）混英文键 | 🔴 高 | 统一为一套标准 Schema（见 3.3） |

| 3 | 覆盖台账缺失 | 补全清单第五部分建议的 `_本地法条银行_覆盖台账.md` 尚未生成 | 🟠 中 | 阶段 0 生成（见 3.6） |
| 4 | Dataview 路径失效 | 指导案例索引 `FROM "判例索引/..."` 仍是旧目录 | 🟠 中 | 改为 `法条银行/最高院指导案例/` |

## 三、建议方案

### 3.1 目录与分类标准（10 域 → 11 域）
沿用现有 10 域，新增 **`地方性法规·贵州`** 域，把"贵州省道交条例（节选）""贵州高院分项限额通知""贵州高院破产审查指引"等本地文件归入，与"国家法律/行政法规/司法解释"分层。

```
法条银行/
├─ 通用实体法/          民法典、公司法、刑法(节选)、道交法(节选)、保险法、劳动合同法…
├─ 通用法律法规/        著作权/专利/商标/反不正当竞争/个保/网安/数安/政府采购/税收/招投标/消法/光伏…
├─ 程序法/            民诉法、仲裁法、人民调解法…
├─ 司法解释/          道交解释一二、医疗损害、买卖合同、技术合同、人损、九民、执行异议之诉…
├─ 行政法律规章/       基金会条例、工伤保险、广告法、医药代表、民间非营利会计制度…
├─ 慈善合规类法律法规/  慈善法、公开募捐办法、信息公开办法、保值增值投资、境外NGO、公益捐赠、志愿服务…
├─ 医事法律法规库/      医师法、药品管理法、医疗事故处理条例、病历书写规范、疫苗管理法…
├─ 监管类/            取缔非法社会组织、社会组织评估、律师服务收费、民政部登记通知…
├─ 地方性法规·贵州/    【新增】贵州省道交条例、贵州高院分项限额通知、破产审查指引…
├─ 法律资讯周报/      周报 32–38 期
└─ 最高院指导案例/      指导案例索引 + 个案
```

### 3.2 文件命名规范（强制）
```
<法规全称>（<发文字号>）[·<版本指纹>][·<节选范围>].md
```
- 示例：`中华人民共和国慈善法（主席令第19号）·2023修正.md`
- 示例：`中华人民共和国道路交通安全法（主席令第47号）·节选·事故责任与赔偿专题.md`
- 禁止：无发文字号、无版本指纹、纯描述性命名。

### 3.3 统一 frontmatter Schema（两型）
**A 型 · 权威法规卡（本地权威源）**
```yaml
---
title: <法规全称>
type: statute
doc_no: <发文字号>            # 例：主席令第19号
effect_rank: 法律|行政法规|司法解释|部门规章|地方性法规
org: <制定机关>
effective_date: <YYYY-MM-DD>
sxx: 现行有效|已废止|即将生效   # 统一枚举，替换 version_mismatch 文案
source: <权威源URL或核填通道>
source_verify: 双证一致|待核验   # pkulaw/qcc 与本地末条施行日期一致性
retrieved_date: <YYYY-MM-DD>
scope: 全文|节选·<专题>          # 节选必须标范围
statute_text_pending: false       # LTI 门禁联动字段
aliases: [<常用简称>]
updated: <YYYY-MM-DD>
---
```

**B 型 · 资讯 / 案例卡**
```yaml
---
title: <标题>
type: digest|case
source: <官方链接>
maturity: 🌱种子|🌿成长|🌳核心
review_interval: 30
status: draft|active
updated: <YYYY-MM-DD>
---
```
> 指导案例索引统一改为英文键（`title/tags/type/...`），废弃中文键（`标题/创建日期`），Dataview 路径同步改新目录。

### 3.4 版本治理铁律
1. **双证一致**：`source_verify` 须 pkulaw/qcc 远程指纹 与 本地末条施行日期一致，否则 `sxx: 待核验`、`statute_text_pending: true`。
2. **`version_mismatch` 处置 SOP**：发现旧版（如慈善法 2016）→ 现行版另存为 `·2023修正` 置顶；旧版移 `法条银行/_archive/` **不删**，frontmatter 标注 `superseded_by`。
3. **禁止据疑本回填**：`sxx: 待核验` 的副本，LTI 与管线一律不得引用。

### 3.5 引用与回源规则（重申本地源引证铁律）
- 文书 / 卡片引用法条 → 优先命中 `法条银行/` 本地文件；命中不到 → 标 `statute_text_pending` 走 pkulaw / 元典 / qcc 核填，**核填完 verbatim 回填本地并置 false**。
- 民法典后条号重排 → 引用同时给新旧条号。
- 公众号转载法规 → 仅作线索，禁条号级引用。

### 3.6 覆盖台账 + 缺口滚动
- 生成 `_本地法条银行_覆盖台账.md`：字段 = 法规名 / 域 / doc_no / sxx / source / retrieved_date / 被引用卡数 / 缺口标记。
- 缺口 P0–P2 滚动（补全清单已列 24 项），**月度复检**：新法时效核验 + 配额熔断。
- 与知识飞轮 / LTI 接口：`statute_text_pending` 字段双向联动，取号不冲突（六-A 门禁）。
