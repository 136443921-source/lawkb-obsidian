# 红队出庭律师心智训练·思维轨迹

> 记录 2026-09-14 晚间至 09-15 凌晨，一场「红队出庭律师心智训练」的八节点演进链：心智诊断 → 留痕治理提分 → 外置化瘦身 → 路径修复 → 心智卡化与 DRAFT 门槛 → 编号与并发治理 → 收尾铁律固化 → 对齐活文档标准。
> 每个节点遵循决策档案契约：**决策点 / 考虑了什么 / 否决了什么 / 推翻信号 / 落点**。

## 背景触发

老强要求「复盘红队出庭律师心智模型，便于在模拟法庭上进行红蓝对抗」。连下多场指令：① 心智解剖 + 训练手册；② 手册做成备忘录存入 LawKB 并自动更新训练记录；③ 建 red_persona 心智卡 + 修悬空知识库声明 + 建文书防御要点目录 + 统一 wrap_output 签名；④ R4-R8 补 red_team 字段提分；⑤ 路径修复 R6/R7；⑥ 剩余 R4/R5/R8 去重瘦身 + 蓝队 lift；⑦ 对称化备忘录病灶表；⑧ 固化"回填状态栏"收尾铁律；⑨ 对齐法官活文档标准。实质是"如何把一个能预驳回攻击、可度量成长、可观测心智的红方参谋造出来，并沉淀进中枢"。

## 思维轨迹（决策演进链）

### 节点 1 · 诊断先行：8 处病灶必须 grep/ls 实测，不凭 SKILL 描述

- **决策点**：R1（无心智卡）/`R2`（悬空知识库声明）/`R3`（无外置文档）/`R4`（章节重复）/`R5`（埋点缺失）/`R6`（路径错）/`R7`（引用外置未做）/`R8`（冗余）一律 `grep`/`ls` 实测，禁止凭技能描述推断。
- **考虑了什么**：`R2` 声称"声明了知识库引用"但全文 `grep` 0 命中实体；`R6/R7` 所谓"路径"需先确认文件存在——三条都是**只有实地跑才能发现**的。
- **否决了什么**：否决"看 SKILL 描述觉得结构齐就放行"——描述与实体脱节正是 R 类病灶的本质。
- **推翻信号**：若后续 SKILL 结构与诊断时行号大幅漂移，本节点证据需重新采集。
- **落点**：8 处实证病灶表，全部附行号级证据，作为整轮训练的单一事实源。

### 节点 2 · 留痕治理优先于能力治理：补 red_team 字段 +13，但区分两类分

- **决策点**：把 7 场既有对抗记录的 `red_team` 字段补标（+13 分冲 M5），同时**显式区分"留痕治理分"与"真实能力分"**。
- **考虑了什么**：零成本提分（补字段、统一 `wrap_output(text, ai_participation, caller="红队出庭律师")` 签名）能快速把仪表盘拉到 M5，但红队**真实对抗场次（D1）并未增加**——这 13 分是治理分，不是能力分。
- **否决了什么**：否决"冲到 M5 就算完事"——成熟度是本体系唯一真值锚，把治理分当能力分汇报＝污染闭环（与蓝队 DEC-008 节点 2「埋点守真」同铁律）。
- **推翻信号**：老强确认某几场确为红队真实对抗 → 该场次从治理分转为能力分，D1 须同步上调。
- **落点**：红队成熟度 **76(M4) → 89(M5)**，但卡片头部须标注"M5 含留痕治理分，真实对抗场次待补"，写入技能踩坑「先拿结构分、再拿能力分」。

### 节点 3 · 外置化瘦身非删除：保护 300+ 全名链接

- **决策点**：`R8` 冗余瘦身、`R3/R6/R7` 外置文档，**一律"原样迁出"不删**，只改 SKILL 内的引用路径。
- **考虑了什么**：知识飞轮有 300+ 历史卡全名链接指向这些段落；硬删会断链。引用型修复必须**验证被引用物存在**（R1/F1 教训复用）。
- **否决了什么**：否决"删了清爽"——断链是不可逆信息损失，远大于冗余带来的阅读负担。
- **推翻信号**：若链接治理工具能批量重定向 → 本节点的"只迁不删"可放宽。
- **落点**：SKILL 从 987 行瘦身至 477 行（v2.4.0→v2.6.0），外置 5 份文档（攻击模式库/使用指南/红蓝对抗流程/执行细则-LTI/red_persona_v1），引用路径全部 `grep` 验证存在。

### 节点 4 · 路径修复须有实体：拒绝"版本记录写 ✅ 就是修好"

- **决策点**：`R6` 照蓝队三个外置文档做、`R7` 改一行路径，均**先 grep 确认目标文件存在再改**。
- **考虑了什么**：`R7` 本质是"引用了不存在的模板"同款风险；若核心能力里引用清单而清单不存在，就是 F1 断链。
- **否决了什么**：否决"版本记录标了 ✅ 就默认修好"——蓝队 DEC-008 节点 5 已证此判据须永久保留。
- **推翻信号**：无——此判据应永久保留为通用铁律。
- **落点**：R6/R7 实体核验通过（外置文档确在、路径确改），写入红队 SKILL v2.5.0 变更日志。

### 节点 5 · 心智卡 red_persona_v1 建立 + DRAFT 降级门槛（与蓝队节点 6 同逻辑）

- **决策点**：新建 `red_persona_v1.md`（攻击四维度 + L1-L4 档位 + 维度权重 yaml），`status: DRAFT` 却被 SKILL 要求「每次调用前必读」→ 设**转正门槛** + DRAFT 期间降级执行。
- **考虑了什么**：错的卡会被 100% 执行，风险大于少分；转正判据须有产物为证（至少 1 场真实对抗逐条对照攻击模式库）。
- **否决了什么**：否决"建了就用"——未校验资产强制使用是系统性风险（写入技能踩坑 #17）。
- **推翻信号**：⚠️ **与蓝队的关键差异**——蓝队心智卡已在第 4 场实战校验后转正 ACTIVE；**红队心智卡至今仍 DRAFT（缺真实对抗校验场）**，这是红队当前的 P0 待办，诚实标注不掩盖。
- **落点**：red_persona_v1 落位 `~/.workbuddy/skills/红队出庭律师/`，与 blue/judge/clerk 卡同构（五章对称）。

### 节点 6 · 编号与并发治理："看起来像≠核实过"

- **决策点**：`R4` 章节去重时，发现**并行 Edit 同一文件会静默丢第二处改动**（F7 章节缺失），改用 ripgrep 逐章验证；发现 `v1.4.0` 版本号已被占用，新版本改 `v1.5.0` 防重号。
- **考虑了什么**：声明"已修复 R4" vs 实际字节落盘是两回事；同文件多 Edit 必须串行或逐章核验。
- **否决了什么**：否决"Edit 返回成功就信它改完了"——静默丢改是最隐蔽的一类 bug。
- **推翻信号**：若中枢引入文件锁/写入队列 → mtime 手工检测可降级。
- **落点**：写入技能成熟度追踪三件套踩坑 #12（并发冲突）、#14（并行 Edit 静默丢）；红队 SKILL 版本链无重号。

### 节点 7 · 收尾铁律固化：fix_done 与状态栏割裂的教训

- **决策点**：出现 `fix_done: 8/8` 但病灶表状态栏整列 `⬜ 待修` 并存——根因是刷新脚本只重写两个标记区块 + 同步 frontmatter，**从不碰状态栏**。建通用脚本 `backfill_memo_status.py`（`--check` 一致性校验 + `--set` 行级回填 + dry-run + 写前备份），把"修复即回填状态栏"**固化进三件套 SOP 收尾步**。
- **考虑了什么**：老强只看表以为"啥都没修"，无法逐条追溯——这是比"忘了回填"更危险的**可追溯性断裂**。
- **否决了什么**：否决"脚本刷新完就算交付"——状态栏才是逐条追溯的单一事实源，必须同步回填。
- **推翻信号**：若备忘录改为结构化数据库存储 → 回填动作可自动化触发，无需手动 SOP。
- **落点**：红队备忘录 R1-R8 状态栏从 `⬜待修` 全部回填为 `✅ vX.X.0 已修`；三件套 SKILL 升 v1.5.0 含收尾铁律章。

### 节点 8 · 对齐法官活文档标准：补齐"活文档"骨架

- **决策点**：红队备忘录原缺法官活文档标准的 6 处骨架（标题含「（活文档）」/ 活文档说明块 / 带权重量表 / 六层现状快照 / 叙述性训练日志 / 改进路线图 / 使用维护），**对照法官范本补齐**，保留红队全部精华内容（解剖/弹药对照/五步法/评分卡/人机分工/蓝队对照）。
- **考虑了什么**：红队内容比法官标准还丰富，但骨架不统一会导致四方备忘录"可读性参差"，老强跨角色对比时认知负担大。
- **否决了什么**：否决"内容够好就不用改格式"——活文档的价值在于**可机读、可对照、可自动追踪**，格式即契约。
- **推翻信号**：若中枢引入统一渲染层 → 骨架可由渲染层补齐，源文件可只存内容。
- **落点**：红队备忘录结构对齐法官标准（改造 85 行全为增量骨架 + 去陈旧）；`backfill --check` 终验状态栏 8/8 与 `fix_done:8` 仍一致。

## 收敛结论

一场「训练红队」的诉求，实际走出的是**八步递进**：

```
① 实证诊断（不凭描述）
   → ② 留痕治理（区分治理分/能力分）
      → ③ 外置瘦身（只迁不删·护链接）
         → ④ 路径修复（先验证实体存在）
            → ⑤ 心智卡化（DRAFT 降级门槛）
               → ⑥ 编号并发治理（看起来像≠核实过）
                  → ⑦ 收尾铁律（修复即回填状态栏）
                     → ⑧ 对齐活文档（四方骨架对称）
```

四条可迁移判断：
1. **真值优先于分数**——留痕治理分与真实能力分必须分开标注，否则成熟度体系自毁（节点 2）。
2. **引用型修复必须验证被引用物存在**——R1/F1 的最大遗产（节点 3、4）。
3. **新建设产默认 DRAFT 并设转正门槛**——未校验资产强制使用的风险大于缺分（节点 5）。
4. **长文档/同文件多改动用 ripgrep 逐章核验，禁用静默丢改**——"看起来改了"不等于"字节落盘"（节点 6）。

红队成熟度演进：**76(M4) → 89(M5)**（含留痕治理分）；SKILL 477 行（v2.6.0）；心智卡 `red_persona_v1.md` **DRAFT 未转正**（与蓝队 ACTIVE 的关键差异）。详见 `知识飞轮系统/05-调用/红队心智模型与训练备忘录-2026-09-14.md`（活文档 · 89/100 · M5）。

## 推翻信号（整体）

- 老强确认某几场补标记录确为红队真实对抗 → 节点 2 治理分转能力分，D1 上调。
- 红队心智卡在真实对抗中校验通过、老强拍板转正 → 节点 5 DRAFT 升 ACTIVE（当前 P0 待办）。
- 中枢引入文件锁/写入队列 → 节点 6 的 mtime 手工检测可降级。
- 备忘录改结构化存储 → 节点 7 回填动作可自动化触发。
