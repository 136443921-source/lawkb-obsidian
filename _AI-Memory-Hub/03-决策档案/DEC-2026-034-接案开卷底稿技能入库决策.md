# DEC-2026-034 · 接案·开卷底稿技能入库决策

> **只记录方法论与治理事实，不含个案卷宗、案号、当事人姓名。**

## 一、背景

拟把外部文章提出的「诉讼案情分析助理」四步法接入数字分身系统。系统复盘结论：既有 `case-file-review` 已覆盖前两步半，
真缺口是「双列争议焦点」与「利弊三栏」，故采**轻量编排层**方案（新建 `intake-case-grid`），定位 CLM G0→G1。

**关键认知纠正**：曾判定「`case-file-review` 在 `skillOverrides` 无键＝未挂载＝源头没注入」，经四证复核为**误判**——
中枢呈批件（2026-10-29 已拍板 D1–D4）、技能主文件挂载声明、席位路由表、安装登记表 `disable=False` 均证明它
已挂 **L2 能力模块 · 席位调用**通道并实跑过。无 override 键仅表示**不走自动注入**。

## 三、理由

- **D1**：加键会推翻 2026-10-29 已拍板的 D1 决策、造成上下游挂不同通道、并让 57KB 重型技能抢自动路由（现 247 override 中仅 2 个 on）。**通道一致才是防 `RULE-060` 的正解**。
- **D2**：一个枚举值，改动面最小，`gate.gap_coverage` 等断言不受影响；从 schema 层堵死「缺料硬判」。
- **D3**：`skill_role_registry.yaml` 的 `default_role: meta` 与治理铁律 2/3 明确「未声明即 meta、漏声明→欠计是安全方向」，**不为登记而登记**，零写入。
- **D4**：验收只做了**材料子集**（未读 L0、未调案由 wiki、未回源法条、未解析全部卷宗）。**装机 ≠ 投产**，保留闸门，解闸须喂齐材料复跑。
- **D5**：官方 `doc_spec_gate.py` / `doc_spec_check.py` 经文件名层两次零命中 + 内容层只命中引用 + 全盘检索超时，**当前不可定位**；按 `RULE-053` 原文四判据自建等价校验实跑 ALL PASS，**不冒称官方脚本通过**；后续找回脚本须补跑。
- **D6**：两处实为**适用对象不同**（建工专属争点建议 vs 判项复核表；示例文本 vs 正文铁律），非同一栏正面冲突；修订既有生产技能文件属另一授权范围，本轮不动。
- **D7**：避免装机后 `field_ssot` 指向工作区造成悬挂引用；依 Fix-the-source **只改母版**，副本逐字节派发并记 MD5。
