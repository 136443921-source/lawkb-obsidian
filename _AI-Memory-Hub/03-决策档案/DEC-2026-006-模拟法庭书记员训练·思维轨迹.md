# DEC-2026-006 · 模拟法庭书记员训练·思维轨迹

> 记录 2026-09-14 晚间，一次「复盘书记员 → 建训练追踪 → 拍板剥离 → 沉淀入中枢」的完整思维演进链。
> 每个节点遵循决策档案契约：**决策点 / 考虑了什么 / 否决了什么 / 推翻信号 / 落点**。
> 本卡是 **RULE-TRAINING-WRITEBACK（训练记录回写铁律）** 的**首次完整应用样例**。

## 背景触发

老强提出"复盘模拟法庭书记员角色，想训练它"。此时书记员**在系统中并不作为独立角色存在**——职责挂在 QC-Controller 名下。整晚的演进，实质是"如何把一个不存在的席位造出来，并让它可被度量地成长"。

---

## 思维轨迹（决策演进链）

### 节点 1 · 先摸系统再说话，拒绝凭空给建议

- **决策点**：收到训练诉求后，**先读源码定位现状**，再决定给什么建议。
- **考虑了什么**：记忆中「书记员」在系统里似乎有定义，但角色归属不明。实地 grep 后发现：全库无独立书记员技能，职责写在 `QC-Controller/SKILL.md:37`，且 QC 同时握有"否决权和流程终止权"（同文件:43）。
- **否决了什么**：否决"直接输出一份通用书记员培训清单"——那会给出一堆**用不上的正确废话**。真正的病灶是结构性的：记分员兼裁判。
- **推翻信号**：若后续发现已有独立技能（grep 漏检），则节点 2 的诊断结论作废，退回"能力训练"路线。
- **落点**：诊断结论——**"现在的问题不是书记员不够聪明，而是这个位置根本没人坐"**。

### 节点 2 · 出解剖手册：五病灶 + 法定职责基线

- **决策点**：产出《模拟法庭书记员-心智模型解剖与训练手册 v1.0》，对齐既有红/蓝队手册格式。
- **考虑了什么**：法条基线必须**本地源实地核对**（不凭记忆灌条文），核对出民诉法 140/147/150、民诉法解释 47/49/131/261 共 10 条；同时发现宣布纪律台词引用的《法庭规则》14/17 条**本地库无全文**，按老强铁律标 `statute_text_pending` 而非当作已核验源。
- **否决了什么**：否决"为了让手册好看而保留《法庭规则》引用"——标 pending 会让手册显得不完整，但**标了 pending 才是诚实**。
- **推翻信号**：若《人民法院法庭规则》全文入本地库并通过核验，CK5 的 pending 标记即可消除（届时未消即属遗留 bug）。
- **落点**：手册 v1.0（含五病灶 CK1–CK5、六层心智栈、六项硬能力 C1–C6、10 维评分卡、方案 A/B/C）。

### 节点 3 · 要"可度量成长"→ 复用蓝红范式而非另起炉灶

- **决策点**：按老强"存 LawKB + 训练时自动更新记录"的要求，建**备忘录 + 追踪脚本 + 周刷新自动化**三件套。
- **考虑了什么**：蓝队(66)/红队(56) 已有完全同构基建（备忘录 + `*_maturity.py` + 周一自动化），直接复用可保证**跨角色分数可比**；五维权重与蓝红保持一致。
- **否决了什么**：否决"为书记员设计一套全新评分维度"——新维度看似贴合，实则**切断了与蓝红的可比性**，跨角色对照（谁拖后腿）就失效了。
- **推翻信号**：若书记员职责被证明与蓝红不同构到"五维无法表达"的程度，则允许另设维度，但需同步声明不可比。
- **落点**：`LawKB/知识飞轮系统/05-调用/模拟法庭书记员心智模型与训练备忘录-2026-09-14.md` + `clerk_maturity.py` + 周一 09:30 自动化（避让蓝队 09:20、红队 09:25）。

### 节点 4 · 首测 0 分：不只报数字，要翻译出可执行动作

- **决策点**：成熟度首测 **0/100**，判定为真实基线而非脚本 bug，并**追加设计「潜场补录池」双通道**。
- **考虑了什么**：26 份模拟法庭调用记录中提及"书记员"者 **0 份**、协同日志 0/32 条——脚本没坏，是这角色**从未被当独立角色留痕过**，恰与节点 1 诊断互证。但直接报 0 分毫无指导意义。
- **否决了什么**：否决"如实报 0 分就完事"——那是把诊断成本转嫁给老强。改为脚本额外统计**有笔录产出却未标注书记员的场次**，挖出 **5 场**（吊顶案 6658、雅菲案 6660 等），补一个 `clerk` 字段即可转正。
- **推翻信号**：若补录后分数仍未起，说明识别口径（正文关键词 / frontmatter 字段）有漏，需先修口径再看分数。
- **落点**：0 分报告的语义从"这技能没救了"变为"**补 5 个字段就能起分**"。

### 节点 5 · 拍板方案 A：先剥离结构，再谈训练

- **决策点**：老强拍板"打开 A"——书记员从 QC 剥离为独立技能。
- **考虑了什么**：三方案并列——A 独立成技能 / B 在 QC 内做双模隔离 / C 只补能力不动结构。判断依据是 **CK1 是身份冲突而非能力缺陷**：不剥离的话，中立性那一维永远打不上去。
- **否决了什么**：否决 **C（只补能力）**——"只是让一个身份错乱的角色话更多"；否决 **B**——双模隔离治标，兼任关系仍在，未来仍可能被"优化"合并回去（故在 A 中额外写死**结构性禁令**：严禁与 QC-Controller 合并或互相代行）。
- **推翻信号**：若未来证实"记录与评判必须由同一实体完成"才能保一致性，则 A 的结构需重评（届时以新决策覆盖本节点）。
- **落点**：新建 `模拟法庭书记员/SKILL.md` v1.0.0（245 行）；QC 升 v1.2.0 纯总闸；主控升 v1.6.1 完成 ②③ 台词归位；法官技能加"台词归位"注记；署名 `书记员：QC-Controller` → `〔书记员姓名〕` 共 6 处。成熟度 **0 → 8**（D5 2/5）。

### 节点 6 · 训练成果入中枢：从偏好升格为铁律

- **决策点**：老强要求"训练记录属于可复用方法论 + 项目状态，按共享记忆协议**应进中枢，应成为的铁律**；训练对话应沉淀为思维轨迹卡"→ 建 **RULE-TRAINING-WRITEBACK** 并写入**协议第七条**，同时落 WF-033 / PROJ-002 / 本卡三件套。
- **考虑了什么**：PREF-007 已在偏好层写了"训练记录须回写中枢"，但**偏好卡只对读卡的 AI 可见**，权威层（协议/规则）才能强约束所有 AI；且 PREF-007 只讲"要回写"，没讲"**训练对话要沉淀为思维轨迹**"。
- **否决了什么**：否决"沿用 PREF-007 一张卡够用"——重蹈 DEC-2026-005 节点 2 的教训（老强主动要求进协议层）；也否决"把训练过程写成普通日志"——**结论会随版本失效，否决理由与推翻信号才长期有效**。
- **推翻信号**：若老强改口允许训练记录只留业务目录，则本铁律降级为建议（RULE 卡已写明）。
- **落点**：`00-全局规则/RULE-TRAINING-WRITEBACK-…md` + 协议第七条 + 修订日志 + PREF-007 加 `superseded_by` 指引；新建 WF-033 / PROJ-002 / 本卡；更新三处索引。

### 节点 7 · 首场实战后 D2 只拿 4.2/25：改数字不如讲清口径

- **决策点**：老强"跑一场 6658 案实战，让书记员真出一次三件套，D2 那 25 分才拿得踏实"。跑完后 D2 从 0 涨到 **4.2/25**（1/6 场带台账），与"拿 25 分"的预期落差很大——要不要调整计分口径让数字好看？
- **考虑了什么**：D2 是**比率维度**（带台账记录数 ÷ 总记录数）。分母 6 场中有 5 场是**追认转正**的历史庭审，当时书记员尚未独立，**从未产出台账**。若把追认场次剔出分母，则 D2 = 1/1 = 满分 25，数字立刻好看。
- **否决了什么**：**否决"剔除追认场次以美化分母"**——追认场次确实没台账，这是**真实欠账**；把它们剔出分母等于用口径技巧掩盖"历史 5 场庭审都没有证据台账"这一事实，与节点 4「分数不能撒谎」自相矛盾。也否决"就此把 D2 判为失败"——实战场次台账率实为 **1/1 = 100%**，能力本身达标，低分只是覆盖率问题。
- **推翻信号**：若后续追认场次被**补出真实台账**（而非补字段），则其计为满分具备事实基础，届时本判断的"欠账"前提消失，应据实重算。
- **落点**：脚本增补 **D2 拆分口径**行——`实战场次台账率 1/1（100%）；追认场次 0/5`，并注明"追认场次计入分母系如实反映历史欠账，补 `evidence_ledger` 可提分但**不等于新增实战能力**"。本场产出：三件套（自评 98/100）+ 调用记录（带 `evidence_ledger`）；PROJ-002 状态、CK4 病灶、下一步、对照表同步更新。

## 收敛结论

一次"训练某个技能"的诉求，实际走出的是**四层递进**：

```
① 诊断结构（这个位置有没有人坐）
   → ② 造出位置（角色剥离四步法）
      → ③ 装上仪表（双通道采集 + 五维成熟度）
         → ④ 沉淀进中枢（三件套 + 思维轨迹铁律）
```

三条可迁移判断：
1. **结构问题优先于能力问题**——角色身份冲突不解决，训练再多也是白训。
2. **0 分报告必须配可执行动作**——否则就是把诊断成本转嫁给用户。
3. **偏好层不够，要进权威层**——凡"必须"级约束，应写入协议/规则卡并让偏好卡指回它。

## 推翻信号（整体）

- 老强改口训练记录可只留业务目录 → 节点 6 的铁律降级。

- 书记员与 QC 被证实必须合并 → 节点 5 的方案 A 作废，CK1 需重新定义。
