# DEC-2026-007 · 模拟法官心智训练·思维轨迹

> 记录 2026-09-14 晚间，一场「模拟法官心智训练」的三场次演进链：从 LTI 五维 QC → 卷宗证据联动 → 多域竞合研判 → disputeFocus 驱动要件 → 红蓝对抗接入法官心智 → jsdom 无头验证收口。
> 每个节点遵循决策档案契约：**决策点 / 考虑了什么 / 否决了什么 / 推翻信号 / 落点**。
> 本卡是 **RULE-TRAINING-WRITEBACK（训练记录回写铁律）** + **协议第七条** 在「模拟法官」技能上的完整应用样例（继 DEC-2026-006 书记员之后）。

## 背景触发

老强把「AI 模拟法官 / 庭审主持中台」作为长期训练对象，当夜连下三场训练指令：① LTI 五维 QC 前端校验器 + 卷宗证据编号联动；② 路B 重 agent（多域竞合深度研判）+ disputeFocus 驱动要件 + 客观 eval 套件；③ 红蓝对抗推演接入法官心智。实质是"如何把一个可裁判、可对抗、可度量成长的法官智能体造出来，并沉淀进中枢"。

## 思维轨迹（决策演进链）

### 节点 1 · 先定红线边界再动手（R2 铁律前置）

- **决策点**：模拟法官全部产出强制【候选·待人工确认】，AI 只给候选推理、绝不下终局 verdict。
- **考虑了什么**：继承自用户级 R2 安全铁律（AI 只给候选，终局由老强拍板）；沿用既有 LTI 五维 QC「REJECT=0 才准交付」门禁作为质量闸门。
- **否决了什么**：否决"AI 直接出裁判结论/合议庭意见"——违反 R2，是老强一贯红线；即便判断再自信也不替人下判。
- **推翻信号**：若老强改口允许 AI 输出终局裁判结论，则本节点的 R2 标注约束降级。
- **落点**：`lti_qc.js` 五维门禁（R/L/C/T/P）+ 全链路【候选·待人工确认】标注贯穿。

### 节点 2 · LTI 五维 QC 移植为前端纯函数（不读磁盘源）

- **决策点**：把 `_LTI工具/lti_verify.py`（依赖本地法条源文件）移植成前端 pure-function 校验器，校验**生成物 checksum** 而非 fetch 源文件。
- **考虑了什么**：前端运行环境无磁盘访问能力；保留「REJECT=0 才准交付」语义不丢；实测覆盖 R1–R4 / L1–L4 / C301–C304 / T1–T3 / P1–P4。
- **否决了什么**：否决"前端 fetch 本地法条库做源核验"——浏览器沙箱不可达本地库，且会泄露源路径；否决"只校验文本不含法条"——失去 LTI 真意。
- **推翻信号**：若中台改为服务端架构（有合法源访问通道），可重新评估源核验方案，届时降级为本地校验 + 服务端双轨。
- **落点**：`lti_qc.js`（UMD，`window.LTI_QC` + Node 可测）；`test_harness.js` 15/15。

### 节点 3 · 卷宗/证据编号做成双向真实联动（非假静态源）

- **决策点**：要件涵摄 fact 框引用「证N」→ chip 显示卷宗出处；证据抽屉写、事实框读，localStorage 持久化 → QC T2 溯源校验。
- **考虑了什么**：早期方案用假静态证据源，实测无法溯源、QC T2 校验空转；双向联动让证据抽屉成为事实框的唯一真相源。
- **否决了什么**：否决"静态写死证N–卷宗映射表"——那是假数据，违反 LTI 溯源铁律，且换案即失效。
- **推翻信号**：若接入真实卷宗 OCR / 办案系统 API，可替换抽屉后端，但 chip 联动契约不变。
- **落点**：`EVIDENCE_REG` + `renderFactWithChips`（证N chip 显卷宗出处）+ QC T2 校验。

### 节点 4 · 多域竞合研判：矩阵键序规范化 + 短关键词命中

- **决策点**：`analyzeConcurrence` 用 7 域分类法 + 竞合/先决/牵连/吸收/排斥关系矩阵；主路径用「域优先级契约法」（合同优先）兜底，全 R2 标注。
- **考虑了什么**：初版用整句包含匹配 → 解析为空；关系矩阵键序 `a|b` vs `b|a` 漏配 → 规范化**排序键**统一；实测「吊顶质量不合格 + 违约 + 侵权」→ 识别违约责任 ↔ 过错侵权责任**竞合**（引用民法典 186 条择一主张）。
- **否决了什么**：否决"整句语义相似度匹配"——重、慢、不可控、不可回归；否决"只报域不报关系"——失去竞合研判的核心价值。
- **推翻信号**：若引入 LLM 语义层做意图识别，可升级匹配，但矩阵与输出契约不变。
- **落点**：`multidomain_analyzer.js`；concur 抽屉端到端（候选域 + 竞合关系 + 第186条建议 + 主路径同步 Path B）。

### 节点 5 · disputeFocus 驱动要件：删引擎 stub，以动态模型为单一事实源

- **决策点**：`resolveDisputeFocus` 用短关键词映射 → 候选法条；采纳即驱动涵摄面板并持久化 `S.disputeFocus`；**删除引擎 civ_1165 stub**。
- **考虑了什么**：引擎 stub 被 `dynamic_models.json`（更丰富的 4 要件 + 过错推定模型）覆盖 → 仅填 e1–e3 留 e4 未满足 → 误判 `pending-burden`；实测算例暴露此 bug。
- **否决了什么**：否决"保留引擎 stub 并手动合并两源"——双源必漂移，违背单一事实源原则，且每次 dynamic 更新都要手工同步。
- **推翻信号**：若 dynamic_models.json 结构变更（字段语义调整），需同步引擎加载/合并逻辑。
- **落点**：`subsumption_engine.js` 新增 `resolveDisputeFocus` + `buildFromDisputeFocus`；`eval_suite.js` 扩至 39 项断言。

### 节点 6 · 红蓝推演接入法官心智作为参与智能体（打通两张皮）

- **决策点**：`judge_mind.js` 对每轮攻防做心证判定 + 整场一键裁决 + 拟裁判要旨（候选）+ 回写心证档案 `S.xinZheng`。
- **考虑了什么**：法官心智抽屉（裁判视角）与红蓝战情面板（律师攻防）原是两张皮；jsdom eval 中 `JUDGE_MIND` 裸标识符不在 Node 全局 → 改为 `global.JUDGE_MIND` + `window.JUDGE_MIND` 双轨；函数提取用「独占 `\n}` 结尾」正则精确抠真实源码。
- **否决了什么**：否决"法官心智只做旁观打分不回写"——不回写则训练无累积；否决"复制一份法官逻辑进推演脚本"——双份必漂移。
- **推翻信号**：若推演数据结构（`S.assault3.rounds` 字段）重构，需同步 `judge_mind.runTrialJudge` 的解析层。
- **落点**：`judge_mind.js` + `renderAssault3` 每轮内嵌「⚖️ 法官心证」+ `renderWarroom` 拟裁判要旨块 + `test_judge_trial.js` 10/10。

### 节点 7 · 用 jsdom 无头校验替代浏览器手点（委托验证）

- **决策点**：老强原建议"浏览器手动点一遍 confirm 交互"，改为 jsdom 无头 harness 挂载真实 HTML 跑全链路；老强明确"你来处理"。
- **考虑了什么**：jsdom 加 `url` 才启用 localStorage；不跑整 app `init()`（防 null 崩）+ `getElementById` stub 兜底；精确匹配定义段脚本（避免抓到调用段）；多套件分工：15/15 回归 + 39 项 eval + 10/10 推演。
- **否决了什么**：否决"依赖人工点验"——不可回归、不可累积、换人即失忆；否决"直接 eval 整 app 脚本"——`init()` 缺元素必崩。
- **推翻信号**：若引入真实浏览器 E2E（如 playwright），可升级为可视化回归，但无头 harness 仍作 CI 快通道。
- **落点**：`test_harness.js` 15/15 + `eval_suite.js` 39/39 + `test_judge_trial.js` 10/10，全绿交付。

## 收敛结论

一场「训练模拟法官」的诉求，实际走出的是**六步递进**：

```
① 门禁前置（R2 + LTI 五维 QC）
   → ② 源真联动（卷宗证据双向真实，非假静态）
      → ③ 多域研判（竞合矩阵 + 契约法主路径）
         → ④ 焦点驱动（disputeFocus → 要件，单一事实源）
            → ⑤ 推演接入（法官心智作为参与智能体，打通两张皮）
               → ⑥ 无头验证（jsdom 替代手点，可回归可累积）
```

三条可迁移判断：
1. **单一事实源优先于双源合并**——引擎 stub 被动态模型覆盖即漂移，删 stub 才是正解（节点 5）。
2. **真联动优先于假静态**——证据/卷宗必须双向真实写入，否则溯源校验空转（节点 3）。
3. **可回归校验优先于人工点验**——无头 harness 把"老强手点"变成可累积资产（节点 7）。

模拟法官成熟度三场次演进：**~90 → ~93（第一场）→ ~95（第二场）→ ~96（第三场，折算综合）**，详见 `PROJ-模拟法官心智成熟度备忘录.md`。

## 推翻信号（整体）

- 老强改口允许 AI 下终局裁判 → 节点 1 的 R2 红线降级。
- 中枢被新事实源取代 → 整套回写链路重指新源（以 DEC-2026-003 的替代决策为准）。
- 推演数据结构或 dynamic_models.json 结构重构 → 节点 5/6 的解析层需同步更新。
