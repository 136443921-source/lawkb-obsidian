# 🩺 医院法律顾问卡族拆卡 · 卡型按内容性质五型分流，不硬套审判要件卡八段格式

## 背景

- 源书《医院法律顾问与医疗纠纷解决》（`知识库/医法知识库/医院法律顾问与医疗纠纷解决/`，共 19 章，25KB~108KB）待按 [[WF-026-审判要件卡拆卡流水线]] 拆卡入轮。
- 该书与 WF-026 的既定源材料（法院《类案审判要件指南》类 PDF）**性质不同**：WF-026 拆的是法院视角"该怎么判"的正向裁判规则；本书讲的是"医院该怎么合规、顾问该怎么干"的**实务操作**。
- WF-026 红线明载：「审判要件卡 ≠ 要件映射卡」，**绝对不把审判要件内容塞进 `lti_element_cards.json`**——语义污染是明令禁止的。硬套八段（裁判规则/构成要件与举证/抗辩与但书/来源与地域效力…）会让本族卡在语义上失真。

## 候选方案

- **A｜严格按 WF-026 八段格式，统一建「审判要件卡」**
  - 弊：源书八成内容不是裁判规则，"构成要件与举证""抗辩与但书"两段大量空转，属**语义污染**。
- **B｜一律建「实务规则卡」，不细分卡型**
  - 弊：本书含完整操作流程（调研四步法、识别四法）与量化锚点（三维评分、红橙黄蓝分级），与纯"实务判断"不同质，检索颗粒度过粗。
- **C｜按内容性质分流卡型** ← 拍板
  - 利：卡型与内容同质，检索与调用精度最高；流程型内容有 `操作指引卡` 承载，量化型有 `裁量尺度卡` 承载。
  - 弊：需预分配 5 种卡型，建卡时多一步判型。

## 结论（选项 C，2026-09-24 老强拍板）

**五型分流口径**，落地在 `06-沉淀/裁判规则库/医疗损害责任纠纷/医院法律顾问实务/`：

| 卡型 | 用途 | 骨架 | 首批数量 |
|---|---|---|---|
| 规范要点卡 | 规范体系、范围、结构梳理 | 规范要点 → 实务判断 → 法条依据 → 翻车标本 | 2 |
| 合规审查卡 | 合规红线与审查要点（含翻车标本） | 合规红线 → 审查要点 → 攻防要点 → 翻车标本 | 3 |
| 实务规则卡 | 职业定位、策略选择、价值判断 | 实务规则 → 攻防要点 → 翻车标本 | 3 |
| 操作指引卡 | 可执行流程、步骤、方法 | 操作指引（分步骤表） → 操作要点 → 避坑 | 3 |
| 裁量尺度卡 | 量化锚点、评分分级 | 指标表 → 计算公式 → 分级处置 → 取值提示 | 1 |

**配套决策**：
1. **域码取 PI（人身损害）**，不新开医疗域码——避免触发 `_规则卡编号体系规范.md` 白名单修订红线。落 **PI 域新建子目录** `医院法律顾问实务/`。
2. **取号唯一入口** `next_rule_id.py --domain PI --n <N>` → 落盘后 `--commit`；建卡后必跑 `rule_id_guard --since 60`。
3. **先拆 3 章试点**（第 1/2/3 章，12 张），老强验收粒度后再续拆余 16 章（约 100+ 张）。

## 理由

1. 卡型必须与内容同质。WF-026 的红线本质是**防语义污染**，只防了"审判要件塞进要件映射卡"，却没防"裁判规则格式套到实务内容上"——后者同样失真。
2. 保留八段中的**攻防要点 / 翻车标本**两段（实战价值最高），按卡型重排骨架，不是推倒重来。
3. PI 是白名单既有域码，不新增即不动规范，风险最低。
