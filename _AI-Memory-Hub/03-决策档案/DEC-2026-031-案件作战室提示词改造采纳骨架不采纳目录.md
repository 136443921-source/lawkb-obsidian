# 案件作战室提示词改造决策

## 背景

老强提供一份《案件作战室 WorkBuddy 流水线提示词》通用骨架（六大目录 + 开案 SOP + 日常流水线 ABC + 结案沉淀 + 输出纪律），要求结合当前项目给改造方案。

侦察发现：老强已有实战体系（CLM 七阶段 + G0–G8 门禁 + case-state.json 单一可信源 + 桌面办案系统 + LTI 五维 QC + 红蓝复核 + 裁判规则库 + 知识飞轮 + 中枢）。上传提示词若直接照用会与之冲突。

## 备选

| 方案 | 内容 | 评估 |
|---|---|---|
| A | **总纲式**：作战室项目内只放指针与规程，案件实体全留 LawKB + 桌面；case-state 为唯一状态源 | ✅ **采纳**——零迁移、零双源、立即可用 |
| B | 全量迁移：实体全部搬进作战室项目 | ❌ 大规模搬迁破链接，违反批量前 dry-run |
| C | 双轨同步 | ❌ 两套真相源 = 待解决的病根本身 |

## 结论

**采纳骨架，不采纳目录；采纳动作，改造落点；补三道质量门禁；解一处脱敏冲突。**

### 三处硬冲突
1. **目录体系重复** → 事实源分裂。上传提示词 01-06 六目录 vs 桌面办案系统 + LawKB 既有编号目录 → 只建指针索引，不建平行实体。
2. **缺单一可信源** → 阶段漂移。实证：项目指令写"G3 active·择期宣判未结"，权威 case-state 写"9-29 判决已出·全案胜诉·G3 pass·stage⑥"。
3. **缺质量门禁** → 带病交付。上传提示词"四段式"零校验环节 → 补红蓝复核 → LTI(REJECT=0) → 六维门禁三道闸。

### 脱敏规则改造（不照搬原提示词）
原提示词"姓名用甲乙丙"**不采纳**，改为**流向三级脱敏**：
- 案件目录内 → 实名（仅打码证件/电话/银行卡/详细住址）
- 中枢 → 只留方法论，当事人姓名不入中枢（沿用 PROJ-LAW-6658 约定）
- 公开制品/联网 → 甲乙丙代号 + 隐私全脱敏

**理由**：全案代号化会打断 01_答辩状/31_庭后代理词 编号链、庭审十件套 MD5+正文指纹定版、LTI C301/C302 一致性校验。

### 反向补入（原提示词完全缺失的 8 项）
CLM 七阶段+G0–G8 门禁 / case-state 单一可信源 / LTI 五维 QC / 红蓝复核+六维门禁 / 裁判规则库 / 本地源引证铁律(statute_text_pending) / 否定型结论+变体矩阵+E1004 / 双目录同步+IMA 回传+飞轮 LOG。

## 理由

上传提示词是"从零搭房子"的图纸，老强已住进有门禁、有验收标准的楼。改造 = 不拆楼，把图纸降级为"作战室总纲"接入既有 CLM 门禁。**本次改造最大增值点不是给一套通用提示词，而是把散落在 10 条铁律 + 8 个技能里的隐性纪律固化成作战室可执行规程。**
