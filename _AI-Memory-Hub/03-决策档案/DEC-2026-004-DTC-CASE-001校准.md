# DEC-2026-004 · DTC-CASE-001 案件双轨索引校准（2026-09-14）

## 背景
SR 召回引擎（scan_cases.py 扫 case-state.json）与飞轮索引（案件-知识映射索引.md）失同步，导致召回漏案。2026-09-03 双轨并入 `案件生命周期管理系统/` 后，仅 6658/6660 pilot 建了 case-state.json，其余 11 案只有案件笔记，召回层不可见。

## 决策 / 方法
1. **单一事实源对齐**：为无 state 的 11 案生成 case-state.json，使 SR 召回边界 = 飞轮索引 13 案全量。
2. **诚实生成**：state 仅含索引可证字段（caseNo/title/domain/status），court/judge/client/deadlines/meta.agents 标 `calibration.pendingFields` 待人工从笔记/桌面真卷回填，禁止凭记忆编造。
3. **双轨承载说明**：桌面真卷轨仅 6658/6660 有真实庭审十件套；其余 11 案真卷以 `LawKB/案件生命周期管理系统/` 案件笔记为权威（壳轨承载）。
4. **新案铁律**：入案须同步建 case-state.json，否则再次漏案。

## 关键发现（重要）
`scan_cases.py` / `sync_case_state.py` 在 SKILL.md 与运维手册中标注"已交付"，但 `~/.workbuddy/skills/案件生命周期大屏流水线/` 实际仅含 SKILL.md，脚本文件未实装。SR 召回引擎当前实际召回依赖飞轮索引被跨案件模式识别读取。补装脚本后须跑 `--dry-run` 验证 13/13。
