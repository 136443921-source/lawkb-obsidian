# 不设「业务运营官」· 数字员工考核统一归口律所主任

## 背景

- 2026-09-25 23:5x，老强提议：在业务中台设「业务运营官」一个岗位，**指挥、调度并考核**业务中台全岗员工（心智模型席位）+ 派遣员工 43（自动化操作工），向律所主任（总经理）汇报。
- AI（小强）评估后指出三处会撞车的口径问题：
  1. **43 数的归属错配**——花名册 v1.2 显示 43 操作工分四班，真正归业务中台的只有「业务作业班 10 + 模拟法庭班 2 = 12 个」，其余 31 个（知识采编班 22 + 资产保管班 9）属跨中台共享；全归该岗等于授予其跨中台指挥权。
  2. **与 SOP-BUS-05 冲突**——该文件已定义「业务中台设备总线单一入口」，调度权明确写为"**总经理派工**"；再设一个"指挥调度全岗"的岗＝两个调度入口。
  3. **考核权闭合风险**——若该岗同时考核 QC-Controller 与 LTI，会出现"自己派活、自己评分"的自证闭环。
- 老强随即改判：**不设该岗；考核工作统一由律所主任（总经理）负责。**

## 候选方案（同轮比较）

- **A｜设「业务运营官」作编排层**（AI 原建议）— 弊：如上三处，且平白多一层管理跨度。
- **B｜不设该岗，考核归总经理** ← **拍板**
  - 利：架构回到"唯一股东 → 总经理 → 数字员工"三层扁平；无新增编制、无跨中台指挥权、无与 SOP-BUS-05 的调度权冲突；考核者（总经理）天然独立于被考核对象。
  - 弊：管理跨度全部压在人身上（8 席位 + 43 操作工）；需在"采数"与"考核"之间切一刀，否则出现事实上的影子执行臂。
- **C｜设但降级为纯记录岗（不具考核权）** — 弊：名不副实，且仍要维护一个岗位。

## 结论（选项 B）

1. **不设**「数字员工·业务运营官」。该设想**自始未落任何治理文件**（编制方案 / 岗位手册 / 花名册 / SOP-BUS-05 均无对应条目），故本次决定**对现有文件零改动**。
2. **数字员工的考核权 100% 归律所主任（总经理）**，不设中间考核层。适用于两类：
   - 心智模型席位（8–11 席）：考核内容＝成熟度评级（M3/M4/M5）、转正、扩编、裁撤建议。
   - 操作工（43）：考核内容＝运行健康度（执行成功率 / LTI 门禁率 / 回传入库率 / 重复执行与误删副作用 / active-paused 状态位）。
3. **采数与考核必须分离**（防影子执行臂）：
   - 数据供数由既有执行臂承担：**数字资产运维官**（操作工侧登记调度，维护花名册 json+md+运营副本）、**数字员工·IT 运维员**（9655 驾驶舱六维与巡检）。二者**只供数、只登记，不具考核判定权**。
   - 考核判定权唯一保留在总经理；据此给出的暂停 / 唤醒 / 改写 / 裁撤建议，仍按四类 R 动作口径需老强拍板。
4. **QC-Controller 与 LTI 门禁的垂直独立性不受本决策影响**——二者继续垂直向总经理，不向任何业务岗汇报，本轮红线原样保留（`RULE-QCJUDGE-DISAMBIG`）。

## 风险与遗留

- **考核负荷落在人身上**：54 名数字员工的考核若靠人工逐项过，不可持续。建议后续把"考核"从**记忆驱动**改为**数据驱动**——由驾驶舱与花名册自动汇总一份「总经理周考核包」（执行率 / 门禁率 / 回传率 / 异常清单），总经理只做裁定不加工。
- ** corollary 陷阱**：给考核供数的 automation 本身也在被考核名单里，须明确"**工具只采数、免考核**"或"仅纳入观察不纳入评级"，否则考核工具自我服务。
- 本决策**不创设任何法律主体**，数字员工仍为纯内部治理隐喻（源：`数字员工编制方案 v1.0` §1）。
