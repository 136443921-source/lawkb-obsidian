# DEC-2026-032 · T501接线+T504转正+MOC全量重扫口径

# DEC-2026-032 · T501 接线 + T504 转正 + MOC 全量重扫口径（2026-10-22）

## 背景

法发〔2026〕10号第十九条第三段要求「提交法庭前应当认真核实相关法律、司法解释、案例等内容的真实性、准确性」。
老强拍板三项：T504 灰度转正 / 12 条待核验案号清理 / MOC 全量重扫对齐。

## 决策一：T501 保持 WARNING（不阻断），但必须先把机制接通

**发现**：`CitationRegistry` 从未被生产门禁传入（registry=None → T501 整体静默）。
即 T501 长期是**死机制**，即使 `T501_BLOCKING=True` 也毫无作用。

**备选**：
- A. 直接把 `T501_BLOCKING` 置 True（"有法源支撑就转正"）
- B. 先接线让机制活起来，开关保持 False
- C. 不接线，维持死状态

**结论：B**

**理由**：
1. 白名单仅覆盖 369 条已核验案号；实践中大量**真实**案号尚未入库（贵州基层法院案件元典库普遍未收录、
   外地案例未逐一登记）。置 True 会对真实案号大面积 REJECT，误阻断风险不可接受。
2. 「核实」不等于「已在白名单登记」——以未登记推定不真实，逻辑上过强，且不符合无罪推定式的执业伦理。
3. T502（编造案号 → REJECT）+ T504（真案号假要旨 → 对外交付 REJECT）已覆盖最致命的两类风险；
   T501 定位为「提示补登记」的辅助闸门更合适。

**升 True 的前置条件**（写入 trace.py 注释）：白名单覆盖率显著提升 + ≥200 份真实文书实测误报率 ≤1%
+ 配套批量登记与一键核验的降摩擦工具。

## 决策二：T504 双档正式生效（非灰度）

- `internal`（默认）→ WARNING，不阻断，避免打断写作流；
- `external`（`--delivery external`）→ CRITICAL → REJECT，**对外交付硬闸门**。

**口径**：对外交付稿（提交法院/监管/客户）**必须**用 external；内部稿用默认。

## 决策三：MOC 全量重扫——不替换主体，全量独立成快照

**关键纠错**：首次扫描（仅 `裁判规则库/` 一个目录）得出「多余 200 张」，方向错误——
R-CF-001 实际位于 `06-沉淀/慈善合规域库/`。扩面到 `06-沉淀/`（17 个域库）后：

| 指标 | 数值 |
|---|---|
| 物理卡 | 2507 张 |
| MOC 收录 | 208 张（覆盖率 8.3%） |
| 多余（MOC有·物理无） | 16 张（从 200 降至 16） |
| 同号冲突 | 34 组 |

**结论**：MOC 主体**不替换**，全量索引独立成 `裁判规则库-全量物理索引快照-20261022.md`（457KB）。

**理由**：
1. `裁判规则库.md` 是「月度快照 + 分散索引表」体例，**不存在单一卡表块**，
   `卡族MOC重生成` 的「整段替换」逻辑不适用；
2. 96KB → 预计 500KB+，失去可读性；
3. 成员口径涉及卡型分族（全库 3471 张 R-* 中 `card_family: 裁判规则库` 仅 130 张、
   多数未填），须老强定口径后才宜重建。

**不删除任何 MOC 条目**（含 16 张多余）——铁律：防丢卡。16 张全为旧「学习笔记」目录散落卡
（R-GZ-001~011、R-LN-001~005）。

## 决策四：案号核验口径——「检索未命中 ≠ 虚假」

元典对贵州基层法院案件普遍未收录。故：
- 本地案卷可查的案号 → 登记 `exists=True, source=local-case-file`，**明示未经外部库核验**；
- 格式异常（缺法院代字）或年份冲突的 → **不登记**，入 `case_verify_suspect.md` 待人工核原件。

本次：10 条 → 去重 9 条（1 条脏数据合并）→ A 类 7 条登记 / B 类 3 条存疑。

## 副产物：修一个真实产品缺陷

门禁原 `hints[:12]` 截断 → T501/T504 命中却完全不可见（实测 T501 命中但输出 0 次）。
已改为**重要规则（T501/T502/T504）优先显示 + 🔴 标记**。
