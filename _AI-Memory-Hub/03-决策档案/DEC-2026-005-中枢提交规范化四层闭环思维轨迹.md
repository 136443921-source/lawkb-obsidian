# DEC-2026-005 · 中枢提交规范化四层闭环·思维轨迹

> 记录 2026-09-14 一天内，一条工程约定如何沿「口头偏好 → 偏好卡 → 协议硬规则 → 技能触发 → 方法论卡」四级固化，并形成闭环的思维演进链。每个节点遵循决策档案契约：决策点 / 考虑了什么 / 否决了什么 / 什么信号会推翻。

## 背景触发

2026-09-14 第 5/6 轮推「总驾驶舱 C 编号改版」时，连续遭遇 `LawKB/.git/index.lock` 残留死锁（并发会话 git 中断），手敲 `git` 多次卡死。老强据此提出一条工程约定，并明确要求固化为中枢强制规则——而非停留在口头偏好。

## 思维轨迹（决策演进链）

### 节点 1 · 口头偏好 → PREF-006（01-用户偏好/）

- **决策点**：凡对中枢 `_AI-Memory-Hub/` 的 git 提交，一律走 `backfill.py`（内置 index.lock 安全重试），禁止手敲 git。
- **考虑了什么**：`backfill.py` 的 `_run_git()` 已实测能在 `index.lock` 阻塞时以 `pgrep -fl git` 精确判定是否有真实 git 进程持有锁（有则 ABORT、无则清锁重试），比手敲稳；同时借机修掉 backfill.py 两处工程 bug（锁路径写死 `cwd/.git` → `git rev-parse --git-dir`；重试 add 未捕获 `CalledProcessError`）。
- **否决了什么**：否决「信任手敲 git」——实测手敲在并发会话下必卡死。
- **推翻信号**：若 backfill.py 安全重试被证不可靠（频繁误清锁 / 误 ABORT），则回退评估替代通道。
- **落点**：PREF-006 卡片 + 索引行，push origin/main（commit `3da3ef2b`）。

### 节点 2 · PREF-006 → 协议第六条（00-全局规则/）

- **决策点**：把约定从「偏好卡」升级为「协议级硬规则」，写进共享记忆协议第六条。
- **考虑了什么**：偏好卡仅对读卡的 AI 可见，协议是权威层、对所有 AI 强约束；第六条含 6.1 禁手敲 / 6.2 链路分工（write_back.py 只落盘、backfill.py 唯一 git 通道）/ 6.3 安全重试原理 / 6.4 引 PREF-006。
- **否决了什么**：否决「仅留 PREF-006 一张卡够用」——老强主动要求进协议层。
- **推翻信号**：若协议第六条与 PREF-006 表述冲突，以协议第六条为准（权威层）。
- **落点**：协议第六条正文（含 6.2），push origin/main。**本节点曾因同消息并发 3 个 Edit + Obsidian 自动改 `updated` 抢写，导致正文竞态丢失、推出"谎称有第六条"的残缺版；下轮 Read 回验发现并重推修正。**

### 节点 3 · 协议第六条 → hub-card-backfill 技能触发

- **决策点**：在技能 `description` + 红线速查补「协议第六条已生效，通用提交走 `--files`」触发。
- **考虑了什么**：让意图匹配层在会话开始就识别「对中枢做 git 提交要走 `--files`」，不用等老强开口。
- **否决了什么**：否决「只靠协议 / PREF-006 被动等读」——主动把触发前置到技能意图层。
- **落点**：SKILL.md 本地更新（技能文件属 `~/.workbuddy/skills/`，**不走中枢 git**、不进 backfill.py）。

### 节点 4 · 6.2 显式 `--files` + 并发漏写事故修正

- **决策点**：协议第六条 6.2 显式点出 `--files` 通用提交 + `--card` 补卡主入口两种命令模式。
- **考虑了什么**：协议层应显式给出命令，避免执行时混淆两种模式。
- **事故反哺**：节点 2 的并发漏写事故暴露「Obsidian 监听文件勿并发 Edit、改后必 Read 回验」这一真隐患。
- **落点**：重插第六条正文 + 修订日志补行，backfill.py `--files` 安全推送（又自动化解一次 index.lock 死锁）。

### 节点 5 · WF-031 方法论沉淀（04-Workflows/）

- **决策点**：把节点 4 暴露的「Obsidian 并发 Edit 竞态」沉淀为可复用工作流卡 WF-031。
- **考虑了什么**：场景 C（技术踩坑 / 排障方法论）符合老强「主动提议沉淀」规则；WF-031 自身即「改后回验」活样例。
- **落点**：WF-031 卡片 + 索引行，backfill.py `--files` 双文件推送（干净 exit 0）。

## 收敛结论

一条工程约定经「口头偏好 → 偏好卡(PREF-006) → 协议硬规则(第六条) → 技能触发 → 方法论卡(WF-031)」四级固化，形成**四层闭环、互为引用、零歧义**。期间一次并发事故反哺出 WF-031，印证「事故即资产」——踩坑不浪费，沉淀为可召回方法论。

## 推翻信号（整体）
