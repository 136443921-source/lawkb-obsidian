# 🔒 技能训练记录回写中枢铁律

**规则正文**：凡针对 AI 技能开展的**解剖 / 训练 / 调优 / 结构改造**活动，其成果**必须**回写 LawKB 共享记忆中枢，且必须齐备**三件套**——`方法论卡（WF）` + `项目状态卡（PROJ）` + `思维轨迹卡（DEC）`。训练对话本身不得只停留在业务目录或单次会话 memory 里。

**为什么**（不写清楚会被后来的 AI 删掉）：
老强同时推进多个 AI 技能的心智训练（法官 / 蓝队 / 红队 / 书记员…），训练是有**时间跨度**的长期工程。记录若散落在工作区 md、项目 memory 或单次会话里，换设备、换会话、换 AI 即整体失忆——**成熟度分数无法跨会话累积，等于每次从零开始训**。中枢是唯一能让他"随时看清每个技能长到什么程度"的地方。此条 2026-09-14 由老强明确要求从偏好层升格为铁律（原 PREF-007）。

**违反时会怎样**：
训练成果不可召回、成熟度数据断档、已修病灶被重复修、已否决方案被重新提出；下一任 AI 会重新走一遍老路，老强的时间被反复浪费。

## 一、三件套落位（缺一不可）

| 件套 | 落位 | 承载内容 | 卡片类型 |
|---|---|---|---|
| ① **方法论** | `04-Workflows/WF-xxx.md` | 可复用训练流水线、解剖模板、评分维度、数据口径坑 | `workflow` |
| ② **项目状态** | `02-当前项目/PROJ-xxx.md` | 当前成熟度分、五维明细、病灶清单、下一步、关键资产路径 | `project-fact` |
| ③ **思维轨迹** | `03-决策档案/DEC-YYYY-NNN.md` | 训练**对话**的演进链：每个关键决策点「考虑了什么 / 否决了什么 / 推翻信号 / 落点」 | `decision` |

**为什么思维轨迹单独成卡**（老强 2026-09-14 明确）：
训练对话里最有价值的不是结论，而是**"当时为什么这么选、否掉了什么"**。结论会过时（版本升级即失效），但**否决理由和推翻信号**长期有效——它防止下一任 AI 把已否决的方案当新想法再提一遍。

## 二、思维轨迹卡的写作契约

每个节点必须写满五要素，缺项视为未完成：

```
### 节点 N · <节点名>
- **决策点**：一句话说清这一步定了什么
- **考虑了什么**：备选方案与实测依据（须有实地核验的数字/路径，禁凭记忆）
- **否决了什么**：被否的方案 + 否决理由（**最关键，决定这张卡的价值**）
- **推翻信号**：出现什么现象时本节点决策作废
- **落点**：实际写入的文件 / commit
```

另需两条卡级要素：**收敛结论**（整条链沉淀出什么）+ **推翻信号（整体）**。

## 三、落位决策树（避免放错目录）

```
训练产出
├─ 可复用步骤/模板/口径 → 04-Workflows/WF-xxx.md
├─ 当前状态/分数/病灶/下一步 → 02-当前项目/PROJ-xxx.md
├─ 训练对话的"为何这样选" → 03-决策档案/DEC-YYYY-NNN.md
├─ 踩坑事故与防护 → 06-经验沉淀/EXP-YYYY-NNN.md
├─ 暴露的新长期偏好 → 01-用户偏好/PREF-xxx.md
└─ 单日训练流水 → 04-每日日志/YYYY-MM-DD.md
```

## 四、硬性约束（老强一贯铁律，训练场景同样适用）

1. **先查重再建条目**——同类中枢条目存在则**更新**而非新建，禁止生成近似重复笔记（查重范围：`_索引.md` / `_活跃项目.md` / `_近期决策.md`）。
2. **不凭记忆引用**——技能路径、行号、成熟度分值、场次计数须**实地 grep / 跑脚本复测**后再写。
3. **先备份再改**——改既有中枢卡前 `cp` 到 `/tmp` 时间戳目录。
4. **禁止静默覆盖**——发现 id 撞号或指向不同文件时 ABORT，不覆盖他人卡片（见 EXP-2026-001）。
5. **隐私红线**——个案卷宗（当事人姓名 / 证件号 / 银行卡 / 证据原件）**禁止入中枢**；案件名仅作训练语料标识，只提炼方法论与工作流事实。
6. **提交通道**——中枢 git 一律走 `backfill.py --files`，禁手敲 git（见 PREF-006 / 协议第六条）。
7. **改后回验**——写入后必须 Read 回验正文，禁同消息并发 Edit（见 WF-031）。
