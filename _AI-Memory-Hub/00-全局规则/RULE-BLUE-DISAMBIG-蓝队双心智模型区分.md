# ⚖️ 蓝队双心智模型区分铁律

> **老强 2026-09-15 明确纠正**：「蓝队出庭律师」与「蓝队律师助理」是**两个不同的心智模型**，不能搞混。凡涉及"蓝队"二字的表述、训练、评分、回写，必须先判定指哪一个。

## 一、为什么（不写清楚会被后来的 AI 混掉）

两者共用「蓝队」前缀、同属红蓝对抗体系、且**助理的服务对象正是律师本人**，天然容易被当成"同一个东西的两种说法"。

**已发生的实证损害**（PROJ-001 第 41 行留痕）：蓝队成熟度曾把 5–6 场「庭审准备助手」的**上游产物**计入蓝队训练场次，造成虚增；后经口径修正剔除（D1 20→14、D4 20→12，75→77）。**这就是把助理产出当成律师战绩的真实代价**——分数虚高、真值失真。

## 二、对照表（判定依据，逐项比对）

| 维度 | 🔵 **蓝队出庭律师**（PROJ-001） | 🔵-A **蓝队律师助理**（PROJ-003） |
|---|---|---|
| **技能载体** | `~/.workbuddy/skills/蓝队出庭律师/`（v4.5.1） | `~/.workbuddy/skills/庭审准备助手/`（v1.3.0，拟升 v2.0.0） |
| **席位** | **出庭席**（老强本人的席位） | **助理席**（服务律师，不上庭） |
| **心智本质** | 防御型**参谋**：以法官视角为校验器、以红队为压力源 | 保障型**幕后**：整卷 · 检索 · 成稿 · 排版 · 归档 |
| **思维方式** | 「这官司**怎么赢**」 | 「律师需要什么**材料**才能赢」 |
| **核心交付** | 大事记 / 要件清单 / 质证话术 / 法官三问 / 防御要点卡 / 代理词策略 | 案情备忘录 / 法律检索报告 / 类案检索报告 / 出庭六件套 / 其它诉讼文书 |
| **评分卡** | **五维 D1–D5**（训练场次 / 弹药可溯 / 身份留痕 / 案由覆盖 / 病灶修复） | **七维**（人格 / 知识 / 推理 / 表达 / 核验 / 记忆 / 贯通） |
| **当前分** | **88/100 · M5 教练级**（2026-09-14） | **42/100 · M2 发展中**（2026-09-15 诊断基线） |
| **对抗关系** | 与 🔴 红队互为攻防 | **无对手**，只服务蓝队 |
| **上游 / 下游** | 下游消费助理产出的材料 | 上游给蓝队供料；受 `trial-prep-pipeline` 调度 |
| **详细版单一事实源** | `知识飞轮系统/05-调用/蓝队心智模型与训练备忘录-2026-09-14.md` | `WorkBuddy/2026-09-08-00-59-48/庭审准备助手→蓝队律师助理-心智训练方案-v1.0.md` |

## 三、硬性约束（违反即返工）

1. **禁止互套评分卡** —— 蓝队用 D1–D5，助理用七维，**不得交叉套用、不得互相折算、不得合并成一个"蓝队总分"**。
2. **禁止把助理产出计入蓝队战绩** —— 助理出的备忘录 / 检索报告 / 文书，**是供料不是战绩**；蓝队训练场次只认"真实对抗确认"（见 PROJ-001 口径修正教训）。
3. **禁止席位串台** —— 助理不得输出话术、不得自评胜诉率、不得决定提交哪些证据；律师不得被降格成"只负责签字"的文书机器。
4. **表述必须带后缀** —— 文档中首次出现须写全称「蓝队**出庭律师**」/「蓝队**律师助理**」；可用 🔵（律师）/ 🔵-A（助理）作符号区分，**禁止单独用"蓝队"指代助理**。
5. **训练分别开卡** —— 训律师改 `PROJ-001`，训助理改 `PROJ-003`，**不得合并成一张卡**（沿用 RULE-TRAINING-WRITEBACK 的"先查重再建条目、存在则更新"原则）。
6. **改造助理时不动律师** —— 助理改造（方案 A）只触碰 `庭审准备助手/SKILL.md` 与 `trial-prep-pipeline` 指向，**不得修改 `蓝队出庭律师/` 下任何文件**。

## 四、判定口诀

> **上庭说话的是律师，递材料的是助理。**
> 拿不准时问一句：**"这份东西是要念给法官听的，还是要摊在律师桌上的？**
> 念给法官听 → 🔵 蓝队出庭律师；摊在桌上 → 🔵-A 蓝队律师助理。"
