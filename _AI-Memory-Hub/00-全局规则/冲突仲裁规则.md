# ⚖️ 冲突仲裁规则

> 当同一事实在多个位置出现不同说法时，**唯一**裁决依据。任何 AI 不得自行"挑一个顺眼的"。

## 仲裁四级漏斗

```
输入：候选事实集合 C = {c1, c2, ... cn}
│
├─ 第1级【状态过滤】-------------------------------------
│   status ∈ {deprecated, superseded, draft} 直接出局
│   → 若过滤后为空 → 报告 ⚠️NONE，请求人工裁决，禁止凭记忆补全
│
├─ 第2级【时效优先】-------------------------------------
│   取 updated 最大者为 winner
│   → 若并列 → 进第3级
│
├─ 第3级【来源权重】-------------------------------------
│   source_ai 权重从高到低：
│     human(手工编辑)   = 100   ← 老强亲自改的永远最大
│     obsidian-manual  =  90
│     workbuddy        =  60
│     claude           =  50
│     codex            =  50
│     gemini           =  40
│     cursor           =  40
│     unknown          =  10
│   → 若仍并列 → 进第4级
│
└─ 第4级【置信度 + 挂起】---------------------------------
    confidence: high > medium > low
    → 仍无法判定 → 标记 ⚠️CONFLICT，全部候选写入
      03-决策档案/_待裁决队列.md，明确请老强拍板
```

## 冲突处置动作表

| 场景 | 动作 | 产出 |
|---|---|---|
| 新事实更新且更强 | 旧条目 `status: superseded`，新条目 `supersedes: <旧id>` | 双向可追溯链 |
| 新事实更新但更弱来源 | 仍以新为准，但 `confidence` 下调一级并记录疑点 | 保留证据链 |
| 事实被证伪 | `status: deprecated` + `deprecated_reason` | 90 天后自动归档 |
| 项目已结案 | `status: deprecated` + `scope` 锁定 | 移 `05-归档/` |
| 同义重复不同措辞 | 保留最早 id 作为 canonical，其余 `status: superseded` | 一处更新即可 |

## ⛔ 明令禁止

1. **禁止静默覆盖**：发现冲突必须留痕，不允许"后者直接覆盖前者而无 supersedes 链"。
2. **禁止跨拉取认定**：不可因为"别处也这么写过"就判定该事实有效——须看本中枢条目本身。
3. **禁止用 updated 之外的方式犯懒**：同一天内多次更新，必须用时间+来源权重走完漏斗。

## 实例（2026-09-14 立）

> 老强技能黑名单：曾从"方案A 先提示确认"改为"方案B 自动启用"。
> 若中枢条目写"方案B"，而某平台原生 memory 仍写"方案A" → **中枢 updated=2026-09-14 胜出**，执行方案B，不询问。

## 附：平台原生 memory 的合法角色

| 允许 | 不允许 |
|---|---|
| 缓存本轮会话的临时上下文 | 宣称某事实版本最终有效 |
| 记录未提炼的原始流水 | 与中枢冲突时不肯让步 |
| 作为下次提炼的输入素材 | 被直接当作跨 sessions 的真相 |
