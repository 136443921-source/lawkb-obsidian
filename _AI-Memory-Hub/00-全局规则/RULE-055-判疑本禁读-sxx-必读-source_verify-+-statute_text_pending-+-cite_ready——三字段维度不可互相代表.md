# 判疑本禁读 `sxx`，必读 `source_verify` + `statute_text_pending` + `cite_ready`

## 一、三个字段承载三个不同维度，不可互相代表

| 字段 | 回答的问题 | 不回答什么 |
|---|---|---|
| `sxx` | **这部法律本身**是否现行有效 | 不回答「你手上这张卡是不是现行版本」 |
| `source_verify` | 本地卡体与权威源**指纹是否双证一致** | 不回答「法本身是否现行」 |
| `statute_text_pending` | 本地卡体**能否直接条号级引用** | 不回答「法本身是否现行」 |
| `cite_ready` | 综合判定（全文 ∧现行∧ 双证一致 ∧ 非桩） | — |

**典型并存状态（不矛盾）**：
```yaml
sxx: 现行有效                    # 买卖合同这部法还有效
statute_text_pending: true              # 但本地这张卡是2012旧版
source_verify: 待核验（卡体为2012-07-01施行版，官方现行2020修正版2021-01-01）
```

## 二、实证事故（2026-10-15，法条银行复盘）

- **错误做法**：只读 `sxx` → 实测「待核验 0 张」→ 得出**「库里没有疑本」**的假阴性结论
- **实情**：**5 张疑本卡标记完整存在**，一个都没被抹
- **险情**：若据此起草 6660雅菲案（买卖合同纠纷）代理词，会引用 **2012 旧版《买卖合同司法解释》**，而官方现行是法释〔2020〕17号（2021-01-01 施行），**条号已重排**
- **根因**：**字段语义混淆** —— 把「法本身时效」当成了「本地卡版本时效」

## 三、下笔前必做五步

1. **列全字段再数**——判疑本至少读 `sxx` + `source_verify` + `statute_text_pending`（有 `cite_ready` 优先读它），三者缺一不可
2. **警惕过于整齐的分布**——「101 张全现行有效、零异常」这种整齐是**口径太窄**的信号，不是安全信号
3. **抽样反查**——随机取一张已知有问题的卡，确认在你用的口径下**能否被检出**；检不出即口径错
4. **区分实体时效与载体时效**——法条库、案例库、合同库都有这对概念
5. **凡否定型结论（「无风险本/无版本问题/已全部双证」）须换字段复核后**方可写入任何文书

## 四、与 RULE-016 / RULE-022 的关系（冲突仲裁记录）

- RULE-016：「凡引用法条必须核对 `sxx` 时效性与发布年份」
- RULE-022：「凡引用司法解释，必须核对 `sxx` 时效性字段与发布年份」
- **本规则补充并纠偏**：两者「核对 `sxx`」的要求**方向正确但不充分** —— `sxx` 是必要项，**不是充分项**。单靠 `sxx` 核验会漏掉「法有效但本地卡是旧版」这一整类风险。
- **故不废止RULE-016/022，而是追加本条作为其必要补充**。引用任何法条时，`sxx` 与 `source_verify`/`statute_text_pending`/`cite_ready` **必须同时看**。
