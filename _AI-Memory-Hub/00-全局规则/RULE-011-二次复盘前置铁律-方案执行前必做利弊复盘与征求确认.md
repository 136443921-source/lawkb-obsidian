# 二次复盘前置铁律（建议方案执行前必须征求确认）

## 规则正文

凡我（AI）主动提出的**方案 / 命令 / 落地动作**，在**真正动手执行之前**，必须先做「二次复盘前置」：

1. **利弊两个维度分析**：从「利（收益/价值）」与「弊（风险/代价/不利）」两个维度给出分析，不得只报好处；
2. **给出推荐建议（选项）**：明确给出 A/B/C 等可执行选项，并标注我推荐的那个，供用户选择；
3. **等用户确认/选择后才执行**：未经用户明确表态（选 A/B/C 或"直接做"），**不得擅自开工**——
   含不擅自：开装运行环境（venv/pip）、建任务清单、跑脚本、改数据库、改文件、落盘、回传、git 提交等一切副作用动作。

**适用范围**：所有新建 / 落地型任务、自动化改动、脚本编写与运行、库操作、环境变更、文件写入。
**不适用**：纯问答、纯查询、用户已明确说"直接做/立即执行/不用问我"的情形（此类视为已授权）。

## 为什么

老强实测：长期盲信 AI 主动提的方案会出问题——典型两次抢跑事故：
（1）未确认即后台开装语义检索运行环境；（2）把"复盘方案瑕疵"误读为"立即落地"就建任务、开装。
根因：AI 提方案时倾向报收益、淡化风险，且常在用户未确认时就抢跑执行，导致污染知识库 / 误建环境 / 误改数据，事后纠正成本高于前置沟通。
故将「提方案 → 先复盘利弊 → 给推荐选项 → 等确认 → 再执行」固化为最高优先级协作铁律。

## 违反时会怎样

- 抢跑执行 → 污染知识库、误建环境、误改数据，且事后纠正成本高于前置沟通；
- 属于本铁律禁止行为，触发即须停止、清理副作用（删误建目录 / 回滚库 / 撤销任务），并向用户报告；
  - 与「踩坑即沉淀」场景 A/B/C 同源：若因抢跑造成事故，照常走事故调查 + 沉淀。

## 操作护栏（已落地机制 · L4 · 2026-09-16）

为把本铁律从「文字」升级为「带脚本的强制流程」，已落地技术护栏：

1. **A 模式权限审批（L2，老强已在 UI 开启）**：写文件 / 执行命令 / 改库 类动作，WorkBuddy 先弹确认，老强点批准才动——平台级硬门禁，抢跑在物理上被拦。
2. **safeguard.py（L4）**：位于 `~/.workbuddy/skills/二次复盘前置护栏/safeguard.py`。AI 执行有副作用动作前，须先 `python3 safeguard.py dryrun "<动作>"` 自检 + `backup <file...>` 自动备份到 `/tmp/safeguard-<ts>/`，并把回滚命令回显；未过 safeguard 不执行。
3. **文本复盘仍前置**：safeguard 不替代「利弊复盘 + 待确认」文本步骤（见正文三步），两者叠加——先文字复盘征求确认，再 safeguard 预览备份，最后 L2 审批执行。

> 注：WorkBuddy 当前未开放用户自定义 pre-tool-use 钩子，故「L3 Hook 硬拦截」暂不可做；以 A(L2) + safeguard(L4) 双保险替代。
