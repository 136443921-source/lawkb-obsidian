# 需求拷问前置门禁（Grill Me · 法律咨询 + 任务派发双域）

## 规则正文

凡用户给出「**未充分指定的请求**」（泛化动词+无约束，或目标 / 范围 / 主体 / 完成标准任一不清），
一律**先过 `grill-me-legal-preprocessor` 前置门禁**做苏格拉底式意图澄清、产出「需求对齐卡」后，
才进入 `legal-consult-router` 或任务派发器：

1. **先 grill 后路由 / 派发**：未明确请求先调 `grill-me-legal-preprocessor`，拿到对齐卡再进 router / 派发；对齐卡作下游 context 首段，Q5 直接消费卡内已查实事实，不重复追问。
2. **事实查本地（H 项自查修正 2026-09-23）**：进 L3 前先读 case-state——主源 `Documents/LawKB/案件生命周期管理系统/<casename>/case-state.json`（15 案最全），辅源 `Desktop/小强律师办案系统/<casename>/case-state.json`；**不用精确文件夹名匹配**（桌面与 LawKB 命名对不齐），改用**案号优先（如 6658）+ 当事人 / 案由关键词模糊定位**；事实查找**限定案卷内**，勿翻桌面根目录散落文件（举证清单 / 撤诉意见 / 录音证据 / 大屏 html 及 .bak 是噪声）；当事人信息从桌面原始材料核实，不凭记忆。
3. **越权红线**：grill 阶段只澄清意图，**不给法律意见 / 定性 / 法条**；定性交 router 与专项技能。
4. **七条军规**：一次一问 · 逐分支走决策树（L1 目标 / L2 范围 / L3 事实 / L4 约束含 H4 可逆性 / L5 完成标准）· 每问附推荐答案 · 事实查本地不考用户 · 依赖逐个解 · 锲而不舍至共享理解 · 拷问期禁给法律意见。
5. **跳过条件**：已精确指定技能 + 案号 / 对象、trivial 单步、纯闲聊 → 直接放行，不加仪式感（避免对高频 trivial 任务拖慢）。
6. **防回环**：对齐卡产出后，下游不得再次触发 grill 处理同一请求（卡内标注「已对齐，勿重复触发」）。

## 为什么

老强痛点：AI 做出来 ≠ 想要的，根因是「不知道自己要什么」+「没说清楚」。法律 / 代写业务 stakes 高，
一句「帮我告他」可能误入诉讼而本可发函协商。grill-me 移植自 Matt Pocock 的 Grill Me（grilling 方法），
把「需求意图澄清」自动化为 L0.5 前置门禁，专治「提问的人」，让路由 / 派发在错误方向上不猛生成、
降咨询 / 代写返工；对一人公司等于把没有的「前台 intake 助理」补上。

## 违反时会怎样

- 未澄清即路由 → 模型靠默认选项迎合，错派 / 浅答 / 答非所问，下游在错误方向猛生成；
- 高 stakes 决策（如不可逆的诉讼 / 发表）被误读 → 职业风险 + 客户投诉；
- 代写业务 scope creep（范围蔓延）直接吃利润。

## 操作护栏（已落地机制 · 2026-09-23）

1. **技能载体**：`~/.workbuddy/skills/grill-me-legal-preprocessor/SKILL.md`（自包含，L0.5 门禁，双域罩住）。
2. **router 第零步**：`legal-consult-router` SKILL.md 头部「第零步·需求拷问前置门禁」约定未明确请求先交 grill。
3. **与既有铁律互补**：本门禁只澄清意图，不替代 `RULE-011`（二次复盘前置 / 先方案后执行）与 `PREF-010`（歧义先问不瞎猜）；`pre-action-guard` 仍管副作用动作许可。
