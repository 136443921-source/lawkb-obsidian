# RULE-EMP-ROSTER-UPDATE · 数字员工增员减员必同步更新花名册

**版本**：v1.0　**日期**：2026-09-24　**状态**：生效（老强指示）
**性质**：全局硬规则（数字员工治理层）

---

## 0. 一句话

数字员工**增员、减员**（含操作工自动化新建/停用/删除、心智模型席位新建/裁撤/转正），**必须同步更新《数字员工花名册》三处副本**，三处同源、改一动全动，不得只改其中一处。

---

## 1. 适用范围

- **操作工（自动化 worker）**：`automation_update` 增删、暂停/启用归属变化、工种班变动。
- **心智模型席位（岗位型 seat）**：依据中枢 `09104 数字员工编制方案` 新建/裁撤/更名/扩编/转正（如法条银行行长 WF-046 转正、数字资产运维官在建补入）。

## 2. 必须更新的三处副本

| 副本 | 路径 |
|---|---|
| 机器消费版 json | `LawKB/OPC 一人公司/00-数字资产登记册/数字员工花名册.json`（运营工作副本） |
| 人读版 md | `LawKB/OPC 一人公司/00-数字资产登记册/数字员工花名册.md`（运营工作副本） |
| 中枢共享主存 | `_AI-Memory-Hub/09-OPC/09-5数字员工花名册/数字员工花名册.json` + `.md` |

> 三处内容须逐字一致；任意一处变更，其余两处同日同步，并在花名册「八、变更日志」追加一行（版本/日期/类型/摘要/来源）。

## 3. 归口与批准链

1. 发起：数字资产运维官（操作工侧）/ 律所主任（席位侧）提出增员或减员动议；
2. **批准：老强（唯一股东·超级管理员）** 拍板（四类 R 动作红线不变，对外出件/定价/批量删改/新增改造仅老强决策）；
3. 执行登记：数字资产运维官更新三处副本 + 变更日志；
4. 联动：席位侧变动同步回填 `09104 数字员工编制方案`（名单/更名/扩编），保持与花名册口径一致。

## 4. 减员特别纪律（六-B 安全铁律延伸）

- **减员 = 破坏性动作**：操作工自动化删除前必须先 `cp` 全量备份；席位裁撤须先在 `09104 §2.2 非员工实体/观察席` 留痕，不得静默消失。
- 7 个 `paused` 操作工属**待用员工**（非残次品），减员前须由律所主任出具"僵尸率/存活率"监控结论，不得凭印象清理。
- 蓝队家族四席（诉讼/非诉/助理/红队）、AI 模拟法官与 QC 审判长 的建制变动，须遵守 `RULE-BLUE-DISAMBIG` / `RULE-QCJUDGE-DISAMBIG`，禁止互套或合并折算。

## 5. 校验（写入后必做）

- json 合法性：`python3 -c "import json;json.load(open(...))"` 通过；
- 计数一致性：`operators` + `seats` 总数 = `counts.数字员工总编制`；
- 三处 `counts` 字段逐字相同。
