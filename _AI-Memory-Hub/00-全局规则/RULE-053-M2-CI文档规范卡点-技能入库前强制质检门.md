# RULE-053 · M2-CI 文档规范卡点（技能入库前强制质检门）

> **一句话定义**：M2-CI 卡点 = 给数字分身系统的「技能零件」设了一道强制质检门，用四条规定把「法条可靠、改动可查、时效可知、退化可控」钉死在流程里。

## 一、它是什么
- **CI** = Continuous Integration（持续集成），此处借指「技能文档进库前自动跑检查」；**卡点** = 关卡 / 门禁——过不了就挡在门外，不让进技能库。
- **M2** 是数字分身系统给「文档规范」这道门禁编的编号。
- 实际形态：脚本 `doc_spec_gate.py`（复用 `doc_spec_check.py` 判定逻辑），扫描 `~/.workbuddy/skills/` 下全部**活跃技能**的 `SKILL.md`（已排除 `_archive` / `_backup` / `statute-bank-version-archive`）。
- **判定**：四项全过 → 退出码 `0`，放行入库；任一缺失 → 退出码 `1`，阻断并输出不合规清单打回补齐。

## 二、四条规定（卡点检查项）
| # | 规定 | 判据 |
|---|---|---|
| ① | 变更日志 section | 须有 `## 变更日志 / 更新日志 / 修订记录 / CHANGELOG` 等标题 |
| ② | 语义化版本号 | 文档须出现 `vX.Y.Z` 或 `X.Y.Z` |
| ③ | 创建 / 更新日期 | 须有 `创建日期：YYYY-MM-DD` + `更新日期：YYYY-MM-DD` 显式字样 |
| ④ | 独立 LTI 检查说明引用 | 须有「LTI」且其后 40 字符内含「说明 / 规范 / 检查 / 详见 / .md」等触发词，指向 `LTI文本监控器/SKILL.md` |

## 三、对数字分身系统的四个作用
1. **法条准确性保障**（最核心）—— 第④项强制每个技能挂接 `LTI文本监控器`（R001-R020 五维 QC 法条校验），从源头压降法律 AI 的法条幻觉。
2. **版本可追溯** —— 第②+①项要求语义化版本号 + 变更日志；法律规则常变，改动可查。
3. **时效可核验** —— 第③项写明创建 / 更新日期，一眼知文档何时核实，避免拿旧文档当现行依据。
4. **防回归退化** —— 卡点可定期自动扫全部活跃技能，新增技能或旧技能文档被改坏即时拦截。

## 四、实测基线（2026-10-06 首跑 + 修复）
- 首跑：175 活跃技能，57 不合规（合规率 67.4%）。
- 三波次补齐后复跑：176 活跃技能**全部合规（100.0%）**。
- 复跑中发现 `lawkb-bulk-rename` 为基线后新增、初版未过卡点 → 触发「新增技能未过 M2-CI 卡点，需补齐文档后方可入库」提示，已补齐。
