# ⚖️ QC 审判长双模心智 ≠ AI 模拟法官

> **一句话**：两个都带"审判长/法官"字样，**一个是管程序质量的质控员，一个是管实体裁判的推演内核**。
> 中台 `side` 字段就是判据：**`"qc"` = QC 质控， `"neutral"` = 模拟法官**。凡混淆即回本规则。

## 一、为什么必须立这条规则

| 风险 | 后果 |
|---|---|
| 两者成熟度相差 **48 分**（QC 50/M2 起步 vs 法官 98/100） | 互套评分卡 → 分数虚高或虚低，训练方向跑偏 |
| 都涉及"审判长"字样（普通程序 QC 上**审判长席**） | 席位串味 → QC 越权下实体心证，或法官被当成质控员 |
| 中台同时渲染 `chief`（QC）与 `judge`（法官）两席 | 发言方/指令串台 → 庭审推演失真 |

## 二、判别铁律（三问定席位）

| 问 | QC 审判长双模心智 | AI 模拟法官 |
|---|---|---|
| **① 管什么？** | **程序质量**：流程合规、笔录校核、纠错触发、总闸控制 | **实体裁判**：要件涵摄、心证、拟裁判要旨、数额门控 |
| **② 中台 `side` / `seat`？** | `side:"qc"`；`seat:"qcobs"`（独任）／`seat:"chief"`（普通） | `side:"neutral"`；`seat:"judge"` |
| **③ 人格卡在哪？** | `~/.workbuddy/skills/QC-Controller/qc_persona_v1.md`（**DRAFT**） | `~/.workbuddy/skills/ai-mock-court-judge/judge_persona_v1.md`（**ACTIVE**） |

> **任一问不符即停手核对**，不得继续训练/评分/回写。

## 三、禁止事项（五条）

1. **禁止互套评分卡** —— QC 用四维判据（焦点/节奏/释明/秩序）+ 成熟度 50 基线；法官用七维量表（人格/知识/推理/表达/核验/记忆/贯通）+ 成熟度 ~98 基线。两套量表的同名维度**不可互相引用**。
2. **禁止 QC 染指实体裁判** —— QC **不下心证、不做要件涵摄、不写裁判要旨、不估数额**。发现实体问题 → 出具指令由**法官席**处理。
3. **禁止法官代行质控** —— 法官不校验笔录、不触发纠错、不做总闸控制。那是 QC 的活。
4. **禁止用"审判长"字样反推身份** —— 普通程序下 QC 席位标签就是「审判长（QC-Controller·审判长心智·质控）」，但**身份是 QC，不是法官**。判身份看 `side`，不看标签。
5. **禁止互计战绩** —— QC 的质控留痕不计入法官成熟度，法官的推演裁决不计入 QC 成熟度。

## 四、双模席位法定依据（QC 内部切换，与本规则不冲突）

- 《民事诉讼法》第 132 条（`raw:132`）："合议庭的审判长由院长或者庭长指定审判员一人担任"
  → **独任庭无审判长**：QC 坐**观察席**（`qcobs`）；**普通程序**才有审判长席：QC 上**审判长席·质控**（`chief`），此时法官技能转为合议庭审判员。
- 切换由中台 `procType`（`duiren`/`putong`）**自动决定**，`side` 恒为 `"qc"`——**双模切换不改变 QC 的身份，只改变席位**。

## 五、回写与训练纪律

- 训练/评分/回写前**先声明对象**：写清"本次训练 QC 双模心智"或"本次训练 AI 模拟法官"，不得只写"审判长"。
- QC 训练回写落 `PROJ-006`；法官训练回写落 `PROJ-模拟法官心智成熟度备忘录`。**不得交叉回写**。
- `08-心智资产/_索引.md` 中两者分列不同行，索引维护时**不得合并单元格**。
