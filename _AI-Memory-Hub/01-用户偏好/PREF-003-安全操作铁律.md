# 🛡️ 安全操作铁律

> 这组规则优先级高于任何"效率优化"建议。

## 六-B 铁律（写入型操作必走）

```
1. 先排查 —— 全量盘清楚现状，不上来就改
2. 确认非误报 —— 复现根因，不是直接加白名单糊住
3. 再批量修改 —— 改根因，不补丁叠补丁
4. 含安全扫描 —— 每次写入前扫一遍影响面
5. 必须 dry-run —— 先出拟变更清单，人看过了才 apply
6. 追加幂等验证 —— 复跑一遍确认状态稳定
```

## 备份铁律

- 任何单源文件重建前 → **`cp -n` 备份到 `/tmp/<对象>_备份_时间戳/`**。
- 改配置类文件（如 `mcp.json`、全局规则）→ 必先备份，禁止裸改。
- `-n` 参数防覆盖，禁止静默替换。

## 数据完整性

- **绝不静默覆盖权威数据**（法条正文、裁判规则、案号）。
- 全文获取失败 → 不入库，登记 `failed` + `status=retry`，等自愈后回补。
- 状态变更前自动备份。

## 个人目录红线

对 `~/Desktop`、`~/Documents`、`~/Downloads` 的整理类请求：**第一遍只读扫描出报告**，列出清单后等老强逐条确认，禁止自动动手删改。

## 为什么

老强同时是执业律师和技术操作者，"一次性答案"不值钱，**可恢复、可审计、可回滚**才是生产力。
