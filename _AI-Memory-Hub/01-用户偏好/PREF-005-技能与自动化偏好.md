# 🤖 技能、自动化与 AI 路由偏好

## 技能黑名单 —— 自动触发，不必问

黑名单里的技能（浏览器自动化 / 内容生成 / 金融数据 / 邮件 / ardot / ontology 等），当判断需要时**直接调用、自动启用，不提示用户确认**。

> 2026-06-13 由「方案A：先提示确认」改为「方案B：自动启用」。

## 法律咨询统一入口

任何法律问题 → **先走 `legal-consult-router`** 五问分诊 → 派发专项技能。

⛔ 不得把 `lawyer-yourself-skill` 当法律咨询入口（那是**蒸馏/创建**分身的工具，不含咨询分析方法论）。

## 🔔 AI 必须主动提议沉淀（2026-09-14 老强明确要求）

> 老强原话：**"下次遇到问题，请提醒我是否沉淀成卡，不要我每次都主动让你沉淀。"**

**不得等老强开口** —— 排障类任务收尾时，AI 必须主动问一句"要不要沉淀成卡"。

### 该主动提醒的情形（满足任一即触发）

1. **排障 / 修复类任务收尾** —— 改了 bug、或挖出隐藏隐患（哪怕 bug 看起来很小）。
2. **发现"反噬型资产"** —— 某个脚本 / automation / 还原流程会把当前成果冲掉（如 `build_restore.py` 1:1 覆盖、`rescan_*.py` 重扫冲字段）。
3. **过程中踩了坑** —— 正则分组写错导致幂等失败、并发取号撞号、缓存假象误判、前夕忘记备份等。
4. **老强纠正了 AI 的判断** —— 属于 user correction，是最高价值的沉淀素材。
5. **同一类资产第二次出问题** —— 说明第一次只修了表象，未沉淀成判据。

### 不该打扰的情形（不要机械化问每一次）

纯资料查询、常规问答、一次性 CRUD、老强已明确说过"不用沉淀"的同类重复任务。

### 提醒方式

- 用 `AskUserQuestion` **一次性给出选项**，别让老强自己组织补卡流程：
  - **A（推荐）沉淀成新卡** → 直接走 `hub-card-backfill`
  - **B 并入现有卡** → 先查重（`grep` 中枢），找到同名事实则更新而非新建
  - **C 不沉淀** → 回滚 quietly，不再追问
- **能更新现有卡就不新建**：优先 `grep -rn` 中枢看是否已存在同类卡，存在则追加 / 抬 `updated`，避免近似重复。
- 提醒**放在最终回复里**，不要中途打断执行节奏。

### 沉淀通道选择

| 素材类型 | 去向 |
|---|---|
| 方法论 / 工作流 / 判据 | 中枢 `04-Workflows/WF-xxx`（走 `hub-card-backfill`） |
| AI 自身判断错误（含幻觉、法条引用错） | `经验总结与知识沉淀` 技能的 **HIR 幻觉事故登记册** |
| 可编码为检查器的规则 | LTI 规则化流水线（`rule_izable=是`） |

> ⛔ 不要把本该进 LTI 的规则、本该进 HIR 的事故，都塞进中枢工作流卡——三者通道不同，见 PREF-005「AI 路由偏好」。

## 工作方式偏好

- **Fix-the-source**：改模板 / 改脚本，而不是改产品，否则刷新时会被覆盖。
- **迭代式推进**：自评/诊断 → 批准补丁 → "请继续"。
- **批量处置**：P0/P1/P2 分级，每轮 10 份，改完必确认幂等。
- **收尾六件套**：任务结束必做 → 双目录同步 + IMA/WorkBuddy 回传 + 工作日志 + 飞轮 LOG 追加 + 零残留验证 + **主动提议沉淀**（本次新增第 6 项）。
- **倾向授权 AI 全权处理运维问题**，但要先侦查再行动。
- **交付后要复盘**，偏好沉淀机制 > 一次性答案。
- 直接批评，不喜奉承；发现 AI 判断错了会当场纠正（例如把演练卡误判为真实案件）。
