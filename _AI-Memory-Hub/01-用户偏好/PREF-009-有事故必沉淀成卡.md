# 有事故必沉淀成卡

> 2026-09-15 老强明确要求：**"我要求有事故必沉淀成卡。"**
> （触发场景：规则库归库撞号 577 事故，老强追问"这个事故有沉淀成卡片没"）

## 偏好内容

**凡发生事故 / 误判 / 踩坑 / 返工，当轮任务内必须沉淀成经验卡，不得等老强开口问，也不得只在会话里口头复述完就算交差。**

> ⬆️ **与 PREF-005 的关系**：PREF-005 要求"排障收尾**主动提议**沉淀"；
> 本卡升级为——**直接做，不必先提议**。事故卡是**交付物的组成部分**，不是可选项。

## 什么算「事故」（满足任一即触发）

| 类别 | 判据 | 本源案例 |
|---|---|---|
| **判断错误** | 下过"空白 / 已有 / 为 0 / 已闭环"类断言，后被证伪 | 「域空白」「三块为 0」误判 |
| **数据漂移** | 文档 / 记忆里的数字与实测不符 | 规则库 11/147/132/2447 五连错 |
| **工具静默失配** | 命令返回 0 / 空却不报错，导致误判 | Bash `grep -c` 返回 0 |
| **安全险情** | 差点覆盖、误删、未备份即写入 | 撞号 577，差点后写盖先写 |
| **返工** | 同一问题修第二遍（含修完又漂） | 中台面板改了又被脚本覆盖 |

> ✅ **正向触发器**：一句话自问——**"这件事，下次换个会话我会不会再犯？"** 会 → 立刻建卡。

## 沉淀落位（查重后写入）

| 内容类型 | 落位 |
|---|---|
| 运维 / 盘点 / 数据类事故 | `知识飞轮系统/02-提炼/经验卡片/飞轮运维/` |
| 合规 / 非诉实务类事故 | `知识飞轮系统/02-提炼/经验卡片/非诉合规/` 或 CMS 卡库 |
| 工作流 / 可复用步骤 | `_AI-Memory-Hub/04-Workflows/WF-xxx.md` |
| 重要决策及其推翻 | `_AI-Memory-Hub/03-决策档案/DEC-YYYY-NNN.md` |
| 当日流水 | `_AI-Memory-Hub/04-每日日志/YYYY-MM-DD.md` |

## 卡片质量底线（不达标 = 没沉淀）

1. **有事故回放** —— 写出当时的错值、真值、错因（不写"某处有误"这种模糊表述）。
2. **有可复用铁律** —— 不是感慨，是**下次能照着做的检查清单**。
3. **有精确数字** —— 数字后**必挂口径**（见 `经验卡-统计口径五连错`）。
4. **有互链** —— 与同族卡互链成链，禁止孤立卡。
5. **先查重** —— 已有同类卡则**追加/升级**，不新建近似重复卡（本协议通则）。

## 同步回写（事故卡建完后）

- 更新 `_AI-Memory-Hub` 相关卡（项目页病灶表、索引）
- 更新本机 `.workbuddy/memory/` 与跨项目 `~/.workbuddy/MEMORY.md` 铁律条目
- 按 `blue_nonlit_maturity.py --refresh` 计入训练场次（席位类事故）

## 为什么重要

老强的系统靠"卡片"而非"记忆"运转——**事故不复盘成卡，就等于用同一个坑反复交学费**。
他明确说过：**沉淀机制 > 一次性答案**。
