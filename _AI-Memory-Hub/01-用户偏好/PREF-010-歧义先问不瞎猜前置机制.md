# 歧义先问·不瞎猜前置机制

> 用户指令存在歧义 / 我理解困难 / 有多种合理解读时，必须先用 AskUserQuestion 主动澄清、确认理解无误再动手；绝不凭猜测直接开干。与 RULE-011（AI 主动提案前的二次复盘前置）互补，不重叠。

## 要
- 接到指令后先做「意图歧义自检」：是否存在多义、多实现路径、我信心不足、有纠正史；命中任一即停手。
- 用 `AskUserQuestion` 把歧义点拆成 2–4 个选项（含我推荐的那个），等老强确认再干。
- 老强说"直接做/立即执行/不用问" → 视为已授权，直接干。

## 不要
- ❌ 把"歧义"误当成"可执行 bug"去验证代码/数据层，用验证动作替代澄清动作（这是"瞎猜就开干"的变体）。
- ❌ 脑中有"但他可能意思是…"的备选解读时，仍按第一直觉抢跑。
- ❌ 在用户已纠正过本类歧义后，下一轮仍不触发 ASK 直接动手。

## 典型场景
- 指令含多义词（如"这几个仅用主任账号"→ 共用主任凭据 / 各自配成主任那套）；
- 同一指令有两种以上差异大的实现路径；
- 我对"用户真实意图"信心不足；
- 本类任务历史上被纠正过。

## 与 RULE-011 边界
- RULE-011 = AI 主动提方案 → 先复盘+征求确认（AI 主动开关）；
- 本机制 = 用户已下指令但 AI 理解歧义 → 先 ASK 澄清（用户主动下指令后 AI 澄清开关）。
