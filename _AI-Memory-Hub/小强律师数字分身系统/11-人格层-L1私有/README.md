# 11-人格层（L1）· 私有 · 绝不开源

> 🚫 **本目录属方案 B 定义的 L1 人格层，任何情况下不得进入任何公开仓库。**

**⚠️ 关于"隔离强度"的诚实说明（2026-09-10 修正）**

`~/Documents/LawKB/` 本身**就是一个 git 仓库**（`.git` 在 LawKB 根）。
因此把 L1 放在 `11-` 目录**不等于物理隔离**——同一仓库内换目录，只是"分层"，不是"隔离"。
真正的隔离只有一条路：**移出该 git 仓库**（例如迁到 `~/.lawtwin/persona/`）。

当前采取的是**双层防护**，须同时生效：

| 层 | 措施 | 强度 | 已被绕过的可能 |
|----|------|------|---------------|
| 1 | 目录分层（远离 `10-` 开源候选域） | 弱 | 易——防的是误操作，不是故意 |
| 2 | `LawKB/.gitignore` 顶层规则 | 中 | 可被 `git add -f` 强制绕过 |

**已核查（2026-09-10）**：本目录与老强实例**均从未被 git 跟踪**
（`git ls-files` 无匹配、全部分支 `git log` 无历史），故无历史泄露，当前加规则有效。

> 若将来需要向外部开源 `10-` 中台，**不要直接把这个仓库推上去**。
> 正确做法：只把 `10-律所数字分身中台/` 复制到一个全新空仓库，从零开始提交。
> **带着 LawKB 的历史推远端，等于把整个知识库拱手让人。**

## 一、为什么是 L1

按 `10-律所数字分身中台/02-中小律所数字分身模板方法论.md` §6 的三层剥离：

| 层 | 内容 | 处置 |
|----|------|------|
| L0 内核层 | EV 骨架、四模板协议、LTI 判据引擎、MCP 适配器壳 | ✅ 开源 Apache-2.0 |
| **L1 人格层** | **self.md / persona.md / HOW-I-THINK / 决策日志 / 律师画像实例** | 🚫 **本目录，绝不开源** |
| L2 数据层 | LawKB 卡库、裁判规则库、案件卷宗、客户档案 | 🚫 绝不开源 |

**L1 是本系统护城河的本体**（白皮书 §5.1）：思维指纹、决策启发式、执业偏好，
均以年为单位沉淀。进公开仓库＝把护城河免费送人。

## 三、使用规则

1. **本目录不建 git 仓库**；若父目录建仓，须在 `.gitignore` 顶层写入 `11-人格层-L1私有/`（双保险）。
2. 引用本目录实例时**用绝对路径**，不在中台文档内写相对路径回链（避免反向暴露结构）。
3. 对外演示/截图/讲座 PPT 一律使用 `10-.../01-律师画像模板/example.lawyer.profile.yaml`（虚构样例），
   **不得使用本目录真实实例**。
4. 新增任何文件前自问：**含真实案号 / 当事人 / 身份证 / 思维指纹吗？** 是 → 放这里，不放中台。
5. 每次向中台输出内容前，跑一次脱敏门禁：
   `python3 07-系统搭建与Skill配置/开源脱敏工具/desensitize_check.py <目标> --strict`
