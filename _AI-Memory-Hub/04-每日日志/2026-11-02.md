## 十五、本轮收口沉淀（方法论）

**一条贯穿主线**：从「学习三表法 → 规则卡 WF-131 → B 方案落地 → 架构纠正 → 一致性审计 → 完整能力复盘 → 8 项治理 + 残留修正」，本质是把证据目录三表法的**四个方法内核，从「提示词级自觉」逐级升到「门禁级机制」**。

**可复用方法（写回门禁层）**：
- **「提示词级 → 门禁级」升级判据**：任何"靠自觉执行"的纪律，若出错不可逆（自认表述、红蓝复核漏点、case-state 滞后），应升级为 gate-config 强制步骤（L3 人工签字 / L2 自动放行）+ meta 结构化字段 + 自动化兜底，三件套齐了才算"机制化"。
- **「有实无名」与「有名无实」双向审计**：文档层漏记（作战室）与文档层虚记（sync_case_state.py 脚本不存在、最佳实践库路径不存在）都要抓——前者靠"对照实际系统 grep 文档"，后者靠"文档记载的文件/路径实测是否存在"。
- **「双原件冲突」治理范式**：桌面旧版 vs L0 新版的冲突，不在个人目录删文件，而在 L0 显式声明"唯一权威源 + 旧版 MD5 指纹 + 不得引用"，既安全又留痕。
