## 3. 对比：你的分身 vs 元宝 vs 豆包（2026-09 实况）

### 3.0 三者定位一句话

| 系统 | 定位 |
|---|---|
| **你的分身** | **生成器 + 拦截器 + 私有知识资产**：带案卷、带本地法条银行、带 LTI 门禁、越用越厚的飞轮 |
| **腾讯元宝** | 通用大模型（混元）+ 联网搜索 + **ima 公开知识库**（2026-06-15 接入，金融/法律/医疗 20+ 行业，来源卡片可跳转）+ 应用广场「法律博士」+ **得理法律咨询**（5 亿+法律数据，免费入驻） |
| **豆包** | 通用大模型 + 联网搜索 + **用户自装/自建 Skill**（合同审查等）；无原生法律数据库，批量文档处理（"工作任务"模式）见长 |

### 3.1 场景 A：咨询一个法律问题

| 维度 | 你的分身 | 腾讯元宝 | 豆包 |
|---|---|---|---|
| 检索底座 | 本地法条银行 **124** md（verbatim 核填）+ 法律法规库 **76** md + 元典 MCP（1.82 亿裁判文书）+ pkulaw + 案例缓存 342 | 混元 + 联网 + ima 法律知识库 + 得理（5 亿+数据） | 联网搜索 + 用户自喂材料 |
| 法条引用 | 本地 verbatim + LTI 全链校验（含**版本位移 R116**） | 引用带**来源卡片可跳原文**；无条号/时效校验 | 靠模型记忆 + 联网；**多篇实务指南原话要求律师逐条核验** |
| 时效性（现行有效 vs 废止） | ✅ R001/R108/R116 自动判 | ⚠️ 依赖联网结果新旧混杂 | ⚠️ 同左 |
| 案例引用 | ✅ T502 存在性核验 | 得理可给参考案例（未核验真伪由数据方保证） | 需自己下载文书上传归纳 |
| 个人案件上下文 | ✅ 案卷/要件卡/裁判规则在本地 | ❌ 须手动喂 + 隐私顾虑 | ❌ 须**脱敏后**上传 |
| 幻觉防线 | ✅ LTI：80.6% 检出 / 0% 误报 | ❌ 靠信源质量 + 人工点卡片 | ❌ 靠人工 |
| 输出 | 结构化分析 + LTI 五维 QC + docx 双轨 | 对话 + 来源卡片 + 知识卡片 | 对话 + 清单初稿 |
| 成本 | 自建（元典按量，月赠 3,500 分） | **免费**（得理免费） | 免费 + 专业版订阅 |
| 广度 | ⚠️ 受本地库边界限制 | ✅ **最强**（联网 + ima + 微信公众号生态） | ✅ 强 |

> **场景 A 结论**：问一个**通用法律问题**（"租房押金不退怎么办"），元宝 ima+得理的组合甚至比你的分身更顺手、更广；
> 但问**带案卷的具体问题**（"6658 号案里 622 条怎么用"），只有你的分身答得既贴案又可核验。

### 3.2 场景 B：检查一份法律文书（差距最大）

| 校验维度 | 你的分身（LTI） | 元宝 | 豆包 |
|---|---|---|---|
| 条号越界（编造"第 999 条"） | ✅ **R101 阻断** | ❌ | ❌ |
| 条号↔内容错配（张冠李戴） | ✅ R111/R112 + 元典在线核验 | ❌ | ❌ |
| **版本位移**（引了修正前的旧条号） | ✅ **R116 独有** | ❌ | ❌ |
| 中文数字条号（"第五百八十六条"） | ✅（09-01 修复后全中） | ❌ | ❌ |
| 金额前后矛盾 | ✅ **C301 阻断** | ⚠️ 靠模型自觉发现 | ⚠️ 同左 |
| 主体名称/案号/称谓/审级一致 | ✅ C302/C304/C305–C308 | ⚠️ 部分 | ⚠️ 部分 |
| 法理逻辑（定性自打脸） | ✅ L201–L204 + 六维门禁 | ❌ | ❌ |
| **案例真实性**（案号是否真实存在） | ✅ **T502** | ❌ | ❌ |
| 输出交付 | 红蓝复核 → LTI → **docx 双轨**（修订标记版+干净签字版，法〔2016〕221 号版式） | 对话内标红（文书分析模式：缺失项/期限矛盾/免责异常高亮） | 对话内风险清单初稿 |
| 隐私 | 本地闭环不外发 | 文章明示：敏感合同**建议关闭"体验优化计划"** | 文章明示：**先脱敏再上传** |

> **场景 B 结论**：这一局是**断代差**。元宝的"文书分析"和豆包的"合同 Skill"都停在**找文本问题**（歧义/缺失/矛盾），
> 你的 LTI 做的是**用权威库反向核验**（这个条号存在吗？这部法现行有效吗？这个案号真的有吗？这笔钱前后一致吗？）。
> 前者是"读起来通不通"，后者是"内容真不真"。

### 3.3 四条硬差异（提炼）

1. **校验层的有无**——最本质。元宝/豆包是"生成器"；你的分身是"生成器 + 拦截器"。元宝的 ima 来源卡片是"给你信源自己去查"，不是"系统替你查完才放行"。
2. **个案上下文**——6658/6660 案卷、要件映射卡、裁判规则在本地；元宝/豆包每次都是无状态的，且涉隐私材料不敢传（两家的官方指南都要求脱敏/关隐私开关）。
3. **知识复利**——飞轮 483 卡 / 5767 文件是**越用越厚的私有资产**；元宝/豆包用一万次也不沉淀你的东西（ima 个人知识库存的是文档，不是结构化规则卡）。
4. **你确实输的两处（要诚实）**——① **底层模型**：元宝/豆包背后的通用大模型推理与长文本能力，大概率强于本地链路的模型底座；② **广度**：开放性问题（学理争议、外省新口径、比较法）上，联网 + ima + 得理的覆盖面大于本地库；豆包"工作任务"模式的批量文档处理也比现有流水线灵活。
