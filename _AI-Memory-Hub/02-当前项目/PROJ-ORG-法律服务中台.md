## 📐 一人公司中台分层模型

```
前台  · 客户触点/获客      → 企微 Claw 渠道、公众号（已连通）
        ↓
中台  · 法律服务中台(本案) → 咨询业务线 + 文书代写业务线（业务生产/交付层）
        · 数字资产中台      → 模板/规则包/知识卡 SSOT（资产运维官，供给层）
        ↓
后台  · 合规/LTI/9655 监控  → 风控与质量门禁（监督层）
```

- **前台**＝客户触点，不做内部编排。
- **中台**＝业务生产（法律服务中台）＋ 资产供给（数字资产中台），双中台并列。
- **后台**＝合规/LTI/9655 监控，只监督不产出。

## 🎯 法律服务中台定位与边界

| 维度 | 法律服务中台（本案） | 数字资产中台（资产运维官） |
|---|---|---|
| 本质 | 业务生产/交付层 | 资产供给/支撑层（SSOT） |
| 职责 | 收口"咨询 + 文书"两条营收线 | 管模板/规则包/知识卡，只"供"不"产" |
| 入口关系 | 持有统一接待分诊台（router + 拷问门） | 被文书线"消费"，提供模板/规则/知识 |
| 是否接客户 | 是（经分诊产出交付物） | 否（内部供给） |

## 🔀 两条营收线

- **咨询线**：分诊到各专项技能（人损/医疗/合同/慈善合规…）→ 出法律意见、备忘录。
- **文书线**：分诊到文书生产链（docx 交付流水线 / 红蓝复核 / 非诉文书复核）→ 代写交付。
- **与数字资产中台的上下游**：文书线从数字资产中台**取**模板/规则包/知识卡，形成"中台消费、中台供给"闭环——入口在业务运营中台，资产在数字资产中台，二者不重叠。

## 🚪 入口角色（统一接待分诊台）

- `legal-consult-router` + 需求**拷问**前置门禁（grill-me-legal-preprocessor）＝ 统一接待分诊台。
- 流程：router 接所有诉求 → 拷问门先澄清意图 → 五问分诊 → 派发到咨询线或文书线。
- 已知覆盖：router 自身（预置接入，hook 显式豁免拦截）＋ 72 个下游法律域技能（第零步 + 未来 block 模式 hook 双重覆盖）。
