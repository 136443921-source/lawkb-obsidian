## 2. 系统概述

### 2.1 定义

**小强律师数字分身系统** = 基于 WorkBuddy 平台的**纯 AI 法律数字分身生态**，为律师、法务、法律从业者设计，
由「知识资产层（知识飞轮）＋ 智能体技能层（`~/.workbuddy/skills`）＋ 治理运维层（`00-系统总览与运维中心`）＋ 展示层（驾驶舱/大屏）」四层构成。

> 📌 **概念纠偏（2026-09-27 补）**：数字分身系统 ≠ `lawyer-yourself-skill`。
> 后者只是**数字分身蒸馏/进化**的一个工具技能；本系统包含 legal-base 基座、法律智能体基座、20+ 专项技能、
> LawKB 知识飞轮、驾驶舱与 OPC 治理。**对外咨询入口是 `legal-consult-router`**，不是 `lawyer-yourself-skill`。

### 2.2 核心特点（2026-09-27 实测口径）

- ✅ **纯 WorkBuddy 方案**：无 Neo4j / Redis / MinIO 等重型依赖
- ✅ **知识资产六层飞轮**：采集→提炼→连接→巩固→调用→沉淀
- ✅ **LTI 文本监控器 v4.9.1**：法律文本输出前强制 `wrap_output()` 拦截
- ✅ **自动化矩阵 79 条**：日/周/月/季多频无人值守
- ✅ **技能包 173 个**：法律域 + 工具域 + 治理域
- ⚠️ **目录结构已「整车化」**：v3.0.0 记载的五层目录**不再是物理现实**（见 §3）

**适用场景**：案件分析与策略制定 / 法律文书起草审查 / 合同审查与风险识别 / 法规检索与案例研究 /
庭审准备与模拟法庭 / 客户沟通与谈案 / 慈善组织合规 / 知识管理与经验沉淀 / 律所治理与商业化运营。

### 4.4 LTI 文本监控器（★ v2.9.1 → v4.9.1）

## 6. 使用指南

### 6.1 首次使用准备（3 步）

1. **确认系统配置**：检查 ① 系统根目录存在 ② `~/.workbuddy/skills/` 技能已安装 ③ LTI 可用（`wrap_output` 能调通）
2. **确认知识资产就位**：`LawKB/知识飞轮系统/` 六层可读；法条正文走本地权威源或 `yuandian_verify_cache.json`
3. **确认自动化矩阵**：`automation_update --mode list` 看关键任务 ACTIVE（每日知识摄入／每周复盘／季度锁数）

### 6.2 日常使用（3 场景）

| 场景 | 动作 |
|---|---|
| **办案** | 说触发词 → 联动技能 → LTI `wrap_output()` → 人工复核 → docx 双轨交付（修订版+干净版） |
| **知识** | 每日 08:30 摄入自动入飞轮；每周日批处理；每月 28 日人格蒸馏 |
| **运维** | 每日驾驶舱刷新；每周一评分刷新；每月 28 日卡量锁数 + 一致性巡检 |

### 6.3 定时任务使用

- 查看：`/automations`
- 创建/改期：WorkBuddy `automation_update` 工具（**先 list 取真 ID，不凭记忆写 ID**）
- 铁律：**写入型 automation 必须含六-B**（先排查 → 确认非误报 → 再批量 → 含备份 + dry-run）

### 6.4 技能联动使用

- 说触发词自动联动；或在 `process.md` 查看流程与技能绑定
- 技能改动后须重跑人格蒸馏（`automation-1783957225500`）才进 `self.md`
- 🔴 改 `self.md` 后**必须重跑**，禁止手改 `SKILL.md` 顶层的 combine 产物

## 7. 创建新的律师分身系统（10 步）

> v3.0.0 的「五层目录」步骤在 v4.0.0 中**降级为可选**——现网已改用「整车」指针目录。

| **自动化静默不跑** | 🔴 「自动化必须验证真跑、不信静默成功」→ 用 `diagnose-silent-automation` 技能诊断 |
