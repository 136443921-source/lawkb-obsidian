# 红蓝推演接入法官心智（参与智能体裁决模式）

> 来源：2026-09-14 模拟法官中台"红蓝对抗推演接入法官心智"节点。把独立的法官裁判视角，升级为红蓝推演的**参与智能体**（实时对每轮攻防做心证裁决）。
> 本条只沉淀方法论，个案攻防细节不入中枢。

## 适用场景

任何"已有两个独立视角面板（如 A=裁判视角、B=律师攻防视角）但两张皮"的系统：需要让裁判/裁决方作为**参与智能体**实时介入推演，而非旁观打分。

## 一、内核与 UI 分离（单一事实源）

裁决逻辑放进独立 UMD 模块（导出 `window.JUDGE_MIND` + Node 可测），HTML 只做渲染。否决"复制一份法官逻辑进推演脚本"——双份必漂移。

## 二、裁决三层结构

1. **assessArgument（单条攻防心证判定）**：对单条主张打分——带证据 1.0 / 引规范 0.5 / 纯质疑 0.3 加权，输出采信 / 不采信 / 部分采信 + 理由。
2. **assessDispute（争点双方对抗裁决）**：汇总某争点的红队攻击 vs 蓝队防守，输出倾向（蓝 / 红 / 待证 / 各有胜负）+ 举证负担归属。
3. **runTrialJudge（整场裁决）**：消费推演数据结构（如 `assault3.rounds`）逐轮裁决，汇总争点倾向，生成**拟裁判要旨（候选·待人工确认）**，并接入 LTI QC 门禁（REJECT=0 才准交付）。

## 三、参与智能体契约（打通两张皮）

- **每轮实时点评**：在每轮攻防渲染块内嵌「⚖️ 法官心证」徽标（倾向 + 采信计数），让推演过程可见裁判视角。
- **整场一键裁决**：推演面板按钮触发 `runTrialJudge`，渲染拟裁判要旨 + QC 门禁提示。
- **回写心证档案**：裁决结果回写裁判视角的心证档案（如 `S.xinZheng`），与法官心智抽屉**双向打通**——训练有累积，不回写则无累积。

## 四、R2 铁律贯穿

所有输出强制【候选·待人工确认】+「绝不替代终局裁判」声明；心证须写理由（LTI QC P2 禁「显然 / 当然」兜底词）。

## 五、两个必踩的坑（复用必看）

1. **jsdom eval 中裸标识符不在 Node 全局** → `global.JUDGE_MIND` + `window.JUDGE_MIND` 双轨挂载（同 WF-034 坑 1）。
2. **推演数据结构字段是解析层契约** → `runTrialJudge` 只消费约定的字段（如 `rounds[].redAtk / blueDef / focus`），若上游重构需同步解析层，否则裁决空转。

## 六、红线

- 法官心智只做候选裁决，绝不下终局 verdict（R2）。
- 裁决内核单一事实源，禁双份复制。
- 不回写则训练无累积——必须回写心证档案。
