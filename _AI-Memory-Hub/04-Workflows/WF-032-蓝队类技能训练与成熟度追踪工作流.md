## 适用场景

训练/调优红蓝对抗体系中任一「蓝队（防御方）」类技能，需要可度量、可迭代地提升其成熟度时。

> 本条假设角色**已独立存在**，只谈如何训强。若角色**尚不存在或被他职兼任**（如书记员曾由 QC-Controller 兼任），先走 **[[WF-033-模拟法庭书记员心智模型训练与角色剥离工作流\|WF-033]]** 的「角色剥离四步法」，再回本条做能力训练。

## 一、心智模型六层栈（解剖模板）

解剖任一 Agent 技能时按此六层拆，缺哪层补哪层：

| 层 | 问什么 | 蓝队实测 |
|---|---|---|
| L0 身份层 | 谁在说话？人格/基座继承是否声明 | 分身人格 + legal-base ✅ |
| L1 角色层 | 替谁说话？席位/阵营是否锁定 | 蓝队＝我方代理人席，参谋/代打双模式 ✅ |
| L2 认知层 | 怎么想？思维链 + **校验器**是什么 | 七步链，**法官视角是校验器** ⚠️ |
| L3 弹药层 | 凭什么说？知识源与取用规则 | 飞轮卡库七字段，禁裸判 ✅ |
| L4 输出层 | 说出什么？模板是否落地 | 九类产物，**模板层空洞** ❌ |
| L5 质检层 | 敢不敢出？闸门/埋点 | LTI + 门禁 + 埋点 ⚠️ |

**通用教训**：技能迭代做「精简拆分」时极易把模板/示例删掉却忘了迁移，留下**空转指令**（代码里写着"按模板输出"但模板已不存在）。解剖时必须验证"指令引用的资产是否真实存在"。

## 二、红蓝弹药对照（训练核心抓手）

红蓝共用同一把尺但取用不同字段，这是设计的精髓：

- 蓝队取 `ruling.support`（正向支撑）
- 红队取 `negative_note`（翻车标本 → 攻击点）
- 共用 `elements`：**缺一项，对蓝是致命，对红是攻击点**

**训练推论**：让蓝队在红队开火前，先用红队取弹逻辑自查。做到位则第一轮就该无 S 级漏洞。

## 三、五步训练法

1. **喂料**——用真案不用假案（卷宗先脱敏）
2. **出稿**——逼它按要件走：案由定性 → 要件清单（标证据编号）→ 支撑规则 → 排雷自查 → 法官三问
3. **挨打**——红队四维度全开，要 S/A/B 三级威胁表，S 级 v2 前清零
4. **迭代**——v2/v3 只补洞不重写，每轮 diff 要能说清多堵了哪个洞
5. **回写**——战报转防御要点卡入库。**不做这步等于每次从零开始**

## 四、成熟度五维（可自动计算，勿手工评分）

| 维度 | 权 | 怎么涨分 |
|---|---|---|
| D1 训练场次 | 20 | 多打对抗（10 场封顶） |
| D2 弹药可溯率 | 25 | 每次出稿报 rule_id |
| D3 身份留痕率 | 15 | 记录标注 `source_skill` |
| D4 案由覆盖 | 20 | 换新案由（5 案封顶） |
| D5 病灶修复率 | 20 | 修诊断出的病灶 |

等级：M1 萌芽 → M2 成型 → M3 熟练 → M4 精熟 → M5 教练级。

## 五、两个数据口径坑（复用必看）

1. **`knowledge_called: 无` 会被误判为"有弹药"** → 必须过滤 NULLISH 占位值（无/—/n/a/空）
2. **同一案件多种写法会虚高覆盖度**（丁戊祥/丁茂祥/6658 实为同案）→ 必须做别名归并再计数

教训：**自动化指标先验证口径，再看分数**，否则仪表盘会系统性虚高。
