# WF-138 · 模型调度提示机制（业务域二分 · 提示式路由）

## 一句话定义

**按任务所属业务域判定「唯一允许型号」，仅当它与当前承载模型不一致时输出一次提示卡；由用户明确点名型号后才切换，AI 不得擅自切换主会话模型。** 目的是把「该用哪个模型」的判断从人脑搬进系统，同时不触碰既有默认模型铁律。

> 🔴 **本卡只登记方法论，不登记型号值。** 路由表、书写值映射表、提示卡模板、口径差异一律以注入层 `~/.workbuddy/rules/model-dispatch.md` 为唯一事实源；本卡不复制、不写死，防双源漂移（RULE-060 §六）。

## 一、适用与不适用

| | 范围 |
|---|---|
| ✅ 适用 | 新建实质任务时的模型档位判定与提示 |
| ❌ 不适用 | 定时任务 automation、AI 自动切换主模型、中途频繁来回切、用户已点名型号的任务 |

## 二、工作流步骤

```
① 接单（任务四问后、动手前）
② 按「产出物」判定业务域：法律文书 → 案卷文书域；系统组件 → 系统搭建域；判不清 → 沿用默认并请用户明示
③ 查 SSOT 路由表，得该域唯一允许型号及其下拉菜单点选值
④ 比对建议 vs 当前承载模型：一致 → 静默执行；不一致 → 输出一次提示卡（不阻断）
⑤ 提示卡必须要求用户「明确点名型号」；「切」这类含糊应答不算，须重问一次
⑥ 用户点名 → 由用户在输入框下拉菜单切换（下一轮生效）；未点名或明示维持 → 按原模型继续，并标注「与裁定口径不符，本次豁免」
```

## 三、三条硬边界（方法论层）

1. **提示式，不是自动式**：模型切换是用户在 UI 的操作，AI 改不了主会话模型；官方明确「中途切换下一轮生效」「可能降低性能、增加积分消耗」，故设计为开任务前判定一次，不中途来回切。
2. **授权型号闭环**：仅两个已授权型号进入业务域硬约束；其它型号须「事先提示 + 用户明确点名 + 获得明确许可」，机制不得主动推荐。依据为 L0[23] 后半段「模型升级／积分保护硬约束」。
3. **不改铁律、不新增标准登记值**：本机制属操作层提示规则；默认模型铁律文本保持原样，口径差异登记在 SSOT，不触发 RULE-060 五步单向派发。

## 四、口径治理要点（可复用）

- **书写值分层**：同一模型在「裁定／铁律授权值」「UI 点选值」「方案原文型号」「历史用量标签」四层可能写法不同。须建映射表，逐层标来源；**未做技术同一性验证的一律标 `[口报·未实证]`，不写等号**。
- **时效标注**：厂商限时免费／配额活动会改变成本结论。历史成本实测数据是快照，**禁改**；只在规则层追加时效提示与到期重评待办，不反推历史数据有误。
- **颗粒度辨析**：官方文档常给「品牌级」定位，选型方案常给「具体型号」定位，二者不一致时先分层再判是否矛盾，勿直接写成「互相打脸」。
- **零结果双证**：断言「中枢无某登记值」须 Grep 内容 + 文件名检索双证，并列出书写变体清单。

## 五、验收

- 写入前：备份（`cp -n` 到 /tmp 时间戳目录）→ dry-run → 引用预检（多路径 + 多命名变体）。
- 写入后：回读**内容**确认落地（禁以时间戳判定）→ Grep 工具二次复核中文 → 残留扫描 → `check_registry_sync.py --deep`（FAIL=0）→ 日志留痕。
- 批量写入期间**不得并发跑校验**，批次结束后统一跑。
