# WF-102 · 每周法律资讯收集拆解流水线

> 沉淀自 2026-10-12 第41期周报生成 + 全41期运行复盘。把"每周法律资讯收集"自动化拆成六段线性流水线：触发定周期 → 全网采集 → 筛选撰写 → 本地三处同步 → iMA知识库上传 → 提炼建卡+记忆写回。实证：第41期三处本地副本 md5 一致（ca413628…），唯一长期缺口为第5阶段 iMA 上传（第36–41期连续失败）。

## 适用场景
- 每周一 09:00 自动化触发生成最新法律资讯周报（亦支持手动触发）。
- 需要把全网法律法规动态、最高法/检典型案例、热点司法案例、实务趋势结构化沉淀。
- 周报产出后继续喂给"周报提炼建卡（方案B·草稿待审）"自动化生成规则卡。

## 六阶段流水线

| # | 阶段 | 输入/触发 | 核心动作 | 工具/数据源 | 产物 | 失败处置 |
|---|------|----------|---------|------------|------|---------|
| 1 | 触发与定周期 | 周一09:00自动化 / 手动；上期号 | 期号+1；定覆盖周期（上周一~本周日）；`shell date` 取发布戳 | `date` 取 ISO 时间戳 | 期号、覆盖区间、时间戳 | 期号冲突→查工作区既有文件；时间一律 `date` 不手写 |

| 3 | 筛选与结构化撰写 | 素材池 | 分级（重磅/常规/临近施行/征求意见）；按四段式成文：政策法规更新 / 重要判例要点 / 实务指导意义 / 法条索引；补新规一览表 + 编辑说明；写 Obsidian frontmatter | 文本撰写 + LTI 法条口径核对（本地源优先） | 单份 Markdown 周报（主文件） | 否定型结论须双工具复核；法条不凭记忆，回填本地权威源 |

## 阶段5 单点故障与降级（重点）

> ⚠️ **2026-10-19 复盘勘误**：原"单点故障"叙事已过时，须按本段更正。

- **历史现象（真实）**：第36–41期（9/7–10/12）连续 iMA 上传失败——当时 ima-mcp 连接器在自动化会话内**确未加载**（须 UI 主动启用），非脚本可救，属真实缺口。
- **根因勘误（✅ 2026-10-19）**：ima-mcp 实为**「连接器托管型」**——授权信息写在 `~/.workbuddy/connectors/*/connector-states.json` 的 `headerOverrides.ima-mcp`（或 `connectors.ima-mcp.enabled`），**不在 `~/.workbuddy/mcp.json`**。原 `check_ima_mcp.sh` 只扫 mcp.json → 恒返 `IMA_MCP_UNAVAILABLE`（exit 2），属**假阴性**：第42期（10/19）被它误判"iMA 不可达"而跳过上传，但当时 ima-mcp **实际已连通**（连接器托管、会话内可用）。
- **处置铁律（不变）**：**未上传成功绝不伪造成功**（LTI 铁律：REJECT=0 才准交付）。三处本地副本完整可独立消费。
- **健康检修复（✅ 2026-10-19）**：`check_ima_mcp.sh` 已修正——关1a 扫 mcp.json，关1b 扫连接器状态目录；两关均未发现才 exit 2，且 exit 2 语义改为**"配置层未发现，交运行层复核，非最终判定"**（见上方阶段1.5 判读表），**不再无条件跳过阶段5**。自动化提示词阶段1.5 同步硬化：exit 2 须再经 `<connector-status>`/ToolSearch 运行层复核后才决定是否跳过。
- **补传闭环（✅ 2026-10-19）**：运行层确认 ima-mcp 连通后，已将 **第37–42期共 6 期**周报全部 `create_media`→COS→`add_knowledge` 补传至「小强律师办案系统」（KB 7456591255195718），`DUPLICATE_NAME_STRATEGY_CANCEL` 防重复；`get_knowledge_list` 复核 6 期均在库、`parse_progress=100`。原"历史待补 37–41"与"第42期缺口"**已清零**。
- **阶段1.5（✅ 已实施 · 2026-10-12，2026-10-19 勘误）**：已固化进「每周法律资讯收集」自动化，调用 `check_ima_mcp.sh` 做配置层判读（0=配置OK→ToolSearch 运行层复核→上传；2=配置层未发现→运行层复核，非最终判定；1/3=检查自身异常→保守判不可达、绝不伪造成功），取代每期手动三重复核。详见上方判读表。

## 六条铁律
1. **六-B 前置**：按期号新建文件，绝不以固定文件名覆盖既有单源周报；覆盖前必须先 `cp` 备份。
2. **时间 `date` 取**：created/updated/覆盖周期一律 `shell date` 取，不手写不估。
3. **否定型结论双复核**：凡"无/不存在/为0"类结论，未换第二种工具复核前视为未验证（grep→Glob→专用工具）。
4. **法条不凭记忆**：引用法条以本地权威源回填为准，缺全文标 `statute_text_pending`，不得引为文档源。
5. **iMA 不伪造**：上传失败如实记录缺口，绝不伪造成功。
6. **三处一致性**：本地三处副本必须 `md5` 一致，不一致即回查重跑。
