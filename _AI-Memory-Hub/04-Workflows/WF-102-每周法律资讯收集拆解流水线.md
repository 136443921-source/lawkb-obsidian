# WF-102 · 每周法律资讯收集拆解流水线

> 沉淀自 2026-10-12 第41期周报生成 + 全41期运行复盘。把"每周法律资讯收集"自动化拆成六段线性流水线：触发定周期 → 全网采集 → 筛选撰写 → 本地三处同步 → iMA知识库上传 → 提炼建卡+记忆写回。实证：第41期三处本地副本 md5 一致（ca413628…），唯一长期缺口为第5阶段 iMA 上传（第36–41期连续失败）。

## 适用场景
- 每周一 09:00 自动化触发生成最新法律资讯周报（亦支持手动触发）。
- 需要把全网法律法规动态、最高法/检典型案例、热点司法案例、实务趋势结构化沉淀。
- 周报产出后继续喂给"周报提炼建卡（方案B·草稿待审）"自动化生成规则卡。

## 六阶段流水线

## 阶段5 单点故障（重点）
- **现象**：第36–41期连续 6 期 iMA 上传失败。
- **根因**：ima-mcp 须在 WorkBuddy UI「连接器」页主动启用；自动化会话启动时长连接器清单静态加载，无法动态拉起 ima-mcp。openapi 旧凭证（~/.config/ima/）无权访问共享库（返 220004），旧脚本通道已废弃。
- **处置铁律**：**未上传成功绝不伪造成功**（LTI 铁律：REJECT=0 才准交付）。三处本地副本完整可独立消费；缺口记入 automation memory，待 ima-mcp 启用后由"提炼建卡自动化"后半程补传（历史待补：第37–41期）。
- **根治建议（✅ 已实施 · 2026-10-12）**：已在「每周法律资讯收集」自动化固化——新增 **阶段1.5 · iMA 可达性健康检查（降级核心）**，调用工作区脚本 `check_ima_mcp.sh` 做配置层判读（退出码 0=配置OK→再 ToolSearch 运行时核验 ima-mcp 工具可见→上传；2=`IMA_MCP_UNAVAILABLE`→跳过阶段5、周报 frontmatter 标 `ima_kb: unreachable`、日志记缺口；1/3=检查自身异常→保守判不可达、绝不伪造成功）。原"三重复核"之第2、3项由 ToolSearch 运行时核验自动替代，实现"跑完阶段1即判定可达性，省掉每期手动三重复核"。脚本已实测：当前 mcp.json 无 ima-mcp 条目 → `IMA_MCP_UNAVAILABLE`（退出码 2）。详见下方「阶段1.5」小节。

## 六条铁律
1. **六-B 前置**：按期号新建文件，绝不以固定文件名覆盖既有单源周报；覆盖前必须先 `cp` 备份。
2. **时间 `date` 取**：created/updated/覆盖周期一律 `shell date` 取，不手写不估。
3. **否定型结论双复核**：凡"无/不存在/为0"类结论，未换第二种工具复核前视为未验证（grep→Glob→专用工具）。
4. **法条不凭记忆**：引用法条以本地权威源回填为准，缺全文标 `statute_text_pending`，不得引为文档源。
5. **iMA 不伪造**：上传失败如实记录缺口，绝不伪造成功。
6. **三处一致性**：本地三处副本必须 `md5` 一致，不一致即回查重跑。
