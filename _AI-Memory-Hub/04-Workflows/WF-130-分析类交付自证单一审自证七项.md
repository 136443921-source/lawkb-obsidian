# WF-130 · 分析类交付自证单（一审自证七项）

> **一句话**：一审稿不该是"我写完了"，而该是"我写完了、并且我自己把它审过一遍了"。
> **不跑完这七项 = 未完成交付**，不是"质量略差"，是"没交"。

## 适用场景

**必须跑**：
- 复盘 / 诊断 / 体检报告
- 审查意见、方案评估、技术选型建议
- 接线方案、架构设计、流程改造方案
- 任何含"应该怎样 / 建议这样做 / 存在 N 处问题"判断句的交付

**不必跑**：
- 纯查询、纯转录、单步操作
- 老强已明确说"直接做/不用审"的情形

## 一、为什么需要它：一审出错的 6 类失效模式

> 来源：2026-11-01 事故（见第六节样本库）。11 处错误**没有一处是手滑**，全部可归类。
> M6 系同日第二次事故（状态值误报）补入，见样本库 R12。

| 类型 | 表现 | 真实根因 | 危险度 |
|---|---|---|---|
| **M1 标准漂移** | 用被审对象的口径当"正确标准"，还据此替它辩护 | 审查标准取自**被审对象**，而非独立权威源 | 🔴 最致命 |
| **M2 二手当真** | 被审对象自称什么就信什么；数量凭印象 | 把**自述**当事实，未实测 | 🟡 |
| **M3 静默失败** | 工具返回空 → 写成"零命中/不存在" | 工具失效未察觉，空结果当成结论 | 🔴 |
| **M4 术语空转** | 喊了某原则/规则名，做法却与该原则定义相反 | 引用了**名字**，未验证做法**是否满足定义** | 🟡 |
| **M5 全局失焦** | 前文说A、后文说非A；异质对象一锅端 | 分段写不互检；给动作不推演后果 | 🟡 |
| **M6 多源未择** | 同一事实存在多份文件（甚至同名同路径名），未判定哪份权威就引用 | 只查"有没有"，未查"是不是唯一、是不是最新" | 🔴 |

**核心教训（必须背下来）**：
1. **审查标准取自被审对象 = 最致命**。M1 会让你把要审的错误，固化成审查标准。
2. **假红队比没有红队更危险**。写"对方会怎么打我"是替对方设计防御，不是攻击自己。**真红队第一枪必须打自己的核心结论。**

## 二、自证七项（每项都有可检查的残留物）

> **判定铁律**：每项必须留下**残留物**（表格／清单／检索式／标注）。没留东西 = 没跑 = 未完成。

### ① 标准溯源

- **治**：M1
- **做法**：全文每个"应该怎样"的判断句，逐条标来源——法条号 / 实测结果 / 权威库 / 被审对象自述。
- **残留物**：标准溯源表（判断句 → 来源 → 是否独立于被审对象）。
- **硬规则**：**标不出来源 → 不许写这句话**。
- **为什么有效**：要求标注来源的那一刻，很多错误会自己暴露——"要我写来源，我才发现我没查过"。

### ② 自述降级

- **治**：M2、M6
- **做法**：凡引用被审对象（技能自述、文档声明、他人转述）的内容，一律先标 `[自述待验]`，实测后改 `[已验]` 或改写成实测结论。
- **残留物**：全文搜 `[自述待验]`，**有残留即未完成**。

#### ②-b 状态值引用三件套（2026-11-01 新增 · 治 M6）

报任何**状态类事实**（阶段／门禁／胜算／期限／金额／当事人状态）时，必须写成：

```
（源：文件名#字段或行号 @updatedAt 或 mtime）
```

三条硬要求：

1. **写不出字段名与时间戳 → 不许写这句话**。抄二手描述时必然写不出，此即"电"。
2. **先验唯一性**：确认该事实是否只有一份权威源。同名文件、`_副本`、桌面与中枢各一份 → 先比对 `updatedAt`／MD5，再决定引哪份。
3. **副本一律降级**：`案件笔记`／`作战室总纲`／`项目规则` 承载的是**结构**，不是**值**。它们的职责是指向原件，不是复述原件。

> 实证：2026-11-01 报"case-state 未回写"，实际原件已于 10-28 回写。错因不是抄错，是**引用了 10-13 的桌面旧版**——两份同名文件打架，我取了旧的那份（R12）。

### ③ 计数实测

- **治**：M2
- **做法**：凡写"N 个 / N 处 / N 项 / 最大编号 / 共 N 条"，必须回原始目录/文件数一遍。
- **残留物**：数字后附实测命令与结果。
- **实证**：本轮就靠这条抓到"中枢编号实为 WF-129 而非 WF-030"。

### ④ 零结果双证

- **治**：M3
- **做法**：凡写"零命中 / 不存在 / 未接线 / 未引用 / 没有"，必须**换第二种方法**复核（工具 A 换工具 B、bash grep 换专用检索工具），并留检索式。
- **残留物**：检索式清单 + 两次结果对照。
- **挂接**：与"否定型结论铁律""技术标识变体假阴性铁律"同源，本条是其在**审查场景**的执行细则。

### ⑤ 术语三件套

- **治**：M4
- **做法**：引用任何原则/规则/铁律的名字时，必须同时写出：**名称 → 该原则的定义 → 本文哪一句满足它**。
- **残留物**：三件套对照表。
- **硬规则**：**三缺一即空转**，删掉该引用或改正做法。
- **同类**：引用规则编号（如 E1004、RULE-016）时，必须核**适用范围**，不得扩大适用。

### ⑥ 矛盾扫描

- **治**：M5
- **做法**：抽出全文所有**断言句**，两两比对；重点抓互斥判断（能用/不能用、合规/不合规、适用/不适用、必要/不必要）。
- **残留物**：断言清单表（断言 → 出处章节 → 是否与他处冲突）。
- **典型**：第一节"该技能完全命中本案痛点" vs 第三节"本案用不上"。

### ⑦ 红队自攻

- **治**：M5
- **做法**：扮红队攻击**自己的核心结论**，第一枪必须对准最想让老强相信的那句话。
- **残留物**："我可能错在哪"清单（每条：攻击点 → 我的反驳 → 是否成立）。
- **禁止**：写成"对方会怎么攻击我的建议"——那是替对方设计防御，是假红队。

## 三、与已有铁律的关系（不是新增规则，是接线）

| 已有铁律 | 本单如何挂接 |
|---|---|
| **RULE-016** 引法条必核 sxx 时效性 | → 第①项「标准溯源」的直接执行细则 |
| **否定型结论铁律 / 技术标识变体假阴性铁律** | → 第④项「零结果双证」的执行细则 |
| **引用法条精准（第X条，禁"相关规定"）** | → 第①项，来源必须精确到条号 |
| **RULE-011** 二次复盘前置 | 本单是**交付前**自证；RULE-011 是**执行前**征求确认。两者前后衔接，不重叠 |
| **长标识写全值铁律** | → 第③项「计数实测」的同类，凡长度/编号必断言 |

> ⚠️ **本单要解决的正是"RULE-016 沉睡"问题**：RULE-016 内容正确，但只有一行文字、没绑工序，所以在 2026-11-01 事故中被跳过。
> 有脚本的 RULE-011 极少再犯，只有文字的 RULE-016 反复漏——**规则必须带电，不带的会睡**。

## 四、边界声明（诚实条款）

1. 七项按设计可覆盖 2026-11-01 事故的**全部 11 处错误**，但**不等于零错误承诺**——新领域知识盲区仍需人工判断。
2. 本单最大风险是**本身被跳过**（重演 RULE-016 沉睡）。因此判定标准写死为：**没留残留物就是没跑**，不认"我记得跑了"。
3. 角色定位：本单把老强从**校对员**（找哪里写错，约 1 小时）还原为**决策者**（判断要不要这么干，约 5 分钟）。**若本单失效，这个成本就会转嫁回老强身上。**

## 五、执行流程（三步）

```
写完初稿
   ↓
跑七项，逐项留残留物（表格/清单/检索式/标注）
   ↓
任一项无残留物 → 回退补跑，不得交付
   ↓
七项齐全 → 附「自证单执行记录」一并交付
```

**自证单执行记录**（附在交付物末尾，固定格式）：

```
【自证单执行记录】
① 标准溯源：N 条判断句，来源已标 N/N
② 自述降级：[自述待验] 残留 0 处
③ 计数实测：核对 M 个数字，改正 K 个
④ 零结果双证：L 处否定结论，均已二次复核（检索式见附表）
⑤ 术语三件套：引用 P 个术语，三缺一 0 个
⑥ 矛盾扫描：Q 条断言，冲突 0 处
⑦ 红队自攻：自攻 S 点，成立 T 点（已改 T 点）
```

- **R11**：最隐蔽。工具不报错、返回空，看起来像"确实没有"。**静默失败比崩溃危险**。

## 七、副本腐坏处置规程（2026-11-01 新增 · 普查后立）

> 触发：R12 后全系统普查，实测 9 份文档抄写了 6658 案状态值，并发现**双原件**。

### 7.1 三类文档，三种处置

| 类别 | 判别 | 处置 |
|---|---|---|
| **原件** | 状态真值载体（`case-state.json`） | **全局只准一份**。同名文件存在即视为 P0 事故 |
| **镜像** | 声称"当前状态"的规则／总纲／台账 | **改指针**：只留路径与"末次核对日期"，删掉所有具体值 |
| **时点产物** | 复盘报告、决策月报、历史日志 | **不改**。它们记录"当时是那样"，改了反而破坏历史 |

### 7.2 改指针的模板

```markdown
> 本节不复制任何具体值。一律现读：`<原件路径>`
> 引用必须带源标记：（源：文件名#字段 @updatedAt）
> 末次核对：YYYY-MM-DD，当时 <关键字段>=<值>
```

### 7.3 巡检（带电）

`99-脚本/check_mirror_staleness.py`：扫镜像目录，比对 `mtime` 与关键字值，
镜像旧于原件 → 报"陈旧"；镜像值与原件当前值不同 → 报"漂移"（更严重）。
