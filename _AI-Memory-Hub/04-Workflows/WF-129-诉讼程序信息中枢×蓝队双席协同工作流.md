# 🔗 诉讼程序信息中枢 × 蓝队双席协同工作流

> **一句话**：中枢负责「看见」程序信号，🔵-A 助理负责「整理成事实清单」，🔵 诉讼律师负责「定值与定策」，老强负责「点确认与签字」。
> 四个角色，**串行不并行**，每一步都有明确交付物与交接点。

---

## 一、触发规则（何时自动启用）

满足任一即启用，**无需老强显式下令**：

| 触发形态 | 例子 | 判定 |
|---|---|---|
| **程序问句** | 「什么时候开庭」「传票送到没有」「举证期还剩几天」「判决哪天生效」「上诉期过了吗」 | ✅ 启用 |
| **文书上传** | 传票照片、判决书 PDF、裁定书、送达短信截图、送达平台链接 | ✅ 启用 |
| **案号 + 程序词** | 「6658 号什么时候二审」「6660 撤诉裁定到了吗」 | ✅ 启用 |

**不触发**（避免误启用抢活）：

- 实体问题：「这份合同相对性怎么论证」「原告是不是买受人」→ 走 🔵诉讼律师 庭审准备 / 🔵-A 检索
- 文书起草：「写一份答辩状」→ 走文书流水线（中枢只供程序事实，不写正文）
- 纯法条咨询：「民诉法 174 条怎么说」→ 走 LTI / 法律检索

> 边界口诀：**问"什么时候/到没到/哪一天" → 中枢；问"为什么/怎么写/能不能赢" → 中枢不接。**

## 二、六步协同流程

```
① 触发判定
     ↓
② 中枢采集（一键 pipeline，模型只调度不插手）
     ↓
③ 助理整理 ──→ 【程序事实包】（5 字段交接单）
     ↓
④ 律师定值 ──→ 复核起算点 + 法律依据 → 写 case-state.deadlines[]
     ↓
⑤ 确认闸 ──→ 老强/律师点「确认归档」「确认提醒」
     ↓
⑥ 动作派发 ──→ 分流到庭审准备 / 文书 / 程序申请
```

### ① 触发判定

按上表分流。判定为"不触发"时**明确说出走哪条**，不要让中枢空转。

### ② 中枢采集（工具层，一步到底）

优先一键全链路：

```bash
python3 scripts/court_full_pipeline.py --sms "短信原文"
python3 scripts/court_full_pipeline.py --photo /path/to/传票.jpg
python3 scripts/court_full_pipeline.py --url "https://zxfw.court.gov.cn/..."
```

脚本自带 7 步：解析 → 下载 → PDF 解析 → 通讯录 → 归档 → 日历 → 通知+邮件。
**模型只做调度与呈报，不参与手工解析**，避免二次转述失真。

> 非 zxfw 平台（gdems / jysd / 湖北 / SFDW）会返回 `browser_download`，
> 此时才加载浏览器技能，**且严格串行降级，禁并行双保险**（中枢自身铁律）。

#### ✅ 归档落点：`--to-folder` 已打补丁可用（2026-10-29 22:35）

**原缺口 G6**：SKILL.md 文档声明「确认后带 `--to-folder <路径>` 重跑归档」，但 `scripts/` 下
8 个脚本 **grep `to-folder` 零命中**——文档先行、实现未跟上（空转指令）。
**已修**：`court_full_pipeline.py` 新增 `--to-folder`，函数级沙箱实测通过（两分支 + 幂等）。

```bash
# 一次到底：解析 → 下载 → 归档到独立子目录
python3 scripts/court_full_pipeline.py --photo /path/传票.jpg \
  --to-folder "/Users/chenyouqiang/Desktop/小强律师办案系统/01_案件-丁戊祥诉刘九零吊顶案(6658)/01_法院送达文书_中枢归档" \
  --no-remind

# ← 律师确认提醒计划后，单独创建提醒
python3 scripts/court_full_pipeline.py --remind-file /tmp/court_report.json
```

批次目录**自动生成**为 `{to-folder}/{命名文书}_{YYYYMMDD}送达/`，实测输出：

```
.../01_法院送达文书_中枢归档/传票_20261029送达/传票.pdf
```

**三条落点纪律（不变）**：
1. 落点固定为 `{案夹}/01_法院送达文书_中枢归档/{批次}_YYYYMMDD送达/`，**不直接铺在案夹根**；
2. **绝不触碰**既有 `00_-12_` 编号文件、`庭审十件套_6658_定版/`、`丁戊祥诉刘九零吊顶案/` 子目录；
3. 批次命名沿用中枢优先级：判决书 → 裁定书 → 传票 → **上诉状** → 受理案件通知书 → 其他（谁最"重"用谁）。

**幂等性（实测）**：同参数重跑同名文件 → 生成 `传票_2.pdf`，**不覆盖原文件**。
**兼容性（实测）**：不传 `--to-folder` 时完全走原桌面匹配逻辑，输出路径与打补丁前一致。


### ③ 助理整理 →【程序事实包】

🔵-A 助理把中枢 JSON 转成统一交接单，**五字段固定**，缺字段标 `未获取`：

```yaml
程序事实包:
  案号: (2026)黔0330民初6658号
  文书: 传票 / 判决书 / 裁定书 / ...
  送达日: 2026-10-28 15:20      # 来源标 zxfw.dt_cjsj / 落款日 / 短信时间
  送达日来源等级: 技术坐实 | 落款推定 | 未获取
  程序节点: 开庭 2026-11-05 09:30 · 习水县法院第二法庭
  期限候选: 答辩期 2026-11-12（民诉法174条）· 待律师核实起算点
  附件: 归档路径 + 原始 PDF 路径
```

**助理三条纪律**：
1. 送达日必须标**来源等级**——`技术坐实`（dt_cjsj）> `落款推定`（判决落款日，非送达日）> `未获取`。**禁止把落款日当送达日**。
2. 期限一律写「候选」，不写「应为」「必须」。
3. 产出标 **「初稿·待蓝队核」**，且**不得自行点任何确认键**。

### ④ 律师定值 → 写入 case-state

🔵 诉讼律师做三件事：

1. **复核起算点**：谁收到的、哪天收到、是否公告送达、是否多人不同日（缺口 G5）。
2. **核法律依据**：天数对不对、条号是否有效，未核标 `statute_text_pending`（`RULE-PROC-HUB-MOUNT` 第 4 条）。
3. **定值并落卡**：写入 `case-state.deadlines[]`，字段沿用现有 schema：

```json
{
  "id": "d7",
  "name": "二审答辩期（收到上诉状副本起15日）",
  "due": "2026-11-12",
  "type": "法定",
  "level": "P0",
  "state": "armed",
  "basis": "民诉法第174条｜送达日 2026-10-28（zxfw dt_cjsj 技术坐实）",
  "note": "中枢 procedure-facts 转真值；条号经 LTI 核验"
}
```

> 关键动作是**把 `due: null` 变成真日期**。6658 的 `d3` 正是长期 `due: null` 的状态。

### ⑤ 确认闸（人的手指）

- **归档确认**：中枢展示「匹配到既有案卷 + 命中依据 + 同名同姓风险」→ **律师/老强点确认**。
  - 6658/6660 当事人重叠，命中依据只有姓名时**必须拒绝自动归档**（铁律 5 混案识别）。
- **提醒确认**：展示提醒计划（案号/规则/各条时间与渠道）→ **律师/老强点确认**后才创建。
- 助理在此步只递交清单，**手不落键**。

### ⑥ 动作派发（中枢退出，交给下游）

| 程序节点 | 派发去向 | 承接席 |
|---|---|---|
| 开庭日确定 | 出庭六件套 / 质证提纲 / 法官三问 | 🔵 诉讼律师（🔵-A 供料） |
| 答辩期（一审） | 答辩状流水线 | 🔵 诉讼律师 |
| 答辩期（二审） | 答辩状（如 40 号）→ LTI 九维 QC → docx 双轨 | 🔵 诉讼律师 + LTI |
| 举证期 | 证据清单 / 补充举证 | 🔵-A 供料 → 🔵 定 |
| 保全到期 | 续封/续冻申请（到期日＝裁定日+期限−1日） | 🔵 诉讼律师 |
| 上诉期（对方） | 监控是否上诉 → 触发二审应对 | 🔵 诉讼律师 |
| 上诉期（我方） | 上诉状 + 接案/上诉价值评估 | 🔵 诉讼律师（定策） |
| 撤诉裁定 | 撤诉意见（如 19 号备用稿） | 🔵 诉讼律师 |

> 派发后回到既有三道门禁：红蓝复核 → LTI 五维 QC（REJECT=0）→ 六维门禁 → docx 双轨。
> **中枢不参与文书质量把关，它只保证"时间没搞错"。**

## 四、与既有流水线的接驳点

| 既有资产 | 接驳方式 |
|---|---|
| `case-state.json` | 期限真值终点；中枢只供候选，不直写（铁律 2） |
| 案件作战室总纲 | 效力顺序第 0 条不变；本流程落在「05_程序记录/期限台账」 |
| 桌面案卷（`00_-12_` 编号） | 中枢 10 目录需映射，**映射方案待老强拍板**（见缺口 G0） |
| 出庭六件套 / `trial-prep-pipeline` | 开庭日确认后触发阶段 1 |
| LTI 五维 / 九维 QC | 期限条文与文书正文的独立门禁，不因中枢而豁免 |
| 裁判规则库 | 程序类规则（答辩期、送达）建议补卡，现库偏实体 |

> **缺口 G0（已闭环 · 2026-10-29 老强拍板）**：中枢原生要求 `{原告}诉{被告} {案由}/` + 10 个固定子目录，
> 与 6658 桌面案夹的**扁平编号结构**（`01_民事答辩状…docx`、`31_庭后代理词…docx` 直接铺根目录，
> 另有 `庭审十件套_6658_定版/`）不兼容。
>
> **落地方案：独立归档子目录（不建 10 全套）** —— 只启用
> `{案夹}/01_法院送达文书_中枢归档/{批次}_YYYYMMDD送达/` 这一层，
> 既有 `00_-12_` 编号体系与十件套定版目录**一律不动**。
> 该决定已写入 `config/case-root.json`（`archive_policy: subfolder_isolated`）。
