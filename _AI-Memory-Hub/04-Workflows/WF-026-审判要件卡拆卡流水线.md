# WF-026 · 审判要件卡拆卡流水线

> **一句话**：把法院《类案审判要件指南》类 PDF 里的"该怎么判"正向裁判规则，拆成知识飞轮审判要件卡，六层挂载落库，供模拟法庭法官智能体（judge_reviewer）消费。
> 源：~/.workbuddy/skills/审判要件卡拆卡流水线/SKILL.md（v1.33.0）。本卡只沉淀方法论，不载个案。

## 适用场景
- 拿到审判要件指南 / 裁判指引 / 类案指南类 PDF，要给模拟法庭法官智能体喂「正向裁判规则」时。
- 与 [[WF-025]]（模拟法庭红蓝对抗推演）配套：本流水线产出 = 法官心智的「正向裁判知识底座」。

## 标准步骤（六层 SOP 精炼）
1. **定位活跃库（勿凭记忆）**：`/Users/chenyouqiang/Documents/LawKB/知识飞轮系统/`，六层 `01-采集/02-提炼/03-连接/04-LOG/04-巩固/05-调用/06-沉淀`。主卡落点 `06-沉淀/裁判规则库/<领域>/`。
2. **读编号规范 + 实地取号**：取号唯一入口走 `03-连接/scripts/next_rule_id.py -d <域> --n <本批张数>`（详见 [[WF-024]] 取号/撞号治理）。五铁律：①禁 find/凭记忆手工取号；②一次取满；③落盘即 commit；④口径只看 frontmatter `rule_id`；⑤建卡后必跑 `rule_id_guard.py --since 60`（门禁红着等于没门禁）。**域码以物理目录为准**，白名单领域名仅作检索提示。
3. **提取 PDF 文本**：先判文本层——抽样 20 页测 `len(get_text())`，绝大多数 <50 → 纯扫描件，必须 tesseract OCR（**用 stdin 传图**，勿先 save 到目录再读，沙箱会假报错 `image file not found`）；有文本层直接 fitz 提取。
4. **拆卡（只从三节挖）**：指南骨架 `概述→审理难点→审理思路(审查要点)→抗辩审查→其他问题(争议裁判规则)→附录案例`。审理思路→审查要点卡；抗辩审查→抗辩但书卡；**其他问题/争议裁判规则价值最高**→该怎么判卡。每卡覆盖一个争点，约 5 页/卡。
5. **法条正文回填（绝不凭记忆）**：`elements` 只描述要件不内嵌法条正文。正文三通道回源——A 北大法宝（按条号取原文最准）/ B 华宇元典（语义检索兜底）/ C 企查查法律数据 qcc-legal（第三通道·互补非降级），**只取「现行有效」**。判定「MCP 不可用」须走完整 6 步流程（完整限定名 ToolSearch→模糊查→读 connector-states.json `enabled`→真调用看报错→勿用 mcp.json 判断），三通道均不可用才降级权威公开源并**如实标「权威源核填」**，不可虚标。
6. **卡片八段格式（v1.0 固定）**：frontmatter 含 `card_type: 审判要件卡` + `rule_id: R-<域>-<三位>` + `ruling{support/reject}` + `burden_of_proof` + `negative_sample`。正文八段：裁判规则(正向·该怎么判)/审查要点/构成要件与举证/法条依据(元典核填·现行有效＋`### 官方核验指引`子节)/抗辩与但书/翻车标本/来源与地域效力/关联。**法条核验段统一套 `_模板_法条核验段.md`，勿逐张手补**。
7. **六层挂载（落库最后一公里，别只建卡不挂载）**：06 主卡→03 概念页(卡型对照+全量索引)→02 入库索引(清单+法条溯源+数字留痕)→05 调用记录→04-LOG(**append-only** 追加)→规范登记(`_规则卡编号体系规范.md` 新增卡型章节+刷新取号基线+登记批次)。消费方接「`小强律师数字分身系统/07-系统搭建与Skill配置/法律类skill配置迭代-九阳神功/AI模拟法庭法官skill配置说明书.md`」法官心智四步推理链（定位审理环节→逐项涵摄→举证校验→裁判预判+但书提醒）。**铁律 R2：机器只给候选(`【候选·待人工确认】`)，不自动裁判**。
8. **收尾核验（挂载完必做）**：8 项逐条 `ls`/`grep` 实地复核不靠记忆——主卡落盘数=计划数、卡型总数对总索引、交付校验 `ERROR 0/WARN 0`、六层每层文件真实存在、规范 `version` 与变更记录表一致、待办已勾选、备份项齐全、**消费方文件真实存在(`ls -l` 贴路径字节数)**。

## 红线
- **审判要件卡 ≠ 要件映射卡**：绝对不把审判要件内容塞进 `lti_element_cards.json`（那是负向拦截层，会破坏语义纯度）。
- **取号唯一入口**：`next_rule_id.py`，禁止 find/sort/凭记忆手工取号；建卡后必跑 `rule_id_guard`（见 [[WF-024]]）。
- **法条绝不凭记忆**：通道降级须如实标注核填来源，不可虚标「元典核填/法宝核填/qcc 核填」。
- **YAML 安全**：frontmatter 内**禁止写 `[[wikilink]]`**（YAML 解析成流样式序列→整卡崩）；块标量 `key: |` 内容须缩进 2 空格。
- **六-B 安全铁律**：改已有文件前先 `cp -n` 备份到 `/tmp/<主题>备份_<时间戳>/`；批量写入前 dry-run 查重（文件名冲突须为 0）；04-LOG 只能追加；**中间资产（映射表/章节骨架/提取文本）必须落持久目录（如 `02-提炼/审判要件卡/`）禁留 `/tmp`**（automation 下次跑会失效）。
- **路径须 find 确认真实存在**：曾记消费方 `judge_reviewer/SOUL.md` 全库不存在，日志写得再详≠接入。
- **规范升版两处同步**：文末变更记录表 + frontmatter `version` 字段一起递增，缺一即残留。

## 产出
- `R-<域>-<三位序号>` 审判要件卡（八段格式），挂入六层，喂模拟法庭 judge_reviewer 正向裁判底座。
- 关联卡族：要件映射卡(负向拦截) 与本卡(正向裁判) 物理区分、互补消费。
