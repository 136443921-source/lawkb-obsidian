# WF-数字员工增员减员更新花名册

**版本**：v1.0　**日期**：2026-09-24　**配套规则**：`00-全局规则/RULE-EMP-ROSTER-UPDATE`
**触发**：任何数字员工增员 / 减员（操作工自动化增删、心智模型席位建撤/更名/扩编/转正）
**目标**：保证《数字员工花名册》三处副本（json+md+中枢）逐字一致、零漂移

---

## 流水线（5 步）

### S1 · 发起动议
- 操作工侧：数字资产运维官提出（如新自动化上线、停用、删除、工种班调整）；
- 席位侧：律所主任提出（依据 `09104 数字员工编制方案` 的新建/裁撤/更名/扩编/转正）；
- 动议须含：增/减对象、理由、影响范围、是否触碰四类 R 动作红线。

### S2 · 老强批准（硬门槛）
- **老强（唯一股东·超级管理员）拍板** 后方可执行；
- 减员 = 破坏性动作，先按六-B 铁律 `cp` 全量备份再动；
- 席位建制变动须遵守 `RULE-BLUE-DISAMBIG` / `RULE-QCJUDGE-DISAMBIG`（蓝队四席独立、AI模拟法官≠QC）。

### S3 · 更新三处副本（原子、同日）
1. `LawKB/OPC 一人公司/00-数字资产登记册/数字员工花名册.json`
2. `LawKB/OPC 一人公司/00-数字资产登记册/数字员工花名册.md`
3. `_AI-Memory-Hub/09-OPC/09-5数字员工花名册/数字员工花名册.json` + `.md`

- 操作工：增删 `operators[]`（op_id 顺序延续，不重用已注销号）；
- 席位：增删 `seats[]`（seat_id 顺序延续）；
- 同步刷新 `counts`（操作工总数 / 席位总数 / 数字员工总编制 / 各工种 / 各中台分布）；
- 在花名册「八、变更日志」追加一行（版本/日期/类型[增·改·删]/摘要/来源）。

### S4 · 联动回填
- 席位侧变动 → 同步更新 `09104 数字员工编制方案`（名单/更名/扩编/§2.2 非员工实体留痕），保持与花名册口径一致；
- 资产级登记册 `asset_registry.json`（AU 条目）如涉及，同步补登/注销。

### S5 · 校验（写入后必做）
- json 合法：`python3 -c "import json;json.load(open(p))"`；
- 计数一致：`len(operators)+len(seats) == counts['数字员工总编制']`；
- 三处 `counts` 字段逐字相同（diff 比对）。

---

## 反模式（禁止）
- ❌ 只改一处（如只改 json 忘改 md / 只改 LawKB 忘改中枢）→ 漂移；
- ❌ 凭印象清理 `paused` 待用员工（须先出"僵尸率/存活率"监控结论）；
- ❌ 减员不备份、不回填 `09104`、不追加变更日志。
