## 五步法

### 步骤 1 · 量化影响面（先侦查，别盲跑）
```bash
find 02-提炼/经验卡片 -name "*.md" | wc -l     # 卡片数
find 06-沉淀/裁判规则库 -name "*.md" | wc -l   # 规则数
du -sh 02-提炼/经验卡片 06-沉淀/裁判规则库      # 备份体积
```
确认新卡所在**规则子目录**在 `GROUPS` / `RULE_MERGE` 中映射到哪个 cat 与枢纽文件。
（例：子目录 `通用` → cat `程序知识`+`法条解读` → 共享枢纽 `连接枢纽-通用程序.md`）

### 步骤 2 · 全量备份（cp -R，勿省）
```bash
BK=/tmp/连接层补链备份-$(date +%Y%m%d-%H%M%S); mkdir -p "$BK"
cp -R 02-提炼/经验卡片 "$BK/经验卡片"
cp -R 06-沉淀/裁判规则库 "$BK/裁判规则库"
cp 03-连接/连接枢纽-*.md "$BK/连接枢纽/"
cp 03-连接/scripts/link_lastrun.json 03-连接/scripts/link_neighbors.json "$BK/"
cp 03-连接/scripts/link_cards_rules.py "$BK/"   # 连脚本一起备，防版本误判
```

### 步骤 3 · 跑补链
```bash
python3 03-连接/scripts/link_cards_rules.py
```
看三个输出：`裁判规则覆盖 X/Y`（应 Y=Y、无游离目录）、`处理笔记文件数`、`LINK_STAT {...}`。

### 步骤 4 · 双重验证（v3.1.1 血泪教训）
> 历史 bug：共享 hubfile（`程序知识` + `法条解读` 共用 `连接枢纽-通用程序.md`）被逐类 `open("w")` 覆盖，
> 导致先写分类的卡**每卡 related_links 有，但 MOC 页看不见**。故必须**双重验证**：

1. **枢纽页可见性**：`grep -n "R-PR-17[89]\|R-PR-18[012]" 03-连接/连接枢纽-通用程序.md` + 链接数对比基线
2. **每卡 related_links**：frontmatter 中 `related_links:` 段存在且含枢纽
3. **链接目标存在性**：related_links 逐条 `find -name "$t.md"` 验证（防新断链）
4. **断链归因**：跑 `check_links.py -i -d 1`，确认报告**未出现**新卡编号（否则是本次引入的）

### 步骤 5 · 幂等验证（重跑一次）
再跑一次补链，确认：人工段落存活、自动补链段**不叠加**、枢纽页链接数**稳定**。
这一步同时是对 v3.1.1 覆盖 bug 的反向回归测试。

## 增值动作：族内导航段（推荐）

同族卡（5 张新卡）与既有相关卡（如 R-PR-085 / R-PR-049 / R-PR-109）之间，
自动补链的 top-5 限幅**不会把它们串成族**。建议手工加一段：

```
## 族内导航 · <卡族名>卡族（人工维护 · YYYY-MM-DD）
| 序 | 卡片 | 回答什么 |
| ① | [[R-PR-178-...]] | 授权成不成立 |
...
**既有同族卡（非本次新建）**：- [[R-PR-085-...]] — ...
```

**安全要点**：插在 `## 关联（知识飞轮连接层自动补链` 段**之前**。
脚本按稳定前缀切分 body，只替换自动段，**人工段原样保留**（已实测）。

## 关键教训：多口径检索（本次最大收获）

**事故**：建卡前判定「诉讼代理授权瑕疵 → 起诉条件」域为空白，据此建了 5 张卡。
接入时才发现 `R-PR-085`（2026-09-11 建，subtype 冒名诉讼程序战）**早就在库**。

**根因**：检索词用「授权委托书／无权代理／代理权／诉讼代理」，
未命中 R-PR-085 的用词「**授权意思表示**」——同一域、不同措辞。

**规则**：
1. 检索裁判规则库须**多口径并行**：法律术语 + 通俗表述 + 构成要件表述 + 法条路径（如"143条""意思表示真实"）
2. 判定「域空白」是**重判断**，须至少 3 组不同检索词 + 一次目录级扫描后才可下结论
3. 结论写「**单点卡 + 缺链条**」而非「空白」——后者会误导后续建卡定位
