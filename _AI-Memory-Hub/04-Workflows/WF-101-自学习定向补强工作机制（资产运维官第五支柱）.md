# WF-101 · 自学习定向补强工作机制（资产运维官第五支柱）

> **来源**：复盘「人伤裁判规则定向补强自动化 v1.3」(automation-178391965225，每周三 20:30) 四轮实测，抽象为一人公司通用的**自学习定向补强**能力，嵌进资产运维官体系（数字资产登记册 SSOT + 监控矩阵 8 维 + 规则包封装），不另起炉灶。
> **方案正本**：`OPC 一人公司/自学习定向补强工作机制方案-v1.0.md`
> **脚本底座**：`OPC 一人公司/02-监控/{gap_sense.py, trw_scheduler.py, trw_backfill_sla.py, trw_health_blend.py}` + `01-规则包/gen_rule_package.py`
> **与其他 WF 的关系**：复用 WF-002（LTI 五维 QC）、六-B 备份铁律、编号门禁（WF-024）。本机制是监控矩阵 D1（编目覆盖率）的"行动臂"。

---

## ① 适用场景

- 一人公司知识资产（规则卡 / 笔记 / 规则包）随业务实战**持续 thickening**，而非依赖人工一次性灌库。
- 任意已编目域（人伤/合同/公司/刑事…）出现**覆盖率缺口**或**待回源堆积**时，自动感知 → 定向生成补强 → 安全写入 → 建链 → 回源 → 留痕 → 刷新监控，闭环自强化。
- 域无关：换域只改"缺口扫描口径"和"域模板"，引擎不变。

---

## ② 机制复盘：人伤补强做对了什么（7 原则）

| # | 原则 | 复盘结论（为什么有效） |
|---|------|----------------------|
| P1 | **缺口驱动，不盲目生成** | 每轮先扫索引 MOC + 主文件找零覆盖子主题，再生成。避免自嗨堆量 |
| P2 | **跨格式去重护栏** | 写入前扫「主文件+子目录卡+既有笔记」三重，命中转引用链接不重复写。根除重复写库 |
| P3 | **职责边界硬约束** | 补强只写子目录，绝不碰主文件（那是入库任务地盘）。多任务并行不撞车 |
| P4 | **本地源引证铁律** | 法条全部从本地法律法规库逐字回填（`statute_text_pending:false`），不凭记忆 |
| P5 | **降级范式不编造** | 元典余额 0 时案号标 `yuandian_source_pending:true`，不编造案号，待领额度一键回源 |
| P6 | **六-B 安全前置** | 改单源前 `cp` 备份 + 验字节一致；本任务仅新增不覆盖单源 |
| P7 | **留痕 + 进度双写** | 每轮在 automation memory.md 记一行 + 刷新进度追踪。无人值守也能审计 |

> 四轮已验证：R-PI 水位 535、人伤笔记 221 篇、全库 R-PI 卡 100 条，**零重复写库 / 零幻觉法条 / 零备份事故**。唯一待解风险：降级 pending 卡堆积 → 需设回源 SLA（见 G6 / P2）。

---

## ③ 六阶段引擎（TRE, Targeted Reinforcement Engine）

```
G1 缺口感知  读登记册+包manifest，算 域缺口率=1-实测/目标；缺口率>30% 或 子主题0卡 → 入队
      ↓
G2 选题排期  零覆盖域优先，再按缺口率取 Top-N（N=每轮配额）；回源队列从 pending 聚合
      ↓
G3 定向生成  按域模板产 笔记+规则卡，法条本地源逐字回填
      ↓
G4 去重护栏  跨格式三重扫描(主文件+子目录+笔记)；命中 → 转 [[引用链接]] 不重复写
      ↓ 未命中
G5 质检门禁  六-B 备份 → LTI 五维 → 编号门禁(取号双维度)
      ↓ 全 PASS
G6 回源+留痕  案号标 pending(元典有额度回源) / memory.md一行；登记册刷新+包manifest刷新+进度更新
      ↓
      └── 回 G1（下一轮复跑，水位持续+）──
```

**脚本映射（均已落地、只读不写知识库真源）**：

| 阶段 | 脚本 | 职责 | 写入 |
|---|---|---|---|
| G1 | `gap_sense.py` | 缺口感知器：零覆盖域 / 低覆盖 Top-N / pending 聚合 | 仅 `gap_report.md/.json` |
| G2 | `trw_scheduler.py` | 补强调度器：选题排期 + 回源队列；`--refresh-packages --apply` 刷新包 | 仅 `trw_plan.json` |
| G6 回源 | `trw_backfill_sla.py` | 回源 SLA：聚 pending 卡龄期， oldest-first 回源队列 | 仅 `backfill_plan.md/.json` |
| G6 月报 | `trw_health_blend.py` | 健康月报融合：gap+backfill 合并为月报片段 | 仅 `trw_health_monthly.md` |
| G6 刷新 | `gen_rule_package.py --domain <域>` | 补强后刷新对应包 manifest（实测条数/待核验源数） | 包目录（需 `--apply`） |

## ④ 触发与排期

| 域 | 频率 | 每轮配额 | 触发方式 |
|----|------|----------|----------|
| 人伤法 | 每周三 20:30 | 2-3 子主题 / 5-10 卡 | 专用自动化（保留 automation-178391965225） |
| 合同/公司/刑事… | 双周 / 月 | 1-2 子主题 / 3-5 卡 | 通用调度器 `trw_scheduler.py` 按 D1 阈值自动排期 |
| 全局 | — | — | 监控矩阵 D1 覆盖率 < 70% → 强制入队 |

> 专用自动化（人伤）与通用调度器（多域）**并存不冲突**：人伤走高频专用通道，通用调度器兜底其余域，统一走 G1-G6。

## ⑤ 执行动作（单轮补强 SOP）

| # | 动作 | 命令 / 工具 | 产出 |
|---|---|---|---|
| 1 | 缺口感知 | `python3 gap_sense.py --target 200` | `gap_report.md/.json` |
| 2 | 选题排期 | `python3 trw_scheduler.py --top 3 --subtopics 3 --cards 8` | `trw_plan.json`（dry·未写库） |
| 3 | 定向生成 | 按域模板产笔记+卡（G3） | 新增 md |
| 4 | 去重护栏 | G4 三重扫描（脚本辅助/人工核验） | 不重复写 |
| 5 | 质检门禁 | 六-B 备份 → LTI 五维 → 编号门禁 | REJECT=0 |
| 6 | 回源留痕 | 案号标 pending / memory.md 一行 | 留痕 |
| 7 | 刷新包+登记册 | `python3 trw_scheduler.py --refresh-packages --apply`（仅包域） | 包 manifest 刷新 |
| 8 | 回源 SLA | `python3 trw_backfill_sla.py`（元典有额度时回源） | `backfill_plan.md/.json` |
| 9 | 月报融合 | `python3 trw_health_blend.py` | `trw_health_monthly.md` |

> **红线**：步骤 2/7 默认 dry，零知识库写入；任何改真源动作须主任（老强）拍板或显式 `--apply`。包刷新（`--apply`）是**重建子集导出**，不改源资产（gen_rule_package 设计铁律）。

---

## ⑥ 红线（最高等级强制）

1. **六-B**：改单源前 `cp` 备份 → dry-run → 改 → 复测 → 验幂等；禁止整文件重建主文件。
2. **不编造案号**：元典余额 0 时标 `yuandian_source_pending:true` 降级，绝不伪造案例。
3. **本地源引证**：法条一律本地法律法规库逐字回填，外部源仅作线索。
4. **个案卷宗/当事人隐私绝不入册、绝不入包**（资产运维官红线 2）。
5. **跨格式去重 + 三任务职责边界**：多任务并行防重复写库；补强只写子目录。
6. **编号门禁**：取号双维度（文件名 + frontmatter rule_id 扫描取较大者+1），撞号即停。
7. **慢盘防护**：缺口扫描走 mtime 增量缓存，不 walk 整棵知识飞轮系统（D7：42.77s→0.31s）。
8. **无生产决策权**：调度器/感知器只读不写真源；`--apply` 刷新包属导出重建，仍需显式授权。
