# WF-030 · 静态看板数据管线五道护栏

> 姊妹篇：[[WF-029-静态看板改版前端三坑排障流水线\|WF-029]] 管"改了为什么不显示"，本卡管"改完之后为什么又没了"。
> 沉淀自 2026-09-14 驾驶舱改版：**页面改对了、也验证过了，但下一次跑脚本就全部归零**——这才是真正的白干。

## 适用场景
- 静态看板由「还原脚本 / 重扫脚本 / 构建脚本」定期刷新
- 手工定制的字段、条目、排序需要长期存活
- 需要批量改写文件（Python `re.subn` / sed）

## 护栏一：识别并锁死「破坏性还原脚本」

**事故原型**：`build_restore.py` 从**旧源**（`2026-09-05-03-33-49/cockpit-portal/portal`）1:1 覆盖 `index.html`/`auth.js`/`rbac.js`/`scorecard_data.json`/`workbench.html`。**跑一次，当天全部定制（C0–C9 编号、排序、新增屏）抹得干干净净**，且没有任何提示。

**排查动作**：凡是拿到一个看板项目，**先找谁会写这些文件**：
```bash
grep -rl "scorecard_data\|<目标文件名>" --include="*.py" --include="*.sh" .
```
找到后读一遍，判断它是「增量刷新」还是「整份覆盖」。

**加固模板**（覆盖式脚本必加）：
```python
if "--force" not in sys.argv:
    print("🔴 本脚本将从旧源 1:1 覆盖，默认拒绝执行。确需还原请 --force")
    sys.exit(2)
BK = "/tmp/<proj>_restore_backup_" + datetime.now().strftime("%Y%m%d-%H%M%S")
os.makedirs(BK, exist_ok=True)
# 覆盖前 cp 每个目标文件进 BK
```
**红线**：默认拒绝 + 必须 `--force` + **强制先备份**。三者缺一不可。

## 护栏二：重扫脚本必须「认识」新字段

**事故原型**：`rescan_scorecard.py` 眼里只有 `KEY_MAP` 里那 8 个老 key，不认识 `cno`、不知道有 `cloud`、也不排序。下次刷新：`cno` 全丢、C0 条目蒸发、顺序打回原形。

**加固清单**（重扫类脚本写入前一律加）：
1. **补字段**：`CNO_MAP` 把 key 映射编号，写入时自动带上 `cno`；
2. **保留特殊条目**：不计分 / 手工条目（如 C0）预置为常量，写入前 merge 进去，避免被扫描结果覆盖：
```python
CLOUD_SCREEN = {"cno":"C0","key":"cloud","weight":0,"score":None,"scoring":False}
```
3. **统一排序**：写入前 `screens.sort(key=cno_rank)`（C0→99 压尾，无编号→98）；
4. **自洽校验排除不计分项**：
```python
scored = [s for s in screens if s.get("scoring") is not False]
assert abs(sum(s["weight"] for s in scored) - 1.0) < 1e-6, "计分屏权重合计必须归一"
```

## 护栏三：批量正则必须「断言命中数 + 可回滚」

**事故原型**：`re.subn` 分组写错——`m.group(2)` 取到的是 `(\s*)?` 而不是 key，结果**只命中 2 条**（预期 8 条），剩下的静默漏改。

**三件套**：
```python
new_block, n = re.subn(pattern, repl, block)
assert n == 8, f"预期命中 8 条，实际 {n} 条 —— 回滚重来"   # ① 断言命中数
# ② 断言零残留：'cardfamily' not in s
# ③ 断言唯一性：s.count('key:"contractlifecycle"') == 1
```
**铁律**：断言失败 → **从备份回滚再重跑**，绝不原地打补丁。改前 `cp -n` 备份到 `/tmp` 时间戳目录。
> 分组踩坑记忆点：`re.subn(r'key:"([a-z]+)",(?:\s*cno:"C\d+",)?', ...)` 里，**group(1) 才是 key**，可选组用 `(?:...)` 不捕获就不会占号。

## 护栏四：无真源不补数 —— 宁可「不计分」也不造

**事故原型**：C0 云监控看板没有评分源。若在总表里凭空给它一个分数凑满十屏，**就是拿假数据冒充真实评分**。

**正确做法**：显式标记为不计分位，让系统自动排除：
```json
{"cno":"C0","key":"cloud","weight":0,"score":null,"scoring":false,
 "risk":"云能力 4/4 已启用，但 DB 0 表 / 端用户 0 人，属「已开通未启用」"}
```
- 页面渲染成「— / 不计分 / 监控位 · 不纳入评分」（虚线卡片 + 六维区换占位说明）
- 总分、加权合计、维度均价**全部自动排除**（用 `SCORED = SITES.filter(x => x.scoring !== false)`）

**红线**：**没有一级数据源就标 pending / 不计分，绝不凭记忆或凑数**。这与 [[WF-002-法条LTI五维QC门禁\|WF-002]]「法条必须本地权威源回填」是同一条纪律在前端数据上的延伸。

## 配套纪律：换屏必须换全套数据
复用编号换屏时（如 C7 从"系统卡族看板"换成"合同生命周期中台"），**只改名不换数据 = 拿旧屏 95 分冒充新屏**。六维、KPI、数据源、更新时间、风险项必须全部走新屏真源。副作用（总分下降）是真实数据的自然结果，**不得为了保分数而保留旧值**。

## 护栏五：并发补卡取号防撞（本卡自己踩到的坑）

**事故原型**：本卡落盘时按「`ls` 目录最大序号 +1」取号 → 取到 WF-027。但**同一分钟内另一个会话已建了 `WF-027-案件生命周期大屏流水线.md` 并入了索引**，只是文件还没落盘到我看到的那一刻。结果：
- 我的卡占了 WF-027 → 与别人撞号，且 backfill 脚本检测到「索引已含 WF-027」就**幂等跳过**，导致我的卡**根本没进索引**（最危险：卡存在但召回不到）；
- 我接着取的 WF-028 又撞上 `WF-028-知识飞轮卡库接线.md`（同一天、同目录、并发产生）；
- 两张卡全部重编号为 WF-029 / WF-030 才修好。

**根因**：**取号只看了文件名，没读 `_索引.md`**；而索引与文件系统在多会话并发下会短暂不一致（文件已写、索引待写；或索引已写、文件待写）。

**正确取号流程（补卡前必做）**：
```bash
# ① 索引为准（不是 ls）
grep -o "^| \[\[.*\]\] | WF-[0-9]*" 04-Workflows/_索引.md | grep -o "WF-[0-9]*$" | sort -V | uniq -c
# ② 文件系统交叉验证，找撞号
ls 04-Workflows | grep -o "^WF-[0-9]*" | sort -V | uniq -c | awk '$1>1'
# ③ 取 max(索引, 文件) + 1；两者不一致时以较大者为准，并顺手报告撞号
```
**让号原则**：发现自己的号与一张**已存在且 `status:active`** 的卡冲突时，**让号**（哪怕对方还没进索引），自己顺延 —— 对方可能正在补卡流程中，抢号会让双方都断链。

**补卡后必做自检**（写入索引后）：
```python
# 索引 wikilink 指向的文件必须真实存在；号位不得重复
bad = [t for t in re.findall(r'\[\[([^\]\|]+)\|WF-\d+\]\]', idx)
       if not os.path.exists(f"04-Workflows/{t}.md")]
```
**红线**：backfill 脚本的「索引已含该 id → 幂等跳过」是**保护机制也是陷阱**——它会静默跳过撞号卡。补完卡必须回索引确认**那一行指向的是自己的文件**，不是"有就行"。

## 标准步骤
1. **找写者**：`grep -rl` 找出所有会写目标文件的脚本
2. **分类**：整份覆盖 → 加护栏一；增量重扫 → 加护栏二
3. **备份**：`cp -n` 到 `/tmp` 时间戳目录（含脚本本身）
4. **加护栏**：按上述模板改脚本
5. **测护栏**：**实际跑一次破坏性脚本验证拦截生效**（`python3 build_restore.py` 应退出码 2 并拒绝）
6. **语法校验**：`python3 -m py_compile` / `ast.parse`，然后 `rm -rf __pycache__`
7. **幂等复核**：改完再跑一遍核对脚本，确认编号齐全、权重合计归一、无乱码

## 红线
- 🔴 覆盖式还原脚本：默认拒绝 + `--force` + 强制备份，缺一不可
- 🔴 重扫脚本必须补 `cno`、保留特殊条目、统一排序、排除不计分项做自洽校验
- 🔴 批量替换：`assert` 命中数 + 零残留 + 唯一性；失败从备份回滚，不原地补
- 🔴 **无真源不补数**，标 `scoring:false` / `statute_text_pending`，绝不造假
- 🔴 换屏必换全套数据，不借旧屏分数
- 🔴 **取号以 `_索引.md` 为准，`ls` 只作交叉验证**；撞号时让号给已存在的 active 卡；补完必须回索引确认那行指向自己的文件

## 产出
- 带护栏的还原/重扫脚本（含实测拦截证据）
- 改版成果在后续自动刷新中存活
- 备份目录 + 幂等复核报告
