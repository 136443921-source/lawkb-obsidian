# 多域竞合矩阵研判法（法律域识别与关系判定）

> 来源：2026-09-14 模拟法官中台"路B 重 agent（多域竞合深度研判）"节点。给定一段事实描述，识别候选法律域并判定域间关系（竞合 / 先决 / 牵连 / 吸收 / 排斥），输出候选主路径建议。
> 本条只沉淀方法论，个案识别细节不入中枢。

## 适用场景

任何需要从一段事实 / 争议描述中，自动识别"涉及哪些法律域（合同 / 侵权 / 物权 / 建工…）"并判定"这些域之间什么关系（能否同时主张、谁吸收谁、谁先决谁）"的研判任务。典型：违约责任 ↔ 侵权责任竞合（民法典 186 条择一）、建工合同吸收于承揽等。

## 一、域分类法（DOMAIN_TAXONOMY）

每个域配置：`{ label, statuteKeys:[...], keywords:[...] }`。关键词袋用于后续命中打分。

## 二、关系矩阵（CONCURRENCE_MATRIX）

预置域对关系：`竞合(择一主张) / 先决(甲成立方审乙) / 牵连(可合并审理) / 吸收(甲含乙) / 排斥(互斥)`。每条配教义依据（如民法典 186 条责任竞合、808 条建工吸收于承揽）。

**⚠️ 键序规范化（必看坑）**：矩阵键用 `域A|域B`，但查询时 `a|b` 与 `b|a` 顺序不确定 → **统一排序键**（`[a,b].sort().join('|')`）再查表，否则必漏配（实测「合同|侵权」查不到「侵权|合同」）。

## 三、匹配用短关键词命中，禁整句语义相似度

- **否决整句包含匹配**：`text.includes(fullPhrase)` 要求整句逐字命中，描述稍变即解析为空。
- **改用短关键词命中**：把争议描述拆成短 token（"违约" / "不付违约金" / "赔偿"），与关键词袋做 `includes` 命中计数，按 score 排序取候选域。可控、可回归、可断言。

## 四、主路径兜底（域优先级契约法）

多域命中时，主路径用**域优先级契约**（如合同优先于侵权）做确定性兜底，而非随机 / 按 score 平局。全输出 R2 标注（候选·待人工确认）。

## 五、输出契约

候选域（带 score） + 两两关系表（类型 + 教义依据） + 候选主路径建议（引用法条）。每候选可"→要件涵摄"一键驱动下游。

## 六、红线

- 只报域不报关系 = 失去竞合研判核心价值（必须报关系）。
- 关系判定须有教义依据，禁凭感觉。
- 全链路候选标注，不替用户拍板诉求性质。
