# WF-002 · 法条 LTI 五维 QC 门禁

> 每份法律文书交付前必须通过的文本监控器门禁。任一维度 REJECT 即不得交付。

## 五维定义
| 维度 | 含义 | 校验要点 |
|---|---|---|
| **R** (Rule) | 法条真实性 | 条号/条文须真实存在，优先以 pkulaw（北大法宝）为主源核验，绝不凭记忆灌条文 |
| **L** (Logic) | 法理逻辑 | 请求权基础、要件满足、推理链无断点 |
| **C** (Consistency) | 一致性 | 金额（301）、名称（302）、案号（304）等全文一致，无前后矛盾 |
| **T** (Trace) | 溯源 | 每条关键依据标注来源（法条/判例/内规），可回溯 |
| **P** (Procedure) | 程序 | 程序性事项（期限/管辖/送达/举证）无误 |

## 标准步骤
1. 文书草稿完成后调用 LTI 文本监控器（v4.8.1，R001–R020 / R101 / R103 / R111 + C301 等一致性规则）。
2. 逐维检查，记录各维度 PASS / REJECT。
3. 仅当五维全部 PASS（`REJECT=0`）才允许进入 docx 双轨交付（见 WF-001）。
4. 若有 REJECT：回到起草环节修正 → 重新过门禁，直至 `REJECT=0`。

## 红线
- **本地源引证铁律**：仅引用本地法律法规库源，否则标 `statute_text_pending` 不得引为文档源；权威数据绝不静默覆盖。
- 引用法条须精准到「第X条」，不写"相关规定"等模糊表述。
- 当事人信息须从桌面原始材料（如起诉状 PDF）实地核实填写，不凭记忆占位。

## 产出
- 门禁报告（R/L/C/T/P 五维 PASS/REJECT 清单）
- 交付准入结论：`REJECT=0` / 阻塞
