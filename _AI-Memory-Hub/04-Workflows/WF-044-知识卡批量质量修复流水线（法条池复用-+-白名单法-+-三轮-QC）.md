# 知识卡批量质量修复流水线（法条池复用 + 白名单法 + 三轮 QC）

> 沉淀自 2026-09-15 C 批 R-CF-156~171（16 张操作指引卡）三类质量问题修复。

## 适用场景
一批卡片存在**同类结构性缺陷**（缺法条 verbatim / 标题残留模板提示语 / 书名号误用 / 条号错误），需批量修复且不破坏原有段落结构。

## 核心方法

### 一、建「法条 verbatim 池」再复用，绝不凭记忆书写（PREF-004）
1. **先扫已核填卡**：从同库已完成官方核填的卡片（第五段）抽取 `> 来源：` + `**第X条**` + 正文，按法源归集为 JSON 池。
2. **本地权威库补缺口**：`法律法规库/` 按条号提取，补池。
3. **仍缺的**：标"引用前二次核对"，**不硬造**。
> 本次：池成 8 部法规 79 条，43 条直接复用，零回源成本。

### 二、《》误用用「白名单法」，不用黑名单
黑名单永远列不全（第一轮 10 张，第二轮又冒出 3 张 16 处）。
正确做法：扫描全部《》内名称 → 不在**法规白名单**者一律改「」→ 真实标准（MZ/T、行业规范、条例）加入白名单保留。

### 三、修复前必做「口径侦查」，顺带纠条号
读每张卡的依据段时会暴露**条号错误**，这类错误比格式问题严重得多。本次附带纠出 4 张：
- 条号张冠李戴（把 A 条内容安到 B 条）
- **条号不存在**（如慈善法第101条）
- **跨法规串号**（把慈善法条号写成信息公开办法条号）
- 时限口径错误（官方 5月31日 vs 手册 6月30日），且**不止一处**（会散落在流程段/红线/常见错误）

### 四、三轮式：dry-run → apply → QC 复验 → 二轮补漏
第一轮命中率不会 100%，**必须复验后再跑第二轮**。QC 脚本要覆盖"修复项清零"断言。

## 踩坑
- **切片取卡号带连字符**：`base[:9]` → `R-CF-156-`（尾部多 `-`），字典 key 永不匹配。必须 `re.match(r"(R-CF-\d+)", base)`。
- 更正说明里会保留"错误原文"（如"手册误作6月30日"），QC 需判断**语境**再判 ERROR/WARN，否则假报。
- 索引卡（速查/目录类）无实质条文，verbatim 块应改为「条文调用指引」表格并**单独豁免**。

## 脚本四件套（可复用）
`fix_*.py`（dry-run/apply 双模）→ `add_verbatim_*.py`（幂等补挂）→ `qc_*.py`（清零断言）→ `verbatim_pool.json`（资产）
