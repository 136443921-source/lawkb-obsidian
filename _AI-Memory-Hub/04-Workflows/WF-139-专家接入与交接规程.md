# WF-139 · 专家接入与交接规程

> **一句话结论**：专家的价值不在模型，在**角色预设 + 领域知识库 + 输出纪律**这三件套壳。
> 本系统三件套已厚于平台专家，缺的只是两处接口——**开场怎么问**、**换席位时怎么把「待核」标记带过去**。
> 本卡只补接口，**不重建目录、不新增专家包、不改既有技能的能力边界**。

> **立卡依据**：老强 2026-11-13 提供《WorkBuddy 法律专家指南》，要求总结方法论并评估数字分身系统提升路径；
> 评估结论为「照搬挂专家是降级，补两处接口即够」，老强选 **B 方案**并指令立即处理。
> 同类先例：`DEC-2026-031`（案件作战室提示词改造——**采纳骨架，不采纳目录**）。

## 一、定位与边界

| 线 | 内容 |
|---|---|
| ✅ 管 | ①接上任一专家／技能／席位后的**首轮输入组织** ②**跨席位／跨技能切换前**的交接 ③「待核」标记的跨轮传递 ④胜诉率类表述的**语境分层** ⑤法条效力核验的**输出形态** |
| ❌ 不管 | 不产对外文书、不替代法律定性、不替代 LTI 机检、不改路由表条目、不改法条核验源优先级、不新建专家包 |
| 🔴 同名异物 | 本卡「交接卡」**≠** `grill-me-legal-preprocessor` 的「需求对齐卡」（后者只澄清意图，见 `RULE-061 §三`）。两者**串联不替代**：对齐卡管「要问什么」，交接卡管「上一轮结论与待核项怎么带过去」 |
| 效力顺序 | 中枢 `RULE-060` / `RULE-061` / `RULE-038` / `RULE-057` > 本卡 > 下游技能 > 会话临时上下文 |

**三件套在本系统的现状（2026-11-13 实地查证）**：
- 角色预设：`法律智能体基座` 强制继承 + 元人格卡 + L1 私有 `profile.yaml` + 12 份 `*_persona_v1.md` → **厚而散**，不缺；
- 领域知识库：`legal-base` 三-C 章强制「案由先行定性／要件必须取卡／无对口卡降级标注」＋调用记录回写 → **最强的一件**；
- 输出纪律：LTI 运行时六模块 + 三道门禁（红蓝复核 → LTI → 六维）+ 双清单 → **体量最大，但存在口径不一致**，见 §五表 3 与 §八。

## 二、PROMPT 0 · 开场四段（可直接粘贴）

> 适用：任何专家／技能／席位接上后的第一句话。只改【案由】【我方身份】【阶段】【要解决什么】四项。

```
【确认边界】
请用三句话讲清：①你擅长什么 ②依据什么（知识源／规则卡／法条源）③什么情况你会说「超出范围」。

【交代案子】
案由：____｜我方身份：____｜阶段：____｜一句话目标：____

【交材料】
事实（只写客观、按时间顺序、不写判断）：
证据（编号 + 证明目的）：
对方主张（照原话引用，不替对方总结、不虚构对方立场）：

【定格式】
先结论 → 再依据（法规全称 + 第X条，拿不准写「待核／statute_text_pending」）→ 三个下一步。
对我方不利的事实必须写出来，不得略去。

【纪律】
不复述我的问题；不写「综上所述」；不普法；不给胜诉率／胜诉概率；
不虚构案号、法条正文、当事人信息；不确定处显式标「待核」。
```

**与既有门禁的衔接**：若请求信息量低、目标含糊，仍按 `RULE-038` 先走 `grill-me-legal-preprocessor`
拿「需求对齐卡」；**对齐卡已生成的不重复生成**，本步只补「确认边界 + 定格式 + 纪律」三段。
`legal-consult-router` 五问分诊与路由表**不变**。

**选人顺序**：窄的先用，宽的兜底（专号答不了再退民商事）；选专家看**标签声明的边界**，不看使用量。
本系统对应 `legal-consult-router` 的「派发优先于自答、无命中才通用框架兜底」，本卡只补**边界标签**与**显式降级链**，不改路由表。

## 三、纪律四句与本系统口径对齐

| 文章纪律 | 本系统落点 |
|---|---|
| 不复述 / 不写「综上所述」/ 不普法 | `老强实例.laoqiang.profile.yaml`（`forbid_popularizing`、`one_line_conclusion`）；`legal-consult-router` 铁律 5「直接上深度，不科普」 |
| **不给胜诉率** | 按 §五表 3 **语境分层**执行；个案办案意见与对外文书一律禁给 |
| 不虚构案号 | LTI `R101`／`T502` 阻断级；`RULE-060` A/B 双闸门 |
| 拿不准写「待核」 | `statute_text_pending` 标记（本地源引证铁律）；`legal-consult-router` 铁律 2「四源都取不到只给条号 + 条旨并显式标注」 |

> 🔴 **口径纪律（RULE-060 §六）**：下游一律写「交付门禁以中枢 `RULE-060` 登记为准」，
> **禁止写死版本号、禁止简称「五维 QC」**；现行交付门禁 = A 层 `REJECT=0` **且** B 层 `REJECT=0` 双闸门
> （B 层九维 R/L/C/T/P/S/V/W/E）。
> **门禁通过 ≠ 判断正确**（`LTI文本监控器/SKILL.md:67`）：最终判断权与责任在执业律师。

## 四、PROMPT 8 · 交接卡（可直接粘贴）

> 适用：一个案子常态是「民商事定路线 → 检索核依据 → 合同改条款」，**一人一岗，串起来用**。
> 换专家／技能／席位前必出本卡。

```
【交接卡】
一、已定结论（≤5 条，逐条带来源：文件 + 条款/行号）
二、要问下一位的 3 个问题
三、材料清单（编号 + 名称 + 已读／未读）
四、待核事项（逐条列，保留原「待核／statute_text_pending」标记，禁止改写成肯定句）
五、上一轮输出：整段原文粘贴如下
────────────────────
<此处整段粘贴上一轮输出，不重述、不摘要、不改写>
────────────────────
```

**三条硬纪律**：
1. **整段贴，禁重述** —— 自己重述会丢「待核」标记，而那正是下一位最需要的；
2. **待核项逐条列，禁收编** —— 不得把「待核」悄悄升级为「已确认」；涉及当事人意思／授权类肯定结论须走 `E1004` 三层（陈述时间轴 + 矛盾扫描 + 法院采信）；
3. **对方主张照原话** —— 引对方自认逐字引用并标出处页/段，**禁替对方总结观点后反驳**（`L0[11]`）。

## 五、三张表

### 表 1 · 法条效力核验（六项逐条核 → 三张处置表）

| 六项核验 | 内容 |
|---|---|
| ① 现行名称版本 | 法规全称 + 现行版本，不写简称 |
| ② 条号准不准 | 精确到「第X条」；新旧条号双检索（民诉法 2021/2023 修正存在条号位移） |
| ③ 效力状态 | 有效／修改／废止／被新解释替代 |
| ④ 施行与修正日 | 带日期，不写「相关规定」 |
| ⑤ 原文照录 | 从本地权威源回填，**禁凭记忆灌条文** |
| ⑥ 与文中表述差异 | 逐字比对文书里的转述与原文 |

**处置三张表**：`必须改` / `可保留` / `必须删`；专查「解释（二）」「修正案」是否**明文取代**旧条。
**技巧**：一条一条贴《法律依据清单》，**别贴整段论述**。
本系统对应：LTI 模块 1（R001/R016/R101–R109）已覆盖 ①②③④ 约四项，⑤⑥ 与三张处置表由本卡补齐；
源优先级按 `RULE-057`（本地法条银行优先），本卡不改动。

### 表 2 · 交接卡字段表

| 字段 | 必填 | 禁止动作 | 消费方 |
|---|---|---|---|
| 已定结论 ≤5 | ✅ | 不带来源不许写 | 下一位专家的起手依据 |
| 3 个待问 | ✅ | 不许泛化成「请分析」 | 下一位的任务边界 |
| 材料清单 | ✅ | 不许凭记忆补材料 | 缺料识别 |
| 待核事项 | ✅ | **禁改写为肯定句** | 本卡存在的核心理由 |
| 上一轮输出整段 | ✅ | **禁摘要／禁重述** | 防标记丢失 |

### 表 3 · 胜诉率语境分层（本轮只立规则，不改既有文件旧值）

| 语境 | 允许 | 禁止 |
|---|---|---|
| 类案历史统计（研究／内部底稿） | 统计历史胜诉率，须标**样本范围 + 统计口径 + 数据来源 + 时点** | 不得换算成本案预测 |
| 模拟法庭内部推演 | 内部战情室评分、攻防强弱评级 | 不得写入对外文书／客户意见；不得标「胜诉概率 X%」 |
| 办案意见／法律文书／客户沟通 | 只写要件缺口、证据强弱、风险等级 | **禁**胜诉率、胜诉概率、必胜、必然、稳赢 |
| 数据不足 | 显式标「待核」 | 禁凭印象估概率 |

> 处置：`legal-consult-router` 路由表中「胜诉率 → 类案大数据分析」条目**保留不删**，但须按本表限定在
> 「类案历史统计」语境；`intake-case-grid` / `庭审准备助手` / `蓝队诉讼律师` 的既有禁令继续有效。
> 本卡**只定义分层规则**，未改动任何既有文件中的旧口径值；按 `RULE-060 §三` 五步派发修旧值属下一轮待拍板事项。

## 七、效力与红线

1. 本卡是**操作层规程**，不改版本号／维度／阈值／门禁，**不触发 `RULE-060` 五步派发**（与 `model-dispatch.md` 同性质）；
2. 对外文书 = **草稿**，律师签字后才生效；未过 A/B 双闸门 `REJECT=0` 不得对外交付；
3. 不承诺结果、不虚构事实、不自行补事实；当事人信息从桌面原始材料实地核实；
4. 模板中的占位一律 `［待律师核定］`；不写落款日期、不代律师判断；
5. 本卡与中枢 RULE 卡冲突时 **一律以中枢为准**，并当场报告冲突，不得自行取舍。
