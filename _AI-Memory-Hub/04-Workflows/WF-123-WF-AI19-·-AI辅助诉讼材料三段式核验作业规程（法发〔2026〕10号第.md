# WF-AI19 · AI辅助诉讼材料三段式核验作业规程

> 立：2026-10-22｜来源：老强（贵阳小强律师）｜依据：法发〔2026〕10号第十九条第三段
> 关联：[[RULE-AI19]]（强制铁律）、[[R-LN-137]]（速查卡）
> 修订：2026-11-11 补「内容层全量覆盖 + 检索空白双证」两项，并完成 T504-B 自动阻断接线（源：老强 A 方案落地；不新增流程、不改动三段式结构）

## 适用范围

凡提交法院/监管/客户的材料（诉讼文书、案例检索报告、法律意见书）中，**任何一部分系使用 AI 生成或辅助完成** → 走本规程。全部由律师独立完成、未用 AI 的，无须走。

## 三段式（缺一不可）

```
① 检索登记  →  ② 内容比对  →  ③ 人工签字
   案号有出处        要旨对得上        有人签字担责
```

### ① 检索登记
- 案号来源**只能**来自权威检索工具的返回结果（人民法院案例库 / 中国裁判文书网 / 法信 / 北大法宝 / 元典案例库），**不得凭模型生成**。
- 检索结果写入 `case_verify_cache.json`（`exists` / `source` / `detail` 三字段，`detail` 内含**真实裁判要旨**）。
- 落点：`provision_index/case_verify_cache.json`

### ② 内容比对（🔴 最易漏）
- **案号真实 ≠ 内容真实**。通州案（2025-18-2-494-001）中 AI 生成的案号全部真实存在，被编造的是挂在真案号上的案情与裁判逻辑。
- 凡写成「该案认为…」「该院认定…」的，**必须调取原判决书**核对案件事实与裁判理由。
- 系统自动比对：T504（`digest_check.py`）双指标——2-gram Jaccard 重叠度 + 主张覆盖率，**双低才判**。
- 官方识别特征：AI 生成案号常呈规律化（12345/1234/111）→ **一律先核**。
- **分层定位（2026-11-11 补）**：案号格式与存在性核验属「准入层」，前置自动执行即可；内容比对属「结论层」，
  **须 100% 覆盖、禁止「抽查 3–5 条」式抽样**——通州案型幻觉（真案号挂假要旨）专钻抽样空档。
- **入口约束**：凡报告出现「该案认为…」「该院认定…」的**每一条**主张，均须有 `case_verify_cache.json` 的
  `detail` 原文锚点；无锚点标 `[N]`，不得进入提交稿。
- **出口衔接**：② 未过不得进入 ③；③ 的《AI辅助使用说明》须写明本次核验覆盖范围（全量/条数），
  律师签字即对该覆盖负责（法发〔2026〕10号第十九条第三段「核实＋说明＋负责」）。

### ③ 人工签字
- 对外版《AI辅助使用说明》单页附件，**随主文书提交法院**（法条措辞为"在提交法庭时……作出说明"，故采附件形式，不并入正文，避免破坏文书格式铁律）。
- 内部版《AI辅助使用记录》仅归档留痕，不提交。
- **律师未签字的附件不生效**，不得由 AI 自动生成后直接提交。

## 门禁分档（硬性）

| 档位 | 命令 | T504 命中 | 用途 |
|---|---|---|---|
| internal（默认） | `lti_gate.py <docx>` | WARNING，不阻断 | 内部稿、草稿 |
| **external** | `lti_gate.py --delivery external <docx>` | **CRITICAL → REJECT** | **提交法院/监管/客户的定稿** |

**对外交付稿必须用 external**，否则 T504 的阻断能力不生效（默认走 internal）。

## 检索空白双证（2026-11-11 补 · P0-2）

> 适用：报告中写「未检索到」「无有效依据」「无类案」等**否定型结论**的子问题。

- **单次零命中不构成「不存在」**。须换第二种方法复核后方可写入任何文书
  （[[RULE-058-目录存在性否定结论必须二次源复核（扫描防漏铁律）]] / WF-130 自证七项④零结果双证 / 变体矩阵）。
- 《检索空白说明》中每个空白子问题强制**三件套**：**① 检索式原文 ② 书写变体清单**
  （同义词 / 新旧条号 / 简繁 / 法院代字）**③ 第二方法结论**（换库 / 换字段 / 换工具）。
- 三者缺一 → 改写为「**本次检索范围内未命中，待人工介入**」，不得写「不存在」。
- 关联：RULE-016 新旧条号双检索（条号位移会漏检旧案）；RULE-055 字段分层——
  「库里没查到」不等于「`cite_ready` 为真」。
- **已接线（2026-11-11 · T504-B）**：`LTI文本监控器/references/digest_check.py` 新增
  `build_blank_claim_annotation()`；`main.py` 的 `wrap_output()` 内以**独立分支**调用
  （不依赖 `case_verify` 缓存，沿用 T504 rule_id、kind＝「检索空白缺双证」）。
  双档同 T504：`internal`→WARNING、`external`→CRITICAL→REJECT。
  `lti_gate.py` 已透传 `--delivery` 至两处 `wrap_output`，**门禁脚本无需改动**。
  「类案检索助手」Node 07 人工复核清单保留为第二道兜底，不因自动阻断而删减。
- 验收：改动前基线 162/162；新增 8 例（裸写命中／三件套静默／合规改写静默／泛词静默／
  无否定静默／空值降级／internal 不阻断／external REJECT）须全通过且原 162 例零回归。

## 排坑（实测）

- **Bash grep 在中文路径 + 管道下会假阴性**，用 Grep 工具（ripgrep）或 Python 复核。
- `build_provision_index.py` 是**全量重建**（SOURCES 只声明 4 部法，直接跑会覆盖 manifest 丢掉其余 10 部）→ 增量追加须用本轮新建的 `build_provision_index_add.py`（读-改-写合并 + 空索引断言 + 防覆盖）。
- T504 的主张片段提取**必须跳过案号后紧邻的句号**（「（2024）川01民终522号。该案认为…」），否则切出空串 → 全部漏报。
- 2-gram Jaccard 在**同领域词汇重叠**时会虚高（实测假要旨达 11.2%，高于 8% 阈值）→ 必须叠加**覆盖率**指标，且双指标同时偏低才判。
- `next_rule_id.py` 取号器在超大目录会超时（SIGTERM 137）→ 改用 Python 递归实测物理 max 取号。
