# WF-AI19 · AI辅助诉讼材料三段式核验作业规程（法发〔2026〕10号第十九条落地）

# WF-AI19 · AI辅助诉讼材料三段式核验作业规程

> 立：2026-10-22｜来源：老强（贵阳小强律师）｜依据：法发〔2026〕10号第十九条第三段
> 关联：[[RULE-AI19]]（强制铁律）、[[R-LN-137]]（速查卡）

## 适用范围

凡提交法院/监管/客户的材料（诉讼文书、案例检索报告、法律意见书）中，**任何一部分系使用 AI 生成或辅助完成** → 走本规程。全部由律师独立完成、未用 AI 的，无须走。

## 三段式（缺一不可）

```
① 检索登记  →  ② 内容比对  →  ③ 人工签字
   案号有出处        要旨对得上        有人签字担责
```

### ① 检索登记
- 案号来源**只能**来自权威检索工具的返回结果（人民法院案例库 / 中国裁判文书网 / 法信 / 北大法宝 / 元典案例库），**不得凭模型生成**。
- 检索结果写入 `case_verify_cache.json`（`exists` / `source` / `detail` 三字段，`detail` 内含**真实裁判要旨**）。
- 落点：`provision_index/case_verify_cache.json`

### ② 内容比对（🔴 最易漏）
- **案号真实 ≠ 内容真实**。通州案（2025-18-2-494-001）中 AI 生成的案号全部真实存在，被编造的是挂在真案号上的案情与裁判逻辑。
- 凡写成「该案认为…」「该院认定…」的，**必须调取原判决书**核对案件事实与裁判理由。
- 系统自动比对：T504（`digest_check.py`）双指标——2-gram Jaccard 重叠度 + 主张覆盖率，**双低才判**。
- 官方识别特征：AI 生成案号常呈规律化（12345/1234/111）→ **一律先核**。

### ③ 人工签字
- 对外版《AI辅助使用说明》单页附件，**随主文书提交法院**（法条措辞为"在提交法庭时……作出说明"，故采附件形式，不并入正文，避免破坏文书格式铁律）。
- 内部版《AI辅助使用记录》仅归档留痕，不提交。
- **律师未签字的附件不生效**，不得由 AI 自动生成后直接提交。

## 排坑（实测）

- **Bash grep 在中文路径 + 管道下会假阴性**，用 Grep 工具（ripgrep）或 Python 复核。
- `build_provision_index.py` 是**全量重建**（SOURCES 只声明 4 部法，直接跑会覆盖 manifest 丢掉其余 10 部）→ 增量追加须用本轮新建的 `build_provision_index_add.py`（读-改-写合并 + 空索引断言 + 防覆盖）。
- T504 的主张片段提取**必须跳过案号后紧邻的句号**（「（2024）川01民终522号。该案认为…」），否则切出空串 → 全部漏报。
- 2-gram Jaccard 在**同领域词汇重叠**时会虚高（实测假要旨达 11.2%，高于 8% 阈值）→ 必须叠加**覆盖率**指标，且双指标同时偏低才判。
- `next_rule_id.py` 取号器在超大目录会超时（SIGTERM 137）→ 改用 Python 递归实测物理 max 取号。
