# WF-045 · 模拟法庭席位绑定配置漂移治理流水线

## 一句话

**流程接了、配置没接＝最危险的半接线。** 席位类系统每新增一个角色，必须同步做「登记 seat + 补版本锚定 + 补接口契约 + 补 preflight + 跑校验脚本」五件事，否则四处引用会在 3 天内全线漂移。

## 适用触发

- 新增/剥离一个模拟法庭席位（如书记员自 QC 剥离）
- 任一席位技能升版（触发版本锚定同步义务）
- 定期体检（建议每周随模拟法庭周自检跑一次校验脚本）

## 五步流水线

### ① 找真源，别在会话工作区改
- 单一事实源：`LawKB/模拟法庭管理系统/模拟法庭席位绑定配置.json`
- ⚠️ 会话级工作区 `WorkBuddy/<时间戳>/` 会随会话切换漂移，**不适合放真源**（R7 根治结论）
- 改前必备份到 `/tmp/<名>-<时间戳>/`（本次实操：6 份文件全量 cp）

### ② 登记 seat（不只是加流程）
新增席位须一次补齐字段，缺一即视为半接线：
`seat / camp / emoji / skill / skillPath / version / centerSide / defaultOperator / stages / mustCall / mustNotCall / outputs`
> **mustNotCall 比 mustCall 更重要**——它定义角色边界（如书记员：不评判／不否决／不代发言／不润色／不补白／不与 QC 合并）。

### ③ 全量校正版本锚定（最易漏电的一步）
- 用脚本解析各技能 frontmatter 实际 `version`，**不凭记忆**
- 逐个比对锚定表，替换时注意：AskUserQuestion 的 `label` 与 `question` 文案**是两处**，只改 label 会漏
- 历史变更日志里的旧版本号**保留**（那是史实，不是漂移）

### ④ 补契约与 preflight
- `interfaceContract`：补 主控_to_X / X_to_主控 / X禁区
- `preflightChecklist`：补 X 的开庭前检查项（如「三件套头部带 record_profile」）
- `skillOverridesRequired.skills` + 实际写 `settings.json → skillOverrides = on`

### ⑤ 跑常驻校验脚本收口
```
python3 ~/.workbuddy/skills/_common/scripts/seat_config_verify.py
```
C1 版本锚定↔frontmatter／C2 seats 覆盖／C3 skillPath 存在／C4 skillOverrides／C5 心智卡存在+status／C6 训练态数据源存在。
退出码 0 才算收口；**脚本必须在改完配置后跑，而不是改之前——它能抓出你自己刚制造的新漂移**（本次实操即抓到主控升版后未回表）。

## 踩坑清单（本次实证）

| 坑 | 表现 | 规避 |
|---|---|---|
| 流程接了配置没接 | 主控第四阶段已触发书记员，但绑定表无此席位 | 新增角色必回真源登记 seat |
| 锚定漂移 | 主控写蓝队 v4.5.0，实际 v4.6.2 | 脚本解析 frontmatter，禁手抄 |
| label/question 双写 | 改了选项 label，question 文案仍是旧版 | 替换后全文复扫旧版本号 |
| 心智卡内锚定字段漂移 | red_persona 写 applies_to 红队 v2.4.0（实际 v2.6.0） | 心智卡内 `version_anchor`/`applies_to` 纳入 C 类校验 |
| 数据源字段混入说明文字 | 「路径（2026-09-15 00:35 脚本同步）」导致路径判定失败 | 路径字段只放路径，说明另开字段 |

## 验收口径

- 校验脚本 **0 漂移**（允许 warning，如心智卡 DRAFT 属实待办）
- 四处引用（主控／庭审系统／蓝队／红队）版本锚定与真源完全一致
- 全部席位技能 `skillOverrides = on`
