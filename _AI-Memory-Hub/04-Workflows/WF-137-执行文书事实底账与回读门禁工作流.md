# 执行文书事实底账与回读门禁工作流

## 一句话定义

**执行文书事实底账与回读门禁**：每案建立一份本机 `execution-facts.json`，把判决字段连同来源文件、页码/段落、原文片段和签核状态集中登记；五个关键字段经律师签核后才允许按对外件生成，生成后再逐文件回读 DOCX/XLSX，FAIL 一律退回。

## 适用场景

外部执行文书生成技能已有模板与计算能力，但缺少字段级溯源、人工签核阻断和生成后内容核验时使用。适用于申请执行书、要素式申请书、授权委托书、律所函、执行标的计算表等成套文书。

## 调用顺序（不得颠倒）

1. 读取本机适配层，确认技能本体禁改，所有增强只在 `_local-patches/` 落地。
2. `init` 初始化事实底账；已存在时拒绝覆盖。
3. `set` 填字段及原文锚点；改值即自动清除旧签核。
4. 由实际核验律师执行 `sign`；AI 只可准备底稿，不得代签。
5. `check` 严格模式通过后才生成对外件；未通过仅可显式使用 `--draft` 生成内部底稿。
6. 调用原技能生成，不替换模板引擎。
7. `require` 登记每份交付文书需核对的字段；`audit` 回读 DOCX/XLSX 并保存本地报告。
8. 回读 PASS 后再进入 221 号版式后处理、LTI 双闸门、G9 产出后检查与 `case-state` 回写。

## 五个关键字段

| 字段键 | 核验对象 |
|---|---|
| `principal` | 本金，与判项主文一致 |
| `interest` | 利息起算日、计算方法、终点，取判项原文 |
| `acceptance_fee` | 受理费**负担额**，不得误取总额；二审须区分各审级负担 |
| `effective_date` | 生效日期及送达/生效证明来源，不以判决日机械推算 |
| `respondents` | 判项确定的义务人；证件号不得由出生日期拼接 |

## 六条红线

1. **认不出即空，不许猜**：空值可见，错值需对照原文才能发现。
2. **身份证号只取原文明确写出的号码**，禁止补位拼接。
3. **判项主文原文保留**，机械改写与原文摘录分开保存。
4. **改值即失效**：任何关键字段修改后，原签核自动清空。
5. **草稿不等于交付许可**：`--draft` 只用于内部底稿，须标注未经 LTI、不得对外引用。
6. **回读不替代法律判断**：只证明已声明字段与底账一致，不替代全篇人工阅读、法条核验或 LTI 双闸门。

## 本地脚本与退出码

脚本：`~/.workbuddy/skills/_local-patches/execution-docs-generator/scripts/execution_fact_gate.py`；仅 Python 标准库，本机处理，不调用网络。

命令：`init` / `set` / `sign` / `check` / `require` / `audit`。

退出码：`0` 通过或草稿模式可继续；`1` 结构或参数错误；`2` 签核阻断或回读不一致。

## 产出

- `execution-facts.json`：字段、原文锚点、签核状态、逐文件核对范围。
- `回读比对报告.json`：逐文件、逐字段的 PASS/FAIL 结果。
- `.execution-facts-backups/`：每次覆盖写入前的自动备份。

## 验收证据

- 8 项单元测试：覆盖未签核阻断、草稿放行、改值清除签核、连续写入、DOCX/XLSX 回读、错值/漏文件/占位符/旧值检出。
- 端到端实跑：未签核 `check=2`；签核后 `check=PASS`；DOCX/XLSX `audit=PASS`。
- 原技能 `SKILL.md` MD5 与字节数不变；清单同源检查 FAIL=0 / WARN=0。

## 能力边界

截至 2026-11-09 尚无真实判决书实战，当前只能判定为**逻辑与自动化测试闭环**，不得写成实战验证完成。本地模型、OCR 与图形界面均属后续隐私/体验增强，不是本工作流的核心。
