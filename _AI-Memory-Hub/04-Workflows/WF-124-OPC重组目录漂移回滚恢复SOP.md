# WF-124 · OPC 重组致知识飞轮目录漂移的安全识别与回滚恢复 SOP

> 当 `git status` 或文件巡查显示知识飞轮系统某目录（典型：顶层 `06-沉淀`）被"清空/大量删除"，而其内容整棵出现在另一路径（典型：`02-提炼/06-沉淀`）时，**先识别这是 OPC 重组的目录搬迁（move）而非数据丢失**，再按六-B 安全流程回滚恢复。本卡由 2026-10-28 实战（2975 项变更回滚）提炼。

## 一、适用场景

- git 扫描出现数百~数千个 `D`（删除）项，且删除项集中在单一目录（如 `知识飞轮系统/06-沉淀/`）。
- 被删目录的同位内容在另一路径整棵出现（如 `02-提炼/06-沉淀/` 有 3057 文件 / 30 子目录）。
- OPC（一人公司）体系做过目录规范化重组（"OPC 接管方案"），把卡库从顶层 `06-沉淀` 下沉归并到 `02-提炼/06-沉淀`。

## 二、关键认知（先纠偏，再动手）

1. **git 显示 `D` 不等于数据丢失**：git 不跨目录识别 rename，旧路径显示 `D`，新路径因整目录新建被折叠成一条 `?? 目录/`，所以 porcelain 只看到"大量删除 + 1 个新增目录"。实为 move。
2. **`libmigrate`（2026-10-23）与 `06-沉淀` 搬迁是两件事**：`libmigrate` 备份名实际对象是 `ima_intake_state.json`（IMA 摄入状态文件，241KB→当前 422KB 是状态累积，非丢失）；`06-沉淀` 空壳是另一次 OPC 目录重组（10-25 之后未提交工作区状态）。**回滚 libmigrate 并不能恢复 06-沉淀**。
3. **卡库正统根是顶层 `06-沉淀`**：[[WF-028-知识飞轮卡库接线]] 定义卡库根为 `知识飞轮系统/06-沉淀/裁判规则库/<域>/`；`asset_monitor.py` 监控也硬编码指向顶层 `06-沉淀`（"卡库根"）。OPC 重组把内容搬到 `02-提炼/06-沉淀` 会造成**引用漂移**——监控脚本仍扫旧空目录。

## 三、安全恢复 SOP（六-B 前置）

### Step 1 · 备份（必做，先 cp 不先改）
```bash
TS=$(date +%Y%m%d-%H%M%S)
BACKUP="/tmp/lawkb-rollback-prep-$TS"
mkdir -p "$BACKUP"
tar czf "$BACKUP/src-02提炼-06-沉淀.tar.gz" -C "知识飞轮系统/02-提炼" "06-沉淀"
cp "知识飞轮系统/ima_intake_state.json" "$BACKUP/ima_current.json"
```
> 慢盘（iCloud eviction）下 `cp -R` 易超时，改用 `tar czf` 单文件打包；源目录未动前本就可逆，备份是双重保险。

### Step 2 · 识别冲突项（dry-run，只读）
```bash
cd 知识飞轮系统
SRC="02-提炼/06-沉淀"; DST="06-沉淀"
for f in "$SRC"/*; do [ -e "$f" ] || continue
  b=$(basename "$f"); [ -e "$DST/$b" ] && echo "CONFLICT: $b"
done
```
> 典型冲突项：`casedrop_watch.log`（运行时日志）、`分身记忆备份/`（含 228 批 self_backup 副本）。

### Step 3 · 非冲突项整批搬回（同卷 rename 瞬时）
```bash
for f in "$SRC"/*; do [ -e "$f" ] || continue
  b=$(basename "$f"); [ ! -e "$DST/$b" ] && mv "$f" "$DST/"
done
```
> 同文件系统内 mv = rename，不复制数据，秒级完成，不触发 iCloud 读阻塞。

### Step 4 · 冲突项分别处置（不覆盖活跃文件）
- `casedrop_watch.log`：保留**顶层活跃版**（较新、仍在写），删 02-提炼 侧旧副本。
- `分身记忆备份/`：用 `find ... -type f` 逐文件合并，仅移入顶层**没有**的文件；已存在则跳过。
- **分叉文件**（两边内容 md5 不一致，如 `backup_log.md`/`README.md`/`.last_hash_self`）：不丢任一边——把 02-提炼 侧副本存为 `.from-02提炼侧` 变体到顶层，再删源，信息零丢失。

### Step 5 · 清理与验证
```bash
rmdir "$SRC" 2>/dev/null   # 应成功（残留 0 项）
[ -d 06-沉淀/人伤法域库 ] && echo OK
find 06-沉淀 -type f | wc -l       # 应≈原 02-提炼/06-沉淀 文件数
ls -A "02-提炼/06-沉淀" | wc -l    # 应为 0
```
> 恢复后 `asset_monitor.py` 监控目标（顶层 `06-沉淀`）重新扫到满库，**引用漂移自动消解，无需改脚本**。

## 四、红线（本 SOP 不可逾越）

- **IMA 状态文件（libmigrate 真实对象）勿盲目回滚**：回滚 `ima_intake_state.json` 到 10-23 bak 会丢失 10-23 22:49 之后全部 IMA 摄入进度，违反"闭环不能破坏系统运行为基础"红线。保留当前版，备份已就绪，待老强明示再回滚。
- **git 提交待本地落地**：iCloud 文件回收（eviction）下 `git add -A` 会阻塞 >12min（2026-10-18 / 2026-10-28 均实证）。恢复动作完成即停，不主动 commit/push；待本地文件落地后手动 `git add -A && git commit && git push origin main`。
- **绝不删 05-归档、绝不批量覆写旧卡**（中枢红线）。
