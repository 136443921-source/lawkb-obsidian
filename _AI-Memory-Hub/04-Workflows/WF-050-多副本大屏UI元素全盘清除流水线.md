# WF-050 · 多副本大屏 UI 元素全盘清除流水线

> **一句话**：老强说「凡是大屏有 XX 的，都删掉」时，**不是改一个文件，而是先全盘定位"同一份 UI 的 N 个副本"，再脚本化三层（HTML/CSS/JS）清除 + 备份 + 三重验证**——
> 漏一个副本，下次打开那个大屏，元素又冒出来。

## 适用场景

- 老强发来一张截图（截图中是某段文字/某个 UI 元素），要求「复盘所有大屏，凡有这段文字的都删掉」
- 驾驶舱/门户一套模板被复制成多份（9360 内部版、脱敏门户版、分屏副本、桌面原型、Claw 副本…），需**全副本同步清理**
- 典型元素：提示胶囊、浮块角标、废弃按钮、旧版导航条

## 六步法

### 1｜全盘定位（先侦察，别急着改）
```bash
# 用专用 Grep 工具（ripgrep）扫全盘，不要用 BSD grep 的多模式
# 搜索根：WorkBuddy / Desktop / Documents / ~/.workbuddy/skills
```
- 记录**每一个命中文件**，按「实时在线 / 副本 / 备份 / 文档」四类分桶
- 备份文件（`*.bak*`）、会话日志（`*.jsonl`）、技能文档（`SKILL.md`）**不属于大屏**，默认不动（文档只在"表述失效"时才改）
- ⚠️ **别漏非工程目录的副本**：桌面原型目录（如 `~/Desktop/XXX开作台/`）经常藏着同一份模板

### 2｜摸清"三层引用"（HTML / CSS / JS）
对每个命中文件体检：
```bash
grep -nE "元素类名|元素 id" <file>          # HTML 里的标签
grep -nE "<script[^>]*src=" <file>          # 是否引用同目录外部 JS
```
- 元素往往在 **HTML（标签）+ CSS（样式规则）+ 外部 JS（显隐逻辑）** 三处同时存在
- **只删 HTML 不删 JS → 一定报 Null 类错误**（`x.classList` on null）中断后续渲染
- **只删 HTML/CSS 不删 JS → 安全但留死代码**（违反"零残留"）
- 判据：先 grep JS 里被引用的**变量名**（如 `hint`、`timer`），确认该变量**是否只服务这一个元素**；只服务 → 连声明一起删

### 3｜区分「提示文字」与「功能按钮」
- 老强要求删的是**截图里的那段文字**，不一定是同名的功能入口
- 例：提示胶囊 `若内嵌空白，请点右上「在新标签打开」` 要删，但右上角**功能按钮** `<a id="openNew">在新标签打开 ↗</a>` 必须**保留**（那是可用功能）
- **判据**：删完后功能是否还可用？不可用 → 删错了。

### 4｜脚本化（带 dry-run / 备份 / 幂等 / 可还原）
写 `<skill>/scripts/xxx.py`，必须四件套：
- `--dry-run`：先报告命中数与改动量，零告警才落盘
- 自动 `cp` 备份到 `/tmp/<name>-bak-<时间戳>/`，保留相对路径便于还原
- 幂等：已清理则跳过，重复跑不报错
- `--restore`：从最近备份一键还原
- TARGETS 用 **(HTML 文件, 同目录 JS 文件名)** 元组显式列全，避免 glob 漏网

### 5｜三重回归验证（缺一不可）
| 层 | 手段 | 通过判据 |
|---|---|---|
| JS 语法 | `node --check <file>` 逐个校验 | 全部无输出（零报错） |
| 残留 | `grep -c` 关键词 / 元素 id / CSS 规则 | **全部 = 0** |
| 线上 | `curl -s http://127.0.0.1:9360/ \| grep …` | 无残留 + 服务 HTTP 200 |

- 另做**全盘复扫**（find + grep 三根目录），确认没有漏网的大屏
- 缓存：HTTP 服务若发 `Cache-Control: no-store` 则无需处理；否则 bump 资源 `?v=` 版本号

### 6｜收尾
- 大屏运维 skill 追一条变更日志（版本号、改动清单、备份路径、验收证据、踩坑）
- Obsidian 中枢写回：`04-每日日志/` 一条 + 本类流水线沉淀为本卡
- 工作区 memory 日志追加

## 踩坑清单（实测）

1. **🔴 BSD grep（macOS 默认）不支持 BRE `\|` 交替**——`grep -n "A\|B"` 会**静默返回空**，让人误判"未命中"从而漏改文件。
   多模式**必须**用 `grep -nE "A|B"` 或专用 Grep 工具（ripgrep）。本次首轮即中招：以为桌面两个大屏没命中，实际有。
2. **`grep -rl` 扫 1200+ 条目大目录会被 kill**（exit 137）→ 改 `find … -print0 | xargs -0 grep -l` 或限定 `--include`。
3. **外部 JS 共享行号会漂移**：6 份 `auth.js` 同源但行号不同（82/169/81/82/80/82），脚本必须**按正则匹配**而非按行号删。
4. **同一文件多处编辑必须串行**；且改关键路径后要 **Read 回读确认**（Edit 报成功却不落盘的事故有前科）。
5. **并发会话撞车**：同一份大屏可能被另一会话同时改。改前记 mtime，改后立即复验（curl + grep）确认自己的改动**未被覆盖**；发现对方 bump 了 `?v=` 版本号即说明对方读到了你的写入，属安全的增量协作。
6. **备份目录不要放 `/tmp` 之外**（本类操作临时性），但要**明确告知老强备份路径**，方便一键还原。
