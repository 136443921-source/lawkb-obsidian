## 取号五条铁律
1. **禁止 `find`/`sort`/凭记忆手工取号**（判流程缺陷）。
2. **一次取满**——批量建卡前一次取足，逐个取号＝放大并发窗口 N 倍。
3. **落盘即 commit**。
4. **口径只看 frontmatter `rule_id`**（文件名只是别名）。
5. **建卡后必跑守卫**。

## 存量同号冲突治理（六-B 铁律）
- **文件名一律不动**——规范禁止批量改名（锈蚀数百条 wiki 链接）；只改 frontmatter：`rule_id`→新号，补 `aliases` 旧号，加 `rule_id_fixed:<日期>` + `rule_id_prev:<旧号>` 追溯标记。
- **保留方判定**：① 文件名与 rule_id 自洽者优先留；② 其次 created 早；③ 其次 mtime 早。
- **新号分配**：优先改回库内空闲的"文件名号"一次解决冲突 + 修复漂移；否则域内顺延 `max+1`。
- **执行顺序**：排查 → dry-run（脚本自校验）→ **cp -a 备份 /tmp 时间戳目录** → 实跑 → 三重回归（守卫 / 幂等 / 结构健康）。脚本检测 `rule_id_fixed` 已处理自动跳过，保证幂等。

## 红线 / 坑
- 🔴 **只改 `rule_id` 不够**：部分卡用 `rule_card:` 存号，两处都要改；`rule_card` 值可能是中文标题而非卡号，须判断后再改。
- 🔴 **`aliases` 形态不一**：内联 / 块格式 + 重复键 YAML 畸形 → 全量收集后统一重建为块格式。
- 🔴 **两位序号** `R-LN-63` 会被正则漏匹配，修复前先查三位补零后号是否被占。
- **心法**：门禁红着等于没门禁——误报淹没有效信号比没门禁更糟，守卫上线前必须先消除误报（`classify_card()` 分 rule / legacy / doc 三类）。
