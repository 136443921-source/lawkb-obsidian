# WF-025 · 模拟法庭红蓝对抗推演流程

> 编排外壳：把「诉讼文书红蓝复核工作流」的定稿文书推进到**全流程红蓝对抗庭审模拟**。内部引擎 = 模拟法庭主控协调器；前接庭前检索 + 三轮冲击庭前强化；后接质量闸门（QC-Controller + 庭审战情室）+ 知识飞轮回写。覆盖民事 / 刑事 / 行政 / 仲裁全程序。

## 适用场景
- 已起草 / 复核定稿的诉状、答辩状、代理词，想"拉出来过一遍"预演庭审对抗。
- 训练庭辩反应、暴露论证薄弱点、生成战情与总闸报告。
- **非真实裁判**：模拟结果仅作训练 / 复盘参考，须显著标注"AI 生成参考，请依官方数据库二次核对"。

## 阵营映射
- **你（老强）= 蓝队位·我方代理人**（人机协同，防御方）。
- **系统 = 红队·对方** + 内置 **审判长 / 首席仲裁员**（中立裁决者）。
- 程序适配层（注入式，不改主控协调器本体）：

| 程序 | 我方（蓝队） | 对方（红队） | 裁决者 | 关键程序法 | 输出文书 |
|---|---|---|---|---|---|
| 民事 | 原告/上诉人（或被告） | 相对方 | 审判长 | 民事诉讼法 | 笔录+判决书 |
| 刑事 | 被告人/辩护人 | 公诉机关 | 审判长 | 刑事诉讼法 | 笔录+判决书 |
| 行政 | 原告（相对人） | **行政机关恒为被告** | 审判长 | 行政诉讼法 | 笔录+判决书 |
| 仲裁 | 申请人/被申请人 | 对方 | 首席仲裁员 | 仲裁法 | 笔录+裁决书 |

## 七阶段 SOP
1. **阶段0 承接定向**：判定程序类型 / 审级 / 我方立场，锁定蓝队位=我方代理人，输出定向卡（程序 / 角色 / 目标文书）。
2. **阶段1 庭前检索**（法律检索助手）：查类案裁判规则、法条效力、争议焦点先例；**须先查本地卡库**（案由路由 R-AY-\* + 对口域卡组），确认 `knowledge_called` 含本地卡 rule_id。
3. **阶段2 庭前强化**（三轮冲击控制器）：以定稿文书为基线跑 1–3 轮蓝队 / 红队迭代，蓝队打磨代理词、红队预驳回暴露薄弱点，产出 v1 底稿。
4. **阶段3 庭审模拟**（模拟法庭主控协调器）：注入程序适配层指令后开庭，内置 6 门禁 + 4 总闸；卡源随上下文流入法官。
5. **阶段4 质量闸门**（QC-Controller + 庭审战情室）：生成战情报告与总闸报告。
6. **阶段5 交付**：庭审笔录 + 判决书 / 裁决书 / 调解书 + 战情 / 总闸报告 + 复盘建议。
7. **阶段6 飞轮回写**：写调用记录（frontmatter `knowledge_called` 必列命中 rule_id，禁写 `[[ ]]`）、追加协同效果埋点、场景化知识推送，红队攻击点沉淀为「文书防御要点卡」。

## LTI 门禁（全程强制）
所有交付文本（笔录 / 判决书 / 裁决书 / 调解书 / 战情报告）输出前必须 `wrap_output()` 过 LTI 文本监控器（见 WF-002）；R101 条号伪造与 C301 金额矛盾为不可跳过阻断级。通过后才附加"文本监控器参与说明"。

## 红线
- 模拟结果**不得当作真实裁判或正式法律意见**，必须标注 AI 生成参考。
- 不编造案号；类案仅给检索策略，案号以裁判文书原件 / 权威库核对。
- 法案条文以 pkulaw 主源核验，不凭记忆灌；禁凭模型通用知识裸判，整链须吃本地卡。

## 产出
- 模拟法庭庭审记录（笔录）
- 模拟判决书 / 裁决书 / 调解书
- 战情报告 + 总闸报告 + 复盘建议
- 调用记录 + 协同效果埋点 + 文书防御要点卡（可选沉淀）
