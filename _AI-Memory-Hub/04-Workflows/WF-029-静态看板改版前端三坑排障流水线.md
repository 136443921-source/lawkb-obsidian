# WF-029 · 静态看板改版前端三坑排障流水线

> 沉淀自 2026-09-14「小强总驾驶舱」C0–C9 统一编号改版：代码明明改对了，页面就是不显示。
> 三个坑的共同特征——**现象看着像"没改到"，实际改的是另一处 / 被另一层吃掉**。
> 适用于所有单文件 HTML + 外链 JS + JSON 数据源的静态看板（驾驶舱 / 大屏 / 门户）。

## 适用场景
- 改了 JS/JSON，浏览器刷新后页面无变化（或只有部分区域变化）
- 同一个编号/字段，在 A 处显示、B 处不显示
- 数据文件里字段存在，页面永远不渲染

## 坑一：缓存假象 —— 代码对了，浏览器揣着旧文件

**症状**：改了 `rbac.js` / `auth.js`，截图一看标签栏编号还是没有；但直接 `curl` 抓下来的内容是新的。

**根因**：Python `http.server`（及多数静态服务器）不发 `Cache-Control`，浏览器按 `Last-Modified` 做**启发式缓存**，把旧 JS 揣在本地。你改的是磁盘，浏览器读的是缓存。

**判据（30 秒定性）**：
```bash
curl -s http://127.0.0.1:8139/rbac.js | grep -c "cno"   # 源站有 → 代码没问题
```
源站有、页面无 ⇒ **缓存**，不是改错。

**修法**：改 HTML 里的外链引用，加版本号击穿
```html
<script src="rbac.js?v=20260914c"></script>
<script src="auth.js?v=20260914c"></script>
```
**红线**：**改了外链 JS 必须同步升 `?v=`**。否则必然复现，且极易误判成"我改错了"而反复返工。

## 坑二：多真源不同步 —— 改了 A 处，B 处读的是另一个文件

**症状**：顶部标签栏有编号，作战卡片区和评分总表都没有。

**根因**：同一个"编号"在三个文件里各有一份，改一处只亮一处：
| 真源 | 被谁读 |
|---|---|
| `rbac.js` 的 `sites[*].cno` | 顶部标签栏 |
| `scorecard_data.json` 的 `screens[*].cno` | 作战地图卡片 + 评分总表（**不是 rbac.js**） |
| `workbench.html` 的 `SITES[*].cno` | 统一工作台卡片 + 总表 |

**修法**：改编号前先列真源清单，**三处一起改**；改完用脚本逐处核对：
```bash
# 逐文件统计 cno 命中数，缺谁一眼看出
for f in rbac.js scorecard_data.json workbench.html; do echo -n "$f: "; grep -c 'cno' $f; done
```

**红线**：**不要把排序依赖 JSON 的物理顺序**。重扫脚本会重写 `screens` 数组，物理顺序随时被冲。排序要落在**渲染层**：
```js
function cnoRank(c){ if(!c) return 98; if(String(c).toUpperCase()==='C0') return 99;
  var n = parseInt(String(c).slice(1),10); return isNaN(n)?98:n; }
SITES.sort(function(a,b){ return cnoRank(a.cno) - cnoRank(b.cno); });
```

## 坑三：字段写了没渲染 —— 数据里有，页面永远不显示

**症状**：`workbench.html` 的 `SITES` 里明明写了 `cno:"C7"`，页面就是不显示编号。

**根因**：**只加了数据字段，没加渲染代码**。字段存在 ≠ 会渲染。

**判据**：
```bash
grep -c 'cno:"C' workbench.html     # 数据层：有
grep -c 'class="cnob"' workbench.html  # 渲染层：0 → 就是这坑
```

**修法**：数据字段 + 渲染代码 **成对落地**，并补 CSS：
```js
'<div class="nm"><span class="cnob">' + (x.cno||'-') + '</span>' + x.name + '</div>'
```
```css
.cnob{display:inline-block;margin-right:7px;padding:1px 7px;border-radius:6px;
  font-size:11px;font-weight:800;background:rgba(212,175,55,.14);color:#d4af37;
  border:1px solid #b8932c;vertical-align:middle}
```

## 标准步骤（改版前按顺序走一遍）
1. **列真源**：把本次要改的字段在哪些文件有副本，先列成表（坑二）。
2. **备份**：`TS=$(date +%Y%m%d-%H%M%S); mkdir -p /tmp/bk_$TS; cp -n <待改文件> /tmp/bk_$TS/`（**`cp -n` 防覆盖**）。
3. **成对改**：每个字段同时改「数据层 + 渲染层」，别只改一半（坑三）。
4. **升缓存**：外链 JS 引用加/升 `?v=YYYYMMDDx`（坑一）。
5. **静态校验**：`node --check` 外链 JS；内联脚本用正则抽出后 `new Function()` 试解析；JSON `json.load` 校验；顺带查 `\uFFFD` 乱码。
6. **实跑验证**：浏览器真打开 + 真登录（不只是 curl 首页），截图留证。

## 红线
- 🔴 **外链 JS 改动必升 `?v=`**，否则缓存假象必然复现。
- 🔴 **排序落在渲染层**，不依赖任何会被脚本重写的数据文件物理顺序。
- 🔴 **字段必须数据层+渲染层成对落地**，只加字段 = 永远不显示。
- 🔴 **改前必备份到 `/tmp` 时间戳目录**，用 `cp -n`；批量替换前先 dry-run（打印 `subn` 命中数，命中数不符预期就回滚重来）。
- 🔴 验证必须**浏览器实跑**，curl 只证明源站内容，不证明用户看到什么。

## 产出
- 三处真源一致的编号/字段体系
- 改版前后备份各一份（`/tmp` 时间戳目录）
- 静态校验报告 + 浏览器实跑截图
