---

## 0. 一句话结论

系统失能/继承时，**资产 nominee（共享中枢 + LawKB 独立仓库 + 中枢 git 备份）已自动固化保全**，无需指定人；**治理/操作 nominee 已确认采用 C 方案（失能即冻结治理）**，老强保留升级 A（自然人受托人）/ B（受托智能体）的权利。

---

## 1. 触发条件

| 触发 | 含义 |
|---|---|
| 老强失能 | 无法操作系统（疾病 / 消失 / 权限失效） |
| 继承 | 身故或永久退出 |
| 系统灾难 | 仓库损毁 / 中枢断连 / 不可逆数据丢失风险 |

---

## 2. 接管目标

1. **法人资产不丢**：LawKB / 技能库 / 案例库 / 知产登记结论 不灭失、可追溯、可恢复
2. **内部治理不真空**：有人接管或明确冻结，避免悬空

---

## 4. 治理 / 操作 nominee（已确认 C，老强保留 A/B 升级权）

系统失能后，谁接管"总经理内部治理执行权"？三方案：

| 方案 | 接管者 | 说明 | 状态 |
|---|---|---|---|
| **A** | 指定自然人受托人（同事 / 家属 / 可信第三方） | 需老强提供姓名 + 联系方式 + 授权范围 | ⏳ 可选升级 |
| **B** | 指定受托智能体（另一 WorkBuddy 实例 / 备份系统，预设恢复令牌） | 需老强授权令牌与接管边界 | ⏳ 可选升级 |
| **C（已确认）** | 仅资产 nominee，不指定操作接管人 | 失能即冻结治理，资产保全，待老强恢复或法定继承 | ✅ 生效 |

> **C 的合理性**：数字分身系统的"治理决策"高度绑定老强的专业判断与法律责任（唯一股东），强行由他人/他体接管对外出具法律意见存在合规风险。故默认冻结、保全资产，是最稳妥的 nominee 基线。老强保留随时升级为 A/B 的权利。

---

## 5. 接管流程

```
触发（失能/继承/灾难）
  ↓
资产 nominee 自动保全（中枢+LawKB+git，无需人）  ──✅ 已固化
  ↓
若已指定治理 nominee（A/B）→ 其接管总经理职权
若未指定（已确认 C）      → 冻结内部治理，资产只读保全
  ↓
Phase 5 年度 nominee 演练验证（确保接管链路真实可用）
```
