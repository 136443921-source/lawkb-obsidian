## 2. 治理架构与汇报线

```
老强(超级管理员) ──任命/最终决策──> 总经理(律所主任·管理合伙人)
                                    │
        四大中台 ──汇报──> 总经理 ──汇报──> 老强
       (业务/数字资产/运营/可视化)
                                    │ 受监督
                            监督层(LTI门禁+驾驶舱监控+红蓝QA)
```

**数字员工层**（业务中台 / 可视化中台下属岗位隐喻，非法律雇员）：蓝队诉讼律师 / 蓝队非诉律师 / 红队律师 / AI 模拟法官 / 模拟法庭书记员 / 小德慈善合规 / 蓝队律师助理 / QC-Controller 审判长双模（业务中台，QC 已 ACTIVE 经 WF-046 转正，72/100·M3）、IT 运维员（可视化中台）；归责归老强，四类 R 动作不适用数字员工自主决策（须老强拍板）。全面复盘与编制见 `数字员工编制方案_v1.0.md` + 岗位细则见 `数字员工岗位手册.md`。

**RACI 摘要**：四类 R 动作（对外出件 / 定价发布 / 批量删改 / 新增改造）老强为唯一 R；内部治理运转总经理 A/R；知识入库 / 监测总经理 A、LTI R。

## 4. 质量门禁（LTI 文本监控器）

- **交付前置强制**：任何文本制品（含校验报告、清单、草稿）写入磁盘 / present 前必过 LTI（R001–R116），**REJECT=0 才准交付**。
- **五维 QC**：R 法条真实性 / L 法理逻辑 / C 一致性（金额 / 名称 / 案号）/ T 溯源 / P 程序。
- **六维法理逻辑门禁**：教义路径 + 要件映射 + 举证责任 + 时效 + 管辖 + 效力层级。
- **回归基线**：改门禁后必跑 `tests/test_lti.py` 三连（T1 BLOCK / T2 PASS / 真实文书无误报）。
- 溯源：MEMORY.md §LTI 交付门禁铁律（2026-08-31）/ §P0 纪律（2026-09-02）。

## 6. 知识资产治理

- **LawKB 独立仓库**：`~/Documents/LawKB/`，仅纳入系统所需文件，非系统文件不纳入（物理隔离）。
- **中枢优先级总则**：Obsidian `_AI-Memory-Hub` 为唯一事实源，优先级 中枢 > 各平台原生 memory > 聊天 > 会话；冲突以中枢 `status:active` 最新版为准。
- **中枢 git 提交**：统一走 `backfill.py`（index.lock 安全重试），禁裸 git。
- **新建卡**：默认 `backfill.py --card` 全流程。
- **跨案事实隔离**：禁止串案污染，个案卷宗不纳入中枢。

## 7. nominee 与永续经营

- **资产 nominee（✅ 已生效）**：共享中枢 + LawKB 独立仓库 + 中枢 git 备份，系统失能时自动保全，不需指定人。
- **治理 nominee（✅ 已确认 C）**：失能即冻结内部治理，资产保全，待老强恢复或法定继承；老强保留升级 A（自然人受托人）/ B（受托智能体）权利。
- **接管流程**：触发 → 资产 nominee 自动保全 → 治理 nominee（C 冻结 / A·B 接管）→ Phase 5 年度演练验证。

## 8. 合规与商业化收口

- **商业化治理层（新增 · 对外经营线）**：对外经营业态与商业运营线的治理 SOP、三业态产品线定义卡，统一收敛至共享中枢 `09-OPC/商业化运营/`（`商业运营SOP总册_对外经营线.md` + `产品线-独立部署.md` / `产品线-规则包.md` / `产品线-文书代写.md`）；本 §8.1 / §8.2 为其权威源，归位方案见 `对外经营耦合与业务开拓建议方案_v0.1.md` §4。
- **商业化唯一收口（产出层）**：所有商业运营**新产出**（定价 / SKU / 客户线索 / 交付 SOP / 知产 / 制品）一律追加到 `05-商业化运营备忘录-v1.0.md`，不另起新文件；对外传播前脱敏。两层关系：备忘录 = 产出收口，09-OPC/商业化运营/ = 治理 SOP 收口，互不冲突。
- **法律文书格式铁律**（据最高法法〔2016〕221号）：A4 / 仿宋三号 16pt / 标题宋体 22pt / 行距固定 28 磅 / 页边距上 3.3 下 3.2 左 2.7 右 2.4cm / 页脚居中页码；**禁止论文化写法**（无加粗元信息块 / 无编号小标题 / 无独立法律依据板块）。
- **文本交付物默认 docx**；LTI 未过 / 草稿态提示须加粗标红重点提示。
- **红线**：`~/lawtwin-open/` 仅放 L0，绝不进业务产物。

### 8.1 对外经营业态（三业态）

分身系统对外经营体按三种业态经营（据 v1.1 §5.1 裁决 + 本章程 §8 商业化治理层）：

| 业态 | 交付物 | 能力供给中台 | 归责边界 | 责任深度 |
|---|---|---|---|---|
| 独立部署（私有部署） | 分身系统 + 9655 驾驶舱 + 部署 SOP + 密文存储 | 业务 / 数字资产 / 可视化 / 运营 中台 | 产品缺陷归老强(拟法人)；客户使用产出自担（服务协议免责） | 最深 |
| 规则包（知识付费） | LawKB 规则卡 / 裁判规则库 脱敏打包 | 数字资产中台(核心) + 业务中台(质检) | 知产归拟法人；售前脱敏；授权明示 | 中 |
| 文书代写（法律咨询外包品类） | 文书草稿 → 老强终确认终稿，标"AI 辅助/待律师确认" | 业务中台(蓝队起草+红队预审) + 数字资产中台 | 草稿标 AI 辅助；终稿老强担责；不得冒用律师署名 | 中 |

> 文书代写归入"法律咨询外包"业态品类，不另立第四业态，保持三种业态口径稳定（引 `对外经营耦合与业务开拓建议方案_v0.1.md` §3.1）。

### 8.2 商业运营线（对外经营线）

- **定位**：对外经营侧闭环（获客 → 转化 → 交付 → 复购 → 知产），补四中台"生产侧"之缺；归位方案 A/B/C（当前采用 C：文档先行，试点后升 A，见 `对外经营耦合与业务开拓建议方案_v0.1.md` §4）。
- **公司级 SOP 唯一收敛点**：`09-OPC/商业化运营/商业运营SOP总册_对外经营线.md`（横向册，姊妹于 `部门治理/00-横向铁律执行总册.md`），三业态 + 运营中台-商业轨 统一引用。
- **红线不破**：定价 / SKU / 规则包发布 = R-2 老强拍板；文书终稿 = R-1 老强终确认；对外材料脱敏；数字员工对外披露 Phase 4 补（引 `数字员工编制方案_v1.0.md` §5.3）。
