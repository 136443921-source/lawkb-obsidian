## 🧭 分层定义（与 DEC-2026-023 对齐）

| 层 | 组成 | 本质 | 是否接客户 |
|---|---|---|---|
| **前台** | 企微 Claw 渠道、公众号 | 客户触点 / 获客，不做内部编排 | 是（触点） |
| **中台① 法律服务中台** | 统一接待分诊台 ＋ 咨询线 ＋ 文书线 | 业务生产 / 交付层 | 是（经分诊产出交付物） |
| **中台② 数字资产中台** | 模板 / 规则包 / 知识卡（资产运维官） | 资产供给 / 支撑层（SSOT） | 否（内部供给） |
| **后台** | 合规 / LTI / 9655 监控 | 风控与质量门禁（监督层） | 否（只监督不产出） |

> **双中台并列、职责不重叠**：①法律服务中台"产"、②数字资产中台"供"；入口（router+拷问门）归属①，资产沉淀在②。

> **层级同构说明**：法律服务中台既是宏观「中台层」实体（与数字资产中台并列），亦为四中台（**法律服务中台 / 数字资产中台 / 运营中台 / 可视化中台**）部门之一——与数字资产中台同构；原"业务中台"已统一更名（见 `opc_索引.md` v1.7 / `公司章程.md` v1.8）。

## 🚪 入口角色：统一接待分诊台

- **构成**：`legal-consult-router` ＋ 需求**拷问**前置门禁（`grill-me-legal-preprocessor`）。
- **流程**：router 接所有法律诉求 → 拷问门先做意图澄清 → 五问分诊 → 派发到咨询线或文书线。
- **覆盖口径（域级全入口）**：router 自身（预置接入，hook 显式豁免拦截）＋ 72 个下游法律域技能 = **73/73（含 router）**。D9 面板（`/sharedhub/grill_gate`）已如实体现 `declared=73 / total=73 / unwired=[]`。
- **灰度部署**：Hook 模式 `off` → `warn`（观察期） → `block`，硬强制 + 软接线（第零步 + 面板）双轨。

---

## 🔀 两条营收线（中台①内部）

- **咨询线**：分诊到各专项技能（人损 / 医疗 / 合同 / 慈善合规…）→ 出法律意见、备忘录。
- **文书线**：分诊到文书生产链（docx 交付流水线 / 红蓝复核 / 非诉文书复核）→ 代写交付。
- **与中台②上下游**：文书线从数字资产中台**取**模板 / 规则包 / 知识卡，形成"中台消费、中台供给"闭环——入口在法律服务中台，资产在数字资产中台，二者不重叠。
