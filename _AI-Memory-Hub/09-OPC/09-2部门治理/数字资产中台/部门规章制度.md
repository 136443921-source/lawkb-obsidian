## 一、部门定位与归属

- **部门名**：数字资产中台
- **职能归属**：数字资产 中台（OPC 四大中台之一）
- **汇报线**：→ 总经理（律所主任·管理合伙人）→ 老强（超级管理员·唯一股东）
- **部门定位一句话**：分身系统**法人资产（LawKB 独立仓库）的知识生产与治理中枢**，承载拆卡流水线 + 卡库接线 + **法条银行科室（lawkb-法条银行 子系统 CRUD 治理）**，向总经理汇报、受监督层（LTI）门禁。
- **下属科室**：**法条银行科室**（专司 `~/Documents/LawKB/法条银行/` 子系统增 / 查 / 改 / 核填治理；行长 = 数字员工·法条银行行长，详见岗位手册第 10 章）；**下属设备**：**知识飞轮设备（KF-DEV）**——系统型设备，复用现有知识飞轮系统（采集→提炼→连接→巩固→调用→沉淀 六层 + 驾驶舱 + IMA 摄入自动化），封装为设备并指定**设备主机 = 数字员工·数字资产运维官**（详见岗位手册第 11 章、接入 SOP-AST-10、设备总线 SOP-AST-09）；其余为流程型归口（7 拆卡流水线 + 卡库接线）。

## 五、资产登记册管理办法（SSOT）

本中台维护全公司级《数字资产登记册》（`OPC 一人公司/00-数字资产登记册/asset_registry.json`），为数字资产唯一事实源（SSOT），由数字资产运维官任 owner_seat。

1. **分类轴（含设备 / 设施形态）**：登记册按资产形态设 11 大类——知识库 / 规则库 / 卡库 / 技能 / 连接器 / 中台面板 / 自动化 / 心智模型手册 / 规则包(交付物) / **设备 DEV** / **设施 FAC**。设备（DEV）指封装为标准化产出的子系统（含本中台 KF-DEV 及业务中台 CLM / CMS / Cont-LCM / MCM 四台）；设施（FAC）指支撑性基础设施（驾驶舱屏位、连接器链路等，按需登记）。
2. **设备当轮入册铁律**（继承资产运维官铁律①）：任一设备完成接入（SOP 落地 + 试点通过）当轮即在登记册建条，设备 ID 前缀 `DEV-`，owner = 设备主机（唯一），违则「资产不编目 = 资产不存在」。
3. **条目字段强制**：每条须带 id / name / category / version / owner / location / status / commercializable / billing_domain / last_verified（实测日期，禁止空）/ source_of_truth / notes；设备类另记 设备总线 SOP + 接入 SOP + 制品 frontmatter 口径。
4. **owner 唯一制**：每台设备 owner 唯一指向其设备主机数字员工；共用资产（如卡库）owner 可并列但须标注主责席。
5. **实测与漂移回写**：last_verified 为实测日期，非编撰；记载与实测不符即判文档漂移，须回写本册并三处同步（workspace → 中枢 → git backfill，禁裸 git）。
6. **门禁**：登记册改动经资产运维官 + 中枢 backfill 安全通道（`backfill.py` `_run_git`），遵循 PREF-006。
