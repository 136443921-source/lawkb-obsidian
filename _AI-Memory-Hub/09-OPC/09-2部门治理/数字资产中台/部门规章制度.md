## 一、部门定位与归属

- **部门名**：数字资产中台
- **职能归属**：数字资产 中台（OPC 四大中台之一）
- **汇报线**：→ 总经理（律所主任·管理合伙人）→ 老强（超级管理员·唯一股东）
- **部门定位一句话**：分身系统**法人资产（LawKB 独立仓库）的知识生产与治理中枢**，承载拆卡流水线 + 卡库接线，向总经理汇报、受监督层（LTI）门禁。

---

## 二、部门职责边界（与章程 RACI 对齐）

| 职责 | 性质（A/R/C/I） | 说明 | 是否触四类 R |
|---|---|---|---|
| 知识入库（飞轮拆卡 / 接线） | A | 各拆卡流水线执行，LTI R 校验 | 否（LTI R） |
| 卡库接线（裁判规则库 / 审判要件卡挂载） | A | 把智能体接上卡库，可回溯卡源 | 否 |
| 资产治理（LawKB 独立仓库物理隔离） | A | 仓库权属 / 备份 / 跨案隔离 | 否 |
| 法条核验 / 回源 | C | pkulaw 主源回填，禁凭记忆 | 否 |
| 一致性审计 / 冲突仲裁 | C | 法条一致性 + 卡族冲突仲裁 | 否 |
| 知产登记结论 | A（资产层） | 脱敏后对外 | **是（R-2/R-1 须老强）** |

> 凡涉及四类 R（对外出件 / 定价发布 / 批量删改单源 / 新增改造子系统）的职责，本部门不得自主决策，须移交老强（引总册 §一）。知产登记结论权属老强（章程 RACI）。

## 四、内部协调与派工规则

- **派工来源**：承接总经理知识入库调度（引总经理职权 §2 知识入库调度）。
- **优先级机制**：对外出件关联知识（R-1 待老强）＞ 一致性审计 / 冲突仲裁 ＞ 常规拆卡入库 ＞ 监测。
- **交接规则**：拆卡任务交接须含"在办卡族 + 门禁状态 + 待老强确认项（知产）"；单源重建前 `cp -n` 防覆盖（引总册 §五）。

---

## 五、质量门禁承接

- 所有文本制品过 LTI（REJECT=0 才准交付）——引总册 §二。
- 所有写入 / 批量动作过六-B + 破坏性预检五条——引总册 §三 / §五。
- 法条引用：pkulaw 主源回填，本地源引证（仅引本地法律法规库源，否则标 `statute_text_pending`）——引总册 §六。
- 资产治理：LawKB 独立仓库物理隔离，中枢 git 走 `backfill.py`（禁裸 git），跨案隔离——引总册 §七。

## 七、交接与复盘

- **日常复盘**：周复盘向总经理汇报（入库量 / 门禁通过率 / 待回源清零进度）。
- **治理复盘**：配合周五周报 + 周日 self-improve（引总册 / 公司章程 §7）。
- **异常闭环**：HIR 幻觉事故 / 卡族冲突 → 建卡 + 仲裁（协同 `lawkb-conflict-arbitration`）。
