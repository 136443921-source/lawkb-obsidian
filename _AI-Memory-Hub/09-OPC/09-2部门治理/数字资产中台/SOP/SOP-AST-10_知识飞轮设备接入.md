> 链接式 SOP：KF-DEV 为**系统型设备**（复用现有知识飞轮系统：**采集→提炼→连接→巩固→调用→沉淀** 六层 + 驾驶舱 + IMA 摄入自动化，**不新建系统、不增编**）。本册只写"何时调 / 谁调 / 产出落哪 / 门禁怎么过"，并在数字资产运维官岗位说明增"设备主机"职责段（不重抄流程正文）。流程细节以 `资产运维官` skill 与知识飞轮系统既有脚本为准。

## 一、目的与适用范围

- **目的**：规范 KF-DEV 知识飞轮设备作为数字资产中台**设备主机（数字资产运维官）**的职责落地与调用，标准化产出 `知识卡`（入卡库）/ `回补产物` / `驾驶舱刷新`，落实"设备有人管理"。
- **适用范围**：知识入库（飞轮拆卡 / 接线）/ IMA 摄入 / 回补作业 / 驾驶舱与资产健康看板刷新。
- **不适用**：诉讼业务（走 CLM）/ 合规审查（走 CMS）/ 合同非诉（走 Cont-LCM）——这些消费方调卡经 SOP-AST-07 接线。
- **源规范（权威）**：`数字资产中台·部门规章制度.md` §二（知识飞轮设备运维）/ §三-B（知识飞轮设备）；`资产运维官` skill（席位心智与作业手册 v1.0）；`数字员工岗位手册.md`（第 11 章·设备主机职责段）。

## 五、质量门禁（强制）

- 文本制品：必过 LTI（REJECT=0）——引总册 §二。
- 写入 / 批量：必过六-B + 破坏性预检（先备份→dry-run→改→复测→验幂等）——引总册 §三 / §五 / 资产运维官 skill 铁律。
- 静默成功熔断：产不足 60% 中止——引总册 §四。
- 法条 / 内规引用：pkulaw 主源回填，禁凭记忆——引总册 §六。
- 资产治理：LawKB 独立仓库，中枢 git `backfill.py`——引总册 §七。
- 制品元数据：必带 frontmatter（含设备_id=KF-DEV）——引资产运维官 skill。
