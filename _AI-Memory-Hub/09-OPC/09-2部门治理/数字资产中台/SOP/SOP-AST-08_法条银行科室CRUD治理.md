## 一、目的与适用范围

- **目的**：规范 `~/Documents/LawKB/法条银行/`（lawkb-法条银行 子系统）的**增 / 查 / 改 / 核填 / 归档**治理，确保本地法条权威源的元数据一致性、版本双证与覆盖缺口滚动。
- **适用范围**：法条银行行长对法条银行子系统的日常 CRUD；归属数字资产中台「法条银行科室」。
- **不适用**：卡库接线（走 SOP-AST-07）、对外出具法律意见（R-1，老强终确认）。
- **源规范（权威）**：`法条银行/_Schema规范_v1.0.md`（RULE-038，两型 frontmatter + 命名规范 + 版本治理铁律）；补充 `法条银行搭建建议方案_v1.0.md`（三件套收口：统一 Schema + 版本双证 + 覆盖台账）

## 二、触发条件

| 触发 | 说明 | 责任方 |
|---|---|---|
| 新增法条卡 / 核填回填 | 新法入库、待回源清零（`statute_text_pending` → false） | 法条银行行长（A 授权） |
| 查（覆盖台账 / 缺口滚动） | 月度复检、缺口 P0–P2 滚动 | 法条银行行长（A 授权） |
| 改（版本治理 / 元数据一致性） | 双证不一致、schema 三套并存整改、命名规范化 | 法条银行行长（单条 A；批量 R-3） |
| 归档（版本冲突处置） | 旧版法规 → 移 `_archive` 不删，标注 `superseded_by` | 法条银行行长（R-3 须老强拍板） |

> **四类 R 咬合（老强裁决 2026-09-23）**：增 / 查 / 改单条 / 核填 = **A**（行长执行、老强抽检）；**删 / 批量改写单源 = R-3**（须老强拍板，行长不得自主决策）。

## 四、质量门禁（强制）

- 文本制品：必过 LTI（REJECT=0）——引总册 §二。
- 写入 / 批量：必过六-B + 破坏性预检五条（引用预检 / cp 备份 / dry-run / 安全扫描 / 确认非误报）——引总册 §三 / §五。
- 法条回源：pkulaw 主源 > 元典 > 本地核准表；禁凭记忆灌条文——引总册 §六。
- 资产治理：LawKB 独立仓库物理隔离，中枢 git `backfill.py`（禁裸 git）——引总册 §七。
- 静默成功熔断：核填 / 批量产出量 < 期望 60% 即中止写盘——引总册 §四。

---

## 五、异常处理

| 异常 | 处理 |
|---|---|
| LTI REJECT≠0 | 退回修改，不得带权威源光环出库 |
| 双证不一致 / 版本存疑 | `sxx:待核验` + `statute_text_pending:true`，不得引用，报老强核填 |
| 批量改写单源 | 触发 R-3，暂停并移交老强拍板 |
| 静默成功（产出不足） | 熔断中止 |
