## 3. 载入机制：四台设备如何挂进业务中台

### 3.1 两类接入范式（仿已定子科室骨架，老强裁决 2026-09-24 固化）

| 设备 | 接入方式 | 落地动作 |
|---|---|---|
| CMS / MCM（智能体型） | 直接复用现有数字员工 + 现有 SOP（小德走合规 SOP、MCM 走 SOP-BUS-03/04） | 在岗位说明 / 科室 SOP 中**增"设备主机"职责段**，零章程改动、不新建 |
| CLM / Cont-LCM（设备型） | 仿"法条银行科室"但**不建岗位** | 新建「设备接入 SOP（链接式）」+ 设备元数据描述；设备壳由现有数字员工操作 |

### 3.2 设备总线 · 单一入口（老强裁决 2026-09-24 固化）

- 在 `业务中台·部门规章制度` §二 **增"设备调度"职责**（A：总经理派工；C：承接）。
- 新增 **`SOP-BUS-0X《业务中台设备总调度》`（链接式）**：只写"何时调哪台设备 / 谁授权调 / 制品过哪道门禁 / 落哪"，流程正文链接各设备 SOP。
- **四台设备统一走设备总线单一调度入口**，禁止智能体绕开门禁直接产制品（解决"各自直连 vs 统一入口"问题，裁决=统一入口）。

### 3.3 制品统一元数据 frontmatter（老强裁决 2026-09-24 固化 · 强制）

四台设备制品**强制统一 `制品元数据 frontmatter`**（为 C9 屏抓取 + 中枢回写），规范见 §3.5。未带 frontmatter 的制品不得入库 / 不得上屏。

### 3.4 资产隔离（物理边界不变）

案件 / 合同 / 合规 / 推演数据均属业务产物，归入 LawKB 独立仓库对应子库（物理隔离）；当事人隐私 / 证件号按商业化运营备忘录 §知产 脱敏，不进中枢；单源重建前 `cp -n` 防覆盖至 `/tmp/时间戳`（引总册 §三 / §五）。

### 3.5 制品元数据 frontmatter 规范（强制 Schema）

每台设备产出的制品文件头部须含以下 YAML frontmatter（供 9655 屏抓取 + 中枢 `backfill.py` 回写）：

```yaml
---
设备_id: CLM-DEV | CMS-DEV | CONTLCM-DEV | MCM-DEV
制品类型: 案件档案包 | 合规审查报告 | 合同审查报告 | 推演战报
制品版本: v0.1
操作工: 数字员工·<岗位名>
门禁状态: 草稿态/待LTI校验 | REJECT=0已通过 | 待老强终确认(R-1) | 终稿
落点: <绝对路径>
生成时间: <ISO8601>
关联案件_项目: <案件号 / 项目标识>
---
```

> 门禁状态须与 LTI 实测结果一致；`待老强终确认(R-1)` 类制品未经老强拍板不得标"终稿"。门禁双轨判定见 §3.6。

### 3.6 LTI 门禁双轨（本地源 / 权威源实拉降级）· 常驻路径（P0 固化 · 2026-09-24 试点暴露）

阶段 1 CLM 试点（载体 A 吊顶案 6658）暴露真实缝隙：本地 LTI 权威源原路径 `法律法规库` 命名偏差（`lti_verify.py` 指向旧名且子目录不匹配），导致本地源判缺失、无法出具 REJECT=0（依 R1 铁律正确拒假 PASS）。2026-09-24 已统一命名为「**法条银行**」（`LawKB/法条银行/`，子目录 通用实体法 / 通用法律法规 / 程序法 / 司法解释），并修正 `lti_verify.py` 路径常量——民法典 / 民诉法等已导入法条现可由轨 A 本地核验；民诉法解释等未导入文件仍走轨 B。为杜绝"因源缺失阻断交付"或"为过门禁而凭记忆兜底"，固化 **门禁双轨** 为设备化常驻路径：

- **轨 A（优先）**：本地 LTI 脚本 `lti_verify.py` —— 本地权威源齐备时自动核验，REJECT=0 即门禁通过。
- **轨 B（降级 · 常驻）**：本地源缺失 / 轨 A 无法出具 REJECT=0 时，**强制经权威源实拉核验** —— qcc-legal（企查查·法律数据）/ pkulaw（北大法宝）等已连接权威源，对制品法条主张逐条实拉，返现行有效性 + 逐字原文 + 要点闭合判定；三项均现行有效、要点闭合 → 视为 REJECT=0。
- **门禁判定**：轨 A 或 轨 B 任一 REJECT=0 → 制品门禁状态升"REJECT=0已通过"；两轨均 REJECT≠0 → 退回修改，不得带草稿态对外。
- **铁律（R1 不降级）**：禁止为过门禁凭记忆兜底条号/原文；轨 B 须以已连接权威源实拉结果为准，并记入门禁日志（权威源名 + 核验时间 + 条文时效性）。
- **设备上线六-B 预检**：设备接入 SOP 须含"LTI 本地权威源配置检查"；缺失则降级轨 B 强制启用，不得因源缺失阻断交付。

## 4. 一台设备的标准运行生命周期（工序链）

```
输入(案卷/材料)
  → 智能体经设备总线调设备（单一入口）
  → 工序链执行（产草稿态制品 + 写 frontmatter）
  → 设备总线统一过 LTI（双轨门禁，REJECT=0? 见 §3.6）
        ├─ 轨A 本地源核验 REJECT=0 → 通过 ↓
        ├─ 轨A 缺失/未过 → 轨B 权威源实拉(qcc-legal/pkulaw) REJECT=0 → 通过 ↓
        └─ 两轨均 REJECT≠0 → 退回修改（不得带权威源光环出库）
  → R-1 类?(对外终稿)
        ├─ 是 → 移交老强终确认 → 终稿
        └─ 否 ↓
  → 入库 / 回传 LawKB + 中枢 git backfill.py（禁裸 git）
  → C9 治理中台屏刷新（在制 / 产能 / 门禁通过率）
```

> 静默成功熔断贯穿：任一设备产出 < 期望 60% 即中止写盘（引总册 §四）。
