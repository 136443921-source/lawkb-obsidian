# SOP-BUS-01：诉讼文书红蓝复核

**版本**：v1.0　**日期**：2026-09-22　**Owner**：业务中台　**性质**：部门业务流程 SOP（纯文档，不碰配置）

**维护**：修订须总经理执行、老强批准；与源 skill 冲突以源 skill + 总册为准

## 一、目的与适用范围

- **目的**：诉讼 / 仲裁类法律文书起草或审核时，联合蓝队（防御完整性）与红队（预驳回攻击）红蓝对抗复核，配 LTI 交付门禁，提升文书准确性与可行性。
- **适用范围**：民事 / 刑事 / 行政 / 仲裁 程序的诉讼文书（起诉状 / 答辩状 / 上诉状 / 再审申请书 / 代理词 / 法律意见书等）。
- **不适用**：纯内部笔记 / 非诉讼文书（走 SOP-BUS-02 或对应非诉 SOP）。
- **源流程（权威）**：`诉讼文书红蓝复核工作流` — 路径 `~/.workbuddy/skills/诉讼文书红蓝复核工作流/SKILL.md`　★ **正文以该源为准**

---

## 二、触发条件

| 触发 | 说明 |
|---|---|
| 起草诉讼 / 仲裁类文书 | 蓝队或人工起草后需复核 |
| 审核他人文书 | 收到待审核诉讼文书 |
| 庭前文书定稿前 | 拟对外 / 上庭前最后复核 |

---

## 三、标准步骤（链接式）

| 步 | 动作（调哪个 / 谁调） | 责任方 | 产出落点 | 源流程章节 |
|---|---|---|---|---|
| 1 | 调 `蓝队出庭律师` 做防御完整性体检（谈案 / 出庭 / 证据 / 攻防） | 数字员工·蓝队诉讼律师 | 蓝队体检报告 → 案件夹（`桌面办案系统/案件/庭审十件套`） | 诉讼文书红蓝复核工作流 §蓝队 |
| 2 | 调 `红队出庭律师` 做预驳回攻击（逻辑断层 / 法条 / 管辖 / 时效） | 数字员工·红队律师 | 红队战报 → 同案件夹 | 诉讼文书红蓝复核工作流 §红队 |
| 3 | 调 `LTI 文本监控器` 门禁校验（五维 QC + 六维法理） | 监督层 | REJECT=0 才准交付 | 总册 §二 / 公司章程 §4 |
| 4 | （可选）`三轮冲击控制器` 迭代：蓝队改 → 红队再批 → 定稿 | 蓝队 + 红队 + 控制器 | 迭代记录 → 案件夹 | 三轮冲击控制器 SKILL |

> 蓝队家族四席独立（RULE-BLUE-DISAMBIG），不互套评分卡；红队"不下场做建设式合规"，仅挑刺。

---

## 四、质量门禁（强制）

- 文本制品：必过 LTI（REJECT=0 才准交付）——引总册 §二。
- 写入 / 批量：必过六-B + 破坏性预检五条（cp 备份 / dry-run / 安全扫描）——引总册 §三 / §五。
- 构建产物：必过静默成功熔断（产出 < 期望 60% 即中止）——引总册 §四。
- 法条引用：必走 pkulaw 主源回填，禁凭记忆——引总册 §六。

---

## 五、异常处理

| 异常 | 处理 |
|---|---|
| 静默成功（产出不足） | 熔断中止，不写盘，报告 owner（业务中台） |
| LTI REJECT≠0 | 退回修改，不得带草稿态对外 |
| 回归基线失效 | 回滚至基线，记入治理复盘 |
| 四类 R 触发（对外终稿） | 立即移交老强终确认，本部门不决策（引总册 §一） |
