## 一、目的与适用范围

- **目的**：把每日校齐自动化（`015696af`『9655 驾驶舱·每日数据校齐』）**只出差异、不闭环**的缺口堵上——
  **②口径差异／③断流·缺失／④越权·异常 三类差异，必须当日建卡、按期处置、按期核销**，
  并在周报里与校齐率**并列成行**，防止「天天有差异、天天没人管、周报看不见」。
- **适用范围**：9655 驾驶舱每日校齐输出的全部 ②③④ 类差异（分级口径见接管方案 §5.10.4-A4）。
- **不在范围**：①一致项（无需建卡）；屏新增/改版（走 SOP-VIS-02）；大屏修复动作（走 SOP-VIS-04）。
- **硬约束**：**建卡≠处置**。只建卡不处置的，等于把问题从「每日校齐」搬到了「某个卡文件夹」，
  本 SOP 的意义全在 §四 的闭环状态机。

## 二、触发条件

| 触发 | 说明 | 时限 |
|---|---|---|
| 每日 08:20 校齐跑出 ②③④ 类差异 | 主触发。校齐脚本 + 心跳判据（`fresh_h > 26` 判 ③断流） | **当日**建卡 |
| `fresh_h > 26` | ③断流，**置顶**，优先级高于其它 ②③④ | **当日**建卡 |
| 同一差异连续 3 日未下降 | 自动升级为 P1，进周报红区 | T+3 |
| 连续 3 日屏校齐率 < 95% | 判故障升 P1（接管方案 §5.10.6 第 6 步口径） | T+3 |
| 周五 17:00 周报 | 校齐率 + 卡闭环率**并列成表** | 每周 |

## 三、卡编号与模板

### 3.1 编号规则

```
CRT-YYYYMMDD-NN
│   │        └─ 当日第几张（当日流水号，从 01 起）
│   └─ 日期（建卡当日，非处置日）
└─ 前缀（CRT = Cockpit Reconcile Ticket，驾驶舱校齐单）
```

### 3.2 卡模板（最小必填 8 列）

| 字段 | 说明 |
|---|---|
| 卡号 | `CRT-YYYYMMDD-NN` |
| 差异类型 | ②口径差异 ／ ③断流·缺失 ／ ④越权·异常 |
| 差异原文 | 校齐脚本 `drift[]` 或心跳判定原文，**不得改写** |
| 影响面 | 涉及屏号 / 指标 / 文件 |
| 责任席位 | 见 §三.3 派单表 |
| 整改建议 | 一句话可执行的动作（**禁止写「加强关注」类空话**） |
| 建卡时间 | 当日 08:20 后 |
| 闭环状态 | 见 §四 状态机（见 → 处置 → 核销 → 归档） |

> 🔴 **③断流卡必须附 `fresh_h` 实测值**，否则核销时无法证明「数据确实在动」。

### 3.3 派单表（差异类型 → 责任席位）

| 差异类型 | 责任席位 | 说明 |
|---|---|---|
| ③ 断流／缺失（`fresh_h > 26` 或 KPI 缺失） | SEAT-07 IT 运维员（可视化中台·F） | 先查扫描任务 `.scan`/`load` 是否加载、服务是否崩，再查展示层 |
| ② 口径差异（屏/指标与基线快照不一致） | 总经理（B）定口径后 SEAT-07 执行 | 口径裁定属 R-4 决策，AI 无权自行裁定 |
| ④ 越权／异常（rbac 可见性与角色不匹配） | 总经理（B）＋ 老强（A） | 涉权限，属 R 动作，须拍板 |

## 四、闭环状态机（本 SOP 的核心）

```
① 见（T+0 当日）
      │  建卡，注明责任席位 + 整改建议
      ▼
② 处置中（责任席位接单）
      │  执行整改（过六-B：备份→dry-run→确认→执行→验证）
      ▼
③ 待核销（责任人回填处置结果）
      │  校齐脚本复跑证据：drift_count 下降 / fresh_h ≤26 / aligned:true
      ▼
④ 核销（可视化中台·监控运维职能复核后关闭）
      │  复跑证据不足 → 打回②，不得直接关
      ▼
⑤ 归档（进周报汇总表，保留 90 日后转入 `09-2部门治理/治理复盘归档/`）
```

| 状态 | 超时规则 | 超处置 |
|---|---|---|
| ② 处置中 | > 3 日未动 | 自动升 P1，进周报红区 |
| ③ 待核销 | > 2 日未核销 | 打回 ② 并计一次「核销逾期」 |
| ④ 核销后 | 同一卡根因 30 日内复现 | 升 P1（重复故障，同 SOP-VIS-04 §三 第 6 步） |

> **核销唯一凭据**：**复跑 `drift_check_9655.py` 的输出**（只读，退出码 + `drift_count` + `aligned`）
> 或心跳实测 `fresh_h ≤ 26`。**没有复跑证据的一律不核销**——这是防止「口头已修复」的硬闸门。

## 六、周报并列表（周五 17:00 强制项）

**周报必须同时出现下面两行，禁止合并成一个数，禁止只报校齐率不报闭环率。**

| 指标 | 算法 | 目标 | 本周 |
|---|---|---|---|
| **屏校齐率** | ①一致项 ÷ 总比对项 | ≥ 95% | — |
| **卡闭环率** | 当周核销卡数 ÷ 当周建卡数 | 100%（每逾期一张即欠） | — |
| ├ 已建卡 | — | — | — |
| ├ 已核销 | — | — | — |
| └ 逾期（②>3日 / ③>2日） | — | **0** | — |

> 若本周无卡（全绿），**仍需在周报写「本周无 ②③④ 类差异」**——不写会被当成「漏跑」。

## 七、红线

1. **严禁只建卡不处置**：卡连续 3 日停在「见」状态 → 自动升 P1（同 §四 超时规则）。
2. **严禁无证据核销**：无复跑输出不得关闭卡片。
3. **严禁顺手改展示层**：整改只修「坏」，改屏号/布局/配色/title/HTML → 回 SOP-VIS-02。
4. **严禁运行 `scan_9655.py`**：写入型，会重写 `scorecard_data.json`（写入型脚本红线）。
5. **A7 不静默成功**：校齐链路异常（退出码非 0 / 零产出）→ 中止并明报，**不得伪装成校齐通过**。
6. **六-B 前置**：任何写入动作先 `cp` 备份到 `/tmp` 时间戳目录，先 dry-run 再执行。
7. **macOS grep 坑**：BSD grep 不支持 `\|` 交替，否定型检测一律写 `grep -E "A|B"`，否则静默假阴性。
