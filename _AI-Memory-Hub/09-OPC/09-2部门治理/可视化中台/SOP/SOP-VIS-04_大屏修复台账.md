## 一、目的与适用范围

- **目的**：把散落在 `00-系统总览与运维中心/8139大屏修复备忘录/`（11 份修复记录）的**大屏修复历史**收成一份受控台账，做到「同类故障可查、责任可溯、修复可复用」，避免同类事故重犯（承 PREF-009 异常闭环）。
- **适用范围**：9655 驾驶舱及其前身 8139 大屏的**一切修复、回归、版本回退**动作。
- **不在范围**：屏的新增/改版/下线（走 SOP-VIS-02 屏增审批）；日常数据校齐（走 SOP-VIS-01 / 接管方案 §5.10）。
- **历史素材**：原 11 份备忘录**并入本台账存档，不删除**，作为台账第 8 列「归档位置」的索引来源。

---

## 二、触发条件

| 触发 | 说明 |
|---|---|
| 修复发生时 | 任何大屏修复动作必须**先建台账行**，再动手（先登记后修复） |
| 回归验证通过 | 修复后回填回归结果，台账行关闭 |
| 每日 08:30 | L2 巡检第 7 项「驾驶舱健康」异常 → 属修复范畴，转本流程 |
| 每季度 | 台账盘点一次，识别重复故障与共性根因 |

## 三、标准步骤（链接式）

| 步 | 动作（调哪个 / 谁调） | 责任方 | 产出落点 | 源材料 |
|---|---|---|---|---|
| 1 | 建台账行：编号 + 现象 + 等级（P0–P4） | 可视化中台·监控运维职能（SEAT-07） | 大屏修复台账（本册 §四） | L1 每日整改清单 |
| 2 | **过六-B 后动手**：备份 → dry-run → 确认 → 执行 → 验证 | 数字员工·IT运维员（SEAT-07） | 修复记录 + 备份目录 | `00-横向铁律执行总册` §三 |
| 3 | 记根因与处置措施（不写"已修复"三字收工） | IT 运维员（SEAT-07） | 台账第 4–6 列 | — |
| 4 | 回归验证（采样两次一致 + 非空 + 形态未被改动） | 可视化中台 | 台账第 7 列 | 接管方案 §5.5 联调门禁 |
| 5 | 关闭台账行 + 归档位置登记 | 可视化中台 | 治理复盘归档（季度） | — |
| 6 | 重复故障（同一根因季度内 ≥2 次）→ 升 P1 并进周报 | 可视化中台 | 周报 + 治理复盘 | 接管方案 §5.7 |

> **不改形态硬约束**（承接管方案 §5.10.1）：修复只修"坏"，不趁机改屏号/布局/配色/title/HTML；需要改形态 → 回 SOP-VIS-02 屏增审批。

## 五、异常处理

| 异常 | 处理 |
|---|---|
| P0 事故（门户挂 / 评分卡 NaN / 案号外泄 / 驾驶舱不可达） | 立即单独告警老强（20:00–08:00 亦不得拦截）+ 建台账行 + 走 PREF-009 事故卡 |
| **前端点击无反应类故障**（L-7） | 直接按 `00-系统总览与运维中心/前端点击无反应排查SOP-运维卡片.md` 排查，**排查结论回写到本台账第 5–6 列** |
| 修复导致形态变化 | 立即回滚 + 报老强 + 记入治理复盘（SOP-VIS-02 §五） |
| 同一根因季度内 ≥2 次 | 升 P1，进日报/周报，并要求整改而非重复修 |
