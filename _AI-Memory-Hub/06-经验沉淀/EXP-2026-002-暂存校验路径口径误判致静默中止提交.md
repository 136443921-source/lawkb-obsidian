# 暂存校验路径口径误判导致提交静默中止

> 类别：事故复盘 / 可迁移教训。发生于 2026-09-14 22:33 中枢提交（书记员训练三件套入中枢），已修复并通过实证。

## 一、现象

用 `backfill.py --files <11 个文件>` 提交中枢卡片，输出：

```
[WARN] add 后暂存区缺 11 个文件，逐个补 add：…
[WARN] 仍无法暂存：…
[DONE] 提交通道失败，请检查
```

但事后 `git diff --cached --name-only` 显示——**11 个文件全部已成功暂存**。即：`git add` 是成功的，是**校验逻辑误判**导致脚本提前 `return False`，commit/push 根本没执行。

## 二、根因

`git_commit_push()` 的暂存区校验：

```python
staged = git diff --cached --name-only   # 输出已是「相对仓库根」的相对路径
staged_set = set(os.path.relpath(s, repo) for s in staged)   # ❌ 对相对路径再 relpath
missing = [c for c in changed if os.path.relpath(c, repo) not in staged_set]
```

1. `git diff --cached --name-only` 在 `cwd=repo` 下输出形如 `_AI-Memory-Hub/00-全局规则/xxx.md` 的**相对路径**。
2. `os.path.relpath(s, repo)` 对**本已相对**的路径，会先 `join(cwd, s)` 再算相对关系 → 路径失真（变成 `../..` 一串）。
3. 于是 `missing` 恒为全部文件 → 逐个补 add → 仍误判 → 提前中止。

**本质**：混用两种坐标系（相对 vs 绝对），未归一化就比对。

## 三、修复（已落地）

统一归一化为「相对仓库根」的 POSIX 相对路径：

```python
def _rel(p):
    # 相对路径按 repo 基准解析（git 以 repo 为 cwd，语义即相对仓库根）
    ap = p if os.path.isabs(p) else os.path.join(repo, p)
    return os.path.relpath(os.path.abspath(ap), repo).replace(os.sep, "/")

staged_set = set(_rel(s) for s in staged if s.strip())
missing    = [c for c in changed if _rel(c) not in staged_set]
```

> 注意**第二层坑**：直接写 `os.path.abspath(p)` 仍错——脚本运行时 `cwd` 是**脚本所在目录**（`99-脚本/hub-card-backfill/`），相对路径会被按 cwd 解析成 `.../99-脚本/hub-card-backfill/_AI-Memory-Hub/...`，路径翻倍。必须 `os.path.join(repo, p)` 显式按仓库根拼接。修复时**两种输入（绝对/相对）都实测过**才通过。

## 四、经验教训（可迁移）

1. **任何「读命令输出 → 与本地路径比对」的校验，必须先统一坐标系**。git 系列命令（`diff --name-only` / `ls-files` / `status --porcelain`）默认输出**相对仓库根**，而 `os.path` 系列默认以 **cwd** 为基准——二者混用必错。
2. **"保护性校验"本身也会成为故障源**。本例的校验本意是防"并发锁争用下静默漏暂存"，却因口径错而**把成功判成失败**。加校验时要同步验证校验逻辑自身的正确性，否则等于装了个会误报的报警器。
3. **失败信息要能区分"真失败"和"校验误判"**。本例 `[DONE] 提交通道失败` 让人以为是 git 出问题，实际是脚本中止——排查时应**先查 `git diff --cached` 实况**，再判断哪一层出错。
4. 修复后必须**两种输入形态都实测**（绝对路径 / 相对路径），只测一种会漏掉第二层坑。
