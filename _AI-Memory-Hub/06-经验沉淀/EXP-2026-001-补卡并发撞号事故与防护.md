# 补卡并发撞号事故与防护（双索引器竞态）

> 类别：事故复盘 / 可迁移教训。发生于 2026-09-14 补卡 WF-027/028，已沉淀防护并镜像至 `99-脚本/hub-card-backfill/`。

## 一、事故概述
补卡 WF-027/WF-028 时，发现 `04-Workflows/_索引.md` 中意外出现 WF-029/WF-030 两张「静态看板」卡片（非本次目标）。经 `git log` 还原，中枢内实际跑着**两个写入器**：

- ① 本 session 的 `backfill.py`（「按需补卡」流水线的索引更新器）
- ② 此前批准的「周日遗留盘点自动化 `6bd4143c`」内置的**目录自动索引器**（扫 `04-Workflows/` 下所有 `.md` 自动登记索引）

两者竞态：自动索引器先抢占 WF-027/028 两个 id（填入「静态看板…」内容），随后一个「撞号修正」提交将其重编为 WF-029/030，腾出空位给本 session。终态一致、正确（WF-027/028/029/030 四卡齐全、索引 45–48 行对齐），但暴露了写入器自身的脆弱点。

## 二、根因
1. **多写入器无全局取号门禁**：`backfill.py` 取号仅靠「读索引顺延」，与自动索引器无协调，id 被并发抢占。
2. **旧幂等检查只看 id 字符串**：`update_index` 用 `f"| {id_} |"` 匹配，撞号时 id 已存在 → 误判「已含跳过」，既不插入也不报错，**静默丢卡**。
3. **wikilink 转义 `\` 污染**：正则 `[^|\]]+` 贪婪吞掉 Obsidian 转义的 `\|` 反斜杠，使解析出的文件名带尾随 `\`，导致「同文件重跑」被误判为撞号。

## 三、防护机制（已落地并通过验证）
- `backfill.py` 新增 `parse_index_ids()` 解析 `{id: 文件名}`；`update_index()` 升级判定：
  - id 不存在 → 正常插入；
  - id 存在且指向**同文件** → 真幂等跳过；
  - id 存在但指向**不同文件** → `[ABORT] 撞号` 中止、**不写索引、不提交**（严禁覆盖他人卡片）。
- 正则改为 `[^|\]\\]` 显式排除反斜杠，文件名不再带尾随 `\`。
- 验证：语法 OK；真实索引解析不再带反斜杠；隔离测试模拟「不同文件抢 WF-027」→ 正确 ABORT 且真索引未被改；WF-028 实跑入库成功。

## 四、经验教训（可迁移）
- **多写入器必须配全局取号门禁**（参考 WF-024 LawKB 取号器 `next_rule_id` 的「单一真源 + 24h 预留」机制）；任何「读后写」的索引/登记类操作都需防竞态。
- **幂等校验必须比对「指向实体」而非仅 id**，否则撞号会静默丢卡、污染事实源。
- **对 Obsidian wikilink `[[a\|b]]` 的正则解析，字符类须排除 `\|` 的反斜杠**，否则文件名脏化触发误判。
- 镜像副本已固化至 `99-脚本/hub-card-backfill/`（含本防护），换设备 `git pull` 即得多设备复用版。
