# 谈案律师技能设计方案

**技能名称**：案件洽谈与材料整理助手（简称"谈案律师"）

**版本**：v1.0.0（设计草案）

**设计日期**：2026年5月28日

**设计师**：WorkBuddy AI Assistant（小强）

---

## 一、技能概述

### 1.1 核心定位

模拟**资深谈案律师**的工作方式，通过**自由对话**逐步澄清案情，智能解析多种格式材料（Word/PDF/文本 → 未来支持OCR/录音），自动判断是否需要法律检索（**检索前自动脱敏个人信息**），生成**经过LTI审核**的案件分析报告，并保存到Obsidian知识库。

### 1.2 适用场景

- ✅ 初次接待客户，需要快速理清案情、整理证据材料
- ✅ 复杂案件，需要系统梳理事实、证据、法律关系
- ✅ 需要快速生成"案件分析和行动建议报告"（带LTI审核）
- ✅ 需要与"法律检索助手"联动，自动进行法规和案例检索

### 1.3 核心原则（⚠️ 安全优先）

1. **本地存储原则**：所有案件信息只保存在本地，禁止上传云端。
2. **门禁原则**：只有授权用户（老强）才能查看和使用。
3. **总闸原则**：一键切断所有数据外流。
4. **检索环节个人信息脱敏机制**：调用"法律检索助手"前，自动脱敏个人信息（身份证号、电话、住址、照片等），防止外泄。

## 二、核心功能模块

### 2.1 模块1：自由对话式案情采集

**功能描述**：
- 你自由描述案情（文字、语音转文字、文件上传）
- 技能通过**追问**逐步澄清关键信息：
  - **人物**：当事人、对方当事人、第三人、法官/仲裁员（如有）
  - **时间**：事件发生时间、合同履行时间、侵权行为时间、诉讼时效
  - **地点**：事件发生地、合同履行地、侵权行为地、管辖法院
  - **事件**：案件事实、争议焦点、法律关系
  - **证据**：已有哪些证据、还缺哪些证据
- **你可以随时回溯修改**（如："刚才说的时间不对，应该是2023年5月"）
- **技能自动判断信息是否完整** → 完整后进入下一阶段

**⚠️ 安全机制**：
- 所有对话记录和案情信息**只保存在本地**，禁止上传云端

---

### 2.2 模块2：多媒体材料解析（分阶段）

#### 第一阶段（当前实现）：
- ✅ 解析Word文件（.docx）→ 提取文字内容
- ✅ 解析PDF文件（.pdf）→ 提取文字内容
- ✅ 解析文本文件（.txt、.md）→ 直接读取
- ❌ 图片OCR（暂不支持，第二阶段添加）
- ❌ 录音转录（暂不支持，第三阶段添加）

**⚠️ 安全机制**：
- 所有解析结果**只保存在本地临时目录**，禁止上传云端

#### 第二阶段（1-2周后）：
- ✅ 添加图片OCR功能（自动识别图片中的文字）
- **⚠️ 安全机制**（重要）：
  - **优先使用本地OCR工具**（如：Tesseract）
  - **如果必须使用在线OCR API**，则必须先对图片进行**脱敏处理**：
    - 遮挡人脸、遮挡身份证号、遮挡地址、遮挡电话号码等
    - 只发送脱敏后的图片给在线OCR API

#### 第三阶段（1-2周后）：
- ✅ 添加录音转录功能（自动将录音转为文字）
- **⚠️ 安全机制**（重要）：
  - **优先使用本地语音识别工具**（如：whisper.cpp）
  - **如果必须使用在线语音识别API**，则必须先对录音进行**脱敏处理**：
    - 变声处理、去除个人信息（如：姓名、身份证号、电话号码等）
    - 只发送脱敏后的录音给在线语音识别API

### 2.3 模块3：智能法律检索联动（⚠️ 检索前个人信息脱敏）

**核心流程**：
1. 技能根据**案情复杂度和关键词**，**智能判断**是否需要法律检索
2. 如果需要检索 → **先调用"个人信息脱敏模块"**
3. 将**脱敏后的案情信息**发送给"法律检索助手"
4. "法律检索助手"进行法规检索、案例检索、类案比对（可调用外部API）
5. 检索完成后 → **可选：将脱敏信息还原为原始信息**
6. 整合检索结果到案件分析报告中

**需要检索的情形**（自动调用"法律检索助手"）：
- 涉及**争议焦点**（如：合同效力、侵权责任认定、诉讼时效计算）
- **法律适用不明**（如：新法 vs 旧法、司法解释冲突）
- **类案参考价值高**（如：新型案件、疑难复杂案件）

**不需要检索的情形**（直接生成报告）：
- 事实清楚、法律适用明确的简单案件
- 你明确说"不需要检索"

**你可以随时干预**：
- 强制要求检索（如："这个案子需要查一下类案"）
- 要求跳过检索（如："事实很清楚，不用检索了"）

#### ⚠️ 需要脱敏的个人信息类型：

| 信息类型 | 脱敏后占位符 | 示例 |
|---------|--------------|------|
| 姓名 | `[当事人A]`、`[当事人B]`等 | 王德明 → `[当事人A]` |
| 身份证号 | `[身份证号]` | 520102199001011234 → `[身份证号]` |
| 联系电话 | `[联系电话]` | 13800138000 → `[联系电话]` |
| 家庭住址 | `[住址]` | 贵州省贵阳市XX路XX小区 → `[住址]` |
| 照片 | `[照片]`（或禁止上传） | 身份证照片 → `[照片]` |
| 银行卡号 | `[银行卡号]` | 6222021234567890123 → `[银行卡号]` |
| 电子邮箱 | `[电子邮箱]` | example@email.com → `[电子邮箱]` |
| 工作单位详细地址 | `[工作单位]` | XX公司XX楼XX室 → `[工作单位]` |
| 家庭成员姓名 | `[家庭成员A]`、`[家庭成员B]`等 | 张三 → `[家庭成员A]` |
| 案件编号 | `[案件编号]` | 2023黔01民初123号 → `[案件编号]` |
| 法院案号 | `[法院案号]` | (2023)黔01民初123号 → `[法院案号]` |

#### 脱敏示例代码（Python）：

```python
import re

def desensitize_personal_info(text):
    """脱敏个人信息"""
    # 1. 脱敏姓名（简单示例，实际需要使用NER模型）
    text = re.sub(r'王德明', '[当事人A]', text)
    text = re.sub(r'王方利', '[当事人B]', text)
    
    # 2. 脱敏身份证号
    text = re.sub(r'\d{17}[\dXx]', '[身份证号]', text)
    
    # 3. 脱敏联系电话
    text = re.sub(r'1[3-9]\d{9}', '[联系电话]', text)
    
    # 4. 脱敏家庭住址（简单示例）
    text = re.sub(r'贵州省贵阳市.*?小区', '[住址]', text)
    
    # 5. 脱敏银行卡号
    text = re.sub(r'\d{16,19}', '[银行卡号]', text)
    
    # 6. 脱敏电子邮箱
    text = re.sub(r'\w+@\w+\.\w+', '[电子邮箱]', text)
    
    return text

# 使用示例
original_text = "王德明（身份证号：520102199001011234，电话：13800138000）"
desensitized_text = desensitize_personal_info(original_text)
print(desensitized_text)
# 输出：[当事人A]（身份证号：[身份证号]，电话：[联系电话]）
```

#### 脱敏后的检索示例：

- **原始案情**："王德明（身份证号：520102199001011234）在2023年5月与李芳签订借款合同..."
- **脱敏后**："`[当事人A]`（身份证号：`[身份证号]`）在2023年5月与`[当事人B]`签订借款合同..."
- **发送给"法律检索助手"进行检索** → 不会泄露个人信息
- **检索完成后** → 可选：将"`[当事人A]`"还原为"王德明"

### 2.4 模块4：LTI文本监察系统（强制审核 + 本地运行）

**功能描述**：
- **所有输出**都必须通过LTI文本监察系统审核
- **审核内容包括**：
  - **案情摘要**：事实是否准确、有无遗漏关键信息
  - **证据材料清单**：证据分类是否合理、有无遗漏
  - **案件分析报告**：法律分析是否正确、法条引用是否准确
  - **行动建议书**：建议是否可行、有无法律风险
- **如果LTI审核发现**：
  - ✅ **AI幻觉** → 禁止输出，自动重新生成
  - ✅ **法条错误** → 禁止输出，自动修正后重新生成
  - ✅ **事实错误** → 禁止输出，自动修正后重新生成
- **审核不通过 → 自动重新生成**（最多重试3次，仍不通过则提示你手动介入）

**⚠️ 安全机制**：
- LTI文本监察系统**必须在本地运行**
- **禁止将任何案件信息传输到云端**

## 三、数据安全与隐私保护机制（⚠️ 核心）

### 3.1 原则1：本地存储原则（数据不离境）

**核心目标**：  
所有案件信息（包括案情描述、证据材料、分析报告、检索结果）都只保存在本地，禁止上传到任何云端服务器。

**具体实现**：

1. **案情采集阶段**：
   - 所有对话记录 → 只保存在本地临时文件（如：`/tmp/tanan_lawyer/conversation_history.txt`）
   - 禁止上传到：腾讯文档、iCloud、Google Drive、任何云端API

2. **材料解析阶段**：
   - 所有解析结果 → 只保存在本地临时目录（如：`/tmp/tanan_lawyer/parsed_materials/`）
   - 原始材料文件 → 只保存在本地（你不主动删除，就不会被删除）
   - 禁止上传到：任何云端存储服务

3. **法律检索阶段**：
   - 所有检索结果 → 只保存在本地缓存目录（如：`/Users/chenyouqiang/Documents/LawKB/法律检索缓存/`）
   - 禁止上传到：任何云端数据库或API

4. **报告生成阶段**：
   - 最终报告 → 只保存在本地Obsidian目录（如：`/Users/chenyouqiang/Documents/LawKB/法律文书/案件分析报告/`）
   - 禁止自动同步到：iCloud、Google Drive、腾讯文档等云存储服务

5. **LTI审核阶段**：
   - 所有审核记录和结果 → 只保存在本地临时文件
   - 禁止将任何案件信息传输到云端进行AI审核

---

### 3.2 原则2：门禁原则（访问控制）

**核心目标**：  
只有授权用户（老强）才能查看和使用这些案件信息。其他用户或进程无法访问。

**具体实现**：

1. **文件系统权限控制**（macOS）：
   - 所有案件相关目录和文件 → 设置权限为`chmod 600`（只有所有者可以读写）
   - 示例代码：
     ```python
     import os
     import stat
     
     def set_secure_permissions(file_path):
         """设置文件权限为600（只有所有者可以读写）"""
         os.chmod(file_path, stat.S_IRUSR | stat.S_IWUSR)
     ```

2. **进程隔离**：
   - "谈案律师技能"运行在独立的进程空间中
   - 其他技能或应用程序无法访问其内存空间

3. **用户认证**（可选，未来添加）：
   - 每次启动"谈案律师技能"时，需要输入密码或生物识别（如：Touch ID）
   - 防止他人未经授权使用

---

### 3.3 原则3：总闸原则（一键切断数据外流）

**核心目标**：  
设置一个总开关，可以一键切断所有数据外流（网络传输、云同步、外部API调用）。

**具体实现**：

1. **总闸开关**：
   - 在技能配置文件中设置：`CLOUD_ENABLED = False`（默认关闭）
   - 示例代码（`tanan_lawyer_config.py`）：
     ```python
     # 谈案律师技能配置文件
     CLOUD_ENABLED = False  # 总闸：禁止所有云端传输
     
     # 如果CLOUD_ENABLED = False，以下功能将被禁用：
     # 1. 禁止调用任何云端API（如：腾讯文档API、iCloud API、外部法律数据库API）
     # 2. 禁止上传任何文件到云端
     # 3. 禁止使用任何需要网络传输的功能（如：在线OCR、在线语音识别）
     # 4. 只能使用本地功能（如：本地PDF解析、本地Word解析、本地OCR、本地语音识别）
     ```

2. **网络传输拦截**：
   - 在技能代码中，所有网络请求都必须先检查`CLOUD_ENABLED`开关
   - 如果`CLOUD_ENABLED = False`，则禁止发送任何网络请求
   - 示例代码：
     ```python
     import requests
     
     def safe_http_request(url, data):
         """安全的HTTP请求（遵守总闸原则）"""
         if not CLOUD_ENABLED:
             raise Exception("总闸已关闭：禁止所有云端传输")
         
         # 只有在总闸开启时，才能发送网络请求
         response = requests.post(url, json=data)
         return response
     ```

3. **云同步拦截**：
   - 在技能代码中，所有文件保存操作都必须检查`CLOUD_ENABLED`开关
   - 如果`CLOUD_ENABLED = False`，则禁止保存文件到任何云存储目录（如：iCloud目录、Google Drive目录）
   - 示例代码：
     ```python
     def safe_save_file(file_path, content):
         """安全的文件保存（遵守总闸原则）"""
         if not CLOUD_ENABLED:
             # 总闸关闭：只能保存到本地非云存储目录
             if is_cloud_directory(file_path):
                 raise Exception("总闸已关闭：禁止保存到云存储目录")
         
         # 保存文件
         with open(file_path, 'w') as f:
             f.write(content)
     ```

4. **一键切断功能**：
   - 在技能界面中添加一个"一键切断"按钮
   - 点击后，立即设置`CLOUD_ENABLED = False`，并杀掉所有网络请求进程

- 在调用"法律检索助手"之前，必须先调用脱敏模块

- 在检索完成后，你可以选择**是否将脱敏信息还原为原始信息**
- 如果还原，则报告中使用真实信息
- 如果不还原，则报告中使用脱敏信息（如："`[当事人A]`"）

### 3.5 原则5：OCR和录音转录功能的安全机制（⚠️ 新增）

**核心目标**：  
如果必须使用在线OCR API或在线语音识别API，则必须先对图片或录音进行**脱敏处理**。

**具体实现**：

#### 1. OCR功能（图片文字识别）
- **优先使用本地OCR工具**（如：Tesseract）
- **如果必须使用在线OCR API**（如：百度OCR API、腾讯OCR API），则：
  - 先对图片进行**脱敏处理**（遮挡人脸、遮挡身份证号、遮挡地址等）
  - 只发送脱敏后的图片给在线OCR API
  - 接收OCR结果后，再还原为原始图片（可选）

#### 2. 录音转录功能（语音转文字）
- **优先使用本地语音识别工具**（如：whisper.cpp）
- **如果必须使用在线语音识别API**（如：讯飞语音转写API、腾讯语音识别API），则：
  - 先对录音进行**脱敏处理**（变声、去除个人信息等）
  - 只发送脱敏后的录音给在线语音识别API
  - 接收转录结果后，再还原为原始录音（可选）

## 四、详细工作流程（迭代式 + 安全机制）

### 4.1 阶段1：案情采集（自由对话 + 本地存储）

**流程步骤**：
1. 你启动技能（说"谈案律师"或上传材料）
2. 你自由描述案情（文字、文件上传均可）
3. 技能通过**追问**逐步澄清关键信息
4. **你可以随时回溯修改**
5. 技能**自动判断信息是否完整** → 完整后进入阶段2

**⚠️ 安全机制**：
- 所有对话记录 → 只保存在本地临时文件
- 禁止上传到云端

---

### 4.2 阶段2：材料解析（自动提取 + 本地存储 + 脱敏准备）

**流程步骤**：
1. 你上传材料（Word/PDF/文本）
2. 技能自动解析材料，提取文字内容
3. 技能将解析结果与你说的情况**交叉验证**
4. **你可以随时补充或替换材料**
5. 材料解析完成后，技能生成**"案情摘要和证据清单"（草稿）**
6. **你确认后** → 进入阶段3

**⚠️ 安全机制**：
- 所有解析结果 → 只保存在本地临时目录
- 禁止上传到云端
- 如果后续需要调用外部API（如：OCR、语音识别），必须先**脱敏处理**

---

### 4.3 阶段3：智能法律检索（可选 + ⚠️ 检索前个人信息脱敏）

**流程步骤**：
1. 技能根据案情复杂度和关键词，**智能判断**是否需要法律检索
2. 如果需要检索 → **先调用"个人信息脱敏模块"**
3. 将**脱敏后的案情信息**发送给"法律检索助手"
4. "法律检索助手"进行法规检索、案例检索、类案比对（可调用外部API）
5. 检索完成后 → **可选：将脱敏信息还原为原始信息**
6. 检索结果整合到案件分析报告中
7. 如果不需要检索 → 直接进入阶段4
8. **你可以随时干预**（强制检索或跳过检索）
9. 检索完成后 → 进入阶段4

**⚠️ 安全机制**：
- **检索前必须脱敏个人信息**
- 即使"法律检索助手"调用外部API，也不会泄露个人信息
- 所有检索结果 → 只保存在本地缓存目录
- **禁止使用任何需要网络传输的外部API**（如：中国裁判文书网API、北大法宝API、无讼API等）
- 如需使用外部法律数据库，必须**先下载到本地**，再进行本地检索

---

### 4.4 阶段4：报告生成（草稿 + 本地存储）

**流程步骤**：
1. 技能整合所有信息（案情摘要、证据材料、法律检索结果）
2. 技能生成**"案件分析和行动建议报告"（草稿）**
3. **你可以多次修改**
4. 修改完成后 → 进入阶段5

**⚠️ 安全机制**：
- 草稿报告 → 只保存在本地临时目录
- 禁止上传到云端

---

### 4.5 阶段5：LTI文本审核（强制 + 本地运行）

**流程步骤**：
1. 技能将报告草稿提交给**LTI文本监察系统**审核
2. LTI审核内容包括：
   - ✅ 事实是否准确（与你说的情况、上传的材料是否一致）
   - ✅ 法条引用是否准确（法条编号、内容、生效时间）
   - ✅ 法律分析是否正确（法律关系认定、争议焦点归纳）
   - ✅ 有无AI幻觉（虚构法条、虚构案例、虚构事实）
3. **如果审核通过** → 进入阶段6
4. **如果审核不通过** → 自动重新生成（最多重试3次）
5. 仍不通过 → 提示你手动介入

**⚠️ 安全机制**：
- LTI审核 → 必须在本地运行
- **禁止将任何案件信息传输到云端**

---

### 4.6 阶段6：输出最终报告（Obsidian格式 + 本地存储）

**流程步骤**：
1. 技能生成**最终报告**（Markdown格式，带YAML frontmatter和双向链接）
2. 自动保存到：
   ```
   /Users/chenyouqiang/Documents/LawKB/法律文书/案件分析报告/
   ```
3. **⚠️ 安全机制**：
   - 最终报告 → 只保存在本地Obsidian目录
   - **禁止自动同步到iCloud、Google Drive、腾讯文档等云存储服务**
4. 你可以在Obsidian中查看和编辑报告
5. 报告自动关联到相关法律条文、类案、其他法律文书（双向链接）
