## 三、实时更新架构（"数据变化 → 各屏全面更新"）

### 3.1 当前阻断点
- 子屏内联 内部操作版静态数据（`cp` 字节副本，永不更新）。
- `scorecard_data.json` 靠人工 `scan_9655.py`，无自动刷新（scan plist 已就位，每 5 分钟重扫）。

### 3.2 目标架构
```
[系统内数据变化]
   │  (文件变更 / 连接器调用 / 技能运行 / 进程状态)
   ▼
[聚合探针 scan_9655.py（扩展版）]
   │  探：本机/进程/磁盘 + LawKB卡数 + case-state + 连接器health + 元典余额 + LTI日志 + skills目录
   ▼
[实时数据产物] scorecard_data.json + system_registry.json（智能体/工作流/连接器注册表+健康）
   │
   ├─ 写入磁盘（自动，launchd 每 5–15min 触发）
   └─ 文件监听 / webhook（系统变化时即时触发一次）
   ▼
[各屏 fetch(…?t=now) + 轮询/自动刷新]
   → 打开即最新、定时刷新、变化时秒级更新
```

### 3.3 落地要点
1. **子屏重接**：把 13 个 内部操作版副本改为 fetch 9655 实时 JSON 的轻量渲染页（保留 内部操作版视觉风格，但数据走本机探针）；对必须保留 内部操作版富交互的（如模拟法庭、决策树），至少把"数据块"替换为实时拉取。
2. **聚合探针扩展**：在 `scan_9655.py` 中新增 `probe_agents()` / `probe_workflows()` / `probe_connectors()` / `probe_lawkb()` / `probe_yuandian()`（D7/D8 注册表屏由 `build_registry()` 实扫 `system_registry.json` 驱动，已落地）。
3. **自动 refreshing**：launchd 加一个 `com.xiaoqiang.cockpit9655.scan.plist`（LaunchCalendar/StartInterval 每 N 分钟跑 `scan_9655.py`）；关键事件（如 case-state 变更）可触发即时重扫。
4. **前端轮询**：各屏 JS 内置 `setInterval` 或 `EventSource` 拉取最新 JSON（`cache:no-store` + `?t` 戳破缓存）。
5. **连接器实时性**：D3 连接器 health 优先读 `connector-states`/enabled 状态（无需 token 即可判断连通）；元典余额等需 token 的，走已授权 mcp 或在本地缓存最新值并标注时间戳。
