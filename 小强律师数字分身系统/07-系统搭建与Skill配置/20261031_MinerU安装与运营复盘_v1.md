## 三、运营现状：两条通道，一条通一条断

### 3.1 CLI 通道 ✅（现默认）

```bash
~/pdf-docai/venvs/mineru/bin/mineru-kit parse <文件> -o <目录> --format markdown --tier standard
```

| 样本 | 类型 | 耗时 | 结果 |
|---|---|---|---|
| 判决书第 1 页 | PDF（有文字层） | 24 s | ✅ 0 失败 |
| 判决书全本 15 页 / 631 KB | PDF（有文字层） | **39 s ≈ 2.6 s/页** | ✅ 7,902 字 |
| 判决书第 8 页 200 dpi | **纯图片（真 OCR）** | 52 s | ✅ 606 字 |

**准确率**

- 文字层 PDF：**16/16 关键字段 100% 命中**——案号、两个统一社会信用代码、5 个身份证号、判付 2,855.00、整装 178,000、受理费 25.00、落款日、三名审判人员；判项两段原文片段完整命中。
- 纯图片页：**字符级相似度 99.6%**（606 vs 原文 609 字），"丁茂祥/丁戊祥/第二百零八条/冒名/主体不适格"全部正确。

> ⚠️ **别被 100% 骗到**：有文字层的 PDF，MinerU 可直接取内嵌文字、等同跳过 OCR。判断真实 OCR 能力只看第三行（99.6%）。这个口径必须固化，否则以后容易高估。

### 3.2 API 通道 ❌（本次查明，从来没通）

**现象**：`ocr_local.py p1.pdf` 卡 **300 秒**后报 `mineru-api(tier=standard) 启动超时`。
**服务日志**（`~/pdf-docai/log-mineru-api.log`）连续打印：
`No such option: --allow-local-source (Possible options: --allow-http-source)`

**两层根因**

| 层 | 问题 | 证据 |
|---|---|---|
| ① 启动参数 | `pdf-dual/scripts/mineru_serve.py:187` 传 `--allow-local-source`；standard 档还追加 `--no-flash`。两者在 4.1.2 **都不存在** | `mineru-api --help` 仅列 `--allow-http-source`；`mineru-api --no-flash --help` 直接报错 |
| ② **来源协议** | 4.1.2 只接受 `source: upload \| url`；本机客户端先发 `{'type':'local','path':…}`，再降级 `{'type':'inline','data':base64}`，两者都非法 | `mineru/parser/api_server.py`：`sources: list[Literal["upload","url"]]`；`_validate_source_policy()` 仅校验 `_StoredSource` 与 url scheme |

⇒ **不是"参数写错、改个名就好"，是客户端与 4.1.2 API 契约版本错位。** 把参数名改对，请求仍会被判 `unsupported_source`。
另：`--allow-http-source` 是放开明文 URL 来源，与本机"卷宗不出网"原则相悖，**不能拿它顶替**。

## 四、未解决与风险

| 级别 | 事项 | 说明 |
|---|---|---|
| 🔴 P0 | **`pdf-dual` 技能本体的 parse 仍会 300 s 超时** | 我只修了桥接层。若谁直接用该技能跑双路解析，照样卡死。需二选一：① 等上游修客户端；② 在技能内加"检测到 4.1.2 则禁用 API、走 CLI"的分支 |
| 🔴 P0 | **文字层 PDF 的高准确率易致误判** | 已在文档固化口径；后续任何"OCR 100%"结论必须注明样本是否有文字层 |
| 🟡 P1 | 逐文件重载模型 | 当前 `ocr_local.py` 循环里一文件一次 CLI 调用，每次重载 VLM（约 2 s）。`mineru-kit parse` 支持多输入，批量卷宗可改成一次传全部，N 个文件可省 (N−1)×2 s |
| 🟡 P1 | 纯图片 52 s/页，无并发 | 15 页扫描件约 13 分钟。大批量扫描卷宗需评估：降 dpi、走 flash 档、或批量后台跑 |
| 🟢 P2 | 格式级瑕疵 | 全角冒号→半角（"原告:"）；字间偶发空格（"习 水 县"）；`\s` 归一即消失，不影响实体 |
| 🟢 P2 | 落款日期分辨率敏感 | 10-30 低分辨率图漏识、本次 200 dpi 正确识别 → 属分辨率问题；仍按铁律 9 人工复核 |
| 🟢 P2 | Docling 缺口 | 4.5 GB 已占；若要补 Docling 另需约 2–3 GB 且下载不稳，建议先确认是否真的需要双路页码校验 |
