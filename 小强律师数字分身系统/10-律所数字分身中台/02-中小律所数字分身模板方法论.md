## 一、一句话结论

**开源 L0 内核（架构 / 协议 / 规则引擎骨架），锁死 L1 人格层与 L2 数据层私有；以「可插拔 persona-pack」为产品形态；不做通用 SaaS，走「开源内核 + 私有化部署 + 蒸馏服务 + 行业规则包」的 Red Hat 模式。**

理由浓缩成一句：**这套系统的护城河不在代码，而在"只有你本地才有的语料 + 思维指纹 + 规则沉淀"；任何要求这些数据上云的商业化形态，都是在摧毁护城河本身。**

## 二、缘起：从个人分身到中台

老强数字分身（小强律师）已验证一条路径：用 AI 把一位律师的「思维链 + 执业纪律 + 知识资产」
固化为可复用系统，而不是买一个通用大模型聊天框。当律所扩张、多席位并行时，这条路径天然
可抽象为「律所数字分身中台」——一份模板驱动 N 个席位分身，对标 Vorys、海欣 & 鼎象的多席位
复用实践，但成本与门槛低一个数量级。

## 四、核心方法论四件套

1. **EV 架构（数字分身操作系统隐喻）**
   把分身当一辆车管：三电=知识飞轮与质检、补能=连接器、智驾=决策思维系统、座舱=模拟法庭、
   黑匣子=车规日志、OTA=自动化。结构化、可运维、可快照回滚。

2. **知识飞轮（LawKB 六层）**
   采集→提炼（经验卡）→连接→巩固→调用→沉淀（裁判规则库）。问答前先检索、任务后必沉淀，
   知识资产滚雪球，越用越深——这是「深度未至」被补齐的机制。

3. **LTI 文本监控器（防幻觉门禁）**
   R/L/C/T/P 五维 QC + 六维法理逻辑门禁，REJECT=0 才准交付。把「引用是否越界 / 是否真实」
   变成可量化的质量闸，是中小所敢把 AI 用于出文的底气。

4. **四模板联动（律师画像模板）**
   律师画像模板 → self.md（分身）↔ legal-base（基座）↔ cockpit RBAC（权限）。
   一份模板驱动全席位，纪律同源、行为可分。详见 `01-律师画像模板/`。

## 五、先破三个幻觉

### 5.1 幻觉一：护城河是代码，所以要赶紧藏起来

不是。EV 六模块本质上是一套**目录约定 + Markdown 协议 + 规则判据**，一个有经验的工程师照着文档两周能复刻骨架。

真正抄不走的是三样东西：

| 资产 | 为什么抄不走 | 沉淀周期 |
|------|-------------|---------|
| self.md / persona.md 里的**思维指纹** | 来自几百次真实办案的取舍，不是 prompt 工程能编出来的 | 年计 |
| HOW-I-THINK.md + 决策日志的**决策启发式** | 每条都要真实决策 + 事后复盘验证，"结论对但理由错"的档位尤其珍贵 | 年计 |
| LawKB 卡库与裁判规则库（800+ 条量级） | 逐条从权威源回填、逐条过 LTI，是体力活也是信任资产 | 年计 |

**结论：代码开源不损失护城河，反而因为"骨架 public、资产 private"，让护城河变成显性的、可证明的。**

### 5.2 幻觉二：做成 SaaS 能放大优势

反的。三点致命：

1. **法理上不允许裸奔**。律师对当事人信息的保密义务是执业底线；案件数据上第三方云，涉及《个人信息保护法》与律所合规红线。中小律所主任最怕的就是"案卷跑到别人服务器上"。
2. **合规成本高**。一旦构成"向境内公众提供生成式 AI 服务"，即触发备案、安全评估、AIGC 标识等义务；而"数字分身"还叠加《互联网信息服务深度合成管理规定》的规制。个人/实习律师身份扛这套，性价比极差。
3. **商业上不成立**。中小律所付费意愿低、决策链长（主任 → 合伙人 → 行政）、要发票要合同要售后要培训。你一个人，做的是 7×24 运维的生意，主业会被拖死。

### 5.3 幻觉三：开源 = 白送

开源的是**空瓶子**。卖的是三样：装水的方法（蒸馏服务）、水（行业规则包）、教人装水（培训）。

Meta 开源 Llama 没损失什么，损失的是那些"以为模型权重就是护城河"的人。**你的权重（思维指纹）从来不进仓库。**

## 六、产品线设计：三层剥离（核心架构决策）

| 层 | 内容 | 开源决策 | 理由 |
|----|------|---------|------|
| **L0 内核层** | EV 六模块目录骨架、四模板联动协议、LTI 规则引擎（**判据逻辑，不含条文库**）、MCP 适配器接口（**只留壳，不带密钥/不带数据**） | ✅ 开源 Apache-2.0 | 骨架价值在传播，不在独占 |
| **L1 人格层** | self.md、persona.md、HOW-I-THINK.md、决策日志、律师画像实例 | ❌ **绝不开源** | 这是"深度个性化"本体，且含可识别个人信息。**存放于 `11-人格层-L1私有/`**（2026-09-10 已从开源域移出） |
| **L2 数据层** | LawKB 卡库、裁判规则库、案件卷宗、客户档案 | ❌ **绝不开源** | 含真实案号/当事人，且受保密义务约束 |

### 6.1 关键设计：persona-pack 可插拔

把 L1 设计成**符合规范的目录包**，别人 clone L0 后，往 `persona/` 里填自己的 self.md / persona.md，就得到"张三律师分身"。

## 七、可复制骨架（最小技能集）

开源核心骨架只含「跑通四件套」的最小集，刻意不做重。
**下列目录由 `03-开源核心骨架/deploy.sh` 脚手架生成**，与 §6.1 的 `lawtwin/core` 是同一套内容在不同视角下的呈现：

```
digital-avatar-kit/
├── legal-base/SKILL.md          # 基座：LTI 拦截 + 幻觉防御 + 飞轮检索纪律
├── lawyer-yourself-skill/       # 数字分身创建器（消费 profile → self.md）
│   ├── SKILL.md
│   └── self.md                  # 由 combine.sh 从 profile 生成（勿手改）
├── LTI文本监控器/SKILL.md        # 门禁（R/L/C/T/P + 六维）
├── 知识飞轮/                     # 六层挂载脚本 + 扫描/回填
├── cockpit-portal/              # 统一工作台（RBAC + SSO 骨架）
│   └── portal/{index.html, rbac.js, auth.js}
├── templates/
│   ├── lawyer-profile-template.schema.yaml   # 基座模板（来自 01-律师画像模板/）
│   └── example.lawyer.profile.yaml           # 实例样例
├── combine.sh                   # 模板 → self.md 生成器
└── README.md
```

最小技能集 = `legal-base` + `lawyer-yourself-skill` + `LTI文本监控器` + 飞轮扫描脚本 +
`cockpit-portal` 权限骨架。其余（模拟法庭、积分监测等）为增强项，按需加装。

> **组件分级**：`legal-base` / `lawyer-yourself-skill` / `LTI文本监控器` 为必须；
> `知识飞轮` 为必须项增强；`cockpit-portal` 为可选增强（对标 Harvey Command Center 的控制台形态，
> 但**交付方式是私有化部署，不是订阅制 SaaS**）；模拟法庭 / 积分监测为按需加装。

Apache-2.0 带**明确专利授权条款**，防止大厂 clone 后申请专利反咬；MIT 没有专利保护。
做的是方法论输出，防白嫖比求传播更重要。

### 8.2 六条合规红线

| # | 红线 | 具体动作 |
|---|------|---------|

| 6 | **境外托管评估** | 代码托管平台选择需评估数据出境与可访问性，README 中说明 |

## 九、产品形态：从"个人分身"升级为"律所分身"

这是**比个人分身更值钱、也更真实的需求**。中小律所买不起大所那套一体化系统，但痛点真实存在：新人培养慢、老人经验不带走、质控靠主任肉眼。

| 层 | 对应 | 内容 | 价值主张 |
|----|------|------|---------|
| **Person** | 律师个人分身 | self.md / persona.md / 个人卡库 | "你的经验不会因为你休假而停摆" |
| **Practice** | 专业组（人伤组 / 慈善组 / 合同组） | 专项规则包、组内共享卡库、典型案例 | "组里最好的那个人的打法，全组都能用" |
| **Firm** | 所级质控 | 所级 LTI 门禁、文书红线清单、客户信息隔离策略 | "主任不用逐份看文书，也能守住底线" |

**卖点不是"AI 替你写文书"，是"律所的知识不再随人走"。** 这句话主任听得懂，也愿意付钱。

## 附录 A：阶段 0 脱敏门禁（已交付，2026-09-10）

工具位置：`07-系统搭建与Skill配置/开源脱敏工具/`

### A.1 交付物

| 文件 | 说明 |
|------|------|
| `desensitize_check.py` | 主工具，v1.0.0，纯标准库无依赖 |
| `pre-commit-hook.sh` | git 提交钩子模板 |

### A.2 检测能力

| 级别 | 检测项 | 校验方式 |
|------|--------|---------|
| HIGH | 身份证号 18 位 | **MOD 11-2 校验位验证**（GB 11643-1999），篡改即失效 |
| HIGH | 身份证号 15 位 | 日期段合法性 |
| HIGH | 统一社会信用代码 | **GB 32100-2015 校验位验证** |
| HIGH | 银行卡号 | **Luhn 校验** + 16-19 位 |
| HIGH | 当事人姓名 | 名单驱动（`--names-file`，本地私有不入库） |
| MEDIUM | 手机号 | `1[3-9]\d{9}` + 前后非数字断言 |
| MEDIUM | 法院案号 | 带括号 / 无括号两种写法均覆盖 |
| MEDIUM | 车牌号 | 省份简称 + 发牌机关字母 |
| LOW | 疑似卡号 | 未过 Luhn 但符合卡 BIN（漏报兜底） |
| LOW | 邮箱地址 | 提示级 |

### A.3 实测结论（2026-09-10）

- 内置自检 **9/9 通过**（`--self-test`）
- 敏感样本 **14 项全命中**（身份证×2、卡号×2、信用代码、案号×4、手机号、车牌、邮箱、姓名×2）
- 正常文档 **零误报**，退出码 0
- 脱敏闭环：脱敏副本复扫 **0 命中**
- 行内豁免 `desensitize:ignore` 生效
- 安全铁律：原地脱敏未指定备份目录时**强制拒绝**（退出码 3）

### A.4 常用命令

```bash
# 第一步永远是 dry-run：只报告，不改文件
python3 desensitize_check.py /path/to/repo

# 载入当事人姓名名单（名单文件绝不入库）
python3 desensitize_check.py . --names-file ~/.lawtwin/names.txt

# pre-commit 推荐：严格模式，LOW 也阻断
python3 desensitize_check.py . --strict

# 生成脱敏副本（原文件不动）
python3 desensitize_check.py . --redact --out-dir ./_redacted

# 原地脱敏（强制要求备份目录）
python3 desensitize_check.py . --redact --in-place --backup-dir /tmp/backup_$(date +%s)
```

### A.5 已知边界（诚实说明）

1. **姓名只能用名单匹配**，无法从文本自动识别未知姓名。名单需人工维护，是本工具最大的覆盖盲区。
2. **住址、银行开户行、具体金额**等未纳入检测——这类信息识别依赖语义，正则不可靠，须人工复核。
3. **图片 / PDF 扫描件无法检测**，其中的身份证、案号不会被发现。开仓库前须人工过一遍所有非文本文件。
4. LOW 级（邮箱、疑似卡号）默认只提示不阻断，pre-commit 需加 `--strict`。
