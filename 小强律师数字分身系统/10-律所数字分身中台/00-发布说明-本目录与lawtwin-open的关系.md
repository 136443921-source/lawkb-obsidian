# 00 · 发布说明：本目录与 lawtwin-open 的关系

> 一句话：**在这里写，在那里发。**

| 角色 | 位置 | 说明 |
|---|---|---|
| **内容源** | 本目录 `10-律所数字分身中台/` | 日常在这里写。位于 LawKB 内，受 LawKB 私有仓库备份保护 |
| **发布仓库** | `~/lawtwin-open/` | 只放 L0。独立 git 仓库，跑通门禁后可 push 到公开远端 |

## 为什么要分成两份

本目录在 LawKB 里，而 **LawKB 本身是一个私有 git 仓库**
（remote `lawkb-obsidian.git`，用于 Obsidian 备份）。

如果把公开仓库直接建在这里，会出两个问题：
1. **嵌套仓库**：本目录已是 LawKB repo 的一部分，再 `git init` 会变成嵌套结构；
2. **历史连坐**：整个 LawKB 的提交历史会跟着一起走，L2 内容一次泄露到底。

所以发布仓库放在 LawKB **之外**，只装 L0 内容，历史干净。

## 同步方式

写完本目录后，到发布仓库跑：

```bash
cd ~/lawtwin-open
./tools/sync-from-source.sh          # 同步 + 自动重装钩子 + 跑门禁
./tools/sync-from-source.sh --dry    # 只看会同步什么，不执行
```

同步项在脚本里**显式列举**（不是通配符），
因此新增文件默认不会被同步——**加新文件要同时改脚本的同步清单**。

## 铁律

1. **真实 `*.profile.yaml` 实例一律放 `11-人格层-L1私有/`**，不放本目录。
   本目录 `01-律师画像模板/` 只留 schema 与虚构 example。
2. 案号一律写尖括号占位（`<年份>黔<法院代字>民初<编号>号`），
   不要写格式合法的数字串——会被门禁判为真实案号并阻断。
3. 门禁命中时，先问"**这个文件是不是放错层了**"，再考虑豁免。
   放错层 → 移走；不是加 `desensitize:ignore`。
4. 图片 / PDF / docx / xlsx 等**非文本文件一律不进发布仓库**
   （门禁扫不到二进制，`.gitignore` 已排除，开仓前仍须人工过一遍）。
