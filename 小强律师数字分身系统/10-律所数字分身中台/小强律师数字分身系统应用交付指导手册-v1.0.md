# 小强律师数字分身系统应用交付指导手册 v1.0

**一句话结论**：本系统已具备可外发的私有化交付包、成文 SOP 与门禁脚本，但**尚无真实外部客户验收记录**；本手册不新增任何功能，只把既有资产串成一条「选型 → 前置 → 部署 → 试点 → 验收 → 交接 → 运营」的可执行链，把每个环节的动作、判据、命令、红线与「待实跑」标记写实，让第一位交付实施人能照着走完闭环。

| 项目 | 内容 |
| --- | --- |
| 版本 | v1.0 |
| 编制日期 | 2026 年 11 月 11 日 |
| 适用对象 | 小强律师数字分身系统对外交付（律所内网版 / 单机密文版 / 开源核心骨架） |
| 目标读者 | 交付实施人、目标所管理员、最终决策人（R-4） |
| 归档位置 | 小强律师数字分身系统 / 10-律所数字分身中台 |
| 主要依据 | `LawKB/lawtwin/` 两大形态方案与 SOP、私有化部署手册、单机密文版启动清单与部署记录、10-中台商业化方法论与部署 SOP、开源骨架 `deploy.sh` |
| 性质 | 内部作业指导手册，非对外法律文书；未经 LTI 双闸门校验，不得对外引用 |

> **数据口径声明**：本手册所有组件状态、脚本名、清单项均于 2026-11-11 从本地文件实地读取，未凭记忆补写。历史复盘、白皮书与部署记录中的统计值标注 `[自述待验]`，不作为当前运行态结论。商业报价数字来自既有方法论的**推导建议**，非市场调研结果。凡未在真实客户环境跑通的环节，一律标「待实跑」或「需人工确认」。

## 一、手册定位与适用边界

本章先界定三个术语、给出三种部署形态的选型判据，再诚实声明各组件的成熟度，最后划清本手册不做什么，作为后文所有动作的口径基准。

### 1.1 术语三件套

| 术语 | 定义 | 本文哪一句满足 |
| --- | --- | --- |
| **应用交付** | 把系统从「源所可用」搬到「目标所可用」，对上线、被采用、可交接负责，而非只交付文件 | §四的七个 Phase 与 §六的验收交接 |
| **私有化形态** | 按客户数据出所许可、使用规模、外联策略分出的 A / B / C 三种落地形态 | §1.2 决策树 |
| **交付闭环** | 至少一次由非开发者的真实使用者完成真实工作，并留下基线、评测、反馈、复测与案例证据 | §五、§六 |

**角色定位**：交付实施人不是「把系统装好的人」，而是「让目标所自己能跑起来、并留下可核验证据的人」。这一区分决定了本手册把大量篇幅放在验证、验收与交接，而不是安装命令本身。

### 1.2 三种部署形态与选型

决策树（源：`05-私有化部署手册.md` §2.1）：

| 序 | 判断问题 | 分支 | 结论形态 |
| --- | --- | --- | --- |
| Q1 | 客户是否允许任何数据出所 | 否（涉密 / 政府 / 强监管） | C · 涉密隔离版 |
| Q1 | 同上 | 是 → 进入 Q2 | 继续判断 |
| Q2 | 使用规模 | 1–20 人、单机或单终端 | A · 单机密文版 |
| Q2 | 同上 | 20+ 人、多终端、共享知识库 | B · 律所内网版 |

| 维度 | A · 单机密文版 | B · 律所内网版 | C · 涉密隔离版 |
| --- | --- | --- | --- |
| 典型客户 | 个人律师 / 5–20 人小所 | 20–100 人所 | 政府、国企法务、涉密单位 |
| 推理 | 客户自有 API；或本地 Ollama 降级 | 内网 GPU（vLLM）或统一 API 网关 | 完全离线本地模型（须 GPU 服务器） |
| 检索 | SQLite + sqlite-vec | Qdrant / Milvus 独立部署 | 本地向量库 + 加密卷 |
| 法条核验 | 本地法规库快照 + 可选 pkulaw | 本地镜像 + 法宝 / 元典账号 | 预置快照 + U 盘增量更新 |
| 外联 | 允许（可关闭） | 白名单 | 零外联 |
| 交付周期 | 1–2 周 | 4–8 周 | 8–16 周 |
| 建议 | **先做这个** | A 跑通 10 家后再接 | 现阶段不碰（要资质 / 等保 / 驻场） |

> **选型纪律**：先做 A。决策链最短（一个合伙人拍板即可）、不碰客户 IT 环境；跑通后有案例才好谈 B 的预算。选定 A 后直接使用单机密文版专版手册，不在通用手册里自行做减法。两条路径冲突时，**形态内专版优先**。

### 1.3 成熟度诚实声明

| 组件 | 状态 | 落地位置 |
| --- | --- | --- |
| 模板骨架克隆 | 立即可用 | `clone-lawtwin.sh`，§4.1 |
| 脱敏门禁 | 立即可用 | `desensitize_check.py`，§4.6 |
| 技能安装与版本锁 | 立即可用 | `02-skills-manifest.md`，§4.3 |
| 人格层加密封装 | 立即可用 | `crypto-l1.sh`（openssl + 钥匙串），§4.5 |
| 推理层适配 | 已交付 v0.1.0 | `~/lawtwin-open/core/`，含 CLI 与 12 项离线自检 |
| **LTI 门禁独立进程化** | **待建设** | 当前依托 WorkBuddy 运行时，尚未剥离为独立服务 |

> 涉及「待建设」的步骤，本手册给出**当前替代做法**与**目标做法**，按现状执行即可，不要等待。另据 2026-09-21 单机密文版部署记录，版本锁回填 20/20 `[自述待验]`，但巡检实测 `lti-gate=DOWN/P0` 须激活守护进程，且验收清单多项仍标「需人工确认」——**这是本手册把「门禁校准」列为放行硬判据的直接原因**。

### 1.4 本手册的边界与使用纪律

- **不新增功能、不改写既有 SOP**：本手册是索引与串接，具体步骤以各专版手册原文为准；两者冲突时以专版为准。
- **不承诺结果**：不写「必然跑通」「一定通过验收」，只给判据与红线。
- **不代客户做决策**：形态选定、上线放行、是否对外，须客户书面确认与 R-4 点头。
- **不代点 UI、不打印令牌明文**：跨所授权由目标所管理员在界面完成。
- **草稿态须加粗提示**：交付物未过门禁时明确标注。

## 三、交付前决策与准备

本章把「动手之前」的四类前置条件固定下来，任一不满足即停止写入，这也是六-B 铁律在交付场景的具体化。

### 3.1 角色与决策归属

| 角色 | 职责 | 不可越界 |
| --- | --- | --- |
| 源所管理员 | 提供版本锁基线（`02-skills-manifest.md` 已填 actual 版本号） | 不提供源所案件数据或个人记忆 |
| 交付实施人 | 落地克隆、装技能、配推理、校准门禁、组织试点与交接 | 不代点 UI、不打印令牌、不擅自上线 |
| 目标所管理员 | 本所重授权、写隔离 README、确认形态与验收 | 令牌不复用旧所 |
| 目标所助手 | 占位符替换辅助、知识入库 | 只接触脱敏材料 |
| **最终决策人（R-4）** | 是否部署、部署到哪、是否对外 | 部署 / 上线属 R-4，最终决策权在老强 |

### 3.2 Phase 0 前置四项

| ☐ | 前置项 | 最低判据 | 源 |
| --- | --- | --- | --- |
| ☐ | 硬件核验 | 达标，或已书面告知降级 | 部署手册 Step 0.1 |
| ☐ | 网络与白名单 | 网络策略书面确认，形态 C 零外联 | Step 0.2 |
| ☐ | 账号与授权清单 | 目标所席位、知识库、连接器账号齐备 | Step 0.3 |
| ☐ | 备份基线 | `cp -n -R` 到 `/tmp/lawtwin_deploy_<时间戳>` 并回显回滚路径 | Step 0.4 |

> 🔴 **铁律**：没有 Phase 0 备份 → 不许执行任何写入步骤。`05-私有化部署手册.md` §13 明确「全面失败」时的回滚即恢复该备份。

### 3.3 合同与预期管理

| 事项 | 写法 / 判据 | 源 |
| --- | --- | --- |
| 能力边界 | 合同写死「AI 输出为辅助草稿，律师对最终成果独立负责」 | 合规红线第 6 条 |
| 预期管理 | 客户以为买「AI 替我办案」，实际买「经验固化工具」；用盲测验收把预期落地 | 商业化方法论 §二 |
| 付款节奏 | 3-4-3（签约 30% / 盲测通过 40% / 交付 30%），把验收标准变成收款依据 | 同上 §九 |
| 案例授权 | 前 3 单降价的对价，写明可否脱敏后用于宣传 | 同上 §七 |
| 备案边界 | 纯内网一般不触发；**一旦对客户以外第三方开放，须走备案 + 安全评估**，合同写明 | 合规红线第 5 条 |

> 定价（`L2 8,000–20,000 元/人`、`L3 30,000–100,000 元/所`）为方法论中的**推导建议**，对外报价前必须找 3 个真实潜在客户试探反应并校准，本手册不据此对外报价。

### 3.4 六-B 铁律（交付版）

**先备份 → 先排查确认非误报 → 批量前 dry-run → 执行 → 验证幂等与零残留。** 对应到本手册：`cp -n` 防覆盖、`clone-lawtwin.sh` 默认 dry-run、占位符替换后 `grep` 残留校验、`deploy.sh` 跑完 `diff -rq` 对照备份。

## 四、标准交付流程（七个 Phase）

本章是手册主体。每个 Phase 给「动作 / 命令或判据 / 输出物 / 红线」四列；**上一 Phase 的放行判据未满足，不许进入下一 Phase**。Phase 编号沿用 `05-私有化部署手册.md` 原文。

### 4.1 Phase 1 · 骨架落地

| 动作 | 命令或判据 | 输出物 | 红线 |
| --- | --- | --- | --- |
| dry-run 预览 | `bash clone-lawtwin.sh /path/to/新所库`（默认不写入） | 预览输出 | 不许直接 `--apply` |
| 执行克隆 | `bash clone-lawtwin.sh /path/to/新所库 --apply` | 目标库同名文件 | `cp -n`，同名不覆盖 |
| 占位符替换 | `--apply --replace --firm "所名" --lawyer "负责人"` | 本所化文件 | 只替换 `[律所名]` / `[律师名]` |
| 残留校验 | `grep -rn -e "[律师名]" -e "[案由]"` 输出为空 | 零残留证明 | **不做这步等于没做** |

> 启动包到位判据：`README / 00 / 01 / 02` 齐全（部署手册 §11 记「5 个模板文件到位」）。[口径见 §8.2]

### 4.2 Phase 2 · 推理层配置

| 动作 | 命令或判据 | 输出物 | 红线 |
| --- | --- | --- | --- |
| 选定后端 | 客户自有 API / 本地 Ollama 降级 / 内网 vLLM，按形态定 | 选型记录 | 形态 C 完全离线 |
| 填配置 | `cp 启动包/inference.A.yaml 02-配置/inference.yaml`，编辑 `base_url` / `model` / `network.mode` | `inference.yaml` | 密钥只走 `api_key_env`，**绝不落盘** |
| 连通性 | `lawtwin-infer validate && selftest && check` | 自检报告 | 12 项离线自检须通过 |

### 4.3 Phase 3 · 技能安装与版本锁

| 动作 | 判据 | 输出物 | 红线 |
| --- | --- | --- | --- |
| 按 P0 → P1 → P2 安装 | 顺序不可跳 | 已装技能 | — |
| P0 三项先通 | `legal-consult-router` + `lawyer-yourself-skill` + `LTI 文本监控器` | 分诊可用 | 投测试问题须能五问分诊并派发 |
| 版本锁回填 | 目标所实际版本号回填 manifest，**无空项** | 版本锁基线 | 装到更高版本须记录差异并评估回退，避免行为分叉 |

> 单机密文版 2026-09-21 记录中 P0 版本示例：`legal-consult-router 1.0.0`、`lawyer-yourself-skill 1.2.0`、`LTI 文本监控器 4.9.1`、`legal-base 1.3.0` `[自述待验]`。版本口径存在多处差异，见 §8.2，交付时以目标所实测回填值为准，不照抄。

### 4.4 Phase 4 · 连接器配置

| 动作 | 判据 | 红线 |
| --- | --- | --- |
| 连接器分级 | IMA 知识库 / 邮箱 / 华宇元典等按量授权 | 调用前确认 `enabled=true` |
| 本所重授权 | 目标所 WorkBuddy 界面重新授权 | **跨所令牌不可复用**：旧所令牌不迁移、不复制，否则调用失败或串所 |
| 离线降级 | 形态 C 必做：本地法规库快照 + U 盘增量 | 断网时法条返回 `statute_text_pending`，**不编造** |

> AI 不代点 UI、不打印令牌明文；令牌过期走目标所管理员界面重新授权。

### 4.5 Phase 5 · 人格层注入（L1）

| 动作 | 命令或判据 | 红线 |
| --- | --- | --- |
| 生成 profile 实例 | `profile.yaml` → `lawyer-yourself-skill` 的 `combine.sh` → `self.md` | **`self.md` 是 combine 的产品，禁止直接编辑**（Fix-the-source） |

## 五、现场采用与试点闭环

部署完成不等于交付完成。本章把「目标所真实用起来」变成可核验的动作与证据，对应外部岗位要求中的「试点期坐旁边修摩擦点」「用律师复核答案建评测集」。

### 5.1 蒸馏五步法

源：`04-商业化方法论-服务变现实施报告-v1.0.md` §3.1。

| 步 | 名称 | 动作 | 产出 | 参考工时 |
| --- | --- | --- | --- | --- |
| 1 | 采集 Intake | 5 问 intake + 原材料归集（A–F 六类）+ 2 小时访谈 | 原材料包 + 访谈纪要 | 4–6 h |
| 2 | 析出 Distill | 双线分析：Self Memory（事实 / 经历）+ Persona（风格 / 表达） | `self.md` / `persona.md` 初稿 | 8–10 h |
| 3 | 校准 Calibrate | 盲测验收（§5.2），识别率不达标回第 2 步 | 盲测报告 + 修订稿 | 4–6 h |
| 4 | 接线 Wire | 接知识层 / 思维层 / 决策层三层检索；接 LTI 门禁；接 MCP 检索源 | `SKILL.md` + 接线自检表 | 4–6 h |
| 5 | 交付 Evolve | 使用手册 + 培训 1 场 + 3 个月进化期（含 2 轮纠正迭代） | 交付包 + 进化记录 | 4–6 h |

> **关键控制点**：W3 的盲测第 1 轮不达标立刻回炉，不要拖到 W5 才暴露问题。

### 5.2 盲测验收法

「像不像」是主观感受，主观感受**不能写进合同，也就不能收费**。盲测法把它变成可量化指标：由目标所真人律师在不知来源的情况下辨认答案是否出自本所分身，统计识别率与样本，形成盲测验收报告。

| 用途 | 判据 |
| --- | --- |
| 校准是否可交付 | 识别率达标才进入 Wire；不达标回 Distill |
| 拒绝虚假预期 | 「盲测 55%，确实还不像，我再迭代一轮」 |
| 收款依据 | 3-4-3 中「盲测通过付 40%」 |
| SOP 成熟度指标 | 盲测识别率稳定 ≥ 65% 视为蒸馏 SOP 可复制 `[自述待验]` |

### 5.3 试点期现场记录

| ☐ | 记录项 | 为什么记 |
| --- | --- | --- |
| ☐ | 用户先看什么、跳过什么、不信什么 | 摩擦点不靠猜 |
| ☐ | 每一次人工纠正的原话与上下文 | 转化为规则卡或测试样本 |
| ☐ | 原流程耗时 / 错误 / 成本基线 | 前后对比的分子分母 |
| ☐ | 至少 1 位非开发者的真实使用者完成一次真实工作 | 「被采用」的最低证据 |
| ☐ | 试用记录含「跳过什么、不信什么」 | 验收清单第 8 项同源要求 |

### 5.4 版本对比与证据留存

V0.1 首轮评测 → 错误清单 → 只修最重要的少数问题得 V0.2 → **用同一套测试集复测** → 指标对照表。指标至少覆盖召回、证据覆盖、处理耗时与稳定性；**不编造效率提升数字**。项目案例须能完整展示问题、系统、评测、结果、个人贡献，配 1–3 分钟可演示版本。

## 七、日常运营与持续迭代

克隆完成即转入 `01-SOP手册.md` 的 SOP-01~07 做日常运营；克隆迁移 SOP 仅在「开新所实例」时触发。

### 7.1 七大日常 SOP 索引

| 编号 | 名称 | 一句话要点 |
| --- | --- | --- |
| SOP-01 | 部署与初始化 | 2 周内搭起可启动骨架，先写全局规则再装技能 |
| SOP-02 | 知识入库（卡片化） | 入库即卡片化，任务后沉淀 |
| SOP-03 | 文书生产 | 起草 → 蓝队 → 红队 → LTI → 交付，`REJECT=0` 才放行 |
| SOP-04 | 案件生命周期管理 | 阶段与门禁以 `case-state.json` 为唯一可信源 |
| SOP-05 | 红蓝对抗与模拟庭审 | 对抗推演，不利案例强制同出 |
| SOP-06 | 日常运维 | 摄入 / 周报 / 体检 |
| SOP-07 | 安全与合规 | 备份、dry-run、连接器门禁、隐私隔离、交付门禁、冲突仲裁 |

> SOP-01 常见错误：跳过全局规则直接装技能 → 后续冲突无仲裁依据。SOP-07 常见错误：无备份直接重建单源文件、令牌明文落文档。

### 7.2 版本锁与 Fix-the-source

- **版本锁**：P0 / P1 / P2 每装一个即回填「目标所实装版本」，不留空；差异记录并评估回退。
- **Fix-the-source**：`self.md` 由 `combine.sh` 从画像实例生成，**改模板而非产品**，否则刷新即被覆盖。
- **R-LN-114 拒绝假自洽**：`deploy.sh` 跑完须跑 `drift_check_9655.py`，`aligned: true` / `drift_count=0` / 退出码 0。
- **执行位实测**：`部署SOP.md` 登记时实测 `deploy.sh` 为 `-rw-r--r--`（无 `x`），运行前由执行人补 `chmod +x` 或改走 `bash deploy.sh`；**此处只登记不擅自 chmod**。

### 7.3 常见错误速查

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 复制源所连接器令牌 | 跨所失效 / 串所 | 目标所重新授权 |
| 漏替换占位符 | 交付物带错所名 | dry-run → 替换 → grep 核验 |
| 版本不对齐基线 | 行为差异、经验不通 | 按 manifest 版本锁安装 |
| 把当事人数据一并迁 | 隐私违规 | 只迁方法论 / 模板，数据留源所 |
| 跳过试点直接推广 | 链路未验证就铺开 | 先单案由闭环再复制 |

### 7.4 跨所经验互通边界

各所共用同一版本基线 + 同一卡片 Schema（裁判规则卡 / 审判要件卡 / 经验卡），**方法论级卡片经脱敏后可跨所共享**；当事人维度的卷宗、隐私数据**严禁跨所流动**。
