# 🏛️ 小强律师数字分身系统 · 全系统复盘与性能评估报告

> **一句话结论**：**能力层已达行业罕见的重度自建水准（192 技能 / 2456 张规则卡 / 54 名数字员工 / 178 处 LTI 规则），但治理层明显滞后——七维加权 70.3 分，被"可观测性 4.0""上下文效率 4.5"两项硬拖。系统当前的主要矛盾已不是"能力不够"，而是"能力过剩却看不清楚自己"**。

## 三、逐维实测证据（只列硬证据）

### 3.1 可观测性 4.0 —— 本报告最重的发现

三处埋点，三处断链：

| 埋点                       | 设计用途        | 实测                                                              | 判定             |
| ------------------------ | ----------- | --------------------------------------------------------------- | -------------- |
| `card_consumption.jsonl` | 卡片消费/命中率    | **1773 条，其中 1769 条在 2026-09，10 月仅 4 条**（最后 10-13）               | 🔴 断 9 天以上     |
| `frontdesk_events.jsonl` | 唤醒/分诊/绿旁路遥测 | **仅 15 条，全部 10-09 当天，其中 9 条 caller = `test-frontdesk-routing`** | 🔴 建成当日后再无真实数据 |
| `grill_events.jsonl`     | 门禁拦截        | 4 条 + violations 6 条                                            | 🟡 低频但有效       |

**根因定位（已查代码，非推测）**：`frontdesk_wake_hook.py` 的模式读取顺序为 `环境变量 FRONTDESK_WAKE_MODE > 文件 frontdesk_wake_mode`，**默认 `off`**；`~/.workbuddy/metrics/` 下**不存在** `frontdesk_wake_mode` 文件 → 钩子虽已挂在 `settings.json` 的 `UserPromptSubmit`，但**永处于 telemetry-off 态**。故 9655 驾驶舱 D9 指标恒为 0。

> 📌 佐证：本次对话首句即以「小强律师」开头，`frontdesk_events.jsonl` 仍停在 10-09 —— **唤醒埋点未生效是已被本对话自身证伪的"活证据"**。

### 3.2 知识调用效率 5.5

| 指标                     | 数值                                    | 说明                  |
| ---------------------- | ------------------------------------- | ------------------- |
| 卡片宇宙（有 rule_id 活跃卡，去重） | **2456**                              | 2026-10-06 普查口径     |
| 已挂载（被 ≥1 智能体/心智模型引用）   | **998**                               | —                   |
| **挂载率**                | **40.6%**                             | 未挂载 1458 张          |
| 未挂载 TOP3               | 通用裁判规则 428 / 案由路由 302 / 审判要件 282      | 恰是"最该被调用"的三类        |
| 协同效果日志                 | 59 条，实质命中 30（**50.8%**），"规则:无"占 37.3% | 但**近 30 天仅 2 天有记录** |

**判读**：这不只是"知识没挂上"，更严重的是**调用记录纪律在 9 月底后松动**——不记录就无法度量命中率，命中率不可度量就无法优化。与 3.1 的埋点断链是**同一个病根**：观测动作靠人记，没靠机制记。

### 3.3 上下文与维护效率 4.5

- **192 个技能的 `name` + `description` 合计 54,266 字符 ≈ 2.7 万 tokens，每轮对话常驻注入**。这挤压了实质工作上下文，也稀释了技能选择的注意力（技能越多，选错概率越高）。
- **11 个技能 name 与目录名不一致**（占 5.7%），存在调用歧义风险：`QC-Controller（庭审质量控制器）`、`AI模拟法庭法官`(目录 ai-mock-court-judge)、`contract-review-workflow`(目录 合同审查工作流)、`蓝队律师合同审查法律意见书标准版模板 v1.0`(目录 blue-team-contract-review-standard-v1.0) 等。
- **.bak 泛滥**：`ima_intake_state.json` 累计 **50+ 个备份**；`card_route_registry.yaml` 单目录 **9 个 .bak**。backup 纪律执行到位是优点，但**无归档清理策略**导致目录噪声。
- 32 个技能 < 6 KB（学伴族 7 科各约 5 KB），存在合并空间。

### 3.4 质量门禁 9.0 —— 全系统最扎实的一环

- LTI 文本监控器 146 KB / 1070 行 / **178 处规则引用**；QC-Controller 53 个门禁章节。
- **真拦截证据**：`grill_hook_violations.jsonl` 记录 6 次真实 block（人损专项 ×4、模拟法庭主控 ×1、蓝队诉讼 ×1），`grill_gate_mode = block` **处于生效态**。
- 2026-09-01 报告记载的 C4 实证：民法典 774 条命中但原文不含"定作人无责" → 机器 🟡 拦下人工 ✅ —— **门禁是真闸不是摆设**，这条经过 6658 实战检验。

### 3.5 编排能力 8.5

- 三层薄壳结构清晰：`xiaoqiang-front-desk-router`（元心智分诊 v1.0.0）→ `grill-me-legal-preprocessor`（需求拷问）→ `legal-consult-router`（法律域五问）/ `seat-orchestrator`（54 员工编排 v1.2.0）。
- `seat-orchestrator` 有**实跑验证记录**：2026-09-29 以 6658 第二次开庭跑通"拉取案件材料→模拟庭审"全链路；6660 亦实跑五方对抗。
- 红线设计克制（绿旁路三道闸 + fail-open 宁错派不漏接），符合"不单独处理"原则。

## 四、横向对比（严格限定口径）

### 4.1 先说清楚能比什么、不能比什么

**不能比**：其他律师的数字分身系统是私有部署，其技能数、埋点密度、命中率、门禁拦截次数**均无公开数据**。任何给出"某律师系统 XX 分"的说法都是编造。本报告**不给**这类数字。

**能比**：① WorkBuddy **平台默认基线**（公开可知）；② 2026 年 9–10 月**四场律所公开分享**披露的律师用户主流用法（京师成都、剑桥颐华、杰海、石城）；③ 用户自己的**历史基线**。

### 4.2 与平台默认基线对比

| 维度   | WorkBuddy 平台默认                      | 小强分身系统                           | 倍数               |
| ---- | ----------------------------------- | -------------------------------- | ---------------- |
| 可用技能 | 内置约 20 个（docx/pptx/sheet/library 等） | **192 个自建 + 内置**                 | **≈ 9.6×**       |
| 自动化  | 用户按需建几条                             | **93 条（71 在跑）**                  | **量级差 1–2 个数量级** |
| 知识库  | 资料库（通用文档/表格）                        | **7551 md / 2456 规则卡 / 156 法条卡** | 不可比              |
| 质量门禁 | 无内置法律门禁                             | LTI 五维 + 178 规则 + QC 53 门        | **平台无此层**        |
| 可维护性 | 开箱即用、零治理成本                          | **需持续治理**（本报告即治理成本的一部分）          | **平台占优**         |

### 4.3 与律师同行主流实践对比（能力形态，非分数）

据 2026-09 至 10 四场律所公开分享，同行主流用法呈现三个特征：

1. **单点技能**：多为"1 个自建 skill + 若干内置技能"（如某所律师"基于 workbuddy 编写 skill 生成案件分析/合同审查报告"）；
2. **连接器 + 定时任务**：知识库打通、周期性资讯收集；
3. **人机分工清晰**：普遍强调"AI 整理、律师判断""责任边界不外包"。

| 形态维度                   | 同行主流      | 小强分身系统                     |
| ---------------------- | --------- | -------------------------- |
| 技能数量级                  | 个位数 ~ 十几个 | **192**（约 10–20×）          |
