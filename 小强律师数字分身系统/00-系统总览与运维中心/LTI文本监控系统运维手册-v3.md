## 一、升级动机

原 LTI 门禁只有五维（R/L/C/T/P），覆盖「法条真不真、逻辑通不通、数值一不一致、出处有没有、程序合不合规」。
《LTI文书质检清单扩展版》要求每份对外法律文书交付前再过多四维：

- **S 策略契合度**——文书是否服务本案核心争点与诉讼目标，不节外生枝、不暴露己方弱点；
- **V 风险预判**——是否预判被驳回 / 对方反击风险并写应对；
- **W 表达规范**——法言法语中性、用词精准、无冗余；
- **E 证据闭环**——每项事实主张能否指到具体证据，无「主张飘空」。

这四维多为**定性判断**，无法像金额/案号那样被确定性脚本完全自动核验，故定级为**人工确认维**，由执业律师在交付前逐项签字确认；系统只负责「把九维门禁摆上交付路径、汇总 verdict、归零才放行」。

## 四、门禁语义与纪律（不变更底线）

1. **REJECT = 0 才准交付**：任一 ❌（含律师在 L/S/V/E 判的 ❌）即阻断，须归零后重跑。
2. **机械维可脚本自动**：C（案号/名称/金额）、P（格式/期限/签署）由 `lti_qc9.py` 与既有 `lti_gate.py` 自动校验，高置信硬错才标 ❌。
3. **策略/逻辑/证据/风险维人工确认**：L / S / V / E 不自动 REJECT（守「宁漏勿误、零误报」），须执业律师逐项确认；未确认默认记 ⚠️（不阻断，但交付前应补强归零）。
4. **接入既有红蓝复核 + 六维法理门禁**：九维门禁是交付路径上的最后一道 BMS，红蓝对抗在前、九维收口在后。

## 六、固化脚本用法（每出一份文书自动跑一遍）

```bash
# 非交互（自动化/座舱调用）：人工维默认 warn 不阻断，机械维自动查
python3 lti_qc9.py <文书.docx|.md|.txt> --report 九维报告.md
# exit 0 = PASS（可交付） / exit 1 = REJECT（须修后重跑）

# 显式给人工维结论（律师确认后回填）
python3 lti_qc9.py 文书.docx --manual L=pass S=pass V=warn E=pass

# 本地真终端逐维问询
python3 lti_qc9.py 文书.docx --interactive

# 并行调用既有 lti_gate.py 做 R/C/T/P 深度校验（best-effort）
python3 lti_qc9.py 文书.docx --legacy-gate /path/to/lti_gate.py
```

脚本依赖仅 Python 标准库（zipfile 解 docx，无需 python-docx）；`exit 0/1` 对齐既有 `lti_gate.py` 门禁约定。

## 九、九维升级复盘：对系统产出文本制品的提升（2026-10-09）

**一句话结论**：升级把交付文书的 QC 从「5 维及格线（R/L/C/T/P）」扩到「9 维闭环（＋S 策略契合 / V 风险预判 / W 表达规范 / E 证据闭环）」，并对每件文本制品新增**可落盘的多维审计 + 九维质检报告**——四个原先完全空白的维度现在都有了检查与留痕，且零误报纪律不变。

### 9.1 维度覆盖对比（文本制品受检面）

| 维度 | 升级前 v4.8.1 | 升级后 v4.9.0 | 对文本制品的实质影响 |
|---|---|---|---|
| R 法条真实 | ✓ | ✓（同） | 不变 |
| L 法理逻辑 | ✓（wrap_output 含法理审查） | ✓ 显式化为人工确认项 | 从「隐式」变「显式待确认」 |
| C 一致性 | ✓ | ✓ | 不变 |
| T 溯源 | ✓ | ✓ + 自动 T501 提示 | 增强：引用/事实缺「证据册/附件」标注自动标 |
| P 程序 | ✓ | ✓ | 不变 |
| **S 策略契合** | ✗ 无 | ✅ 新增（人工确认） | 是否服务核心争点、不节外生枝、不暴露己方弱点 |
| **V 风险预判** | ✗ 无 | ✅ 新增（人工确认） | 识别被驳回/不予准许风险、预判对方反击位 |
| **W 表达规范** | ✗ 无 | ✅ 新增（部分自动） | W901 术语不规范、W902 冗余「第一款」自动 lint |
| **E 证据闭环** | ✗ 无 | ✅ 新增（人工确认） | 每项主张指到具体证据、无「主张飘空」 |

> 受检维度 **5 → 9**，新增的 4 维对应「文书为什么写、写了有什么风险、写得规不规范、说的有没有证据撑」四个文本质量基本面。

### 9.2 对文本制品的具体提升方面

1. **表达规范自动化（W）**：「签定合同 / 法人代表 / 第一款」这类失真/冗余表述，以前无人拦；现在 `lti_qc9.py` 自动标 **W901 / W902**，文本术语与精简度提升。
2. **溯源提示增强（T）**：以前只核验法条存在；现在缺「证据册/附件/在案」出处标注自动提示 **T501**，倒逼文本把事实主张挂到出处。
3. **策略对齐（S）**：以吊顶案为例——庭后代理词现在会被问「是否紧贴冒名诉讼主轴、有无暴露己方弱点」，避免文书跑题。
4. **风险预判（V）**：交付前显式列「对方可能反击点 / 被驳回风险」，把风控前置进文本。
5. **证据闭环（E）**：每件事实主张须能指到证据册条目，杜绝「说了没佐证」的飘空主张，文本与证据册逐条对账。
6. **新增可交付报告产物**：每件文书可附《九维质检报告.md》（表格化逐维结论），与文书同台交付、留痕可查（落 `subapps/lti/reports/`）。
7. **审计可观测（meta 提升）**：S/V/W/E 命中趋势真实落盘 `lti_qc9_audit.jsonl`，可跨文书量化追踪文本质量演进，而非凭感觉。
8. **规则治理化**：S701–S703 / V801–V803 / W901–W903 / E1001–E1003 共 **12 条已并入 `rules:` 统一调度**，QC 成可版本化、可调度、可审计的规则体系。
9. **座舱可见**：九维 QC 门禁模块动态渲染 9 维，运维一眼看到覆盖度。

### 9.3 纪律与边界（不变 / 不过度宣称）

- ⚠️ **零误报纪律不变**：S / L / V / E 仍不自动 REJECT，AI 不替律师判策略/证据/逻辑，只标「待确认」——避免误伤真实文书。
- ⚠️ **REJECT = 0 才交付** 不变；自动维仍只标高置信硬错。
- ⚠️ **S / V / E 是人工确认维**：提升的是「显性化检查清单 + 留痕」，不是「AI 自动写对」——最终质量仍靠执业律师确认。
- ⚠️ **W 自动检查较浅**：目前仅术语/冗余两类，深度表达规范（语气、层次、繁简）待后续扩 `check_W`。

### 9.5 小结
