## 一、三电系统养护（动力与安全的根）

### 1.1 动力电池包 = 知识飞轮（六层 01-06 + SR 算法）
- **作用**：储能全部知识资产。容量 = 经验卡 + 规则库；健康度 = 资产质量（非堆量）。
- **当前电量（实时扫描 2026-09-04）**：六层 .md 共 **3,022**；经验卡 **205** 张（真实 204 / 演练 1）；裁判规则库 **816 文件 / 785 规范命名卡（R-领域-序号）/ 26 子库**；CaseDrop 已归档 **15** 案。
- **养护动作**：
  - 每月跑 `月度知识复利报告`（automation-1783918982318，每月 28 日 23:00），避免「只进不出」。
  - 规则库编号治理定期复查（裸号断链率门禁 0.5%，当前 0.111%）。
- **禁忌**：严禁凭记忆灌条文正文（会污染电池电芯）。

### 1.2 驱动电机 = SR 召回引擎（规则匹配调用）
- **作用**：新案进来时检索匹配规则卡 → 产出建议，把「存储电量」转成「驱动力」。
- **养护动作**：保持 `lawyer-yourself-skill` 的 SR 算法与飞轮索引同步；案件库双轨（飞轮 `案件库/` 壳 vs `案件管理/` 真卷）须做**双向索引校准**，否则召回会漏案（见故障码 DTC-CASE-001）。

### 1.3 电控 + BMS = LTI 文本监控器（v4.8.6）
- **作用**：三电管家，防「热失控」（幻觉/错引/伪造案例）。R/L/C/T/P 五维 + **T502 案例存在性核验**（编造案号→REJECT）。
- **当前状态（人工核验）**：P1+P2 已落，回归 **131/131 通过**；六维门禁 G2/G6/G8 生效。
- **养护动作**：
  - **出文必过机检**：交付前跑 `wrap_output(text, case_verify=load_case_cache())`，REJECT=0 才准交付。
  - 元典 `hall_detect` 账号仍 403（仅 VIP）→ 降级用 `rh_ft_search` 的 `sxx` 时效字段 + 官方渠道交叉印证，不中断流程。
- **禁忌**：不得为「赶交付」跳过 LTI 直接出文。

### 1.4 动能回收系统 = HIR 经验沉淀（红蓝→LTI→HIR→回流飞轮）
- **作用**：把「刹车 / 出错」的动能回收进电池——每次红蓝复核、LTI 拦截、事故登记都回流成经验卡，越开电量越多。
- **当前状态（实时扫描）**：HIR 调用记录 **36** 份（05-调用 10 类）。
- **养护动作**：保持「红蓝复核 → LTI 五维 → 六维门禁 → HIR 事故登记 → 规则回流」闭环畅通；非诉交付必走 `非诉文书红蓝复核工作流 → 专项体检 → LTI 防火墙`。

## 十、安全红线（不可越界）

1. **方向盘后必须有人**：独立法律判断、庭审临场应变、对客户最终担责——分身不可代。
2. **出文 REJECT=0 才交付**：LTI 不过，宁不交。
3. **不凭记忆灌条文**：法条正文必须从本地权威源 / 元典 / pkulaw 回填，严禁凭记忆注入缓存（实测凭记忆错引率 22%，慈善法高达 75%）。
4. **连接器断开不代点**：IMA / 法随重连须老强 UI 亲手授权，本环境不代点。
5. **写入先排查后批量**：六-B 铁律——先排查 / 确认非误报 / 再批量 / 含 dry-run + 备份。**已由 P0-1 扩展至全部写入型 automation 覆盖**。
