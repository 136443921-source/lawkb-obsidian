# 9655 驾驶舱 · 运维手册（普通律师也能看懂 · 运营 · 维护 · 保养层）

> **📌 先说人话（给第一次看的同事）**：9655 驾驶舱就是一个**网页仪表盘**，网址 `http://127.0.0.1:9655/`。它把"小强律师数字分身系统"（一台帮律师干活的人工智能助手）的**全部健康指标**集中显示在一块块"屏"上。你不用懂代码，只要会看颜色、看分数、看告警，就能判断这台"智能车"是不是正常、哪里该保养。

> **🔒 隔离声明（红线级）**：本手册是**运营 · 维护 · 保养层**，只教你怎么"看车、养车"，**绝不改车**。它只读引用造车平台 EV 的工程文件（index.html / auth.js / rbac.js / scan_9655.py / subapps/* / EV 白皮书 / EV 运维手册），**绝不修改它们**。任何"修/造/增/减"动作由老强在造车平台 EV 工程流程中另走，本手册只做"观察—诊断—建议"。

## 一、怎么打开和登录（三步，不用懂技术）

1. **打开**：在 Mac 本机浏览器输入 `http://127.0.0.1:9655/`（需本机已启动驾驶舱服务；若打不开，联系老强确认 launchd 守护在跑）。
2. **登录**：页面弹出登录框 → 选一个**席位卡片**（如"超级管理员全部屏""执业律师 C0–C8 + D1–D6""律师助理""IT 运维员"）→ 点卡片后输入工号 + 密码（统一演示凭据 `LZ-001` / `lz001@2026`）→ 点"登录演示席位"。
3. **进舱**：登录后左侧出现 **18 个导航标签**（C0–C8、D1–D9），每个标签前有个**小圆点**做分类配色；点标签即在右侧切换屏。C0 是首页（评分导航），其余 17 个是可点进去的屏。

> **小圆点颜色速记**：C0 灰、C1 紫、C2 橙、C3 青、C4 金、C5 蓝、C6 红、C7 绿、C8 粉、D1 蓝、D2 黄、D3 浅蓝、D4 紫、D5 紫(#c084fc)、D6 玫红(#fb7185)、D7 青绿(#22d3ee)、D8 琥珀(#f59e0b)、D9 品红(#e879f9)、C9 靛(#818cf8)。颜色只是"分类标签"，**不代表好坏**；好坏看分数和告警旗。

## 三、评分怎么看（分数和颜色都代表什么）

### 3.1 档位（A–E）：系统统一口径

| 档位 | 分数 | 你该怎么理解 | 你要做什么 |
| --- | --- | --- | --- |
| **A 优秀** | ≥ 90 | 很健康 | 例行巡检即可 |
| **B 良好** | ≥ 75 | 正常 | 关注趋势 |
| **C 合格** | ≥ 60 | 能用 | 排期优化 |
| **D 待改进** | ≥ 45 | 有隐患 | 近期处置 |
| **E 高危** | < 45 | 立即处理 | 马上查对应屏 |

### 3.2 六维（C0 首页顶部的六条健康条）

C0 首页顶部有六条健康度，是整车综合评分的六个角度（每条 0–100）：

| 维度 | 大白话 | 当前值 |
| --- | --- | --- |
| 部署就绪度 | 各分系统是不是都就位能跑 | **62** |
| 架构健康度 | 分层与映射是否一致 | **75** |
| 安全合规度 | 红线/权限/加密合不合规 | **67** |
| 门禁运行度 | 质控门禁是不是真在线 | **60**（门禁守护已拉起，仍偏低需关注） |
| 版本锁回填 | 版本锁/快照回填完没完成 | **100**（满分） |
| 缺口闭环度 | 已知问题是不是都闭环了 | **50** |

**环形总评** = 这六条的平均值 = **69.0 → C 合格**。哪条掉得狠，总评就被它拖垮（当前"门禁运行度 60""缺口闭环度 50"偏低，是主要短板）。

### 3.3 律所 4 屏为什么要单独说

C4/C5/C6/C7 是**律所业务屏**（案件/合规/模拟/合同），它们的评分取自 9360 静态值（66.5/61/62/71），**权重 0、不计入环形总评**——它们只是"专业工位"展示，不影响整车综合分。换角色登录时按权限显示。

### 6.1 已知坑：门禁守护在沙箱 / 远程会话拉不起（I/O error 5 · 预期边界）

> 这条是 2026-09-21 每日校验连续踩坑后补的**运维备忘**，专门防以后重复浪费时间。

- **现象**：在 WorkBuddy 沙箱、SSH、或其他"无 GUI 登录会话"的环境里执行 `launchctl bootstrap gui/$UID ...` 或 `launchctl load ...`，稳定报 `Bootstrap failed: 5: Input/output error` / `Load failed: 5: Input/output error`，门禁守护起不来，每日校验门禁项持续 ⚠️。
- **根因**：`launchctl`（用户域 LaunchAgent）必须把 agent 注入**当前登录用户的 GUI 会话域 `gui/501`**；沙箱 / 远程会话跑在隔离的 bootstrap 命名空间里，不在该域，launchd 直接拒绝写入——这是**环境边界，不是脚本或 plist 故障**，别去改 `start_lti_gate.sh` 或 plist。
- **正确做法**：回到**本机真实 Terminal**（你已 GUI 登录的会话）执行启动；已固化一键脚本 `start_lti_gate.sh`（终端跑 `./start_lti_gate.sh`）/ `start_lti_gate.command`（Finder 双击自动开 Terminal），内含双路径加载（bootstrap 优先 + load 回退）+ **诚实失败检测**（I/O error 5 时不再误报"加载成功"，直接退出码 1 并提示回真实 Terminal）。
- **勿踩**：① 别在沙箱里反复 `launchctl load` 指望它生效；② 别用 `sudo launchctl bootstrap` 强塞系统域（偏离用户域且仍可能失败）；③ 别因此误判"门禁坏了"——它只是没在正确会话里被拉起。
