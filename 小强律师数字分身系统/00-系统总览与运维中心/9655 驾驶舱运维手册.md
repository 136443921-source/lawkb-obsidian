## 一、怎么打开和登录（三步，不用懂技术）

1. **打开**：在 Mac 本机浏览器输入 `http://127.0.0.1:9655/`（需本机已启动驾驶舱服务；若打不开，联系老强确认 launchd 守护在跑）。
2. **登录**：页面弹出登录框 → 选一个**席位卡片**（如"超级管理员全部屏""执业律师 C0–C8 + D1–D6""律师助理""IT 运维员"）→ 点卡片后输入工号 + 密码（统一演示凭据 `LZ-001` / `lz001@2026`）→ 点"登录演示席位"。
3. **进舱**：登录后左侧出现 **17 个导航标签**（C0–C8、D1–D8），每个标签前有个**小圆点**做分类配色；点标签即在右侧切换屏。C0 是首页（评分导航），其余 16 个是可点进去的屏。

> **小圆点颜色速记**：C0 灰、C1 紫、C2 橙、C3 青、C4 金、C5 蓝、C6 红、C7 绿、C8 粉、D1 蓝、D2 黄、D3 浅蓝、D4 紫、D5 紫(#c084fc)、D6 玫红(#fb7185)。颜色只是"分类标签"，**不代表好坏**；好坏看分数和告警旗。

## 三、评分怎么看（分数和颜色都代表什么）

### 3.1 档位（A–E）：系统统一口径

| 档位 | 分数 | 你该怎么理解 | 你要做什么 |
| --- | --- | --- | --- |
| **A 优秀** | ≥ 90 | 很健康 | 例行巡检即可 |
| **B 良好** | ≥ 75 | 正常 | 关注趋势 |
| **C 合格** | ≥ 60 | 能用 | 排期优化 |
| **D 待改进** | ≥ 45 | 有隐患 | 近期处置 |
| **E 高危** | < 45 | 立即处理 | 马上查对应屏 |

### 3.2 六维（C0 首页顶部的六条健康条）

C0 首页顶部有六条健康度，是整车综合评分的六个角度（每条 0–100）：

| 维度 | 大白话 | 当前值 |
| --- | --- | --- |
| 部署就绪度 | 各分系统是不是都就位能跑 | **62** |
| 架构健康度 | 分层与映射是否一致 | **75** |
| 安全合规度 | 红线/权限/加密合不合规 | **67** |
| 门禁运行度 | 质控门禁是不是真在线 | **30**（被 C1/C8 拉低，关键短板） |
| 版本锁回填 | 版本锁/快照回填完没完成 | **100**（满分） |
| 缺口闭环度 | 已知问题是不是都闭环了 | **50** |

**环形总评** = 这六条的平均值 = **64.0 → C 合格**。哪条掉得狠，总评就被它拖垮（现在就是"门禁运行度 30"在拖后腿）。

### 3.3 律所 4 屏为什么要单独说

C4/C5/C6/C7 是**律所业务屏**（案件/合规/模拟/合同），它们的评分取自 9360 静态值（66.5/61/62/71），**权重 0、不计入环形总评**——它们只是"专业工位"展示，不影响整车综合分。换角色登录时按权限显示。

## 五、每天 / 每周 / 每月怎么用手册运营（普通律师能执行）

### 5.1 每日（5 分钟）
- 开 C0 首页，看**环形总评**是不是还在 C 以上；看**告警旗**有没有 🔴。
- 看 **C1 / C8**：LTI 门禁守护是不是"🔄 未启动"——**门禁不在时，你出任何法律文书都必须先手动跑一遍 LTI 质控，REJECT=0 才准发出**（见第八章红线）。
- 看 **D1**：本机源目录占用是不是逼近 90%（当前 75%，盯着趋势）。

### 5.2 每周
- 看 **C2**：实测漂移是不是又多了（当前 2 项⚠️）——漂移=实测和方案快照对不上，需回源核对。
- 看 **D5**：L1 密文是不是还"待加密"——人格层未加密是安全隐患，排期处理。

### 5.3 每月
- 看 **D2 缺口闭环**（当前 50%）：推进已知问题闭环，闭环率升=系统变干净。
- 看 **C2 版本锁回填**（当前 20/20）：新增组件要回填版本锁，保持 100%。

### 5.4 怎么"刷新"数据
C0 首页右上角 **↻** = 一键重算 `scorecard_data.json`；不点也行，**扫描守护每 5 分钟自动重扫**一次。

## 六、亮红灯了怎么办（故障 / 告警速查 DTC）

> 下表只说"现象→根因→你做什么"。告警是否点亮由实时状态判定；没映射的标"未判定"，不假装正常。

| 告警 | 现象（在哪屏看到） | 你做什么 |
| --- | --- | --- |
| **门禁未启动** | C1/C8：LTI 守护"🔄 未启动" | 让老强跑 `launchctl load` 门禁；**门禁离线期间你出文必须手跑 LTI**，这是安全机制不是故障 |
| **实测漂移** | C2：⚠️ 漂移 | 回源核对决策/思维层快照，消除漂移 |
| **磁盘水位高** | D1：源目录占用高 | 清旧备份 / 扩容，保障本机源不撑爆 |
| **L1 待加密** | D5：密文"待加密" | 排期 L1 人格层加密 + 钥匙串托管 |
| **出文被拦截** | 任何出文被 LTI 拦下 | **正常安全机制，非故障**；回填权威法条/案例源后重跑，严禁绕过 |

## 十一、活文档机制（功能一变化 · 手册即随之变更）

### 11.1 真源清单（功能变化的权威判据）

| 变化类型 | 真源文件 | 本手册对应章节 |
| --- | --- | --- |
| 屏增删 / 屏名 / 权重 | `rbac.js`（sites 注册表） | 二、三 |
| 六维/评分算法 | `scan_9655.py`（`grade_of` / `compute_score`） | 三 |
| 档位阈值 | `scan_9655.py`（`grade_of`） | 3.1 |
| C0 实时数据/各屏 KPI | `scorecard_data.json` | 四 |
| 隔离层重划 | 本手册 §八 + 造车平台 EV 总纲 | 八 |

### 11.2 变更触发点（任一发生 → 本手册须同步修订）
- 新增/删除/更名任一屏（如 D7/D8 这类注册表屏的增删）；
- 调整任何屏的 `weight` 或 `scoring` 开关；
- 修改 `grade_of` 档位阈值；
- 修改 C0 六维算法或 `mk_six` 覆盖项（某屏六维从"派生"变"实分"）；
- 调整 `scan_9655.py` 探针（新增 `probe_*` 即新增 KPI）；
- 重划"运营维护层"与"造车平台 EV 工程层"的隔离边界。

### 11.3 回写流程（保持与中枢一致）
1. 功能变更发生后，由**小强**回写本文件（升 `version` 次版本号，如 v1.1 → v1.2）；
2. 在文末「版本与变更日志」记：变更日期 / 触发点 / 改了哪节 / 依据真源；
3. 数值类"当前态"只在修订时对齐 `scorecard_data.json` 重新截图，平时以实时值为准，**不写死趋势**；
4. 本手册与造车平台 EV 文件**零写入交叉**——修代码去 `outputs/9655-cockpit-v2/`，修手册来中枢这里。

### 11.4 自动防漂移守护（已落地 · "活文档"真正自动触发）

- **基线快照** `9655_驾驶舱基线快照.json`（与本手册同目录）= 机器可读的"手册口径"：15 屏精确集合、律所 4 屏静态分（C4=66.5 / C5=61 / C6=62 / C7=71）、评级阈值（A≥90 / B≥75 / C≥60 / D≥45）、非评分位（C0 / D3）、D7/D8 禁用。是比对的唯一参照真源。
- **比对脚本** `outputs/9655-cockpit-v2/drift_check_9655.py`（只读，零写入）——比对 `rbac.js` + `scorecard_data.json` + `scan_9655.py` 三处真源 vs 基线，输出 **口径漂移清单**（D7/D8 重现 / 律所评分逻辑变化 / 阈值或权重变更 / 屏增删）+ **运行健康清单**（总评跌破 C、评分屏空值）。
- **周级自动化**：每周一 09:00 自动跑比对；发现口径漂移即**提醒老强修订本手册**（并同步更新基线快照），无需人工记着复核。
- 手动跑法：`python3 drift_check_9655.py` → 退出码 `0`=对齐 / `1`=口径漂移(需改手册) / `2`=仅健康告警。

### 11.5 防漂移约定
- 本手册 §〇/§四 的"当前评分/快照"标注生成时点（如 `2026-09-18T23:27`）；超过一次功能变更或一个月即视为待复核。
- 基线快照与手册同生命周期：手册升版时，基线 `manual_version` 字段须同步升版，二者不可脱节。
