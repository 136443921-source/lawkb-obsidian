# 技能库职责重叠审计与整理清单 v1.0

> 方法论：先跑 `skill-auditor/scripts/audit_skills.py`（venv python，含 yaml）做 frontmatter 体检；
> 再对 147 个技能做人工功能判重——逐个读取候选技能的 `description` + `触发词`，按功能簇归类，定位重叠。
> 本清单**只出结论与建议，不执行任何移动/删除**；破坏性操作须经老强逐项确认。

---

## 一、审计结论速览

| 指标 | 结果 |
|---|---|
| 活跃技能总数 | **147** |
| 字节级克隆（同名同内容） | **0** |
| 缺 name / 缺 description / 无 frontmatter | **0**（全部规范） |
| 编号命名目录（不可读目录名） | **0** |
| **功能性重叠簇** | **7 簇**，涉及约 **22 个**技能 |
| 建议合并/归档 | **约 9 个**（见第二节） |
| 建议保留独立（已合理分层） | 其余 |

**核心判断**：技能库没有"脏数据"，但有"胖数据"——大量技能功能相邻、触发词交叉，靠用户每次选对入口。文章精神「SOP 不是越多越好」同样适用于技能：**合并 ≠ 降级，是把边界理清楚、让入口唯一**。

## 五、与 27 SOP 文章精神的呼应

文章说「SOP 不是一次写完就再也不改」「SOP 不是越多越好」。技能库同理：

1. **合并不是削减能力**，是把「同一件事有多个入口」收敛成「一个入口 + 清晰分层」。
2. **重叠的本质是没沉淀边界**——每加一个 skill 时没回头看"这件事谁已经在做"。建议今后新建 skill 前先跑一次簇比对。
3. 清完一轮，预期活跃技能从 **147 → ~138**（保守，仅并明显冗余），token 注入负担下降，触发更准。
