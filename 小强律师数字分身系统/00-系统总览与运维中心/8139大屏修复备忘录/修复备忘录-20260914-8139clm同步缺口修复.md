# 修复备忘录 · 8139 C4 展示链脱节缺口修复（2026-09-14）

> 工作流：8139 大屏修复工作流（v1.0.2）· 六步法
> 屏：C4 案件生命周期大屏 · 类型：**脚本配置错（根因级）**

## 一、问题现象
8139 大屏 C4（案件生命周期大屏）展示页 `subapps/clm/index.html` 长期不随 `case-state.json` 变更刷新：手动改完 case-state 后跑 `refresh_8139.py --screen clm`，C4 展示页纹丝不动，必须手动 `cp` scan_cases 产物覆盖快照才能看到修复成果（2026-09-14 修 6658 案 34 号呈递状态、6660 案深度卡回填时两次踩坑即此根因）。

## 二、根因分类
**配置错（脚本层）**：`refresh_8139.py` 原 `GEN["clm"] = (subapps/clm/index.html, [PY, CLM_SCAN], None)` —— 把 `outfile`（备份/校验目标）误指 8139 C4 展示页，但 `scan_cases.py` 的 `main()` 只把全量版写到自身 `dashboard/案件生命周期大屏.html`，**根本不写** `subapps/clm/index.html`。主循环 `subprocess.run([PY, CLM_SCAN])` 跑完，展示页未被任何步骤触碰 → 脱节。本质是「GEN 三元组假设生成器会写 outfile」与「scan_cases 不写该路径」的不匹配（设计缺口）。

## 三、改动文件 + 备份路径
- **改**：`~/.workbuddy/skills/8139大屏修复工作流/scripts/refresh_8139.py`
  - 备份：`/tmp/8139fix-clm-20260914-210026/refresh_8139.py`
  - 改动：
    1. 常量区新增 `CLM_DASH / CLM_DASH_RED / CLM_OUT / CLM_SUBAPP / CLM_CLAW_DASH / CLM_CLAW_OUT`；`GEN` 字典删除 `clm` 项
    2. 新增 `ALL_SCREENS = list(GEN.keys()) + ["clm"]`
    3. 新增专用函数 `_refresh_clm(dry_run)`：① 跑 `scan_cases.py` 生成全量版+简报+桌面副本；② 把全量版 cp 同步到 `subapps/clm/index.html`（8139 C4 展示页）与 `Claw/case-lifecycle/dashboard`；③ 简报同步到 `Claw/case-lifecycle/out`；先备份再覆盖、幂等
    4. `main` 循环：`k=="clm"` 走 `_refresh_clm`，未知屏提示用 `ALL_SCREENS`
- **同步文档**：`~/.workbuddy/skills/8139大屏修复工作流/SKILL.md`（v1.0.2）：C4 映射表刷新命令、Phase 3 C4 关键点、§3 助手脚本、变更日志
