# LTI 文本监控系统 · 运维手册

> **当前版本**：v4.8.6（最后代码落地 2026-09-03；2026-09-06 本会话将 `case_verify` 注入交付门禁 `lti_gate.py`，T502 生产生效）
> **运维手册版号**：**v1.0**（初版归档 · 2026-09-06 19:03 · 含门禁注入；T502 噪音闭环与自动化触发尚未纳入）
> **定位**：小强律师数字分身系统「法律问题处理代理」的防法律文书幻觉拦截器
> **设计哲学**：六模块形式层校验 + **宁漏勿误**（误报优先级 > 漏报）+ **LTI 通过 ≠ 文本无误**（法条内容/适用性/引用正确性/实体定性由人工·AI 法理层兜底）
> **维护铁律**：先排查确认再批量修改、批量前先 dry-run、改前 `cp -n` 备份（六-B）；权威数据绝不静默覆盖；法条/源文绝不凭记忆灌入

### 1.2 数据资产

- **`provision_index/yuandian_verify_cache.json`**（1054 条）：法条核验缓存，`{法规_第X条: {content/article/law/source/fbrq/ssrq/sxx/verified_at}}`。`source` 区分 `yuandian-mcp`（在线核验）与 `local-index`（本地权威索引）。
- **`provision_index/case_verify_cache.json`**（5 条）：案例存在性缓存，`{规范案号: {exists, source, detail, verified_at}}`，T502 门禁数据源。
- **`provision_index/index_*.json`**（14 部法）：本地全文索引（民法典/刑法/刑诉法/民诉法/民诉法司法解释/公司法/行诉法/行政处罚法/行政强制法/慈善法/工伤保险条例/医疗纠纷预防和处理条例/基金会管理条例/买卖合同司法解释）。
- **`provision_index/raw/*.txt`**：gov.cn/新华网公布件全文（部分 JSON 包裹，读取须先探测格式）。
- **`provision_index/manifest.json`**：索引注册表（增量读-合并-写，防全量重建破坏既有索引）。

### 1.3 门禁接线

- `references/main.py` `wrap_output(text, enable_modules, case_verify, registry, ...)`：六模块统一裁决入口。T502 由 `case_verify` 参数驱动（None→静默降级）。
- `lti_gate.py`（位于 `WorkBuddy/2026-08-08-15-48-47/`）：交付流水线调用，段落级 + 全文级双粒度跑 `wrap_output`；**2026-09-06 已注入 `CASE_VERIFY=load_case_cache()` 并传入两处调用**，T502 在交付门禁中实际运行。

### 2.2 关键迭代脉络解读

**① 定位升级（v2.9.2 → v3.0 → v4.0）**
- v2.9.2 用「方案B」把散装术语映射换成四个确定性检查器（R101–R104），R101 经 ≥200 份文书验证误报率 0% 后升为 REJECT——这是「凭样本验证再升阻断」纪律的起点。
- v3.0 主动砍掉所有格式/结构检查（R002–R024），**确立「只管法条真实性、不管文风」的边界**，避免伪权威。
- v4.0 从「单点校验器」升级为「三模块监控器」（法条+逻辑+一致性），C301 金额硬矛盾成为第二个 REJECT 级规则。

**② 盲区逐层封堵（v3.x → v4.x）**
- 条号真实 ≠ 内容真实：R109（内容编造）→ R107（漏款截断）→ R102/R111（张冠李戴）→ R112（定性盲区）→ R116（版本位移），一层层把「形式层放行≠安全」坐实。
- 溯源防幻判：T501（案号有出处）→ T502（案例真实存在）→ T503（事实锁定），构成「伪造裁判文书」三道闸门。

**③ 在线权威源替代凭记忆（v4.7 → v4.8.0 → v4.8.6）**
- 元典 MCP 接入后，表外法律/版本时效不再靠记忆，改由 `yuandian_verify.py` 在线核验 + 缓存持久化；案例存在性由 T502 + 元典 `rh_ptal_search` 回填闭环。

**④ 事故驱动的反向污染防护（v4.8.2 → v4.8.5）**
- 四次「静默成功却产出错误」事故，催生：民诉法索引补齐、通说表回溯重校、空索引熔断、源文自清洁 C0/C1/C2。**一句话教训：崩溃式失败会喊人，静默成功不会。**

## 四、日常运维 SOP

### 4.1 法条核验回填（新增/修订法条后必做）

**本地索引预回填（零成本，首选）**
```bash
cd ~/.workbuddy/skills/LTI文本监控器/references
python3 prefill_cache.py          # 从 index_*.json / raw/*.txt / LawKB 提取高频条正文
```
**元典在线核验（表外法律/版本时效，按调用计费≈1分/条）**
```bash
# 会话 AI 调 yuandian-mcp：yuandian_rh_ft_detail(fgmc=法规名, ftnum=条号)
# 将返回写入缓存（record_verification 自动规范化 law 键 + 写前备份）
```
**铁律**：仅从本地已索引/已落盘权威文件或元典在线核验提取，**绝不凭记忆灌正文**；同键不覆盖（在线核验优先）。

### 4.2 案例核验回填（T502 数据源，交付前必做）

```bash
cd ~/.workbuddy/skills/LTI文本监控器/references
# 1) 提取文书中的案号/指导案例
python3 verify_cases.py --extract 文书.md
# 2) 会话 AI 调元典 rh_ptal_search(ah=案号) 确认是否存在，写成 results.json：
#    [{"ref":"(2024)川01民终522号","exists":true,"source":"yuandian-mcp","detail":"..."}]
# 3) 回填（写前自动 .bak 备份）
python3 verify_cases.py --record results.json
# 4) 查看缓存
python3 verify_cases.py --status
```
**三态语义**：`exists=false`（经核验不存在）→ T502 REJECT 阻断；缓存无记录→ T502 INFO 提示（不阻断）；真实→静默；不传 `case_verify`→静默降级。

### 4.3 看缓存状态 / 元典余额

```bash
python3 verify_cases.py --status                       # 案例缓存条目
python3 -c "import json;print(len(json.load(open('provision_index/yuandian_verify_cache.json'))))"  # 法条条目数
# 元典余额：会话 AI 调 yuandian_get_user_balance（2026-09-06 约 1470 分）
```

### 4.4 跑回归测试（改任何规则后必跑）

```bash
cd ~/.workbuddy/skills/LTI文本监控器/references
python3 -m pytest tests/test_lti.py -q     # 或 python3 tests/test_lti.py
# 门禁：131/131 全绿方可交付；新增规则须带负对照用例
```

### 4.5 源文卫生体检（重建/新增索引后必跑）

```bash
python3 check_raw_hygiene.py        # D1 重复条号/D2 页脚噪声/D3 断层/D4 超短/D5 头部缺失/D6 复合条
# 0 ERROR 级问题为合格；修复空索引/源文缺条须熔断（条数 < 期望×60% 即 SystemExit）
```
**加固**：`build_law_index.py` 含空索引熔断；复合条号须用复合键比较，防 C2 误杀（v4.8.5 事故）。

### 4.6 R116 样本收集与评估（升阻断前置）

```bash
python3 r116_samples.py stats                          # 看样本数与误报率
python3 r116_samples.py list                           # 列样本
python3 r116_samples.py label <id> tp|fp|skip          # 标注 真阳性/误报/跳过
python3 r116_samples.py evaluate                       # 达门槛给"可升 BLOCKING"结论
```
- **现状**：`R116_BLOCKING=False`（用户拍板，样本 3/100 未达门槛）。每次 `law_authenticity` 校验自动落样本（惰性调用+异常兜底），**无需手动收集**。
- 达 ≥100 份且误报率 ≤1% → 由老强拍板置 `R116_BLOCKING=True`。

### 4.7 交付门禁实跑（文书交付前）

```bash
python3 /Users/chenyouqiang/WorkBuddy/2026-08-08-15-48-47/lti_gate.py "<docx绝对路径>"
# 段落级 + 全文级双粒度；T502 已注入 → 未核验案号出 [T502] INFO、编造案号 REJECT
# exit 0 = PASS 可交付；exit 1 = REJECT 须修后重跑
```

### 4.8 灰度升级决策流程（升 BLOCKING 铁律）

> WARNING 灰度 ≥1 周期 → ≥200 份真实文书抽样 → 误报率 ≤1% 且漏报可接受 → 执业律师人工评审 → 置 `XXX_BLOCKING=True`。**误报率超标禁止升级。**
> 工具：`grayscale_monitor.py`（`--dir` 批量跑、`--trace-empty-registry` 最严场景、`--out` 导出 JSON 供标注）；样本骨架 `grayscale_samples/`。

| 条号真实但内容编造 | R109/R102 部分根治（刑法/民法典精确比对），其余5部靠 R102 | 须人工逐条核验条文内容 |
| 引用范围表外法律 | R106 分级提示（>800→WARNING/>300→INFO） | 复用 R101 正则 |
| 法律名称虚构 | R105 提示（白名单滞后于立法） | `law_names.py` 定期维护，权威源核对 |
| 在审草案未生效 | R108 提示（只判存在/在审，不判现行有效） | `law_versions.py` 维护 |
| 法理逻辑深层矛盾 | 规则层仅抓显性矛盾（L201–L204）；长文书由 L-ENHANCE 提示 | 依赖 AI 法理层点评 |
| 跨句/多标的金额冲突 | C301 仅同句单一标的冲突才报（宁漏勿误） | 人工/AI 增强层 |
| 纯人名前后错写 | C302 聚焦组织主体名，避免纯人名误吞 | 规划增强 |
| **案例存在性** | **T502 已堵：编造案号 REJECT / 未核验 INFO** | 交付前 `verify_cases.py` 回填 |
| R105 对司法解释盲区 | 真实司法解释（如《证据规定》）会被误标"疑似虚构" | 非阻断，勿误删引用；F1 白名单已补常用解释 |

**核心原则**：LTI 只做形式层校验（条号真实/内容指纹/引用完整/映射已附/领域不冲突/涵摄痕迹/版本自洽），**法条内容·适用性·引用正确性·实体定性由人工/AI 法理层兜底**。
