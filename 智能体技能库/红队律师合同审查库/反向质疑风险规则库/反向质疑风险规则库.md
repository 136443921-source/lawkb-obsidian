# 反向质疑风险规则库

**版本**: v1.0  
**创建日期**: 2026-05-20  
**最后更新**: 2026-05-20  
**总规则数**: 52条  
**覆盖类别**: 10类  
**用途**: 红队律师反向质疑引擎核心规则库，用于识别蓝队遗漏风险点和生成反向挑战清单  

---

## 一、规则库概述

### 1.1 规则库定位

本规则库是红蓝对抗体系中**反向质疑引擎（Reverse Challenge Engine）**的核心组成部分。红队律师使用本规则库对蓝队审查报告进行"预驳回攻击"，识别蓝队遗漏的风险点，生成反向挑战清单。

### 1.2 规则结构

每条规则包含以下字段：

| 字段 | 说明 |
|------|------|
| **编号** | 规则唯一标识，格式：`规则_类别_序号` |
| **质疑强度** | 🔴强质疑（必须挑战）/ 🟠中质疑（建议挑战）/ 🟡弱质疑（可选挑战） |
| **质疑点** | 规则核心问题 |
| **质疑说明** | 规则的具体检查内容 |
| **法律依据** | 相关法律法规 |
| **攻击策略** | 对方可能的攻击方式 |
| **预期后果** | 不利情形描述 |
| **红队建议** | 修改建议或应对策略 |

### 1.3 质疑强度分布

| 强度 | 数量 | 占比 | 说明 |
|------|------|------|------|
| 🔴 强质疑 | 18条 | 35% | 必须挑战，否则重大不利 |
| 🟠 中质疑 | 22条 | 42% | 建议挑战，可能改善地位 |
| 🟡 弱质疑 | 12条 | 23% | 可选挑战，优化空间 |

## 二、规则详情

### 类别一：管辖权条款（3条规则）

#### 【🔴强质疑】规则_01_01：管辖权条款的攻击性解释

| 字段 | 内容 |
|------|------|
| **质疑点** | 蓝队是否遗漏了管辖权条款的攻击性解释？ |
| **质疑说明** | 检查管辖法院是否对委托方不利，对方可能如何利用管辖权条款增加委托方诉讼成本 |
| **法律依据** | 《民事诉讼法》第34条（协议管辖）、第23条（一般管辖） |
| **攻击策略** | 如管辖法院为对方所在地，对方可利用主场优势增加委托方诉讼成本 |
| **预期后果** | 委托方需异地诉讼，增加时间成本和差旅费用 |
| **红队建议** | 争取约定"原告住所地法院管辖"或"守约方所在地法院管辖" |

#### 【🟠中质疑】规则_01_02：仲裁条款遗漏

| 字段 | 内容 |
|------|------|
| **质疑点** | 管辖权条款是否排除了仲裁？ |
| **质疑说明** | 检查是否遗漏了仲裁条款，仲裁可能比诉讼更保护商业秘密 |
| **法律依据** | 《仲裁法》第16条、第17条 |
| **攻击策略** | 如合同未约定仲裁，对方可选择诉讼并公开审理，泄露委托方商业秘密 |
| **预期后果** | 商业秘密泄露风险增加 |
| **红队建议** | 考虑增加"或裁或审"条款，优先约定保密性强的仲裁机构 |

#### 【🟠中质疑】规则_01_03：多个可选管辖法院

| 字段 | 内容 |
|------|------|
| **质疑点** | 管辖权条款是否约定了多个可选法院？ |
| **质疑说明** | 多个管辖法院会导致管辖权争议，拖延诉讼进程 |
| **法律依据** | 《民事诉讼法》第35条（选择管辖） |
| **攻击策略** | 对方会利用管辖权争议提出管辖异议，拖延诉讼 |
| **预期后果** | 诉讼进程被拖延3-6个月 |
| **红队建议** | 明确约定唯一管辖法院，避免管辖争议 |

### 类别二：违约责任条款（5条规则）

#### 【🔴强质疑】规则_02_01：违约金被调减风险

| 字段 | 内容 |
|------|------|
| **质疑点** | 蓝队是否低估了违约责任条款的潜在风险？ |
| **质疑说明** | 检查违约金是否过高（可能被法院调减），或过低（无法弥补损失） |
| **法律依据** | 《民法典》第585条第2款（违约金调整规则） |
| **攻击策略** | 对方会主张违约金过高请求法院调减，或利用低违约金恶意违约 |
| **预期后果** | 违约金条款被调减，或对方恶意违约成本低 |
| **红队建议** | 违约金设定为实际损失的30%-50%，并增加"不超过实际损失"的上限约定 |

#### 【🔴强质疑】规则_02_02：赔偿范围被限定

| 字段 | 内容 |
|------|------|
| **质疑点** | 违约责任是否限定了赔偿范围（如排除间接损失）？ |
| **质疑说明** | 检查是否有限定赔偿范围的条款，这可能严重损害委托方利益 |
| **法律依据** | 《民法典》第584条（损失赔偿范围） |
| **攻击策略** | 对方会主张仅赔偿直接损失，排除利润损失、商誉损失等间接损失 |
| **预期后果** | 委托方实际损失无法获得充分赔偿 |
| **红队建议** | 删除所有限定赔偿范围的条款，或明确"包括但不限于直接损失和间接损失" |

#### 【🟠中质疑】规则_02_03：违约金支付时限不明

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否约定了违约金支付时限？ |
| **质疑说明** | 检查违约金支付时限是否明确，模糊时限会导致执行困难 |
| **法律依据** | 《民法典》第511条第4项（履行期限不明确） |
| **攻击策略** | 对方会主张支付时限未约定，无限拖延支付 |
| **预期后果** | 违约金执行周期延长，现金流受损 |
| **红队建议** | 明确违约金支付时限，如"违约事实确认后15个工作日内" |

#### 【🟡弱质疑】规则_02_04：违约金计算基数不明确

| 字段 | 内容 |
|------|------|
| **质疑点** | 违约金计算基数是否明确？ |
| **质疑说明** | 检查违约金是按合同总额还是实际损失计算 |
| **法律依据** | 《民法典》第585条第1款 |
| **攻击策略** | 如未明确基数，对方会主张按最低标准计算 |
| **预期后果** | 违约金金额存在争议空间 |
| **红队建议** | 明确违约金计算基数，如"以合同总金额为基数" |

#### 【🔴强质疑】规则_02_05：根本违约解除权被排除

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否排除了根本违约的解除权？ |
| **质疑说明** | 检查是否有限制委托方解除合同权利的条款 |
| **法律依据** | 《民法典》第563条（合同法定解除） |
| **攻击策略** | 对方会主张合同限制了解除权，阻止委托方及时止损 |
| **预期后果** | 委托方无法及时解除合同，损失持续扩大 |
| **红队建议** | 明确约定根本违约情形下的解除权，不受其他条款限制 |

### 类别三：付款条件条款（3条规则）

#### 【🔴强质疑】规则_03_01：验收标准模糊导致付款障碍

| 字段 | 内容 |
|------|------|
| **质疑点** | 付款条件是否过于宽松（如'验收合格后付款'但验收标准模糊）？ |
| **质疑说明** | 验收标准模糊会导致对方拖延付款或拒绝付款 |
| **法律依据** | 《民法典》第510条（合同约定不明处理） |
| **攻击策略** | 对方会主张验收不合格拒绝付款，委托方需举证验收合格 |
| **预期后果** | 付款被拖延，委托方举证困难 |
| **红队建议** | 验收标准具体化，约定"单方验收权"或"视为验收合格"条款 |

#### 【🟠中质疑】规则_03_02：逾期付款无违约责任

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否约定了逾期付款的违约责任？ |
| **质疑说明** | 检查是否遗漏逾期付款违约金或利息条款 |
| **法律依据** | 《民法典》第577条（违约责任）、第584条 |
| **攻击策略** | 如未约定，对方逾期付款只需返还本金，无额外成本 |
| **预期后果** | 对方恶意拖欠付款无成本约束 |
| **红队建议** | 增加逾期付款利息条款，如"按日万分之五计算" |

#### 【🟠中质疑】规则_03_03：付款账户信息不明确

| 字段 | 内容 |
|------|------|
| **质疑点** | 付款账户信息是否明确？ |
| **质疑说明** | 检查收款账户是否明确，避免对方错误付款导致纠纷 |
| **法律依据** | 《民法典》第509条（全面履行义务） |
| **攻击策略** | 如账户信息不明确，对方可主张已付款但委托方未收到 |
| **预期后果** | 付款路径争议，增加履约风险 |
| **红队建议** | 明确约定收款账户、开户行、账号，注明"如账户变更需书面通知" |

### 类别四：保密条款（3条规则）

#### 【🔴强质疑】规则_04_01：保密信息定义过宽导致条款无效

| 字段 | 内容 |
|------|------|
| **质疑点** | 蓝队是否忽略了保密条款的例外情形？ |
| **质疑说明** | 保密信息定义过于宽泛会被认定无效，需明确除外情形 |
| **法律依据** | 《民法典》第496条（格式条款无效情形） |
| **攻击策略** | 对方会主张保密信息定义过宽、包含公知信息，导致条款无效 |
| **预期后果** | 保密条款被认定无效，无法追究对方违约责任 |
| **红队建议** | 明确保密信息定义，列明除外情形（如公知信息、独立开发信息等） |

#### 【🟠中质疑】规则_04_02：保密信息返还/销毁时限缺失

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否约定了保密信息的返还或销毁时限？ |
| **质疑说明** | 合同终止后保密信息的处理时限是常见遗漏 |
| **法律依据** | 行业惯例+《反不正当竞争法》第9条 |
| **攻击策略** | 如未约定，合同终止后对方仍持有保密信息，增加泄露风险 |
| **预期后果** | 保密信息失控，泄露风险持续存在 |
| **红队建议** | 明确"合同终止后30日内返还或销毁全部保密信息" |

#### 【🟡弱质疑】规则_04_03：保密期限不明确

| 字段 | 内容 |
|------|------|
| **质疑点** | 保密期限是否明确？ |
| **质疑说明** | 检查保密义务是否有期限限制，永久保密可能不被法院支持 |
| **法律依据** | 《民法典》第496条（公平原则） |
| **攻击策略** | 永久保密义务可能被法院认定过于苛刻而调整 |
| **预期后果** | 保密期限存在争议空间 |
| **红队建议** | 平衡保密需求与合理性，建议核心机密永久保密，一般商业秘密5年 |

### 类别五：知识产权条款（3条规则）

#### 【🔴强质疑】规则_05_01：衍生作品和改进版本归属不明

| 字段 | 内容 |
|------|------|
| **质疑点** | 知识产权归属是否明确（特别是衍生作品和改进版本）？ |
| **质疑说明** | 检查IP归属条款是否覆盖衍生作品、改进版本、后续开发 |
| **法律依据** | 《著作权法》第13条、《专利法》第6条 |
| **攻击策略** | 如未明确，对方会主张衍生作品IP归其所有 |
| **预期后果** | 委托方失去衍生作品和改进版本的IP所有权 |
| **红队建议** | 明确约定衍生作品、改进版本归委托方所有 |

#### 【🟠中质疑】规则_05_02：IP侵权追偿机制缺失

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否约定了IP侵权的追偿机制？ |
| **质疑说明** | 检查对方提供的材料侵犯第三方IP时，委托方是否有追偿权 |
| **法律依据** | 《著作权法》第53条、《专利法》第71条 |
| **攻击策略** | 如未约定，委托方使用对方材料被诉侵权时需独自承担责任 |
| **预期后果** | 委托方承担全部IP侵权风险和损失 |
| **红队建议** | 增加"对方保证不侵犯第三方IP，侵权时承担全部责任"条款 |

#### 【🟠中质疑】规则_05_03：对方对背景IP的权利边界不清

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否排除了对方对委托方背景IP的使用权？ |
| **质疑说明** | 检查是否明确对方仅对委托方背景IP有使用权而无所有权 |
| **法律依据** | 《著作权法》第10条（著作权内容） |
| **攻击_strategy** | 如未明确，对方可能主张对委托方背景IP享有共有权 |
| **预期后果** | 委托方背景IP被对方主张共有权 |
| **红队建议** | 明确背景IP的使用范围仅限于本合同目的，禁止共有权主张 |

### 类别六：合同解除与终止（3条规则）

#### 【🔴强质疑】规则_06_01：解除条件不对等

| 字段 | 内容 |
|------|------|
| **质疑点** | 解除条件是否对委托方过于苛刻？ |
| **质疑说明** | 检查委托方解除合同的条件是否过于严格，对方解除条件是否过于宽松 |
| **法律依据** | 《民法典》第563条（法定解除）、第565条（解除程序） |
| **攻击策略** | 对方会利用宽松的解除条件随时解除合同，而委托方无法解除 |
| **预期后果** | 合同解除权不对等，委托方处于被动地位 |
| **红队建议** | 确保双方解除条件对等，增加"对方重大违约时委托方的即时解除权" |

#### 【🟠中质疑】规则_06_02：后合同义务不明确

| 字段 | 内容 |
|------|------|
| **质疑点** | 合同终止后的义务是否明确？ |
| **质疑说明** | 检查合同终止后双方的义务（如资料返还、债务清算、保密义务延续） |
| **法律依据** | 《民法典》第558条（后合同义务） |
| **攻击策略** | 如未明确，对方会在合同终止后拒绝履行后合同义务 |
| **预期后果** | 合同终止后权益无法保障 |
| **红队建议** | 明确列明合同终止后的各项义务及违反责任 |

#### 【🟡弱质疑】规则_06_03：过渡期缺失

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否约定了合同终止后的过渡期？ |
| **质疑说明** | 检查是否给予委托方合理的过渡期寻找替代供应商/服务商 |
| **法律依据** | 行业惯例+公平原则 |
| **攻击策略** | 如未约定，对方终止合同后委托方立即陷入供应/服务中断 |
| **预期后果** | 业务连续性受损 |
| **红队建议** | 增加过渡期条款，如"合同终止前60日通知，给予90日过渡期" |

### 类别七：不可抗力条款（2条规则）

#### 【🔴强质疑】规则_07_01：不可抗力定义被滥用

| 字段 | 内容 |
|------|------|
| **质疑点** | 不可抗力定义是否过于宽泛（对方可能滥用）？ |
| **质疑说明** | 检查不可抗力定义是否被对方利用来逃避责任 |
| **法律依据** | 《民法典》第180条（不可抗力定义） |
| **攻击策略** | 对方会主张市场变化、原材料涨价等属于不可抗力，拒绝履约 |
| **预期后果** | 对方滥用不可抗力条款逃避违约责任 |
| **红队建议** | 明确排除商业风险（如市场波动、资金困难），仅限自然灾害/战争等 |

#### 【🟠中质疑】规则_07_02：不可抗力通知义务不明确

| 字段 | 内容 |
|------|------|
| **质疑点** | 不可抗力通知时限和证明要求是否明确？ |
| **质疑说明** | 检查对方主张不可抗力时需要履行的通知义务和证明标准 |
| **法律依据** | 《民法典》第590条（不可抗力通知义务） |
| **攻击策略** | 如未明确，对方可事后补造不可抗力证据 |
| **预期后果** | 不可抗力主张难以反驳 |
| **红队建议** | 明确通知时限（如7日内）、证明材料要求（官方证明）、不减损义务 |

### 类别八：争议解决条款（2条规则）

#### 【🔴强质疑】规则_08_01：维权成本过高

| 字段 | 内容 |
|------|------|
| **质疑点** | 争议解决条款是否对委托方成本过高？ |
| **质疑说明** | 检查诉讼/仲裁地点、费用承担、律师费承担等成本条款 |
| **法律依据** | 《民事诉讼法》第34条、《仲裁法》第16条 |
| **攻击_strategy** | 如约定对方所在地管辖或对方不承担律师费，委托方维权成本过高 |
| **预期后果** | 委托方因维权成本过高放弃追责 |
| **红队建议** | 约定"守约方所在地管辖"+"败诉方承担律师费" |

#### 【🟠中质疑】规则_08_02：保全措施配合义务缺失

| 字段 | 内容 |
|------|------|
| **质疑点** | 是否约定了诉讼保全和证据保全的便利措施？ |
| **质疑说明** | 检查是否约定对方配合诉讼保全、证据保全的义务 |
| **法律依据** | 《民事诉讼法》第100条（财产保全）、第81条（证据保全） |
| **攻击策略** | 如未约定，对方会转移财产、销毁证据，导致判决无法执行 |
| **预期后果** | 胜诉后无法执行，判决成为一纸空文 |
| **红队建议** | 增加"双方配合对方采取保全措施的义务"条款 |

| **法律依据** | 《民法典》第500条（缔约过失责任） |
| **攻击策略** | 如陈述与保证不充分，对方隐瞒重大信息导致委托方损失 |
| **预期后果** | 委托方因信息不对称做出错误决策 |
| **红队建议** | 清单化约定对方的陈述与保证事项，并约定违反时的赔偿责任 |

| **法律依据** | 《民法典》第577条（违约责任） |
| **攻击策略** | 如未约定，对方违反陈述与保证时委托方救济措施有限 |
| **预期后果** | 委托方救济措施不足，损失难以追回 |

### 类别十：附件与主文一致性（3条规则）

#### 【🔴强质疑】规则_10_01：附件与主文冲突

| 字段 | 内容 |
|------|------|
| **质疑点** | 附件与主文是否存在冲突？ |
| **质疑说明** | 逐条比对附件与主文的表述，识别冲突、矛盾、遗漏 |
| **法律依据** | 《民法典》第466条（合同条款解释规则） |
| **攻击策略** | 对方会主张以对其有利的版本（主文或附件）为准 |
| **预期后果** | 条款解释争议，对方选择对其有利的解释 |
| **红队建议** | 明确"附件与主文冲突时以主文为准"，或明确优先顺序 |

#### 【🟠中质疑】规则_10_02：附件生效机制不明确

| 字段 | 内容 |
|------|------|
| **质疑点** | 附件是否具有独立的签署和生效机制？ |
| **质疑说明** | 检查附件是否经过双方签署，是否与主合同同时生效 |
| **法律依据** | 《民法典》第490条（合同生效时间） |
| **攻击策略** | 如附件未独立签署，对方会主张附件未生效 |
| **预期后果** | 附件条款无法执行 |
| **红队建议** | 附件与主文同时签署，注明"与本合同具有同等法律效力" |

#### 【🟡弱质疑】规则_10_03：引用标准版本过旧

| 字段 | 内容 |
|------|------|
| **质疑点** | 附件引用标准是否为最新版本？ |
| **质疑说明** | 检查附件引用的技术标准、法律法规是否为现行有效版本 |
| **法律依据** | 《标准化法》第10条（标准复审） |
| **攻击策略** | 如引用废止标准，对方会主张按废止标准执行 |
| **预期后果** | 技术标准争议，执行标准不符合最新要求 |
| **红队建议** | 约定"引用标准以合同签订时最新有效版本为准" |

## 四、使用指南

### 4.1 使用场景

本规则库适用于以下场景：

1. **红蓝对抗审查**：红队对蓝队审查报告进行预驳回攻击
2. **合同起草前**：识别可能的不利条款，提前设计攻防策略
3. **合同谈判**：针对对方提出的条款进行反向质疑
4. **风险评估**：补充蓝队审查，识别遗漏风险点

### 4.2 使用流程

```
Step 1：加载规则库（52条规则）
        ↓
Step 2：逐条检查蓝队报告
        ↓
Step 3：标记状态（已覆盖/遗漏/评级不足）
        ↓
Step 4：生成反向质疑清单
        ↓
Step 5：输出红队报告（集成反向质疑章节）
```

### 4.3 输出格式

详见反向质疑引擎插件文档（`plugins/reverse_challenge_engine.md`）
