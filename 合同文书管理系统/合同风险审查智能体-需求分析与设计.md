# 合同风险审查智能体 - 需求分析与设计

**项目启动时间**：2026年4月17日  
**目标用户**：老强（慈善基金会秘书长 + 实习律师）  
**当前阶段**：第一阶段 - 需求分析与设计

---

## 一、用户背景与核心需求

### 1.1 用户画像
- **双重身份**：贵州省5A级慈善基金会秘书长 + 实习律师
- **专业背景**：法律职业资格证书 + 中级社会工作师证
- **复合经验**：政府6年 + 企业高管5年 + 慈善组织8年
- **医学背景**：药监、卫生部门工作经验（潜在医疗合同需求）

### 1.2 实务场景
**高频处理的合同类型**：
1. **慈善组织相关**：
   - 捐赠协议（公募/非公募）
   - 受赠协议
   - 项目合作协议（与政府部门、企业、社会组织）
   - 志愿服务协议
   - 资助协议

2. **企业客户相关**：
   - 服务合同（咨询、技术、培训）
   - 采购/销售合同
   - 保密协议（NDA）
   - 劳动/劳务合同（员工、顾问）
   - 租赁合同

3. **个人业务相关**：
   - 民间借贷合同（已有模拟法庭案例）
   - 委托代理合同
   - 人身损害赔偿协议（医疗、工伤、交通事故）

### 1.3 核心痛点
1. **外部律师不熟悉慈善组织业务**：对《慈善法》《基金会管理条例》等特殊法规理解不足
2. **审查效率有待提升**：人工逐条审查耗时，标准不统一
3. **风险识别不全面**：易忽略隐蔽条款（如跨境支付、数据出境）
4. **修改建议缺乏系统性**：依赖个人经验，缺乏最佳实践库
5. **知识无法有效沉淀**：审查经验散落在不同文档，难以复用

### 1.4 核心需求
**功能性需求**：
1. 支持多种格式输入（DOCX、PDF、纯文本）
2. 自动识别合同类型并匹配审查规则
3. 识别关键风险条款（高/中/低风险分级）
4. 提供具体的修改建议和法律依据
5. 生成结构化风险报告（可直接交付客户）
6. 积累审查案例，形成知识库

**非功能性需求**：
1. **易用性**：界面简单，操作便捷（适合法律专业人士）
2. **准确性**：风险识别准确率>85%，误报率<15%
3. **效率**：10页合同审查时间≤15分钟
4. **可扩展性**：支持自定义风险规则库
5. **集成性**：可与iMA知识库、腾讯文档联动

## 二、功能范围确认

### 2.1 支持的合同类型（第一阶段）
| 合同类型 | 优先级 | 说明 |
|----------|--------|------|
| 捐赠协议 | ⭐⭐⭐⭐⭐ | 慈善组织核心业务，涉及《慈善法》特殊规定 |
| 项目合作协议 | ⭐⭐⭐⭐⭐ | 基金会与政府/企业/社会组织的合作项目 |
| 服务合同 | ⭐⭐⭐⭐ | 通用业务，覆盖咨询、技术、培训等 |
| 保密协议（NDA） | ⭐⭐⭐⭐ | 高频使用，条款标准化程度高 |
| 民间借贷合同 | ⭐⭐⭐⭐ | 已有模拟法庭经验，可直接验证 |

### 2.2 风险审查维度
**合同通用风险维度**：
1. **责任限制条款**
   - 无限责任/单方责任不对等
   - 赔偿上限不合理
   - 除外责任范围过宽

2. **付款条款**
   - 付款条件过于苛刻（如“验收合格后支付”无客观标准）
   - 付款期限过长
   - 预付款比例过高/过低

3. **知识产权条款**
   - 权利归属不明确
   - 许可范围过窄/过宽
   - 保密期限不合理

4. **违约条款**
   - 违约金比例过高（超过法定上限）
   - 违约定义过于宽泛
   - 单方解约权不对等

5. **管辖与法律适用**
   - 管辖法院对己方不利（外地、偏远地区）
   - 法律适用不利于己方（如约定外省法规）
   - 争议解决方式不合理（仲裁vs诉讼）

**慈善组织特殊风险维度**：
1. **资金使用限制**
   - 是否违反《慈善法》关于捐赠财产使用规定
   - 管理费用比例是否合规（≤10%）
   - 是否设置不合理的资金使用条件

2. **信息公开义务**
   - 是否违反《慈善组织信息公开办法》
   - 信息公开范围是否合理（涉密信息保护）
   - 公开时限是否符合规定

3. **关联交易风险**
   - 是否存在未披露的关联关系
   - 关联交易条件是否公允
   - 是否履行必要审批程序

4. **公益活动合规**
   - 是否涉及公开募捐（需备案）
   - 是否涉及境外捐赠（需审批）
   - 是否涉及敏感领域（宗教、政治）

### 2.3 风险等级评估标准
| 风险等级 | 评估标准 | 处理建议 |
|----------|----------|----------|
| **高风险** | 条款明显违法/违规；可能造成重大损失；权利义务严重不对等 | 必须修改；提供替代条款；说明法律依据 |
| **中风险** | 条款存在不合理之处；可能引发争议；对己方有一定不利影响 | 建议修改；提供优化方案；提示潜在风险 |
| **低风险** | 条款表述模糊；行业惯例但有优化空间；对己方影响较小 | 提示关注；提供澄清建议；可不修改但需知晓 |

### 3.2 核心模块设计
#### **3.2.1 合同解析模块**
- **输入支持**：
  - DOCX文件 → 调用`minimax-docx`技能解析
  - PDF文件 → 调用`minimax-pdf`技能解析
  - 纯文本 → 直接处理
- **输出结构**：
  ```json
  {
    "metadata": {
      "合同类型": "捐赠协议",
      "签约方": ["捐赠方", "受赠方"],
      "签署日期": "2026-04-17",
      "合同金额": "100000元"
    },
    "sections": [
      {
        "title": "第一条 捐赠事项",
        "content": "捐赠方向受赠方捐赠人民币壹拾万元整...",
        "line_number": 1-5
      }
    ]
  }
  ```

#### **3.2.2 风险识别引擎**
The risk identification engine will be based on a rules-based approach with keyword matching and contextual analysis.

**Risk Rule Structure**:
```json
{
  "risk_id": "R001",
  "category": "责任限制",
  "name": "无限责任条款",
  "description": "合同约定一方承担无限责任",
  "keywords": ["无限责任", "全部损失", "一切后果", "连带责任"],
  "context_triggers": ["承担", "负责", "赔偿"],
  "risk_level": "high",
  "applicable_contract_types": ["服务合同", "合作协议"],
  "legal_basis": "《民法典》第五百八十四条：违约赔偿不得超过可预见的损失",
  "suggestion": "建议增加责任上限条款，如：'任何一方在本合同项下的累计责任不应超过本合同总金额的两倍。'"
}
```

#### **3.2.3 建议生成引擎**
对于每个风险点，提供三个层级的建议：
1. **必须修改**（高风险）：提供完整替代条款
2. **建议优化**（中风险）：提供修改方案
3. **提示澄清**（低风险）：提供澄清建议

### 3.3 数据设计
#### **3.3.1 风险规则库**
```json
{
  "rules": [
    {
      "risk_id": "R001",
      "category": "责任限制",
      "name": "无限责任条款",
      "keywords": ["无限责任", "全部损失", "一切后果"],
      "risk_level": "high",
      "suggestion[[_template|_template]]": "建议增加责任上限：'任何一方在本合同项下的累计责任不应超过本合同总金额的[X]倍。'"
    }
  ]
}
```

#### **3.3.2 最佳实践库**
- 标准条款库（捐赠协议、服务合同、保密协议等）
- 行业标准（慈善组织、制造业、服务业等）
- 法院支持条款（基于判例收集）

### 3.4 集成设计
#### **3.4.1 与现有技能集成**
| 关联技能 | 集成方式 | 用途 |
|----------|----------|------|
| `minimax-docx` | 解析DOCX文件 | 提取合同文本和结构 |
| `minimax-pdf` | 解析PDF文件 | 提取PDF格式合同内容 |
| `腾讯ima` | 知识库同步 | 保存审查案例，积累经验 |
| `腾讯文档` | 导出报告 | 生成可协作的审查报告 |

#### **3.4.2 与WorkBuddy生态集成**
- **作为独立技能**：可通过`use_skill`调用
- **支持自动化任务**：可配置定时批量审查
- **多智能体协同**：未来可与“模拟法庭智能体”联动

## 四、技术实现路径

### 4.1 开发策略（分阶段）
**第一阶段（MVP - 2-3天）**：
1. ✅ 需求分析与设计（本文档）
2. 🔄 技能框架搭建（SKILL.md + 基础脚本）
3. 🔄 风险规则库（捐赠协议、服务合同各5-10条核心规则）
4. 🔄 基础解析与匹配功能

**第二阶段（功能完善 - 3-5天）**：
1. 扩展合同类型支持（保密协议、借贷合同）
2. 增强风险识别准确率（上下文分析）
3. 完善报告输出格式（HTML/Markdown/PDF）
4. 集成iMA知识库同步

**第三阶段（优化扩展 - 持续）**：
1. 机器学习辅助（NLP模型训练）
2. 行业特定规则库（慈善组织、医疗、教育等）
3. 多语言支持（英文合同审查）
4. API接口开放（供其他智能体调用）

### 4.2 关键技术选型
- **解析引擎**：重用`minimax-docx`、`minimax-pdf`（避免重复造轮子）
- **规则引擎**：Python-based，支持JSON规则配置
- **文本处理**：正则表达式 + 简单NLP（后续可集成Spacy）
- **输出格式**：Markdown为主，支持转换为DOCX/PDF
- **存储方案**：本地JSON文件（初期），后期可接数据库

## 五、成功标准与验收指标

### 5.1 功能验收标准
| 指标 | 目标值 | 测量方法 |
|------|--------|----------|
| 合同解析准确率 | ≥95% | 对比人工标注与系统解析结果 |
| 风险识别召回率 | ≥85% | 已知风险条款的识别比例 |
| 风险识别精确率 | ≥80% | 识别为风险的条款中实际为风险的比例 |
| 报告生成时间 | ≤15分钟/10页 | 系统计时 |
| 用户满意度 | ≥4.5/5分 | 用户问卷评分 |

### 5.2 业务价值指标
1. **效率提升**：合同审查时间减少50%以上
2. **风险降低**：高风险条款遗漏率降低80%
3. **知识沉淀**：每月新增10+个审查案例到知识库
4. **质量统一**：审查标准统一，降低个人经验差异

## 六、风险与应对

### 6.1 技术风险
| 风险项 | 可能性 | 影响 | 应对措施 |
|--------|--------|------|----------|
| 合同解析失败 | 中 | 高 | 提供文本输入备选方案；加强错误处理 |
| 风险误报率高 | 高 | 中 | 完善规则库；增加人工确认环节 |
| 性能问题 | 低 | 中 | 分批处理大文件；优化算法复杂度 |

### 6.2 业务风险
| 风险项 | 可能性 | 影响 | 应对措施 |
|--------|--------|------|----------|
| 法律依据过时 | 中 | 高 | 定期更新规则库；提示“仅供参考，最终以最新法规为准” |
| 特殊条款无法识别 | 高 | 中 | 支持人工标注并反馈学习；提供“专家复核”建议 |
