## 三、为什么没启用（诚实判断）

不是"忘了建"，而是**当前工作流用不到它**：

- 现有案件管理走的是 `小强律师数字分身系统/案件库/` 与 `案件生命周期管理系统/`，
  以**案件**为主键组织；`客户档案` 以**客户**为主键组织，是另一套维度。
- 老强目前是实习律师阶段，客户数量少、且多为一次性委托，
  **按客户维度聚合的边际收益 < 维护成本**，所以一直空着是对的。
- 强行往里填，会造出"同一份信息在案件库和客户档案各存一份"的**双真源**，
  反而比空着更糟。

## 四、什么情况下该激活（触发条件）

满足**任一**即可考虑启用，而不是"有空就填"：

1. **出现回头客**：同一客户委托第 2 件以上案件 → 需要跨案聚合视图；
2. **机构客户 ≥ 3 家**（厚德基金会、航合物流、至善公司等陆续进入常年顾问）→
   需要按机构归档沟通与合规节点；
3. **要做客户满意度/回访机制** → 需要"沟通记录"作为落地载体；
4. **开始做客户开发/案源管理** → 需要客户基本信息作为线索池。

## 五、激活时的落地契约（先定规则，再填数据）

激活那天，按下面四条执行，避免又变成双真源：

1. **单一真源**：客户主体的**唯一权威记录**只放这里；
   `案件库` 里只存 `客户ID` 指针，不重复存客户信息。
2. **命名规范**：`客户基本信息/<客户全称或姓名>.md`；
   机构用工商登记全称，自然人用"姓名（+身份证后4位）"防重名。
3. **必填 frontmatter**：`client_id` / `client_type`（自然人|机构）/ `created` / `updated` / `tags`。
4. **索引驱动**：本文件改写为活索引（客户清单表 + 状态），由自动化随写随更新，
   不再只挂一个 `status: not_activated`。
