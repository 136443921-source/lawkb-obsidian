# 把律师数字分身系统，当成一辆电车来造和驾驶

## 律师数字分身系统（单机密文版 · 形态 A）· EV 架构白皮书（对外版）v1.0

> **一句话结论**：法律 AI 真正的瓶颈，从来不是模型不够聪明，而是律师的知识资产**没有能量闭环**——只进不出、召不回来、失控无拦截、人被甩在环外。我们用一套"造车 + 开车"的工程语言，重建了一个可**私有化部署**的律师个人知识系统：**六大总成、四条公理、一条不可越界的 L3 边界，以及一个把"造"和"开"分开讲的交付包。**

---

## 摘要

**问题。** 过去三年，法律科技几乎把全部注意力押在"模型多聪明"上。但一个一线律师的真实困境是这样的：办过的案子沉淀不下来，写过的文书下次还得重写，检索到的法条不敢直接引用，AI 生成的东西看着漂亮却不敢署名送出。知识不是不够多，是**不成系统**——它是一堆零件，不是一台车。更麻烦的是：哪怕造出了一台好车，绝大多数人**不知道怎么安全地开它**。

**方法。** 我们放弃"图书馆"和"大脑"这两个惯用隐喻，改用**智能电动车（EV）**作为一级隐喻——因为它逼你回答四个问题：能量从哪来、存在哪、怎么放出去、失控了怎么办，以及最关键的：**谁坐在方向盘后面**。本版在原有六模块架构之上，把白皮书拆成两半：**上半场讲"造"**（怎么把这套系统私有化部署到一台只属于你、数据不出本机的车里），**下半场讲"驾驶"**（日常怎么保养、怎么在律师—助理之间协同、怎么跨电脑安全交接、怎么随时知道车还健不健康）。

**结果。** 一套由个人可维护、L3 级定位、且**本机加密 + 推理可插拔**的知识系统，六大总成全部落地并实测运转：知识资产 3,000+ 篇文档、800+ 条裁判规则卡片、质检门禁回归 131/131 全通过、资产断链率 0.111%、10 项自动化 OTA 常驻；并在单机密文版形态下补完了门禁独立进程化（G2）、本地检索（G3）、推理流式与计费（G4）三项关键能力。它不生产判决，它生产**可交付的确定性**。

**边界。** 它是 L3，不是 L5；它是**单机密文版**，不是公有云。独立法律判断、庭审临场应变、对客户的最终担责、把数据送出本机——这四项是本系统**明确声明不做、且结构上无法代劳**的部分。这不是谦虚，是设计。

## 第一章 为什么是"电车"：三种隐喻的取舍

选一个隐喻，就是选一套工程约束。你用什么比喻你的知识系统，决定了你会问什么问题、忽略什么风险。

| 隐喻 | 它解决的问题 | 它带来的盲区 | 典型失败形态 |
| --- | --- | --- | --- |
| **图书馆** | 分类、编目、检索 | 只解决"存"，不解决"流"与"用" | 电子垃圾场：收藏 thousands 篇，办案时一篇想不起来 |
| **大脑 / 智能体** | 推理、涌现、拟人 | 黑箱、不可审计、出事无法定责 | 幻觉体：输出流畅自信，引用全是编的，且无法追责 |
| **电车（本系统）** | 能量闭环、可控、可保养、人在环上 | 需要持续运维，不会自己开 | 保养得当则复利，疏于养护则趴窝（可预期、可诊断） |

**关键判断：法律行业不能接受黑箱，也不能接受仓库。**

- 黑箱的问题不在于它错，而在于**错了你不知道错在哪、没法向法庭和客户解释**。一份被 AI 编造案号污染过的代理词，代价不是重写，是职业信誉。
- 仓库的问题在于**知识没有势能**。存了等于没存，因为从"存"到"用"之间缺一套能量转换装置。

电车隐喻的强悍之处在于，它天然包含四件事：

1. **能量必须闭环**——充进去的电要能放出来，还得能回收（动能回收）。
2. **失控必须有硬拦截**——BMS（电池管理系统）的存在不是为了提速，是为了防止热失控。它的权限高于续航。
3. **级别必须诚实**——L3 就是 L3。宣称 L5 的系统，出事时责任边界是模糊的。
4. **可保养、可诊断**——故障码、保养周期、铭牌参数，全部可量化可核验。

> **本节金句**：选隐喻不是文案工作，是架构决策。你用"大脑"形容它，就会去卷推理；你用"电车"形容它，就会去建 BMS、装黑匣子、写保养手册——而后者才是律师真正需要的东西。本版再加一条：**你用"造车"形容它，就会去想它该停在谁的车库里、钥匙在谁手上。**

## 第二章 四条公理

整套系统由四条不可协商的公理约束。任何新模块、新自动化、新部署形态上线前，先过这四条。

### 公理一 · 能量必须闭环

知识资产若只进不出，电池就会"鼓包"——体量增长，可用度下降。

因此系统强制三条回流路径：每次红蓝对抗复核 → 沉淀为经验卡；每次质检拦截 → 登记为事故并反哺规则；每个案件结案 → 回填决策日志。判据很简单：**月回流卡数 > 0 即视为闭环正常，= 0 即视为系统停摆。**

### 公理二 · 失控优先于续航

在所有性能冲突中，**安全拦截一票否决**。

本系统的质检门禁（LTI）具备对交付物的一票否决权：REJECT 计数不为 0，即不准交付。宁可不交，不可错交。这条公理在商业上很反直觉——它直接牺牲交付速度——但在法律行业，它是唯一正确的排序。**律师卖的不是字数，是署名。**

### 公理三 · L3 不是 L5

系统明确定位为 **L3 执业助理级**：辅助驾驶，方向盘后必须有人。

它产出的是"经质检的草案 + 推演"，不是"结论"。拍板、出庭、对客户担责，永远归人类律师。这条公理不是免责声明，而是**能力边界的诚实标注**——一个不声明自己边界的系统，本质上是在转嫁风险给使用者。

### 公理四 · 可扫描优先于可描述

系统里所有指标分两类，且**严格区分标注**：

| 类型 | 获取方式 | 例子 |
| --- | --- | --- |
| **实时扫描值** | 脚本定时遍历真实文件系统统计，刷新即变 | 文档数、卡片数、规则库文件数、断链率 |
| **人工核验值** | 需人工实地核验后写入，脚本不得伪造 | 连接器连通性、质检回归结果、成熟度定级 |

**铁律：能扫描绝不写死，扫不出就标注"人工核验"，绝不假装知道。**

这条公理带来一个反常识的界面设计：驾驶舱上同时显示**铭牌值与实测值**，两者不一致时**不覆盖、不取舍，而是把口径差异摊开显示**。因为口径差异本身就是最重要的一类信息——它告诉你系统哪里在自欺。

## 第三章 六大总成总览

整车由六大总成构成，对应一条完整的能量链路：

```
  充能  →  存能  →  用能  →  交互  →  自检  →  进化
 (充电桩) (三电)  (召回/推演) (座舱) (健康度) (黑匣子+OTA)
```

| # | 总成 | 车辆对应 | 系统实现 | 核心命题 |
| --- | --- | --- | --- | --- |
| 一 | 🔋 **三电系统** | 电池 / 电机 / 电控 / 动能回收 | 知识飞轮 + SR 召回引擎 + 质检门禁（G2 独立进程）+ 经验沉淀 | 能量的存、放、控、收 |
| 二 | 🔌 **补能网络** | 充电桩 | 权威法律数据源连接器集群（含离线快照降级） | 能量从哪来、断了怎么办 |
| 三 | 🧠 **智驾系统** | 域控芯片 + 激光雷达 | 决策思维系统 + 跨案模式识别 + 推理层 M1（流式/计费 G4） | 谁在判断、凭什么判断 |
| 四 | 🖥️ **座舱与影子模式** | 车机 + 数字孪生演练 | 人格配置 + 模拟法庭红蓝对抗 + 助理协同分域 + 跨机交接 | 人机界面与碰撞预演 |
| 五 | 📊 **健康度自检** | 仪表盘 + 故障码 + 保养表 | 指标体系 + DTC 故障码 + 9655 运维驾驶舱 | 怎么知道车还健康 |
| 六 | 📦 **黑匣子与 OTA** | EDR 行车记录 + 远程升级 | 决策日志 + 自动化编排 + 私有化部署手册（溯源主区） | 留痕定责与持续进化 |

> **设计说明**：六大总成不是六个软件模块，而是**六个工程问题的答案**。每一总成都自带"失效长什么样"的定义——这是电车隐喻区别于一般架构图的地方：架构图只画成功路径，电车手册必须写故障码。

## 第四章 模块一 · 🔋 三电系统：能量的存、放、控、收

> **这一模块回答：知识怎么存下来、怎么调出来、怎么保证它不出错、怎么越用越多。**

### 1.1 动力电池包 = 知识飞轮

**车上是什么**：整车能量的唯一来源。容量决定续航，健康度决定寿命。

**系统里是什么**：分层组织的法律知识资产库。当前实测基线（沿用已验证系统）：

| 指标 | 实测值 |
| --- | --- |
| 知识文档总量 | 3,000+ 篇（六层结构） |
| 经验卡 | 205 张 |
| 裁判规则库 | 816 个文件 / 785 张规范命名卡 / 26 个子库 |
| 已归档案件 | 15 宗 |

**它解决的真问题**：律师的知识库最大的敌人不是"没存"，而是**存的都是不能直接用的原料**。一篇裁判文书原文，和一条"可被引用的裁判规则"，是两种东西。飞轮的价值不在于装了多少，而在于**完成了从原料到规则的炼制**。

**单机密文版新增项**：电池包（L2 数据层）**在本机 AES-256 加密**，密钥存 macOS 钥匙串，**绝不离开律师电脑**。私有化部署的本质不是"把模型搬到本地"，而是把 L1 人格层与 L2 数据层锁死在本机、把推理层做成可插拔。

**失效模式**：容量虚胖。文档数增长而规则卡不增长 = 电池鼓包，需要触发资产审计而非继续采集。

**红线**：**严禁凭记忆灌入法条正文。** 实测数据显示，凭记忆引述法条的错引率约 22%，在特定部门法领域高达 75%。一条记错的法条混进知识库，会像坏电芯一样污染整包——而且极难反向定位。

### 1.2 驱动电机 = 规则召回引擎

**车上是什么**：把电池里的电转成车轮的驱动力。

**系统里是什么**：新案件进来时，从规则库中语义匹配相关规则卡并输出建议的召回层。单机密文版下，召回引擎为**本地检索 M2（G3）**：`sqlite-vec` 向量索引 + `FTS5 trigram` 中文全文混合检索（RRF 融合），离线哈希嵌入（可插拔真 SBERT），**断网也能检索**。

**它解决的真问题**：知识库"存了但想不起来"的本质，是**从存储到调用之间没有马达**。召回引擎就是这台马达——它把静态资产转成办案时的即时驱动力。

### 1.3 电控 + BMS = 质检门禁（LTI，G2 独立进程化）

**车上是什么**：电池管理系统。防过充、过放、热失控。它的存在不是为了跑得快，是为了**不起火**。

**系统里是什么**：文本质检监控器。五维校验（法条真实性 / 法理逻辑 / 一致性 / 可溯源 / 程序合规）+ 案例存在性核验。当前实测：**回归测试 131/131 全通过，六维逻辑门禁生效**。

**单机密文版新增项（G2）**：门禁不再依赖 WorkBuddy 运行时，而是**剥离为独立常驻守护进程**（Unix socket 封装既有成熟 `lti_gate.py`，零修改；配 `launchd` plist 保活）。意义在于——哪怕推理层、座舱都停了，门禁这道 BMS 仍然在岗，**REJECT ≠ 0 永远不许出门**。

**设计决策**：质检门禁**常驻在交付路径上，不可跳过**。系统甚至规定：被质检拦截**不算故障，是安全机制生效**——因此故障码体系里，质检拦截码**永不点亮**。

**降级哲学**：当外部核验接口不可用时，系统不是停工等待，而是**降级到替代核验路径 + 官方渠道交叉印证，同时明确标注降级状态**。不中断流程，但绝不假装没降级。

### 1.4 动能回收系统 = 经验沉淀（HIR）

**车上是什么**：把刹车时的动能回收进电池。刹车不再是纯损耗，而是充电。

**系统里是什么**：把每一次对抗、拦截、事故，回流成新的经验卡与规则。当前实测：**36 份沉淀调用记录**。

**它解决的真问题**：大多数知识系统会在两年后失去价值，因为它们只有"采集"没有"回收"。动能回收让**犯错变成资产**——被质检拦下一次，系统就多一条以后不再犯的规则。

**这是整套系统复利效应的来源**：开得越多，电量越多；犯的错越多，下次越少犯错。

## 第五章 模块二 · 🔌 补能网络：能量从哪来

> **这一模块回答：权威数据从哪进系统，断供时如何优雅降级。**

**车上是什么**：充电桩。车再好，桩断了就是废铁。

**系统里是什么**：外部权威法律数据源的连接器集群——法条核验、判例检索、机构业务数据、知识库摄入、报告投递。

**当前状态**：6 个桩位全部实测连通（6/6 达标）。

**单机密文版关键设计 · 离线降级**：单机密文版默认面向"数据不出本机"场景，因此补能网络内置**本地法规库快照**兜底——断网时返回 `statute_text_pending`（待回源核填）而非编造条文。**宁可标 pending，也绝不让模型凭记忆编法条。** 这是红线。

**它解决的真问题**：律师最怕的不是"AI 说得不对"，是**"AI 说得像对，但你没法验证"**。补能网络的本质不是接入更多数据，而是**接入可被追责的权威源**。

**设计权衡：多源而非单源，且允许此消彼长。** 系统同时接入多个权威源，并保持"法条源"与"案例源"的分离冗余。

**关键设计：不代点原则。** 部分连接器的重连需要人工授权操作。系统**明确不代为执行**，只负责诊断与提示。这条看似"不够智能"的规则，实则是把控制权留在人手里：**自动化可以做一切，除了替人类做授权决策。**

## 第六章 模块三 · 🧠 智驾系统：谁在判断

> **这一模块回答：系统靠什么形成判断，以及它如何越来越像它的主人。**

### 6.1 智驾域控芯片 = 决策思维系统

**车上是什么**：融合感知、规划、决策的核心算力单元。

**系统里是什么**：决策捕获 + 思维蒸馏 + 决策日志 + 核心权重文件（HOW-I-THINK）。

**它解决的真问题**：绝大多数 AI 助手"不像你"，是因为它只学了你的**输出**，没学你的**取舍**。决策卡强制三行结构——**考虑了哪些选项 / 为什么排除其他 / 什么信号会推翻它**——记录的是推理过程而非结论。

**架构选择**：存结论，系统只能模仿你的答案；**存推理，系统才能模仿你的判断**。

### 6.2 激光雷达 / 环境感知 = 跨案模式识别 + 推理层 M1（G4 流式/计费）

**车上是什么**：看见路况的眼睛，以及决定踩多深的电门。

**系统里是什么**：识别跨案件相似模式、预警同类风险的模块；以及可插拔的推理适配层 M1——已交付**流式输出（stream）与成本记账（CostLedger）**，让每一次推理可观测、可计量、可降级。

**它解决的真问题**：律师的经验优势，很大程度体现在"这个案子我见过类似的"。模式识别模块把它变成**新案接入时的强制第一步**。而 M1 的流式和计费，则让"开车"有了油表——你随时知道这脚电门花了多少、该不该收。

**设计决策**：固化进接案 SOP 第一环——新案接入、庭审准备、文书起草前主动调用。

## 第七章 模块四 · 🖥️ 座舱与影子模式：人机界面与碰撞预演

> **这一模块回答：人怎么跟系统相处，系统怎么在"真上路"前先撞一次，以及律师和助理怎么同车。**

### 7.1 智能座舱 = 人格配置

**车上是什么**：方向盘、仪表、语音交互——定义"这辆车怎么跟你说话"。

**系统里是什么**：分身的人格配置文件，定义"我是谁 / 什么风格 / 边界在哪"。单机密文版下，人格层（L1）同样**本机 AES-256 加密**，密钥存钥匙串。

**它解决的真问题**：通用 AI 的输出风格是平均值，是"谁都不像的律师"。人格配置把执业者的**专业背景、复合视角、论证框架**固化进系统，让输出带上个人印记。

### 7.2 影子模式 / 碰撞预演 = 模拟法庭

**车上是什么**：真上路前，先在数字孪生里跑一遍，看会不会撞。

**系统里是什么**：红蓝对抗庭审推演——一支队伍构建论证，另一支队伍专职攻击它。

**设计精髓：攻击方不是评委，是敌人。** 蓝队负责把论证建到最完整，红队负责用最残酷的方式找漏洞。这不是"复核"，是**预驳回攻击**——假定自己会被驳回，倒推哪里会先崩。

### 7.3 同车协议 = 律师—助理协同（单机密文版新增）

**车上是什么**：一辆车，司机只有一个，但副驾可以帮看导航、帮加油、帮记录。

**系统里是什么**：单机密文版本质 = 单所有者 + 单机 + L1/L2 本机加密 + 本地门禁；协同做成**「律师独占加密内核 + 角色分域监督式覆盖层」**——助理/实习只在律师授权、可审计的边界内贡献（数据共享 + 工作量追踪台账）。真多租户/RBAC 属律所内网版范围，本形态不做。

**跨机交接（单机密文版新增）**：助理在自己电脑跑完的文件，用 `handoff.sh` 以**角色密钥端到端加密**打包，传输通道（USB/微信/邮件/微云）无需保密；律师收到后解密进待审区 + 跑门禁 + 记台账。信任边界 =（加密交接文件）+（律师单机）。

## 第八章 模块五 · 📊 健康度自检：怎么知道车还健康

> **这一模块回答：系统现在还好吗，以及它坏的时候会怎么告诉你。**

### 8.1 仪表的诚实边界

系统公开区分两类指标，并且**明确承认其中一类的局限**：

> **体量指标 ≠ 质量指标。** 健康度仪表盘显示的是"你有多少资产"，不是"这些资产有多好用"。质量要看召回命中率、质检回归通过率、思维文件填充度。

**这种自我限定的声明，是整套系统最值得被复制的设计之一。** 一个只报告好消息的仪表盘，比没有仪表盘更危险。

### 8.2 故障码（DTC）体系

借鉴汽车 OBD 标准，为每类失效定义唯一故障码（见附录 A）。

**关键设计：故障码只定义"含义"，不写死"当前是否触发"。** 是否点亮由实时状态判定。手册新增但尚未映射的故障码，一律标注"未判定"，**不假装正常**。

### 8.3 9655 运维驾驶舱（单机密文版新增）

单机密文版配有一块**实扫运维驾驶舱（9655）**：门户聚合多屏——版本锁回填、架构健康度、安全合规度、门禁运行度、缺口闭环度。数据走实源：扫本地知识目录 + 解析总体方案版本锁 + 探门禁进程，**不靠记忆、不编指标**。

**它解决的真问题**：律师没空每天手敲诊断命令。驾驶舱把"车还健不健康"变成一眼可见的仪表，并把"门禁是否在岗"这种最容易虚报的状态，做成**真实探活**而非 socket 文件残留判断。

### 8.4 保养周期

| 周期 | 保养项 |
| --- | --- |
| **每日** | 查收摄入报告；出文必过质检门禁；连接器健康守卫；看一眼 9655 驾驶舱 |
| **每案** | 入案先跨案识别 → 出文红蓝对抗 + 质检 + 门禁 → 结案经验回填 → 决策卡建档 |
| **每周** | 自检改进 + 链接刷新；周报复盘 |
| **每月** | 知识复利报告 + 案件蒸馏 + 规则对账 + 决策月报 + 连接器保活巡检 |
| **每季/年** | 资产断链审计（门禁 0.5%）；案件库双轨索引校准；外部接口可用性复盘 |

## 第九章 模块六 · 📦 黑匣子与 OTA：留痕与进化

> **这一模块回答：出事怎么定责，以及系统怎么在不拆车的情况下变强。**

### 9.1 黑匣子 / EDR = 决策日志

**车上是什么**：全程记录行车数据，事故后可回溯定责。

**系统里是什么**：决策日志 + 系统运行日志。

**它解决的真问题**：法律行业的每一次输出都可能被追溯。当客户或法庭问"这个结论是怎么来的"，你需要的不只是答案，是**推理链的存档**。黑匣子让系统的每个判断都可回放。

### 9.2 车规纪律 = 行为规则文件（六-B 铁律）

**车上是什么**：车规级强制标准。

**系统里是什么**：AI 行为规则文件，规定所有自动化必须"真跑 + 留痕"，**禁止摆设式自动化**。

**核心条款（六-B 铁律）**：所有写入型自动化必须包含——**先排查 / 确认非误报 / 再批量修改 / 含安全扫描 + 预演（dry-run）+ 备份**。这条铁律源自一次真实教训：自动化脚本在无人确认下批量改写知识资产，代价是长时间回滚。**它后来被扩展到全部写入型自动化，无例外。**

### 9.3 OTA 远程升级 = 自动化编排 + 私有化部署手册

系统常驻 10 项自动化任务，覆盖每日摄入 / 每 4 小时仪表刷新 / 每周自检 / 每月复利报告 / 常驻安全校验。

**单机密文版新增 · 溯源主区**：本形态的每一次部署决策、流程变更、版本升级、门禁调整、踩坑修复，统一归集进**《05-私有化部署手册（单机密文版·活文档）》的 §5 决策日志**——带「日期 / 摘要 / 依据 / 影响文件 / 操作人」五字段，刷新文首 `updated`。这是单机密文版**唯一的决策溯源主区**，相当于车辆的"出厂改装档案"。

| 阶段 | 点火的总成 | 发生的动作 |
| --- | --- | --- |
| **① 接案** | 感知雷达 + 充电桩 | 跨案模式识别先扫历史相似案件；同步核验外部权威源连通性 |

## 第十一章 边界：这辆车不做什么

**一份不写边界的架构白皮书，本质上是广告。**

以下是本系统**明确声明不做、且在结构上无法代劳**的事项：

| 不可越界项 | 为什么不能交出去 |
| --- | --- |
| **独立法律判断** | 判断意味着价值权衡与后果承担，两者都需要主体资格 |
| **庭审临场应变** | 法庭是高压实时博弈，容错窗口以秒计，且错误不可逆 |
| **对客户最终担责** | 责任的对称性：签字的人必须是能负责的人 |
| **代替人工授权操作** | 授权行为具有法律意义，自动化不得代为行使 |
| **绕过质检门禁交付** | 速度永远不优先于署名信誉 |
| **把 L1/L2 数据送出本机** | 单机密文版的核心承诺：人格层与数据层永不外传、绝不云同步 |

> **关于"天花板"的态度**：这六项不是"当前做不到，以后努力"，而是**设计上就不应该做到**。把 L3 的系统宣传成 L5，受益的是营销，受损的是使用者与他的客户。

**这带来一个反直觉的竞争力判断**：在法律行业，**诚实声明边界，本身就是一种专业能力**。因为客户真正购买的，从来不是"AI 能做什么"，而是"有人清楚地知道 AI 不能做什么，并且为此建了闸门"。

## 第十二章 可复制性：最小起步路径

这套系统由一名实习律师个人搭建并维护，没有工程团队，没有专门预算。**它的可复制性高于它的复杂度。**

### 三档起步建议（单机密文版视角）

| 档位 | 适用对象 | 起步动作（按优先级） |
| --- | --- | --- |
| **档一 · 单车（私有部署）** | 独立执业律师 | ① 先建质检门禁（哪怕只有几条规则）→ ② 建经验卡（每案一张）→ ③ 接一个权威法源 → ④ 把人格层与数据层本机加密 |
| **档二 · 副驾（协同）** | 律师 + 助理/实习 | ① 统一规则库编号规范 → ② 红蓝对抗制度化（出文必过）→ ③ 结案强制回填 → ④ 用跨机交接做助理贡献回流 |
| **档三 · 车队（内网）** | 机构 / 大所 | ① 决策日志与复盘模板 → ② 自动化保养编排 → ③ 断链率与召回率纳入考核（注：真多租户属律所内网版，非本形态范围） |

### 三条踩过的坑

1. **不要先建库，先建闸门。** 没有质检的知识库，规模越大风险越高。我们最初的投入顺序是错的，返工代价很高。
2. **不要让采集快于炼制。** 采集是线性成本，炼制是能力壁垒。只采不炼，两年后你会得到一个 3,000 篇的电子垃圾场。
3. **不要让自动化脱离"真跑 + 留痕"。** 一个你不检查它是否真的执行了的自动化，比没有自动化更危险——**它会让你误以为事情已经做了。**

### 一句话运维口诀

> **三电保健康（飞轮充能 / 质检防冒烟 / 经验回收），充电桩别断（权威源优先重连），智驾勤标定（决策卡累积 + 月报），出门必过机检（REJECT = 0），方向盘后必须有人。**

## 第十三章 怎么"造"这辆车（私有化部署路径 · 单机密文版）

> **这一章是上一版白皮书没有的——专门讲"造"。** 单机密文版的交付物是一台**只停在你自己车库、钥匙只在你手里**的车。

### 13.1 四层架构（造车的底盘）

| 层 | 内容 | 部署位置 | 能否出网 |
| --- | --- | --- | --- |
| **推理层 M1** | 大模型 API / 本地 Ollama | 客户自选（API 或本机 GPU） | 可外联（可关闭，默认 airgap 友好） |
| **L0 内核层** | 骨架、协议、门禁规则 | 本机 | 否 |
| **L1 人格层** | 律师画像实例、self.md | 本机 + **AES-256 加密** | **绝否** |
| **L2 数据层** | 知识库、案卷、法规库、检索索引 | 本机 + **加密归档** | **绝否** |

### 13.2 造车的五道工序

1. **实例化空目录**：用 `bootstrap.sh --apply` 生成 README + 方案 + 启动包（活文档格式，一步一操作）。
2. **L1/L2 加密封装**：`crypto-l1.sh` 把人格层与数据层打成 `.L1.tar.gz.enc`，密钥存钥匙串，**不在对话/日志打印明文**。
3. **门禁独立常驻（G2）**：Unix socket 守护进程 + `launchd` plist 保活，门禁跨会话不死。
4. **本地检索落地（G3）**：`m2_secure.sh` 建多源语料索引 → 加密归档（检索+密文闭环）。
5. **推理可观测（G4）**：M1 流式输出 + 成本记账，出文前能看到"这脚电门花了多少"。

### 13.3 出厂改装档案（溯源）

每一次"造车"改动都记入《05-私有化部署手册（单机密文版·活文档）》§5 决策日志。相当于这辆车的**改装履历**——哪天加了什么、为什么加、动了哪些文件，翻一眼就溯源清楚。

## 第十四章 怎么"驾驶"与运营这辆车（日常上路 + 系统运营 · 单机密文版）

> 车造好不等于能开好，能开好不等于会运营。单机密文版的"驾驶"与"运营"是一件事的两面：**驾驶是每天怎么上路办案，运营是让这台车长期、稳定、可审计地替你跑。** 这一章讲前者与后者的日常面。

### 14.1 上车第一件事：看仪表（9655 运维驾驶舱）

每天开工先扫一眼 9655 驾驶舱，重点看四块表：

| 仪表 | 看什么 | 异常信号 |
| --- | --- | --- |
| 版本锁回填 | 目标实装版本是否 100% 无空项 | 出现空项 = 跨所复制必错配 |
| 门禁运行度 | 门禁守护进程是否**真实在岗**（探活非 socket 残留） | 守护跨会话死亡 → 清死 sock 重启 |
| 安全合规度 | 数据不出本机 / AIGC 标识等红线旗 | 出现"需人工确认"旗 → 不忽略 |
| 缺口闭环度 | G2/G3/G4 等构建产物是否被扫描探到 | 扫描盲区 ≠ 真实缺口，以部署记录为准 |

仪表数据全部实扫，**不靠记忆、不编指标**；铭牌值与实测值不一致时摊开显示，不覆盖、不取舍。

### 14.2 出门铁律：守闸门（REJECT = 0 才放行）

任何对外文书，**REJECT = 0 才准出车库**。质检门禁（BMS）是独立常驻守护进程，哪怕推理层、座舱都停了它仍在岗。

- 被拦**不是故障，是安全机制生效**——回填权威源后重跑，严禁绕过。
- 养成"先机检、后署名"的肌肉记忆。**律师卖的不是字数，是署名。**

### 14.3 每天的"车载日课"：一个案子怎么开

把第十章的九步流转，落成每天的"上路"节奏：

1. **点火前**：跨案模式识别先扫历史相似案件；核验外部权威源连通性（桩没断吧？）。
2. **挂挡**：从权威源取回法条与判例原文（禁止凭记忆）；与本地规则库交叉比对。
3. **行驶中**：以执业者人格生成初稿；规则引擎召回相关裁判规则注入论证。
4. **预碰撞**：蓝队补全论证，红队预驳回攻击，多轮迭代。
5. **过闸**：五维校验 + 案例存在性核验，REJECT = 0。
6. **演练**：模拟庭审预演，暴露庭上突袭点。
7. **回库**：经验沉淀成卡；决策日志存档复盘模板。
8. **OTA**：月度蒸馏进核心权重文件；自动化持续刷新仪表。
9. **交接**（如需）：助理贡献经加密交接进待审区 + 门禁 + 台账。

任何一环失效，都会被下一环或仪表捕获——这就是"车"和"一堆工具"的区别。

### 14.4 运营系统：让车长期替你跑

单机密文版不是"装好就完"，而是**一套常驻的运营节奏**：

- **自动化 OTA 编排**：10 项常驻任务（每日摄入 / 每 4 小时仪表刷新 / 每周自检 / 每月复利报告 / 常驻安全校验）。运营的要点不是"有没有跑"，而是"**跑的结果对不对**"——运行时提示"连接器断开/能力降级"，那是授权未绑定，不是 OTA 故障，分开报能省大量无效排障。
- **改装档案（溯源主区）**：每一次部署决策、流程变更、版本升级、踩坑修复，统一记进《05-私有化部署手册》§5 决策日志，带「日期/摘要/依据/影响文件/操作人」五字段。运营者每月翻一次，就知道这辆车改过什么、为什么改。
- **版本锁回填纪律**：版本锁"目标所实装版本"列**不得留空交付**——没有版本号的清单等于没锁，日后跨所复制必错配。
- **周/月节奏**：周报复盘 + 链接刷新；月做知识复利报告 + 案件蒸馏 + 规则对账 + 决策月报 + 连接器保活巡检。

### 14.5 管好同车人：助理协同与跨机交接（运营视角）

- **日常协同边界**：助理在律师授权、可审计的边界内贡献（数据共享 + 工作量台账）。真多租户/RBAC 属律所内网版，本形态不做。
- **跨机交接日常**：助理电脑跑完的文件，用 `handoff.sh` 角色密钥端到端加密打包，微信/邮件/U 盘随便传；律师收到解密进待审区 + 跑门禁 + 记台账。**传输通道不需要保密，解密边界在你单机。**
- **授权与审计**：所有助理操作留痕（台账 + 决策日志），律师随时可审计"谁在什么时候贡献了什么、过没过门禁"。

### 14.6 运营红线（每天都不能碰）

1. 不把 L1 人格层 / L2 数据层送出本机（单机密文版核心承诺）。
2. 不绕过质检门禁交付（速度永远不优先于署名信誉）。
3. 不代点 UI / 不代行人工授权（自动化可以做一切，除了替人类做授权决策）。
4. 不把密钥明文落盘或进对话/日志。

## 第十五章 保养与系统运维（让车十年不大修）

> 电车不怕开，怕的是"疏于养护"。单机密文版的运维，本质是把"造车时定下的铁律"变成"可周期性执行的保养动作"，并对每一次异常都有**标准处置预案**——而不是出事再救火。

### 15.1 保养周期表（落到人/自动化）

保养周期以**附录 B**为权威完整版。运营落地的关键是把每一格"责任方"坐实：

- **每日（自动化 + 律师确认）**：查收摄入报告；出文必过质检门禁（REJECT = 0）；连接器健康守卫；看 9655 驾驶舱。
- **每案（律师 + 系统）**：入案先跨案识别 → 出文红蓝对抗 + 质检 + 门禁 → 结案经验回填 → 决策卡建档。
- **每周（自动化）**：自检改进 + 链接刷新；周报复盘。
- **每月（自动化 + 律师）**：知识复利报告 + 案件蒸馏 + 规则对账；决策月报；连接器保活巡检；**版本锁回填复核**（空项即错配风险）。
- **每季/年（律师 + 系统）**：资产断链审计（门禁 ≤ 0.5%）；双轨索引校准；外部接口可用性复盘；密钥轮换建议。

### 15.2 备份与回滚（六-B 铁律 + cp 备份铁律）

所有写入型动作，先有备份/回滚机制，否则不许做：

- **六-B 铁律**：先排查 / 确认非误报 / 再批量修改 / 含安全扫描 + 预演（dry-run）+ 备份。扩展到全部写入型自动化，无例外。
- **cp 备份铁律**：单源文件重建前，先 `cp -n` 备份到时间戳目录（`/tmp/时间戳`），防覆盖。
- **回滚基线**：Phase 0 备份是任何写入的前置条件——没有基线，不许执行任何写入步骤。

### 15.3 密钥与加密资产巡检

单机密文版的安全锚点在密钥，巡检要周期做：

- 钥匙串里 `lawtwin-l1-<所>`、`lawtwin-handoff-<role>` 密钥是否存在、能否读取。
- 加密归档 `.L1.tar.gz.enc`（人格层 / 数据层 / 检索索引）是否**可解密验证**（round-trip：解密后与原明文 sha 一致）。
- 加密参数一致性：`-aes-256-cbc -pbkdf2 -iter 600000` 三参数与封装脚本一致。
- 演示/临时密钥用毕即吊销（如验证用的 `assistant` 角色密钥），真用须重新 `init-role`。

### 15.4 连接器保活与补能网络巡检

- 6/6 桩位连通性定期探活；某一源断开时，按"此消彼长、整体不中断"降级，并明确告知"性价比最高的恢复动作"。
- 断供时返回 `statute_text_pending`（待回源核填）而非编造——**宁可标 pending，绝不让模型凭记忆编法条**。
- 重连需人工授权，系统只诊断提示、**不代点**。

### 15.5 断链审计与容量审计（防电池鼓包）

- **断链率**：季度审计，门禁 ≤ 0.5%（当前实测 0.111%）。断链 = 链接失效的知识资产，是隐性负债。
- **容量审计（防鼓包）**：文档数增长而规则卡不增长 = 电池鼓包。触发资产审计（提炼/编号/交叉索引/断链校验），而非继续采集。**低摩擦的入库，必然带来高噪声的库容。**

### 15.6 版本锁与升级（OTA 纪律）

- 目标所实装版本**不得留空**；升级前先备份、再灰度、最后回归质检（REJECT = 0）。
- 升级记录进 §5 决策日志，标注"升级了什么 / 为什么 / 回滚路径"。
- 禁止无备份跨大版本直冲——先在小范围验证，再全量。

### 15.7 故障码处置演练（DTC 实战）

把附录 A 的故障码变成"肌肉记忆"，而非纸面清单：

| 故障码 | 现场处置 SOP |
| --- | --- |
| **DTC-GATE-DOWN** | 清死 sock → 按 plist 重启守护 → 发 `{"ping":true}` 验证 PONG → 重扫驾驶舱 |
| **DTC-HANDOFF-FAIL** | 核对加密三参数；确认收发双方角色密钥一致；必要时重新 `init-role` |
| **DTC-LTI-REJECT** | 正常安全机制；回填权威源后重跑；严禁绕过 |
| **DTC-KB-001 / CASE-002** | 人工重新授权连接器；改指多源避免单点硬依赖 |
| **DTC-DISTILL-003** | 持续累积决策卡；跑决策月报提升智驾标定 |

### 15.8 合规红线日常巡检

- 数据不出本机（L1/L2 永不外传、绝不云同步）。
- AIGC 标识：AI 生成草稿保留水印/元数据标识。
- 执业责任：AI 输出为辅助草稿，律师对最终成果独立负责。
- 备案边界：纯内网使用一般不触发备案；一旦对客户以外第三方开放，须走备案 + 安全评估。

### 15.9 年度大保养清单

每年一次"进厂大修"：

1. 全量资产断链审计（门禁 ≤ 0.5%）。
2. 案件库双轨双向索引校准（不合并双轨）。
3. 外部接口可用性复盘（哪些源已废、哪些需换）。
4. 密钥轮换建议（钥匙串密钥到期/泄露即轮换）。
5. 改装档案（§5 决策日志）年度回顾：哪些改动有效、哪些该回滚。

> **运维金句**：保养得当则复利，疏于养护则趴窝——而且电车的趴窝是**可预期、可诊断**的。把运维做成"周期动作 + 标准预案"，车就不会在你最需要时掉链子。

> 本表只定义故障码"含义"，**不写死当前是否触发**。是否点亮由实时状态判定；未被脚本映射的码标"未判定"，不假装正常。
