# 协同方案建议：实习律师 / 律师助理 如何接入单机密文版

> 范围声明：本建议仅基于「形态 A · 单机密文版」总体方案（个人律师 / 5–20 人小所、单机、L1/L2 本机加密、推理可插拔），不引用律所分身内容。

---

## 〇、一句话结论

单机密文版的本质是 **单所有者 + 单机 + L1/L2 本机加密 + 本地门禁**。实习律师/助理的协同**可以**在不突破该本质的前提下实现——做法是把协同做成「律师独占加密内核 + 角色分域监督式覆盖层」：**律师始终是人格层、知识层、门禁的唯一持有者，助理/实习只在律师授权、可审计的边界内贡献**。真正的多租户 / RBAC 并发协作不在单机密文版范畴（属形态 B 律所内网版，本空间不展开）。

---

## 一、前提：哪些能共享、哪些绝不能共享

| 类别 | 能否共享 | 说明 |
|---|---|---|
| ✅ 可共享 | 脱敏后的法规检索摘要、格式校对、日程整理、公开案例摘编、待审草稿 | 无涉密个人信息/当事人隐私 |
| ❌ 不可共享（密钥律师独占） | L1 人格层（self.md / profile）、L2 涉密案卷原文、门禁运行权 | LTI gate 仅律师跑；人格层 AES-256 加密、绝不出网 |
| 🔒 物理前提 | 单机不变 | 协同发生在同一台机器，或经加密交接文件，不把加密内核搬离律师机器 |

---

## 二、推荐架构：角色分域协同覆盖层（07-协同）

在现有 `01-方案 / 02-配置 / 03-人格层L1 / 04-知识层L2 / 05-门禁 / 06-部署记录` 之上，新增覆盖层，**不动内核**：

| 目录 | 作用 | 加密 |
|---|---|---|
| `07-协同/01-共享工作区/` | 已脱敏/非涉密任务区（检索素材、草稿、模板） | crypto-l1.sh 独立 role key |
| `07-协同/02-待审交付物/` | 助理/实习产出物落此，等待律师审阅 + 门禁 | crypto-l1.sh 独立 role key |
| `07-协同/03-工作台账/` | 工作量追踪（本地台账，见 §四） | crypto-l1.sh 加密归档 |
| `07-协同/04-角色密钥/` | 钥匙串条目（律师持全部，助理/实习仅持各自 role key） | 钥匙串管理 |

**所有权红线**：`03-人格层L1`、`04-知识层L2`（涉密部分）、`05-门禁` 保持律师独占，密钥不向助理/实习分发。

---

## 三、数据共享机制

1. **物理层**：同机文件系统分区（单机前提不变）。助理/实习在律师机器上操作，或仅经加密文件交接。
2. **密钥层**：共享区用独立 role key（如 `lawtwin-collab-assistant` / `lawtwin-collab-intern`），经 macOS 钥匙串管理；律师持有全部 key，助理/实习仅持各自 key。
3. **交接（handoff）流程**：
   - 助理产物 → `crypto-l1.sh` 加密入 `02-待审`；
   - 律师解密审阅 → 跑 `05-门禁` LTI 门禁审查；
   - 通过后进正式 `04-知识层L2`（用 `m2_secure.sh rebuild` 重新索引入密文闭环）。
4. **复用现有资产**：交接加密直接调 `启动包/crypto-l1.sh`；检索辅助调 `04-知识层L2/m2_secure.sh query`。

---

## 四、工作量追踪（Workload Tracking）

台账落 `07-协同/03-工作台账/worklog.md`（模板见同目录），纯本地、无外联，可随时用 `crypto-l1.sh` 加密归档（airgap 友好）。

| 字段 | 说明 |
|---|---|
| 日期 | 派发 / 完成日期 |
| 承办人(角色) | lawyer / assistant / intern |
| 事项 | 任务摘要 |
| 关联案号/项目 | 如 (2026)黔0330民初6658号 |
| 状态 | 进行中 / 待审 / 已完成 / 已驳回 |
| 耗时(h) | 承办人填报，律师复核 |
| 门禁结果 | PASS / REJECT（过 `05-门禁` 后回填） |
| 指纹 | 复用 `audit.py` 的 `prompt_fingerprint` 思路做事项去重，防重复记 |

**统计出口**：可在台账上做角色维度汇总（谁承接多少、待审积压多少、门禁驳回率），实现「工作量追踪」。

---

## 五、协同流程（Workflow）

1. **派发**：律师在台账建任务 + 共享区放脱敏素材。
2. **执行**：助理/实习在共享区工作，产物入 `02-待审`。
3. **审查**：律师跑 `m2_secure.sh query` 检索辅助 + `lti-gate` 门禁审查。
4. **归档**：通过门禁的成果进正式 L2，台账标记「已完成」；被驳回的回到「待审」。

---

## 六、风险与边界

- **角色 key 管理**：助理/实习离职必须轮换 key 并清空其 role 加密区（六-B 铁律：先备份再轮换）。
- **单机约束**：助理不应把加密内核拷到自有设备；如需远程，只能经加密交接文件，且明文不落对方机器。
- **边界声明**：本方案是「单律师加密内核 + 监督式协同覆盖层」，**不是多租户 / RBAC 系统**；真正的并发协作、细粒度权限隔离、跨机同步属形态 B（律所内网版）范畴，按本空间铁律不展开。若未来确需，请明确放开该约束。

---

## 七、落地优先级（建议）

1. **先建 `07-协同/` 骨架 + `worklog` 模板**（低风险、即见效）——见本目录。
2. **配 role key + 一次加密交接演练**（验证 crypto-l1.sh 的 role key 路径）。
3. **跑一轮「助理产出 → 律师门禁 → 归档」闭环**（验证 §五流程 + 台账回填）。
