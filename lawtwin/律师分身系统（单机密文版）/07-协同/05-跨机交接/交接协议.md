# 跨机加密交接协议（助理在自有电脑作业）

> **范围声明**：本协议仅服务律师分身（小强律师数字分身系统），不含「律所分身」内容。
> 对应活文档：`07-协同/协同方案建议.md` 中「角色分域覆盖层」的跨机延伸。

## 一、问题的本质

单机密文版（形态 A）的硬边界是 **单所有者 + 单机 + L1/L2 本机加密绝不出网 + 本地门禁**。
当助理在**自己的电脑**上作业时，等于引入了一个「外部未授信端点」。此时不能把加密内核搬到助理机器，
而要把**安全边界从「单机」平移到「加密交接文件 + 律师单机」**。

核心结论：**助理的机器永远不持有律师的内核（L1 人格层、L2 知识层主密钥、门禁运行权）**。
助理只持有一把独立的「角色密钥」，用它把工作成果加密成一个**可任意传输的密文文件**，发回律师处解密入库。

## 二、信任模型（务必讲清）

```
助理电脑 (外部端点)                传输通道 (无需保密)              律师单机 (加密内核)
┌─────────────────┐            ┌──────────────────┐          ┌────────────────────────┐
│ 工作成果(草稿)    │  pack      │  xxx.L1handoff.enc │ 任意通道  │  receive → 02-待审交付物  │
│  + MANIFEST.md   │ ───────▶  │  + .meta 侧车       │ ───────▶ │  → LTI 门禁 → 通过入 L2   │
│  角色密钥(钥匙串) │  加密      │  (已端到端加密)      │  USB/微信  │  主密钥/门禁仅律师持有     │
└─────────────────┘            └──────────────────┘          └────────────────────────┘
```

- 传输通道 **不需要保密**：文件已被角色密钥加密，拿到文件也解不开（除非同时拿到角色密钥）。
- 角色密钥 **不随文件传输**，只在线下可信渠道（当面 / 加密 IM）一次性转交，存入双方本机钥匙串。
- 律师解密后，产物先落 `02-待审交付物/`（待审），**经 LTI 门禁通过**才正式进入 L2 知识层（用 `m2_secure.sh rebuild` 重新索引入密文闭环）。

## 三、密钥引导（一次性，之后无需再做）

1. **律师侧**生成角色密钥并打印一次（仅线下转交用）：
   ```bash
   handoff.sh init-role assistant
   # 输出一串 base64 密钥 + 指令: handoff.sh adopt-role assistant <密钥>
   ```
2. **助理侧**把该密钥存入自己机器的钥匙串：
   ```bash
   handoff.sh adopt-role assistant <律师转交的密钥>
   ```
   此后双方钥匙串里 `lawtwin-handoff-assistant` 是同一把密钥，跨机加解密即可互通。

> 非 macOS 的助理机器：用环境变量 `LAWTWIN_HANDOFF_PWD` 持有该密钥（不建议长期明文，优先 macOS 钥匙串）。

## 四、交接流程（每次作业）

**助理侧（pack）**
1. 在工作目录放一份 `MANIFEST.md`（作者角色 / 日期 / 关联案号 / 内容摘要 / 文件清单）。
2. 打包加密：
   ```bash
   handoff.sh pack assistant ./我的工作产物 ./发出
   # 产出: 我的工作产物.L1handoff.enc  +  我的工作产物.L1handoff.meta
   ```
3. 把 `.enc` 和 `.meta` 发给律师（微信 / 邮件 / U盘 / 微云均可，通道无需保密）。

**律师侧（receive）**
1. 收到后解密入库：
   ```bash
   handoff.sh receive assistant 我的工作产物.L1handoff.enc ./02-待审交付物
   # 自动: 解密到 02-待审交付物/<时间戳>/ + 打印 MANIFEST + 跑 LTI 门禁(若守护进程在跑) + 记台账
   ```
2. 门禁 PASS 的 `.docx` 才进一步审阅；通过后用 `m2_secure.sh rebuild` 把approved 内容索引入 L2 密文闭环。

## 五、明文 meta 侧车（非敏感，可随文件发）

`pack` 会同时生成一个 `<name>.L1handoff.meta`，内容仅含路由信息（角色 / 打包人 / 时间 / 密文 sha256 / 文件数），
**不含任何案卷内容**。律师收到后无需解密即可核对来源与完整性（比对 sha256）。

## 六、红线（绝不跨越）

- ❌ 绝不把 L1 人格层、L2 主密钥、门禁运行权下发到助理机器。
- ❌ 绝不把涉密案卷原文（未脱敏）交给助理处理。助理只接触脱敏后的草稿 / 公开资料 / 待审产物。
- ❌ 角色密钥不写进脚本、不落盘明文、不发公网（仅线下一次转交）。
- ✅ 助理离职：立即 `security delete-generic-password -a <你> -s lawtwin-handoff-assistant` 吊销该角色密钥，
  并要求助理清空其机器上的加密区（六-B 铁律：先备份再轮换 / 吊销）。
