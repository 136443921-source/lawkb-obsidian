### 2.1 四层模型（私有化本质：L1/L2 锁死本机，推理层可插拔）

|---|---|---|---|

| **L1 人格层** | 律师画像实例、self.md | **本机 + AES-256 加密** | **绝否** |
| **L2 数据层** | 知识库、案卷、法规库 | **本机** | **绝否** |

## 三、搭建总体方案（Phase 0–7，适配形态 A）

> 全流程遵守「六-B 铁律」：先建备份基线，再动手；批量前 dry-run；确认幂等。

### Phase 0 · 部署前置（不完成不许往下走）
- **硬件核验**：API 模式 ≥4 核/8GB/50GB；本地模型 ≥8 核/**32GB**/80GB（16GB 只够 7B Q4 降级，须书面告知客户为降级模式、幻觉率上升）。
- **网络确认**：拿到客户 IT 书面网络策略（允许外联 / 白名单）。
- **账号清单**：客户推理 API Key（或已备 GPU）、律师名与执业角色、1 个高频试点案由。
- **备份基线（六-B 铁律）**：`mkdir -p /tmp/lawtwin_deploy_<时间戳>` 并 `cp -n -R` 客户知识库。**无备份基线 = 立即停手**。

### Phase 1 · 骨架落地（律师分身原生，自包含）
- `bash 启动包/bootstrap.sh --dry-run` → 确认零写入。
- `bash 启动包/bootstrap.sh --apply` → 生成 `01-方案 02-配置 03-人格层L1 04-知识层L2 05-门禁 06-部署记录 logs` 标准子目录，并复制 `inference.A.yaml` 到 `02-配置/`。
- **残留校验**：`grep -rn "\[律师名\]\|\[案由\]"` 必须**输出为空**（零残留）。

### Phase 2 · 推理层配置（M1 已交付）
- 选后端：客户 API（DeepSeek/通义/智谱）填 `base_url`+`api_key_env`；或本机 Ollama `http://127.0.0.1:11434/v1`。
- 配：复制 `启动包/inference.A.yaml` → `02-配置/inference.yaml`，改 `base_url`/`model`/`network.mode: allow_external`。
- 校验：在 `~/lawtwin-open/core/` 跑 `lawtwin-infer validate`（明文密钥硬拒、网络策略门禁）→ `selftest`（12 项断言）→ `check` → `chat` 验证法律语境回复。
- **单机密文版注意**：密钥只进环境变量，绝不落盘；命中 fallback 自动标记 `degraded` 并触发 LTI 收紧阈值（预期行为）。

### Phase 3 · 技能安装与版本锁（关键，不许跳）
- 按 P0→P1→P2 顺序装；每装一个**立即回填 manifest「目标所实装版本」列（不得留空）**。
- P0 三项必须先通：`legal-consult-router` + `lawyer-yourself-skill` + `LTI 文本监控器`。
- 投一个法律测试问题，确认 `legal-consult-router` 能五问分诊并派发（失败先查 `legal-base` 基座是否安装）。

### Phase 4 · 连接器配置
- 法条源（pkulaw/元典）**核心**；离线用本地法规库快照兜底。
- **跨所令牌不复用、不打印**；由客户管理员在自有 WorkBuddy 重新授权（AI 不代点 UI）。
- **断网降级路径**：命中本地缓存→返回并标核验日期；未命中+有外联→实时核验回写；未命中+无外联→标 `statute_text_pending`，**禁止凭记忆编条文**（红线）。

### Phase 5 · 人格层注入（L1，密文核心）
- 生成律师 `profile.yaml`（display_name/firm/seat_role/practice_areas）→ 经 `lawyer-yourself-skill` 的 `combine.sh` 生成 `self.md`（遵守 Fix-the-source 铁律）。
- **加密封装**（已落地为 `启动包/crypto-l1.sh`，源所已验证方案）：
  ```bash
  bash 启动包/crypto-l1.sh encrypt 03-人格层L1 lawyer-l1
  # 内部：openssl rand 生成口令 → 存 macOS 钥匙串 → tar 打包 → aes-256-cbc+pbkdf2(iter=600000) 加密
  #       → round-trip 解密验证 sha256 一致 → 密文权限 600
  ```
- **验收**：密文权限 600 + **round-trip 解密验证 sha256 一致** + 密码存钥匙串（不在对话/日志打印明文）。未验证不许交付。

### Phase 6 · 知识层导入（L2）
- **分层裁剪**：通用规则包✅ / 行业规则包✅（按订阅）/ 客户私有层✅留本机 / **源所私有层（老强决策日志、办案笔记、当事人信息）🚫绝不交付**。
- 导入离线法规快照，记录快照日期+核验日期。
- **脱敏门禁**：`python3 启动包/desensitize_check.py <目录> --strict` 退出码 0 才放行（注意：图片/PDF 扫描件检测不到，开仓前须人工过一遍）。

### Phase 7 · 门禁校准与试点验证
- LTI 五维自检（R101 条号越界、C301 金额硬矛盾能阻断）；本地降级模式调严阈值。
- 跑通 1 个高频试点案由全链路：起草→蓝队→红队→LTI→交付，**LTI REJECT=0**。
- 填写「部署记录表」归档（一客户一表，含版本锁、形态、网络策略、密码移交方式）。

## 四、单机密文版「密文」专项设计

1. **L1 人格层密文**：profile → self.md → tar 打包 → `aes-256-cbc + pbkdf2(iter=600000)` 加密 → 密码存 macOS 钥匙串；交付前 round-trip 验证。
2. **L2 数据层本地**：知识库、案卷、法规库全部留本机，绝不外传；源所私有层（当事人/决策日志）严格排除。
3. **密钥管理**：推理密钥只走环境变量（`api_key_env`），M1 明文密钥硬拒加载；跨所重新授权；不打印令牌明文。
4. **单机备份**：Phase 0 基线 + 加密包自备份；无备份不许写入。
5. **可关闭外联**：`network.mode` 默认 `allow_external`，可收紧为 `whitelist`；降级模式自动触发 LTI 收紧。
6. **审计不落正文**：M1 审计日志默认只记 host/模型/耗时/状态 + prompt 的 sha256 前 12 位，防内网二次泄敏。

## 五、合规红线

1. **数据不出本机**：L1/L2 永不外传。
2. **不编法条**：离线未回源一律标 `statute_text_pending`，禁止引为文档源。
3. **令牌不复用不打印**：跨所重新授权；AI 不代点 UI、不打印令牌明文。
4. **AIGC 标识**：AI 生成草稿保留水印/元数据标识。
5. **备案边界**：纯本机自用一般不触发备案；一旦对客户以外第三方开放，须走备案+安全评估——合同须写明边界。
6. **执业责任**：AI 输出为辅助草稿，律师对最终成果独立负责。
