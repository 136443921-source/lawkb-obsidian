# 🛡 律师数字分身 · 缺口技能建设方案（四支柱版）

> **状态：草稿（draft）**。本方案是《律师分身系统（单机密文版）总体方案》的**缺口技能落地点位图**，把原律所内网版"四化成熟度"视角换成**四个安全/质量支柱**——**数据不出机 / 经验可沉淀 / 运维可审计 / 制品防幻觉**——逐项标注「已有底座 vs 待建缺口」，避免重复造轮子。
> 配套纲领：[[律师分身（单机密文版）总体方案]]（形态 A 架构 / 已有资产 / 合规红线来源）。
> **审核通过前不建任何技能骨架**（同总体方案 §0 铁律）。

---

## 0. 四支柱定义与建设原则

**四支柱（本方案主轴，替代原"四化"）**：

| 支柱 | 一句话 | 本质是回答 |
|---|---|---|
| 🔒 **数据不出机** | L1/L2 永落本机、脱敏门禁、加密、零外联可观测 | "隐私数据有没有漏出去？" |
| 📚 **经验可沉淀** | 案结即萃卡、入飞轮、过门禁、可复用 | "办过的案有没有变成资产？" |
| 🔍 **运维可审计** | 门禁存活/降级/触发率可观测、巡检留痕 | "系统是不是在偷偷变差？" |
| 🚫 **制品防幻觉** | LTI REJECT=0 铁门禁、断网不编法条、裁判真源 | "交付物有没有编出来的内容？" |

**建设总原则（护栏，任何技能不得突破）**：
1. **数据不出机** —— 复用总体方案 §五 合规红线①：L1/L2 永不外传；推理密钥只走环境变量、不落盘；跨所令牌不复用不打印、由客户管理员重新授权（AI 不代点 UI）。
2. **LTI 门禁** —— 涉及文书/卡片的技能，入库或出文前强制过 LTI（REJECT=0），断网未回源一律标 `statute_text_pending`，禁止凭记忆编条文。
3. **六-B 铁律** —— 先备份再动手、批量前 dry-run、改后幂等确认、零残留验证。
4. **复用优先** —— 每个缺口技能先挂现有底座（LTI v4.9.1 / 脱敏门禁 / crypto-l1.sh / m2_secure.sh / 治理席位驾驶舱巡检 / 知识飞轮拆卡流水线），只补缺失环节。
5. **本地优先** —— 所有备份落自托管（本机/NAS），**绝不上第三方云**；密钥不入库、本地密钥文件 `0600`。
6. **标准化交付** —— `SKILL.md`（含 frontmatter + 触发词 + 依赖 + 红线）+ 配套脚本 + 自测 + 回写本方案 §1 总览与变更日志。

## 2. 各支柱技能设计卡（详细，标注已有底座）

### 2.1 🔒 数据不出机（已有底座强，补 3 缺口）

**已有底座（落实复用，勿重建）**：
- 脱敏门禁 `启动包/desensitize_check.py` —— 对外交付前扫描，退出码 0 才放行（注意图片/PDF 扫描件检测不到，开仓前须人工过一遍）。
- L1 加密封装 `启动包/crypto-l1.sh` —— openssl aes-256-cbc+pbkdf2(iter=600000)，密码存 macOS 钥匙串，round-trip 验证 sha256 一致。
- L2 密文检索 `04-知识层L2/m2_secure.sh` —— M2 索引用 crypto-l1.sh 加密归档，仅密文落盘、检索即时解密用完即焚。
- M1 零外联门禁 `~/lawtwin-open/core/` —— 明文密钥硬拒、网络策略门禁、降级感知、`network.mode` 默认 allow_external 可收紧 whitelist。

**缺口卡**：

#### D1 · L2 本地法规库快照制备（P0 · Batch 1 · 与 H1 共享底座）
- **触发词**："制备法规快照" / "离线法条库" / "断网核验底座"
- **输入**：本地权威法规源（民法典/民诉法/司法解释等，取自本地 LawKB 法规库，不联网抓取）
- **输出**：带快照日期+核验日期的离线法规索引包（密文落盘，复用 m2_secure.sh）
- **依赖**：`m2_secure.sh`、`crypto-l1.sh`；总体方案缺口 G5
- **配套脚本**：`build_statute_snapshot.sh`（导出→加密归档→记快照/核验日期）
- **红线**：绝不联网抓取第三方；快照日期须标注，过期（>12 个月）触发告警
- **验收**：断网环境下 LTI 法条核验命中本地快照、未命中返 `statute_text_pending`（非编法条）

#### D2 · 连接器出网审计中间件（P1 · Batch 1）
- **触发词**："哪些连接器外发" / "出网审计" / 连接器调用前
- **输入**：连接器调用 payload（qq-mail / 元典 / pkulaw / 企查查等）
- **输出**：出网审计日志（连接器名/目标域/数据类别/是否含 PII/时间戳）+ 超阈值告警
- **依赖**：现有连接器清单；总体方案 §五 红线③（令牌不复用不打印）
- **配套脚本**：`egress_audit.py`（包裹连接器调用、记审计、PII 命中即阻断）
- **红线**：审计日志仅记元数据、不落正文（同 M1 审计不落正文）；绝不屏蔽合法业务外联
- **验收**：注入含真实案号样本，审计日志拦截率 100%，正常业务外联不误拦

#### D3 · 单机加密备份自动化（P0 · Batch 1）
- **触发词**："备份律师分身" / "加密备份" / "定时备份"
- **输入**：单机密文版全目录（含 L1 密文、L2 密文索引、配置）
- **输出**：`lawtwin-<date>.bundle.gpg`（AES-256 加密包）→ 落本机 + 可选 NAS
- **依赖**：`crypto-l1.sh`；总体方案 §四.4（单机备份基线）
- **配套脚本**：`lawtwin_encrypted_backup.sh` + launchd/cron（每日增量）
- **红线**：**绝不上第三方云**；密钥不入库；本地密钥文件 `0600`
- **验收**：模拟机毁 → 从 .gpg 恢复成功，L1/L2 资产零丢失、round-trip 验证通过

### 2.2 📚 经验可沉淀（全系统最空，重点补建）

**已有底座（落实复用）**：LawKB 知识飞轮（10719 md / 331M）、3 条拆卡流水线（审判要件卡 / 裁判规则卡 / 经验卡）、LTI 门禁、连接枢纽。

**缺口卡**：

#### E1 · 案件结案复盘卡自动化（P0 · Batch 2）
- **触发词**："案子结了" / "结案复盘" / `case-state→closed`
- **输入**：`case-state.json` 状态变 closed；庭审十件套
- **输出**：自动萃取裁判规则卡 + 审判要件卡 + 经验卡 → 过 LTI → 入 `06-沉淀`
- **依赖**：案件生命周期大屏 `case-state`、3 条拆卡流水线、LTI v4.9.1
- **配套脚本**：`case_closed_harvest.py`（监听 closed → 调拆卡 → LTI 校验 → 入库）
- **红线**：萃取须过 LTI（REJECT=0）；当事人信息脱敏（调 D 系列脱敏门禁）
- **验收**：1 个 closed 案件自动产出 ≥1 张合规卡入 06-沉淀

#### E2 · 沉淀质量门禁流水线（P0 · Batch 2）
- **触发词**："入库质检" / "沉淀门禁" / 卡片入库前
- **输入**：待入库卡片（md）
- **输出**：LTI + 冲突仲裁 + 一致性审计三联报告；FAIL 阻断
- **依赖**：LTI 文本监控器、`lawkb-conflict-arbitration`、`lawkb-legal-consistency-audit`
- **配套脚本**：`ingest_gate.sh`（串联三门禁，FAIL 即阻断，禁白名单跳过）
- **红线**：门禁不可加白跳过；命中先定位是否放错层
- **验收**：含错误法条的卡被拦截，合规卡放行

#### E3 · 经验卡萃取模板库（P1 · Batch 2）
- **触发词**："经验卡模板" / "按案由萃取" / 复盘模板
- **输入**：5 类高频案由（人伤/合同/股权/侵权/婚姻家事 等）
- **输出**：5 套经验卡萃取模板（要素式结构 + 红线清单 + 错误示例）
- **依赖**：E1 萃取流水线；知识飞轮卡库接线
- **配套脚本**：模板 md 库 + `harvest_from_template.py`
- **红线**：模板不得含当事人 PII；萃取后强制脱敏
- **验收**：输入 1 个案由卷宗 → 输出 1 张贴合模板的经验卡

#### E4 · 复用度量埋点（P2 · Batch 2）
- **触发词**："卡片复用率" / "沉淀 ROI" / 复用统计
- **输入**：卡片被引用/检索/回写记录
- **输出**：复用率 / 失效卡 / 孤岛卡月度报表
- **依赖**：知识飞轮卡库接线；Hub 索引
- **配套脚本**：`reuse_metrics.py`（扫描引用边 → 聚合报表）
- **红线**：度量仅统计卡 ID，不触碰卡片正文
- **验收**：输入 3 个月引用日志 → 输出复用率/孤岛卡清单

### 2.3 🔍 运维可审计（适配单机密文版，补专属）

**已有底座（落实复用）**：LTI 审计日志（M1 审计不落正文）、协同效果日志（治理席位「主任交付」埋点）、`律所主任·驾驶舱监控` SKILL + WF-047 铁律第 7 条（核实闭环三动作）、`mp_maturity.py` 成熟度追踪。

**缺口卡**：

#### O1 · 单机密文版运维审计巡检适配（P0 · Batch 3）
- **触发词**："单机密文版健康度" / "门禁存活" / 挂 9360 子屏
- **输入**：LTI 门禁存活状态、`crypto-l1.sh` 轮转/权限、脱敏门禁触发率、M1 降级次数、D3 备份新鲜度
- **输出**：单机密文版专属健康看板 + 异常告警（门禁挂了/密钥过期/降级频发）
- **依赖**：`律所主任·驾驶舱监控` 引擎（复用其 P0–P4 评级 + 报告框架）、`cockpit_daily_monitor.py`
- **配套脚本**：`lawtwin_audit_probe.py`（探针组，输出结构化 JSON 喂给引擎）
- **红线**：仅所内/本机回环，不含当事人 PII；只读探针，不改配置（L1 只读边界）
- **验收**：人为停掉 lti-gate 守护 → 巡检 P0 告警；密钥权限非 600 → P1 告警

#### O2 · 部署记录表自动化归档（P1 · Batch 3）
- **触发词**："部署记录" / "交付归档" / 一客户一表
- **输入**：版本锁 manifest、形态、网络策略、密码移交方式、试点案由
- **输出**：自动化填充的部署记录表（一客户一表，含总体方案 §七 验收清单勾选）
- **依赖**：总体方案 §六 版本锁基线、§七 验收清单
- **配套脚本**：`deploy_record_fill.py`（读 manifest + 校验空项 → 生成归档表）
- **红线**：版本锁"目标所实装版本"列**不得留空**（消除总体方案 G6）；密码移交方式不入库明文
- **验收**：manifest 全部回填后生成完整部署记录，空项自动标红拦截

#### O3 · 技能成熟度追踪接入（P1 · Batch 3）
- **触发词**："成熟度" / "技能覆盖" / 训练曲线
- **输入**：单机密文版实装技能清单（来自版本锁 manifest）
- **输出**：单机密文版技能成熟度报表（对照版本锁基线）
- **依赖**：`mp_maturity.py`（治理席位成熟度脚本）；版本锁 manifest
- **配套脚本**：`mp_maturity.py --scope lawtwin`（扩展 scope 参数）
- **红线**：成熟度基于可观测版本号/调用记录，不主观打分
- **验收**：输入 manifest → 输出实装 vs 基线差异报表

### 2.4 🚫 制品防幻觉（LTI 强底座，补 4 缺口）

**已有底座（落实复用）**：LTI 文本监控器 v4.9.1（五维 QC：R/L/C/T/P，REJECT=0 才准交付）、`lti_gate` 守护进程 + 客户端 + launchd（airgap 默认开）、`statute_text_pending` 机制（断网不编法条）、裁判规则库归库（835 主体 / 730 变体 / 71 维度真源，rules_consolidate.py + rules_loader.py）。

**缺口卡**：

#### H1 · L2 法规库快照制备（P0 · Batch 1 · 与 D1 共享底座）
- **说明**：同 D1。从"制品防幻觉"视角：断网环境下法条核验必须有本地权威源，否则只能返 `statute_text_pending`，绝不允许凭记忆编条文（总体方案 §五 红线②）。**两个支柱共享同一脚本 `build_statute_snapshot.sh`，不重复建。**
- **验收**：同 D1。

#### H2 · 法条双源核验强制（P1 · Batch 1）
- **触发词**："法条核验" / "双源比对" / 引用法条
- **输入**：待核验法条（条号/正文）；pkulaw + 元典 + 本地法规快照
- **输出**：三源比对结果；冲突/缺失即告警（标 `statute_text_pending` 或阻断）
- **依赖**：pkulaw MCP / 元典 MCP / D1 本地快照；`rules_loader.py`
- **配套脚本**：`statute_verify.py`（三源拉取 + diff + 冲突告警）
- **红线**：三源均缺失 → 标 pending，**禁止编**；冲突以本地快照+pkulaw 权威为准
- **验收**：注入 1 条被篡改法条 → 双源比对告警；注入正确法条 → 放行

#### H3 · statute_text_pending 清零追踪（P1 · Batch 2）
- **触发词**："待回源清零" / "pending 扫描" / 回源核填
- **输入**：全库 `statute_text_pending` 标记卡片
- **输出**：待清零清单（按来源/日期）+ 清零进度
- **依赖**：`statute-pending-clear` 技能（已沉淀）；LTI 门禁
- **配套脚本**：复用 `statute-pending-clear` 流水线（批量清零前逐卡核验）
- **红线**：清零前必须逐卡核回填真实条文，禁止"假清零"
- **验收**：跑一轮后 pending 计数下降、且清零项均有真实条文落源

#### H4 · 幻觉监控看板（P1 · Batch 3）
- **触发词**："幻觉率" / "LTI 拦截" / 挂 9360 C8 屏
- **输入**：LTI 五维 QC 拦截记录、REJECT 项、误报率、裁判真源命中率
- **输出**：幻觉监控看板（C8 LTI 屏）：R/L/C/T/P 拦截率、REJECT 趋势、误报 Top
- **依赖**：LTI v4.9.1 审计输出；`律所主任·驾驶舱监控` 引擎（C8 数据源）
- **配套脚本**：复用 `cockpit_daily_monitor.py` 的 C8 提取段 + 看板 HTML
- **红线**：看板仅统计聚合指标，不含当事人 PII
- **验收**：9360 内可打开 C8 屏，近 7 日 REJECT 趋势实时可见

## 3. 建设批次（建议 3 批，先守底线→补沉淀→补审计）

|---|---|---|---|
