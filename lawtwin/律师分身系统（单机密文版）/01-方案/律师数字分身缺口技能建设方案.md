## 0. 主轴框架：四支柱 + 四配套维度

### 0.1 四支柱（本方案核心主轴，替代原"四化"）

| 支柱 | 一句话 | 本质是回答 |
|---|---|---|
| 🔒 **数据不出机** | L1/L2 永落本机、脱敏门禁、加密、零外联可观测 | "隐私数据有没有漏出去？" |
| 📚 **经验可沉淀** | 案结即萃卡、入飞轮、过门禁、可复用 | "办过的案有没有变成资产？" |
| 🔍 **运维可审计** | 门禁存活/降级/触发率可观测、巡检留痕 | "系统是不是在偷偷变差？" |
| 🚫 **制品防幻觉** | LTI REJECT=0 铁门禁、断网不编法条、裁判真源 | "交付物有没有编出来的内容？" |

### 0.2 四配套维度（老强指令：四支柱之外，全面对准 9655 复盘补充）

> 来源：直接取自 [[9655 造车平台 EV版手册]] 的复盘结论与造车收口铁律。**9655 是单机密文版唯一实时镜像**，其自身暴露的矛盾就是缺口技能必须补齐的"非四支柱"维度。

| 维度 | 一句话 | 来源（9655 复盘） | 本质是回答 |
|---|---|---|---|
| 🪞 **可诊断·可定责（实时镜像）** | 驾驶舱是整车实时镜像，源可溯/变可察/责可定；子屏必须接实时 JSON 而非静态快照 | §10.9 设计原则 + §11.4 核心矛盾（13 子屏静态快照脱节） | "出了问题能不能回放、定位到哪一屏？" |
| 🚧 **红线前置（令牌/AIGC 红线）** | 缺口技能把红线门禁前置到触发前，不能事后才发现 | §10.6 告警旗 R3 令牌红线 / R4 AIGC 标识红线（需人工确认） | "红线有没有在入口就拦住？" |
| 📐 **评分可信（防假自洽·零虚构）** | scorecard 评分环==六维条均值，绝不伪造指标 | §10.3 数据管线纪律 + R-LN-114 假自洽红线 | "看板上的数字是不是真的？" |
| 🔐 **单机密文版定位（引用边界）** | 9655 是单机密文版唯一实时镜像，不与 9360 内网版/律所分身混 | §0 引用边界铁律 + §11.7 战略姿态 | "这东西是不是挂对了体系？" |

**为什么这四条必写进方案**：9655 复盘（§11.4）已实锤——当前驾驶舱最大矛盾是"子屏内联静态快照、与系统实时状态脱节"，且评分有过"环取屏加权均值、与六维条矛盾"的假自洽事故（R-LN-114）；运维期还亮着令牌/AIGC 两面红线旗。缺口技能若不把"实时镜像 / 红线前置 / 评分可信 / 引用边界"当建设铁律，**造出来只会给 9655 再添一批假数据屏**——这不是补缺口，是制造新盲区。

### 0.3 建设总原则（护栏，任何技能不得突破）

1. **数据不出机** —— 复用总体方案 §五 红线①：L1/L2 永不外传；推理密钥只走环境变量、不落盘；跨所令牌不复用不打印、由客户管理员重新授权（AI 不代点 UI）。
2. **LTI 门禁** —— 涉及文书/卡片的技能，入库或出文前强制过 LTI（REJECT=0），断网未回源一律标 `statute_text_pending`，禁止凭记忆编条文。
3. **六-B 铁律** —— 先备份再动手、批量前 dry-run、改后幂等确认、零残留验证。
4. **复用优先** —— 每个缺口技能先挂现有底座（LTI v4.9.1 / 脱敏门禁 / crypto-l1.sh / m2_secure.sh / 9655 实扫探针 / 知识飞轮拆卡流水线），只补缺失环节。
5. **本地优先** —— 所有备份落自托管（本机/NAS），**绝不上第三方云**；密钥不入库、本地密钥文件 `0600`。
6. **标准化交付** —— `SKILL.md`（含 frontmatter + 触发词 + 依赖 + 红线）+ 配套脚本 + 自测 + 回写本方案 §1 总览与变更日志。
7. **9655 对准铁律（新增）** —— 任何缺口技能交付的看板/指标，**必须喂 9655 实扫探针（`scan_9655.py` 扩展探针）**，由 `scorecard_data.json` 渲染；**禁止另写静态快照屏**；屏名与 9655 自身屏名规范逐字一致；数据零虚构（同 EV 手册 §10.8）。
