# 🔧 律师数字分身系统 EV · 9655 造车平台 EV版手册

> **范围与铁律声明**：本手册**只覆盖「造车」**——即律师数字分身系统（形态 A · 单机密文版）从 0 到 1 的搭建过程，**不讲"开车/运维"**（那部分见对外版白皮书第十四、十五章与《05-私有化部署手册》）。造车平台的终点是"一辆可诊断、可定责、数据不出本机的车 + 一块能看懂这辆车的驾驶舱"。
> **引用边界（铁律）**：本空间全部内容只取「律师分身」，不引用律所分身。本手册所述驾驶舱（9655）为单机密文版**自研单机运维监控台**，独立设计、实扫本机数据，与律所分身无涉。
>
> **活文档（Living Document）声明**：本手册是单机密文版「造车」过程的**唯一内部参考 + 变更溯源区**。凡造车流程有变（命令改、版本升、架构调、驾驶舱屏增），**必须同步更新本文件**：刷新文首 `updated`、在 §14 变更日志补一行。改动建议在 LawKB 内 `git` 提交留痕。

## §1 一句话结论

**单机密文版不是"买一辆现成的车"，而是"照着一套工程图纸，在自己车库里造一辆只属于你、数据不出本机的车"。** 造车分九段：定铁律 → 搭四层底盘 → 装三电 → 接补能 → 标智驾 → 配座舱 → 装自检 → 埋黑匣子 → 立驾驶舱。其中**驾驶舱（9655）是一块实扫运维监控台**，为单机密文版自研单机版运维驾驶舱，是本车"健康状况的仪表盘"——它不造车，但它让造出来的车**可被看见、可被诊断、可被定责**。

## §3 段 0 · 定铁律（造车前先立规矩）

造车第一步不是写代码，是**锁范围**：

1. **范围锁定**：本车 = 律师分身（个人律师 / 5–20 人小所）· 形态 A 单机密文版。律所内网版（B）、涉密隔离版（C）不在本手册范围。
2. **引用边界**：全程只取「律师分身」内容；律所分身资料一律隔离，不并入。
3. **红线预埋**：数据不出本机（L1/L2 永不外传）、不编法条（离线标 `statute_text_pending`）、令牌不打印不复用、AI 不代点 UI。

> 铁律不是口号，是后面每一段的"设计约束"——比如"数据不出本机"直接决定了 L1/L2 必须本机加密，而非上云；也决定了驾驶舱（9655）必须**实扫本机**而非调用远程接口。

## §4 段 1 · 四层底盘（造车的骨架）

| 层 | 内容 | 部署位置 | 能否出网 |
|---|---|---|---|
| **推理层 M1** | 大模型 API / 本地 Ollama | 客户自选（API 或本机 GPU） | 可外联（可关闭，默认 airgap 友好） |
| **L0 内核层** | 骨架、协议、门禁规则 | 本机 | 否 |
| **L1 人格层** | 律师画像实例、self.md | 本机 + **AES-256 加密** | **绝否** |
| **L2 数据层** | 知识库、案卷、法规库、检索索引 | 本机 + **加密归档** | **绝否** |

**造车要点**：底盘的核心是"把 L1/L2 锁死在本机、把推理层做成可插拔"。这意味着造车时不预设模型厂商，只预留 `inference.yaml` 抽象层（填 base_url + 模型 + network.mode）。驾驶舱（9655）读取的"系统健康度"，本质就是这四层在**本机**的真实落地状态——底盘稳不稳，仪表盘第一个知道。

## §5 段 2 · 三电系统（车的能量心脏）

### 5.1 动力电池包 = L2 知识飞轮

- **造车动作**：建立六层结构知识资产库，从"原料（裁判文书原文）"到"规则（可被引用的裁判规则）"的炼制流水线（提炼 → 编号 → 交叉索引 → 断链校验）。
- **加密**：L2 数据层用 `crypto-l1.sh` 打包为 `.L1.tar.gz.enc`，密钥存 macOS 钥匙串，**绝不离开本机**。
- **红线**：严禁凭记忆灌法条正文（错引率约 22%，特定领域达 75%）。

### 5.2 驱动电机 = G3 本地检索（M2）

- **造车动作**：`m2_build_index.py` 建多源语料索引，`sqlite-vec` 向量索引 + `FTS5 trigram` 中文全文混合检索（RRF 融合），离线哈希嵌入（可插拔真 SBERT）。
- **关键脚本**：`m2_core.py`（build/query）、`m2_secure.sh`（rebuild/seal/query/verify/status 闭环）。
- **闭环**：建完索引用 `crypto-l1.sh` 加密归档 `m2_index.db` → 形成"检索 + 密文"闭环。

### 5.3 电控 + BMS = G2 门禁独立守护（LTI）

- **造车动作**：不重写成熟 `lti_gate.py`，用 Unix socket 守护进程 **subprocess 封装**（零修改），配 `com.xiaoqiang.lti-gate.plist` 保活。
- **意义**：门禁跨推理层/座舱崩溃仍独立在岗；`REJECT ≠ 0` 永远不许出门。
- **降级哲学**：外部核验不可用时降级到替代核验 + 官方交叉印证，标 `pending`，不编法条。

### 5.4 动能回收 = HIR 经验沉淀

- **造车动作**：把每次红蓝对抗 / 质检拦截 / 事故回流成经验卡与规则。开得越多电量越多，错得越多下次越少错。

> **三电与驾驶舱的接口**：驾驶舱 C3 知识飞轮舱读的是 L2 卡数（02-提炼/06-沉淀）与 `flywheel-data.js`；C8 AI 幻觉监控舱读的是 G2 `lti-gate` 进程存活与日志。三电不是孤立总成，它们是驾驶舱上"最亮的那几块表"的数据源。

## §6 段 3 · 补能网络（充电桩）

- **造车动作**：接入 6 个权威法律数据源连接器（法条核验 / 判例检索 / 机构业务 / 知识库摄入 / 报告投递），6/6 实测连通。
- **离线降级**：内置**本地法规库快照**兜底——断网返回 `statute_text_pending` 而非编造。
- **不代点原则**：重连需人工授权，系统只诊断不代执行。

> 补能网络对应驾驶舱 **D3 云服务中台**（连接器 health：enabled 状态 / 最近调用）。断网时驾驶舱不黑屏，而是显示"本地快照 + 待补能"状态。

## §7 段 4 · 智驾系统（谁在判断）

- **域控 = 决策思维系统**：决策卡强制三行结构（考虑了哪些选项 / 为什么排除其他 / 什么信号会推翻），存推理而非结论。
- **激光雷达 = 跨案模式识别**：固化进接案 SOP 第一环。
- **电门计量 = G4 推理流式/计费**：M1 加 `StreamChunk`+`stream()`、`CostLedger` 成本记账、CLI `--stream`/`--cost-report`。让"开车"有油表。

> 智驾对应驾驶舱 **C2 决策思维舱**（决策卡 + 决策日志实扫）与 **D1 积分监测中台**（元典余额 + workbuddy.db 消耗）。"谁在判断、花了多少油"在仪表盘上一目了然。

## §8 段 5 · 座舱与影子模式（人机界面 + 碰撞预演）

- **智能座舱 = L1 人格配置**：`profile.yaml` → `combine.sh` → `self.md`，**本机 AES-256 加密**。
- **影子模式 = 模拟法庭**：蓝队建论证、红队预驳回攻击，开庭前先撞一次。
- **同车协议 = 协同 + 跨机交接**：`handoff.sh` 角色密钥端到端加密打包，传输通道无需保密，解密边界在律师单机。

> 座舱对应驾驶舱 **C6 模拟庭审中台**（模拟法庭 + 红蓝对抗 + 蓝/红队/书记/战情）与 **C5 合规管理中台**（小德合规）。注意区分：L1/L2 座舱是"车里的人机界面"，而 9655 驾驶舱是"看这辆车的另一块屏"——两者同名"座舱"但层级不同，前者是总成、后者是监控。

## §9 段 6–7 · 自检与黑匣子（可诊断 + 可定责）

- **DTC 故障码**：借鉴汽车 OBD，为每类失效定义唯一码（见 附录 A）。
- **黑匣子 = 决策日志**：每个判断可回放。
- **车规纪律 = 六-B 铁律**：写入型自动化必须"先排查 / 确认非误报 / 再批量 / 含扫描 + dry-run + 备份"，扩展到全部写入型自动化。
- **溯源主区**：每次造车改动记进《05-私有化部署手册》§5 决策日志。

> 自检与黑匣子是驾驶舱"可信"的底座：驾驶舱显示的每一个数字，背后都有 DTC 可解释、有黑匣子可回放。这也是为什么驾驶舱屏名铁律、数据零虚构红线必须前置——仪表盘一旦造假，整辆车就失去可诊断性。

## §10 ⭐ 段 8 · 驾驶舱打造详解（9655 · 重点）

> 这一章是造车手册的重心之一：**运维监控驾驶舱不是买来的，而是按单机密文版自研架构，从零"造"出来的单机版运维监控台。** 独立设计、数据实扫本机，与律所分身无涉。它把 §4–§9 造出来的"车"，映射成 15 块看得见的屏。

### 10.1 为什么要造驾驶舱

单机密文版交付后，最大的盲区是"车还健不健康"靠人肉敲命令判断。按单机密文版**自研运维监控台架构**，打造单机版 **9655**——聚焦与律师业务/运维相关的屏。没有驾驶舱，你不知道飞轮建了多少卡、门禁是否还活着、G4 流式到底接没接上；有了驾驶舱，这些从"靠记忆"变成"看仪表"。

### 10.2 总体架构（门户 + 作战地图 + 15 屏 + 实扫数据）

产物目录：`~/WorkBuddy/2026-09-17-16-22-53/outputs/9655-cockpit-v2/`（初版 `outputs/9655-cockpit/` 已删除，仅留 v2）

**核心架构决策：数据驱动 + 子屏富仪表盘自研**

```
9655-cockpit-v2/
├── index.html              # 门户（作战地图首页：评分环 + 九屏维度导航），纯静态
├── subapps/<name>/index.html  # 子屏；富仪表盘自研（自包含 KPI 卡 / 状态模块卡 / 评分环）
├── subapp_shell.css/.js   # 壳渲染器：读 document.body.dataset.cno + fetch /scorecard_data.json 切片渲染
├── gen_subapps.py          # 一键重写 9 屏薄壳（统一引用 subapp_shell）
├── scorecard_data.json     # ★唯一真源：scan_9655.py 实扫生成（35KB，含六维/panels/screens）
├── scan_9655.py            # 实扫管线（探真实文件系统 + 进程）
├── start_9655.sh           # 启停（端口 9655 / 127.0.0.1 / pidfile / setsid 保活）
├── com.xiaoqiang.cockpit9655.plist  # launchd 保活（RunAtLoad + KeepAlive）
└── install_launchd_9655.sh # launchd 一键装载/状态/卸载（幂等）
```

**架构要点**：
- **页面与数据解耦**：子屏不写死数据，运行时 `fetch /scorecard_data.json` 按 `cno` 取切片渲染（评级环 / 六维条 / KPI 卡 / 模块卡 / 缺口表 / 风险旗）。改扫描逻辑不改页面，改页面不动扫描。
- **子屏内容自研富仪表盘**：不是另写薄壳，而是内联 css/js/数据的自包含富仪表盘（KPI 卡 / 状态模块卡 / 评分环范式）。
- **门户即作战地图**：C0 首页聚合 15 屏评分与九屏维度导航，是全车的"总仪表"。

### 10.3 数据管线（实扫，零虚构）

`scan_9655.py` 探真实文件系统与进程，写入 `scorecard_data.json`：

| 数据 | 来源（实扫） |
|---|---|
| 知识资产规模 / 子库数 | 遍历 `LawKB/lawtwin/律师分身系统（单机密文版）/` 真实目录统计 |
| 版本锁回填率 | 解析总体方案 §六 版本锁 + 实测"目标所实装版本"空项 |
| 缺口闭环度 | gaps 屏**真探磁盘产物**（G2 daemon / G3 L2 检索层 / G4 streaming.py 存在性），不再硬编码"待建" |
| 门禁运行度 | **pgrep 探 lti-gate 进程**（非 socket 文件残留判断） |
| 六维评分 | 组合上述实扫值 + 红线旗（令牌复用 / AIGC 标识） |

> **关键工程纪律**：评分环值 = 六维算术均值，强一致（R-LN-114 假自洽红线：曾出现环取"屏加权均值"与六维维度条矛盾，已修）。仪表显示"铭牌值 vs 实测值"，不一致摊开显示不覆盖。**绝不伪造指标。**

### 10.5 子屏富仪表盘搭建的关键坑（造车时必知）

- **符号链接陷阱**：驾驶舱屏引用的 `flywheel-data.js` 是相对符号链接。`cp -p` 会复制链接本身→在 9655 解析失效 404。**正确做法**：`readlink -f` 取真实目标后 `cp` 真实文件。
- **同目录依赖**：如 `mind-models` 引用同目录 `mind-data.js`，整目录复制（除 `.bak`）。
- **外部 CDN**：`lti` 屏引用 cloudflare Chart.js，保留原样（需联网）。
- **禁止改薄壳**：不能把富仪表盘换成通用数据视图器薄壳——那会丢失 KPI 卡 / 状态模块卡范式。
- **旧架构残留坑**：`subapp_shell.js/.css`、`subapp_common.js/.css` 是旧"数据视图器"残留，已被自研富仪表盘取代，计划重接实时数据源时一并清理或改造为实时渲染器（见 §11.4 / 11.5）。

终态实测：六维均值 **64.0 / C 合格**；告警旗 2 面（令牌复用、AIGC 标识红线，均"需人工确认"）；门禁真探活 pgrep。评分环 == 六维条均值，无假自洽。

> 评分不是装饰：每一维低分都对应一个可执行的造车/整改动作（如版本锁回填 100% 说明部署清单已锁；缺口闭环度经 gaps 真探后由 17 升到 50，抓出"文档过度宣称 G4 已建但 streaming.py 缺失"的真实不一致）。六维评分本身，就是驾驶舱对"整车健康度"的量化表达。

### 10.7 启停与保活（两层）

- **启动**：`bash start_9655.sh` → `http://127.0.0.1:9655/`（HTTP 200）。脚本钉死受管 python 路径、setsid 拉起、写 pidfile。
- **launchd 保活**：`bash install_launchd_9655.sh install` → 复制到 `~/Library/LaunchAgents/com.xiaoqiang.cockpit9655.plist` 并 `launchctl load`（RunAtLoad + KeepAlive，崩溃自拉起）。**沙盒内 `launchctl load` 报 EIO**，需老强在本机 Terminal 执行该脚本。
- **门禁探活坑**：门禁守护进程在 sandbox 会话间会死，仅残留 `/tmp/lti-gate.sock` 死文件 → 探活必须用 `pgrep` 探进程而非判断 socket 文件，否则虚报"门禁运行中"。处置：清死 sock → 按 plist 原样 `/usr/bin/python3 lti-gate-daemon.py --socket /tmp/lti-gate.sock` 后台重启 → 发 `{"ping":true}\n` 验证 PONG → 重跑 `scan_9655.py` 刷新。

### 10.8 红线（造车期确立，防回退）

1. 禁止改动导航屏名（与驾驶舱自身屏名规范逐字一致）。
2. 禁止把富仪表盘改成薄壳。
3. 禁止 `cp -p` 复制符号链接（用 `readlink -f`）。
4. 数据零虚构：`scorecard_data.json` 全部来自 `scan_9655.py` 实扫。

### 10.9 驾驶舱的可诊断性设计原则（造车收口）

驾驶舱不是"好看的面板"，而是"可诊断、可定责"的闭环末端。造车时必须守住三条设计原则：
- **源可溯**：每个数字背后有 `scan_9655.py` 的实扫逻辑，不是手填。
- **变可察**：系统状态一变，仪表应随之变（当前为半实时，见 §11.5 实时化路线）。
- **责可定**：出事能回放（黑匣子 + DTC），能定位到哪一总成、哪一屏、哪一探针。

### 11.5 实时架构：数据变化 → 各屏全面更新

**当前阻断点**：子屏内联静态数据（字节副本，永不更新）；`scorecard_data.json` 靠人工 `scan_9655.py`，无自动刷新。

**目标架构**：
```
[系统内数据变化]
   │  (文件变更 / 连接器调用 / 技能运行 / 进程状态)
   ▼
[聚合探针 scan_9655.py（扩展版）]
   │  探：本机/进程/磁盘 + LawKB卡数 + case-state + 连接器health + 元典余额 + LTI日志 + skills目录
   ▼
[实时数据产物] scorecard_data.json + system_registry.json（智能体/工作流/连接器注册表+健康）
   │
   ├─ 写入磁盘（自动，launchd 每 5–15min 触发）
   └─ 文件监听 / webhook（系统变化时即时触发一次）
   ▼
[各屏 fetch(…?t=now) + 轮询/自动刷新]
   → 打开即最新、定时刷新、变化时秒级更新
```

**落地要点**：
1. **子屏重接**：把 13 个静态副本改为 fetch 9655 实时 JSON 的轻量渲染页（保留视觉风格，但数据走本机探针）；对必须保留富交互的（如模拟法庭、决策树），至少把"数据块"替换为实时拉取。

3. **自动刷新**：launchd 加 `com.xiaoqiang.cockpit9655.scan.plist`（StartInterval 每 N 分钟跑 `scan_9655.py`）；关键事件（如 case-state 变更）可触发即时重扫。
4. **前端轮询**：各屏 JS 内置 `setInterval` 或 `EventSource` 拉取最新 JSON（`cache:no-store` + `?t` 戳破缓存）。
5. **连接器实时性**：D3 连接器 health 优先读 `connector-states`/enabled 状态（无需 token 即可判断连通）；元典余额等需 token 的，走已授权 mcp 或在本地缓存最新值并标注时间戳。
