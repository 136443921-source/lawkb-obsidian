## §1 此轮对话思路总览（沉淀于 2026-09-18）

> 本节把「单机密文版从 0 到 1 实例化 + 功能补全 + 协同 + 跨机交接」整轮工作的**思路与判断**固化，供日后溯源。

### 1.1 起点判断：已验证可建，但尚未实例化

盘点结论——单机密文版的**设计、骨架脚本、推理核心三者均已就绪**，但「律师分身 · 单机密文版」的**专属模板目录原先为空**。它是一套 *"已验证可建、但尚未实例化"* 的系统。
**最高优先级动作 = 把空目录实例化**（生成 README + 方案 + 启动包），消除「有设计无落地」的落差。

### 1.2 四层架构（贯穿全程的设计锚点）

| 层 | 内容 | 部署位置 | 能否出网 |
|---|---|---|---|
| **推理层 M1** | 大模型 API / 本地 Ollama | 客户自选（API 或本机 GPU） | 可外联（可关闭，默认 airgap 友好） |
| **L0 内核层** | 骨架、协议、门禁规则 | 本机 | 否 |
| **L1 人格层** | 律师画像实例、self.md | 本机 + **AES-256 加密** | **绝否** |
| **L2 数据层** | 知识库、案卷、法规库、检索索引 | 本机 + **加密归档** | **绝否** |

> 核心判断：**私有化部署的本质不是"把模型搬到本地"，而是把 L1 人格层与 L2 数据层锁死在本机、把推理层做成可插拔。** 门禁（LTI）**仅律师跑**，助理/实习不持有内核。

### 1.3 实例化决策：活文档格式落地

按老强授权，把方案以**活文档**格式写入空目录 `律师分身系统（单机密文版）/`，产出：
- `README.md` + `01-方案/律师分身（单机密文版）总体方案.md`（活文档，标记 G1–G4 + 闭环 `已建`）
- `启动包/`（`bootstrap.sh` 实例化、`crypto-l1.sh` 加密、`desensitize_check.py` 脱敏门禁、`inference.A.yaml`、`00-启动清单.md`）
- 真实验证跑通，非纸面方案。

### 1.4 功能补全路线（G2 / G3 / G4）

| 项 | 思路 | 落地做法 |
|---|---|---|
| **G2 · LTI 门禁独立进程化** | 门禁不该依赖 WorkBuddy 运行时，须剥离为独立常驻服务 | Unix socket 守护进程封装既有成熟 `lti_gate.py`（**零修改**，airgap 默认开）；配 `com.xiaoqiang.lti-gate.plist` 保活 |
| **G3 · 本地检索 M2（sqlite-vec）** | 离线也能检索，不依赖云端向量库 | `sqlite-vec` 向量索引 + `FTS5 trigram` 中文全文混合检索（RRF 融合）；离线哈希嵌入（可插拔真 SBERT） |

### 1.5 「检索 + 密文」闭环

把 M2 的多源语料（5 个**律师分身**源，显式排除律所）建索引后，用 `crypto-l1.sh` 把 `m2_index.db` 加密归档为 `.L1.tar.gz.enc`，密钥存 macOS 钥匙串。形成 **rebuild → seal → query → verify → status** 闭环，L2 检索产物同样不出本机。

### 1.6 协同与跨机交接（07-协同）

- **协同判断**：单机密文版本质 = 单所有者 + 单机 + L1/L2 本机加密 + 本地门禁；协同须做成「**律师独占加密内核 + 角色分域监督式覆盖层**」，助理/实习只在律师授权、可审计边界内贡献。
- **跨机交接判断**：助理电脑 = 外部未授信端点；安全边界 =（加密交接文件）+（律师单机）。交接文件用「角色密钥」端到端加密，传输通道（USB/微信/邮件/微云）无需保密。落地 `handoff.sh`（init-role / adopt-role / pack / receive / test）+ 交接协议 + MANIFEST 模板。

## §2 关键设计决策（可复用判断）

1. **门禁守护零修改封装**：不重写成熟 `lti_gate.py`，用 daemon 子进程 `subprocess` 调起，降低回归风险；airgap 默认开。
2. **混合检索 RRF 融合**：向量召回 + FTS5 中文全文各出一列，Reciprocal Rank Fusion 融合，兼顾语义与关键词，离线可用。
3. **加密统一基线**：`aes-256-cbc + pbkdf2(iter=600000)`，密钥存 macOS 钥匙串，与 `crypto-l1.sh` / `handoff.sh` 一致，降低密钥管理分叉。
4. **协同不碰形态 B 真多租户/RBAC**：属律所内网版范围，按铁律不在本手册展开；单机密文版协同只做「律师内核 + 角色分域覆盖层」。

## §3 关键踩坑与修复（两个 bug · 已验证）

### 3.1 `m2_secure.sh` 非 ASCII 标点致 unbound variable

- **现象**：脚本报未定义变量，但变量明明已赋值。
- **根因**：`→` / `（）` / `「」` 等非 ASCII 标点**紧贴 `$var`**，本环境 bash 把多字节字符并入变量名，解析错位。
- **修复**：全改 ASCII（`->` / `()` / `""`）。
- **可复用教训**：本环境 shell 脚本中，**`$var` 不得紧贴非 ASCII 标点**。

### 3.2 `handoff.sh` round-trip 间歇性误报（macOS BSD tar）

- **现象**：pack 的 round-trip 校验**间歇性**失败（orig sha != dec sha），但真实 `receive` 能正常解密（纯误报）。
- **根因**：macOS BSD `tar` 默认把 xattr/AppleDouble **临时写回源目录**，污染 `.` 目录 mtime；pack 内**两次** `tar czf`（一次加密、一次算 orig）捕获到不同 mtime → sha 不一致。偶发取决于源目录是否存在 xattr。
- **错误尝试**（记录防止重蹈）：① `gzip -dc | sha256` 比对 → 引入 "trailing garbage" 反全失败；② 解压后比纯 tar 流 → 仍不根治（根因在二次 tar 本身）。
- **根治（已验证 8/8 稳定通过）**：
  1. `export COPYFILE_DISABLE=1` 禁止 xattr/AppleDouble 写回源目录；
  2. **只归档一次** —— `tar czf` 到临时 tar → `openssl enc` 出 `.enc` → `openssl dec` 回比 `cmp -s` **字节级一致** → 通过再保留 `.enc`。
  3. 最终 `.enc` 格式不变（仍是 gzip tar），`receive` 无需改。
- **可复用教训**：tar 归档校验**避免二次 tar**，用「单次归档 + `cmp` 字节比」。

### 3.3 安全事项（必须记）

- 验证用的 `assistant` 角色密钥**已在验证后吊销**（口令曾现 transcript）。真用须重新 `init-role` 生成新密钥。
- 律所分身误投文件（`MEMO-LAWFIRM-AVATAR-DEPLOY-A`）已**隔离**至 `/tmp/lawtwin_quarantine_*`，未删除，待老强定夺；不并入本手册。
