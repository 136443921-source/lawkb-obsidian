# 🛠 律所分身 · 缺口技能建设方案（待审核）

> **状态：待老强审核**。本方案为《总纲备忘录》§6 缺口清单（P0×8 / P1×7 / P2×1）的落地规划。**审核通过前不建任何技能骨架**。
> 配套纲领：[[中小律所数字分身系统总纲备忘录|总纲备忘录]]（四化成熟度 / 缺口清单来源）。

---

## 0. 背景与建设原则

**背景**：总纲备忘录四化评估显示——带教成长快（45）、人走资产在闭环（58）、经验可沉淀闭环（58）是最大短板；其余三化有底座，缺口集中在"**流程自动化 + 度量**"，并非从零造。

**建设总原则（护栏，任何技能不得突破）**：
1. **数据不出所**：所有脚本本地优先；备份落自托管（内网 Gitea/NAS），绝不上第三方云。
2. **LTI 门禁**：涉及文书/卡片的技能，入库或出文前强制过 LTI（REJECT=0）。
3. **六-B 铁律**：先备份再动手、批量前 dry-run、改后幂等确认、零残留验证。
4. **不代点 UI / 不落地令牌明文**；令牌需 UI 重新授权。
5. **复用优先**：每个技能先挂现有底座（LawKB git / D5 权限 / LTI / 飞轮拆卡流水线），只补缺失环节。
6. **每个技能标准化交付**：`SKILL.md`（含 frontmatter + 触发词 + 依赖 + 红线）+ 配套脚本 + 自测 + 回写总纲备忘录 §6 与变更日志。

---

## 1. 建设批次（建议 3 批）

| 批次 | 范围 | 解决四化 | 紧急度 |
|---|---|---|---|
| **Batch 1** | 数据不出所护栏 ＋ LawKB 加密自托管备份 | 数据不出所 ＋ 人走资产在（底线） | 🔴 最急 |
| **Batch 2** | 新人接入 LawKB SOP ＋ 离职知识交接单自动化 | 人走资产在（人事闭环） | 🟠 高 |
| **Batch 3** | 案件结案复盘卡 ＋ 沉淀质量门禁 ＋ 带教看板 ＋ 能力矩阵 SOP | 经验可沉淀 ＋ 带教成长快 | 🟡 中 |

> 顺序逻辑：先守住房产不丢/不外泄（Batch 1），再堵人走知识走的流程断点（Batch 2），最后补沉淀与带教的运营闭环（Batch 3）。

## 2. P0×8 技能设计卡（详细，待审核核心）

### 2.1 数据不出所护栏（P0 · Batch 1）
- **触发词**：外发/上传/粘贴前 PII 拦截；"帮我检查会不会泄露"；"脱敏校验"
- **输入**：待外发的文本/文件/粘贴板内容；或连接器调用前的 payload
- **输出**：命中清单（案号/身份证/姓名/手机号/银行卡）+ 红脱后文本；git pre-commit 阻断报告
- **依赖**：现有 `desensitize_check.py`（MOD 11-2 / Luhn / 信用代码校验位）
- **配套脚本**：`pii_guard.py`（① 手动扫描命令 ② git pre-commit hook ③ 连接器发送前钩子）
- **红线**：不得为绕过加 `desensitize:ignore`；假阳性先问"是不是放错层"
- **验收**：对含真实案号样本拦截率 100%，假阳性可人工复核

### 2.2 LawKB 加密自托管备份（P0 · Batch 1）
- **触发词**："备份 LawKB" / "加密备份" / "定时备份"
- **输入**：LawKB git repo；自托管远端地址
- **输出**：`lawkb-<date>.bundle.gpg`（AES-256 加密包）→ 推送内网 Gitea/NAS
- **依赖**：LawKB git；`openssl`/`gpg`；内网目标（**需你提供 Gitea 地址/NAS 路径/密钥管理偏好**）
- **配套脚本**：`lawkb_encrypted_backup.sh` + LaunchAgent/cron 自动化（每日增量）
- **红线**：绝不上第三方云；密钥不入库；本地密钥文件 `0600`
- **验收**：模拟机毁 → 从 .gpg 恢复成功，资产零丢失

### 2.3 新人接入 LawKB SOP（P0 · Batch 2）
- **触发词**："新同事入职" / "接入 LawKB" / "onboarding"
- **输入**：新人姓名/角色（主任/律师/助理/IT运维）
- **输出**：克隆指引 + rbac 角色分配 + onboarding 卡 + 导师配对
- **依赖**：`rbac.js` 角色模型；lawtwin-open 模板
- **配套脚本**：`onboard_lawkb.sh`（生成账号/角色/目录骨架）+ onboarding 卡模板
- **红线**：角色按最小权限；导师配对写入 hub `02-当前项目/`
- **验收**：新人按 SOP 30 分钟内可 clone + 分配到角色 + 收到 onboarding 卡

### 2.4 离职知识交接单自动化（P0 · Batch 2）
- **触发词**："XX 离职" / "离职交接" / 接 D5 清除
- **输入**：离职人账号；D5 权限中心
- **输出**：交接清单（在办案件 / 未结卡 / 个人叠加层）→ 重分配门禁 → 阻断未结再清除
- **依赖**：D5 离职清除 UI（已在线 200）；`rbac`；`case-state.json`
- **配套脚本**：`offboard_checklist.py`（扫描在办+未结+署名卡 → 生成交接单 → 校验重分配完成）
- **红线**：未结事项清零前不得清除账号；个人 L1 叠加层随人走，所级资产留存
- **验收**：有未结案件时 D5 清除被门禁拦截，生成交接单

### 2.5 案件结案复盘卡自动化（P0 · Batch 3）
- **触发词**："案子结了" / "结案复盘" / `case-state→closed`
- **输入**：`case-state.json` 状态变 closed
- **输出**：自动萃取裁判规则卡 + 审判要件卡 + 经验卡 → 过 LTI → 入 `06-沉淀`
- **依赖**：案件生命周期大屏 `case-state`；三条拆卡流水线；LTI 文本监控器
- **配套脚本**：`case_closed_harvest.py`（监听 closed → 调拆卡流水线 → LTI 校验 → 入库）
- **红线**：萃取须过 LTI（REJECT=0）；当事人信息脱敏
- **验收**：1 个 closed 案件自动产出 ≥1 张合规卡入 06-沉淀

### 2.6 沉淀质量门禁流水线（P0 · Batch 3）
- **触发词**："入库质检" / "沉淀门禁" / 卡片入库前
- **输入**：待入库卡片（md）
- **输出**：LTI + 冲突仲裁 + 一致性审计三联报告；FAIL 阻断
- **依赖**：LTI 文本监控器；`lawkb-conflict-arbitration`；`lawkb-legal-consistency-audit`
- **配套脚本**：`ingest_gate.sh`（串联三门禁，FAIL 即阻断，禁白名单跳过）
- **红线**：门禁不可加白跳过；命中先定位是否放错层
- **验收**：含错误法条的卡被拦截，合规卡放行

### 2.7 带教看板（P0 · Batch 3）
- **触发词**："带教看板" / "学员进度" / 挂 9360 D6/P
- **输入**：学员任务流 / 导师批注 / 红蓝复核记录
- **输出**：统一可视化看板（mentoring board），挂 9360 子屏
- **依赖**：9360 cockpit 子屏机制（`subapps/`）；现有角色化看板
- **配套脚本**：`subapps/mentor/` 看板 HTML（本地 `127.0.0.1`）
- **红线**：仅所内回环；不含当事人 PII
- **验收**：9360 内可打开看板，学员/导师/红蓝状态实时可见
- **⚠ 待你拍板**：挂 D6 治理席 还是 P 专项屏

### 2.8 实习律师能力矩阵 SOP（P0 · Batch 3）
- **触发词**："能力矩阵" / "实习律师评估" / 月季成长报告
- **输入**：学员训练记录 / 红蓝战报 / 文书过 LTI 记录
- **输出**：3/6/12 月能力项达标表 + 成长报告
- **依赖**：`rbac` 角色；可对接带教看板数据
- **配套脚本**：能力矩阵模板（md 表）+ `capability_report.py`（聚合记录 → 报告）
- **红线**：评估基于可观测记录，不主观打分
- **验收**：输入 3 个月记录 → 输出达标/缺口报告
