## §1 本手册解决什么问题

### 1.1 与 03-克隆迁移SOP 的分岔点

`03-克隆迁移SOP` 的 Step 4 写着：「涉密业务主导所 → **步骤 4 改为私有部署**」，但**没有展开**。本手册就是那个展开。

```
                 ┌─ 客户接受数据出所（用公有云连接器）→ 走 03-克隆迁移SOP 标准流程
开始部署 ────────┤
                 └─ 客户要求数据不出所 / 涉密 / 内网隔离 → 走本手册 ↓
```

### 1.2 核心原则（先看懂再动手）

> **私有化部署的本质不是"把模型搬到本地"，而是把 L1 人格层与 L2 数据层锁死在客户内网、把推理层做成可插拔。**

| 层 | 内容 | 部署位置 | 能否出网 |
|---|---|---|---|
| **推理层** | 大模型 API / 本地模型 | 客户自选（API 或内网 GPU） | 可外联（若选 API） |
| **L0 内核层** | 骨架、协议、门禁规则 | 客户内网 | 否 |
| **L1 人格层** | 律师画像实例、self.md | 客户内网 + 加密 | **绝否** |
| **L2 数据层** | 知识库、案卷、法规库 | 客户内网 | **绝否** |

### 1.3 ⚠️ 成熟度诚实声明（别把规划当现货）

| 组件 | 状态 | 说明 |
|---|---|---|
| 模板骨架克隆 | ✅ **立即可用** | `clone-lawtwin.sh` 已可跑，见 §4 |
| 脱敏门禁 | ✅ **立即可用** | `desensitize_check.py` 已可跑，见 §9 Step 9.3 |
| 技能安装与版本锁 | ✅ **立即可用** | 见 §6 |
| 人格层加密封装 | ✅ **立即可用** | 见 §8，已有 openssl+钥匙串方案 |
| **推理层适配** | ✅ **已交付 v0.1.0** | M1 推理适配层已编码，代码在 `~/lawtwin-open/core/`，含 CLI 与 12 项离线自检 |
| **LTI 门禁独立进程化** | ⚠️ **待建设** | 当前门禁依托 WorkBuddy 运行时，尚未剥离为独立服务 |

## §2 部署形态三选一（第一步必须先做）

### 2.1 决策树

```
Q1: 客户是否允许任何数据出所？
 ├─ 否（涉密/政府/军工/强监管）──────────────→ 【C · 涉密隔离版】
 └─ 是 → Q2
        Q2: 使用规模？
         ├─ 1–20 人、单机或单终端 ──────────→ 【A · 单机密文版】
         └─ 20+ 人、多终端、需共享知识库 ──→ 【B · 律所内网版】
```

### 2.2 三形态对照

| 维度     | A · 单机密文版                    | B · 律所内网版              | C · 涉密隔离版           |
| ------ | ---------------------------- | ---------------------- | ------------------- |
| 典型客户   | 个人律师 / 5–20 人小所              | 20–100 人所              | 政府、国企法务、涉密单位        |
| 推理     | 客户自有 API；或本地 Ollama **降级模式** | 内网 GPU（vLLM）或统一 API 网关 | 完全离线本地模型（须 GPU 服务器） |
| 检索     | SQLite + sqlite-vec          | Qdrant / Milvus 独立部署   | 本地向量库 + 加密卷         |
| 法条核验   | 本地法规库快照 + 可选 pkulaw          | 本地镜像 + 法宝/元典账号         | 预置快照 + **U 盘增量更新**  |
| 外联     | 允许（可关闭）                      | 白名单                    | **零外联**             |
| 交付周期   | 1–2 周                        | 4–8 周                  | 8–16 周              |
| **建议** | **⭐ 先做这个**                   | A 跑通 10 家后再接           | 现阶段不碰（要资质/等保/驻场）    |
|        |                              |                        |                     |

> **选型建议**：先做 A。决策链最短（一个合伙人拍板即可）、不碰客户 IT 环境、跑通后有案例才好谈 B 的预算。

## §3 Phase 0 · 部署前置（不完成不许往下走）

### Step 0.1 硬件核验

**操作**：
```bash
# macOS
sysctl -n machdep.cpu.brand_string; system_profiler SPHardwareDataType | grep -E "Memory|Chip"
# Linux
lscpu | grep "Model name"; free -h; df -h /
```

**验收点**：对照下表确认形态可行。

| 形态 | CPU/RAM 最低 | 磁盘 | GPU |
|---|---|---|---|
| A（API 模式） | 4 核 / 8 GB | ≥ 50 GB 可用 | 不需要 |
| A（本地模型） | 8 核 / **32 GB**（16 GB 只够 7B Q4 降级） | ≥ 80 GB | 建议 |
| B | 服务器 16 核 / 64 GB | ≥ 500 GB | **必需**（≥24GB 显存） |
| C | 物理机 32 核 / 128 GB | ≥ 1 TB | **必需**（≥48GB 显存） |

**失败处置**：
- 内存 16 GB 却要求本地全功能模型 → **明确告知客户这是降级模式**，幻觉率会上升，须把 LTI 门禁阈值调严（见 Step 7.1）。**不要承诺本地全功能。**

### Step 0.2 网络与白名单确认

**操作**：向客户 IT 索取以下信息并填入部署记录表：

| 项 | A | B | C |
|---|---|---|---|
| 出网是否允许 | 是 | 白名单 | **否** |
| 需放行的域名 | 推理 API 域名 | + 法条源域名 | 无 |
| 是否需要代理 | 视客户 | 视客户 | 无 |

**验收点**：拿到客户 IT 的**书面**网络策略确认（邮件即可）。

**失败处置**：客户拒不提供 → 默认按最严（形态 C）部署，避免中途返工。

### Step 0.3 账号与授权清单

**操作**：逐项确认，缺一项不许开工。

- [ ] 客户推理 API Key（或已备 GPU 服务器）
- [ ] 客户法条源账号（pkulaw / 华宇元典）——**可选**，离线则用本地快照
- [ ] 客户律所名、负责人姓名（用于占位符替换）
- [ ] 客户明确的高频试点案由 1 个（如合同/工伤/交通事故）
- [ ] 部署记录表（模板见 §10 Step 10.3）已建

**验收点**：以上 5 项全部打勾。

### Step 0.4 建立备份基线（六-B 铁律）

**操作**：
```bash
STAMP=$(date +%Y%m%d-%H%M%S)
mkdir -p /tmp/lawtwin_deploy_${STAMP}
cp -n -R <客户知识库路径> /tmp/lawtwin_deploy_${STAMP}/ 2>/dev/null
echo "备份完成: /tmp/lawtwin_deploy_${STAMP}"
```

**验收点**：`ls /tmp/lawtwin_deploy_${STAMP}` 有内容且字节数与原目录量级一致。

**失败处置**：备份失败 = **立即停止部署**。没有回滚基线的操作一律不许做。

## §5 Phase 2 · 推理层配置

> ✅ **M1 推理适配层已于 2026-09-17 交付（v0.1.0）**，代码在 `~/lawtwin-open/core/`。
> 本章步骤已更新为**可直接执行的命令**，`inference.yaml` 抽象层不再是规划态。
> 特性：零第三方依赖（客户内网装不了 pip 包也能跑）、Python 3.8+ 兼容、
> 明文密钥硬拦截、零外联策略硬门禁、主备自动降级并标记 `degraded`。
> 详细说明见 `~/lawtwin-open/core/README.md`。

### Step 2.1 选定推理后端

**操作**：按形态选择并登记：

| 形态 | 后端 | 配置方式 |
|---|---|---|
| A | 客户自有 API（DeepSeek/通义/智谱） | 填 base_url + key |
| A 降级 | 本地 Ollama（qwen2.5:14b-instruct-q4_K_M） | `http://127.0.0.1:11434/v1` |
| B | 内网 vLLM（Qwen2.5-32B） | 内网地址 |
| C | 本地模型（离线） | 本地地址，**无任何外网调用** |

**验收点**：部署记录表中「推理后端」一栏已填且客户签字确认。

### Step 2.2 填推理配置

**操作**：从 M1 骨架拷贝对应形态的样板，按客户环境修改：

```bash
cd ~/lawtwin-open/core
cp examples/inference.A.yaml inference.yaml    # 按形态选 A / B / C
$EDITOR inference.yaml                          # 填 base_url、model、network.mode
```

配置契约（密钥只写环境变量名，**值绝不落盘**）：

```yaml
provider: openai_compatible
base_url: "<客户内网或 API 地址>"
api_key_env: LAWTWIN_API_KEY      # 从环境变量读，不落盘
model: "<模型名>"
fallback:
  enabled: true
  base_url: "http://127.0.0.1:11434/v1"
  model: "qwen2.5:14b-instruct-q4_K_M"
  note: "降级模式，LTI 门禁自动收紧阈值"
network:
  mode: allow_external            # A=allow_external / B=whitelist / C=airgap
```

**校验**（不联网，纯静态检查，含明文密钥扫描与网络策略门禁）：

```bash
./lawtwin-infer validate --config inference.yaml
```

**验收点**：退出码 0，输出中不含明文密钥。

**失败处置**：
- `PlaintextKeyError`（退出码 2）→ 配置里写了 `api_key:` 等明文字段，**已被硬拒绝**。改用 `api_key_env` 引用环境变量。
- `NetworkPolicyError` → 后端地址违反当前 `network.mode`。C 形态只允许回环/`10.`/`172.16-31.`/`192.168.`；确需外联请改 `whitelist` 并登记域名（须客户管理员确认）。
- 提示「环境变量未设置」→ `export LAWTWIN_API_KEY=<密钥>` 后重启进程。

### Step 2.3 连通性测试

**操作**：先跑离线自检（不需要任何后端），再做连通性测试：

```bash
cd ~/lawtwin-open/core
./lawtwin-infer selftest                        # 12 项断言，确认骨架代码完好
export LAWTWIN_API_KEY=<客户密钥>                # 密钥只进环境变量
./lawtwin-infer check --config inference.yaml   # 主备逐个探活 + 列模型
./lawtwin-infer chat --config inference.yaml --prompt "简述表见代理的构成要件"
```

> `selftest` 的意义：把「环境没配好」和「代码有问题」两类故障分开。
> 客户现场开工前先跑它，能省掉大量扯皮。

**验收点**：
- `selftest` 输出「12 通过 / 0 失败」
- `check` 至少一个后端 ✅
- `chat` 收到非空、符合法律语境的回复（不是通用闲聊）

命中 fallback 时会显示「⚠️ 降级模式」并提示 LTI 按 `lti_strict` 收紧阈值 —— 这是**预期行为**，不是故障。

**失败处置**：

| 现象 | 处置 |
|---|---|
| 401/403 | Key 无效或未授权，**重新申请**（不代点 UI，由客户管理员操作） |
| 超时 | 检查白名单/代理/内网 DNS；可调大 `timeout_seconds` |
| 返回乱码 / 404 | `./lawtwin-infer list-models --config inference.yaml` 核对模型名 |
| airgap 下访问公网 | 被**硬拦截**（预期行为）；确认形态是否为 C，确需外联改 `whitelist` 并登记域名 |
| 全部后端失败 | 看异常输出里的 `attempts` 逐条定位；`--json` 可导出结构化结果 |

## §7 Phase 4 · 连接器配置

### Step 4.1 连接器分级

| 连接器 | 必需性 | 私有化说明 |
|---|---|---|
| 法条源（pkulaw / 华宇元典） | **核心** | 离线时用本地法规库快照兜底 |
| 知识库后端（IMA 等） | 可选 | **形态 C 禁用** |
| 邮箱 | 可选 | 视客户是否需文书送达 |
| 网盘备份 | 可选 | **形态 C 禁用** |

### Step 4.2 重授权铁律

**操作**：在**客户自己的 WorkBuddy** 连接器页重新授权。

**验收点**：`enabled=true` 且能实际调用成功。

**失败处置**：
- ⚠️ **跨所令牌不可复用**：旧所令牌不迁移、不复制，否则调用必失败或串所。
- 授权失败 → 由客户管理员操作（**AI 不代点 UI**）。

### Step 4.3 离线降级路径（形态 C 必做）

```
查询法条
 ├─ 命中本地权威缓存 → 直接返回，标注核验日期
 ├─ 未命中 + 有外联 → 实时核验 → 回写本地缓存
 └─ 未命中 + 无外联 → 标 statute_text_pending，LTI 按未回源处理，禁止引为文档源
```

**验收点**：断网状态下投一个法条问题，返回 `statute_text_pending` 而非编造条文。

> 🔴 **这条是红线**：宁可标 pending，也绝不让模型凭记忆编法条。

## §8 Phase 5 · 人格层注入（L1）

### Step 5.1 生成客户 profile 实例

**操作**：
```bash
cp templates/example.lawyer.profile.yaml <客户所>.profile.yaml
$EDITOR <客户所>.profile.yaml
```

**验收点**：填入客户真实的 `display_name` / `firm` / `seat_role` / `practice_areas`。

### Step 5.2 生成 self.md

**操作**：
```bash
./combine.sh templates/<客户所>.profile.yaml
```

**验收点**：`lawyer-yourself-skill/self.md` 内容已更新为客户端信息。

**失败处置**：改了 profile 却没重跑 combine → 下次刷新会被覆盖（**Fix-the-source 铁律**）。

### Step 5.3 人格层加密封装

**操作**（源所已验证的方案）：
```bash
PWD_RAW=$(/usr/bin/openssl rand -base64 32)
security add-generic-password -a "$(id -un)" -s "lawtwin-l1-<客户所>" -w "$PWD_RAW" -U
COPYFILE_DISABLE=1 tar czf - -C <staging> . \
  | /usr/bin/openssl enc -aes-256-cbc -pbkdf2 -iter 600000 \
      -out "<客户所>.L1.tar.gz.enc" -pass env:PWD_RAW
```

**验收点**：
1. 密文文件生成且权限 600
2. **必须做 round-trip 解密验证**，比对 sha256 与原文件一致
3. 密码已存入钥匙串，**不在对话/日志中打印明文**

**失败处置**：解密验证不一致 → **废弃重做**，不许交付未验证的加密包。

## §9 Phase 6 · 知识层导入（L2）

### Step 9.1 分层裁剪（不许整包给）

| 层 | 内容 | 是否交付 |
|---|---|---|
| 通用规则包 | 检索纪律、文书格式、通用证据规则 | ✅ |
| 行业规则包 | 人伤 / 合同 / 慈善 / 医疗 专项卡族 | ✅ 按订阅 |
| 客户私有层 | 客户案卷、模板、裁判规则 | ✅ 留客户内网 |
| **源所私有层** | 老强决策日志、办案笔记、当事人信息 | 🚫 **绝不交付** |

### Step 9.2 导入本地法规库

**操作**：导入离线法规快照，记录**快照日期与核验日期**。

**验收点**：能离线检索到常用法条且带条号。

### Step 9.3 脱敏门禁扫描（对外交付前必须跑）

**操作**：
```bash
python3 tools/desensitize_check.py <待交付目录> --strict
```

**验收点**：**退出码 0**（零 HIGH/MEDIUM/LOW 命中）。

**失败处置**：
- 有命中 → 逐个处置。**豁免标记 `desensitize:ignore` 不该用来掩盖"放错层"的文件**——含真实人格数据或案号的文件，问题是"它不该在这里"，应移出而非开白名单。
- **已知边界**：姓名只能名单匹配（名单质量=检测质量）；住址/开户行/金额未覆盖；**图片与 PDF 扫描件完全检测不到**，开仓前须人工过一遍。

## §10 Phase 7 · 门禁校准与试点验证

### Step 10.1 LTI 门禁自检

**操作**：投一段含已知错误的测试文本，确认门禁能拦。

**验收点**：R（法条真实）/ L（法理逻辑）/ C（一致性）/ T（溯源）/ P（程序）五维均返回判定；`R101`（条号越界）、`C301`（金额硬矛盾）能阻断。

**失败处置**：
- 本地降级模式下幻觉率上升 → **调严阈值**，宁可多拦不可漏放。
- 门禁依赖云端 → 违反私有化承诺，**回退重配**。

### Step 10.2 跑通 SOP-03 全链路

**操作**：选客户 1 个高频试点案由，跑：起草 → 蓝队 → 红队 → LTI → 交付。

**验收点**：全链路通，**LTI REJECT=0**。

**失败处置**：REJECT>0 → 逐项整改至 0 才准交付。**REJECT 不为 0 的文书不许出门。**

### Step 10.3 交付与留痕

## §12 故障排查速查

| 症状 | 可能原因 | 处置 |
|---|---|---|
| 克隆脚本报「源模板不存在」 | 源路径错 | `--src` 指定正确路径 |
| 替换后仍有 `[律所名]` | 替换未覆盖新文件 | 重跑 `--replace`，再 grep 校验 |
| 分诊无响应 | `legal-base` 基座缺失 | 装 legal-base 1.3.0 |
| 法条返回编造内容 | 未走本地核验 | 检查 statute 缓存，确认 pending 机制生效 |
| API 401/403 | Key 无效 | 客户管理员重新申请（不代点 UI） |
| 本地模型幻觉率高 | 显存/量化过低 | 调严 LTI 阈值，或改 API 模式 |
| 门禁 REJECT>0 | 文书质量问题 | 整改至 0，不许放行 |
| 解密失败 | 参数不一致 | 核对 `-aes-256-cbc -pbkdf2 -iter 600000` 三参数 |

## §14 合规红线

1. **数据不出所**：L1/L2 层永不外传；形态 C 零外联。
2. **不编法条**：离线未回源一律标 `statute_text_pending`，禁止引为文档源。
3. **令牌不复用不打印**：跨所重新授权；AI 不代点 UI、不打印令牌明文。
4. **AIGC 标识**：AI 生成草稿保留水印/元数据标识。
5. **备案边界**：纯内网使用一般不触发备案义务；**一旦对客户以外第三方开放，须走备案+安全评估**——合同里必须写明这条边界。
6. **执业责任**：AI 输出为辅助草稿，律师对最终成果独立负责。
