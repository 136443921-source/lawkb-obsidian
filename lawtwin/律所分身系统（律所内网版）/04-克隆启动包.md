# 04-克隆启动包 · 律所数字分身模板分发清单 v1.0

> 配套：03-克隆迁移SOP（操作细节）、02-skills-manifest（版本锁）、README（隔离规则）。
> 定位：把 `lawtwin-open/` 整库打包成一份"开箱即用"的启动包，目标所拿到后**发目录 + 跑脚本**即可起步。

---

## 一、启动包包含什么

| 文件 | 作用 | 是否含隐私 |
|---|---|---|
| `README.md` | 隔离规则 + 入库清单 + 命名约定 | 否 |
| `00-总体方案.md` | 总体方案（架构/能力/路线图/成本/护栏） | 否 |
| `01-SOP手册.md` | 7 大日常运营 SOP | 否 |
| `02-skills-manifest.md` | 技能安装清单 + 版本锁基线 | 否 |
| `03-克隆迁移SOP.md` | 跨所克隆迁移流程 | 否 |
| `clone-lawtwin.sh` | 一键克隆脚本骨架 | 否 |

> ✅ 整个启动包**仅含方法论 / 模板 / 方案**，不含任何案件卷宗或当事人数据，可安全外发。

## 二、分发方式（任选）

1. **整目录拷贝**：把 `lawtwin-open/` 整个文件夹发给目标所（U 盘 / 网盘 / git 子仓）。
2. **git 分发**：源所建 `lawtwin-open` 公开仓，目标所 `git clone` 后对齐版本。
3. **IM 直发**：压缩 `lawtwin-open/*.md` + `clone-lawtwin.sh` 发目标所管理员。

> 分发时**只发本启动包**，不要把源所 `小强律师数字分身系统/` 或个人记忆一并带出。

## 三、目标所起步（三步）

```bash
# 1) 预览（默认 dry-run，不写入）
bash clone-lawtwin.sh /path/to/新所库

# 2) 确认无误后真正复制
bash clone-lawtwin.sh /path/to/新所库 --apply

# 3) 复制并替换占位符（所名/负责人）
bash clone-lawtwin.sh /path/to/新所库 --apply --replace --firm "正明律师事务所" --lawyer "王律师"
```

## 四、脚本安全骨架（要点）

- **默认 dry-run**：不加 `--apply` 只预览，绝不改写任何文件。
- **`cp -n` 防覆盖**：目标所已有同名文件不被覆盖，安全幂等。
- **占位符替换显式开启**：须 `--replace` + `--firm` 才执行，且只替换 `[律所名]/[律师名]`。
- **仅复制 `.md`**：方法论文件，天然不含案件数据。
- **自包含**：复制时连带本脚本一起拷，目标所可直接二次分发。

## 五、分发检查清单

- [ ] 启动包仅含 6 项（README/00/01/02/03/脚本），无当事人数据
- [ ] 目标所收到后先 `dry-run` 预览，确认路径正确
- [ ] `--apply` 复制成功，目标所库出现同名文件
- [ ] 占位符替换后 grep 无残留 `[律所名]`
- [ ] 目标所按 03-克隆迁移SOP 完成技能安装 + 版本对齐 + 连接器重授权 + 隔离 README
- [ ] 试点案由闭环通过，LTI REJECT=0

## 六、与迁移 SOP 的关系

`03-克隆迁移SOP` 是**操作规范**（为什么这样做、避哪些坑）；本启动包是它的**工程化落地**（一条命令把骨架落到目标所）。两者配合：脚本负责"搬过去"，SOP 负责"装起来、跑通"。

> 启动包随模板演进：新增模板文件时，同步更新本清单「一、启动包包含什么」与 README 入库清单。
