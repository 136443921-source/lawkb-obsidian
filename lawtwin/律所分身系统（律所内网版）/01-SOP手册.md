# 中小律所数字分身模板 · SOP 手册 v1.0

> 使用说明：本手册是模板的"操作说明书"。每条 SOP 含【目的 / 适用范围 / 角色 / 步骤 / 检查清单 / 输出物 / 常见错误】。克隆后替换 `[律所名]/[律师名]` 即可直接用。所有写入型操作遵守《六-B 铁律》（先备份、先排查、再批量、dry-run、幂等确认）。

---

## SOP-01 部署与初始化

**目的**：在 2 周内搭起可启动的数字分身骨架。
**角色**：管理员（合伙人兼）。

**步骤**
1. 建目录骨架（见总体方案 §4），复制 `99-脚本/`。
2. 安装 P0 技能：legal-consult-router、lawyer-yourself-skill、LTI 文本监控器。
3. 配置连接器：IMA 知识库、邮箱、华宇元典（按量授权）。
4. 全局替换占位符 `[律所名]` → 本所名。
5. 写 `00-全局规则/共享记忆协议` 与 `_索引.md`。

**检查清单**
- [ ] 目录骨架存在且 `99-脚本` 可执行
- [ ] legal-consult-router 能分诊（投一个测试法律问题）
- [ ] 连接器 `enabled=true` 且能调用
- [ ] 占位符已替换

**输出物**：可启动的系统 + `共享记忆协议.md`。
**常见错误**：跳过全局规则直接装技能 → 后续冲突无仲裁依据。

## SOP-02 知识入库（卡片化）

**目的**：把判例、要件、经验变成可检索、可演进的卡。
**角色**：助手（知识入库）。

**步骤**
1. 取源：从裁判文书网/元典/本所卷宗提取素材，**仅引权威源**，否则标 `statute_text_pending`。
2. 定卡型：裁判规则卡 / 审判要件卡 / 经验卡 / 文书范式卡 / 合规审查卡。
3. 填 frontmatter：card_type、rule_id（R-* 取号脚本）、status、updated。
4. 落库：写入对应子目录（`06-沉淀/` 或 `02-提炼/`）。
5. 查重：写回前用 `write_back.py` 查重，存在则更新不新建。
6. LTI 校验：法条段须"元典核填·现行有效"，无凭记忆灌条文。

**检查清单**
- [ ] 每条法条可回源（T 维度）
- [ ] rule_id 无同号冲突
- [ ] 已查重、未生成近似重复卡
- [ ] 当事人隐私未入卡（仅方法论）

**输出物**：入库卡片 + 飞轮日志。
**常见错误**：凭记忆写条文正文 → 触发 LTI REJECT，须回填权威源。

## SOP-03 文书生产（起草 → 红蓝 → LTI → 交付）

**目的**：产出经得起对抗、达标可交付的法律文书。
**角色**：起草律师 + 蓝队 + 红队 + 管理员（门禁）。

**步骤**
1. 起草：用文书范式卡 + 红蓝复核工作流产出初稿。
2. 蓝队体检：防御完整性（逻辑断层/证据链/法官视角）。
3. 红队攻击：预驳回（四维度：逻辑/法理/证据/程序）。
4. LTI 门禁：R/L/C/T/P 五维 QC，**REJECT=0 才准交付**。
5. 导出：DOCX 带修订标记 + 干净签字版双轨。
6. 归档：本地归档 + 腾讯文档 + IMA 回传，双目录同步。

**检查清单**
- [ ] 红蓝两轮已留痕
- [ ] LTI REJECT=0
- [ ] 案号/名称/金额三处一致（C301）
- [ ] DOCX 双轨 + 剔除 AI 内部附注标记

**输出物**：签字版 DOCX + 修订标记版 + 归档记录。
**常见错误**：跳过红队直接交付 → 庭上暴露漏洞；LTI 未过先发 → 格式/法条翻车。

## SOP-04 案件生命周期管理

**目的**：案件状态可观测、可追溯。
**角色**：承办律师 + 管理员。

**步骤**
1. 建案：在 `02-当前项目/` 建案件页，写 `case-state.json`（单一事实源）。
2. 更新：每关键节点（立案/举证/开庭/判决）更新状态。
3. 刷新：案件生命周期大屏扫描 `case-state.json` 生成内网全量大屏 + 对外脱敏简报。
4. 结案：触发结案沉淀自动化，经验回写 `06-沉淀/`。

**检查清单**
- [ ] case-state.json 为唯一事实源，无多份冲突
- [ ] 大屏与简报数据一致
- [ ] 结案经验已回写

**输出物**：案件页 + 大屏 + 结案经验卡。
**常见错误**：多处记状态 → 大屏与实际不符；结案不沉淀 → 经验流失。

## SOP-05 红蓝对抗与模拟庭审

**目的**：出庭前预驳回，降低败诉率。
**角色**：蓝队（防御）、红队（攻击）、书记员、战情室观察员。

**步骤**
1. 启动：模拟法庭主控协调器归案源（默认对话内材料优先）。
2. 定向：程序类型/审级/我方立场。
3. 推演：蓝队准备 → 红队三轮冲击 → 法官心智（审判要件卡正向裁判规则）浮层。
4. 记录：书记员出庭审笔录/证据台账/争点-证据映射三件套。
5. 复盘：庭审战情室出战报（红蓝优缺点 + 优化建议）。
6. 回写：推演结论与漏洞清单回写知识飞轮。

**检查清单**
- [ ] 到庭/纪律/证据状态机已驱动
- [ ] 三轮冲击留痕
- [ ] 战报含红蓝双方优化建议

**输出物**：庭审记录 + 判决书/裁决书草案 + 战报。
**常见错误**：只走蓝队不红队 → 无预驳回价值；推演结论不回写 → 重复踩坑。

## SOP-06 日常运维（摄入 / 周报 / 体检）

**目的**：系统持续自进化、可观测、无腐化。
**角色**：管理员 + 自动化。

**步骤**
1. 每日摄入（08:30）：5 库 × 3 篇/日，LTI 缓存兜底，拒绝凭记忆灌条文。
2. 周报（周五 17:00）：案件进展 + 飞轮增量 + 风险项。
3. 体检（每月）：lawkb-legal-consistency-audit 法条一致性 + 编号冲突门禁。
4. 自学习：周日 self-improve + 链接刷新，沉淀机制优先于一次性答案。

**检查清单**
- [ ] 摄入配额达标且来源权威
- [ ] 周报已生成并归档
- [ ] 体检无 REJECT、无同号冲突

**输出物**：周报 + 体检报告 + 飞轮日志。
**常见错误**：摄入用记忆代替权威源 → 知识库失真；长期不体检 → 撞号/矛盾积累。

## SOP-07 安全与合规

**目的**：守住数据、权限、交付三道红线。
**角色**：全员 + 管理员（门禁）。

**步骤**
1. 写入前备份：`cp -n` 防覆盖 + 时间戳备份至 `/tmp` 或等价隔离区。
2. 批量前 dry-run：确认非误报、确认幂等，再执行。
3. 连接器门禁：调用前确认 `enabled=true`；令牌过期走 UI 重新授权，**不代点、不打印**。
4. 隐私隔离：当事人证件/银行卡/手机号/证据原件禁入知识库，只提炼方法论。
5. 交付门禁：LTI REJECT=0 才准交付；草稿态/待校验须加粗重点提醒。
6. 冲突仲裁：中枢 > 原生 memory > 聊天记录 > 会话上下文；冲突以中枢覆盖并记日志。

**检查清单**
- [ ] 所有写入型操作有备份/回滚
- [ ] 批量操作确认幂等、零残留
- [ ] 连接器 enabled 且令牌有效
- [ ] 隐私未泄露入库
- [ ] 交付物 LTI REJECT=0

**输出物**：备份记录 + 门禁日志 + 冲突处理记录。
**常见错误**：无备份直接重建单源文件 → 一旦出错不可恢复；令牌明文落文档 → 安全事故。
