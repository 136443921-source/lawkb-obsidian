# 第 7 章 · 造记忆母舰｜所有系统共用的"总记忆"

> **你要准备的东西**：前六章装好的手（WorkBuddy）、脑子（Obsidian）、料仓（IMA）、案件保险柜，上一章刚接上的大脑；一件你最近跟 AI 说过三遍以上的同一件事（现成的例子）
> **今天要过的六关**：记忆母舰是什么 → 建子库 → 定协议 → 去重 → 冲突仲裁 → 验收
> **总共用时**：约 2 小时（可以分两天做）
> **做完你会得到**：一份所有部件共用的「总记忆」+ 一份「进来先读、出去必写」的协议 + 一套「两条记忆打架了怎么办」的规则
> **本章施工**：记忆系统（L0 底盘 · 总记忆）——六大总成够不着的地基，先把「唯一说了算的记性」造出来

---

## 开始之前，先记住一句话

**同一件事你说了三遍，不是记性问题，是架构问题。**

前面六章，你把手（WorkBuddy）、脑子（Obsidian）、料仓（IMA）、案件保险柜都装好了，立了铁律、架起底盘，上一章刚给车接上会想的大脑。现在的问题是：**这些部件，各自记住的东西，是不是同一份？**

你的格式偏好，在三个地方说过三遍；同一个客户的背景，几条线各存一份。等到某天两条线给出不一样的答案，你不知道该信哪个。

**记忆母舰就是解决这个的：一份记忆，所有部件读。** 这一章，你要造出这台车的「总记忆」，并定下两条铁规矩——**进来先读，出去必写。** 还有最麻烦的一件：**两条记忆打架了，谁说了算。**

**六关，约两小时。做完之后，你有一个不撒谎的、唯一的记忆。**

## 第一关 · 记忆母舰是什么：先看看你有几份记忆（20 分钟）

### ① 做什么

在动手建之前，先承认一件事：**你现在不是没有记忆，你是记忆太多份了。**

### ② 怎么做

**第 1 步**：数一数，你有几个地方在「记东西」。问自己五个问题：

| 问题 | 如果答「有」 |
|---|---|
| 你跟 WorkBuddy 说过的偏好，它下次还记得吗？ | 记在会话里 |
| 你在 Obsidian 里有笔记吗？ | 记在笔记里 |
| 你微信收藏夹里有东西吗？ | 记在收藏里 |
| 你有几个文档叫「XX模板」？ | 记在文档里 |
| 你脑子里有几条「这个我知道怎么办」？ | 记在你脑子里 |

**五个地方，五份记忆。它们不会互相同步。**

**第 2 步**：认清「缓存」和「总记忆」的区别。让 WorkBuddy 帮你讲一遍：

> **跟 WorkBuddy 说：**
> 「我发现自己有五个地方在记东西，互相不同步。帮我用大白话讲清楚：哪些是『随手记的缓存』、丢了不要紧；哪一份才该是『唯一的、说了算的总记忆』。顺便告诉我，如果五份记忆互相矛盾，到底该信哪一份。」

**第 3 步**：等它回你。它会告诉你一个关键结论：**聊天记录是缓存，总记忆才是唯一说了算的那份。** 你现在的问题是——**所有东西都活在缓存里。**

### ③ 你会看到什么

你能回答这个问题：**「我上次跟 AI 说的那个格式要求，现在在哪儿？」**

如果你答「在聊天记录里」——那它已经半丢了，下次开新对话它就不在了。

如果你答「我记不清了，反正每次都重说」——那你每天在付一笔「重说税」。

**这笔税不大，但天天付。**

**对照一下**：如果你能一口气报出五个地方、却说不出「上次那条格式要求到底存在哪」，那已经是「重说税」在天天扣了；如果你连自己有没有说过都答不上来，更正常。两种都算认账，不丢人——这一关只是让你看清起点。

### ④ 为什么这件事必须先做

因为**总记忆最大的失败，不是建不起来，是建起来之后没人读。** 你花两小时建个漂亮的中枢，然后明天开新对话，AI 还是问你「请问您希望什么格式」——因为它不知道有那个中枢。

**所以这一章的顺序是：先认账（这一关），再建库（第二关），再定协议（第三关），再谈去重（第四关）和冲突（第五关）。** 顺序错了，你会建一个「给自己看的档案馆」。

## 第二关 · 建子库：给总记忆开四个房间（25 分钟）

### ① 做什么

建一个文件夹当「总记忆的家」，然后在里面**开四个房间**，分类放不同东西。现在它们**还不存在**，这一关把它们**造出来**。

### ② 怎么做

**第 1 步**：跟 WorkBuddy 说：

> **跟 WorkBuddy 说：**
> 「帮我在脑子（Obsidian）库的根目录下，建一个文件夹当『总记忆的家』，名字要让它排在最上面（比如用下划线开头）。里面开四个子文件夹，分别放四样东西：
> ① 不许违反的规矩；
> ② 我的习惯和偏好；
> ③ 正在办、还没完的事；
> ④ 今天干了什么的日志。
> 建完告诉我每个文件夹的完整路径，和每个各装什么。」

**第 2 步**：认这四个房间各装什么：

| 房间 | 装什么 | 一句话判据 |
|---|---|---|
| 第一个 · 规矩 | 不许违反的 | 「这条违反了要出事」 |
| 第二个 · 偏好 | 你的习惯 | 「我希望你以后都这样」 |
| 第三个 · 在办的事 | 还没完的事 | 「这事还没完」 |
| 第四个 · 日志 | 今天干了什么 | 「昨天干到哪了」 |

**第 3 步**：写第一份「说明书」，只写三行。跟 WorkBuddy 说：

> **跟 WorkBuddy 说：**
> 「在这个总记忆的家根目录，写一份只有三行的说明书，大意是：这是我的总记忆、唯一说了算的地方；跟别处冲突时以这里为准；往里写之前先搜一遍、别重复建。就三行，别多写。」

### ③ 你会看到什么

打开脑子（Obsidian），左侧文件树最上面出现那个「总记忆的家」，点开有四个子文件夹。那份说明书，**一眼能读完，不用滚。**

**看到四个房间 + 三行说明书，第二关就过了。**

**对照一下**：如果左侧只出现一两个文件夹，或者那份说明书要滚动才读得完，让它重做一遍。房间少了、说明书写长了，第三关的协议就没地方挂。

### ④ 为什么是「四个房间」，而且说明书只写三行

因为**分类不是越多越好，是「够用、能坚持」最好。** 四个房间刚好覆盖「规矩 / 偏好 / 在办的 / 干过的」，再多你就分不清该放哪了。

说明书只写三行，也是同理——**它是给「下次忘了的自己」看的，三行能读完，三十行读不完。** 一句话说清「以这里为准」，比写十页使用说明有用得多。

**顺带记住「唯一」这两个字比「全」更重要**：两份互相矛盾的记忆，比没有记忆更糟。没有记忆你会去查；有两份矛盾的，你会挑一份顺眼的信——然后错的就这么定下来了。

**四个房间只是起步这一套，不是标准答案。** 以后要记的东西多了，再加新房间——房间不止这一种，用到哪种加哪种，别现在就纠结「该不该先多建几个」。

## 第三关 · 定协议：进来先读，出去必写（20 分钟）

### ① 做什么

记忆建好了，但**光有库，AI 不会自动去读它**。这一关，定下两条铁规矩——一条管「进来」，一条管「出去」。现在它们**还不存在**，这一关把它们**写下来**。

### ② 怎么做

**第 1 步**：认这两条的名字：

| 条 | 叫什么 | 干什么 |
|---|---|---|
| 第一条 | **进来先读** | 动手前，先去总记忆里搜一遍有没有现成结论 |
| 第二条 | **出去必写** | 干完，把这次新学到的东西写回总记忆 |

**这两条是一进一出。缺一条，总记忆就废一半。** 只读不写 → 总记忆永远是建库那天那副样子；只写不读 → 总记忆越来越大，但没人用。

**第 2 步**：让 WorkBuddy 把这两条写成一个文件。跟 WorkBuddy 说：

> **跟 WorkBuddy 说：**
> 「在『规矩』那个房间里，建一个文件叫『记忆协议』。内容就两条：第一条『进来先读』——每次接到任务，先在总记忆里搜一遍相关主题，搜到就按总记忆的来，没搜到才允许凭当场判断；第二条『出去必写』——任务结束后，把这次新学到的结论、为什么这么定、下次遇到同类怎么办写回总记忆，不写流水账。文件开头标好『版本、状态、更新日期』三个信息。建好念给我听。」

**第 3 步**：把「进来先读」变成一句你每次能说出口的话。协议写在文件里，AI 不会自动读，你得每次给它一句：

```
动手之前，先去总记忆里搜一下这件事有没有现成结论。有就按那个来，告诉我你搜到了什么；没有就直接说没有，别编。
```

**这句话你要说很多次，直到它变成你的习惯。**

### ③ 你会看到什么

「规矩」房间里出现了「记忆协议」这个文件。点开它，顶部能清楚看到**版本、状态、更新日期**三个信息。

**看到这三个信息 + 两条协议写清了，第三关就过了。** 如果顶部那三个信息是空的，说明格式没写对（大概率是那几个横线符号漏了或打错了），让它重写。

### ④ 为什么「进来先读」和「出去必写」必须成对

**因为记忆的价值不在「存」，在「下次能用上」。**

只写不读，你就是在给一个从不打开的文件柜添纸；只读不写，你就是在反复看一份三个月前的旧地图。**两条一起，总记忆才是「活的」——进来时它喂你，出去时你喂它，越用越准。**

## 第四关 · 去重：新东西进来之前，先搜一遍（25 分钟）

### ① 做什么

给「写」加一道前置动作：**先搜，再决定。** 新东西要进总记忆时，先搜关键词，搜完只有三种处理。这一关，把这个「去重」的动作学会。

### ② 怎么做

**第 1 步**：记住三种命运，选一个：

| 搜到什么 | 怎么办 |
|---|---|
| **没有** | 新建一条，正常写 |
| **有，而且是对的** | 不新建，补充或加一句「确认于 X 月 X 日」 |
| **有，但已经错了/过时了** | 把旧的标「作废」，再新建 |

**大多数人死在第二种情况——他们图快，直接新建了。** 新建比「打开旧的看一眼、再判断对不对」要快，而**图快，就是重复的来源。**

**第 2 步**：学会「作废」这个动作怎么做。**不是删除，是标记。** 跟 WorkBuddy 说：

> **跟 WorkBuddy 说：**
> 「以后我在总记忆里发现某条旧记忆过时了、错了，怎么『作废』它？我听说不是直接删，是标一个记号、再写一句为什么作废。帮我演示一遍：假设我有一条旧的『命名规则』现在改了，把它作废、写清原因、再建一条新的，念给我看三个动作。」

**第 3 步**：给容易混的东西加「别名」。同一个东西有两个叫法时，别建两张卡，在一张卡上写清它另外几个叫法。

### ③ 你会看到什么

你搜一个词，出来的结果**变少了**。以前搜「格式要求」出来七八条，现在出来一两条，而且内容一致。**这就是去重成功的标志。**

**看到「搜一个词只出一条」，第四关就过了。** 如果你搜出来还是七八条——说明你过去所有「新建」都没去重，得补一轮。

### ④ 为什么「作废」不能「删除」

因为**半年后你会问「这条以前是不是这么定的」**，删了就答不上来。作废是「留着、但标清楚它不算数了」，这样历史还在，你随时能查「当时为什么改」。

**三个动作一个都不能省：① 标「作废」② 写一句「为什么作废」③ 更新日期。** 尤其「为什么作废」——没有这句，你半年后看到一张作废的卡，会想「这为什么废了？是不是当时搞错了？」，然后只能再踩一次坑。

## 第五关 · 冲突仲裁：两条记忆打架了，谁说了算（30 分钟）

### ① 做什么

去重能防「重复」，但防不住「矛盾」——两条都标着「有效」的记忆，说的却是相反的话。这一关，定下一套**「打架了谁赢」的规则**，并学会分辨**「真打架」和「假打架」**。

### ② 怎么做

**第 1 步**：先分清「真打架」和「假打架」。让 WorkBuddy 讲一遍：

> **跟 WorkBuddy 说：**
> 「我的总记忆里，可能出现两条记忆『撞了』。帮我分清两种：一种是真矛盾——同一个编号或同一件事，两个不同的意思，必须处理；另一种是假矛盾——同一个东西跨了房间、被引用了两处，其实是指向同一条，不用动。用大白话各举一个例子。」

**第 2 步**：记住判断口诀：

| | 真打架 | 假打架 |
|---|---|---|
| 现象 | 同名**不同义**，或互相矛盾 | 同名**同义**，只是跨了房间 |
| 要不要动 | **要** | **不要** |
| 动错了会怎样 | 留着会引错 | 动了会断链 |

**假打架不能删。** 它是一条链路的两个端点，删了就断。

**第 3 步**：定「谁赢」的规则。跟 WorkBuddy 说：

> **跟 WorkBuddy 说：**
> 「帮我定三条『记忆打架了谁赢』的规则，写进『规矩』房间：① 都标着『有效』时，日期更新的那条赢；② 一条标『有效』、一条标『作废』时，有效的赢；③ 一旦发现某条错了，标『作废』并写清原因，90 天后再归档。写清楚这三条，念给我听。」

### ③ 你会看到什么

你手上多了一套「谁赢」的规则，和一套「真打架 / 假打架」的判断。你可以自己试一个例子：搜一个词，如果出来两条互相矛盾的，你**能说出哪条该赢、哪条该作废**。

**看到你能自己裁决一条矛盾，第五关就过了。**

**对照一下**：拿两条去问它，它回「这两条其实是一回事、只是放了两个房间」＝假打架，别动；回「两条说法相反」＝真打架，按「谁赢」规则处理。**分不清就先别动，宁可留着。**

### ④ 为什么「冲突仲裁」是最容易被忽视、又最要命的一关

因为**记忆打架这事，平时不响，一响就是事故。** 你今天记「命名规则是 A」，明天记「命名规则是 B」，两条都在库里、都标着有效——三个月后你按其中一条写了五个文件名，才发现按错了，回头改五遍。

**最阴的一种是「假打架被当真打架处理了」**：同一个编号跨房间被引用，你以为是重复，手一快删掉一条——结果引用它的地方全断了。**所以第五关第一要务是：先分清真假，再动手。分不清，宁可不动。**

（关于「这套记忆系统到底健不健康」的进阶真相——比如某些数字看着满分其实没在数——不在本章范围，等你总记忆超过三百条，去翻**附录 E**。现在先学会「进来先读、出去必写、打架了按规则裁决」，就够用了。）

## 第六关 · 验收：把这一章清点一遍（10 分钟）

### ① 做什么

最后一关，清点一遍：这一章该有的东西，是不是都到位了，尤其是「有没有不该露出去的东西混进来了」。

**先说清一件事**：上一章验收，你看的是「大脑状态灯」亮不亮；这一章**不看灯**。总记忆是文件夹和文件，不是一盏灯——它只能靠「数得清、搜得到、说得出来」来验。别去找灯，找不到。

### ② 怎么做

**第 1 步**：跟 WorkBuddy 说：

> **跟 WorkBuddy 说：**
> 「帮我清点一遍这一章的结果：① 总记忆的家建好了没有（四个房间都在）；② 记忆协议写好了没有（进来先读、出去必写两条）；③ 有没有把钥匙、密码这类不该进记忆的东西，误写进了总记忆（有就指出来）。三样都查清，告诉我结果。」

**第 2 步**：等它回你。它会告诉你三样齐不齐、有没有「钥匙/密码」混进去。

### ③ 你会看到什么

它回你一句，大意是「四个房间都在、协议写好了、没发现钥匙密码混进来」。**看到这句，第六关就过了。这一章，也就过了。**

**对照一下**：如果它回你「发现一条像钥匙的内容」，别自己翻，直接说「把它拿出来删掉，再清点一遍」；如果它说「四个房间少了一个」，回去补第二关。

### ④ 为什么验收要专门查「钥匙密码有没有混进来」

因为**总记忆是「要共享给所有部件读」的，而钥匙密码是「谁都不该读」的。** 你把钥匙写进总记忆，等于把家门钥匙挂在小区公告栏上。所以验收时专门扫一遍——**清点结果里不该出现任何一串钥匙、密码；出现一条，就让它当场拿出来删掉，再清点一遍。**

（这一条从建案件保险柜那天起就没变过：钥匙永远不进记忆，记忆永远不存钥匙。）

## 第一周怎么安排（别一天做完）

六个关加起来两个多小时，**但别一天做完。** 原因很实在：第二关建完库，你得**隔一天再回来看**——第一天你满脑子是「我刚建了什么」，看不出「这东西到底有没有用」。隔一夜，你才会用平常心去搜一次，才知道它顺不顺手。

| 哪天 | 做什么 | 用时 | 做完的标志（去哪看） |
|---|---|---|---|
| **第 1 天** | 第一关：数你有几份记忆 | 20 分钟 | 一张「我到底有几份记忆」的清单 |
| **第 2 天** | 第二关：建总记忆四个房间 | 25 分钟 | 左侧出现「总记忆的家」+ 4 个文件夹 |
| **第 3 天** | 第三关：写两条协议 | 20 分钟 | 顶部看到版本 / 状态 / 日期 |
| **第 4 天** | 第四关：给写入加去重 | 25 分钟 | 搜一个词，只出一条 |
| **第 5 天** | 第五关：定「谁赢」规则 + 分真假 | 30 分钟 | 你能裁决一条矛盾 |
| **第 6 天** | 第六关：清点 + 查钥匙 | 10 分钟 | 「三样齐、没发现钥匙密码」 |
| **第 7 天** | 复查：拿一件真事走一遍 | 10 分钟 | 这次没重说，它自己找到了 |

**第 7 天那步最重要，也最容易被跳过。** 拿一件你上周真干过的事，跟它说「先去总记忆搜一下」。搜到了——这一整套就成立了。搜不到——说明你的总记忆还只是个空壳，回去补第二关和第三关。

## 第二周开始，只做一件事

**每周五，让 WorkBuddy 把总记忆里的「新结论」回写一遍，你只看一眼有没有漏。**

不用看分数，就问一句「这周我新学的，都写回总记忆了吗」。

**为什么要盯这一下？** 因为「出去必写」是最容易偷懒的一条。写着写着，某天忙起来就「这次先不写了」——**漏一次，那天的经验就蒸发了。** 每周五回头扫一眼，就是给这条规矩上保险。

## 长成 · 记忆越存越多之后

| 什么时候做 | 做什么 | 你怎么知道自己需要 |

| 房间不够用了 | 对 WorkBuddy 说「再开一个放 XX 的房间」 | 你总在纠结「这条该放哪」 |

| 想换电脑 | 把整个总记忆的家拷走，再清点一遍 | 换电脑后总记忆没了 |

**最后一行最要紧。** 换电脑时，总记忆是整个系统里**最不能丢**的一部分——它攒着你所有的规矩、偏好、决策。搬完让 WorkBuddy 清点一遍：四个房间还在、协议还在、没有钥匙密码混进来。

**换电脑时，两种电脑做的事一模一样，只是打开文件夹的地方名字不同：**

| 你要做的事 | 苹果（macOS） | Windows |
|---|---|---|
| 找到总记忆的家、整个拷走 | 在**访达（Finder）**里找到那个文件夹 | 在**文件资源管理器**里找到同一个文件夹 |
| 拷到新电脑后确认齐不齐 | 在访达里数四个房间 | 在文件资源管理器里数四个房间 |
| 路径长什么样 | `文档/我的数字分身/…` | `文档\我的数字分身\…` |

**别在 WorkBuddy 里分系统**：你只说「帮我把总记忆清点一遍」，它会自己认出你在用哪种电脑，用那种电脑的方式帮你做。

## 卡住了怎么办

下面九条，是真实卡过的地方。**你大概率会卡在其中某一条。**

### 卡 1 · 四个房间建了，但不知道东西该放哪个

**现象**：每写一条都犹豫三分钟。

**怎么办**：直接回 WorkBuddy：

```
我要记一条：<一句话说清这条是什么>。你觉得它该放总记忆的哪个房间？说理由，别只给答案。
```

**判据就一条**：这条会变吗？会变 → 放「在办的事」；不会变 → 放「干过的/规矩」；是「以后都得这样」 → 放「偏好」；是「违反了要出事」 → 放「规矩」。

### 卡 2 · 搜同一个东西出来七八条，不知道该留哪个

**现象**：去重做不下去，越搜越乱。

**怎么办**：直接回 WorkBuddy：

```
我在总记忆搜「<关键词>」出来这几条：<贴文件名>。帮我判断哪条最新、哪几条重复、哪几条该标作废。理由是看更新日期和内容是否矛盾。
```

**别自己一条条读。** 这是最费时间的活，交给它。

### 卡 3 · 协议写了，但 AI 从来不读

**现象**：写了几千字协议，下次开对话它还是问「请问您需要什么格式」。

**怎么办**：**协议不会自己生效，你得每次给它一句：**

```
先去总记忆里搜一下「<这次要做的事>」，看有没有现成结论和我的格式偏好。搜到什么就告诉我，搜不到就说没有。
```

说二十次之后，你自己也记住了。

### 卡 4 · 日志写了一堆，但下次都用不上

**现象**：每天写「今天完成了XX」，三个月后翻回去什么也捞不着。

**怎么办**：直接回 WorkBuddy：

```
今天这件事，如果三个月后的我只看一条记录，应该看到什么？按这个标准帮我写一条，不要流水账。
```

**判据**：写下来的东西，三个月后还能直接照做 → 合格。只是「我今天干了什么」 → 不合格。

### 卡 5 · 两个文件重名，把旧的覆盖了

**现象**：建新文件时没注意，把旧的盖掉了。

**怎么办**：直接回 WorkBuddy：

```
我刚可能覆盖了一个文件。帮我在总记忆里搜一下有没有内容相近但版本不同的文件，以及最近 3 天有没有被改过的同名文件。
```

**预防**：新建之前先搜一次名——这就是第四关干的活。

### 卡 6 · 编号乱了，有两个重复的

**现象**：房间越建越多，编号开始撞号。

**怎么办**：直接回 WorkBuddy：

```
列一下总记忆下所有子文件夹的名字和里面的文件数，按编号排序。如果有编号重复的，单独指出来。
```

**别急着改名。** 改名会让所有引用它的地方断链。先查清有多少地方引用了旧名，再定方案。

### 卡 7 · 分不清「真打架」和「假打架」

**现象**：一条记忆撞了，你拿不准该不该动。

**怎么办**：直接回 WorkBuddy：

```
把这两条撞了的记忆的完整标题和路径都贴出来。如果是同一个意思、只是跨了房间，就是假打架，别动；如果是两个意思，就是真的，按「谁赢」规则处理。
```

**看标题，别看编号。** 编号一样可能是跨房间引用，标题不一样才是真矛盾。

### 卡 8 · 发现「作废」的卡越来越多，想删掉

**现象**：标了「作废」的卡堆了一堆，你想清理。

**怎么办**：**别删。** 作废的卡是历史，留着能查「当时为什么改」。真到 90 天后要归档，让 WorkBuddy 处理：

```
帮我把标了「作废」且超过 90 天的卡，归档到一个专门的「归档」房间，不要删。
```

**归档不是删除。** 历史永远留着。

### 卡 9 · 总记忆越建越大，找东西越来越慢

**现象**：几百个文件，搜一个词出来几十条。

**怎么办**：直接回 WorkBuddy：

```
总记忆里哪些房间的文件最多？给我前五名和各自的文件数。文件最多的那个，帮我看看里面有多少是重复的、多少是过期的。
```

**大不是问题，乱才是。** 先定位最大的那个房间，再在里面做一轮去重。
