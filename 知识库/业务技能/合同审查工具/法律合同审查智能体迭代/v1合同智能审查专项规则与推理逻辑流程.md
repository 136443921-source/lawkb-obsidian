## 一、系统概述

本系统由两大部分组成：

1. **专项审查规则 (Specific Review Rules)**：针对特定合同类型，从规则库中提取核心风险点，形成更聚焦、更具操作性的审查清单。
2. **推理逻辑流程 (Inference Logic Flow)**：规定审查的思考路径和决策树，确保审查过程严谨、全面，避免遗漏或逻辑跳跃。该流程采用**“分步推理，条件分支”**的设计，符合法务人员的思维习惯。

## 二、专项审查规则模板

每个专项审查规则都会遵循以下结构，确保信息完整且可执行：

markdown

```
### 【合同类型名称】
- **风险编号**：R-[合同类型缩写]-[编号]
- **风险点名称**：
- **风险等级**：(高/中/低) 基于规则库的初始评级。
- **风险描述**：(从规则库提取核心内容)
- **触发条件**：(审查员或AI需要检查的具体条件，这是推理的起点)
- **深度分析**：(解释风险为何发生，可能的法律后果)
- **修改建议模板**：(提供可直接参考或微调的标准条款措辞)
- **谈判策略**：(根据谈判地位，提供不同强度的应对方案)
- **关联规则**：(指向规则库中其他相关联的通用规则，形成知识网络)
```

## 三、专项审查规则示例

此处我们选取几类最具代表性的合同，基于规则库生成专项审查规则。

### 1. 买卖合同专项审查规则

> **适用场景**：采购、销售、设备购买等转移所有权的交易。

|风险编号|风险点名称|等级|风险描述|触发条件|修改建议模板|谈判策略|
|---|---|---|---|---|---|---|
|**R-PS-001**|货物权属与权利瑕疵|**高**|卖方可能对货物无完整所有权或货物存在抵押、查封等权利限制，导致买方无法取得完整所有权或被第三方追索。|1. 审查合同“标的物”条款，是否有“无权利瑕疵”保证？2. 如为二手、进口或特殊设备，是否有权属证明承诺？|“卖方保证对合同项下货物拥有合法、完整、排他的所有权或处分权，且该等货物不存在任何抵押、留置、查封、冻结或任何形式的第三方权利主张。因卖方违反本条保证导致买方遭受任何损失的，卖方应承担全部赔偿责任。”|**优势方**：坚持加入，并要求赔偿范围包括间接损失。  <br>**劣势方**：如对方强硬，可退一步要求对方出具书面承诺，并约定若因此导致损失，对方应予以配合解决。|
|**R-PS-002**|检验期限设置不当|**高**|未约定或检验期限过短，买方可能因错过异议期而丧失对货物质量提出异议的权利。|1. 是否有明确的“检验/验收”条款？2. 检验期限是否合理（如：表面瑕疵24小时，内在质量7-15天）？|“买方应在收到货物后【7】个工作日内对货物的数量、规格、外观进行初步检验。对于货物内在质量或隐蔽瑕疵，买方有权在【45】日内通过书面方式提出异议。买方未在上述期限内提出异议的，视为货物验收合格，但不免除卖方在质保期内的质量保证责任。”|**优势方**：争取较长检验期和隐蔽瑕疵异议期。  <br>**劣势方**：明确检验期，并加入“卖方质保期内的责任不受检验期限届满影响”的条款。|
|**R-PS-003**|货物风险转移节点不清|**中**|未约定货物在运输途中毁损、灭失的风险承担主体，发生货损时双方推诿。|1. 是否有明确的“交付”条款？2. 交付方式是否约定？（如：送货上门、自提、代办运输）|“货物的风险自买方或其指定收货人在【交货地点】签收《送货单》或《收货确认函》时起由卖方转移至买方。在此之前，货物的毁损、灭失风险由卖方承担。若因卖方原因导致无法按时交付，风险仍由卖方承担。”|**优势方**：明确约定“风险在买方签收后转移”。  <br>**劣势方**：争取将风险转移节点后移至安装调试完毕或最终验收合格后。|
|**R-PS-004**|所有权保留约定不当|**中**|分期付款买卖中未明确约定所有权保留条款，或约定不明，导致卖方在买方未付清全款前无法取回货物。|1. 是否为分期付款买卖？2. 合同是否有“所有权保留”条款？3. 条款是否明确了买受人付清全款前，所有权属于出卖人？|“双方同意，在买方付清本合同项下全部价款（包括但不限于本金、利息、违约金等）之前，本合同项下货物的所有权仍属于卖方。若买方未按期支付任何一期价款，卖方有权在不通知买方的情况下取回货物，并要求买方承担取回货物的费用及相应损失。”|**优势方**：明确保留所有权，并约定加速到期权和取回权。  <br>**劣势方**：可接受该条款，但争取约定“卖方行使取回权时，应将买方已支付的款项在扣除折旧和合理费用后予以返还”。|

### 2. 技术开发（委托开发）合同专项审查规则

> **适用场景**：委托他人开发软件、新工艺、新产品等。

|风险编号|风险点名称|等级|风险描述|触发条件|修改建议模板|谈判策略|
|---|---|---|---|---|---|---|
|**R-TD-001**|开发需求与验收标准模糊|**高**|仅笼统描述“开发一套管理系统”，无具体功能、性能指标，导致验收时无客观标准，开发方“交差”即可。|1. 是否有《技术需求规格书》？2. 该文件是否作为合同附件？3. 验收条款是否量化（如：支持1000用户并发，响应时间<2秒）？|“本合同项下的开发内容、技术参数、功能清单、交付成果及验收标准，详见本合同附件一《技术需求规格书》。该附件与本合同具有同等法律效力。任何一方不得以本合同正文未明确为由，对交付成果提出非附件约定的要求。”|**优势方**：强制要求将详细《技术需求规格书》作为合同必备附件，并作为验收唯一依据。  <br>**劣势方**：提前与业务/技术部门共同撰写规格书，避免模糊表述，防止开发方后续漫天要价。|
|**R-TD-002**|知识产权归属约定不利|**高**|未约定或约定“归开发方所有”，委托方支付了开发费，成果却归对方，未来使用、升级均受限制。|1. 是否有“知识产权”条款？2. 该条款是否明确新产生知识产权归委托方所有？|“因履行本合同所产生的全部技术成果、软件代码、技术文档、设计图纸及其他任何形式的知识产权，均归委托方（甲方）所有。受托方（乙方）仅享有为履行本合同之目的的使用权。受托方应协助甲方办理相关知识产权的申请登记手续。”|**优势方**：坚决要求所有权归己方。  <br>**劣势方**：若对方强势（如使用对方核心技术），可争取为“双方共有”，并明确共有方式、收益分配及权利行使规则。|
|**R-TD-003**|开发失败风险责任不明|**中**|因现有技术或科学水平限制，导致开发失败无法实现合同目的，双方就已支付的费用和投入产生纠纷。|1. 合同是否有“开发风险”条款？2. 是否明确了开发失败后的责任分担（如：已付费用不退，按工作量结算）？|“双方确认，鉴于技术开发工作本身存在失败的风险。因现有科学技术水平无法克服的技术困难导致本合同目的无法实现的，不视为任何一方违约。在此情况下，受托方应就已完成的开发成果向委托方进行说明并交付，双方按实际工作量进行结算，委托方已支付的费用不再返还。”|**优势方**：明确风险由委托方承担，但已付费用不退，避免“钱货两空”。  <br>**劣势方**：争取约定“若开发失败，受托方应退还大部分或全部已付费用，除已产生的、不可撤销的第三方费用外。”|

### 3. 租赁合同（经营性租赁）专项审查规则

> **适用场景**：商铺、写字楼、厂房、住宅租赁。

|风险编号|风险点名称|等级|风险描述|触发条件|修改建议模板|谈判策略|
|---|---|---|---|---|---|---|
|**R-LE-001**|出租人主体身份存疑/无权处分|**高**|二房东无大房东授权、出租人非产权人、房屋存在查封/抵押，导致合同无效或被强制清退。|1. 出租人是否为产权人？若非，是否有产权人书面同意转租证明？2. 要求提供不动产登记中心查询的《房屋权属信息》。3. 房屋是否存在抵押、查封？|“出租人保证其对租赁房屋拥有合法的所有权或转租权。因出租人无权出租房屋导致本合同无效，或房屋被第三方主张权利导致承租人无法正常使用的，出租人应双倍返还承租人已支付的押金，并赔偿承租人全部损失。”|**优势方**：坚持“双倍返还押金+赔偿全部损失（含装修费、搬迁费、经营损失）”的约定。  <br>**劣势方**：退一步，约定“若因无权处分导致合同无效，出租人应赔偿承租人经证实的合理装修损失”。|
|**R-LE-002**|装修投入处置约定不明|**中**|合同到期或提前解除时，对于承租人投入的装修、改造等添附物如何处理无约定，导致纠纷。|1. 是否有“装修和改建”条款？2. 提前解约时，装修残值如何计算和补偿？3. 合同到期后，装修归谁？|“经出租人书面同意，承租人可进行装修改造。合同因【出租人违约、不可抗力、政府征收】等原因提前终止的，出租人应按照【约定公式或评估】补偿承租人剩余租期内的装修残值。合同正常到期，承租人将房屋恢复原状（或保持装修完好）后交还，装修无偿归出租人所有。”|**优势方**：明确各类情况下的处置规则，特别是因出租人违约导致解约时，需补偿装修残值。  <br>**劣势方**：争取“如出租人要求拆除，应补偿承租人拆除及恢复原状的费用”或“装修经出租人确认可保留的，无偿归出租人”。|
|**R-LE-003**|租金调整与优先承租权约定模糊|**中**|长期租约未约定租金增长机制，或合同到期后承租人无法以“同等条件”优先续租，面临搬迁损失。|1. 租金是否固定？是否有“每N年递增X%”的条款？2. 合同是否有“优先承租权”条款？如何定义“同等条件”？|“前【3】年租金为X元/月；从第【4】年起，每【2】年递增【5%】。本合同租赁期限届满前【60】日，出租人如继续出租，承租人有权在同等条件下优先承租。‘同等条件’指其他潜在承租人的报价及租赁条件与承租人匹配时，出租人应优先与承租人签约。”|**优势方**：明确递增比例，并对“同等条件”进行详细解释，防止出租人找“托”抬价。  <br>**劣势方**：接受递增，但争取将递增比例与周边商铺/写字楼市场租金联动，避免涨幅过大。|

## 四、推理逻辑流程

该流程是一个动态的、可嵌套的决策树，确保审查的完整性和逻辑性。

**第一步：合同信息解析与类型识别**

text

```
流程：接收合同 → 提取关键信息（主体、标的、金额、期限等） → 识别合同类型（依据“合同标题+核心条款”判断，如发现有“开发”、“所有权”、“验收”等字眼的标的条款，初步判断为“技术开发合同”）。
输出：合同基本信息摘要 + 初步合同类型标签。
```

**第二步：通用规则前置审查**

text

```
流程：根据【风险规则库-通用审查规则（20条）】，逐条扫描合同。主要关注：
- 主体资格与签约权限 (规则1-5)
- 核心条款完备性 (规则6-17，重点检查标的、质量、价款、履行、违约责任、争议解决)
- 程序合规性 (规则18-20)
输出：生成一个“通用风险清单”，标记出高风险、中风险、低风险项。
决策点：如果合同中缺失“标的”、“数量”、“价款”等绝对必要条款，或违反法律强制性规定，则评为“极高风险”，直接建议“合同不能签署”，并终止审查。
```

**第三步：专项规则深度审查**

text

```
流程：基于第一步识别的“合同类型”，调入对应的【专项审查规则】（如上文的规则示例）。
步骤：
1. 遍历该类型下的所有风险点。
2. 对于每一条专项规则，核对“触发条件”：
   - 若“触发条件”满足（例如：对于技术开发合同，检查“是否有技术需求附件？”答案是“否”），则识别出一个新风险点。
3. 对该风险点进行“深度分析”（引用规则库中的法律依据和后果），并调用“修改建议模板”。
4. 根据风险等级和“修改建议模板”，结合用户/我方的谈判地位（优势/劣势），从“谈判策略”中选取合适的修改措辞或应对方案。
输出：一份针对特定合同类型的“专项风险清单”，包含深度分析和具体的修改措辞。
```

**第四步：条款交叉验证与系统性风险评估**

text

```
流程：
1. 将“通用风险清单”和“专项风险清单”合并，去重。
2. 进行条款交叉验证检查（这是高级审查的关键）：
   - 例如：付款条款是否与交付、验收条款匹配？（货到付90%，但验收条款在付款之后，这就不合理）
   - 违约责任是否覆盖了所有关键义务？（如果合同约定了交付时间，违约责任里也要有逾期交付的责任）
   - 附件内容是否与主合同描述一致？（技术规格书里要求的零件品牌，是否与主合同报价清单一致？）
   - 管辖权约定是否为己方所在地？
3. 进行系统性风险评估：
   - 统计高风险、中风险、低风险的数量和性质。
   - 识别风险最集中的领域（如知识产权、付款）。
   - 判断整体合同的风险水平（高/中/低）。
输出：一份综合性评估，并明确“主要风险集中点”。
