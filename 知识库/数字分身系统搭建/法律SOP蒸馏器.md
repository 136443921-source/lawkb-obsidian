# Anthropic 开源了一套"法律SOP蒸馏器"——而且可能不是故意的

![](wechat_img_1779067413665_347.jpg)

2026年5月12日，Anthropic 开源了 claude-for-legal。这是一个法律 AI 插件体系，包含11个业务领域插件、80多个命名Agent、20多个MCP数据连接器，覆盖商业合同、公司并购、劳动用工、隐私合规、产品法务、监管合规、AI治理、知识产权、诉讼仲裁等全链条。全部 Markdown 和 JSON，无构建步骤，Apache 2.0 协议。媒体关注的是"Anthropic 进军法律垂直领域"。律师关注的是"这些 Skill 好不好用"。但我看完整个仓库之后，觉得最值得注意的不是它写了多少美国法条，而是它无意中展示了一套方法论：怎么把法律人的隐性知识蒸馏成 AI 可执行的结构化格式。这套方法论的价值可能超过插件本身。


## 为什么需要"知识蒸馏"01

   **法律人的核心资产不是法律条文——条文谁都能查到。核心资产是判断力：什么时候用哪条、什么场景怎么审、什么条款绝不能让。这种判断力存在于三个地方：律师脑子里、Word批注里、带新人的口头交代里。全是隐性知识。**  传统知识管理（KM）系统试图把隐性知识显性化。搞了20年，基本失败了。原因很简单：写KM文档没人看、没人更新、没人执行。律师的时间值钱，花两小时写一份SOP文档，不如花两小时多做一份合同审查。AI 提供了一个新路径：不需要律师写KM文档。只需要让AI读律师的真实工作产物，然后从中提取模式。claude-for-legal 做的就是这件事。而且它把蒸馏过程拆成了四层，每层解决一个不同的问题。


## 四层蒸馏结构02


第一层：Practice Profile——"你是谁"这是蒸馏的起点。通过一个叫"冷启动访谈"（cold-start interview）的机制完成。你安装一个插件后，它不是给你一个功能菜单，而是问你10到20分钟的问题。你的合同模板是什么？哪些条款绝不让步？风险怎么分级？什么情况升级到合伙人？然后它要求你提供种子文件：签过的合同、审查备忘录、升级矩阵。它从这些文件中提取你的业务模式，生成一份 Practice Profile（实践档案），保存为 CLAUDE.md。做法很直接：你不需要写一份"我们团队审合同的十个要点"——你只需要把审过的十份合同喂给它。AI从中提取你的模式，比你自己描述的还准确。

第二层：Skill——"怎么做某件事"每个 Skill 是一个 SKILL.md 文件。它把一个复杂的法律任务拆解为步骤链。拿 vendor-agreement-review（供应商合同审查）举例，它的结构大致是：- 

```
frontmatter（元数据：名称、描述、触发条件）
→ 步骤1：识别合同类型
→ 步骤2：加载对应的 Playbook
→ 步骤3：逐条款审查
→ 步骤4：风险分级（高/中/低）
→ 步骤5：生成 redline memo
→ 输出格式：表格 + 批注 + 升级建议
```

每个步骤有明确的输入、判断标准和输出物。步骤之间还有"检查门"（gate）——比如风险等级为"高"的时候，必须触发升级流程，不能跳过。蒸馏的关键动作：把"凭经验做"变成"按步骤执行"。步骤来自资深律师的隐性经验，但被结构化了——有了先后顺序、判断标准、输出格式。传统SOP文档是给人看的，人可以灵活变通。Skill 是给 AI 执行的，每一步都会被走完。你不用担心"新人跳过了第三步"，因为 AI 不会跳。

第三层：Agent——"什么时候做"Skill 解决"怎么做"，Agent 解决"什么时候做但可能忘了做"。claude-for-legal 里有五类定时 Agent：- 续期监控器：每周扫描合同台账，找出即将到期的合同

- 庭期监控器：自动跟踪法庭动态和截止日期

- 监管动态监控器：定期扫描法规变化，生成摘要

- 数据室监控器：监控尽职调查数据室的新上传文件

- IP续费监控器：追踪商标、专利的续费截止日

这里蒸馏的是另一类知识：不是"怎么做"，而是"记得什么时候做"。这类知识通常不存在于任何SOP文档里，只存在于资深律师的日历提醒和经验中。Agent 把这种"时间维度的隐性知识"也编码化了。

第四层：Connector——"数据在哪"MCP 连接器把 AI 和法律科技系统打通。claude-for-legal 配套了20多个连接器：Slack、Google Drive、Ironclad（合同管理）、DocuSign（电子签名）、iManage（文档管理）、Everlaw（电子取证）、CourtListener（判例库）、Westlaw（法律研究）等等。这一层解决的是数据路径问题。一个资深律师和初级律师的区别，很大程度上不在于法律知识，而在于"知道去哪里查什么"。连接器把这种"数据路径"也编码化了——AI 不只是知道怎么审合同，还知道从哪个系统调取历史合同、从哪个数据库验证引用。

以"审查一份供应商合同"走一遍完整流程：1. Profile 提供你的合同审查 playbook——你的红线、你的风险分级标准、你的升级阈值

四层分别蒸馏了法律人隐性知识的四个维度：**业务规则（Profile）、操作步骤（Skill）、时间管理（Agent）、数据来源（Connector）。**


## 常见误区04
有人觉得"把SOP写成Word文档就够了"。不够。静态文档无法执行、无法自动更新、无法验证执行结果。Skill 是可执行的SOP——每一步都会被走完，每一步的输出都有格式约束。也有人觉得"让AI自己学就好了"。没有结构化输入，AI学到的就是通用知识。通用知识审出来的合同和模板一样——该抓的问题抓不到。冷启动访谈和种子文件的价值在于：让AI学的是"你"的做法，不是"所有人"的做法。还有一个容易忽略的点：**蒸馏不是一次性的。业务在演进，playbook在变化。claude-for-legal 允许重跑冷启动访谈，也允许手动编辑 Practice Profile。**有一个叫 Playbook Monitor 的 Agent 专门干这件事：当你审合同时的偏差累积到一定程度，它会建议更新 playbook。


## 适用边界05

这个蒸馏方法最适合的场景：高频、有重复性的法律工作。合同审查、合规检查、尽职调查流水线、案件管理——这些工作有SOP（即使你没写下来），AI可以帮你把隐性SOP显性化。不太适合的场景：高度定制的一次性项目、需要深度法律判断的诉讼策略、纯创意性的法律论证。这些工作的"步骤"本身就不确定，蒸馏不出稳定的步骤链。还有一个前提条件：你必须有自己的SOP。 哪怕它只存在于你的脑子里和Word批注里。如果你连自己审合同的逻辑都说不清楚，AI也帮不了你蒸馏——它只能输出通用的审查清单，和网上的模板没区别。作者简介： 陈石律师，浙江海泰律师事务所副主任、高级合伙人、房地产与建设工程部主任，宁波市律师协会副秘书长、第七届宁波仲裁委员会仲裁员，聚焦建筑房地产、投融资、并购重组及商事争议解决。曾获多家法律媒体与专业机构认可，荣登 LegalOne 2025 中国区建工及房地产实务先锋 45 强、律新社 2025 年度管理合伙人 20 佳（华东），入选《商法》The A-List 法律精英，获评 ALB China 区域市场十五佳长三角地区律师新星，并获律新社 2024 年度并购领域品牌之星。长期为万科、华润置地、信达地产、保利置业、招商蛇口、中海地产等企业提供法律服务，承办"首宗百亿地王""长春第一高楼""台州第一高楼"等代表性项目，累计服务项目投资额超千亿。近年来持续推动 AI 与法律实务融合，强调以结构化方法打通技术逻辑、法律判断与商业场景；著有《赋能法律人：AI 底层思维与应用范式》，并在多地开展相关主题讲座与分享。

## 一、在 WorkBuddy 中创建「老强法律人蒸馏器」

WorkBuddy 的定位很契合你这套思路：

它不是让你“问AI法律问题”，而是 **承载一个可复用、可演化的法律专家系统**。

### 1️⃣ 第一步：创建你的 Legal Profile（蒸馏起点）

**目标：把“你脑子里的规则”变成 CLAUDE.md / Profile.md**

#### 在 WorkBuddy 中的操作

- 新建一个 **Legal Profile Bot**（可命名为「老强-供应商合同审查」）
    
- 开启 **Cold‑Start Interview（冷启动访谈）**：
    
    - 由 WorkBuddy 向你连续提问（10–20 分钟）
        
    - 问题示例：
        
        - 你审查合同时最在意哪 5 个条款？
            
        - 哪些条款是“绝不让步”？
            
        - 风险如何分级（低 / 中 / 高）？
            
        - 什么情况下必须升级到合伙人？
            
        
    
- 上传 **种子文件**：
    
    - ✅ 已签署合同（脱敏）
        
    - ✅ 审查备忘录 / 批注版 Word
        
    - ✅ 升级矩阵 / 内部审批表
        
    
- WorkBuddy 自动生成：
    
    - `Profile.md`
        
    - 包含：
        
        - 合同偏好
            
        - 红线条款
            
        - 风险分级标准
            
        - 升级规则
            
        
    

✅ **这一步不要求你写 KM，只要求你“交作业”。**

---

### 2️⃣ 第二步：定义 Skill（怎么做）

**目标：把“凭感觉审”变成“按步骤执行”**

#### 在 WorkBuddy 中的操作

- 创建一个 **Skill：「供应商合同审查 Skill」**
    
- 每个 Skill = 一个 `SKILL.md`
    
- 拆解成 **步骤链 + 检查门（Gate）**
    

示例结构：

markdown

markdown

```
Skill：供应商合同审查

Step 1｜合同识别
- 输入：合同文本
- 判断：是否为标准供应商合同
- 输出：合同类型标签

Step 2｜加载 Profile
- 调用：老强 Profile
- 校验：是否匹配行业/金额/地区

Step 3｜逐条审查
- 输入：条款原文
- 判断标准：Profile 中的红线条款
- 输出：风险标记（🟥🟧🟩）

Step 4｜Gate Check
- 若风险等级 = 高 → 强制升级
- 禁止进入 Step 5

Step 5｜生成审查意见
- 输出格式：Word 批注式意见
```

✅ **Skill 不依赖“灵感”，只依赖“你曾经怎么审”。**

### 3️⃣ 第三步：部署 Agent（什么时候做）

**目标：解决“不是不会做，而是忘了做”**

|Agent|作用|
|---|---|
|🔁 续期监控器|扫描合同台账，预警到期|
|⚖️ 庭期监控器|抓取开庭、举证、上诉期限|

|™️ IP续费监控器|商标/专利续费倒计时|

✅ Agent 不创造判断，只是 **按时触发 Skill**。

### 4️⃣ 第四步：接入 Connector（数据在哪）

**目标：让 AI 像资深律师一样“知道去哪查”**

#### 在 WorkBuddy 中配置 MCP Connector

- 文档管理：iManage / Google Drive
    
- 法律研究：Westlaw / CourtListener

Connector 的作用：

> **Skill 不再问“合同在哪”，而是直接调取。**

## 三、给你的一些关键建议（非常重要）

### ✅ 1. 不要一开始就做“全所蒸馏”

> 先做 **1 个人 × 1 个高频场景**​

例如：

- 你自己的供应商合同
    
- 某合伙人的 NDA 审查
    

**成功一个，再复制。**

---

### ✅ 2. Profile ≠ 完美，而是“可用”

- 不追求一次写清
    
- 允许 AI 从 **“错一次就记住”**​ 中迭代
    
- Profile 是活的
    

---

### ✅ 3. Skill 要“像你”，而不是“像教科书”

- 少写“法律依据”
    
- 多写：
    
    - “这类合同我通常怎么改”
        
    - “出现这句话我会警惕”
        
    

---

### ✅ 4. 初级律师的角色会发生变化

|原来|将来|
|---|---|
|抄模板|运行 Skill|
|找合同|Connector 自动拉|
|担心漏审|Gate 防止跳步|
|写报告|审核 AI 输出|

✅ **你不是在替代他们，而是在“放大你的判断力”。**

---
