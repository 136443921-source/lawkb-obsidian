# 中小律所数字分身模板 · 总体方案 v1.0

> 一句话结论：把"小强律师数字分身系统"抽象成一套**品牌无关、可一键克隆**的律所数字分身骨架——双基座 + L0 路由 + 20+ 专项技能 + 知识飞轮 + LTI 质量门禁 + 红蓝对抗推演 + 驾驶舱 + 自动化——任何 3–20 人的中小律所都能在 90 天内低成本落地，并持续自进化。

---

## 0. 为什么中小律所现在就需要数字分身

数字分身不是"聊天机器人"，而是律所**可沉淀、可复核、可追溯的第二大脑**：年轻律师问它、它答得出依据；老律师审它、它经得起红蓝对抗；案件结束、经验自动入库。

| 中小律所痛点 | 数字分身的解法 |
|---|---|
| 案多人少，文书重复劳动占比高 | 文书起草 → 红蓝复核 → LTI 门禁 → 交付，流水线化 |
| 知识沉淀靠人脑，人走知识走 | 知识飞轮把判例/要件/经验卡片化，永久留存 |
| 年轻律师成长慢、出错率高 | 模拟法庭 + 红蓝对抗，上岗前先"流干眼泪" |
| 合规与执业风险高 | LTI 五维 QC 门禁，REJECT=0 才准交付 |
| 管理靠微信群，案件状态不可视 | 案件生命周期大屏 + 驾驶舱，一屏掌控 |

---

## 1. 模板定位与适用对象

- **适用**：3–20 人综合所 / 专业所；实习律师培养体系薄弱的所；知识管理几乎为零的所。
- **最佳切入点**：先在一个高频案由（如合同、侵权、工伤）跑通闭环，再横向复制。
- **不适用（需私有化变体）**：涉密业务占主导、必须数据不出局的所——此时把连接器与知识库改为本地/私有部署即可，架构不变。

**品牌无关设计**：模板中所有 `[律所名]`、`[律师名]`、`[案由]` 均为占位符，克隆后全局替换即可。本方案以"XX 律所数字分身系统"代称。

## 2. 核心能力矩阵（6 大能力）

| # | 能力 | 对应模块 | 直接价值 |
|---|---|---|---|
| C1 | 法律咨询统一入口 | legal-consult-router（L0 五问分诊） | 不裸答、不漏派，所有法律问题先分诊 |
| C2 | 专项作业 | 20+ 专项技能（检索/文书/合规/证据/报价） | 每个环节有专业智能体兜底 |

| C4 | 质量门禁 | LTI 文本监控器（R/L/C/T/P） | 法条真实、逻辑自洽、格式合规 |
| C5 | 推演与对抗 | 蓝队 + 红队 + 模拟法庭 + 战情室 | 出庭前预驳回，降低败诉率 |
| C6 | 可视与自动化 | 驾驶舱 + 每日摄入 + 周报 + 结案沉淀 | 管理可观测、运维无人值守 |

## 6. 知识飞轮配置

- **卡型**：裁判规则卡、审判要件卡、经验卡、文书范式卡、合规审查卡、工作流卡。
- **挂载子目录**：`02-提炼/`（经验卡片）、`06-沉淀/`（裁判规则库）、`04-Log/`（飞轮日志）。
- **日摄入配额**：5 个自有库 × 3 篇/日（LTI 缓存兜底，拒绝凭记忆灌条文）。
- **编号治理**：R-* 规则卡取号脚本化，同号冲突自动门禁（参考 lawkb-rule-id-governance）。

## 7. LTI 质量门禁（简化版，必过）

| 维度 | 校验内容 | 不通过后果 |
|---|---|---|
| R 法条真实 | 条号/条文与权威源一致 | REJECT |
| L 法理逻辑 | 推理链自洽、无断层 | REJECT |
| C 一致性 | 案号/名称/金额三处一致 | REJECT |
| T 溯源 | 每条结论可回源 | REJECT |
| P 程序 | 程序节点正确（如管辖/时效） | REJECT |

**铁律：REJECT=0 才准交付。** 交付物标准：DOCX 带修订标记 + 干净签字版双轨，存腾讯文档/本地归档。

## 9. 成本与人力测算

- **人力**：1 名管理员（合伙人兼，每周 2–3h）+ 0.5 名助手（知识入库/摄入）。
- **工具**：WorkBuddy 席位 + 连接器（IMA/元典/邮箱，多为按量计费）。
- **周期成本**：以中小所体量，首年投入主要为人力时间，工具边际成本低；ROI 主要来自文书工时下降 + 年轻律师成长加速 + 败诉风险下降。
- **隐性收益**：知识资产化，人员流动不丢经验。

---

## 10. 风险与护栏（六-B 铁律）

1. **先备份再动手**：任何写入型操作前 `cp -n` 防覆盖 + 时间戳备份。
2. **先排查确认再批量修改**：批量前先 dry-run，确认非误报。
3. **幂等确认**：改后双目录同步 + 零残留验证。
4. **红线**：不代点 UI、不打印令牌明文；令牌不可凭空造，需 UI 重新授权。
5. **隐私隔离**：当事人证件号/银行卡/手机号/证据原件**禁止入知识库**，只提炼方法论。
6. **门禁**：LTI REJECT=0 才交付；连接器 `enabled=false` 先翻 true 再调用。
