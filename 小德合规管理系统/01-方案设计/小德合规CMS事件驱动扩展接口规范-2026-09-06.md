# 小德合规 CMS 事件驱动扩展接口规范（EDI · v1.0.0）

> 设计初衷：CMS 双子模板（子模板A 慈善合规中枢 / 子模板B 医院合规与纠纷处理）覆盖"稳定领域"，但**遇突发/新领域事件（如本周 R6 航合物流致死事故）双子模板没有现成路由**。EDI（Event-Driven Interface）作为**第三层可插拔扩展接口**，让任意新事件以**零修改 gate-config + 零破坏双子模板**的方式接入 G8 门禁 + 周巡检 + 经验沉淀闭环。

---

## 一、为什么需要 EDI（背景与痛点）

| 已有问题 | 现象 | 影响 |
|---|---|---|
| 双子模板领域覆盖窄 | 仅覆盖慈善+医院，运输/数据/税务/劳动/广告/环保等 6+ 领域无现成路由 | 突发领域事件降级为"通用合规体检"，漏掉领域专项规则 |
| 突发领域新卡沉淀慢 | 本周 R6 航合物流事故到经验卡沉淀需 6 小时跨文件夹落盘 | 知识飞轮回流链路滞后 |
| 门禁配置不可改 | gate-config.md v1.1.0 已 G0-G8 排满 | 任何新领域不敢动门禁配置 |
| 周巡检 domain 字段硬编码 | 简报 frontmatter `cms_subtemplates` 仅列 A+B | 扩展领域无 frontmatter 字段可填 |

**EDI 解决方案**：把"领域不固定、事件驱动"的扩展域从双子模板剥离出来，作为独立接口层；任何新事件只需新增"注册条目（1 行 YAML）+ 经验卡 1 张 + 简报 1 段"，不修改任何门禁配置。

---

## 二、EDI 三层架构

```
┌──────────────────────────────────────────────────────┐
│ G8 非诉合规门禁（gate-config.md v1.1.0+）             │  ← 不可修改，受铁律约束
├──────────────────────────────────────────────────────┤
│ ★ 第 3 层 · 事件驱动扩展接口 (EDI · 本规范)            │  ← 本规范定义
│   - 事件领域 schema（领域+触发+依据+路由+留痕）       │
│   - 注册表（02-落地报告/事件驱动扩展接口注册表）       │
│   - 实例化卡片（每次新事件沉淀一张经验卡）              │
├──────────────────────────────────────────────────────┤
│ 第 2 层 · CMS 双子模板（不可修改）                    │
│   - 子模板 A：慈善组织合规与纠纷处理                   │
│   - 子模板 B：医院合规与纠纷处理                       │
├──────────────────────────────────────────────────────┤
│ 第 1 层 · L0 路由 小德合规管理系统（CMS）               │  ← 父路由，调用 A/B/EDI
└──────────────────────────────────────────────────────┘
```

**关键约束**：EDI 层**不得修改双子模板核心字段**，仅在"实例化"阶段向双子模板**反向注入**新经验卡/新规则卡（沿用既有互哺路径）。

---

## 三、EDI 注册表 schema（8 字段必填 · YAML）

任何新事件在 `02-落地报告/事件驱动扩展接口注册表-<日期>.md` 下追加如下 YAML 块（每事件一行）：

```yaml
- event_id: EDI-YYYYMMDD-NNN   # 唯一编号（按时间戳顺序递增）
  trigger_date: YYYY-MM-DD
  event_type:  # 6 选 1
    - 突发安全事件（运输/生产/消防）
    - 数据合规专项（跨境/个人信息/AI训练）
    - 税务合规专项（稽查/汇算清缴/转让定价）
    - 劳动用工专项（裁员/工伤/职业病）
    - 广告合规专项（医疗/金融/教培）
    - 环保/ESG 专项
  cms_layer: 3-EDI
  base_subtemplate:  # 1-N 个，用于跨模板联动
    - 子模板A-慈善合规中枢（关联交易交叉）
    - 子模板B-医院合规（工伤认定联动）
  primary_skill_route:    # 主技能路由（必填）
    - <主技能名>
  cross_domain_skills:    # 跨领域技能（可空）
    - <技能2>
  knowledge_called:    # 非空（满足 G8 留痕铁律）
    - <卡 1>
    - <卡 2>
  legal_basis:    # 法条引用
    - <法条 1>
  trigger_source:    # 触发源（如：周巡检 R6、临时专项、紧急事件）
  inspection_report: <周巡检简报路径>
  experience_card: <新增经验卡路径>
  confidence: <0-1>
  recycle_hook: <下次同类事件如何召回>
  archived_until: <YYYY-MM-DD>
  status: active / archived
```

## 四、EDI 调用协议（5 步走）

```
事件触发
   ↓
[1] 在注册表追加新 event_id（YAML）
   ↓
[2] 触发 L0 路由 → 调 primary_skill + cross_domain_skills
   ↓
[3] 产出经验卡（落 02-提炼/经验卡片/非诉合规/ 或对应子目录）
   ↓
[4] 周巡检简报 frontmatter 增 cms_extensions_this_week 字段 + 风险点新段落
   ↓
[5] 回流钩子：下次同类事件触发时由 CMS 自动召回（recycle_hook 字段驱动）
```

每步均受 G8 门禁强制步骤 1-5 管辖（详见 `合规与非诉维度P0升级落地报告-2026-08-27.md` §A1）：
1. 非诉文书经「非诉文书红蓝复核工作流」复核通过
2. 合规专项体检已跑（输出风险点清单）
3. 所有对外文本过 `LTI文本监控器` 防火墙
4. **调用记录已留痕**（消灭 `knowledge_called:无`）
5. **本次非诉经验已沉淀为经验卡**

## 五、EDI 与双子模板的边界（重要）

| 项 | 双子模板（慈善A/医院B） | EDI（事件驱动） |
|---|---|---|
| **领域** | 固定（慈善/医院） | 任意（含运输/数据/税务/劳动/广告/环保） |
| **触发** | 常规合规体检 | 突发/专项事件 |
| **schema** | 6 域固定结构 | 8 字段动态（见 §三） |
| **沉淀位置** | `03-经验卡片/<子模板>/` | `02-提炼/经验卡片/非诉合规/` 或 `03-经验卡片/慈法合规/` 等 |
| **门禁** | G8 | G8（同） |
| **gate-config 修改** | 否 | **绝对不动**（EDI 通过注册表 + frontmatter 注入，不改门禁配置） |

## 六、EDI 首次实例化 · 2026-09-06 R6 航合物流事故（对照样本）

| 字段 | 取值 |
|---|---|
| event_id | EDI-20260906-001 |
| trigger_date | 2026-09-06 |
| event_type | 突发安全事件（运输） |
| cms_layer | 3-EDI |
| base_subtemplate | 子模板A（关联交易交叉核查）+ 子模板B（工伤认定联动） |
| primary_skill_route | 医院合规与纠纷处理（子模板B跨域延伸） |
| cross_domain_skills | 小德慈善合规中枢、决策卡-航合物流事故四段式表态框架-20260904 |
| knowledge_called | R-LN-051、R-LN-052、R-PI-243、R-PI-244、R-PI-253、R-HT-187、R-HT-227、决策卡 DEC-20260904-006 |
| legal_basis | 安全生产法第21、41条；道路交通安全法第76-79条；民法典第1217条；道路运输车辆动态监督管理办法；指导案例24号 |
| trigger_source | 周合规巡检 R6（事件驱动） |
| inspection_report | 周合规巡检简报-2026-09-06.md §R6 |
| experience_card | 经验卡片-运输安全合规-重型货车致死事故整改框架与四段式表态-2026-09-06.md |
| confidence | 0.85 |
| recycle_hook | 下次同省/同地重型货车致死事故发生后 24 小时自动召回；任何运输企业+慈善组织合作项目立项时作"前置必读" |
| archived_until | 2026-12-04 |
| status | active |

**后续同类事件**：直接复制本 YAML 块 → 改 event_id 与 trigger_date → 完成 5 步走 → 简报与经验卡自动接入。

## 七、EDI 升级路线（v1.1+ 候选）

- v1.1：把 EDI 注册表接入 WorkBuddy Connector，使"事件触发 → 智能体路由 → 经验沉淀"全自动化（候选 connector：yuandian-mcp 法规匹配 + ima-mcp 经验回写）
