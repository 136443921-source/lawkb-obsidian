# 小德合规管理系统 · 搭建方案（2026-08-27 实地核查版）

> 目标：将「小德[[慈善组织合规|慈善组织合规]]专家」从一个问答型身份，升级为**嵌入小强律师数字分身系统的合规管理子系统**，由两大子模板组成——
> **子模板A 慈善组织合规与纠纷处理** + **子模板B 医院合规与纠纷处理**，
> 统一覆盖 **内部制度 / 流程 / 运营 / 财务 / 人资 / 税务** 六域。

> 🟢 **执行状态（2026-08-27 已落地）**：Phase 0–4 全部完成。父路由 `小德合规管理系统` + 子模板B `医院合规与纠纷处理` 已新建；子模板A `小德慈善合规中枢` 已加「子模板A 身份声明」段对齐；门禁 G8 / 铁律第6条 / 周合规巡检已扩展双模板。落地报告见 `小德合规管理系统四阶段落地报告-2026-08-27.md`，双跑验证见 `CMS四阶段落地-实战双跑验证-2026-08-27.md`。

---

## 一、系统定位

「小德合规管理系统（CMS）」是小强律师数字分身系统的**合规管理子系统**（类比既有的「模拟法庭庭审系统」子系统定位）。

- **不越位**：纯法律争议（诉讼/仲裁/合同违约/侵权）仍优先走小强律师数字分身系统；CMS 只接管"合规管理 + 非诉纠纷处理"层。
- **不重复造轮子**：复用既有数字分身四子架构（知识飞轮 / LTI / HIR / 跨案识别）、门禁 G0–G8、铁律、周合规巡检自动化。
- **双子模板共享六域框架**：慈善与医院用同一套六域语言，输出可比、经验可互哺。

### 真实缺口（本方案要补的）
1. **父级路由缺失**：目前 小德慈善合规中枢 只认慈善，没有"慈善 vs 医院"的顶层分发器。
2. **医院子模板无"管理系统"外壳**：医疗纠纷专项 skill 偏诉讼对抗，不是"六域合规管理"；8章卡是"书本章节"不是"六域工作流"。
3. **六域框架未统一**：慈善按 139条16领域、医院按 8 章，术语不对齐，跨模板经验无法互哺。
4. **医院合规卡库未结构化沉淀**：医疗纠纷/ 卡在 经验卡片/ 下，未纳入非诉合规沉淀与门禁留痕体系。

## 三、总体架构

```
小强律师数字分身系统
└── 合规管理子系统（小德合规管理系统 CMS）
    ├── L0 父路由：小德合规管理系统（新建，识别慈善/医院/数据税务，分派子模板）
    │
    ├── 子模板A：慈善组织合规与纠纷处理（升级自 小德慈善合规中枢）
    │   └── 六域工作流：制度 / 流程 / 运营 / 财务 / 人资 / 税务
    │       底座：慈法合规60卡 + 慈善合同纠纷9卡 + 139条手册
    │
    └── 子模板B：医院合规与纠纷处理（新建）
        └── 六域工作流：制度 / 流程 / 运营 / 财务 / 人资 / 税务
            底座：医疗纠纷/8章卡 + 医法知识库 + 医疗纠纷专项/人损纠纷专项 skill

        【两模板共用六域框架 + 共用数字分身接口】
        ├── LTI 文本监控器（legal-base 继承，R/L/C/T/P 五维）
        ├── 门禁 G8 非诉合规门禁（覆盖双模板交付物）
        ├── 铁律第6条：调用必留痕 + 必产卡（非诉合规/ → 新增 医院合规/）
        ├── 知识飞轮：02-提炼/经验卡片/ 下 非诉合规/ + 医院合规/ 双轨沉淀
        └── 跨案件模式识别（已跨域，自动召回历史相似合规/纠纷经验）
```

## 四、六域框架映射（双模板共用）

| 六域 | 子模板A 慈善 | 子模板B 医院（对应既有8章卡） |
|---|---|---|
| **内部制度** | 139条手册·制度体系（机构架构/党的建设） | 第三章风控基础 / 第四章设立与主体资格 |
| **流程** | 业务流程合规（捐赠募捐/关联交易/重大活动审批流） | 第二章常年法律顾问服务内容与流程 |
| **运营** | 项目执行追踪/信息公开/受益人管理 | 第七章资产管理与运营 |
| **财务** | 预决算/收支/投资/募捐成本管理 | 第六章设备药品采购 / 第八章医保基金合规 |
| **人资** | 劳动人事/志愿服务管理 | 第五章[[人力资源管理|人力资源管理]] |

> 映射价值：把"书的章节"翻译成"管理的六域"，老强以后问任何机构的合规问题，都用同一套语言，系统也能把"医院采购合规"经验反哺"慈善投资活动合规"。

## 六、分阶段搭建步骤

### Phase 0 · 父路由 + 六域框架（轻量，1 个技能）
- 新建 `小德合规管理系统` 技能（user 级），定义 L0 路由：慈善→子模板A、医院→子模板B、数据/税务→转对应审查 skill。
- 内置"六域框架"定义，作为两子模板共用语言。
- 非破坏性，复用 legal-base。

### Phase 1 · 子模板B 医院合规管理搭建（核心增量）
- 新建 `医院合规与纠纷处理` 技能（extends legal-base），把现有 8 章卡按六域重映射为工作流。
- 在 `02-提炼/经验卡片/` 下新建 `医院合规/` 目录 + README 沉淀规范。
- 路由红线：医疗事故/医疗损害诉讼 → 转小强律师数字分身系统 + 医疗纠纷专项；纯[[医院运营合规|医院运营合规]] → 本模板接管。
- **实战验证案例**：韩杰医生医疗事故再审辩护（医疗损害纠纷，走"纠纷处理"分支验证路由不越位）。

### Phase 2 · 子模板A 慈善升级对齐
- 把现有 `小德慈善合规中枢` 重命名为/重构为 `子模板A：慈善组织合规与纠纷处理`，与父路由 + 六域框架对齐（保留 139条内规强制引用 + 慈法卡库）。
- 纠纷处理分支明确：慈善内部治理/捐赠/信息公开纠纷 → 非诉调解优先，诉讼转小强系统。

### Phase 3 · 接口对接（嵌入收口）
- 门禁 G8 描述扩展涵盖双模板。
- 铁律第6条增列 医院合规/ 目录。
- 周合规巡检 automation 巡检对象扩展（基金会 + 医疗机构）。

### Phase 4 · 实战双跑验证
- 慈善：厚德基金会某合规体检走子模板A。
- 医院：韩杰医生案 / 某医院常年顾问体检走子模板B。
- 验证跨模板经验互哺（如医院采购合规经验能否反哺慈善投资活动合规）。

## 七、风险与边界（诚实交代）

1. **医院知识是"书本章节"非"实战卡"**：8章卡源自指南性材料，需 Phase 1 重映射为可调用工作流，并补真实案例卡（韩杰案即首张）。
2. **不替代小强律师数字分身系统的诉讼职能**：CMS 红线——任何涉诉/涉裁问题必须转小强系统，CMS 只做非诉合规 + 纠纷调解层。
3. **连接器依赖**：数据/税务审查 skill 若需威科/北大法宝等外部库，仍依赖连接器保活（当前 ima-mcp/yuandian-mcp 已 connected，但威科/北大法宝未连接）。
4. **六域对齐是软约束**：慈善 139条 与医院 8章 术语差异大，初期用"映射表"过渡，不强行改底层卡结构。

---

## 八、落地建议

- **建议分两批**：Phase 0+1（父路由+医院模板，本方案最大增量）先上， Phase 2+3（慈善对齐+接口收口）紧随，Phase 4 实战验证。
- **零新建法律风险面**：所有底层能力（慈法卡/医疗卡/数据税务审查/LTI/门禁）均为既有资产，本方案只做"路由 + 框架对齐 + 沉淀目录"，符合六-B 安全铁律（先备份再改）。
- **可立即开工**：本方案不依赖任何外部授权，父路由与医院模板可在本会话内非破坏性落地。
