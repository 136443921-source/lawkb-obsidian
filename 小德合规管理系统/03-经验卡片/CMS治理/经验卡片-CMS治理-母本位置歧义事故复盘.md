# 经验卡片-CMS治理-母本位置歧义事故复盘

> 🔴 **事故等级：高（静默失真型）**。与「SKILL.md 声明 107 张卡实测 0 张」同性质——**系统看着正常，实际在错误前提上运行**。

## 一、事故概况

- **时间**：2026-09-13 00:30 前后（v1.3.0 变更守卫机制建立过程中）
- **现象**：母本 `小德合规管理系统-运维手册（五模板版）.md` 与 ①单模板台账 `小德慈善组织合规管理系统-运维手册备忘录.md` 被**异常移动到 `01-方案设计/` 目录**，06-运维备忘录 目录内仅剩脚本与 tools/
- **直接后果**：变更守卫 `cms_change_guard.sh check` 读取台账返回 **0 行**（静默失真），守卫失去检测能力却无报错
- **波及面**：权威源（L0）出现**位置歧义**——同一文件在两处存在，编辑哪份变成不确定项

## 二、根因分析（4 项）

| # | 根因 | 性质 |
|---|---|---|
| R1 | 权威源物理位置无强制约束，移动文件不触发任何告警 | 治理缺位 |
| R2 | 守卫依赖「文件就在 06/」的隐性假设，文件被挪即失效 | 假设脆弱 |
| R3 | 计数器正则只认 `\| 2026-` 单格式，台账实际混用 `\| **2026-**` 加粗格式 | 正则不完备 |
| R4 | 脚本变量未加引号 / bash 3.2 兼容问题 | 工程缺陷（见第四节） |

> 📌 **R1 是根本原因**：只要权威源可以"被挪走还看起来正常"，任何检测都建在沙上。

## 三、处置过程（已执行）

1. **发现**：shell `find` 仍能定位母本（在 01-方案设计/ 下），确认未丢失
2. **恢复**：`cp -n` 将 01 下副本恢复至 06-运维备忘录/，**md5 核验一致**（母本 74415B / v1.3.0；单模板 36489B / v1.3.0）
3. **去重**：01 下重复副本 `mv` 至 `/tmp/xiaode_dedup_20260913-003831/`（**未硬删**，保留可追溯）
4. **止血**：母本新增铁律「**母本物理位置唯一 = 06-运维备忘录/**，别处同名文件一律视为副本，不得就地编辑」
5. **补检测**：新增 〇.4 变更守卫 + 基线 B23（受控文件数），把"系统一变→备忘录必回写"由纸面协议升级为 md5 三态强制

## 四、3 个 bug（全是实跑才暴露）

| # | bug | 触发 | 修复 |
|---|---|---|---|
| B1 | `MARKED_AT=$(date '+%Y-%m-%d %H:%M:%S')` 含空格，被 shell 当命令执行 | `mark` 时 | `printf 'MARKED_AT="%s"\n' "$(date ...)"` 整值加引号 |
| B2 | `local total=$((changed+added+removed))` 在 macOS 默认 bash 3.2 下赋值未生效；变量名紧贴中文括号 `总数（改…）` 被误解析 | `check` 时 | 拆为独立 `local changed=0` 等 + 计数变量用 ASCII 名 + 中文注释另起行 |
| B3 | 台账行两种格式 `\| 2026-`（4 行）与 `\| **2026-**`（5 行），原正则 `^\\| 2026-` 只数前者 → **9 行错报 4 行** | `ledger_n()` | 正则改为 `^\|[[:space:]]*\**2026-` 兼容加粗 |

> ⚠️ **B3 最危险**：它让守卫"看着正常"实际漏计 5 行。若未实跑，这就是**新的漂移源**——印证铁律「自检脚本不实跑，它自己就成了新漂移源」。

## 五、教训提炼（可迁移）

1. **权威源必须物理锚定 + 位置告警**：任何"唯一真源"都要有位置约束，移动即视为事故
2. **脚本写完必须实跑，且要故障注入**：正常态通过 ≠ 正确，须故意制造异常验证报警链路
3. **计数正则须兼容全部历史格式**：台账格式会演进（加粗/不加粗），正则要向后兼容
4. **shell 变量一律加引号，避开 bash 3.2 坑**：macOS 默认 bash 是 3.2，复合赋值/local 紧贴中文均不可靠
5. **静默失真 > 显性报错**：系统不报错但答案错，危害远大于崩溃

## 六、铁律 / 防呆机制（已固化进母本）

- **铁律④（位置唯一）**：母本物理位置唯一 = `06-运维备忘录/`，别处同名文件一律视为副本，不得就地编辑
- **〇.4 变更守卫**：53 个受控文件 md5 快照 + 台账行数 + 版本登记；`check` 三态（无变更✅／已回写✅／未回写🔴 exit 2）；`mark` 回写后登记基线
- **回写 SOP**：任何系统变更 → S4 回写母本（台账 + 基线 + 版本）→ 跑守卫 `mark` 登记
