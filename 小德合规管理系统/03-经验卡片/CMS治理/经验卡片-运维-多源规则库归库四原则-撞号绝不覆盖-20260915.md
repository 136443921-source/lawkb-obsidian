# 多源规则库归库四原则 · 撞号绝不覆盖

> **一句话**：归库不是「把文件合并成一个」，是「**在不丢一条、不覆盖一条的前提下建立单一真源**」——
> 撞号时**先判副本还是异名**，异名一律重编号保留双方，**绝不静默覆盖**。

## 一、场景

`蓝队律师合同审查` 规则库散落 **58 个 json**（含 45 个 `risk_rules_expansion_*.json`），无单一真源、无加载器，
且历史记载条数混乱（11 / 147 / 132 / 2447 四种说法）。归库前必须先拿到真数。

## 二、归库四原则

| # | 原则 | 做法 | 反例（禁） |
|---|---|---|---|
| 1 | **真数先行** | 用「含 `id` + `name` 的条目」为统计口径递归计数，不用"顶层键数""所有 list 长度" | ❌ 用 `len(dict)` 当条数（得到 11）；❌ 把 keywords 等子数组计入（得到 2447） |
| 2 | **基准层 ID 不动** | 主库条目 ID 一字不改，保护既有引用与外链 | ❌ 统一重排"更整齐" |
| 3 | **撞号先分类** | 逐条比对 `name`：同名→副本（可去重）；异名→**真撞号（必须重编号）** | ❌ 一律后写覆盖先写 |
| 4 | **同号不同视角分层** | 变体层（ER 派生）/ 维度层（十维视角）独立成层，`base_rule_id` 关联 | ❌ 硬并进主体造成二次撞号 |

## 三、撞号判定法（可复用代码思路）

```python
# 1) 建主库索引 main_by_id
# 2) 遍历 expansion，按 id 聚合
# 3) 逐条判定：
if rid not in main_by_id:      并入（非撞号）
elif exp.name == main.name:    去重丢弃（副本）
else:                          真撞号 → 重编号至安全号段（M1001+）
```

**安全号段选取**：主库最大 862、expansion 最大 920 → 取 **M1001 起**，留足余量。
**分配要确定性**：按 `(old_id, 文件名)` 排序后递增分配，保证重跑结果一致（**幂等的命门**）。

## 四、本次实测数据（2026-09-15）

| 项 | 数 |
|---|---|
| 主库 `risk_rules.json` | **729**（M1–M862，133 空号） |
| expansion 唯一 ID | 634（M201–M920） |
| 撞号 | **577** = 560 同名副本 + **49 条异名真撞号** |
| 归库后 | 主体 **835** + 变体 730 + 维度 71，**重复 ID = 0** |
| 覆盖丢失 | **0**（双方全保留） |

**真撞号示例**：主库 M847「境外主体特殊审查」 vs expansion M847「合同约定解除条件成就认定标准风险」
→ 主库保持 M847，expansion 版重编号为 **M1032**，原号存 `_renamed_from`。

## 五、幂等验证（六-B 铁律最后一道）

连跑两次 `--apply`，**逐字段 hash 比对**（不能只比文件大小或 md5）：

```
rules / variants / dimensions / dedup_log / rename_log / id_index  →  全部 ✅ 一致
仅 metadata.generated 时间戳变化（预期，不算漂移）
```

> ⚠️ **坑**：直接比 `md5` 会因为时间戳不同而报警 → 必须**排除 generated 后**比对内容字段。

## 六、铁律清单

1. **权威数据绝不静默覆盖** —— 撞号宁可重编号，不可后写盖先写。
2. **不硬删** —— 12 个 backup 归档至 `_archive_backup/`，可回滚。
3. **先备份再动手** —— 全量 `cp -R config/` 至 /tmp 时间戳目录（本次 9.0MB）。
4. **dry-run 先行** —— 出报告 → 人工确认 → 才 `--apply`。
5. **统计口径要写进报告** —— 本次四种错口径（11/147/132/2447）全部源于口径不明。
