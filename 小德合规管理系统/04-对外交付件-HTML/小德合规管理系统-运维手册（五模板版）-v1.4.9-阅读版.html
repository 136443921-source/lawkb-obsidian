〇.4 变更守卫（技术强制 · 2026-09-13 新增）🛡️

〇.2 的 SOP 是人的自律；本节是机器的强制。 光有协议没有检测，等于没有协议 —— 「回写母本」会在赶进度时被静默跳过。

守卫脚本：06-运维备忘录/cms_change_guard.sh（v1.0.1 · 已实跑验证三态）

bash cms_change_guard.sh init              # 建立/重建指纹快照（仅在回写完成后执行）
bash cms_change_guard.sh check             # 检测（默认）：系统变了但台账没加行 → 红态报错
bash cms_change_guard.sh mark "变更摘要"    # 回写完成后登记新基线
bash cms_change_guard.sh list              # 列出受控文件清单

原理：对 CMS 全部受控文件取 md5 存快照，同时记录「台账行数 + 母本 version」；check 时三态判定 ——

状态 判定输出 退出码 处置
无文件变动 ✅ 备忘录无需更新 0 —
有变动 且 台账行数已增加 ✅ 回写已完成（版本未刷则提示） 0 确认后 mark
有变动 但 台账行数未变 🔴 未回写，本次迭代【未完成】 2 补 S4 三件事

受控范围（53 个文件）：00-索引／SKILL.md／01-方案设计(11)／02-落地报告(8)／03-经验卡片(27)／05-系统配置(3)／06-运维备忘录 内 md(2)。 新增系统资产时须同步在脚本 collect() 中追加。

执行时机：① 每次系统改完必跑；② 每周运维日跑；③ 母本回写（S4）完成后执行 mark 登记基线。

⚠️ 2026-09-13 事故教训（权威源位置歧义）：本母本与单模板 md 曾被异常移动至 01-方案设计/ 目录， 导致权威源出现两个物理位置、守卫脚本读台账返回 0（静默失真）。已恢复并核验 md5 一致，副本移出。 铁律补充：母本与单模板台账的物理位置唯一 = 06-运维备忘录/。 若在别处发现同名文件，一律视为副本，须移出，不得就地编辑。
