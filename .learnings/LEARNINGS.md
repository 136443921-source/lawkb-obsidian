# 学习记录 (LEARNINGS)

## 2026-08-27 · git 批量提交特殊文件名解析坑

**现象**：用 `git status --porcelain | sed 's/^...//'` 提取路径后逐文件 `git add -- "$f"`，含空格/中文/书名号的文件名被 git status 加引号包裹（如 `"Clippings/权威发布 - ...md"`），导致 `git add` 把引号当作路径一部分 → `pathspec did not match` 失败。

**正确做法**：
- 优先用 `git add -A`（git 自己解析路径，不受引号影响）。
- 若必须逐文件处理，用 `git status --porcelain -z` 取出 NUL 分隔的原始路径，或 `git diff --cached --name-only -z | xargs -0 ...`。
- 分批提交用 `git diff --cached --name-only -z | xargs -0 -n 500 -J % git commit -m "..." -- %`（注意 `-m` 必须在 `--` 之前，否则被当成 pathspec）。

**教训**：自动化 git 备份脚本不要手动解析 porcelain 文本，直接用 `git add -A` + `git commit`。本任务最终因此补录了 4 批。

## 2026-11-09 · 写入型脚本必须覆盖「第二次写入」分支

**现象**：带自动备份的 `execution_fact_gate.py` 在端到端连续 `set` 时，第二次写入因文件代理对已存在目录的 `mkdir(exist_ok=True)` 抛 `FileExistsError` 而中断；首次写入与只做一次修改的单测均正常。

**正确做法**：① 对备份目录用 `mkdir(parents=True, exist_ok=True)` 并捕获 `FileExistsError` 后校验 `is_dir()`；② 备份名加入 UUID，避免同微秒覆盖；③ 凡「每次写入都自动备份」的脚本，单测必须至少连续写两次并断言备份数量，不能只测首次创建。

**教训**：这是典型的「静默成功/首次通过掩盖后续写入失败」变体，端到端 CLI 实跑比只调用 Python 函数更容易暴露。详见 `ERRORS.md` 同日记录。

## 2026-11-09 · 索引回读遇「检索静默失效」不得判为写入失败

**现象**：中枢正式回写后，用 bash `grep -n "WF-137\|DEC-2026-035"` 回读 `04-Workflows/_索引.md` 与 `03-决策档案/_近期决策.md`，返回空、退出码 1，一度疑似 `write_back.py` 只报「索引已更新」但未落盘。改用专用检索工具复核，两行分别在 `_索引.md:165`、`_近期决策.md:51`，均为带转义竖线的中文表格行，实际已写入。

**正确做法**：① 判断「零结果/不存在」必须换第二种方法复核（对应零结果双证）；② 中文长表格行、含 `\|` 转义或全角符号的文件，一律以专用检索工具为准，不采信 bash grep 的空结果；③ 工具报「成功」也要回读内容，但回读方法本身失效时先换工具，别急着改文件重跑（否则会产生重复条目）。

**教训**：本次既是 [38]「bash 中文 grep 静默失效」的又一次实证，也暴露「静默成功」的反向变体——**校验器自身假阴性**会伪装成写入事故；误判后若直接重写索引，反而会制造重复登记。
