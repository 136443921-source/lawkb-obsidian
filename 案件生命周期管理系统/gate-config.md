# 门禁配置说明书（gate-config）

> **一句话**：本文件是 CLM「门禁体系」的**静态说明书**——只存门禁的**定义、判定标准、强制步骤**；
> 门禁的**实时状态**（pass / active / warn / fail / todo / waived）不存本文件，一律现读各案 `case-state.json` 的 `gates` 字段（L0 唯一可信源）。
> 引用门禁状态必须现读 case-state.json，**不得凭记忆**。

---

## 一、门禁体系总览（十门禁 G0–G9）

| 门禁 | 名称 | 类型 | 挂靠阶段 |
|---|---|---|---|
| G0 | 收案门禁 | 阶段流转 | ① 接案建档 |
| G1 | 检索门禁 | 阶段流转 | ② 检索研究 |
| G2 | 文书门禁 | 阶段流转 | ③ 文书起草 |
| G3 | 庭审门禁 | 阶段流转 | ④ 庭审查庭 |
| G4 | 客户门禁 | 阶段流转 | ⑤ 客户协作 |
| G5 | 程序门禁 | 阶段流转 | ⑥ 程序执行 |
| G6 | 风控门禁 | 阶段流转 | ⑦ 风控归档 |
| G7 | 结案回流 | 阶段流转（收尾） | 结案回流 |
| G8 | 非诉合规 | 触发式 | 非诉专项（不并入阶段流转） |
| G9 | 执行专项 | 触发式 | 执行程序（不并入阶段流转） |

> **G0–G7 为阶段流转门禁**；**G8 非诉合规**（v2 新增）与 **G9 执行专项**（v2.1 新增）均为**触发式、不并入阶段流转**，未触发的案件不影响任何阶段放行。

---

## 二、门禁状态取值（六态）

| 取值 | 含义 |
|---|---|
| `pass` | 已通过 |
| `active` | 进行中（当前阶段正在推进） |
| `warn` | 预警（有缺口 / 存疑，未阻断但须处置） |
| `fail` | 未通过（阻断） |
| `todo` | 待办（尚未开始） |
| `waived` | 豁免（未开庭等场景） |

---

## 三、十门禁定义与强制步骤（判定标准 · 缺一项即阻断）

| 门禁 | 名称 | 强制步骤（缺一项即阻断） |
|---|---|---|
| **G0** | 收案门禁 | 利益冲突审查通过 ＋ 收案审批表完成 ＋ 委托合同签署 ＋ 已建档 |
| **G1** | 检索门禁 | 法律检索报告已出（含相反观点＋本地口径＋风险）＋ 类案检索报告已出 ＋ 检索结论归档 → **接案三件套齐备** |
| **G2** | 文书门禁 | 文书经蓝队＋红队红蓝复核通过 ＋ 证据目录齐备 ＋ 质证齐备 |
| **G3** | 庭审门禁 | 庭前准备清单通过 ＋ 庭审记录已生成 ＋ 庭后复盘已写 |
| **G4** | 客户门禁 | 客户会议纪要已存 ＋ 材料清单已交付 ＋ 工作汇报已发（五段式） |
| **G5** | 程序门禁 | 立案 / 保全 / 送达签收（签收日＝期限起算）/ 期限无遗漏 四项全过 |
| **G6** | 风控门禁 | 所有对外文书过 LTI 防火墙（REJECT=0）＋ 文件校对 |
| **G7** | 结案回流 | 归档（经验卡）＋ 提炼（总结报告）＋ 模板优化 ＋ 检查点迭代 ＋ 回流登记 |
| **G8** | 非诉合规（触发式） | 非诉文书经红蓝复核 ＋ 合规专项体检 ＋ 过 LTI ＋ **调用留痕** ＋ **经验卡沉淀** |
| **G9** | 执行专项（触发式） | 见下方两段式 |

---

## 四、G9 执行专项（两段式 · v2.1 新增）

### G9-a 立案前六项（**任一项不过则不写申请书**）

1. 执行依据生效**实证**（禁「判决日＋上诉期」推算）
2. 申请执行人主体资格（民诉法第 247 条）
3. 给付内容可执行
4. 执行时效（民诉法第 250 条，二年）
5. 金额口径四子项（法释〔2014〕8 号）
6. 管辖（民诉法第 235 条）

### G9-b 产出后两项

7. 全套文书 LTI `REJECT=0`
8. 执行案 case-state 回写

> **未进入执行程序的案件无需检查，不影响 G5 放行。**

---

## 五、门禁状态读取规则（铁律）

1. 门禁**实时状态** ＝ 各案 `case-state.json` 的 `gates` 字段，**L0 唯一可信源**。
2. 引用必须带源标记：`（源：case-state.json#gates @YYYY-MM-DD）`。
3. 写不出字段名与 `updatedAt` ＝ 没读过原件 ＝ **不许写**。
4. 桌面案夹旧版 `case-state.json` 不得引用（见 case-warroom §8.2 双原件警告，旧版 MD5 `92ac6643…`，含「待生效」三字即读错）。

## 六、权威源与冲突仲裁

| 层级 | 文件 | 效力 |
|---|---|---|
| L0 状态源 | 各案 `case-state.json` 的 `gates` 字段 | 门禁**状态**唯一可信源 |
| 本文件 | `gate-config.md` | 门禁**定义 / 判定标准**（静态说明书，运维手册 §3.5 指向的权威源） |
| 运维手册 | `00-运维手册-案件生命周期管理系统.md` §3.3 / §3.5 | 与本文件同源（§3.5 为摘要，权威源指向本文件） |
| 作战室总纲 | `作战室/00_总纲/案件作战室总纲_6658_v2.0.md` §3.2 | 本案实例化放行条件 |

**冲突仲裁**：门禁**状态**以 `case-state.json` 为准；门禁**定义 / 判定标准**以本文件为准；两者冲突 → **当场报告老强，不得自行取舍**。
