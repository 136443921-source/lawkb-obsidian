# 运维手册 · 案件生命周期管理系统（CLM）v2.0.0

> **一句话定位**：小强律师数字分身系统的「案件全程驾驶舱」——把接案到结案的全周期状态，变成一份机器可读的事实源，向下游分出**内部全量大屏**（自己看）与**对外脱敏简报**（当事人看）两条独立管线；同时把「哪些智能体在哪一阶段干活、产出了什么文件」也固化进同一事实源（`meta.agents`）。
>
> **本手册回答四个问题**：系统由什么组成、智能体怎么路由、日常怎么操作、出故障怎么办。
> **本手册不回答**：案件怎么做、文书怎么写——那是 [[案件全生命周期·编排器]] 的职责；推演怎么打——那是 [[模拟法庭推演专家]] 的职责。

## 一、系统定位与四层架构

```
L1 数据层  ──  case-state.json（单一事实源 ★ 含 meta.agents 智能体路由）
                    ↓
L2 引擎层  ──  scan_cases.py（扫描 / 倒计时 / 分级 / 智能体面板渲染）
                    ↓
        ┌───────────┴───────────┐
L3 内部展示（全量）      L4 对外通道（脱敏）
   大屏 / 驾驶舱 / 智能体面板   简报 / 进度页 / 微信 / 邮件
```

**铁律：L3 与 L4 是两条独立管线，绝不共用渲染。** 内部能看到的所有东西（红蓝态势、法官预判、证据分级、底线金额、对方当事人信息、智能体挂载明细），对外一律不可见。

### 与既有资产的分工

| 组件 | 职责 | 位置 |
|---|---|---|
| `案件全生命周期·编排器` | **管流程**：七阶段 SOP、G0–G8 门禁、结案回流 | `~/.workbuddy/skills/案件全生命周期·编排器/` |
| `案件全生命周期·门禁体系` | **门禁定义单一可信源** G0–G8 | `~/.workbuddy/skills/案件全生命周期·门禁体系/references/gate-config.md` |
| **本系统（CLM）** | **管状态可视化、智能体路由挂载、对外沟通** | 本手册所描述的范围 |
| `案件生命周期大屏流水线` | 本系统的技能化封装（触发词：案件大屏 / 案件进度 / 刷新大屏） | `~/.workbuddy/skills/案件生命周期大屏流水线/SKILL.md` |

## 三、单一事实源：case-state.json

### 3.1 为什么必须是 JSON

案件笔记是**散文**，散文无法驱动大屏、推送与智能体路由。所以：

> **`case-state.json` 是唯一事实源。md 笔记由它派生展示，绝不可反向从散文解析状态。**

### 3.3 七阶段与八门禁（v2 增补 G8）

| 阶段 | 名称 | 出口门禁 |
|---|---|---|
| ① | 接案建档 | G0 收案 |
| ② | 检索研究 | G1 检索 |
| ③ | 文书起草 | G2 文书 |
| ④ | 庭审查庭 | G3 庭审 |
| ⑤ | 客户协作 | G4 客户 |
| ⑥ | 程序执行 | G5 程序 |
| ⑦ | 风控归档 | G6 风控 → G8 非诉合规 |
| — | 结案回流 | G7 结案回流 |

门禁状态取值：`pass` / `active` / `warn` / `fail` / `todo` / `waived`（未开庭等场景用 waived）。

> 门禁的**强制步骤清单**以 `案件全生命周期·门禁体系` 为准，本系统只读不改。v2 起门禁为 **G0–G8**（较 v1 的 G0–G7 新增 **G8 非诉合规门禁**，见 §3.5）。

### 3.4 `meta.agents` 字段（v2 新增 · 智能体路由落地）

`meta.agents` 是 v2 核心新增：把「哪一阶段由哪个真实智能体/连接器干活、产出了什么文件」固化进事实源，大屏据此渲染「智能体挂载」面板。

**字段说明**：
- `stage`：七阶段名（与 §3.3 对齐）
- `gate`：对应门禁（如 `G1` / `G6/G8`）
- `role`：职能（检索/文书/模拟法庭/推送…）
- `agent`：**真实承载**（解析后的连接器/技能，非逻辑名）
- `status`：已接入 / 已建 / 待配
- `artifacts`：该阶段实际产出物**真实路径**（可点击跳文件，见 §6.2）
- `note`：补充说明（如「二源互补」「邮件待配webhook」）

**当前两案均写入 11 条 `meta.agents` 记录**（含 接案三件套 / 庭审六件套 真实路径）。

### 3.5 门禁强制步骤速查（摘要，权威源见 gate-config.md）

| 门禁 | 强制步骤（缺一项即阻断） |
|---|---|
| **G0 收案** | 利益冲突审查通过 + 收案审批表完成 + 委托合同签署 + 已建档 |
| **G1 检索** | 法律检索报告已出（含相反观点+本地口径+风险）+ 类案检索报告已出 + 检索结论归档 → **接案三件套齐备** |
| **G2 文书** | 文书经蓝队+红队红蓝复核通过 + 证据目录齐备 + 质证齐备 |
| **G3 庭审** | 庭前准备清单通过 + 庭审记录已生成 + 庭后复盘已写 |
| **G4 客户** | 客户会议纪要已存 + 材料清单已交付 + 工作汇报已发（五段式） |
| **G5 程序** | 立案/保全/送达签收（签收日=期限起算）/期限无遗漏 四项全过 |
| **G6 风控** | 所有对外文书过 LTI 防火墙（REJECT=0）+ 文件校对 |
| **G7 结案回流** | 归档（经验卡）+ 提炼（总结报告）+ 模板优化 + 检查点迭代 + 回流登记 |
| **G8 非诉合规**（v2 新增） | 非诉文书经红蓝复核 + 合规专项体检 + 过 LTI + **调用留痕** + **经验卡沉淀** |

## 六、日常运维 SOP

### 6.1 刷新大屏（每日 / 案件有进展时）

### 6.2 智能体面板维护（v2 新增）

- **校验**：改完 `meta.agents` 先 `--dry-run` 确认 JSON 合法。

### 6.3 接入新案件（四步）

1. 在 LawKB 对应案件夹建 `case-state.json`，照 §3.2 填写（**含 `meta.agents` 11 条路由**）。
   **事实一律取自桌面真卷 + 案件笔记实地核实，不凭记忆。**
2. `--dry-run` 验证可解析、阶段与门禁填写完整。

## 九、故障排查手册（踩坑档案）

### 9.1 脱敏版把案号改成「民初CASE-01号」
**原因**：`caseId` 替换规则抢在案号正则之前命中。**铁律**：`_redact_str` 中必须**先**跑 `(民初|民终|民再|刑初)\d+号 → \1****号`，**再**跑 caseId 替换。

### 9.2 脱敏版仍泄漏真实姓名与本地路径
**原因**：`_path` 与 `_folder` 未处理。**解法**：脱敏预处理中 `c.pop("_path")`、`c["_folder"] = f"案件{i}"`。

### 9.3 `wecom-cli --version` 版本解析失败
**解法**：正则 `re.search(r"(\d+)\.(\d+)\.(\d+)", raw)` 提取。

### 9.4 grep 多词扫描扫不出东西
**原因**：BSD grep 的 BRE **不支持 `\|` 交替**。**解法**：用 `grep -E "A|B|C"`，或逐词循环。

### 9.5 `timeout` 命令不存在
**原因**：macOS 无 GNU coreutils。**解法**：后台运行 + `sleep` + `pkill`。

### 9.6 探测 init 二维码不能转述
**正确做法**：用户本机实时跑 `setup_wecom.sh`；或由助手前台跑 `wecom-cli init --noninteractive` 使其**阻塞**（auto-background 保活），把**当次**二维码给用户扫。

### 9.7 非交互终端子进程跨轮不保活
**解法**：不要 `(cmd &)` 挂起；让命令自然阻塞触发 auto-background。

### 9.8 探测 init 是否有副作用
**判据**：`wecom-cli msg --help` 不再报"未找到 MCP 配置缓存" + `cache status` 非空 + `~` 下出现 wecom 配置目录。已验证掐断探测**无残留进程、缓存为空、授权未变**。

### 9.9 智能体面板不显示 artifacts 路径
**现象**：面板只渲 stage/gate/role/agent/status/note，未渲染 `artifacts`。
**状态**：已知待补（§十二 P2）。`artifacts` 已存于 state，渲染层加「点开跳文件」即可。

### 10.2 坎 3：消息权限被封
**2026-09-05 实测**：授权成功，但域可用性——文档 doc / 待办 todo ✅；消息 msg / 通讯录 / 日程 / 会议 ❌ 被封。

**待确认**：本企业成员数是否 ≤10 人。超过则走 10.4。

### 10.3 坎 4：会话范围限制
即使消息权限开通，也只能发给**授权人本人**或**机器人最近有消息往来的单聊/群聊**；**不能**按通讯录搜索发任意外部联系人。→ 当事人须先跟机器人说过话。

### 10.4 ✅ 绕过方案：群机器人 webhook（推荐）

返回 `"errcode":0` 即成功。内容**仍只取 publicView 白名单**。
