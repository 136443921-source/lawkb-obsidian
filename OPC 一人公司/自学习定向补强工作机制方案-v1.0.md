# 一人公司·内部智能体自学习定向补强工作机制方案（v1.0）

> 缘起：复盘「人伤裁判规则定向补强自动化 v1.3」(automation-178391965225，每周三 20:30) 的运行机制，将其可复用设计抽象为一人公司通用的「自学习定向补强」能力，嵌进既有 **资产运维官** 体系（数字资产登记册 SSOT + 监控矩阵 8 维 + 规则包封装），不另起炉灶。
> 维护者：小强｜委托人：老强｜2026-10-07

---

## 〇、目标

让一人公司的内部智能体（数字员工）具备**自我感知知识薄弱区 → 定向生成内容补强 → 安全写入 → 建链 → 回源 → 留痕 → 刷新监控**的闭环能力，使知识资产随业务实战**持续 thickening**，而非依赖人工一次性灌库。

---

## 一、机制复盘：人伤裁判规则定向补强做对了什么

### 1.1 闭环结构（6 环节）

```
缺口分析 → 定向生成(2-3子主题/5-10卡) → 跨格式去重护栏 → 安全写入(六-B)
   → 双向链接(笔记↔卡↔索引) → 进度追踪+memory.md 留痕 →（下周复跑，水位+）
```

### 1.2 七条可复用设计原则（提炼自 9-02 / 9-09 / 9-16 / 10-07 四轮实测）

| # | 原则 | 复盘结论（为什么有效） |
|---|------|----------------------|
| P1 | **缺口驱动，不盲目生成** | 每轮先扫「人伤法索引 MOC 第五节规则表」+ 主文件，找零覆盖子主题（如 1186/1209/1214/1215/1218/1224/1200），再生成。避免自嗨式堆量 |
| P2 | **跨格式去重护栏** | 写入前扫「主文件裁判规则库.md + 子目录卡 + 既有笔记」三重，命中则转引用链接不重复写。根除「重复写库」风险（三任务职责边界文档的核心痛点） |
| P3 | **职责边界硬约束** | 补强只写子目录 `人伤法/`，绝不碰主文件 `裁判规则库.md`（那是入库任务地盘）。多任务并行不撞车 |
| P4 | **本地源引证铁律** | 法条全部从本地《民法典（全文）》逐字回填（`statute_text_pending:false`），不凭记忆灌条文——法律幻觉第一道防线 |
| P5 | **降级范式不编造** | 元典余额 0 时，案号/案例锚定标 `yuandian_source_pending:true`，**不编造案号**，待领额度一键回源。诚实优于完整 |
| P6 | **六-B 安全前置** | 改索引 MOC 前必 `cp` 备份 + 验字节一致；本任务仅新增不覆盖单源，无备份改写动作 |
| P7 | **留痕 + 进度双写** | 每轮在 automation memory.md 记一行（状态/产出/异常），并刷新索引「进度追踪」当前值。无人值守也能审计 |

### 1.3 复盘硬结论

- 该机制本质是 **「感知缺口 → 定向生成 → 安全写入 → 建链 → 留痕 → 进度」** 的**自强化闭环**，且**域无关**——换成人伤之外的域（合同/公司/刑事…）同样适用，只需改"缺口扫描口径"和"域模板"。
- 现有四轮已验证：R-PI 水位 535、人伤笔记 221 篇、全库 R-PI 卡 100 条，零重复写库、零幻觉法条、零备份事故。
- 唯一待解风险：**降级范式下 pending 卡堆积**（人伤法规则包 v1.0 已 174 张「待核验源」偏高）→ 需设回源 SLA。

## 二、抽象：定向补强通用范式（TRP, Targeted Reinforcement Paradigm）

把"人伤专项"抽成"域无关"工作流，核心变量参数化：

| 参数 | 人伤现状 | 通用化 |
|------|----------|--------|
| 域（domain） | 人伤法 | 任意登记册已编目域（合同/公司/刑事/劳动…） |
| 频率 | 每周三 20:30 | 按域成熟度排期（周/双周/月） |
| 每轮配额 | 2-3 子主题 / 5-10 卡 | 可配置（默认 子主题≤3，卡 5-10） |
| 缺口源 | 人伤法索引 MOC | **资产运维官监控矩阵 D1（编目覆盖率）** + 各规则包 manifest 目标/实测 |
| 去重口径 | 主文件+子目录+笔记 | 通用（主文件+子目录+笔记三重） |
| 质检门禁 | LTI 五维 + 六-B + 编号门禁 | 通用 |

## 三、一人公司落地方案

### 3.1 体系定位（嵌资产运维官，不另起炉灶）

在 **资产运维官 skill** 现有四支柱（编目/监控/打包/商业化）之外，新增 **🟪 第五支柱：自学习补强（Self-Reinforcing）**，作为监控矩阵 D1 的"行动臂"——

> 监控矩阵 D1 发现「某域编目覆盖率 < 阈值」→ 自动排入补强队列 → 补强引擎生成内容 → 产物直接刷新登记册 + 进对应规则包。

复用现成底座：
- **缺口实测源** = `00-数字资产登记册/asset_registry.json`（D1 覆盖率）
- **补强产物容器** = `01-规则包/rule_package_<域>_v1.0/`（人伤法包已存在，直接扩）
- **慢盘防护** = 资产运维官 D7 教训（mtime 增量缓存，不 walk 整树）
- **质检** = LTI 文本监控器（五维 R/L/C/T/P）

### 3.2 六阶段引擎设计（TRE, Targeted Reinforcement Engine）

```
┌─────────────────────────────────────────────────────────────┐
│  G1 缺口感知  读登记册+包manifest，算 域缺口率=1-实测/目标   │
│       ↓ 缺口率>阈值(默认30%) 或 某子主题 0 卡 → 入队列       │
│  G2 选题排期  按缺口率排序取 Top-N（N=每轮配额）             │
│       ↓                                                      │
│  G3 定向生成  按域模板产出 笔记+规则卡，法条本地源逐字回填   │
│       ↓                                                      │
│  G4 去重护栏  跨格式三重扫描(主文件+子目录+笔记)             │
│       │   命中 → 转 [[引用链接]] 不重复写                     │
│       ↓ 未命中                                               │
│  G5 质检门禁  六-B 备份 → LTI 五维 → 编号门禁(取号双维度)   │
│       ↓ 全 PASS                                              │
│  G6 回源+留痕 案号标 pending(元典有额度回源) / memory.md一行  │
│       ↓ 登记册刷新 + 包manifest刷新 + 进度指标更新           │
│  └─────────────── 回 G1（下一轮复跑，水位持续+）────────────┘│
└─────────────────────────────────────────────────────────────┘
```

### 3.3 缺口感知如何复用监控矩阵 D1

- 资产运维官 `asset_monitor.py` 已能算「9 类资产登记率、编目完整性」。
- 每个规则包 `manifest.json` 自带 `目标条数 / 实测条数`。补强引擎读这两个源即可得**域级缺口率**与**子主题级 0 卡清单**，无需重新发明扫描器。
- 与人伤现状对齐：人伤法包 v1.0 实测 174 张新增偏高（待核验源 24.3%），正说明补强在持续喂但**回源 SLA 没跟上** → G6 须补回源节奏治理。

### 3.4 配置与节奏（参数化 + 阈值触发）

| 域 | 频率 | 每轮配额 | 触发方式 |
|----|------|----------|----------|
| 人伤法 | 每周三 20:30 | 2-3 子主题 / 5-10 卡 | 专用自动化（保留现状 automation-178391965225） |
| 合同/公司/刑事… | 双周 / 月 | 1-2 子主题 / 3-5 卡 | **通用补强调度器**（新）按 D1 阈值自动排期 |
| 全局 | — | — | 监控矩阵 D1 覆盖率 < 70% → 强制入队 |

> 专用自动化（人伤）与通用调度器（多域）**并存不冲突**：人伤保留高频专用通道，通用调度器兜底其余域，统一走 G1-G6 引擎。

### 3.5 与规则包 / 登记册的衔接（补强即刷新）

- 补强产出的新卡/笔记，**当轮写回**对应 `rule_package_<域>_v1.0/assets/`（复用 `gen_rule_package.py` 的 manifest 刷新逻辑，`--dry` 幂等）。
- 登记册 `asset_registry.json` 同步刷新该域「实测条数 / 更新日期」，消除 D1 文档漂移（资产运维官铁律 3：记载须=实测）。
- 进度指标（薄弱区当前值）随登记册刷新，无需在索引 MOC 重复维护。

## 四、治理铁律（沿用既有，最高等级强制）

1. **六-B**：改单源文件前 `cp` 备份 → dry-run → 改 → 复测 → 验幂等；禁止整文件重建主文件。
2. **不编造案号**：元典余额 0 时标 `yuandian_source_pending:true` 降级，绝不伪造案例。
3. **本地源引证**：法条一律本地法律法规库逐字回填，外部源仅作线索。
4. **个案卷宗/当事人隐私绝不入册、绝不入包**（资产运维官红线 2）。
5. **跨格式去重 + 三任务职责边界**：多任务并行防重复写库；补强只写子目录。
6. **编号门禁**：取号双维度（文件名 + frontmatter rule_id 扫描取较大者+1），撞号即停。
7. **慢盘防护**：缺口扫描走 mtime 增量缓存，不 walk 整棵知识飞轮系统（D7 血泪：42.77s→0.31s）。
