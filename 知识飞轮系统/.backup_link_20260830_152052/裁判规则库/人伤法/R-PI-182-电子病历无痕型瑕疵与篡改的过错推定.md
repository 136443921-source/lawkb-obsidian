# R-PI-182｜电子病历"无痕型瑕疵"与篡改的过错推定——以真实性鉴定前置为突破口

## 裁判规则

电子病历系统**缺失操作痕迹记录功能**（无日志、无质控留痕、无法还原修改前内容），或病历存在**事后修改、增删、补录**且无合规审批记录与合理诊疗解释的，均属《民法典》第1222条所称"伪造、篡改"病历资料情形，**直接推定医疗机构有过错**；因病历失真致医疗过错鉴定不能（鉴定机构退鉴）的，**不利后果由病历制作、保管方即医疗机构承担**，法院可径行依据病历违法事实定责，**无须以医疗过错鉴定为定责前提**。

责任比例并非推定全责：仍应综合患者自身疾病基础、诊疗过错程度与原因力大小酌定（实证：三甲医院 PCI 术后死亡案 50% 责任、赔偿 463,451.36 元；另案篡改核心病历 80 次案 50% 责任、赔偿 45.8 万元）。

> **⚠ LTI 旧法纠偏**：网络流传的"《侵权责任法》第58条（2026）"系**已废止法条**。《侵权责任法》已随《民法典》于 2021-01-01 施行同时废止，其第58条由《民法典》第1222条承继。凡见该引用，一律改引《民法典》第1222条。

> **🔗 必读配套（2026-08-30 增补）**：本卡解决「病历瑕疵**如何证明**」（技术路径与动作顺序），但**未区分瑕疵强度**。**并非所有病历瑕疵都触发推定过错**——实证存在从「推定全责」到「仅作酌定因素」的**五档裁判梯度**，见 [[R-PI-184-病历瑕疵五档裁判梯度从推定全责到酌定因素]]。两卡须**合并使用**：先用本卡证明瑕疵，再用 R-PI-184 定位档位与预期责任区间。

## 实务要点

### 一、瑕疵两分法（决定攻击路径）
| 类型 | 表现 | 认定路径 |
|---|---|---|
| **积极篡改型** | 病程记录创建时间晚于记录时间（实证8条，其中7条出院后新增）、出院后修改手术记录/病例讨论、电子与纸质手术记录不一致、护理记录出院13天后仍被修改、医嘱收费记录时序混乱突变 | 电子数据司法鉴定还原修改时间/操作人/内容 → 认定篡改 |
| **消极无痕型** | 系统无质控留痕功能、后台日志被清除、无法还原修改前内容 | 依《电子病历应用管理规范（试行）》第6条认定违反刚性留痕义务 → 病历真实性存疑 → 不能客观反映诊疗过程 |

**要点**：无痕型不等于"没有改"，而是"医院自己消灭了证明自己没改的能力"，同样触发不利后果归属。

### 二、患方五步动作（顺序不可颠倒）
1. **封存优先**：第一时间书面申请封存全套病历（纸质 + 电子），要求加盖公章，双方在场签字确认，全程录音录像；
2. **鉴定顺序倒置**：**暂不申请医疗过错鉴定**，先行申请**电子病历真实性专项鉴定**（须选具有电子数据司法鉴定资质的机构），先解决"病历能否作为鉴定依据"的前提问题；
3. **证据保全**：同步向法院申请证据保全，调取电子病历后台原始数据（含数据库镜像），防继续删改；
4. **行政线并行**：向卫健委书面投诉，官方调查结论可作司法关键证据；
5. **定责主张**：鉴定确认伪造/篡改后，径依《民法典》第1222条主张过错推定，绕开"必须鉴定才能定责"的举证壁垒。

### 三、医方（被告）抗辩三支点
1. **留痕系统合规自证**：提交完整操作日志、修改审批流程、修改事由与诊疗依据；无留痕、无审批、无依据的修改方视为违法篡改；
2. **关键/非关键区分**：篡改关键诊疗信息大概率担责（甚至全责）；**非关键信息**的违规修改，应抗辩仅承担相应不利后果而非全案推定；
3. **责任比例抗辩**：即便推定过错成立，仍以患者自身疾病基础、原因力大小、多因一果为据压缩赔偿比例（实证区间 50%）。

### 四、证据技术锚点（庭审可检验清单）
- 电子病程记录**创建时间 vs 记录时间**是否倒挂
- 修改行为是否集中于**患者死亡/纠纷发生之后**
- 电子记录与纸质存档**内容差异**
- 护理记录、医嘱、收费记录**时序突变**
- 系统是否具备**质控留痕功能**、能否还原修改前内容
- 经合规第三方区块链存证的电子数据，法院推定未被篡改（最高法区块链司法应用规定）
