## 二、🔴 关键洞察：入链结构决定"改不改文件名"

实测各待定号卡的入链分布（链接数 = vault 内 `[[目标]]` 出现次数）：

| 组         | 裸号链接       | 全名链接           | 结论         |
| --------- | ---------- | -------------- | ---------- |
| R-CF-052  | 38         | **191**（税前扣除卡） | 全名链接占绝对多数  |
| R-CF-053  | 28         | 58（基金会互捐卡）     | 同上         |
| R-CF-076  | 20（**断链**） | 14 / 21        | 无裸号文件，裸号全断 |
| R-HT-101  | 37（**断链**） | 21 / 30        | 同上         |
| R-LN-024  | 49（**断链**） | 26 / 14        | 同上         |
| R-LN-025  | 42（**断链**） | 24 / 18        | 同上         |
| R-CASE ×3 | 0          | 0              | 孤立卡，无历史包袱  |

**两条硬结论**：

1. **绝大多数链接用完整文件名建立**（191 vs 38）。若重编号时改文件名，`R-CF-052` 一组就会炸掉 **191 条链接**，代价不可接受。
2. 4 组无裸号文件的卡，其裸号链接（20+37+49+42 = **148 条**）目前**全部是断链**——补 alias 即可一次性修复。

### ✅ 推荐策略（零断链）

> **只改 frontmatter 的 `rule_id` 与 title 内编号，文件名一律不动；同时为新 rule_id 补 `aliases`。**

- 依据：规范 v1.0.0 第 36 行——**「唯一标识以 frontmatter `rule_id` 为准，文件名仅为可读别名」**。
- 收益：① 编号冲突消除；② 现有 300+ 条全名链接零影响；③ 顺带修复 148 条裸号断链。
- 代价：部分文件「文件名内编号」与「rule_id」不一致（属规范允许，且可由 alias 双向解析）。
