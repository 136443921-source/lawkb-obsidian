# 小强律师数字分身系统 · 能力评估报告

> **一句话结论**：分身系统已从"概念架构"走到"可用闭环"——防幻觉门禁（LTI 五维 + lti_verify）实战拦下过 C4 论证跳跃、经验双通道回流已固化、模拟法庭推演组双案落地；但**它仍是"规则校验器 + 流程引擎"，不是"法律判断主体"**，价值判断与拍板权必须留人。当前成熟度：**主干能力 7/9 已达 A 级（成型可用），知识飞轮与跨案识别为 B 级（迭代中），语义理解层为 C 级（规划）**。

---

## 一、系统定位与四子架构

分身系统 = 法律问题处理的**代理人设**，下挂四子架构，形成"起草 → LTI 五模块 → G4/G5 门禁 → 交付 → HIR 事故登记 → 规则回流"的防幻觉闭环：

| 子架构 | 职责 | 当前状态 |
|--------|------|---------|
| ① 知识飞轮六层 | 采集→提炼→连接→LOG→调用→沉淀 + SR 算法 | B（规则卡 5 库 R-HT/R-LN/R-PI/R-HG/R-CF，13 枢纽；覆盖 191 / 已摄入 156；**300+ 卡存在 6 组同号冲突待重排**） |
| ② LTI v4.8.1 文本监控器 | R 法条真实 / L 逻辑 / C 一致性 / T 溯源 / P 当事人信息 五维校验 | A（规则卡 R001–R020 / R101 / R103 / R111；一致性 C301 金额 / C302 名称 / C304 案号） |
| ③ HIR 经验沉淀智能体 | 事故登记 + 经验复利 | A（v1.0.2，已落双通道回流 ima 库 + obsidian-lawkb） |
| ④ 跨案模式识别 | 同主体 / 同事实线索关联 | B（6658 与 6660 黄茂姣实际买受人线索已显，系统化待做） |

> 模拟法庭庭审系统作子系统挂载（红蓝对抗推演可视化 🔵🔴⚔️）。

## 三、本会话实证（硬证据，非自述）

1. **民诉法权威源从 121 → 306 条**，并全副本收口（6 个用户 LawKB 副本全干净 OK）—— 门禁不再因"权威源没收全"误拦合法引用。
2. **C4 门禁拦截实证**：民法典第 774 条条号命中但原文不含"定作人无责" → 机器 🟡 标记，人工原标 ✅ 被纠 → 证明门禁是真闸，不是摆设。
3. **赋能清单 SOP 七维落地**，④ 双通道回流写入架构表 / 机制行 / 操作动作 / 产出物。
4. **模拟法庭推演组双案落地**：6658（冒名诉讼程序战）+ 6660（雅菲窗帘合同相对性），各含静态成品 + JSON 模板，脚手架一键加载。

## 四、能力边界与风险（诚实评估）

- **LTI 是规则校验器，不是判断主体**：只报"原文无此四字"，不答"能否从条文推出"——价值判断必须人拍板（C4 案例已证）。
- **权威源仍有缺口风险**：民诉法已补，但其他法域 / 司法解释若未同步，门禁可能误 UNVERIFIED；需 periodic 健康度巡检。
- **规则卡编号冲突**：300+ 卡 6 组同号冲突，影响精准检索与回流命中，待重排（参考 `_编号治理-待定号方案表.md`）。
- **ima-mcp 连通性反转**：本会话早段记录"未连通"，而当前环境显示 **ima-mcp 已 connected**——意味着检索回填通道现已打通，但本会话实证主要基于本地 LawKB，**需补一次"连通后端到端回归"** 验证 ima 5 库直连回填。
- **红队技能库 2 份旧副本未动**（怕动坏技能本体），一致性待你定夺。
- **连接器按调用计费**：yuandian-mcp（华宇元典）按调用计费，需设用量护栏。
- **刑事定性依赖人工兜底**：涉"虚假诉讼"等宁以"存疑"表述，系统不自动下刑事结论。

> **金句**：AI 不替你思考，它替你跑腿；分身不替你担责，它替你把门。**把资深律师的复核习惯固化成可复用系统，是一个人用一份带宽撑住一个诉讼团队案量的本质。**
>
> **评估者判语**：分身系统当前最大的杠杆不在"更聪明"，而在"更稳的门禁 + 更顺的回流"——它把你会犯的错挡在交付前，把你会忘的经验存进飞轮。剩下的，是人和机器各守其界。
