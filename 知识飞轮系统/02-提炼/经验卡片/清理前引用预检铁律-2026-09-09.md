# 经验卡片 · 清理前引用预检铁律（CJK 路径 + zsh glob 陷阱）

> **类别**：correction / best_practice（AI 工作流安全）
> **触发场景**：对 `Documents/LawKB` / 桌面 / Documents 下任何文件做**删除、移动、重命名**类操作前
> **一句话**：破坏性操作前的「引用预检」必须用 Grep 工具（或正确转义的通配符），**绝不能用会静默失败的错误命令冒充「无引用」**。
> **关联铁律**：六-B 安全铁律（先排查/确认非误报/再批量修改/含安全扫描+dry-run）、cp 备份铁律（单源重建先备份到 /tmp 时间戳目录）

---

## 一、事故回放（2026-09-09 · DTC-CASE-001 清理）

- **意图**：清理 `LawKB/案件管理/` 下 3 个已并入新真卷的旧案卷（众志救援 / 刘九零装修装饰 / 月亮湖养殖）
- **预检命令（错的）**：`grep -rl "..." "$VAULT" --include=*.md`
  - 在 zsh 中 `--include=*.md` 的 `*` 未被引号包裹 → 被 shell glob 展开成当前目录文件列表 → grep 收到的 include 实参错乱 → 命令报错但**返回空**
  - 我误把「返回空」当成「无引用」，下结论「可安全清理」
- **动作**：先 `cp` 备份到 `/tmp` → `mv` 进 `~/.Trash` 回收站（**非 rm，可恢复**）
- **真相（精确核查后）**：15+ 处 wikilink 跨库引用这 3 个旧文件夹，直接删会断链
- **补救**：立刻从回收站 `mv` 回原位 → 零丢失

---

## 二、根因

1. **zsh glob 陷阱**：`--include=*.md` 的 `*` 未用单引号包裹，被 shell 展开，导致预检命令本身失败而非「无匹配」
2. **逻辑错误**：把「命令报错 / 返回空」当成「无引用」——**静默失败 ≠ 安全**
3. **唯一救场的是备份铁律**：`mv 到回收站而非 rm` 让误操作可 100% 恢复

---

## 三、固化铁律（每次破坏性操作前必念）

| # | 铁律 | 说明 |
|---|---|---|
| 🔴 1 | **预检用 Grep 工具** | 直接调 Grep 工具（ripgrep），不用 bash grep；若必须用 bash，通配符必须引号包裹 `'--include=*.md'`，或用 `find -name '*.md'` |
| 🔴 2 | **静默失败 ≠ 无引用** | 命令返回空 / 报错时，**先怀疑命令本身**，换一种方式（Grep 工具 + 精确前缀匹配）各跑一遍交叉验证 |
| 🔴 3 | **先列清单再动** | 删除前把命中的 `file:line` 清单打印出来，确认每一项都有重定向目标，绝不「清单空 = 安全」 |
| 🟢 4 | **永远走回收站** | `mv` 到 `~/.Trash`（macOS）而非 `rm`；3 个以下小批量逐批；删前 `/tmp` 全量备份 |
| 🟢 5 | **删后反向复查** | 动完再用 Grep 反向核查一次，确认旧路径残留 = 0 才闭环 |

---

## 四、本次修复后的正确执行流（方案 A 范本）

1. Grep 工具精确抓取 `案件管理/众志救援…|案件管理/刘九零…|案件管理/月亮湖…` → 得到 15 处 `file:line`
2. 逐项建「旧路径 → 新真卷路径」映射表（众志救援 1:1；刘九零/月亮湖映射到新真卷对应案件笔记）
3. 逐文件 Edit 改链接（小批量，每批 ≤3 文件）
4. Grep 反向复查 → 旧路径残留 = 0
5. `cp -r` 全量备份到 `/tmp` → `mv` 进 `~/.Trash`
6. 最后再 Grep 一次确认回收站外已无引用 → 闭环

---

## 五、复盘金句

> **「命令没报错 ≠ 没东西依赖它；引用预检跑空，先怪命令，再怪自己。」**
> 破坏性操作的安全感只能来自**可恢复的备份**与**可验证的零残留**，不能来自一条可能静默失败的预检命令。
