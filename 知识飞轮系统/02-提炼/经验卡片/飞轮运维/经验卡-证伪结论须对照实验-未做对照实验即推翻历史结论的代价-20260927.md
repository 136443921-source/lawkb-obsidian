# 经验卡片 · 证伪结论须对照实验——未做对照实验即推翻历史结论，把对的判成错的

> **类别**：correction / best_practice（AI 工作流安全 · 归因纪律）
> **触发场景**：打算**推翻一条既有结论**（尤指自己或前轮得出的「被拒 / 失败 / 不可能 / 系统限制」类结论）时
> **一句话**：**「推翻别人的结论」是最强的断言之一——它需要对照实验，不需要推理。你没做对照实验就宣布历史结论错了，那不是纠错，是制造新错误。」**
> **关联铁律**：六-B 安全铁律、R-LN-114 拒绝假自洽、存在性断言须实证（同族）

### 我当时的"证据"是什么

只有三样：
1. 两份 plist 的 `plutil -lint` 通过、路径已改对；
2. `launchctl list` 里 grep 不到 cockpit9655；
3. **一个推理**——「既然 plist 改对了、语法没问题，那失败就不是配置问题，是没人执行」。

**这三样里没有一样能证伪「被系统拒」。** 第 3 条是推理不是证据，而且**方向恰好是反的**：它把「没做」当成了「做不到」的替代解释，却跳过了唯一能分清这两者的实验。

### 代价

- v1.6 已**交付给老强**并口头汇报过，含一句「不是系统不让，是没人执行，一条命令就能修」；
- v1.6 已**回写进治理文档**（§四 门槛表＋变更记录），白纸黑字；
- 差点让老强**按错误处方去等一条注定失败的 `launchctl load`**，真正的解法（注销/重启）反而被我标注为"可选"。

## 二、根因

1. **把「自洽的推理」当成了「实验的证据」**：我有一条能自圆其说的解释，就宣布旧结论不成立。**推理只能提出假设，只有实验能推翻结论。**
2. **缺最小对照（missing control）**：判定「是配置问题还是通道问题」，只需要**一个已知能成功的最小样本**——当时没做，也没意识到必须做。
3. **对「失败」的归因有天然偏好**：失败容易被解释成"系统限制"（不必改自己）；成功则必须解释机制。**这个偏好让「被系统拒」这种省事的解释长期不被复查**，而我这次本该反过来查它。
4. **证伪口气太廉价**：我在没有对照的情况下用了"历史讹误订正""归因证伪"这类强判定词。**强判定词是承诺，不是修辞。**

## 三、固化铁律（下次想说"这是被系统拒 / 做不到 / 旧的判断错了"之前，必念）

| # | 铁律 | 说明 |
|---|---|---|
| 🔴 1 | **证伪须有对照实验，推理不作数** | 凡宣布「某结论错误 / 某事不可能 / 系统限制」，必须附**可复跑的实验证据**；"我想通了"不构成证据 |
| 🔴 2 | **"失败"判定必须先做最小对照** | 见下「最小对照三选一」——**没有对照就没有失败归因** |
| 🔴 3 | **不许单方推翻历史结论** | 推翻前须找到**反证**；找不到就维持原结论并标注「待验」，不改写、不静默替换 |
| 🟢 4 | **强判定词须配证据块** | 「证伪 / 订正 / 讹误 / 不可能 / 一律」这类词，落笔时必须同段附上实验命令与原始输出 |
| 🟢 5 | **撤销自己的结论，须明文标注「本条系错误判断、已撤回」** | 可以改写，但**不许静默抹去**——留痕才能让后来者看懂为什么这里有过一轮反复 |
| 🟢 6 | **交付前的「反转」自查** | 凡本轮结论与历史结论相反，交付前须自问：「我做过对照实验吗？证据在哪？」——答不出就先别发出去 |

### 最小对照三选一（判定"是配置问题还是通道问题"时）

| 对照物 | 用途 |
|---|---|
| **极简 plist**（`/bin/echo` + Label + RunAtLoad） | 判定 launchd 通道本身能否装载——**本次就靠这一条定案** |
| 已知**可复用**的同类型对象（另一份能跑的 plist / 另一个已 load 的服务） | 判定配置是否自身有问题 |
| 同一命令对**已知可用**目标复跑 | 判定命令与权限是否可用 |

## 五、复盘金句

> **「你没做对照实验，却宣布别人的结论是错的——这比不做实验更危险。」**
>
> 不实验就说"这样做不行"，只是没验证；**不实验就说"旧的判断错了"，是凭空制造了一个新错误，还要别人为此付出信任成本。**
>
> 记住这次的形状：**失败永远有两种解释——「没做」和「做不到」。分清楚它们只需要一个对照样本，而那个样本，我本来随手就能做。**
