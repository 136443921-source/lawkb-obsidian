# 经验卡片 · 外部文档标记不等于死快照，先搜本地生成链

## 一句话经验

> 文件带 `data-page-node-id`（语雀/飞书导出标记）≠ 本地无生成器、无法刷新。先全盘搜本地真源与生成脚本，跑通能重生的才算"死快照"。

## 触发场景

- 刷新/更新一个静态站点子页（开发者平台、cockpit-portal 等），页面带语雀/飞书导出残留标记；
- 被要求"从源文档重导出覆盖后重部署"，但本环境无对应连接器（无语雀/飞书 MCP）；
- 准备下"须用户提供源文档/无法自动刷新"的结论前。

## 错误做法（反例 · 2026-09-10 踩的坑）

1. 看到 `cheji/index.html`、`portal/index.html` 带 `data-page-node-id`，直接判定"语雀/飞书静态快照，本地无生成器，须用户重导出"；
2. **只搜了同名 html、没搜本地生成器脚本**，也没看文件是否自包含，就向用户下"卡在源访问、我无法完成"的结论；
3. 把 portal 的"语雀壳"和 cheji 的"语雀导出残留"混为一谈，整体报"cheji/portal 须语雀重导出"，导致 cheji 明明有本地活源却空等语雀多轮。

## 正确做法（正例 · 本次纠错后固化）

**鉴别四步法（下"依赖源重导出"结论前必走）：**

1. **全盘搜本地真源**：以页名/子系统名为关键词搜全库 `*.html`/`*.md`，如 `分身系统驾驶舱.html`、`驾驶舱_模板.html`；
2. **查有无生成器脚本**：搜 `*.py`/`*.js`/`*.sh` 内含该页名，如 `刷新驾驶舱.js`、`飞轮中台刷新.py`、`积分监测器.py`、`刷新决策树.js`；
3. **自包含校验**：`grep -oE '(src|href)="(https?:)?//[^"]*"' file.html` 外链数 = 0 → 文件复制即用，本地可重生；
4. **标题 + 跑通核对**：文件名标题与线上一致 + 实际跑通生成器产出新件 → 确属本地活产物。

**本次实测：** `Documents/LawKB/知识飞轮系统/分身系统驾驶舱.html`（397KB、0 语雀标记、0 外链）+ `刷新驾驶舱.js` v2.0.0（扫五大支柱指标 + 解析「数字分身系统运维手册-EV版」md）。重跑 → 覆盖 `cockpit-portal/cheji/index.html`（先 `cp -n` 备份旧快照到 /tmp）→ 整目录重部署，cheji 焕新。**推翻此前"cheji 须语雀重导出"误判。**

## 适用边界

- 适用于一切"外部文档标记 + 疑似需重导出"的静态页刷新场景；
- **仅当四步法全盘搜确无本地源 + 无生成器 + 非自包含时**，才下"依赖源文档重导出"结论；否则先跑脚本；
- 本环境无语雀/飞书连接器时，更应先穷尽本地生成链，避免把"活产物"误当"死快照"空等。
