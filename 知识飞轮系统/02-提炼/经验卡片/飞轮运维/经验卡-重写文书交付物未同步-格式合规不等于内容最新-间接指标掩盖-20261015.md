# 经验卡片 · 重写文书后交付物未同步——「格式合规 ≠ 内容最新」间接指标掩盖事故

> **类别**：best_practice（AI 工作流安全 · 交付验证纪律）
> **触发场景**：**重写／大修任何交付物**（文书、报告、代码、数据）之后，验证"是否已更新成功"时
> **一句话**：**验证"文件已更新"必须用内容指纹（源文件独有特征词双向比对），绝不能用段落数／格式合规／残留标记等间接指标——间接指标可能恰好与旧文件相同，从而完美掩盖"我读的根本不是这个文件"。**
> **关联铁律**：否定型结论铁律、单点证据结论须实证铁律、裁决项二次核验铁律（**全部同源：结论须实证，且实证手段本身须能证伪目标命题**）

## 一、事故回放（2026-10-14 深夜 · 6660 案 22A 刑事报案书）

### 时间线

| 时刻 | 事件 |
|---|---|
| 23:18 | 老强拍板三项修订（改名报案书／证据定性修正／加非诬告自证段），生成 docx（**旧稿A**，102 段） |
| 23:46 | **老强严厉批评**架构不堪，我按 6658 标杆全面重写 md（**新稿B**，80 段，删整段教义学） |
| 23:55 | 跑 md2docx，脚本打印"✅ docx 已生成"——**但生成实际未生效，磁盘上仍是 23:18 的旧稿A** |
| 23:55 | **我的验证**：段落数 80 ✅／残留标记零 ✅／格式铁律全绿 ✅ → 判定"已完成重写" ❌ |
| 23:59 | **老强二次批评**："说理部分还是混乱的，控告书不是代理词，请重新审查" |

### 老强看到的是什么

老强打开 docx，逐句读到的仍是**旧稿A**：

- "**控告人**刘九零、刘维系……"（新稿B为"报案人"）
- "**四、法律适用：符合《刑法》第三百零七条之一第一款之构成要件，且应适用第三款择重从重之规定**"——**整段教义学论述赫然在列**
- 段落数 **102**（新稿B 为 80）

**故老强二次批评完全正确**：他读到的确实是一份说理混乱的旧稿。

### 真相（实测比对）

```
md 源文件（23:46）：含"本案涉嫌滥用诉权" ✅ ／ 无"四、法律适用" ✅  → 确为新稿B
docx（时间戳 23:55）：含"四、法律适用" ❌ ／ 无"本案涉嫌滥用诉权" ❌  → 实为旧稿A
```

**md2docx 脚本对同一 md 复跑则输出正确（80 段）**——说明脚本本身无 bug，是**23:55 那次调用未真正落盘**（旧文件静默留存），而我当时未做任何内容比对。

## 二、根因（核心：验证指标与验证目标不匹配）

### 🔴 根因一：验证指标全是**间接指标**，且恰好与旧文件相同

我当时验了三样：

| 我验的 | 指标性质 | **为什么无效** |
|---|---|---|
| 段落数 = 80 | 间接（形状） | **旧稿A是 102 段，但中间某次生成曾产出过 80 段的中间态**；更关键：段落数是**数量**，不是**内容**，任何排版调整都会变，但**内容未变时它照样"看起来对"** |
| 残留标记零（无 `>` / `**`） | 间接（清洁度） | 新旧稿都干净，**该指标对"是否最新版"零区分度** |
| 格式铁律全绿（A4／宋体22／仿宋16／行距28／页边距） | 间接（合规性） | 新旧稿格式完全一致，**同样零区分度** |

**三项指标全部只验证"这份文件像一份合规的文书"，没有任何一项验证"这份文件是我刚写的那一版"。**

**最凶险之处**：段落数是三者中看起来最"硬"的量化指标，最容易给人虚假安心。而它恰好无法区分版本。

### 🔴 根因二：把「生成命令成功」等同于「内容已更新」

md2docx 打印了 `✅ docx 已生成`。我据此认为生成成功，**但没有独立复核文件内容**。

> **一般规律**：写操作型脚本的"成功"只保证**调用完成**，不保证**结果正确**。旧文件存在时，失败会**静默保留旧内容**，不报错、不告警。

### 🟡 根因三：与既有经验卡同源，但机理不同

- 与「**LTI 九维被旧文档带偏**」同源：**都是"拿了旧物当真源"**。但那张是我**读**了旧文档当真相，这张是**交付出去的产物本身**就是旧的。
- 与「**C3 知识飞轮中台刷新事故·部分同步与双份漂移**」同构：**部分写入 / 未写入致两份产物漂移**。
- 与「**外部快照勿轻判死·先搜本地生成链**」同构：**改交付物前须知其生成链**（本案＝md→docx 脚本链）。

## 三、固化铁律（重写／大修任何交付物后必念）

| # | 铁律 | 说明 |
|---|---|---|
| 🔴 1 | **验证"已更新"必须用内容指纹，不得用间接指标** | 取**源文件独有特征词 ≥3 个** + **旧版独有特征词 ≥2 个**，**双向 grep 判别**：新词必须全命中、旧词必须全不命中，才算通过 |
| 🔴 2 | **格式合规 ≠ 内容是最新版** | 段落数／残留标记／字号行距页边距，只证明"像一份合规文书"，**不证明"是这一版"** |
| 🔴 3 | **先删旧、再生成、再验内容** | 生成前 `rm -f` 旧产物，杜绝"失败静默留旧文件"；生成后立刻验内容 |
| 🔴 4 | **脚本打印"成功"不作为交付依据** | 写操作型脚本的成功提示只证明调用完成，**须以独立内容复核为准** |
| 🔴 5 | **交付物与源文件须同源校验** | md→docx/pdf 等派生交付物，**必须从当前源文件生成**，并留生成命令与时间戳；禁止凭"上次生成过"推定本次仍有效 |
| 🟢 6 | **被质疑"内容有问题"时，先查交付链，再改文书** | 老强第二次提同类意见，即为**交付链可疑信号**，应先验文件版本，勿立刻再改内容（本案若先改内容，会在旧稿上白改一轮） |
| 🟢 7 | **量化指标须问"它能否证伪目标命题"** | 段落数不能证伪"是否最新版"，故对"是否最新版"这一问题**无效**；选指标前先自问这一句 |

## 四、正确的重写交付流（已闭环）

```
1. 备份旧交付物（/tmp 时间戳目录）
2. 重写源文件（md）
3. rm -f 旧交付物（docx）          ← 杜绝静默留旧
4. 从新源重新生成 docx
5. 内容指纹双向比对               ← 核心新增步骤
     · 新稿特征词 ≥3 → 必须全 True
     · 旧稿特征词 ≥2 → 必须全 False
     · 正文 / 批注区 分离定位（如禁用词须确认只在批注区）
6. 格式铁律复验（A4／字体／字号／行距／页边距／页脚页码／残留标记）
7. 重跑 LTI 九维 QC，确认 REJECT=0
8. present_files 交付 + 内存指纹已在文档内注明生成时间
```

## 五、附带沉淀：文书体裁纪律（本案副产物）

本次事故暴露出另一独立问题，与"未同步"同批解决，一并立卡：

| 文书体裁 | 应当写什么 | **不应写什么** |
|---|---|---|
| **刑事报案书** | 事实线索清单＋当事人原文引述＋证据出处定位；罪名点到为止 | **教义学系统阐释（选择性罪状/ 双罚构造 / 择重从重）、报案人自我辩解段** |
| 代理词 / 庭后意见 | 教义学论证、构成要件分析、反驳证伪 | — |

> **根一句话**：**报案书不是代理词。** 我曾把代理词的教义学论证习惯带入报案书，属**文书体裁错位**；且"自证未捏造事实"段在报案件中显属冗余辩解。6658 案《刑事报案书》为本体裁标杆（78 段、七成篇幅为事实与证据、教义仅在请求中点一句）。
