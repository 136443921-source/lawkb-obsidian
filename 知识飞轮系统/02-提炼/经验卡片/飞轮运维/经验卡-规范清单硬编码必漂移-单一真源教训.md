# 经验卡片 · 规范清单硬编码必漂移——编号守卫误报 103 条（单一真源教训）

> **类别**：correction / best_practice（AI 工作流安全 · 规范治理）
> **触发场景**：在代码/脚本里复述「规范文件中本来就有的枚举清单」（域码白名单、卡型清单、状态码…）
> **一句话**：凡是「规范里有、代码里也该有」的清单，**代码只负责解析，不负责复述**——硬编码必漂移，接到「纳入白名单」类指令先回源头读规范实际表格。
> **关联铁律**：六-B 安全铁律、cp 备份铁律、清理前引用预检铁律（同源·二级文本不能当真相）

---

## 一、事故回放（2026-09-11 · AY-WHITELIST-INCIDENT）

- **意图**：用户令「把 AY 纳入规范白名单、清掉那 103 张的 WARN 告警」
- **我当时的误判**：照着**摄入自动化 prompt 里写的旧版本「14 域白名单」**，在 `rule_id_guard.py` 的 G3 里把白名单**硬编码成 14 个域**；取号器 `next_rule_id.py` 也沿用了已被规范 v1.2.0 修正的领域名互换错误（`CS=建设工程 / JG=鉴定`，物理事实是 `CS=案例 / JG=建工`）
- **真相（实地读规范后）**：规范《_规则卡编号体系规范.md》第二节「## 二、域代码白名单」**实际列了 21 个域**，且：
  - `AY` 早在 **2026-09-06（v1.8.0）就是第 15 域正式域码**，带约束「只有 `card_type: 案由路由卡` 才可用」
  - `CL / RA / RN / XR / YS / RY`（承揽 + 人格权子域）六个域**全在规范白名单里**
  - 标题「15 域」只是 v1.8.0 时代旧文字，后续加 6 域没改标题——但我**没读表格，只信了标题和 prompt**
- **后果**：编号守卫把 **103 张完全合规的卡**误报为「域码不在白名单」——`AY 案由路由 90 / RA 名誉权 6 / CL 承揽 3 / RN·XR·YS·RY 各 1`，整整 103 条 WARN 全是噪音，淹没真实信号（G2 30 + G6 21）

---

## 二、根因

1. **违反单一真源**：规范里已有一份权威白名单，我却在代码里「抄了一份」。规范改版（加域、改领域名）时，代码副本必然滞后——这是结构性必然，不是偶发。
2. **拿二级文本当真相**：接到「纳入白名单」指令，我直接采信了**上一轮扫描结论 / 摄入 prompt 的旧版本**，没回源头读规范**实际表格**。当日同类第二次栽坑（前一次是凭记忆以为「需新建 AY 域」）。
3. **标题误导 + 不读表**：规范标题写「15 域」、prompt 写「14 域」，两个二级信号互相印证，反而让我更确信「AY 不在白名单」——但**表格本身才是真相**，标题和 prompt 都是衍生物。

---

## 三、固化铁律（每次碰「规范枚举」前必念）

| # | 铁律 | 说明 |
|---|---|---|
| 🔴 1 | **清单只解析不复述** | 规范里有的枚举（域码/卡型/状态码），代码一律**实时解析规范文件**，绝不硬编码字面量 |
| 🔴 2 | **接「加域/纳入白名单」指令，先读规范表** | 先 `Grep` 规范实际表格确认现状，不拿上一轮结论 / prompt / 记忆摘要当事实 |
| 🔴 3 | **二级文本只能当线索，不能当真相** | prompt、记忆摘要、旧标题都是衍生物；权威源以**规范文件本身**为准 |
| 🟢 4 | **解析失败必须回退+告警** | 单一真源解析器在规范格式异常时回退内置兜底清单并 `stderr` 告警，**门禁绝不因规范改版而失效** |
| 🟢 5 | **新增域只改表、不改码** | 规范第二节加一行（首列恰好两字母），两个脚本下次运行自动生效，无需动任何代码 |

---

## 四、本次修复后的正确执行流（已落盘）

1. **建单一真源解析器** `03-连接/scripts/rule_id_spec.py`：定位规范「## 二、域代码白名单」章节，取表格首列两字母域码；解析失败回退内置 21 域兜底 + stderr 告警
2. **守卫 G3 改为动态白名单**：`rule_id_guard.py` 经 `load_spec()` 取域清单，不再硬编码；规范改版门禁自动跟随
3. **新增 G7 卡型专用域校验**：把「AY 仅 `card_type: 案由路由卡` 可用」固化为代码，非指定卡型占 AY 域即 WARN
4. **取号器同步去硬编码**：`next_rule_id.py` 领域名改由解析器提供，修正 `CS/JG` 互换错误
5. **规范升 v1.42.0 标注「机器可解析单一真源」**，并写入「改表铁律」三条（保持三列结构 / 首列两字母 / 非域码行不写成三列表格行）
6. **验证闭环**：`rule_id_guard.py` 全库扫描 1460 张 → **ERROR 0 ／ 同号冲突 0 组 ／ WARN 51**（仅 G2 30 + G6 21）／ **G3·G7 均 0**；另写单测证明 G7 对违规 AY 卡必拦、对合规 AY 卡零误报

---

## 五、复盘金句

> **「规范里有的清单，代码抄一遍就是埋一颗漂移的雷；接到『加白名单』先翻规范表格，别把你上一轮的扫描结论当圣旨。」**
> 安全感只能来自**单一真源 + 实时解析 + 失败回退告警**，不能来自一条硬编码的副本。
