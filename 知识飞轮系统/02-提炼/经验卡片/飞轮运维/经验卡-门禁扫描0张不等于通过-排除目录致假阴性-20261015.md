# 门禁「扫描 0 张 → ✅ 通过」是假阴性：一条目录排除语句让编号守卫失效 24 天

## 一、一句话结论

**守卫脚本输出「扫描 N 张」时，N=0 必须判为「未验证」而非「通过」**——
0 张意味着扫描范围为空（门禁根本没睁眼），不意味着没有问题。

---

## 二、事故经过（2026-10-15 实测）

| 环节 | 现象 |
|---|---|
| 触发 | 当日摄入 24 张规则卡后，按 v1.25 铁律跑 `rule_id_guard.py --since 60` |
| 输出 | `扫描 0 张规则卡 ｜ 🔴 ERROR 0 ｜ 🟠 WARN 0 ｜ ✅ 编号门禁通过` |
| 复核 | 换 `--since 1440`（24 小时）重跑，**仍为 0 张** → 判定非时间窗问题，是范围问题 |
| 根因 | `rule_id_guard.py` 第 87 行 `dn[:] = [d for d in dn if ... and d != "裁判规则库"]` |
| 后果 | `06-沉淀/裁判规则库/` 被**整体排除**，该目录 284 个 md / **68 张 R-XX-NNN 卡**（含当日新建 31 张）**从未进入门禁** |
| 修复后 | 移除该排除条件 → 全库扫描 **2480 张**，立即暴露 **🔴 ERROR 31 组同号冲突** |

> 同一条语句里排除的还有 `_备份`（合理）与隐藏目录（合理），
> 但 `裁判规则库` 恰恰是**新建规则卡的默认落点**，排除它等于把门禁对准了空气。

---

## 三、与既有铁律的呼应（同一失效模式的第三次出现）

| 既有铁律 | 本例对应 |
|---|---|
| 🔴 **否定型结论铁律**（假阴性防护） | 「扫描 0 张 / ERROR 0」正是否定型结论，未换口径复核前不得采信 |
| 🔴 **交付物版本验证铁律**（间接指标掩盖） | 「✅ 通过」是**间接指标**——它只证明脚本没报错，不证明门禁真的扫过卡 |
| 🔴 **单点证据结论须实证** | 一次 `--since 60` 的输出不足以定论，需换 `--since 1440` 二次复核 |

**三者的共同内核**：**先自问「这个指标能否证伪目标命题？」**——「ERROR 0」不能证伪「存在编号冲突」，
因为扫描数为 0 时它恒为 0。**不能证伪的指标 = 无效指标。**

## 五、可复用检查清单（下次跑任何门禁/校验脚本前）

1. **看扫描数，不看结论行**——`扫描 N 张` 中 N 是否与预期量级相符？N=0 或 N 远小于预期 → 立即判「未验证」。
2. **换口径复核**——时间窗（`-–since 60` → `1440`）、范围（增量 → 全库）至少各跑一遍。
3. **抽查命中物**——随机取 1 张已知卡，确认它是否真在扫描集合内（本次即由此定位）。
4. **看排除语句**——凡 `exclude` / `skip` / `!=` 目录名的清单，逐项问一句：**"被排除的目录里有没有我要检的东西？"**
5. **修完立刻对比**——修复前后扫描数与 ERROR 数必须有可解释的跳变（0 张 → 2480 张），否则修复未生效。

## 六、金句

> **门禁的绿灯有两种：一种是「检查过了，没问题」，一种是「压根没检查」。
> 后者比红灯更危险，因为它会让人连续 24 天安心。**

> **「扫描 0 张」不是结果，是警报。**
