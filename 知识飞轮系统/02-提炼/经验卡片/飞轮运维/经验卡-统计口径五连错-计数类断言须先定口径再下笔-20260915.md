# 统计口径五连错 · 计数类断言须先定口径再下笔

> **一句话**：**"有多少条"这个答案，取决于你数的是"什么单位"**——
> 未定义**计数单位**（顶层键 / 条目 / ID / 记录）就报数，等于用不同刻度的尺子量同一块布，
> 今天这块布被量出了 **11 / 147 / 132 / 2447 / 729** 五个答案，**全错或半错**。

## 一、事故回放（2026-09-15 · 同一天、同一批数据、5 个答案）

盘点 `蓝队律师合同审查` 规则库，我先后给出 5 个互相矛盾的数字：

| # | 我报的数 | 出处 | 实际口径 | 真值 | 错因 |
|---|---|---|---|---|---|
| 1 | **11 条** | 本轮开工前 | `len(risk_rules.json)` = 顶层键数 | **729** | 拿**字典顶层键数**当条数 |
| 2 | **147 条** | 中枢 PROJ-007 旧记载 | 早期版本快照 | 729 / 归库后 835 | 引用**未复测的历史快照** |
| 3 | **132 条** | 技能正文 | 早期版本快照 | 835 | 同上，文档未随代码更新 |
| 4 | **2447 条** | 上一轮汇报 | 递归累加**所有 list**，含 `keywords`/`sources` 子数组 | 主体 **835** | 把**子数组**当独立条目 |
| 5 | **729 条** | 归库时 | 含 `id`+`name` 的**规则条目** | ✅ 正确 | **口径终于定义对了** |

**连锁后果**：基于"11 条"我判定"**主库空壳、可加载率 0.4%**"——这是**重判断**，
差点据此推导出"规则库需重建"的错误路线（实际是"弹药极厚、只缺单一真源"）。

## 二、根因（三类，可自查）

| 类型 | 表现 | 高发场景 |
|---|---|---|
| **A. 单位未定义** | 键 / 条目 / ID / 记录 混用 | JSON 嵌套结构盘点 |
| **B. 层级未定** | 主体层 / 变体层 / 维度层 混计 | 多层数据（本次 835 + 730 + 71） |
| **C. 快照未复测** | 引用记忆或旧文档里的数字 | 写方案、写报告时的"我记得是 X" |

> ⚠️ 本次最隐蔽的是 **A**：`len(dict)` 与 `len(list)` 在 Python 里都合法、都返回数字、
> **都不报错**——所以错得毫无声音，直到交叉验证才暴露。

## 三、铁律：计数类断言「三查法」（报数前必过）

```
① 定单位：我数的是【顶层键 / 条目 / 唯一ID / (id×文件)记录】中的哪一个？
② 定层级：这个数属于【主体层 / 变体层 / 维度层】哪一层？要不要分层报？
③ 定来源：这个数是【本次实测】还是【历史快照/记忆】？未复测的一律标"待核"。
```

**补充四条硬约束**：

1. **报数必带口径** —— 写"835 条"不够，要写"**835 条（含 id+name 的规则条目·主体层·归库后实测）**"。
2. **等式自检** —— 报完数立刻找个能闭合的等式验一遍（见下节）。**对不上就是错了，别硬圆**。
3. **Bash `grep -c` 返回 0 必须换工具复跑** —— 与同族 A 型（存在性断言）同一条纪律。
4. **均值类指标必标样本数 n** —— 见下节"均值陷阱"，不标 n 的分数无法比较。

```
729（主库·基准层）

```

### 附：均值陷阱（同日现场抓到）

归库后跑成熟度脚本：**10 场 → 68/100**，新增第 11 条记录后 → **66/100**。
看起来"退步了"，实则**样本增加导致维度均值重算**（D2 16.7→15.9、D3 13.3→12.7），并非回退。

→ **纪律**：凡均值/评分类指标，报数格式一律 **`分数/满分 · 等级 · n=样本数`**（例：`66/100 · M3 · n=11`）。
**不标 n 的两个分数不可比**——这正是"口径不同、数字打架"的另一副面孔。

### 附 3：容错 fallback 陷阱（**同题第 6 案** · 2026-09-28 · OPC 规则包 M4 挖因）

> **一句话**：这次不是"我没定口径"，是**我自己写的容错代码把口径偷偷换掉了**——
> `or` 短路让一次取错值变成一次**合法的、无声的、看起来完全正常**的读数。

#### 事故回放

| 时点 | 动作 | 结果 |
|---|---|---|
| 09-28 14:1x | 写脚本盘点 18 个规则包的待核验源 | 脚本报「各包 **2 条** / 合计 **36**」 |
| 同上 | 据此向老强报出「**705 vs 36**，差 19.6 倍」 | 断言 manifest 与实体清单**脱钩**（重判断） |
| 14:2x | `cat` 人伤法包清单原文 | 实为 `{"count": 174, "rule_ids": [ …174 条… ]}` |
| 14:2x | **假矛盾当场崩塌**，向老强当场纠正 | 未写入任何文档 |
| 14:3x | 重跑正确口径 | 18 包 manifest / ids / count **三者完全一致**，705 正确 |

#### 错在哪一行

```python
n = len(d.get('pending') or d.get('items') or d.get('list') or d)
#         ↑ 不存在      ↑ 不存在      ↑ 不存在    ↑ 回退成 d 本身
#  → len(d) = 字典的「键数」= 2（"count" + "rule_ids"）
```

三个 key 都不存在 → `or` 链短路 → fallback 到 `d` 本身 → `len()` 量的是**字典键数**，
而数据里恰好有两个键 → 得到「2」这个**完全合法、完全不报错、看上去像个真实条数**的数字。

#### 根因：这是 A 型的**新变种（D 型）**

| 型 | 表现 | 本次形态 |
|---|---|---|
| **A 单位未定义** | 键 / 条目 / ID / 记录 混用 | 09-15 已记（`len(dict)` 当条数） |
| **B 层级未定** | 主体 / 变体 / 维度 混计 | 09-15 已记 |
| **C 快照未复测** | 引用记忆里的旧数字 | 09-15 已记 |
| **🔴 D 容错降级（新）** | **容错代码自身制造了错单位** | `or` 链 fallback 静默换成整个对象 |

A 型是"**我没说清在数什么**"；D 型是"**我说了，但代码替我换了**"——
**后者更难发现，因为它连报错都没有**。

#### 三条新铁律

| # | 铁律 | 说明 |
|---|---|---|
| 🔴 1 | **fallback 必须显式判类型，禁用 `or` 链静默降级** | `d.get(k)` 后先 `isinstance` 校验；取不到就显式报错，**不要回退成整个对象** |
| 🔴 2 | **盘点脚本产出数字后，必须人肉核对至少 1 个样本的原始文件** | 本次正是靠 `cat` 一个清单翻的案。**脚本人不核 = 没核** |
| 🟢 3 | **报"两个数打架"前先自问：是数据矛盾，还是我两次数了不同的东西？** | 同题已第 6 次；9-27「04-LOG 71 vs 105」（`ls` 单层 vs `find` 递归）是同一个病根 |
| 🟢 4 | **同义逻辑多处分散时，改完必须全文搜同类模式复核** | 见下「改一漏二」——本次脚本 3 处日期判据，我改 2 处**漏 1 处**，被自己的门禁当场抓出 |

#### 改一漏二（本日连带事故 · 同一病根的第三次现形）

把 `二次核验门禁.py` 的日期判据从「≠今天」统一为「>今天」时，脚本里**有三处同义逻辑**：

| # | 位置 | 改了吗 | 后果 |
|---|---|---|---|
| 1 | frontmatter `created`/`updated` | ✅ 改了 | — |
| 2 | 正文「数据来源」 | ✅ 改了 | — |
| 3 | **文件名 `YYYYMMDD` 连写分支**（`DATE_NAME_COMPACT`） | ❌ **漏改** | 历史卡 `…-20260915.md` 被判「≠ 当天」→ **误拦** |

发现方式：**被自己的门禁报错抓出**（报错措辞仍是旧的「≠ 系统当天」，与已改的两处不一致，由此定位到漏改点）。

→ **纪律**：改一处判据，必须 `grep` 全文件搜同类模式（如 `!= TODAY`）逐处核对；
**同义逻辑分散，是"口径不一致"最容易被自己放过的一种形态**——因为你以为自己已经统一了。

| **6** | **2026-09-28** | **容错降级** | **代码（口径被悄悄换掉）** |
