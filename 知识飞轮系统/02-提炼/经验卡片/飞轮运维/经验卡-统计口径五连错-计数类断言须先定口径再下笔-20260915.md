# 统计口径五连错 · 计数类断言须先定口径再下笔

> **一句话**：**"有多少条"这个答案，取决于你数的是"什么单位"**——
> 未定义**计数单位**（顶层键 / 条目 / ID / 记录）就报数，等于用不同刻度的尺子量同一块布，
> 今天这块布被量出了 **11 / 147 / 132 / 2447 / 729** 五个答案，**全错或半错**。

## 一、事故回放（2026-09-15 · 同一天、同一批数据、5 个答案）

盘点 `蓝队律师合同审查` 规则库，我先后给出 5 个互相矛盾的数字：

| # | 我报的数 | 出处 | 实际口径 | 真值 | 错因 |
|---|---|---|---|---|---|
| 1 | **11 条** | 本轮开工前 | `len(risk_rules.json)` = 顶层键数 | **729** | 拿**字典顶层键数**当条数 |
| 2 | **147 条** | 中枢 PROJ-007 旧记载 | 早期版本快照 | 729 / 归库后 835 | 引用**未复测的历史快照** |
| 3 | **132 条** | 技能正文 | 早期版本快照 | 835 | 同上，文档未随代码更新 |
| 4 | **2447 条** | 上一轮汇报 | 递归累加**所有 list**，含 `keywords`/`sources` 子数组 | 主体 **835** | 把**子数组**当独立条目 |
| 5 | **729 条** | 归库时 | 含 `id`+`name` 的**规则条目** | ✅ 正确 | **口径终于定义对了** |

**连锁后果**：基于"11 条"我判定"**主库空壳、可加载率 0.4%**"——这是**重判断**，
差点据此推导出"规则库需重建"的错误路线（实际是"弹药极厚、只缺单一真源"）。

## 二、根因（三类，可自查）

| 类型 | 表现 | 高发场景 |
|---|---|---|
| **A. 单位未定义** | 键 / 条目 / ID / 记录 混用 | JSON 嵌套结构盘点 |
| **B. 层级未定** | 主体层 / 变体层 / 维度层 混计 | 多层数据（本次 835 + 730 + 71） |
| **C. 快照未复测** | 引用记忆或旧文档里的数字 | 写方案、写报告时的"我记得是 X" |

> ⚠️ 本次最隐蔽的是 **A**：`len(dict)` 与 `len(list)` 在 Python 里都合法、都返回数字、
> **都不报错**——所以错得毫无声音，直到交叉验证才暴露。

## 三、铁律：计数类断言「三查法」（报数前必过）

```
① 定单位：我数的是【顶层键 / 条目 / 唯一ID / (id×文件)记录】中的哪一个？
② 定层级：这个数属于【主体层 / 变体层 / 维度层】哪一层？要不要分层报？
③ 定来源：这个数是【本次实测】还是【历史快照/记忆】？未复测的一律标"待核"。
```

**补充四条硬约束**：

1. **报数必带口径** —— 写"835 条"不够，要写"**835 条（含 id+name 的规则条目·主体层·归库后实测）**"。
2. **等式自检** —— 报完数立刻找个能闭合的等式验一遍（见下节）。**对不上就是错了，别硬圆**。
3. **Bash `grep -c` 返回 0 必须换工具复跑** —— 与同族 A 型（存在性断言）同一条纪律。
4. **均值类指标必标样本数 n** —— 见下节"均值陷阱"，不标 n 的分数无法比较。

## 四、本次精确口径表（可直接复用为模板）

**归库后可闭合等式**（写进报告前逐条验过）：

```
729（主库·基准层）
 + 57（expansion 非撞号 ID）
 + 49（真撞号重编号条目）
 = 835（主体层合计）                      ✅ 闭合
```

| 口径 | 数 | 说明 |
|---|---|---|
| 主库唯一 ID | **729** | M1–M862，133 个空号 |
| expansion 唯一 ID | 634 | 45 个文件 |
| **撞号（ID 级）** | **577** | = 634 中与主库 ID 相交者 |
| └ 同名副本 ID | 530 | 内容相同，安全去重 |
| └ **真撞号原号** | **47** | 内容不同，**必须重编号保留双方** |
| 重编号**条目**数 | 49 | >47，因 M851/M852 **各跨 2 个文件** |
| 去重丢弃（id×文件 记录级） | 560 | >530，因 **32 个 ID 跨文件重复** |
| 归库后主体 / 变体 / 维度 | **835 / 730 / 71** | 三层**不可相加**（不同视角） |

> 🔑 **这正是本卡的核心教材**：577、560、49 三个数**全对**，但分别是
> **ID 级 / 记录级 / 条目级**三种口径。混用即产生"577 ≠ 49+560"的伪矛盾——
> 不是数据错了，是**我拿三种尺子比大小**。

### 附：均值陷阱（同日现场抓到）

归库后跑成熟度脚本：**10 场 → 68/100**，新增第 11 条记录后 → **66/100**。
看起来"退步了"，实则**样本增加导致维度均值重算**（D2 16.7→15.9、D3 13.3→12.7），并非回退。

→ **纪律**：凡均值/评分类指标，报数格式一律 **`分数/满分 · 等级 · n=样本数`**（例：`66/100 · M3 · n=11`）。
**不标 n 的两个分数不可比**——这正是"口径不同、数字打架"的另一副面孔。

### 附 2：二元判定虚高（判级陷阱 · 2026-09-15 夜 实测）

同日深夜复核 PROJ-007 成熟度，脚本给出 **93/100 · M5 卓越**（n=13）。拆开看口径：

| 维度 | 满分 | 实际判据 | 性质 |
|---|---|---|---|
| D2 法源可回溯 | 25 | `has(triggered_rules) or has(knowledge_called)` | **有无判定** |
| D3 补救可执行 | 20 | `has(key_finding) or has(value)` | **有无判定** |
| D5 运维回写 | 15 | `has(source_skill) or has(related_links)` | **有无判定** |
| D1 风险覆盖 | 20 | `20 × min(1, n/20)` → **纯场次堆砌** | 数量判定 |
| D4 系统建设 | 20 | 四支柱覆盖数 / 4 | 有无判定 |

→ **60/100 来自「填了字段就满分」，另有 13 分纯靠场次**——合计 **73/100 与"能力深度"无关**。
更关键：M5 判级定义写的是"**训练飞轮自运转、成果反哺规则库与卡库**"，而本席**并无自动反哺机制**（仍靠手工沉淀）→ **判级过宽**。

**纪律**：
1. 评分看板须区分 **留痕分（有无判定）** 与 **能力分（质量判定）**，并在卡上**并列标注**，不得只报总分。
2. **判级定义里的机制必须真落地才算数**——"反哺规则库"若仍靠手工，就不能判 M5。
3. 与 PROJ-005 教训同源（该席 P2 产出留痕 + P3 身份留痕双满分 40 分，真实能力分远低于表面分）。

#### 治理结果（同日老强拍板，脚本升 v1.1 已落地）

| 项 | 修正前 | 修正后 |
|---|---|---|
| D2 判据 | `has(字段)` → 25 满分 | **L0–L3**：rule_id 0 个=8 / 1–2 个=16 / **≥3 个=25** |
| D3 判据 | `has(字段)` → 20 满分 | **L0–L3**：<30 字=7 / ≥30 字=14 / **≥30 字且含动作词=20** |
| D5 判据 | `has(字段)` → 15 满分 | **L0–L3**：仅其一=6 / 两者有但关联 ≤1=11 / **两者有且关联 ≥2=15** |
| M5 门槛 | 分数 ≥85 即授 | **三项硬指标全过才授**（真源可回写 + 工具就位 + 定时调度已配置），否则**封顶 M4** |
| 输出 | 单总分 | **能力分 / 留痕分并列 + 虚高额度** |

**实测落差**：留痕分 92 → **能力分 78**（虚高 **−14**），其中 D2 −9.2、D5 −4.5、D3 −0.5。
场次 13 → **12**（`_template.md` 模板文件曾被误计为一场训练）。

**治理中连带挖出的两个隐藏 bug**（都是"口径正确但读数为假"的变体）：
1. **`parse_fm` 不支持 YAML 块标量** —— `key_finding: |` 被解析成值 `"|"`，
   **既误判有无、也算不出真实长度**；3 条记录受影响（其中韩杰那条实为 99 行高质量记录）。
2. **`_template.md` 计入训练场次** —— 模板的占位符 `<规则类别或 M 编号范围>` 被当成真实引用。

> 🔑 **给同族的增量教训**：**"改判据"和"修读数"必须一起做**。
> 只把二元改成分级、却不修解析器，分级算的仍是错的数——
> **判据再好，读数是假的，分数还是假的**。
