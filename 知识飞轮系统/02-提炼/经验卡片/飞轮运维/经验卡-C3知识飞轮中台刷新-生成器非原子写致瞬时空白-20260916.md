# 经验卡片 · C3 刷新生成器非原子写致瞬时"数据没了"误报

> **类别**：correction / best_practice（AI 工作流安全 · 飞轮运维 · 同步校验 · 原子写）
> **触发场景**：浏览器化大屏 / 看板以 `<script src>` 或 `fetch` 加载单一数据源 JS/JSON，且数据源由生成器定时 / 手动重写时
> **一句话**：生成器用 `open(DST,"w").write()` 先清空再写，浏览器在重写瞬窗拉到半截/空文件→屏空白，用户误判"数据没了"；任何被线上实时读取的数据源生成器，**必须原子写**（写临时文件+os.replace），读者永远拿到完整文件。
> **关联铁律**：六-B 安全铁律、cp 备份铁律、C3 刷新部分同步陷阱（同构·同步须全字段校验）

---

## 一、事故回放（2026-09-16 · C3-DATA-GHOST）

- **18:02 用户报**：9360 C3 知识飞轮中台"数据没了"（口误"9630"按 9360 处理）。
- **全链路实地排查（结论：数据没真丢）**：
  - 数据源 `flywheel-data.js`（符号链接→`feilun-refresh/flywheel-data.js`）内容完整，所有段（kpi / cardGrowth / metrics / layerInc / kg / rules / intake / alerts / cardFamily / autos）饱满；node 解析全字段非空。
  - served `/flywheel-data.js` HTTP200 + 12734B + `const DATA` 可解析。
  - C3 子屏 `index.html` 引用 `<script src="/flywheel-data.js">` 正确；首页点 C3 → `./subapps/flywheel/index.html`（rbac.js 映射正确）。
  - **浏览器实渲染 C3 全屏**：KPI(414/1949/4898/15/20/0)、增长曲线、六层活跃(+250/+1287…)、摄入管道、知识图谱(9621节点/150162链接/58.80%密度)、TOP枢纽节点、20条自动化矩阵**全部正常**，无 `undefined`/`NaN`/空表异常。
- **根因定位**：`feilun-refresh/refresh_live.py:378` `open(DST,"w",encoding="utf-8").write("\n".join(out))` —— **truncate 式覆盖**，先清空文件再写，中间毫秒级空窗。用户在 18:02-18:03 生成器重写时刷新，拉到半截文件→`DATA` 未定义→屏空白，误判"数据没了"。

## 二、错因

- 生成器"写完即生效"假设忽略了**写入非原子**：truncate→write 之间存在读者可见的半截态。浏览器化大屏是实时读者，必然偶发撞窗。
- 此前该生成器已带写前备份（六-B），但备份防的是"写坏难恢复"，**不防"写过程中读者看到空窗"**。

## 三、可复用铁律

1. **大屏 / 看板单一数据源生成器必须原子写**：`tmp=DST+".tmp_"+ts; open(tmp,"w").write(content); os.replace(tmp,DST)`。`os.replace` 在同卷上是原子重命名，读者要么看旧完整文件、要么看新完整文件，永不见半截。
2. **改写前主文件绝不动**：任何"读取-修改-写回"型脚本，写回步骤都应是原子替换，而非原地 truncate。中断 / 超时 / 崩溃都不应破坏线上主文件（本次实跑生成器超 150s 被 SIGTERM 杀，主文件 `flywheel-data.js` 仍 12734B 完好、served 仍 HTTP200、无 tmp 残留——即证）。
3. **"数据没了"先实渲染再下判**：用户报大屏空白，先用浏览器实渲染 / curl 验 served 数据 + 查生成器最近写入时间戳，区分"真丢" vs "重写瞬窗 / 缓存"，**勿凭印象判丢失**。
4. **家底口径（报数带单位）**：本次各数据段均饱满，确认非"域空白"类误判。

## 四、处置（已落地）

- 改 `refresh_live.py:378` 为原子写（编译通过 + 抗中断验证通过）。
- 建议用户硬刷新(Cmd+Shift+R)即可见 C3 完整数据。
- 同源重复风险已闭环：同构的 `飞轮中台刷新.py` 写 HTML 内 DATA 块原用 `DASH.write_text`（原地覆盖，iframe 加载同瞬窗）已于 **2026-09-16 一并改原子写**（新增 `atomic_write` helper + 第 325 行调用），详见第五节同类加固清单。
