## 一、系统现状概览

### 1.1 架构：EV 十模块（数字分身系统根目录）
```
00-系统总览与运维中心   01-三电-知识飞轮与质检   02-补能-连接器
03-智驾-决策思维系统     04-座舱与模拟法庭         05-黑匣子与车规
06-OTA自动化            07-系统搭建与Skill配置     08-知识库
09-快照备份
```
> 以"电动车（EV）"为隐喻的执业操作系统架构，十模块职责清晰、物理隔离（事故卡与办案实体卡已强制隔离）。

### 1.2 核心人格配置（self.md 自我画像 · 2026-07-28 创建，09-06 更新）
- **职业定位**：技术派实用主义；重证据重法条；每一法律意见必有法条依据、每一风险判断必有证据支撑
- **三重资质**：法律职业资格证 + 社会工作师（中级）+ 执行中药师 → 民商事 + 慈善合规 + 医疗纠纷复合视角
- **专业领域**：民商事合同审查、慈善组织合规、医院法律实务与医疗纠纷
- **论证框架**：六步法（发现问题→举证质证→法律适用→精确法条引用→类案/纪要支持→结论与请求）
- **执业边界**：绝不违反执业伦理、不承诺案件结果、专业判断必说明依据

## 四、年度重大事件与事故复盘

### 🔴 4-1 批量补要件映射卡事故（2026-09-07，已闭环）
- **现象**：批量生成 R-HT/R-PI 指针卡时，脚本在裸名源卡 `R-PI-243` 正则失败中断，已落 125 张却仅登记 15 行 MOC（**表面成功、实则漏登**）；叠加源库 3 组同号冲突产生重复指针。
- **根因**：① 文件名正则不兼容无描述名；② "存在即跳过"增量登记不可幂等；③ 批量前未 pre-scan 同号。
- **处置**：`rebuild_moc.py` 全量重建（MOC 恢复 132 行）、指针去重、源库冲突上报不改源、全量备份。
- **防护固化**：`要件映射卡批量补卡` 技能新增 rule_id 兜底截取 + 全量重建禁增量 + 批量前 pre-scan + 六-B 备份。
- **遗留**：5 处防幻觉规则"影子副本"（LTI/prc-* 未 `extends: legal-base`）待择方案 A 归一。

### 🟠 4-2 连接器断线误判翻案（2026-09-09，已纠错）
- 初判 yuandian-mcp / pkulaw / 公益 = 亚型 B（须 UI 重授权）**误报**；实测三者工具调用均正常（元典 512 积分、pkulaw 189 法规、公益基金会数据），根因是旧脚本对"原生授权类连接器"误用 headerOverrides 判定。
- 修复：`fix_connector_batch.py` 升 v4.0.5（数据驱动），SOP/监测日志/记忆全纠错。

### 🟡 4-3 WorkBuddy 积分超额（2026-09-09 告警）
- 套餐 17,003.38 已用 102.9%（剩余 −497.16），近 7 日消耗加速比 2.92x；TOP3 消耗：吊顶案（1,090.8）/ 摄入守卫（661.4）/ 每日摄入（525.6）。
- 建议：评估套餐扩容或控耗（详见第六节）。

### 🟢 4-4 cheji 语雀快照误判（2026-09-10，已纠错）
- 初判 cheji/portal 均"无本地源须语雀重导出"——错一半。实测 cheji 有本地活产物 `分身系统驾驶舱.html` + 生成器 `刷新驾驶舱.js`，已重生 Sep 10 最新版覆盖旧快照；portal 确为语雀壳（仅导航，已本地改 SITES）。
- 固化：开发者平台 5 子页刷新管线铁律（feilun→飞轮中台刷新.py / jifen→积分监测器.py / **cheji→刷新驾驶舱.js** / juesi→刷新决策树.js / portal→语雀壳）。
