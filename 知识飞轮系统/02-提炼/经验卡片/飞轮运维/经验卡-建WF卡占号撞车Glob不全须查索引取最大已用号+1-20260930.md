# 经验卡片 · 建 WF/R 类卡前必查 _索引.md 取最大已用号+1

## 一句话经验

> 建卡取号不能只靠 `Glob` 看目录——索引里登记的零散卡 Glob 不一定返回，盲占号就撞车。取号前先读 `_索引.md` 拿最大已用号 +1。

## 触发场景

- 新建 `WF-xxx` / `R-xxx` / `PROJ-xxx` 等带顺序号的卡时，需要确定下一个空号。
- 习惯做法：`Glob 04-Workflows/*.md` 看最大号 → 顺推一个。

## 现象（实测）

- 2026-09-29 建「一人公司方向五维筛分卡」，Glob 只返回 `WF-084`（最大），于是占 `WF-085`。
- 2026-09-30 用户点名改维度名，B6 变更影响核查（`grep WF-085` 全库）发现：`_AI-Memory-Hub/04-Workflows/_索引.md` 与 `WF-owner对照表.md` 里的 `WF-085` 早已指向**另一张脚本卡**（文件名 garbled，owner 表已标"建议归档 05-归档"）。
- 结论：我新建的卡与既有 `WF-085` **同号冲突**，违反编号治理铁律（P0-4 即在治同号冲突）。

## 根因

- `Glob` 只列目录里**当前存在的文件**；但 `_索引.md` 登记的卡，部分文件名不规则（garbled / 特殊字符），或已标归档未删，Glob 返回不全。
- 取号依据漏了"索引登记的已用号"这一权威面 → 命中盲区。

## 修复（本案做法）

1. 维度改名「合规得起」→「能合规」（用户点名）。
2. 解撞号：确认 `WF-100/101/102` 空闲（`grep WF-10[012]` 索引无命中）→ 我的卡 `id` 改 `WF-085`→`WF-100`、`git mv` 改文件名。原 `WF-085` 释放。
3. v1.1 版本记录注明改名 + 解撞号；提交 `4016b7e9` 推送同步。
4. 原 `WF-085` 脚本卡（garbled）留待老强裁决走 `05-归档` 流程，未擅自动。

## 教训（固化纪律）

- **建任何带号卡前，先读 `_索引.md`（对应目录）取最大已用号 +1，再 Glob 交叉确认**——双源对齐才占号。
- 索引登记的号 > 目录实际文件，以索引为准（索引是编号权威面）。
- B6 关（改名/移动前 grep 全库链接）不只是防断链，也能顺带抓撞号——本案就是 B6 救的。
