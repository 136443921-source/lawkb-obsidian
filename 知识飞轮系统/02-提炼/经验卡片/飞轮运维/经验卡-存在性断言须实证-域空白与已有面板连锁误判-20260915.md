# 经验卡片 · 存在性断言须实证——「域空白」与「已有面板」连锁误判事故

> **类别**：correction / best_practice（AI 工作流安全 · 断言纪律）
> **触发场景**：在配置 JSON / 文档 / 对话结论中，对**「某物不存在（空白 / 缺 / 无）」或「某物已存在（已有 / 已建 / 已有对应）」**下判断时
> **一句话**：**「空白」「已有」「不存在」「已建」都是存在性断言，记忆和印象给不出可靠答案——落笔前先 `grep` / `find` 实证，且检索口径要 ≥3 组 + 目录级扫描。**
> **关联铁律**：六-B 安全铁律、cp 备份铁律、清理前引用预检铁律（同源·二级文本不能当真相）

## 一、事故回放（2026-09-15 · 同日双案，同一根因）

### 案 A：「域空白」误判（v1.4.2 建卡族时）

- **我下的断言**：裁判规则库在「诉讼代理授权瑕疵 → 起诉条件」域为**空白**，据此在配置 v1.4.2 写道「建议补建 R-CX/R-MS 域卡族」，并给红队转正实战的埋点标注「无对口 rule_id，不硬凑编号」。
- **真相（接入连接枢纽时复核）**：`R-PR-085`（起诉签名身份不符时授权意思表示真实的审查）**早在 2026-09-11 已建**，subtype 冒名诉讼程序战，源自 6658 号吊顶案办案教义蒸馏 + 民法典第 143 条；另有 `R-PR-049`（原告主体资格九类不适格）、`R-PR-109`（撤销自认）两张相关卡。
- **误判根因**：检索口径单一——只用了「授权委托书 / 无权代理 / 代理权 / 诉讼代理」，**没命中 R-PR-085 的用词「授权意思表示」**。同一域、不同措辞，单口径 `grep` 即漏判。
- **准确表述**（已纠偏）：该域原为「**单点卡 + 缺链条**」，新建 R-PR-178~182 是**补齐链条**，不是填补空白。

### 案 B：「已有面板」误判（v1.4.2/1.4.3 写待办时 → v1.4.4 建面板时暴露）

- **我下的断言**：配置 v1.4.2 写「P3 中台红队心智面板待建（**蓝队/书记员已有对应面板**）」；v1.4.3 沿用。
- **真相（建面板前 grep 实证）**：`mock-trial-center-enhanced.html` 中 grep「蓝队」「书记员」**零命中**——中台此前**只有「🧠 法官心智」一个面板**（入口 `btnJudge`，第 461/570 行）。蓝队/书记员面板**根本不存在**。
- **后果与处置**：没只建红队，而是**三方一并补齐**（通用抽屉 `#minddrawer` + 🔴红队/🔵蓝队/📝书记员 三入口）才实现四方同构；并把「蓝队/书记员已有对应面板」从配置中删除、改为「三方均无、本次补齐」。

### 共性

> 两案同日在**模拟法庭席位配置**这条主线上发生，手法完全一致：**凭印象/上一轮记忆写存在性断言，未先 grep 实证**。且案 A 的「纠错」本应触发对案 B 的警惕（同源），却还是栽了第二回——说明这是**系统性断言纪律缺口**，不是偶发手滑。

## 二、根因

1. **存在性断言靠记忆，结构上不可靠**：「某域空白」「某面板已有」这类否定/肯定存在命题，必须查库才知道；记忆只记得「我上一轮以为」，给不出真值。
2. **拿上一轮结论 / 印象当真相**（与 `规范清单硬编码必漂移` 同源）：案 A 采信了「此前检索未命中＝空白」，案 B 采信了「我以为之前建过面板」。二者都是把**二级产物（我的结论）当成了事实本身**。
3. **检索口径单薄**：案 A 的漏判直接源于只用一组同义词检索；判定「空白」是**重判断**，单口径命中「无」不等于真无。
4. **未执行「先实证再落笔」闸**：写配置前若先 `grep` 一下中台 HTML / 裁判规则库目录，两案都能当场证伪。

## 三、固化铁律（每次下「空白 / 已有 / 不存在 / 已建」判断前必念）

| # | 铁律 | 说明 |
|---|---|---|
| 🔴 1 | **存在性断言先实证，再落笔** | 凡要写「空白 / 缺 / 无 / 已有 / 已建 / 已有对应」，先 `grep`/`find` 真库；记忆与印象一律不可作为存在性依据 |
| 🔴 2 | **判定「域空白」须 ≥3 组检索词 + 目录级扫描** | 同义词、用词差异（如「授权委托书」vs「授权意思表示」）会导致单口径漏判；目录级 `ls`/扫描兜底 |
| 🔴 3 | **「已有 X」也要 grep 实证** | 不能因为「我记得建过」就写「已有」；案 B 正是此坑 |
| 🟢 4 | **同一根因的纠错须触发同源警惕** | 案 A 纠偏后，应立即审查「我还有哪些『空白/已有』断言未实证」——案 B 本应被这一道闸拦下 |
| 🟢 5 | **断言落笔后留痕可核查** | 配置/文档里的存在性断言，附「实证命令 + 命中/未命中」（如 `grep -c 蓝队 enhanced.html = 0`），便于他人复验，也倒逼自己先查 |

## 四·续、案例三：Bash `grep` 误报 → 「L1/L2/L6 三块为 0」误判（2026-09-15 16:45 · 第三案）

**场景**：搭建 🔵蓝队非诉律师（PROJ-007）心智模型方案，需判断基座技能 `蓝队律师合同审查` 是否已含席位声明、算法段、回写机制。

**误判过程**：
```bash
grep -c "席位\|seat" SKILL.md   → 0
grep -c "回写\|write_back\|记忆\|Obsidian\|IMA" SKILL.md → 0
```
据此在方案 v1.0 中写下「L1 席位 / L2 算法 / L6 回写 **三块均为 0**」，并把它列为 P0 三件待办。

**真相**：Grep 工具复核命中 **18 处**；文件内**早已存在**
`## 🪑 非诉席位宣言（蓝队非诉律师 · PROJ-007）`、`## 🧠 非诉心智算法（L2）`（算法A 合同审查四段法 / 算法B 非诉文书起草法）、`## 📥 训练与回写（中枢级）`，
且版本历史摘要明确写了 **v10.0.0（2026-09-15）升格**。三块**全部已落地**，P0 三件待办是**拿已完成的事当待办**。

**根因（新变种）**：Bash 侧 `grep -c "A\|B"` 的**转义与计数在本次环境返回 0**（同一次会话里 `grep -c "LTI"` 却正常返回 17，具有**欺骗性**——不是"grep 坏了"，是"部分模式静默失配"）。
→ 与案例一、二（检索口径不全）**根因不同**：本次是**工具输出静默失真**。

**新增铁律（第 5 条）**：
> **「为 0」的计数结果，一律换工具复跑一次再信。**
> Bash `grep -c` 返回 0 ≠ 不存在：① 用 Grep 工具复核 ② 与文件**版本历史 / changelog** 交叉验证 ③ 仍为 0 才可落笔。
> 同理，任何"已存在/已建"的肯定断言也须双源验证（工具命中 + 版本记录）。

**已造成的代价**：方案 v1.0 与中枢 PROJ-007 卡一度写入错误现状，当日 17:00 前已全量回改（方案二章、P0 表、备忘录一句话结论 + 七层栈 + 病灶表 + frontmatter）。

## 四·续二、案例四：zsh `no matches found` 整条命令中止 →「目录不存在」假阴性（2026-09-27 · 第四案）

**场景**：撰写《三系统商业化复盘 v0.1》，盘点开源引流层（`lawtwin-open`）是否存在、获客入口是否为 0。

**误判过程**：
```bash
ls -d ~/Documents/*lawtwin* ~/lawtwin-open ~/some_other   # 想要一次性确认三个候选位置
# → zsh: no matches found: ~/Documents/*lawtwin*
# → 整条命令中止，后面的 ~/lawtwin-open 分支【根本没执行】，无任何输出
```
据此在复盘初稿写下：**「`~/lawtwin-open/` 目录不存在、获客入口 = 0」，并据此把「开源引流层」整条业态判死**。

**真相（分开逐条重跑后）**：

| 项 | 实测值 | 命令 |
|---|---|---|
| 文件数 | **313**（不含 .git） | `find ~/lawtwin-open -type f -not -path "*/.git/*" \| wc -l` |
| 提交数 | **5** | `git log --oneline \| wc -l` |
| 许可证 | **Apache-2.0** | `head -5 LICENSE` |
| git remote | **0**（未推远端，真问题） | `git remote -v \| wc -l` |
| 未提交变更 | **11 项**（当晚补的 CLA/CONTRIBUTING/README） | `git status --porcelain \| wc -l` |

**根本反转**：目录不但存在，而且已经是一个**有 313 文件、5 次提交、Apache-2.0、脱敏门禁 PASS 的像样骨架**；真问题只有一个——**没配远端、没推送**。初稿把"没推送"夸大成"不存在"，直接误伤一条本可成立的业态。

**根因（与案例三不同机制）**：

| | 案例三（2026-09-15） | 案例四（2026-09-27） |
|---|---|---|
| 失效机制 | **工具输出静默失真**（`grep -c "A\|B"` 转义被当字面量） | **命令根本没跑到**（zsh glob 无匹配 → 整条中止） |
| 可见症状 | 有输出，但数字是错的（返回 0） | **完全无输出**，空输出被当成"不存在" |
| 隐蔽度 | 中（至少读了个数） | **高（连输出都没有，空 = 无 = 不存在，错觉链最短）** |

> ⚠️ **本案最危险之处**：`grep` 假阴性至少还吐了个 `0`，人会警觉去复核；**glob 中止连 `0` 都不吐，空输出被直接等价为"不存在"**——这条最短的错觉链，正是"否定型结论"最容易骗过自己的地方。

**新增铁律（第 6 条）**：
> **否定型结论一律视为"未验证"，须换命令形态重测后方可落笔。**
> `不存在 / 没有 / 为 0 / 未命中 / 目录不在`——**这些词出口前，必须换一种写法再测一次**：
> ① 把多目标命令**拆成一条一个**（本案就是拆开才看见真相）；
> ② 用 `find <dir> -maxdepth 1` 这类不依赖通配的命令替代 `ls -d A B C`；
> ③ 用 Grep / Glob 工具（ripgrep，不受 shell glob 影响）复核否定结论。
> ③ 是**兜底底线**：**凡否定型结论，未换第二种工具复核前，不得写入任何文档。**

**已造成的代价与处置**：复盘 v0.1 初稿 §0/§1.2/§4.1/P0 表/§5.6 六处均写入了"目录不存在、获客入口=0"，当日已在报告内**立「更正声明」框**并全量改回实测值；同时在报告 §三补记了案例三同款 BSD grep 教训，点明「**否定结论是假阴性**」是本 AI 的**反复发作病**。老强当场纠正并定下纪律「**有事故必沉淀成卡**」。

### 案例四·补记（2026-09-27 15:29）：同一事故的第二个形状——**不该建夹却建了夹**

老强随后指出：`OPC 一人公司/` 板块**本就有四段式结构**（`00-数字资产登记册` / `01-规则包` / `02-监控` / `03-商业化运营`），归档位应当落在既有的 **`03-商业化运营/`**，无需另建。我却自作主张新建了 `obsidian-opc-03/`。

| | 主形（假阴性） | 补记形状（建夹癖） |
|---|---|---|
| 错误动作 | 断言"目录不存在" | **默认"归口也不存在"** |
| 本质 | 把**没查到**当成**没有** | 把**没查既有结构**当成**可以另起** |
| 危害 | 误杀一条真实业态 | 制造**结构冗余**，埋下双份漂移 |

**新增铁律（第 7 条）**：
> **归档 / 落位前，先 `ls` 既有板块结构，能挂既有归口就不建新夹。**
> 与铁律第 1 条同源：**「没有这一节」也是断言，必须先看一眼再下笔**——
> 既有目录树本身就是最便宜的存在性证据，而我没做这一步。

**正确处置**：新建空夹已由老强在 Obsidian 中撤销；复盘报告正式副本改存 `Documents/LawKB/OPC 一人公司/03-商业化运营/`（md5 `44b9d1cd…`／29479 B，与工作区原件逐字节一致，原件保留）。
