# 方法卡 · 四模板联动（CLM ↔ 模拟法庭闭环）

## 一句话经验
以 `case-state.json` 为**唯一枢纽**，CLM 管理系统（事实源）→ CLM 大屏（展示端）已能适时呈现进展/期限/待办；真正的联动断点在 **CLM 与模拟法庭之间、两块大屏之间**——用 `mockTrial` 段 + 两处回写钩子打通，即实现「接案走流程→准备报告完成→解锁模拟入口→推演→进展回写大屏」全链路可视化。

## 四模板现状复盘（实地查实）
| # | 模板 | 角色 | 现状 |
|---|---|---|---|
| ① | 案件生命周期管理系统（CLM） | 管理端·事实源 | `LawKB/案件生命周期管理系统/<案名>/case-state.json`（case-state/v1）：七阶段+七门禁 G0-G7、deadlines、nextActions、risks、publicView；`meta.agents` 阶段④已登记 `mock-trial-control-center` 接入点 |
| ② | CLM 大屏 | 展示端 | `scan_cases.py` 扫 case-state → 内部全量+脱敏+桌面副本+对外简报+当事人页；进展/期限/待办已能适时呈现（重跑即刷新） |
| ③ | 模拟法庭庭审系统 | 管理端 | `模拟法庭庭审系统` skill v1.7.0 强制红蓝对抗；阶段0 不读 case-state、阶段3/6 不回写（A档前） |
| ④ | 模拟法庭大屏（控制中台） | 展示端 | `mock-trial-control-center`（93a0d…），单文件静态+localStorage；数据靠剧本 JSON 手工导入 |

## 四个联动断点（须逐个打通）
- **断点① 触发**：CLM「庭审准备报告完成」无法自动衔接开模拟庭 → 用 `mockTrial.prepReportReady` 作触发信号
- **断点② 入口**：CLM 大屏无跳转控制中台入口 → 大屏加"进入模拟法庭控制中台"按钮（深链 `…?case=<caseId>`）
- **断点③ 回写**：模拟推演结论不回写 case-state → 阶段6 收口钩子写 `status/lastTrialAt/trialBriefPath`
- **断点④ 对外**：模拟进展无法以脱敏形态给客户看 → 复用 CLM 脱敏管线产 `对外简报-<caseId>.md`

## A 档落地（本次已实施）
**1. case-state schema 扩展**（case-state/v1 加 `mockTrial` 段，向后兼容）：
```json
"mockTrial": {
  "prepReportReady": false,   // 阶段3 产庭审准备报告后置 true（=触发信号）
  "prepReportPath": "LawKB/法律文书/模拟法庭/庭前强化稿/庭审准备报告_v3.md",
  "status": "未启动|进行中|已完成",
  "lastTrialAt": null,
  "trialBriefPath": null
}
```
已回填 6658（prepReportReady=true，报告 v3 在册）、6660（prepReportReady=true，路径待定留 null）。

**2. CLM 大屏渲染**（`templates/dashboard.template.html`）
- 加 `MOCK_TRIAL_URL` 常量（控制中台 93a0d…）+ `mockTrialHtml(c)` 函数
- 每个案件卡片插入"模拟法庭推演"区块：准备报告就绪态 ✔/✘、状态徽章、最近推演日期、**进入模拟法庭控制中台按钮**（仅就绪时解锁，深链带 `?case=<caseId>`）
- `scan_cases.py` 脱敏模式 `prepare_redact` 已 `pop("mockTrial")` 防本地路径外泄

**3. 模拟法庭两钩子（skill v1.7.0）**
- 阶段0「CLM 案源直通」：按 caseId 读 case-state 自动填定向卡，免粘贴；`prepReportReady==true` 时继承既有准备报告
- 阶段3「回写钩子」：庭审准备报告 v3 定稿后写 `prepReportReady=true` + `prepReportPath` → 解锁大屏入口
- 阶段6「收口回写」（闭环，B 档部分提前实施）：推演后写 `status/lastTrialAt/trialBriefPath`；可选产客户脱敏摘要

**4. 自动化接入**：`CLM 大屏每日刷新` 自动化（每日 07:00）→ 跑 `scan_cases.py` + 复用 sandbox 重部署 `WorkBuddy/案件生命周期管理系统`，CLM 大屏"适时"落地。

## B 档（自动衔接 · ✅ 已落地 2026-09-10）
阶段6 收口钩子已写（见上），进一步：CLM 大屏按 `mockTrial.status`（未启动/进行中/已完成）自动呈现模拟进展/期限；`mockTrialHtml(c)` 已按 status 动态显示"模拟推演进行中/结论已回写"提示。驾驶舱 portal 内 CLM 大屏 iframe 嵌模拟法庭区块（同舱同源已就绪）。

## C 档（给客户看 · ✅ 已落地 2026-09-10）
控制中台加"案件模式"：导入 case-state 自动生成剧本 JSON（免手工填 `案件基本信息.md`）；推演实时状态导出脱敏"模拟进展摘要"页（复用 publicView 白名单）。⚠️ 控制中台含真实案号，对外演示前必须换脱敏剧本。
- **已落地**：① `mock-trial-center/index.html` 加「📁 导入案件(case-state)」按钮（前端内嵌 `convertCaseStateToScript` 复用 `normalize/renderAll`）＋「⬇ 导出客户摘要」按钮（`exportClientSummary` 生成脱敏 HTML）；② 转换器 `case_state_to_mocktrial.py`（6080B）读 case-state → 脱敏剧本 JSON（meta 代号化、真实姓名/案号/法院全脱敏），双案 6658/6660 测试零真名残留。

## 执行纪律（来自用户铁律）
- **Fix-the-source 工作流**：只改 `scan_cases.py`/`dashboard.template.html`（源），不手改生成的 `案件生命周期大屏.html`（产品级编辑会被脚本刷新覆盖）
- 改前先备份；批量前 dry-run；脱敏模式绝不外泄本地路径/真实姓名
- CLM 大屏在线刷新 = 跑 `scan_cases.py` 后 `workbuddy_sites_deploy` 复用 sandbox 重部署
