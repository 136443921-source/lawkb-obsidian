# 中文数字条号转换双向坑 —— int→cn 吞零 + cn→int 进位错

> **一句话**：中文数字条号的**双向转换**（`int_to_cn` 与 `cn2i`）各有一个隐蔽 bug，且**都不报错、只静默算错数**——表现是「检测器造假数据」：文件明明完整，却被判缺号；缓存明明填了，却永不命中。
>
> **更省事的出路**：**条数 / 连续性统计一律用「行首匹配计数」，根本不做数字转换。** 非转不可时，先跑自测用例。

## 两个方向的坑（同一函数家族，2026-09-01 与 2026-10-15 各踩一半）

| 方向 | 函数 | Bug 表现 | 首次沉淀 |
|---|---|---|---|
| **int → cn**（构造缓存键） | `int_to_cn` | **吞零**：105→"一百五"、1208→"一千二百八" → 缓存键与引用归一化结果永远对不上，**静默失效** | 2026-09-01（本节原文） |
| **cn → int**（统计 / 连续性判定） | `cn2i` | **进位逻辑错**：含"十/百/千"的多位数系统性算错（见下三连错）→ **误报缺号假警报** | 2026-10-15（本次新增） |

---

> 初版背景（2026-09-01）：把刑法子条款（40 条之一/之二）补齐进 LTI 缓存，连带根治 `int_to_cn` 吞零 bug。该 bug 让刑法/刑诉/民法典全部含零条号（105、205、1208 等）的缓存「填了但永不命中」，属隐蔽性极强的静默失效。

## 触发场景（trigger）

维护或扩展 LTI 条文正文比对缓存（local-index 预回填 / 元典在线核验回填），凡涉及中文数字条号（含零条号、子条款）即须先过本卡。

**2026-10-15 扩充**：法条银行的条数统计、分编拆分、换版校验、缺号扫描同样适用——凡对「第X条」做数字比较、连续性判定、`article_count` 核对，均属本卡场景。

## 踩坑（don't）
- ❌ **中文数字转换吞零**：旧 `int_to_cn` 把 105→"一百五"、205→"二百五"、1208→"一千二百八"。缓存键变成 `中华人民共和国刑法_第一百五条`，而 LTI 引用归一化结果是 `中华人民共和国刑法_第一百零五条` → **键对不上，相关条号缓存静默失效，等于白填**。回归测试只测无零条号（如 232/66/452）绝不会暴露。
- ❌ **子条款正则不捕获"之X"**：`_CITE_CN` 旧式 `第([一二…]+)条` 在"第二百五十三条之一"只截到"二百五十三"，子条款被误当顶层条号 → 正文比对错配。
- ❌ **并行 agent 拉元典遇 429**：共享配额下 7 并行易打满；整部法 `rh_fg_detail` 返回 86K+ 字符超 token 上限，落盘至 tool-results 路径被沙箱拦截（Read/Bash Permission denied）→ 直读不可行。
- ❌ **轻信 agent 文本清单**：后台 agent 汇报的 verified/not_found 列表可能内部矛盾（同一条号两边出现）。必须以 Python 重解析源文件取真实条号集合为准，不信任 agent 文本。

- ❌ **cn→int 进位逻辑错（2026-10-15 三连错）**：`cn2i` 对含"十/百/千"的多位数系统性算错，**同一天连踩三次**：

| # | 场景 | 错误写法 | 实际后果 |
|---|---|---|---|
| 1 | 民法典分编拆分（G6） | 不认「千」字 | 婚姻家庭 / 继承 / 侵权三编被判 **0 条** |
| 2 | 民法典全文复核 | 对「零」字处理错 | 🔴 **误报「民法典缺 261 条」假警报**——实测 1260 条完整，差点去"补全"一张好卡 |
| 3 | 商标法换版校验（G8） | `sec=(sec or 1)*10+num` | 「二十七」算出 **19** → 商标法被判「第 27–87 条全缺失」假警报（实测 87 条连续完整） |

  > 三次的共同点：**错的全是检测器，文件一个字节都没问题。** 第 2 次最险——若信了"缺 261 条"去补全，反而会把一张完整卡片改坏。

## 应当做（do）
- ✅ **回填前先单测 `int_to_cn` 含零正确性**：覆盖 105/108/109/205/305/405/1208 等再灌缓存。修正实现须严格补零（百位↔十位、十位↔个位间零位空缺均补"零"）。
- ✅ **回填后跑真实查找校验（含零键 + 子条款）**：`get_verification("刑法","第二百零五条")` 须 HIT，而非仅测无零条号。子条款 `get_verification("刑法","第二百五十三条之一")` 须 HIT。
- ✅ **子条款回填范式**：源文件（如 `raw/刑法_sub.txt`）仅含经元典逐条核验存在的子条款；SOURCE `articles=None` 读整文件，`build_plan` 对 `raw_txt_sub` 特判，键构造为 `第{int_to_cn(num)}条之{int_to_cn(sub)}`（缓存键形如 `中华人民共和国刑法_第二百五十三条之一`）。
- ✅ **引用正则扩展捕获"之X"**：`_CITE_CN`/`_CITE_ARABIC` 加 `(之[一二三四五六七八九十]+)?` 组；`build_annotation`/`extract_verify_requests` 传完整"第二百五十三条之一"形式，子条款才不被误截。
- ✅ **note 显示保留"之X"结构**：用 `_display_art`（而非 `_clean_art`）拼 note，避免"第二百五十三之一条"这类错串；`_display_art` 对含"之"的输入返回 `第{head}条之{tail}`。
- ✅ **破坏键先删后建**：改动缓存键格式后，用 `fix_zero_keys.py` 以「旧 buggy int_to_cn」复算并删除错误键（仅删 corruption，保留正确键与 yuandian-mcp 在线键），再跑 prefill 重建正确键。

- ✅ **🔴 条数统计铁律（2026-10-15 三次踩坑后定）**：**条数 / 连续性 / 缺号统计，一律用「行首匹配计数」，绝不做中文数字→阿拉伯数字转换。**

  ```python
  # 正解：行首计数，不转换
  n = len(re.findall(r'^第[一二三四五六七八九十百千零〇\d]+条\u2002', body, re.M))
  # 条号前可能有全角空格 U+3000 首行缩进，用 ^\s* 容错
  n = len(re.findall(r'^\s*第[一二三四五六七八九十百千零〇\d]+条', body, re.M))
  ```

- ✅ **非转不可时，先跑自测用例**（2026-10-15 修正后的正确实现）：

  ```python
  def cn2i(s):
      if s.isdigit(): return int(s)
      t = sec = num = 0
      for ch in s:
          if ch in D: num = D[ch]
          elif ch == '十': sec += (num if num else 1) * 10; num = 0   # ← 关键：num>0 用 num，否则用 1
          elif ch == '百': sec += (num if num else 1) * 100; num = 0
          elif ch == '千': t += (sec + (num if num else 1)) * 1000; sec = num = 0
      return t + sec + num
  ```

  自测用例（**必过**）：`二十七→27`｜`十→10`｜`二十→20`｜`八十七→87`｜`一千二百六十→1260`｜`一百→100`

- ✅ **判「缺号」前先验检测器本身**：得到"缺 N 条"这类否定型结论时，先用**行首计数**复核一遍总数；两个口径不一致 → 是转换器错，不是文件缺。

## 根因（原理）

`get_verification` 用 `replace("第","").replace("条","")` 对缓存键与查询做归一化比对。缺零键归一后少了"零"段（如"一百五" vs "一百零五"），永远不匹配 → 缓存虽在但查不到，表现同"未回填"（静默失效）。故**缓存键与引用归一化口径必须逐字符一致**，含零一致性是回填的硬门槛。

**双向扩充（2026-10-15）**：中文数字是**位权记数法**，"十/百/千"是位权标记而非普通字符。进位逻辑写成 `(sec or 1)*10+num` 时，`sec=0` 被 `or` 兜成 1，于是"二十七"走成 `1*10+2=12`，再叠加个位 7 → **19**。正确写法必须区分「位权前有无数字」：`(num if num else 1)*10`。

**两个方向共同的危害形态：检测器造假数据**——不报错、输出看似合理、根子上错。这与「门禁扫描 0 张不等于通过」「问错字段得出零疑本」同族：**指标不能证伪目标命题时，它就是无效指标。**

## 六-B 安全铁律
- 任何写缓存前 `.bak-*` 时间戳备份（`prefill_cache.main()`、`fix_zero_keys.py` 均内置）；删错误键单独备份，绝不裸 `rm`。
- 回填用幂等逻辑：同键已有条目跳过，保留在线核验（yuandian-mcp）优先权，不降级覆盖。
- **2026-10-15 补**：据"缺号"结论做任何"补全 / 重建"动作前，先确认检测器本身正确——否则会把好数据改坏。
