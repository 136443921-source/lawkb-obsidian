# 如何用 AI 构建自己的案件管理系统？

> 提炼自魏水水文章（2026-07-20）。核心：用 AI 编程工具（Claude Code / Cursor / Codex）从零搭建个人案件管理系统，无需写代码基础，关键是"先梳理流程→AI 做产品设计→再写代码→持续迭代"。对实习律师/独立律师的本地案件管理极具参考价值。

## 一、为什么值得做

市面案件管理软件要么贵、要么不好用。作者用 AI 从零搭建，沉淀了"案件工作台 + 期限中心 + 待办 + 文书状态 + 跟进记录"的本地系统，核心价值是**把期限和待办从人脑记忆转移到系统提醒**。

## 二、四步法（核心方法论）

### 第一步：花 30 分钟梳理办案流程（不写代码）
- 列出 10 个环节：案件来源、利益冲突审查、立项、合同签署与收费、立案、保全、开庭、判决/裁决、执行、归档。
- 列出核心对象（数据模型雏形）：案件(Case)、客户/委托人(Client)、联系人(Contact)、待办(Task)、期限(Deadline)、文书(Document)、费用(Finance)。
- **关键**：这一步产出越具体，AI 给的系统越贴合实际。

### 第二步：让 AI 做产品设计（别急着写代码）
用 3 个 Prompt 分阶段确认：
- **Prompt 1 架构设计**：输出产品架构、页面结构、功能模块、数据模型（首版只做 5 页：工作台/案件列表/案件详情/期限中心/新建编辑）。
- **Prompt 2 数据模型**：4 类核心数据（案件/期限/待办/文书），其中**期限提醒规则**是重点——
  - 开庭：提前 7/3/1 天 + 当天
  - 举证/答辩/文书：提前 7/3/1 天
  - 上诉/异议/复议：提前 7/3/1 天
  - 保全/续封：提前 60/30/15/7 天
  - 缴费/补正：提前 3/1 天
- **Prompt 3 关键决策**：17 项决策（界面风格、案件阶段划分、是否记录客户信息、SQLite 本地存储、Excel 导出、本地密码、标签、结案隐藏等）。技术栈：React+Ant Design / Node+Express / SQLite / 本地端口 3000。

### 第三步：让 AI 写代码
- 开发顺序：项目结构+数据库 → 案件 CRUD → 期限管理+提醒 → 待办 → 工作台 → 搜索筛选 → Excel 导出 → 登录密码。每完成一个模块停下确认。
- 工具适配：Claude Code 直接本地建项目；Cursor/Codex 编辑器内对话；纯网页版 ChatGPT/Claude 则逐文件复制保存。

### 第四步：用起来 + 持续迭代
- 第一版能用就行，先录入手头案件。
- 迭代 Prompt 模板：改 Bug / 加功能（如时间轴）/ 改界面 / 数据迁移（Excel 导入脚本）。

## 三、未来方向（与法律科技结合）
接入类案检索、建立裁判规则库、团队协作、AI 辅助分析案情、对接日历/企微/飞书通知。

## 四、5 条实用建议（直接可迁移）
1. 别一次做太多——首版只做案件录入、期限提醒、待办管理。
2. **数据结构比界面重要**——结构定了再改很麻烦，第二步多花时间值得。
3. 备份、备份、备份——每周导出 Excel 或复制数据库到云盘。
4. 别怕跟 AI 说"不对"——越具体改得越准。
5. 先自己用，再考虑团队。
