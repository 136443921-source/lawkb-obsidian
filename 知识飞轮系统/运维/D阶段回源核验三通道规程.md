# D 阶段回源核验三通道互补规程（v1.0）

## 一、目的与适用范围

本规程定义每日知识摄入自动化 **D 阶段**「降级卡回源核验」与「通道可用时直接采集」的统一三通道策略。自 **v1.27** 起取代原有的「元典单通道 / 元典+法随双通道」回源认知，引入 **企查查法律数据（`qcc-legal`）** 作为第三通道，与 **华宇元典（`yuandian-mcp`）**、**北大法宝（`pkulaw`，经「法律检索助手」智能体）** 形成三通道交叉印证，提升 `source_verified` 权威性与抗幻觉能力。

**适用对象**：
1. D 阶段新建卡的即时核验（三通道可用时直接采集并交叉印证）；
2. 历史降级卡（`source_verified:false`，WebSearch 降级）待通道恢复后的回源补正。

> 本规程为回源策略**唯一真源**；automation prompt 仅引用本路径，不内嵌枚举（符合 v1.26 单一真源原则）。

---

## 二、三通道定义

| 通道 | 工具 / MCP | 角色定位 | 核心能力 |
|---|---|---|---|
| ① 华宇元典 | `mcp__yuandian-mcp__*`（rh_ft_detail ⑤ / rh_ptal_search ⑦⑧） | 法条 / 案例向量检索**首选** | 法条详情（1 分）、案例要旨检索；**受 A0.4 省分纪律约束（积分计费）** |
| ② 北大法宝 | `pkulaw`（经「法律检索助手」智能体调用） | 权威法条 / 案例**时效核验主源** | 法条时效性核验、案例库权威核验；经智能体调用，**不直耗元典积分** |
| ③ 企查查法律数据 | `mcp__qcc-legal__*`（cite_verify / article_search / authoritative_case_search / 企业检索） | **第三通道 · 引证核验专长 + 企业工商补强** | `get_legal_citation_verify` / `get_judicial_citation_verify`（引证核验）、`get_legal_article_search` / `get_judicial_authoritative_case_search`（法规 / 权威案例）、企业工商检索与股权穿透（慈善关联交易 / 负责人忠实义务 / 公司股权类必要补强） |

**计费说明（重要）**：
- 元典为**积分计费**，守 A0.4 省分（<500 仅法条⑤、<1500 ⑦⑧每槽位限 1 次）。
- 企查查为**独立连接器额度**，与元典互不影响，**不会加剧元典积分消耗**。
- 法宝经「法律检索助手」智能体，非直接 mcp 调用，**免元典积分**。
- 三通道并存 **不会突破既有元典省分纪律**；企查查引证核验（citation_verify）低成本、优先用于交叉印证。

## 三、互补分工矩阵

| 核验对象 | ① 元典 | ② 法宝 | ③ 企查查 | 结论门槛 |
|---|---|---|---|---|
| **法条**（条号 / 时效性） | ⑤ `rh_ft_detail` | 法律检索助手时效核验 | `get_legal_citation_verify` + `get_legal_article_search` | 三路中 **≥2 路一致** |
| **案例**（案号 / 要旨） | ⑦⑧ `rh_ptal_search` | 案例库权威核验 | `get_judicial_citation_verify` + `get_judicial_authoritative_case_search` | 三路中 **≥2 路一致** |
| **企业 / 工商关联**（慈善 R-CF 关联交易 · 负责人忠实义务 · 公司股权 R-SH / R-HT 股权类） | — | — | 企业检索 / 股权穿透 / 关联企业 | **企查查工商补强为必要项**，缺则回源不完整 |

> 互补逻辑：元典与法宝长于「法条 / 案例权威来源」，企查查长于「**引证核验（该案号 / 法条是否真实存在、是否被引用）**」与「**企业工商实体数据**」。三路交叉，企查查的引证核验作为抗幻觉的第三道闸门。

---

## 四、回源判定门槛（`source_verified:true` 条件）

1. **普通卡**：三通道中 **≥2 路权威一致**，且企查查引证核验（`citation_verify`）通过 → 标记 `source_verified:true`；`verified_by` 记实际命中的通道（如 `yuandian|pkulaw|qcc-legal`）。
2. **企业 / 工商关联类卡**：在上式基础上，**企查查工商数据补强项须有结果（不可缺）**；否则维持 `source_verified:false` 并标注 `企查查工商补强缺失`。
3. **任一通道 absent**：其余通道补位，至少 **1 路权威（元典或法宝）+ 企查查引证核验通过**；若企查查亦 absent → 维持 `source_verified:false`，待下轮回源。
4. **全通道 absent**：维持 `source_verified:false`，不强行翻 `true`（防幻觉硬约束）。

---

## 五、成本纪律

- 元典守 A0.4 省分：余额 `<500` 仅法条 ⑤；`<1500` ⑦⑧ 每槽位限 1 次；`=0` 全链路降级。
- 企查查引证核验（`citation_verify`）**低成本、优先用于交叉印证**，不突破元典预算；与元典为独立额度。
- 法宝经「法律检索助手」智能体，非直接 mcp 调用，免元典积分。
- D 阶段每日预算仍守 v1.24 精神（≤30 分目标因元典单价实测已暂停，以 A0.4 实际余额为硬约束）。
