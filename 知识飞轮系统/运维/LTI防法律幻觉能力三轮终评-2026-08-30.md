## 三、两条硬边界（不是 bug，是原理限制）

### 边界一：细节编造 0/4

> 特征：**条号正确 + 主题词正确，仅具体规则内容被篡改**

| 用例 | 内容 |
|---|---|
| G1 | 民法典586条定金上限 20% → **30%** |
| G2 | 民法典1165条过错责任 → **无过错责任** |
| G3 | 刑法234条故意伤害致人重伤**量刑档次错** |
| F4 | 民诉法67条举证责任 → **举证责任倒置** |

**为什么本地判不了**：要发现"20% 被改成 30%"，必须**与权威原文逐字比对**。本地主题词表只存「主题词→条号」的映射，**不存条文正文**，原理上无法比对。

### 边界二：案例存在性 0/3

| 用例 | 内容 |
|---|---|
| H1 | 指导案例第**188**号（在 1–279 合法区间内，但内容系伪造） |
| H2 | 案号（2023）最高法民终字第9999号（年份合法，案号不存在） |
| H3 | 《最高人民法院公报》2024年第12期案例（期号无法本地枚举） |

**R115 只堵住了"编号夸张型伪造"（第500/999号、第60/80批），堵不住"编号合理型伪造"**——这与 R102 的边界完全同构：**本地白名单只能拦越界，拦不住区间内张冠李戴。**

### 一句话概括两条边界

> **LTI 能判断"引用是否越界"，不能判断"引用是否真实"。**
> 前者是集合成员判定（可本地），后者是事实核验（须联网）。

## 五、剩余可选项：P2 在线核验

**方案**：`legal-base` **R021 三阶段在线核验**——R101 通过后抽取「法规名+条号+内容主张」→ 元典 `rh_ft_detail`（**1 分/条**）取权威原文 → 相似度比对。

**收益**：直接打通上述两条硬边界（细节编造 + 案例存在性），理论上检出率可逼近 95%+。

**卡点（必须知晓）**：
- `yuandian_verify.py` **不直连 MCP**（Python 拿不到连接器凭据）
- 须由**会话 AI 主动跑三阶段**并回填 `yuandian_verify` 缓存
- **调用方不跑，代码写得再好也是空转**——这是规则层问题，不是代码问题

**落地建议**：做成「**一键核验**」封装——老强交文书时，自动抽取法条 → 调元典 → 比对 → 回填 LTI，无需手工跑三步。

## 六、三轮方法论沉淀（已固化为技能）

> 技能：`~/.workbuddy/skills/法律AI防幻觉能力实测方法/SKILL.md`

1. **先做对照实验再下结论** —— 首轮因缺「中/阿双格式对照」，把正则 bug 误判为能力缺失，差点建议花钱接外部 API
2. **四类对照组缺一不可** —— 写法对照 / 误报对照 / 边界豁免 / 盲区深潜
3. **不看总分看分层** —— "检出率 80%"掩盖了"形式层 100% / 案例层 0%"
4. **盲区必须归因到可量化常量** —— 如「R101 覆盖 64 部法 vs R102 仅 7 部 → 覆盖率 11%」
5. **给防幻觉工具灌数据，数据本身必须核验** —— 实测凭记忆条号错误率 **22%**（慈善法 **75%**），详见 [[LTI条号核验台账]]
6. **白名单类规则只拦越界** —— 实测时须同时构造"越界型"（应检出）与"区间内伪造型"（应承认漏检）
7. **区分"能力边界"与"实现 bug"** —— 两者修复成本相差一个数量级

## 七、一句话结论

**三轮下来，LTI 从"形式层滤网"长成了"形式层严密 + 局部内容层精准 + 案例侧有兜底"的校验器，且始终零误报。它现在能挡住 80% 的幻觉法条；剩下 20% 集中在"引用看起来完全合法、但内容是编的"这类——那是本地规则的物理极限，要跨过去只能联网核验。**
