## 五、建议方案

### 🔴 P0-1：积分治理——建立余额台账与预警线

1. **建台账**：新增 `知识飞轮系统/_运维/元典积分台账.md`，每次批量调用前记录 `日期 / 调用前余额 / 用途 / 调用后余额 / 差值`。
2. **设预警阈值**：

| 余额     | 动作                                     |
| ------ | -------------------------------------- |
| < 1000 | QQ 摘要加 `【⚠元典余额告急】`，自动切入"成本敏感模式"（工作流 D） |
| < 500  | 暂停每日摄入 D 阶段的语义检索①⑥，仅保留关键词②③⑧           |
| = 0    | 全链路降级 WebSearch，标注「来源降级」               |

1. **自动化埋点**：`automation-1783920420205` 的 A0 阶段增加一步 `yuandian_get_user_balance`，把余额写进每日报告与台账。

### 🔴 P0-2：静默错误防御——把指南第三章固化进 legal-base

在 **LTI 文本监控器**的 T 模块（溯源）与 `legal-base` 共享段新增「元典调用后必校验」：

```
取法条 → 看 type / 条号（ft_num 是否含"第X条"）
取版本 → 看 fwzh / sxx
取案例 → 看 ah / title / content 完整性
任何"空返回" → 必看 message（不能只看 code=200）
```

落地方式：写入 `~/.workbuddy/skills/legal-base/`，各法律子技能 `extends: legal-base` 自动继承，**不逐个技能重复维护**。

### 🟠 P1-1：修正「优先语义检索」

`prc-legal-research-law-search/SKILL.md:55` 改为：

> 默认走 `rh_ft_search`（关键词，5分）；仅在「不知道关键词、只有自然语言」或「关键词检索结果 < 3 条」时才用 `law_vector_search`（语义，15分）；语义结果必须 `filter(item.type===1)`。

### 🟠 P1-2：每日摄入 D 阶段降本

| 场景        | 原路径        | 优化路径                    |                 省 |
| --------- | ---------- | ----------------------- | ----------------: |
| 已有明确案由/法条 | ⑥ 语义起步（15） | ⑦ qwal / ⑧ ptal 直接命中（5） |             −10/例 |
| 仅需要旨引用    | ⑦⑧⑨ 全走（20） | ⑦ content 即官方要旨，够用即止（5） |             −15/例 |
| 需原文才下钻    | 固定走 ⑨（10）  | 仅当 ⑦ 截断 / ⑧ 缺失时才 ⑨      | 约 −7/例（按 20% 缺失率） |

按 3 例/日计，预计**日耗由 105 分降至 40 分左右**。

### 🟡 P2-1：把 `yyft` 援引法条反查纳入标准动作

`⑧ rh_ptal_search` 的 `{"yyft": ["中华人民共和国民法典第五百八十五条"], "ft_search_mode": "and"}` 是**元典独有能力**（其他 MCP 做不到），可用于：

- 校验"某判例是否真援引某法条"（`total>0` 即引用过）
- 为争议焦点快速定位实证判例

当前技能已提及但未列为标准动作，建议在「类案检索助手」「庭审准备助手」的争议焦点环节设为**默认步骤**。

### 🟡 P2-2：回写指南

把每日摄入 v1.18 的「不传 `type` 参数」实战经验回写进《元典MCP实务操作指南》，出一版 v1.1。
