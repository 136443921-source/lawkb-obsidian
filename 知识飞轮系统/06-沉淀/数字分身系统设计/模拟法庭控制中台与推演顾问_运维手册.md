## 0. 组件关系总览

```
┌─────────────────────────────┐        打开(URL/本地)        ┌──────────────────────────────┐
│   模拟法庭推演顾问 (Expert)   │ ───────────────────────────▶ │   模拟法庭控制中台 (前端)       │
│   小强律师数字分身·推演顾问    │   第一动作 present_files      │   单文件 HTML + 在线链接        │
│   AI 专家，只驱动界面不改代码  │ ◀─────────────────────────── │   红蓝对抗 / 法官心智 / 多视角   │
└─────────────────────────────┘   口述态势+推送要件卡候选       └──────────────────────────────┘
```

- **控制中台**＝可视化推演前端（你眼睛看的法庭）。
- **推演顾问**＝AI 专家，被调用时**第一动作**就是打开控制中台，然后口述红蓝态势、按阶段推法官心智、给出复盘建议。
- 两者不共享代码：专家**只读驱动界面**，不改写中台 JS（铁律，见 §4）。

## 1. 模拟法庭控制中台（Mock Trial Control Center）

### 1.1 在哪里

| 形态 | 路径 / 地址 |
|---|---|
| 本地文件 | `/Users/chenyouqiang/WorkBuddy/2026-09-05-03-33-49/mock-trial-center/index.html` |
| 在线链接 | `https://93a0d6458e084c0eb62529531a22b48c.app.workbuddy.link` |

> 本地双击即开；在线链接已部署、默认**未脱敏**，公开展示前须先脱敏当事人信息（见 §4 / DEC-005）。

### 1.2 技术形态（心里有数，改起来不慌）

- **单文件零依赖**：HTML + 内联 CSS + 内联 JS，无构建、无 npm、无外链。
- **状态存储**：浏览器 `localStorage`，键名 **`mocktrial_state_v2`**。
- **跨标签页同步**：`BroadcastChannel`（频道名 `mocktrial_sync`）——同一浏览器开两个标签页会实时互相同步。
- **法官心智案由过滤**：内存变量 `judgeDomain`（`null` = 跟随当前案件 `meta.domain`；`"全部"` = 跨域）。

### 1.3 三大面板

1. 🎬 **主控台**（顶部）：载入剧本、指派发言席位、推进庭审阶段、调节红蓝对抗优势条（±100）。
2. 🧠 **法官心智**（左侧滑入浮层）：按案由/庭审阶段过滤「审判要件卡」，向审判长推送正向裁判规则（**机器只给候选，人拍板**——铁律 R2）。
3. 👁 **视角**（透视条）：默认观察席，可随时切入 原告 / 被告 / 审判长 任意一方，其余角色淡出。

### 1.4 操作速查（一步步）

| 想做 | 操作 |
|---|---|
| 载入演示剧本 | 点「演示剧本」按钮（`btnDemo`）→ 载入内置 (2026)黔0330民初6658号 吊顶案 |
| 导入自己的案 | 点导入 → 选 JSON 文件（`importJSON`，按 §1.5 结构） |
| 导出当前推演 | 点导出（`exportJSON`）→ 下载 `mocktrial_<案号>.json` |
| 自动演进录制 | ▶ 开始 / ⏸ 暂停 / ⏹ 复位（`playStart/playPause/playReset`），速率 1x/2x/4x（`setSpeed`） |
| 重整时间轴 | 「重整时间轴」（`retime`）把 transcript 条目等距排布，便于录屏 |
| 庭审计时 | ⏱ 开始 / ⏸ 暂停（`toggleTimer`） |
| 录演示视频 | 开「录制」（`toggleRec`）→ 中台进入录制态，配合自动演进录屏 |
| 清空本场 | 「清空」（`btnReset`，会弹确认框） |
| 法官心智换域 | 点案由芯片（建设工程 / 执行异议 / 医疗损害 / 全部） |
| 运行时加卡 | 法官心智浮层粘贴 JSON 数组 → 「导入卡」（`btnJudgeImport`）即时合并 |

### 1.5 剧本数据模型（改案/建案照这个填）

控制中台状态对象 `S` 结构（来自 `DEMO` + `normalize` 默认值）：

```js
{
  meta:    { caseNo, cause, court, domain, red, blue },   // 案号/案由/法院/案由域/红方摘要/蓝方摘要
  roles:   [ {id,name,role,side,seat} ],                  // side: red=原告 / blue=被告 / neutral=中立
  stageIdx:1,                                             // 庭审阶段 0~5
  speaker: "plain",                                       // 当前发言席位 id
  advantage:5,                                            // 红蓝优势条，±100（正=红方占优）
  view:    "observer",                                    // observer/red/blue/judge
  transcript:[                                           // 推演时间轴
    {t:0,  k:"stage", stage:1, text:"▶ 进入【法庭调查】阶段"},   // 阶段标记
    {t:8,  role:"judge", type:"say", text:"……"},                // 发言
    {t:70, role:"pagent", type:"atk", text:"⚔️ 进攻：……"},        // 进攻
    {t:96, role:"dagent", type:"def", text:"🛡️ 防守：……"}         // 防守
  ],
  evidence:[ {id:"E1", name:"…", by:"plain", status:1} ],  // status 见下
  verdict: "",                                            // 评议宣判结论
  startedAt: null                                         // 计时起点时间戳
}
```

- **transcript 条目类型**：`k:"stage"`（阶段标记）+ `type:"say"|"atk"|"def"`（陈述/进攻/防守）。
- **evidence.status 枚举**：`0 未出示 / 1 已出示 / 2 已质证 / 3 已采纳 / 4 未采纳`（对应 `EVI_STATUS`）。

> 改案最小动作：复制 `DEMO`，改 `meta`（尤其 `domain` 决定法官心智默认域）、`roles`、`transcript`、`evidence`，导出 JSON 或直接改 `DEMO` 常量后刷新页面。

### 1.6 审判要件卡库（法官心智数据源）

- 数组名 **`JUDGE_CARDS`**，当前 **20 张 / 3 域**：
  - **建设工程**（8 张）：`R-JG-006/007/008/013/015/018/021/025` —— 对口 6658 吊顶案被告立场。
  - **执行异议之诉**（6 张）：`R-PR-038/039/040/041/042/045` —— 源《贵州法院类案审判要件指南》。
  - **医疗损害**（6 张）：`R-PI-240`（医疗事故罪，刑法335回源）+ `R026~R030`（民法典侵权编医疗损害责任章 1218–1228；其中 R028/R029/R030 为「派生补全·已标注」桩卡）。
- 每张卡字段含 `domain`（用于过滤）。
- 原始卡文在本地库：`~/Documents/LawKB/知识飞轮系统/06-沉淀/裁判规则库/<域>/R-*.md`（深挖某卡读原文，不凭记忆复述）。

### 1.7 中台维护任务

**A. 加一张审判要件卡**
- 方式①（持久）：在 `index.html` 的 `JUDGE_CARDS` 数组追加对象，务必带 `domain` 字段。
- 方式②（即时）：法官心智浮层粘贴 JSON 数组 → 点「导入卡」（仅本次会话生效，不落盘）。

**B. 加一个新案由域**（如买卖合同 / 股权转让，对口雅菲案 6660 / 吊顶案 6658）
- 给新卡加 `domain:"买卖合同"` 之类字段即可，芯片会自动出现新域（无需改逻辑——扩域走「加字段+过滤」，DEC-008）。

**C. 换一个案件**
- 改 `DEMO.meta`（案号/案由/`domain`）+ 相应 `transcript`/`evidence`；加载时同步 `meta.domain` 即换域推法官心智。

**D. 改完校验**
- 浏览器打开 → F12 看 Console 有无报错。
- 想离线语法预检：把 `<script>` 段单独存 `.js` 跑 `node --check`（中台本体是 HTML，`node --check` 不能直接吃 HTML）。

**E. 重新部署在线版** ⚠️
- 用 WorkBuddy `sites deploy` 覆盖**同一链接**（链接不变，沙箱 `93a0d6458e084c0eb62529531a22b48c`）。
- **重部署会刷新已分享链接，须先确认**（决策卡 DEC-010）——别本地改完顺手就刷。

### 1.8 故障排查

| 现象 | 排查 |
|---|---|
| 页面状态不刷新 / 两标签页不同步 | 清 `localStorage` 键 `mocktrial_state_v2` 后刷新；确认浏览器支持 BroadcastChannel |
| 法官心智空白 | 查 `meta.domain` 是否与卡片 `domain` 匹配；点「全部」看是否跨域有卡 |
| 导入 JSON 报「解析失败」 | 确认是合法 JSON、字段结构同 §1.5（可先导出一个再比对） |
| 优势条/计时异常 | 点「清空」重置 `S` 到 `DEMO`；检查 `advantage` 是否越界 ±100 |

4. 法官心智推演遵守 **R2**：只推送候选裁判规则，最终裁判走向由你（人类）拍板。

## 4. 三条铁律（来自搭建决策卡，务必遵守）

1. **演示 ≠ 代理**（DEC-20260905-005）：控制中台能推法官心智，≠ 替当事人出策略。含当事人隐私须脱敏 / 限内网，公开展示前先脱敏。
2. **覆盖式重发先问**（DEC-20260905-010）：本地改了别顺手刷新线上，会刷掉已分享链接，须先确认。
3. **法条不编造**（DEC-20260905-003 / 007）：法官心智卡内容以 LawKB 本地库为准；R028/R029/R030 为「派生补全·已标注」桩卡，深挖须回源民法典 1218–1228，不当成权威法条直接用。
