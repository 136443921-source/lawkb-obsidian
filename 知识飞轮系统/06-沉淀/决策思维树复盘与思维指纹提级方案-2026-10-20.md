# 决策思维树复盘 · 思维指纹提级方案

> **一句话结论**：决策思维树"建得成、看得见、但用不上"——**三处断点**让思维指纹卡在最后一公里：
> ① 30/35 张决策卡缺 `domain` 字段 → 分层指纹从未切出；
> ② 35 张卡 `verdict` 全部停在「待验证」（0 张已判定）→ 指纹无法自我校准；
> ③ 铁律 8「决策层检索」按 domain 检索，实际只有 5 张卡可被命中（办案 2 / 诉讼策略 1 / 职业发展 1 / 律师实务 1），且 `证据取舍`·`客户沟通`·`个人成长` 三个域**零覆盖**。

**本文所有数字均为 2026-10-20 实地读取磁盘实读所得，非文档描述转述。**

## 二、三处断点（按危害排序）

### 断点 ① 　30/35 张卡缺 `domain` → 分层指纹从未生成

**设计意图**（决策树「办案思维指纹的回流路径」节点原文）：
> domain=办案 的卡 → 蒸馏时单独切出「办案思维指纹」→ 喂给 lawyer 分身。
> 这是加 domain 维度的全部意义：让同一套决策日志能按用途分层产出。

**实测**：35 张卡里只有 5 张有 domain。这条"全部意义"目前**几乎不成立**——
所谓"办案思维指纹"实际只由 2 张卡支撑（吊顶案 + 雅菲案），样本量远低于 mind-distill 自身规定的
「≥10 升规律」门槛。

**复发风险**：`decision-capture` 虽在 SKILL.md 行 90 强制要求 domain 枚举，
但 `04-LOG/决策日志/` 中的历史卡与 `DEC-2026-*` 系思维轨迹卡**并非全部经由 decision-capture 建成**，
存在多入口漏填。**新建卡不漏，不代表存量不漏。**

### 断点 ② 　0 张已判定 → 指纹无法自我校准

四档判定体系（待验证 / 对了 / 错了 / **结论对但理由错**）是这套系统的校准闭环：
只有卡被判过，蒸馏才能区分"哪些启发式真的有效"。

**实测**：14 张「待验证」+ 21 张无 verdict 字段，**「对了」「错了」「结论对但理由错」三档合计 0 张**。
4 张有 `review_date` 的卡到期日均为 **2026-12-02/12-04/12-16**（尚在 42 天后），
故**不是逾期未回填，而是"到期前零判定"**——没有任何一张卡在到期前被提前判定。

**后果**：
- 月报「命中率」分母恒为 0 → 自动化已内置此分支（写「暂无已判定样本」），但**该指标永久无法产出**；
- 「AI 异议成真率」是本系统独有指标（铁律：异议成真但结果赢 → 判「结论对但理由错」），
  **无判定即无异议验证**——雅菲案那 3 条被驳回的异议至今悬空；
- HOW-I-THINK 里的 H1–H15 全部停留在"规律级"标签，**没有任何一条被证伪或坐实的记录**。

### 断点 ③ 　铁律 8 检索口径与实际卡片结构错配

铁律 8 原文（`lawyer-yourself-skill/SKILL.md` 行 864+）：
> 遇到「要不要这么办 / 选 A 还是选 B」类岔路口问题，先检索 `04-LOG/决策日志/` 下
> **同 domain（办案/诉讼策略/证据取舍/客户沟通/职业发展/个人成长）**的决策卡，
> 看有无**已验证的思维指纹**。

**两个失配**：
1. **口径失配**：按 domain 检索只能命中 5 张，且 3 个域零覆盖。检索式形同虚设。
2. **判定失配**：铁律要求"已验证的思维指纹"，但已验证 = 0 张。
   → **即便正确执行铁律 8，也必然返回空集，然后跳过决策层，退回通用答案。**

**配套快照过期**：`legal-consult-router/SKILL.md` 行 87-89 仍写着
「实测快照（2026-09-10）：maturity 观察级(部分填充·2卡样本)」「H1–H12」。
实际已更新为**规律级·34 卡·H1–H15**（2026-09-28）。
该技能同时写着"此判断已发生过一次错误"——**同一个坑复发第二次**。

## 三、思维指纹提级方案（按 ROI 排序）

### P0-1　domain 补全 + frontmatter 门禁　★ 最高 ROI

**做什么**：
1. 对 30 张缺 domain 的卡**按内容实读补标**（不是按文件名猜）——依据 `scope`/`tags`/正文议题归入六域，
   非法值 `律师实务` 归一到 `诉讼策略`；
2. 在 `decision-capture` 之外加一道**落盘后校验**：任一新建决策卡若缺 `domain` 或 `verdict` 字段，
   写入即报错并要求补齐。

**为什么第一**：这是唯一能解锁"分层指纹"的开关，且是**纯数据修复、零架构改动**。
补完后 `办案` 域从 2 张升至（预估）12+ 张，才够得上 mind-distill 的「≥10 升规律」门槛。

**验收**：35/35 张卡有合法 domain；六域无零覆盖。

### P0-2　提前判定机制　★ 让指纹能自我校准

**做什么**：把"到期复盘"改为**"事件触发复盘"**——
- 6658 案判决书已到（`决策卡-6658判决书拆解…20261009` 已在库）→ 立即可判；
- 雅菲案原告已申请撤诉 → 程序走向已明 → 立即可判；
- 吊顶案 34 号已推翻实体主攻版 → 已有可判结果。

**核心原则**：**复盘是"看结果"的动作，判决/撤诉/落定就是结果，不必等 12-02 的日历闹钟。**
当前 4 张卡的 review_date 全设 2026-12-02+，是把"日历驱动"当成了唯一触发器——
这与 HOW-I-THINK 第 1 节第 3 条自己写的
「靠日历而非等对方/法院明确表态——沉默即表态，看日历就该转」**在方法论上自相矛盾**：
系统自己倡导"不等表态"，却把自己的复盘设成了"等到 12 月才表态"。

**为什么第二**：这是唯一能让「命中率」「AI 异议成真率」两个核心指标产生活跃值的动作。

**验收**：至少 3 张卡完成四档判定；「结论对但理由错」档位首次有样本。

### P1-1　铁律 8 检索口径改造　★ 让接线真正生效

**做什么**：
1. 检索式从"同 domain"扩展为 **domain + tags + 正文关键词 三路并联**（domain 补全前也能命中）；
2. 铁律中"看有无**已验证**的思维指纹"改为"**已验证者优先，待验证者标注未定论**"——
   与 `decision-capture` 行 78 的既有口径（「同 domain 尚有 N 张未复盘，参考价值有限」）保持一致；
3. 命中"结论对但理由错"时强制连同纠正引用（此条铁律原文已写好，保留）。

### P1-2　快照治理　★ 防止同一个坑第三次复发

**做什么**：
1. 修正 `legal-consult-router` 行 87-89 的过期快照 → 更新为「规律级·34 卡·H1–H15·2026-09-28」；
2. 修正 `lawyer-yourself-skill` 行 866「尚为骨架（六区空白）」→ 改为实读指令（该技能已有"必须实读"规则，
   但**行 866 自身的硬编码状态与之矛盾**）；
3. 立一条中枢规则：**任何"某文件处于什么状态"的断言，必须带读取时间戳，且状态变更时同步回改快照位置**——
   这是老强已在用户级记忆里立的「否定型结论铁律」在系统内的具体落法。

### P2-1　mind-distill 自动化排程

新建自动化：每月 1 号月报跑完后触发 mind-distill 蒸馏（先出建议、不自动写入，遵守
"先给建议、后写入，思维权重文件只能老强批"的原有约束）。

### P2-2　决策效率增强：岔路口速查卡

**这是"提升决策效率"的直接抓手**。当前每次遇到岔路口，要人工回忆：
- 有哪些真选项？
- 上次同类岔路口我怎么选的、为什么排除其他？
- 什么信号会推翻？

建议产出一张 **《岔路口速查卡》**（一页 A4，挂在决策树总览旁），
由 HOW-I-THINK 第 1/2 节 + 已判定卡自动生成，实测字段：
`触发场景 → 起手式 → 排除理由模板 → 推翻信号模板 → 盲区提示 → 引用卡`。
让"用老强的框架起手"从**要读 17KB 权重文件**变成**看一眼速查卡**。
