# 类案检索报告卡·判例摘要模板（基于「案例入库模板」扩展）

> 本模板由 `02-提炼/案例摘要/案例入库模板.md` 扩展而来，新增「案号 / 审级 / 争议焦点 / 裁判要旨 / 类比要点」五要素，供类案检索助手产出沉淀为结构化判例摘要卡。
> 落点：`06-沉淀/类案检索报告卡族/`，命名 `LC-{序号}-{案号简述}-{核心标签}.md`。

## 一、Frontmatter 规范（纯文本，禁止 `双向链接`）

```yaml
---
title: LC-XXX （案号） 核心标签
card_id: LC-XXX
card_family: 类案检索报告
card_type: 判例摘要
retrieval_case: （关联待决案案号）案由
retrieval_date: YYYY-MM-DD
data_source: 华宇元典 / 北大法宝 / 中国裁判文书网（注明核验方式）
source_url: 案例原文链接
case_no: （案号）
trial_level: 一审/二审/再审（审级·法院层级）
court: 审理法院
cause: 案由
tags: [类案检索, 核心标签, 援引法条]
created: YYYY-MM-DD
updated: YYYY-MM-DD
related_links: [消费方1, 消费方2]   # 纯文本标识，链接放正文
---
```

## 二、正文五要素（必填）

1. **案号** —— 完整标准案号。
2. **审级** —— 审级 + 法院 + 裁判日期 + 文书种类 + 审判程序 + 案由 + 当事人。
3. **争议焦点** —— 法院归纳的 1-3 个争点（原样摘录）。
4. **裁判要旨** —— 「本院认为」核心论述 + 裁判结果 + 援引法条（含条号与现行有效性核验）。
5. **类比要点** —— 与关联待决案的映射：同源前提 / 堵截路径 / 法条衔接 / 裁判倾向，并显式指向消费方（模拟法庭、代理词）。

## 三、质量红线（LTI 前置）

- 法条须权威源回填（元典/法宝核验），禁止凭记忆裸引；
- 裁判要旨须摘录自「本院认为」或裁判要旨原文，不得曲解；
- 类比要点须具体可落到待决案防御点，不得空泛；
- frontmatter 禁止 Obsidian 双链（坑18），链接一律放正文 `[[...]]`。
