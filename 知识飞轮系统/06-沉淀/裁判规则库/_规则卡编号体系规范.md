# 规则卡编号体系规范 v1.0.0

> **制定背景**：2026-08-28 知识健康度盘点发现规则卡引用存在四类失配（裸号引用带描述文件、补零不一致、作废号残留、设计稿臆想域代码）。本规范固化编号口径，杜绝再次漂移。
> **适用范围**：`知识飞轮系统/06-沉淀/裁判规则库/` 全部规则卡，及所有引用规则卡的笔记、技能、自动化。

---

## 一、编号格式（强制）

```
R-<域代码>-<三位序号>[-<简述>]
```

| 组成 | 规则 | 示例 |
|---|---|---|
| 前缀 | 固定 `R-` | `R-` |
| 域代码 | 2 位大写字母，**只能取自第二节白名单** | `HT` |
| 序号 | **必须三位补零**，域内唯一、连续递增 | `109`（不写 `9`/`09`） |
| 简述 | 可选，≤ 20 字，不含日期、不含标点 | `约定违约金过高按LPR1.5倍调整` |

**唯一标识以 frontmatter `rule_id` 为准**，文件名仅为可读别名。引用与检索一律以 `rule_id` 对齐。

## 三、命名双风格并存（现状承认，不批量改名）

实测 573 张卡分两种风格：

| 风格 | 数量 | 形态 | 处置 |
|---|---|---|---|
| 裸号式 | 424（74%） | `R-CF-001.md` | **保留**，描述在 frontmatter |
| 带描述式 | 149（26%） | `R-HT-109-约定违约金过高按LPR1.5倍调整.md` | **保留** |

**🔴 明令禁止批量改名统一**：424 个文件改名将导致数千条 wiki 链接瞬间失效——这正是 2026-08-28 花大力气修复的问题（改名锈蚀）。

**向前统一规则**：
- 新建卡一律采用**带描述式**（可读性优先）
- 旧裸号卡不动，仅在 frontmatter 补 `title` 与 `aliases`
- 引用时优先写 `rule_id`（`R-HT-109`），并用别名管道给出可读名：`[[R-HT-109-约定违约金过高按LPR1.5倍调整|R-HT-109 违约金LPR1.5倍]]`

> **正解（取代预分配）**：
> 1. **不为未来类案预分配固定号段**，排期表只登记「类案 / 张数 / 落盘目录 / 日期」，号段列标注「**拆卡当日实地取号**」；
> 2. 拆卡当日按「三查」确定起始号后**一次性连续取满本批**（建卡过程不再中断，避免中途被抢占）；
> 3. 号段之间允许空洞（同 PR-021 与 HT 132~150 先例），空洞不视为缺口、不复用。
> **本批实证**：HT 域一小时内从 max=131 → 178（本批 28 张）→ 185（摄入流水线 7 张）。
>
> **🔴 补充铁律（2026-09-04 商品房买卖踩坑新增）：查号要查「两个维度 + 排期表」**
> 1. 已落地卡的**文件名**：`find . -name "R-<域>-*.md"`；
> 2. 已落地卡的 **frontmatter `rule_id`**（只查文件名会漏掉「文件名不动、只改 rule_id」的卡）；
> 3. **排期表的预留号段**（`02-提炼/审判要件卡/审判要件卡-拆卡排期表-2026-09.md`）——**必须查**！

> **实证教训**：2026-09-04 拆商品房买卖时，只做了第 1、2 步并确认 151+ 全域空闲，但**漏查第 3 步**——排期表 12:45 已把商品房改为 132~156、保险改为 157~177，导致实际落号 151~178 **撞上给保险预留的 157~177**。最终按「已落地卡禁止批量改名」+「取号以物理事实为准」处置：承认 151~178。（**注：当时给出的「保险顺延 179~199」已在 13:55 废止**，见上条红色警示——该段 20 分钟内即被摄入流水线抢占 179~185。）

## 八、卡型登记：审判要件卡（2026-09-03 新增）

> 本节登记继「要件映射卡」之后的**第二种卡片语义类型**。二者**物理隔离、双轨并行**。

| 维度 | 要件映射卡（已有） | **审判要件卡（本次新增）** |
|------|------------------|---------------------------|
| frontmatter 标识 | 无 `card_type` | **`card_type: 审判要件卡`**（强制） |
| 回答的问题 | 「引用错了吗？」 | **「该怎么判？」** |
| 推理方向 | **负向拦截**（涵摄断裂检测） | **正向裁判**（审理思路→裁判结论） |
| 触发时机 | 文书生成**后**校验 | 庭审推演**中**引导推理 |
| 消费方 | LTI 文本监控器（闸门） | **模拟法庭 `judge_reviewer`（法官心智）** |
| 特有字段 | `elements` / `negative_note` | `review_step` / `ruling.support` / `ruling.reject` / `burden_of_proof` / `geo_scope` |

**建卡检查清单（审判要件卡专用，第六节之外的附加项）**：

- [ ] `card_type: 审判要件卡` 已写入 frontmatter
- [ ] `ruling.support` 与 `ruling.reject` **双双非空**（正向裁判规则的核心，缺一即不合格）
- [ ] `review_step` 标注审理环节（原告诉请审查 / 被告抗辩审查 / 争议裁判规则）
- [ ] `geo_scope` 标注地域效力
- [ ] 法条正文已从本地权威源或北大法宝/元典**回填并标注来源**，卡内不凭记忆撰写条文字句
- [ ] 正文含「裁判规则 / 审查要点 / 构成要件与举证 / 法条依据 / 抗辩与但书 / 翻车标本 / 来源与地域效力 / 关联」八段
