# 规则卡编号体系规范 v1.0.0

> **制定背景**：2026-08-28 知识健康度盘点发现规则卡引用存在四类失配（裸号引用带描述文件、补零不一致、作废号残留、设计稿臆想域代码）。本规范固化编号口径，杜绝再次漂移。
> **适用范围**：`知识飞轮系统/06-沉淀/裁判规则库/` 全部规则卡，及所有引用规则卡的笔记、技能、自动化。

## 一、编号格式（强制）

```
R-<域代码>-<三位序号>[-<简述>]
```

| 组成 | 规则 | 示例 |
|---|---|---|
| 前缀 | 固定 `R-` | `R-` |
| 域代码 | 2 位大写字母，**只能取自第二节白名单** | `HT` |
| 序号 | **必须三位补零**，域内唯一、连续递增 | `109`（不写 `9`/`09`） |
| 简述 | 可选，≤ 20 字，不含日期、不含标点 | `约定违约金过高按LPR1.5倍调整` |

**唯一标识以 frontmatter `rule_id` 为准**，文件名仅为可读别名。引用与检索一律以 `rule_id` 对齐。

## 三、命名双风格并存（现状承认，不批量改名）

实测 573 张卡分两种风格：

| 风格 | 数量 | 形态 | 处置 |
|---|---|---|---|
| 裸号式 | 424（74%） | `R-CF-001.md` | **保留**，描述在 frontmatter |
| 带描述式 | 149（26%） | `R-HT-109-约定违约金过高按LPR1.5倍调整.md` | **保留** |

**🔴 明令禁止批量改名统一**：424 个文件改名将导致数千条 wiki 链接瞬间失效——这正是 2026-08-28 花大力气修复的问题（改名锈蚀）。

**向前统一规则**：
- 新建卡一律采用**带描述式**（可读性优先）
- 旧裸号卡不动，仅在 frontmatter 补 `title` 与 `aliases`
- 引用时优先写 `rule_id`（`R-HT-109`），并用别名管道给出可读名：`[[R-HT-109-约定违约金过高按LPR1.5倍调整|R-HT-109 违约金LPR1.5倍]]`

## 八、卡型登记：审判要件卡（2026-09-03 新增）

> 本节登记继「要件映射卡」之后的**第二种卡片语义类型**。二者**物理隔离、双轨并行**。

| 维度 | 要件映射卡（已有） | **审判要件卡（本次新增）** |
|------|------------------|---------------------------|
| frontmatter 标识 | 无 `card_type` | **`card_type: 审判要件卡`**（强制） |
| 回答的问题 | 「引用错了吗？」 | **「该怎么判？」** |
| 推理方向 | **负向拦截**（涵摄断裂检测） | **正向裁判**（审理思路→裁判结论） |
| 触发时机 | 文书生成**后**校验 | 庭审推演**中**引导推理 |
| 消费方 | LTI 文本监控器（闸门） | **模拟法庭 `judge_reviewer`（法官心智）** |
| 特有字段 | `elements` / `negative_note` | `review_step` / `ruling.support` / `ruling.reject` / `burden_of_proof` / `geo_scope` |

**建卡检查清单（审判要件卡专用，第六节之外的附加项）**：

- [ ] `card_type: 审判要件卡` 已写入 frontmatter
- [ ] `ruling.support` 与 `ruling.reject` **双双非空**（正向裁判规则的核心，缺一即不合格）
- [ ] `review_step` 标注审理环节（原告诉请审查 / 被告抗辩审查 / 争议裁判规则）

## 九、卡型登记：案由路由卡（2026-09-06 新增）

> 本节登记继「要件映射卡」「审判要件卡」之后的**第三种卡片语义类型**。三者**物理隔离、三轨并行**。

| 维度 | 要件映射卡 | 审判要件卡 | **案由路由卡（本次新增）** |
|---|---|---|---|
| frontmatter 标识 | 无 `card_type` | `card_type: 审判要件卡` | **`card_type: 案由路由卡`** |
| 回答的问题 | 「引用错了吗？」 | 「该怎么判？」 | **「该定什么案由？」** |
| 推理方向 | 负向拦截 | 正向裁判 | **横向路由**（定性＋管辖＋请求权基础定位） |
| 触发时机 | 文书生成**后**校验 | 庭审推演**中** | **立案 / 答辩 / 管辖异议 / 案由变更之争** |
| 消费方 | LTI 文本监控器 | 模拟法庭法官心智 | **数字分身调用层 · 立案定性 · 管辖异议** |
| 落盘目录 | — | 按领域目录 | **`裁判规则库/案由路由/`** |
| 域码 | 各域 | 各域 | **专用 `AY`** |

**子类型**

- **单案由路由卡**：一案由一卡
- **定性分野卡**（`card_subtype: 定性分野卡`）：易混案由**横向对比**一卡（如 R-AY-001 买卖／承揽／装饰装修）

**特有字段（强制）**

- **版本校正四件套**：`code_2020` / `code_2025` / `version_status` / `version_delta`
- `jingxia`（管辖）／`request_base`（请求权基础）／`confusable`（易混案由）／`linked_cards`（下游裁判规则卡）

### 9.1 定性分野卡专项建卡细则（2026-09-07 新增）

> **定性分野卡的产出不是「几个案由各是什么」，而是「凭什么分、分完有什么后果、反过来呢」。**
> 只罗列释义的分野卡＝多张单案由卡的拼接，**不合格**。
> **完整 SOP**：`03-连接/概念页/定性分野卡-建卡SOP-v1.0.md`（八步建造流程 + 模板 + 验收清单 + 五种伪形态自查表）

**① 立项三问（不过则不许挂 `card_subtype: 定性分野卡`）**

| # | 门槛 | 不通过的处置 |
|---|---|---|
| Q1 | 同一事实能否被两种定性同时涵摄？ | 放弃（那叫不相干，不叫易混） |
| Q2 | 定性不同结果是否实质不同（管辖/举证/期间/请求权基础/费用/检索六项至少一项）？ | 放弃（定性无实益） |
| Q3 | 有无权威源给出的明确区分标准？ | **降级为单案由路由卡**——硬编标准＝自造裁判规则，违反防幻觉铁律 |

**② 新增三个强制字段（定性分野卡专用，缺一不得标注本子类型）**

- `discriminator`：一句话区分标准
- `discriminator_source`：原文出处（书名 + 页码）
- `counter_case`：反向推论（反例）

> 🔴 **验收硬指标：无 `counter_case`，视为没吃透，退回重做。**

**③ 鉴别器三层展开（强制）**：原文照录 → 教义学拆解（换成判定结构） → **反向推论**。缺第三层不合格。

**④ 决策树每条路径必须唯一出口**；出现「或定 A 或定 B」说明鉴别器没抠干净。

**⑤ 强制双说理**：凡「最高院释义口径 vs 司法解释文义」有缝隙的，须同时给攻方说理与守方说理，明写「须备两套说理，不可只押一头」。

**⑥ 现存量体检结论（2026-09-07）**：四张 AY 卡中**仅 R-AY-001 为真·定性分野卡**（范式参照）；**R-AY-002 / R-AY-004 实为单案由路由卡**，须更正 `card_subtype` 或补对比成员；R-AY-003 待复核是否具备 `counter_case`。
