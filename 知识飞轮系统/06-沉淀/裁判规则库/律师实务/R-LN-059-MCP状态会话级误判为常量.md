# 会话级状态 ≠ 项目级常量：MCP 通道结论不带时间戳且交付后未复测的事故教训

> **卡型**：工程事故卡（AI 协作·法条回填通道）｜**编号**：`R-LN-059`｜**建卡日期**：2026-09-07
> **事故等级**：P1（法条**正文 0 处错误**，但 **2 处推断性表述臆断**入库，并扩散至 6 份挂载文件 + 2 张卡）
> **一句话**：**「此刻不可用」不等于「一直不可用」。** 把一次会话级的通道状态写成不带时间戳的永久结论，等于给自己签了一张**免复核许可证**——而这恰恰是幻觉最爱走的门。

## 一、事故概述（发生了什么）

2026-09-07 拆《贵州法院类案审判要件指南（第二卷）》第五部分·婚姻家庭纠纷（52 张卡，R-HY-004~055）。建卡需回填法条正文，按铁律须走权威源。

**09:00 建卡时**：`ToolSearch` 查 `mcp__yuandian-mcp__yuandian_law_vector_search` 与 `mcp__pkulaw__mcp-law-search-service.get_article` 均报「not found in the deferred tools index」，`connector-states.json` 却显示 `pkulaw: enabled=True`、`yuandian-mcp: enabled=True`。据此判定「**本会话元典/法宝 MCP 未注册进工具表**」，**降级**走权威公开源（court.gov.cn / gov.cn / 本地法律法规库）核填 9 部 165 条，标注写「权威源核填」，并**在总索引、编号规范、可用性登记、消费方、04-LOG、入库索引六处同步登记了该结论**。

**09:58（老强追问后复测）**：两个 MCP **全部可用**——

| 通道 | 工具 | 复测结果 |
|---|---|---|
| 华宇元典 | `mcp__yuandian-mcp__yuandian_law_vector_search` | ✅ 成功，返回解释（二）第八条原文 + `sxx: 现行有效` |
| 华宇元典 | `mcp__yuandian-mcp__yuandian_rh_ft_search` | ✅ 成功，返回条号/正文/时效性/文号 |
| 北大法宝 | `mcp__pkulaw__mcp-law-search-service.get_article` | ✅ 成功，返回解释（二）第八条原文 |

**双源一致性实证**：解释（二）第八条，元典（fgid `98f3ac4b2742a37d93be2f4275b79b63`）与法宝（gid `81b6f4dd98c49ed7bdfb`）返回正文**逐字一致**。

**根因一句话**：09:00 的「不可用」是**会话级瞬时状态**，我却把它当成**项目级常量**写进六份文件，且**交付校验（ERROR 0 / WARN 0）通过后没有再测一次通道**——于是整批带着「未复核的公开源条文 + 2 处臆断表述」完成入库。

## 二、根因分析（三层，逐层往下挖）

**第一层·直接原因**：判定结论**不带时间戳**，表述为「本会话不可用」而非「2026-09-07 09:00 实测不可用」。
→ 「本会话」在写下的那一刻是准确的，但**文件是跨会话长期存在的**。读文件的人（包括 58 分钟后的我自己）会把它读成永久结论。

**第二层·流程缺陷（真正致命的一层）**：**交付校验 ≠ 交付合格**。
校验器只查卡片**内部**一致性（YAML、字段、八段、法条块来源、死链），**不查外部通道是否已恢复**。ERROR 0 / WARN 0 给了我虚假的安心感，于是**跳过了「交付前再测通道」这一步**。

**第三层·认知盲区（最隐蔽的一层）**：**强判断表述不受校验器约束**。
校验器 E9 只校验**法条块内**的来源标注与效力状态；而「已被取代」「不适用某规则」「撤销后无须补偿」这类**推断性表述写在正文、翻车标本、negative_note 里，不在法条块内**——**E9 完全看不见**。这类表述只能靠**回源复核人工逐字比对**才能拦住。

## 三、误判传导链（错一步如何滚成一串）

```
① 09:00 ToolSearch 查不到 → 判「MCP 未注册进工具表」
      ↓ 结论不带时间戳，写成「本会话不可用」（实为 58 分钟的瞬时状态）
② 降级走权威公开源核填 9 部 165 条
      ↓ 公开源能看到正文，看不到「条与条之间的适用关系」
③ 凭语感拼出 2 处法理推断（见第四节），写进正文 + 翻车标本 + negative_note
      ↓ 不在法条块内 → E9 校验器盲区
④ 交付校验 ERROR 0 / WARN 0 → 误以为合格
      ↓ 未再测通道
⑤ 结论同步进总索引 / 编号规范 / 可用性登记 / 消费方 / LOG / 入库索引 六处
      ↓ 臆断表述随六处挂载扩散
⑥ 09:58 老强追问 → 复测发现通道已恢复 → 回源复核 → 2 处臆断暴露
```

**关键**：链条上**每一步单看都合理**，且**没有任何一步报错**。静默失败的可怕之处正在于此。

**两处臆断的具体内容**：

| # | 原表述 | 权威源核对 | 为什么危险 |
|---|---|---|---|
| 1 | 「解释一§29② **已被解释二§8 取代**」 | 元典标解释一§29② **仍「现行有效」**（法释〔2020〕22号，2021-01-01 施行） | 混淆**效力状态**与**适用顺位**。准确表述应为「**仍现行有效，但裁判口径已由后法特别规则解释二§8 重构**（后法特别规则优先）」。→ 若照原表述写进代理词，对方一句「该条现行有效、元典可查」就会当庭打脸 |
| 2 | 「解释二§5③ **撤销后无须补偿**」 | **该款原文根本没有这句话**。第三款仅规定**法定四类撤销事由**（欺诈／胁迫／严重侵害给予方或其近亲属合法权益／有扶养义务而不履行） | **纯属推断**。读起来很专业，条文里一个字没有。→ 会作为「裁判规则」进模拟法庭法官的推理链，误导方向 |

**共同特征**：两条都是**「看起来很专业」的顺出来的结论**，凭语感读条文极易写出，**只有逐字核原文才能拦住**。

## 五、正确做法（SOP：通道状态三铁律，不许跳步）

**铁律一 · 结论必须带时间戳**
- ✅ 写「2026-09-07 **09:00 实测**不可用」
- ❌ 不写「本会话不可用」「MCP 不可用」
- 理由：文件跨会话长期存在，读者会把「此刻」读成「永远」。

**铁律二 · 交付校验后必须再测一次通道**
1. 全部卡片渲染完成、交付校验（ERROR 0 / WARN 0）通过之后；
2. `ToolSearch` 用**完整限定名**重新查一次（`mcp__yuandian-mcp__…`、`mcp__pkulaw__mcp-law-search-service.get_article`）；
3. **真调用一次**（查到 ≠ 能用，必须拿到返回内容）；
4. 恢复 → **立即回源复核**；仍不可用 → 在结论里补记第二次实测时间。

**铁律三 · 回源复核据实登记覆盖比例，不回溯虚标**
- 已核 72 / 165 → 就写 72；**未核 93 条如实标注，维持「权威源核填」**；
- 只有**实际逐条核过**的部，才把 `权威源核填` 升级为 `华宇元典核填 + 北大法宝核填`（并附 fgid / gid）；
- **严禁**：通道一恢复就把整批改成「元典核填」——那是另一种形式的虚标。

**复核优先序**（时间有限时按此顺序）：
1. **新法 / 新司法解释**（本批＝解释二，2025-02-01 施行）；
2. 卡内写了「**已被取代 / 已废止 / 不适用 X 规则 / 撤销后无须 Y**」这类**强判断**的条 ← **最危险，优先核**；
3. 其余。

**判定「MCP 不可用」的完整流程**：见 [[R-LN-055-工具调用失败不等于服务不可用的MCP误判事故教训]] 第五节（六步，不许跳步）。本卡是它的**进阶补丁**——R-LN-055 解决「查不到 ≠ 不存在」，本卡解决「此刻不存在 ≠ 永远不存在」。

## 六、翻车标本（负向拦截·同类错误清单）

1. ❌ 「本会话 MCP 不可用」→ ✅ 「2026-09-07 09:00 实测不可用」
2. ❌ 交付校验 ERROR 0 就认为万事大吉 → ✅ ERROR 0 之后**再测一次外部通道**
3. ❌ 通道恢复后整批回溯改成「元典核填」→ ✅ **只升级实际核过的**，未核的如实标注
4. ❌ 认为「校验器通过 = 没问题」→ ✅ 校验器看不见**法条块外的推断性表述**，那是盲区
5. ❌ 「已被取代」「不适用某规则」这类强判断凭语感写 → ✅ 必须逐字核原文；**没有原文支撑就删**
6. ❌ 一次判定管到底 → ✅ 长任务中途**至少复测两次**（建卡前 + 交付前）
7. ❌ **拿 frontmatter `title` 当文件名写链接** → ✅ **`ls <目录> | grep "^R-<域>-<号>"` 复制真实名**，再跑死链自检脚本
