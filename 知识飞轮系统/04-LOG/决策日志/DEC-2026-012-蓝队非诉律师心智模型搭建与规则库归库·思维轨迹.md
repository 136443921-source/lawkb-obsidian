# DEC-2026-012 · 蓝队非诉律师心智模型搭建与规则库归库·思维轨迹

> 记录 2026-09-15，一场「把 `蓝队律师合同审查` 技能升格为 🔵蓝队非诉律师独立心智模型」的八节点演进链：
> 消歧前置 → 家底实测 → 定位翻转 → 活文档化 → 自查纠错 → 撞号归库 → 口径自证 → 事故沉淀。
> 每个节点遵循决策档案契约：**决策点 / 考虑了什么 / 否决了什么 / 推翻信号 / 落点**。
> 本卡是 **RULE-TRAINING-WRITEBACK** 在「非诉席位」上的应用样例，补齐 PROJ-007 之外缺失的 DEC 件套。

## 背景触发

老强要求：**"蓝队非诉律师心智模型搭建，利用现在的蓝队合同律师基座进行，主要从事合同审查、慈善合规系统建设、医院合规系统建设、运营和监督，主导小德合规管理系统运维。"**
随后连续追加四条指令：① 与蓝队诉讼律师**严格区分并记入记忆铁律**；② 建**活文档**备忘录存中枢、一训练即回写；③ **现在开工归库**；④ **有事故必沉淀成卡**；⑤ 把本次对话沉淀为思维轨迹卡。

实质命题：**如何把一个"只会审合同的工具型技能"造成"能主导合规系统建设与运维的独立心智模型"，且全程不制造数据漂移。**

## 思维轨迹（决策演进链）

### 节点 1 · 消歧前置：先钉死「🔵非诉 ≠ 🔵诉讼」，再谈搭建

- **决策点**：把四席消歧写成**三层**（跨项目 `~/.workbuddy/MEMORY.md` + 工作区 MEMORY + 中枢 `RULE-BLUE-DISAMBIG`），再动手做方案。
- **考虑了什么**：家族内已有 🔵诉讼律师（PROJ-001·谈案出庭）、🔵-A 助理（PROJ-003·共享后台）、🔴对抗律师（PROJ-004·攻方）；本席 PROJ-007 是**合同/交易/合规建设**。列四席对照表，并加七条硬约束（禁混称必带后缀、禁互套评分、禁把助理供料计战绩等）。
- **否决了什么**：**否决"复用既有蓝队出庭律师心智模型改改"** —— 职责域根本不同（非诉出意见/建制度 vs 诉讼念给法官听），混用会导致评分串台（后续果然在技能里抓到"七维评分卡"串台，非诉应为五维 D1–D5）；否决"只在工作区记一笔"——换设备/换会话即失忆。
- **推翻信号**：老强要求合并"蓝队总分"或四席职责重划 → 本边界降级，须重划家族接口。
- **落点**：三层消歧铁律；中枢 `RULE-BLUE-DISAMBIG` 详细版 SSOT 指针改指向 PROJ-007。

### 节点 2 · 家底实测先行：拒绝凭印象写方案

- **决策点**：写方案前**全量实测**（技能行数/卡库/规则库/CMS 母本），拿到真数再落笔。
- **考虑了什么**：实测抓到 3 处漂移——规则库非 147 条而是**散落 45 个 expansion json**；技能 803 行非 712；卡库"合同合规 0 张"实为 **7 张**，且新发现 `非诉合规` 6 张、CMS治理 1 张。
- **否决了什么**：否决"按中枢旧记载（147 条 / 0 张）直接写方案"——会产出一份建立在错数上的路线图。
- **推翻信号**：无（本节点是纪律而非判断，恒有效）。
- **落点**：`蓝队非诉律师-心智模型搭建方案-v1.0.md`（四支柱 + L2 五步算法 + D1–D5 + P0/P1/P2 路线图）。

### 节点 3 · 定位翻转：P0 第一刀是「归库」不是「造弹药」

- **决策点**：把路线图主攻方向从"补充弹药"翻转为"**建立单一真源 + 加载器**"。
- **考虑了什么**：弹药实测极厚（2447 条口径下散 45 个文件），但**主库可加载率极低**——缺的不是规则，是"能不能被技能读到"。
- **否决了什么**：否决"新建规则库 / 扩写弹药"路线——造再多弹药，没有真源和加载器一样读不到。
- **推翻信号**：**本节点判断已被部分推翻**——"可加载率 0.4%"这个支撑数本身是错的（见节点 6，主库实为 729 条）。**但结论仍成立**（归库确是第一刀），属"错论据推出对结论"，已在节点 6 纠正并存档。
- **落点**：方案 v1.0 的 P0 项。

### 节点 4 · 活文档化：SSOT + 追踪脚本，让「一训练即回写」可执行

- **决策点**：中枢 `PROJ-007` 为**单一事实源（活文档）**，配 `_common/scripts/blue_nonlit_maturity.py` 自动刷新 MATURITY / TRAINLOG 双区块。
- **考虑了什么**：复用 PROJ-005 已验证范式（自动区块 + 追踪脚本 + 幂等）；脚本扫 3 个调用记录目录，按「日期+事项」去重；写前 `cp` 备份；技能 §训练与回写 内挂刷新命令 + **四通道**（本卡 / CMS 母本 / 经验卡 / 工作日志）。
- **否决了什么**：否决"只写静态备忘录"——下一场训练即漂移，等于没写；否决"手改脚本产出物"（对照既有铁律：手改 `mind_panels_data.js` 会被脚本覆盖）。
- **推翻信号**：脚本改路径 / 改字段名 → 自动区块定位失效，须同步改脚本与卡内锚点。
- **落点**：`PROJ-007-蓝队非诉律师训练项目状态.md`（v1.0，十二章）+ `blue_nonlit_maturity.py`（幂等已验：连跑两次分数不变、记录不叠加）。

### 节点 5 · 自查纠错：Bash `grep` 误报致「L1/L2/L6 三块为 0」误判

- **决策点**：**主动认错 + 全量回改**方案、中枢卡、活跃项目表，并把"为 0 的计数一律换工具复跑"追加进经验卡。

- **否决了什么**：否决"沿用误报数据继续推进"——会把已完成的工作重做一遍，并把方案写成错误基线。
- **推翻信号**：无（纠错节点）。**固化铁律**：`grep -c` 返回 0 必换工具复跑 + 与 changelog 交叉验证。

### 节点 6 · 归库实战：撞号 577，先分类再合并

- **决策点**：撞号**绝不覆盖**——560 条同名副本安全去重，**49 条异名真撞号重编号至 M1001+ 保留双方**；主库 729 条 ID **一字不动**。
- **考虑了什么**：安全号段取 M1001+（主库最大 862、expansion 最大 920，留足余量）；重编号按 `(old_id, 文件名)` 排序确定性分配（**幂等的命门**）；变体层 730 / 维度层 71 **独立成层**（同号不同视角，防二次撞号）；六-B 铁律：全量 `cp -R config/`（9MB）→ dry-run → apply → verify。
- **否决了什么**：**否决"后写覆盖先写"**（最关键，违反"权威数据绝不静默覆盖"铁律）；否决"统一重排让编号更整齐"——会打断既有引用；否决"12 个 backup 直接删"——归档 `_archive_backup/` 可回滚。
- **推翻信号**：若证明 49 条异名实为同一规则的别名（需人工逐条确认）→ 可改为合并；当前按"内容不同即保留双方"处理。
- **落点**：`config/risk_rules.master.json`（**835 主体 + 730 变体 + 71 维度，重复 ID=0**）+ `rules_consolidate.py` + `rules_loader.py` + `consolidation_report.md`；技能升 v10.1.0（明令禁再散读 45 个 expansion）。

### 节点 7 · 口径自证：577 ≠ 49+560 是伪矛盾（写卡前复算救了自己）

- **决策点**：沉淀前**复算卡内每一个数字**，发现三个数分属三种口径，**都是对的**。
- **考虑了什么**：`撞号 577（ID 级）= 530 同名副本 ID + 47 真撞号原号`；`去重 560（id×文件 记录级，因 32 个 ID 跨文件重复）`；`重编号 49（条目级，M851/M852 各跨 2 文件）`。可闭合等式：**729 + 57 + 49 = 835 ✅**。
- **否决了什么**：否决"硬圆数字"——没有去改数据迁就等式，而是**回头查口径**，结果反而成了本卡最有价值的教材。
- **推翻信号**：无（口径结论，恒有效）。**固化铁律**：报数必带口径 / 等式自检 / 均值必标 n。
- **落点**：`consolidation_report.md`；后续催生统计口径卡（节点 8）。

### 节点 8 · 事故沉淀：处置卡 ≠ 事故卡（老强第三次开口）

- **决策点**：补建**统计口径事故卡** + 中枢 `PREF-009` + 三卡互链；跨项目既有铁律**升级不新建**。
- **考虑了什么**：查重实证——全库 grep「统计口径/口径错误/顶层键」**无同类卡**；中枢 grep「事故必沉淀」**0 命中**；跨项目 MEMORY 已有 09-04「踩坑即沉淀」铁律（场景 A/B/C）→ 在其下做**第三次补强**（新增场景 D 计数类误判 + 检查单第 9/10 项），不另起新段免得两条打架。三卡成链：**统计口径（定口径）→ 存在性断言（证存在）→ 归库四原则（再处置）**。
- **否决了什么**：**否决"已有归库四原则卡就算沉淀了"** —— 那是**处置卡**（教以后怎么并库），不是**事故卡**（记我当时错在哪），二者都必须有，这正是老强第三次开口的真因；否决"新建重复段"——与 09-04 铁律冲突。
- **推翻信号**：无。**固化**：事故卡四要素=错值+真值+错因+可复用铁律；只写"某处有误"视为未沉淀。
- **落点**：`经验卡-统计口径五连错-…`（飞轮运维）+ `PREF-009` + `_索引.md`（顺手修 007/008 **列数错位**）+ 调用记录 + 训练场次刷新至 **12 场**（末场为老强另建的 `面瘫针灸协议` 记录，**闭合 🟨B 医院支柱**）。

## 收敛结论

一场「搭个非诉心智模型」的诉求，实际走出的是**八步递进**：

```
① 消歧前置（非诉≠诉讼，三层钉死）
   → ② 家底实测（拒凭印象，抓 3 处漂移）
      → ③ 定位翻转（归库优先于造弹药）
         → ④ 活文档化（SSOT + 追踪脚本 + 四通道）
            → ⑤ 自查纠错（grep 静默失配→三块为0 误判）
               → ⑥ 撞号归库（577 分类处置，绝不覆盖）
                  → ⑦ 口径自证（三数全对，是尺子不同）
                     → ⑧ 事故沉淀（处置卡 ≠ 事故卡）
```

四条可迁移判断：

1. **消歧先于搭建** —— 家族内已有近似席位时，先钉边界再动手，否则评分卡、路线图、引用全部串台（节点 1，后续果然抓到七维/五维串台）。
2. **实测先于断言** —— 本场共抓出 **5 处错口径**（11 / 147 / 132 / 2447 / "三块为 0"），其中"11 条"还推导出"主库空壳"的重判断，差点导向"规则库重建"的错误路线。
3. **撞号绝不覆盖** —— 多源归库时先判"副本 vs 异名"，异名一律重编号保留双方；**静默覆盖是比崩溃更危险的失败**。
4. **处置卡 ≠ 事故卡** —— 沉淀时二者都要建：处置卡讲"以后怎么做"，事故卡讲"我当时错在哪"。只建前者 = 老强第三次开口的原因。

成熟度：**73/100 · M4 精熟 · n=12**（D1 12.0 / D2 16.7 / D3 13.3 / D4 20.0 / D5 11.2），**四支柱全覆盖**（🟦C 合同 / 🟩A 慈善 / 🟨B 医院 / 🟧运维）。

⚠️ **本卡定稿时同步发生的分数跳变，值得记一笔**（均值口径现场教学）：
同一天内 `n=10 → 66/100·M3` → `n=11 → 66/100·M3` → **`n=12 → 73/100·M4`**。
第三次跳变的真因是老强另建的 `20260915-面瘫针灸协议v2红队交办补强.md` 记录被脚本扫入，
**🟨B 医院/医疗支柱由此闭合**（此前我判定"🟨B 零实战"），D4 系统建设交付 15→**20 满分**。

教训：**分数是"样本的函数"**——不标 n 无法比较，`66` 与 `73` 看似进步 7 分，实为**样本结构与支柱覆盖变化**所致，
并非本席能力在一小时内提升两级。**均值类指标必标样本数 n**（`73/100 · M4 · n=12`）。
