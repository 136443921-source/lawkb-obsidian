# 案例规则卡（Case-derived Rule Card）· 卡型定义与总索引

> **一句话**：案例规则卡**从一个或一组真实裁判案例中归纳出可复用的裁判规则**——记的不是"法条怎么说"，而是**「法院在这个真实案子里是怎么判的」**。
>
> **本页由来**：2026-09-16 P1-5 批量分流中，`R-CS-007~010` 四张卡原被低置信度（`confidence 0.55`）推断归并为「实务规则卡」。实扫发现它们正文含 **「案例锚点」段（带真实案号）**，结构为「一句话规则 → 法律依据 → 案例锚点 → 实务指导意义 → 关联智能体」，与既有单例 `R-PI-258` 同构。经老强拍板**析出为新卡型**并补写本定义。

---

## 一、卡型定位（与相邻卡型边界）—— 易混，务必看清

| 维度 | 通用裁判规则卡 | **案例规则卡（本卡型）** | 类案检索报告卡（LC） |
|---|---|---|---|
| 推理方向 | **演绎**：法条 → 规则 | **归纳**：案例 → 规则 | 检索：需求 → 结果集 |
| 回答 | 「规则是什么？」 | **「法院在这个案子里怎么判的？」** | 「有哪些类似案子？」 |
| 效力来源 | 法条文本（规范效力） | **案例锚点（事实拘束力/参考效力）** | 检索结果（无规则提炼） |
| 必备段 | 法条依据 | **案例锚点（含案号）** | 检索式 + 结果列表 |
| 产出物 | 可引用规则 | **可引用规则 + 可引用案号** | 案例清单 |

> **⭐ 最大易混点**：本族与**通用裁判规则卡**极易混。判据只有一条——**正文是否含「案例锚点」段且带真实案号**。有 → 本案型；无 → 通用裁判规则卡。

> **与 R-PI-258 的关系**：`R-PI-258`（韩杰医生医疗事故罪申诉七疑点）是本卡型的**既存单例**，属「个案方法论亚型」（案情 → 疑点清单 → 辩护命题），与 R-CS-* 的「规则提炼亚型」同族异构，二者均归本卡型。

## 二、字段规范与正文结构

**frontmatter**：
```
rule_id              R-CS-NNN（案例域）/ 其他域沿用本域号
card_type            案例规则卡
card_type_original   实务规则卡（仅 P1-5 分流来的 4 张有此溯源字段）
card_type_reviewed   2026-09-16 P1-5 段名指纹分流
status               已入库
source               来源（法律资讯周报 / 人民法院案例库 / 个案卷宗）
lti_check            REJECT=0（五维 QC 通过）
related_links        关联卡与枢纽
```

**正文结构**（实扫确认两亚型）：

**亚型 A · 规则提炼型**（R-CS-007~010，五段）：

| 段名 | 内容 | 是否必备 |
|---|---|---|
| `## 一句话规则` | 从案例归纳出的可复用规则，一句话说完 | ✅ |
| `## 法律依据` | 法条条号；**未回填正文须标 `statute_text_pending`** | ✅ |
| `## 案例锚点` | **案号 + 来源 + 裁判要旨** ← 本卡型身份证 | ✅ **必备** |
| `## 实务指导意义` | 适用边界 + 攻防两侧注意点 | ✅ |
| `## 关联智能体` | 消费本卡的智能体清单 | ✅ |

**亚型 B · 个案方法论型**（R-PI-258，六段）：
`案情梗概` → `疑点/争点清单` → `核心方法论命题` → `与在办案件关联` → `相关笔记` → `关联`

## 三、识别指纹（用于自动化归类）

```python
# 判据：H2/H3 段名含「案例锚点」
heads = re.findall(r'^#{2,3}\s+(.+?)\s*$', s, re.M)
if any("案例锚点" in h for h in heads):
    → 案例规则卡
```

**辅助特征**（命中 2 条以上可加强判定）：
- `## 关联智能体` 段（R-CS-* 系列标配）
- tags 含「人民法院案例库」/「典型案例」/「参考案例」
- 正文出现真实案号正则 `\(\d{4}\)[^）]{2,8}\d+号`
- 文件名前缀 `R-CS-`

## 四、消费智能体（谁该读本卡型）

| 智能体 | 怎么用 | 取哪个字段 |
|---|---|---|
| **类案检索助手** | 以「案例锚点」的案号作**种子案例**做相似案扩张检索 | `案例锚点.案号` |
| **模拟法庭法官心智** | 引用本卡作**正向裁判规则**（法院实际怎么判） | `一句话规则` + `案例锚点.裁判要旨` |
| **红蓝对抗（红队/蓝队）** | 攻防引用：蓝队引为**防御弹药**，红队据 `实务指导意义` 找**攻击点** | `实务指导意义` |
| **法律咨询路由** | 类案派发依据 | `tags` + `related_links` |
| **LTI 文本监控器** | `法律依据` 段若标 `statute_text_pending`，**不得引为文档源** | `法律依据` |

> **⚠️ 引用铁律**：本卡型法条段常带 `statute_text_pending`（本地法规库为节选、无该条）。**未回填前不得将法条正文引为文档源**，只可引用案号与规则表述。

---

## 五、五条铁律

1. **「案例锚点」是身份证**——无案号不得称案例规则卡，应降级为通用裁判规则卡。
2. **案号必须真实可溯**——禁止凭记忆填案号；来源写清（人民法院案例库 / 公报 / 裁判文书网）。
3. **法条未回填须标 `statute_text_pending`**——不得静默留空、不得凭记忆灌条文（本地源引证铁律）。
4. **只改 frontmatter，绝不重命名文件**——`R-CS-*` 文件名受 300+ 全名链接保护。
5. **规则提炼型与个案方法论型同族**——个案卡（如 R-PI-258）不因"只有一张"而降级或归并。
