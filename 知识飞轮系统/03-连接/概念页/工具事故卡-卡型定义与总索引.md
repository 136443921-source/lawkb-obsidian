# 工具事故卡（Tool Incident Card）· 卡型定义与总索引

> **一句话**：工具事故卡记录**「AI 工具 / 自动化链路出过什么事故、怎么踩的、以后怎么防」**——是**系统运维事故教训卡**，不是法律裁判规则卡。
>
> **🔄 v1.1.0 改名已执行（2026-09-16）**：本族原名「**工程事故卡**」，经老强拍板改名为「**工具事故卡**」。原因有二：① 语义错位——3 张卡内容全是 AI 工具事故，与"工程"无关；② 混淆风险——同库 `建设工程/` 目录下存在真实的 `R-JG-034/035` 建设工程合同卡，检索必混。
>
> 改名方式：**仅改 frontmatter `card_type` + 本定义页文件名，3 张 `R-*` 卡文件一律不重命名**（保护既有全名链接）。旧名已写入 `aliases` 与 `card_type_original` 字段，历史引用可回溯。

---

## 一、卡型定位（与相邻卡型边界）

| 维度 | 通用裁判规则卡 | 实务规则卡 | **工具事故卡（本卡型）** |
|---|---|---|---|
| 领域 | 法律裁判 | 法律办案 | **AI 工具 / 自动化运维** |
| 性质 | 规则本体 | 操作路径 | **事故复盘（负向教训）** |
| 回答 | 「规则是什么？」 | 「怎么操作？」 | **「哪里会炸、怎么防？」** |
| 价值 | 正向供给 | 正向供给 | **负向免疫** |

> 本族是知识飞轮里**极少数非法律类卡**，承载的是「这台机器本身的故障记忆」，与 LTI 的负向拦截互补（LTI 管文本，本族管工具链）。

## 二、字段规范与正文结构

**frontmatter**：`rule_id` / `card_type: 工具事故卡` / `card_type_original: 工程事故卡`（溯源，v1.1.0 起）/ `library` / `created` / `updated` / 建议增加 `incident_date`（事故发生日）、`impact`（影响面）

**正文结构**（实扫确认为六段，比初版建议的五段更完整）：
1. 事故概述（发生了什么）
2. **根因分析**（三层，逐层往下挖）
3. **误判传导链**（错一步如何滚成一串）
4. **代价清单**（量化）
5. **正确做法**（SOP：N 铁律，不许跳步）
6. **翻车标本**（负向拦截·同类错误清单）

## 五、铁律

1. **事故卡优先于操作**：执行批量写入 / MCP 调用前，先检索本族有无同类事故记录。
2. **根因必写**：只记现象不记根因的事故卡无效（无法形成免疫）。
3. **防护措施须可执行**：结论必须落到「具体动作 / 脚本 / 检查项」，不写"加强注意"这类空话。
4. **与六-B 铁律联动**：本族事故是「先备份、先排查、dry-run、确认幂等」等铁律的实证来源。
5. **命名须对齐语义**：卡型名不得与实际内容错位，且不得与既有法律域（如建设工程）产生检索混淆。
