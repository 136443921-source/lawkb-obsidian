# 思维轨迹卡（轨迹卡）· 卡型定义与总索引

> **一句话**：思维轨迹卡记录**「排障/建卡时，脑子是怎么一步步走到根因的」**——是**调试/诊断推理链卡**，不是法律裁判规则卡，也不是决策轨迹卡。
>
> **定位澄清（2026-09-17）**：本族 `card_type` 实际已存在（样本卡 `轨迹卡-AI内部推断外溢为事实断言的拦截路径-20260907.md` 的 frontmatter 即 `card_type: 思维轨迹卡`），落位 `知识飞轮系统/02-提炼/经验卡片/思维轨迹/`，连接枢纽-思维轨迹已自动挂载 10+ 张。**运维员（IT运维员技能）2026-09-17 正式接手策展**，补建本定义页、明确与工具事故卡的成对联接、与决策档案 DEC 类「思维轨迹」的分工。

## 一、卡型定位（与相邻卡型边界）

| 维度 | 工具事故卡 | **思维轨迹卡（本卡型）** | 决策轨迹卡（DEC-2026-XXX·思维轨迹） |
|---|---|---|---|
| 回答 | 「哪里会炸、怎么防？」 | 「怎么查出来的、推理链是什么？」 | 「为什么这么决策？」 |
| 落位 | 06-沉淀/裁判规则库/律师实务 | **02-提炼/经验卡片/思维轨迹** | 03-决策档案 |
| 价值 | 负向免疫（防再犯） | 方法复用（排障路径可复刻） | 决策回溯（路径取舍留痕） |
| 配对 | 必配一张轨迹卡 | **必配一张事故卡** | 独立 |

> ⚠️ **铁律**：一张工具事故卡必配一张思维轨迹卡——事故卡记「错了什么/为什么错」，轨迹卡记「怎么查出来的/推理链」。只建其一 = 链路断裂（PREF-009 教训）。

## 二、字段规范与正文结构

**frontmatter**：`card_type: 思维轨迹卡` / `topic` / `domain` / `case_ref`（关联事故卡）/ `consultation_count` / `evolved_question`（收敛问题）/ `thinking_path`（五层推理链）/ `fact_directions`（核查清单+证据分级）/ `corrections`（老强纠偏）/ `key_leverage` / `pitfall` / `restart_point`（起步四步）/ `open_questions` / `conclusion_refs` / `related_links` / `tags` / `reviewer`

**正文结构**（实扫样本卡确认）：
1. 问题演进（老强追问如何逼到根因）
2. 思维逻辑链（①现象层找同源性 ②归因层共同根因 ③分层定性 ④拦截层找盲区 ⑤固化层机器门禁）
3. 事实思考方向（核查清单 + A/B/C 证据分级）
4. 分歧与纠偏（老强逐条校准 + 真调用核验）
5. 收敛结论
6. 复用提示

## 五、铁律

1. **必配事故卡**：凡由 PREF-009 五类事故沉淀的轨迹卡，必须 pairing 一张工具事故卡（成对出现、互链）。
2. **推理链须完整**：现象→假设→验证→根因→修复 五段缺一不叫轨迹卡，只能算笔记。
3. **证据分级强制**：C 级（AI 内部推断）不得作为事实断言输出，只能写「待核」。
4. **与决策轨迹分工**：本卡记「怎么查」，DEC 类记「怎么定」；同一事件若两者都有，互相链接但不可合并。
5. **命名须对齐语义**：`轨迹卡-<主题>-YYYYMMDD.md`，禁全角括号，遵守卡族总索引命名纪律。
