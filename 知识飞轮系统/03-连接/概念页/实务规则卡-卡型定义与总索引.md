# 实务规则卡（Practice Rule Card）· 卡型定义与总索引

> **一句话**：实务规则卡回答**「具体怎么操作」**（办案操作路径与举证步骤）；审判要件卡回答**「该怎么判」**（正向裁判）；通用裁判规则卡回答**「这条规则是什么」**（规则本体）。**三套东西，不可互相替代。**
>
> ⚠️ **本页沿革**：2026-09-15 前本页为断链消解器（`resolve_broken_links v1.2`）自动生成的**空壳**——仅有自动关联链接、无卡型定义正文，且关联中混有 A、B、名、笔记名 等**模板占位符垃圾链接**（原以双方括号形式书写，会被 Obsidian 解析为真实链接而制造新断链），本次一并清除。本页虽为空壳却挂着全库第二多的 177 张卡，故按 P0-3 补写正本，**全部数据来自实扫**。

## 一、卡型定位（与相邻卡型的边界）

| 维度 | 要件映射卡 | 审判要件卡 | **实务规则卡（本卡型）** | 通用裁判规则卡 |
|---|---|---|---|---|
| 载体 | `lti_element_cards.json` | 规则卡 `R-*` | 规则卡 `R-*` | 规则卡 `R-*` |
| 回答的问题 | 「引用错了吗？」 | 「该怎么判？」 | **「具体怎么操作？」** | 「这条规则是什么？」 |
| 推理方向 | 负向拦截 | 正向裁判 | **正向操作路径** | 规则本体沉淀 |
| 触发时机 | 文书生成**后**校验 | 庭审推演**中** | **起草 / 举证 / 谈判前** | 通用检索 |
| 典型输出 | 「1165 不是无过错责任」 | 「先查四要件，支持/驳回分别……」 | 「先做 A，再查 B，证据清单按 C 组织」 | 规则陈述 |
| 消费方 | LTI 文本监控器 | `judge_reviewer` 法官心智 | **🔵蓝队 / 🔴红队 / 文书生成** | 全体智能体底座 |

> **与审判要件卡的分工**：审判要件卡给「裁判结论」（支持/不予支持），实务规则卡给「**动作序列**」（先做什么、再做什么、证据怎么组织）。前者是**法官视角**，后者是**律师视角**。

## 二、字段规范

### 2.1 frontmatter 强制字段

```yaml
rule_id: R-HT-185              # 强制，白名单域码 + 三位补零
card_type: 实务规则卡           # 【强制】与审判要件卡/通用裁判规则卡物理区分
geo_scope: 全国（…）            # 【强制·第二代标记】地域效力
library: 小强律师数字分身系统     # 【强制·第二代标记】
source: …                      # 来源（含采集方式）
source_verified: false         # 来源是否已核验
statute_text_pending: true     # 法条正文待回源标记（未消不得引为文档源）
review_date: 2027-03-04        # 复核期
rule_card: R-HT-185            # 与 rule_id 同值
```

### 2.2 正文八段结构（标准形态）

1. 规则要旨（正向 · 怎么用）
2. 审查要点（操作路径，**编号步骤**）
3. 构成要件与举证
4. **法条依据（权威源回填，非凭记忆）** + 官方核验指引
5. 抗辩与但书
6. 翻车标本（负向拦截 · HIR）
7. 来源与地域效力
8. 关联（知识飞轮连接层）

> 八段结构与审判要件卡同构，但**第 2 段「审查要点」必须是编号步骤**（动作序列），这是本卡型的识别指纹。

## 三、⚠️ 内部两代混合现状（本次实扫发现，治理前置）

本卡型**不是均质集合**，实扫 177 张卡得到如下分野：

| 指标 | 实测值 | 说明 |
|---|---|---|
| 总数 | **177 张** | 占全库 9.4%，第二大卡型 |
| 含 `geo_scope`（第二代规范） | **52 张（29%）** | 与《通用裁判规则卡》卡型定义文件所载「实务规则卡 52 张、geo_scope 100%」完全吻合 |
| 无 `geo_scope` | **125 张（71%）** | 结构自由，多为第一代存量 |
| 标 `card_type_inferred: true` | **117 张（66%）** | 卡型系**批量推断**而非原生标注 |
| 推断置信度 `card_type_confidence` | **普遍 0.55** | 偏低，属代际指纹推断产物 |

**两种并存结构**：

| 结构 | 张数（估） | 特征 | 样例 |
|---|---|---|---|
| **八段式（规范）** | ~52 | 带 `geo_scope`/`library`、编号步骤审查要点 | [[R-HT-185-建设工程黑白合同的结算规则]] |
| **四段式（降级）** | ~125 | 法条基底→裁判要旨→实务要点→关联；多为 WebSearch 降级采集、带 `source_downgrade` | [[R-LD-006-工伤与第三人侵权竞合的双重赔偿规则]] |

> 🔴 **结论**：本卡型的「177 张」是**推断归并后的账面数字**，其中约 125 张实为第一代卡片被低置信度（0.55）归入。这解释了为何本页此前长期是空壳——**卡型边界未定，无人敢写定义**。

## 六、铁律

1. **法条正文回填铁律**：`elements` 仅描述要件，**绝不内嵌法条正文**；法条正文须从本地权威源（`法律法规库/`）或北大法宝/华宇元典核填，标「现行有效」状态。
2. **`statute_text_pending` 未消不得引为文档源**（本地源引证铁律）。
3. **铁律 R2（机器仅候选）**：本卡给出的操作路径是**候选建议**，须结合个案人工拍板。
4. **地域效力标注铁律**：带 `geo_scope: 贵州省` 的卡**非全国统一口径**，跨省援引须核实当地尺度。
5. **卡型不可混标**：带 `geo_scope` 的规范卡才得标 `实务规则卡`；第一代存量回退 `通用裁判规则卡`（待方案 A 拍板后执行）。
