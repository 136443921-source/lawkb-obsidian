# 裁判规则三任务职责边界

> **创建日期**：2026-07-20
> **背景**：三条自动化任务同时操作[[裁判规则库]]，存在职责重叠与重复写库风险，需明确边界。
> **涉及任务**：裁判规则自动入库 / 裁判规则对账（法随案例库） / 人伤裁判规则定向补强

---

## 一、三任务速览

| 维度 | 入库（Task 1） | 对账（Task 2） | 补强（Task 3） |
|------|---------------|---------------|---------------|
| **ID** | automation-1783158782382 | automation-1783957225528 | automation-1783919652225 |
| **频率** | 每月15日 10:00 | 每月28日 21:00 | 每周三 20:30 |
| **领域范围** | **全部案由**（8+争议焦点） | **全部案由** | **仅人伤** |
| **操作性质** | **写**（入库新规则） | **只读**（审计对账） | **写**（生成+入库） |
| **存储格式** | 单文件索引 `裁判规则库.md` | 报告文件 | 子目录卡片 `裁判规则库/[案由]/` |
| **写入路径** | `06-沉淀/裁判规则库/裁判规则库.md` | `03-连接/裁判规则对账-YYYY-MM.md` | `06-沉淀/裁判规则库/[案由]/` |

## 二、重叠分析与风险

### 重叠点

```
入库(1)：写 → 裁判规则库.md（单文件）
补强(3)：写 → 裁判规则库/[案由]/（子目录）
          ↑
    同一目录，两种存储格式！
    同一条规则可能出现在两个位置
```

**风险 1 — 双重写入**：Task 1（入库）可能提取到一条与 Task 3（补强）相同的规则，分别写入 `裁判规则库.md` 和 `裁判规则库/[人伤]/`，造成事实重复。

**风险 2 — 格式不一致**：Task 1 使用表格格式（规则编号 + 规则内容 + 适用条件 + 案例支持 + 关联度 + 入库日期），Task 3 使用 frontmatter + 叙述格式（案号 + 审理法院 + 裁判要旨 + 适用要点 + 关联法条）。两套格式无法互操作。

**风险 3 — 去重盲区**：Task 1 的 `check_rule_duplicate` 只与 `裁判规则库.md` 内已有规则比对，**看不到 Task 3 写入的子目录规则**；反之亦然。

**风险 4 — 对账图景不全**：Task 2（对账）需读取全部本地规则进行权威对账，两套存储格式增加了读取复杂度。

### 无重叠区

| 任务对 | 重叠 | 说明 |
|--------|------|------|
| 入库 ↔ 对账 | 无 | 对账只读，不入库 |
| 补强 ↔ 对账 | 无 | 对账只读，不入库 |
| 入库 ↔ 补强 | **有** | 均写入裁判规则库 |

## 三、边界清晰定义

### 入库（Task 1）—「全景搜索 + 批量入库」

```
职责：每月从法随案例库全景搜索高频争议焦点，AI提炼规则，去重后批量写入统一索引。
写哪：仅写 裁判规则库.md（单文件索引）
不写：裁判规则库/[案由]/ 子目录（那是补强的地盘）
关键动作：搜索 → 提炼 → 去重 → 写入
```

**去重增强要求**（2026-07-20 新增）：
- 写入前必须同时检查 `裁判规则库.md` **和** `裁判规则库/[案由]/` 子目录的已有规则
- 若发现补强已写入的规则，跳过入库，仅在 `裁判规则库.md` 中追加 `[[案由/规则名]]` 链接引用

### 对账（Task 2）—「权威源校验 + 差异报告」

```
职责：以法随案例库为权威源，校验本地规则卡片的完整性、准确性与去重情况。
写哪：仅写 裁判规则对账-YYYY-MM.md（只读报告）
不写：不修改任何裁判规则卡片内容
关键动作：收集本地卡片 → 在线验证 → 标记异常 → 生成报告
```

**读取增强要求**（2026-07-20 新增）：
- 需同时扫描 `裁判规则库.md` 和 `裁判规则库/[案由]/` 两种存储格式的规则
- 报告中标注每条规则的来源格式（单文件 / 子目录），方便后续统一

### 补强（Task 3）—「人伤专项 + 定向生成」

```
职责：每周针对人伤薄弱领域，从权威来源生成高质量内容笔记与裁判规则。
写哪：仅写 裁判规则库/[案由]/ 子目录（详细卡片格式）
不写：裁判规则库.md（那是入库的地盘）
领域限制：仅人伤（人身损害/交通事故/医疗损害/工伤/劳动争议人身损害）
关键动作：缺口分析 → AI生成 → 建立双向链接 → 进度通知
```

**写入安全要求**（2026-07-20 新增）：
- 写入前检查 `裁判规则库.md` 中是否已有同类规则
- 若已有，改为在对应子目录中创建引用链接（`[[../裁判规则库#规则XXX]]`），不重复写内容

## 四、未来建议（非本次执行）

1. **统一存储格式**：建议中长期将 `裁判规则库.md` 拆分为子目录结构，或反之将子目录统一到单文件。当前两套格式并存属于过渡方案。
2. **建立规则 ID 体系**：为每条规则分配全局唯一 ID（如 `RL-2026-001`），跨存储格式可互认，消除去重盲区。
3. **补强扩展到其他领域**：当前补强仅覆盖人伤，若未来扩展到合同/公司领域，需同步更新本边界文档。
