# 规则卡取号规程 v1.0

> **生效**：2026-09-11 ｜ **制定背景**：编号漂移已从偶发变为持续（2026-09-11 12:27 实证：摄入自动化建的 `R-HT-249/250/251` 撞上 09-10 证据规则目录同号旧卡；全库实测同号冲突 **25 组**）
> **适用范围**：**一切新建裁判规则卡的入口**——每日摄入自动化（A1.3 / B / D4）、审判要件卡拆卡流水线、合规审查卡建卡流水线、文书范式卡建卡流水线、任何手工建卡。
> **唯一真源**：`03-连接/scripts/next_rule_id.py`（取号）+ `03-连接/scripts/rule_id_guard.py`（校验）

---

## 一、为什么改（不改会怎样）

原取号是**提示词口头规则**，各 prompt 里各写一遍 `find . -name "R-<域>-*.md" | sort | tail`。三个致命漏洞：

| # | 漏洞 | 后果 |
|---|---|---|
| ① | 只扫**文件名** | 规范规定「文件名仅为别名，唯一标识以 frontmatter `rule_id` 为准」。治理过的卡两者不一致 → max 算错 |
| ② | 取号到落盘有**时间窗口** | 并发流水线（拆卡 / 摄入 / 回灌）互撞。实证 2026-09-11 R-HT-249/250/251 |
| ③ | 规则分散在多个 prompt | 改一处漏一处，无法统一升级 |

**号段被占按规范第三节几乎不可逆**（改名锈蚀 wiki 链接）。所以必须以代码收口。

## 二、取号三步（强制执行，缺一不可）

### 第 1 步：取号（批量、一次取满）

```bash
PY=/Users/chenyouqiang/.workbuddy/binaries/python/versions/3.13.12/bin/python3
cd /Users/chenyouqiang/Documents/LawKB/知识飞轮系统/03-连接/scripts

# 先体检（推荐）
$PY next_rule_id.py --list

# 批量取号：本批要建几张就一次取几个，禁止建一张取一张
$PY next_rule_id.py --domain HT --n 15 --note "2026-09-11 D阶段合同槽位"
```

输出示例：

```
✅ 已取号并预留 15 个：
   R-HT-254 ~ R-HT-268
```

**要点**：
- **`--n` 一次取满**。逐个取号＝把并发窗口放大 N 倍（坑 8「预分配号段必然失效」的同源教训）。
- 域码须在 14 域白名单：`PI HT CF HG LN PR SH GZ CS JG HY GS LD HJ`。
  已成规模的新域（如 `AY` 案由路由）需加 `--allow-offlist`，**并同步提请更新《_规则卡编号体系规范.md》**。
- 预留有效期 **24 小时**，建卡中断会自动释放，不会永久占号。

### 第 1.5 步：🔴 写入前最后一刻 find 门禁（pre）

> **为什么必须**：`next_rule_id.py` 的 24h 预留只防「同样走取号器的并发流水线」，挡不住①**取号流程外直接落盘**（如手工/其他自动化绕过取号器建卡）②**取号→落盘时间窗口**内被并行建卡占号。实证：2026-09-18 R-LD-056 工伤通用卡（流程外直接落盘）与本批裁量尺度卡双占，本批卡顺移 R-LD-062。

落盘前**最后一刻**再物理 `find` 一次同域，确认预期号仍空闲：

```bash
$PY alloc_guard.py pre --domain HT --nums 254 255 256 257 258 259 260 261 262 263 264 265 266 267 268
#   （或用 --range 254 268 限定区间）
#   占用即 exit 2，abort 落盘——绝不允许带病写入；重新走取号器顺延新号
```

### 第 2 步：建卡落盘

按各流水线原有格式建卡，`rule_id` 填第 1 步取到的号。

### 第 3 步：提交 + 校验（落盘后必做）

```bash
# 提交预留（清除占位，否则 24h 后自动释放——号段白等）
$PY next_rule_id.py --commit-all

# 编号守卫（建卡后必跑，只看本轮改动）
$PY rule_id_guard.py --since 60
```

**守卫退出码**：`0` 通过 ｜ `1` 有 ERROR（**须修复后归档**）｜ `2` strict 下有 WARN。

### 第 3.5 步：🔴 写入后回查同域重号（post）

落盘后再验一次，确保无并行/外部建卡突破一次性取号：

```bash
$PY alloc_guard.py post --domain HT --files <刚落盘的卡路径 f1 f2 ...>
#   （或用 --nums 254 255 ...）
#   校验：① 每预期号恰 1 文件 ② 文件名号 == frontmatter rule_id 号 ③ 不被其他卡共用
#   任一不满足即 exit 2——须定位并修复（重新取号 / 改 rule_id 回退）
```

> `pre` + `post` 构成「预留 + 物理 find + 回查」**三防线**，与 `rule_id_guard.py` 全库体检互补，退出码统一为 `2` 发现冲突，可直接接 CI。

## 三、六条铁律

1. **禁止绕过脚本手工取号**。`find` / `sort` / 凭记忆 一律判**流程缺陷**。
2. **一次取满**。批量建卡前一次性取足，不建一张取一张。
3. **落盘即 commit**。卡片写完必须提交预留，否则号段被隐性占用。
4. **口径只看 frontmatter `rule_id`**。文件名只是别名（规范第三节：明令禁止批量改名统一）。
5. **建卡后必跑守卫**。门禁红着等于没门禁（2026-09-10 教训）。
6. **🔴 写入前最后一刻 find + 写入后回查**（P0-4 双保险）。取号器预留挡不住流程外落盘与取号→落盘窗口，必须靠 `alloc_guard.py` 的 `pre` + `post` 两道物理闸兜底（详见第 1.5 / 3.5 步）。

## 五、脚本速查

| 命令 | 用途 |
|---|---|
| `--list` | 各域基线体检（只读，最常用） |
| `-d HT --peek` | 预览下一可用号，不写预留 |
| `-d HT --n 15` | 批量取号并预留 |
| `--commit-all` | 落盘后提交全部预留 |
| `--release R-HT-254` | 放弃某个预留 |
| `--reservations` | 查看当前预留 |
| `rule_id_guard.py` | 全库编号门禁 |
| `rule_id_guard.py --since 60` | 只查最近 60 分钟改动 |
| `rule_id_guard.py --strict` | WARN 也判失败（CI） |
| `rule_id_guard.py --json out.json` | 导出机器可读结果 |
| `alloc_guard.py pre --domain HT --nums 254 255 ...` | 🔴 落盘前最后一刻物理 find 同域，占用即 exit 2 中止写入 |
| `alloc_guard.py post --domain HT --files f1 f2 ...` | 🔴 落盘后回查同域重号（每号恰 1 文件且文件名号==rule_id号），否则 exit 2 |
