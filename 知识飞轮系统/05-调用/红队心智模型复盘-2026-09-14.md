# 红队出庭律师心智模型复盘（2026-09-14）

## 二、心智内核拆解（现在到底怎么想）

红队的心智 = **四维度攻击框架 + 威胁分级 + 口吻 + 铁律**：

| 层 | 内容 | 评价 |
|---|---|---|
| 攻击维度 | ① 逻辑断层扫描 ② 法理精准度狙击 ③ 证据三性摧毁 ④ 法官视角拷问 | 四维度覆盖完整，与蓝队防御面基本对称 |
| 威胁分级 | S（全盘皆输）/ A（可被利用）/ B（可优化） | 好——逼出优先级，不浪费弹药 |
| 输出口吻 | 致合伙人内部战报 | 好——压制「陪练心态」 |
| 席位铁律 | 不弱化攻击 / 不越界裁判 / 不编造案号 / 每轮过 LTI | 好——尤其「不因扮演对方而弱化」是关键 |
| 弹药逻辑 | 主取 `negative_note`（翻车标本）→ 次取 `ruling.reject` → 用 `elements` 查缺项 | **这套是全系统最优设计**，把知识飞轮的负向样本变成了攻击弹药 |

**结论：心智的「算法」是对的，问题在「载体」。**

## 三、四处断点（按优先级）

### 🔴 P0-1 心智未结构化 —— 红蓝不对称

法官有 `judge_persona_v1.md` 独立人格卡（五章：人格定位 / 庭审主持准则 / 文书说理准则 / 禁区红线 / 接驳），中台上还有「🧠 法官心智 · 正向裁判规则」面板。

**红队没有对应物**：四维度只写在 SKILL.md 第 217–223 行的 7 行字里，中台无红队心智面板。

后果：
- 红队攻击强度**不可调参**（想让它更狠/更收敛，只能改 SKILL 正文）
- 攻击路径**不可观测**（看不到它这一轮为什么选这个攻击点）
- 心智**不可版本化**（judge_persona 有 version 字段，红队心智没有独立版本）

### 🔴 P0-2 知识库悬空

SKILL 第 312–352 行声明「回答前必须先搜索 `/LawKB/知识库/红队出庭律师仓库/`」，该目录**实测不存在**。

后果：每次调用都在执行一条指向空目录的强制指令；且第 331 行要求发现知识库问题须告警——但没有任何一次告警发生，说明该检查实际未生效。

### 🟠 P1-1 攻击点沉淀空转

补丁4（2026-08-17）设计了完整闭环：战报 → 文书防御要点卡 → `02-提炼/案例摘要/最佳实践库/文书防御要点/` → 供场景化推送前置防御。

实测该目录**不存在，0 张卡**。8 场对抗的攻击点全部用完即弃。这是全系统里密度最高的「对手视角」信号，白白流失。

### 🟠 P1-2 埋点与元数据稀薄

- 协同效果日志：红队仅 2/25
- 对抗记录 `red_team` 字段：仅 1/8

后果：无法回答「红队在哪类案由上攻击最有效」——这是后续调优唯一的数据基础，目前是零。

### 🟡 P2 SKILL 本体冗余

| 重复项 | 次数 |
|---|---|
| `## 输出格式 (Output Format)` | 2 |
| `## 输出前LTI检查（强制执行）` | 2 |
| `## 【文本监控器参与说明】` | 9 |
| `#### 2. ⚠️ WARNING` 段落 | 3 |

38KB 文件里有效指令被稀释，加载成本高、易触发不同段落的规则冲突。

## 四、对红蓝对抗的实际影响

**好消息**：红队是能打疼人的。6658 案推演里，红队视角直接改写了己方主攻方向（从「整包前」转到「原告举证不能」），并预判到法官最可能走「以实际受益突破合同相对性」的路径——说明负向标本弹药机制真实有效。

**坏消息**：这种有效是**一次性的、不可复用的**。因为没有心智卡（不可调参）、没有沉淀卡（不可复用）、没有埋点（不可度量），每场对抗都从零开始。
