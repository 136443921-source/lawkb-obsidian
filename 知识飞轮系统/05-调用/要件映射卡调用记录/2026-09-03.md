## 三、卡型设计决策（重要）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 是否塞进 `lti_element_cards.json` | **否，物理隔离新增卡型** | 负向拦截与正向裁判是两套语义，混用会双向污染 |
| 编号前缀 | 沿用白名单 `R-PI-` / `R-PR-`（**弃用第一轮的 `SJ-` 前缀**） | 规范 v1.0.0 禁止新域码；`SJ-` 会破坏编号体系 |
| 是否保留 `elements` | **保留** | 与现有卡同构，可复用 `lti_verify.py` 三元推理闸门 |
| 新增核心字段 | `card_type` / `review_step` / `ruling` / `burden_of_proof` / `geo_scope` | 承载"该怎么判"的正向裁判规则 |
| 法条正文 | **不内嵌，从权威源回填并标注来源** | 遵守回填铁律，避免与权威源漂移 |

## 四、避坑记录（本次踩到并修复）

1. **YAML frontmatter 被英文双引号破坏**：卡片内容中的中文引号写成英文 `"` 塞进 `negative_note: "..."` 导致 YAML 解析失败。
   → **修复**：加 `yq()` 转义函数，值内 `"` 成对转为「」。
   → **沉淀**：今后任何生成 Obsidian 卡的脚本，frontmatter 值一律走引号转义。
2. **校验脚本依赖 pyyaml 缺失**：导致字段全空假报"缺字段"。
   → **修复**：在隔离 venv `binaries/python/envs/default` 装 pyyaml。
   → **沉淀**：校验脚本应先自检依赖，缺失时明确报错而非静默降级。
3. **正则取号时中文数字转换漏"零"**：1208 → 「第一千二百八条」而非「第一千二百零八条」。
   → **修复**：十位为 0 且个位非 0 时补「零」。
