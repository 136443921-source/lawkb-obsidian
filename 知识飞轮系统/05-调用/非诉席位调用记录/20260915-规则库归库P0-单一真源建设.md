# 合同风险规则库归库 P0（2026-09-15）

## 一、为什么做

基座技能 `蓝队律师合同审查` 的规则库散落 **58 个 json**（含 45 个 `risk_rules_expansion_*.json`），
**无单一真源、无加载器**，且此前两轮统计口径均错（记 147 条 / 2447 条）。归库前必须先拿到真数。

## 二、实测真数（2026-09-15 17:26）

| 项 | 此前记载 | **实测** |
|---|---|---|
| 主库 `risk_rules.json` | 11 条 / 147 条 | **729 条**（M1–M862，133 个空号） |
| expansion 唯一 ID | — | **634 个**（M201–M920） |
| 撞号 | 未发现 | **577 个**（560 同名副本 + 49 条异名真撞号） |
| ER 变体 | — | 730 条（仅覆盖 34 个基础规则） |
| 维度层 | — | 71 条 |

> **第 5 处文档漂移**：技能正文称「整合 132 条统一风险规则」，实际 835 条。

## 三、处置（不静默覆盖）

1. **基准层**：主库 729 条，**ID 一动不动**（保护既有引用）
2. **同名副本 560 条** → 去重丢弃，写入 `dedup_log`
3. **真撞号 49 条** → **重编号至 M1001–M1049**，原号存 `_renamed_from`，**双方全保留**（例：M847 主库「境外主体特殊审查」+ M1032「合同约定解除条件成就认定标准风险」共存）
4. **ER 变体 730 / 维度 71** → 独立成层，不并入主体
5. **12 个 backup** → 归档 `config/_archive_backup/`（**不硬删**）

## 四、结果

- **规则主体 835 条**，**重复 ID = 0**（verify 通过）
- **幂等已验**：连跑两次，rules/variants/dimensions/dedup_log/rename_log/id_index 逐字段 hash **完全一致**（仅 generated 时间戳变）
- 加载器可用：`--search 慈善` 命中 M401–M404；`--layer variants --search 无限责任` 命中 ER 变体

## 五、遗留（P1）

- `risk_level` **中英文混用**：high/medium/low 与「高风险/中风险」共 35 条 → 待归一化
- 维度层 M 编号与主库不同义（M001 主库=主体资质缺失／维度=无限责任条款）→ 消费时须显式选层
- 建议建周刷新自动化（周一 9:40）兜底训练回写
