# 每日知识摄入自动化复盘与迭代建议（2026-08-26）

> 依据：automation-1783920420205 执行历史（2026-07-14 ~ 08-26，44 天）、本次 08:30 / 14:25 / 08:38 运行实录、工作区通道故障处置规范与六-B 安全铁律。

## 一、一句话诊断

**它名为"每日自动化"，实为"半自动人工续跑系统"。**

44 天运行史里约 **80%+** 的执行段标题都带"续跑补全 / 回补 / 补正 / 专项"。本次 08:30 定时触发后，仍要你发"请继续"两轮（14:25、08:38）才清算完。最大病灶不是某个通道故障，而是**缺少"一次性跑完"的工程闭环**——凡是网络抖一下、去重错一处、法条要核一下，就得人介入。

## 三、迭代建议（P0 / P1 分级）

### 🔴 P0（决定"自动化"是否名实相符，必改）

**1. 运行态 checkpoint + 自动续跑**
- 把 A0→A1+B→A2/A2.5→C→D→Final 拆成可持久化阶段状态机，每阶段完成即写 `stage_state`（已选文 / 已摄入 / 已蒸馏 / 已采案例 / 已报告）。
- 中断后由"续跑子自动化"或同任务重入自动从断点续，**不再依赖人发"请继续"**。
- 预期收益：续跑率 80%+ → <10%。

**2. 状态文件单一真源 + schema 版本化**
- 废除 `totals` 陈旧缓存字段，改为每次读时由 `libraries[].ingested` 实时聚合；
- `ingested` 元素统一为对象（迁移清掉 dict+str 混排）；读写加 `schema_version` + 兼容层，杜绝 AttributeError 型错误。

**3. 失败项自动升级闭环**
- fetch 失败（220030 / 超时 / 截断）不再"留档待人工"：① 自动 WebSearch 找公开镜像降级补全（标 `pending_source_upgrade`）；② 连续 N 次失败自动 QQ 推送失败清单（目前仅 append log，用户无感）。

### 🔵 P1（显著提质量与体验）

**4. 交付可见性双通道**：Final 阶段除 QQ 推送外，自动 `present_files` / 写 IM，并在工作区生成"今日摄入已就绪"索引，避免漏看。

**5. 法条时效自动校验**：A1+B 选文后内嵌"法条体检"——对引用法条（公司法71/84、医疗损害解释16条等）自动比对"现行有效 / 已废止 / 即将施行"，重大更新自动标红 + 建议条款，不靠人下轮补。

**6. 通道实调探针前置**：执行前对 ima-mcp / yuandian-mcp / qq-mail 做 ToolSearch 实调（不信面板），不可用时立即降级并记录。

**7. 去重 + 摄入原子化**：写回 ingested / failed 用事务式（先备份临时文件 `os.replace`），`verify-before-modify` 固化进自动化标准库，避免每轮临写脚本。

**8. 运行健康度看板**：把"续跑次数 / 单次闭环率 / 降级占比"做成月度趋势（摄入稳定性监测守卫已覆盖 7 类，补趋势维度），定位退化。

## 四、如果只改一件事

> **做 P0-1 运行态 checkpoint + 自动续跑。**

44 天里它几乎每次都要你发"请继续"才能跑完——这不划算。把续跑逻辑内置，你的"每日自动化"才名副其实；其余 P0 / P1 都是在这之上的加固。

## 五、落地下一步（待你拍板）

- **方案 A（最小改动）**：直接改 automation 的 prompt，把"断点续跑"写进标准步骤（立竿见影，但逻辑仍散在 prompt 里）。
- **方案 B（工程化）**：抽一个 `intake_runner.py` 标准库（checkpoint + 状态机 + 降级层 + 法条体检），自动化改为调用它（改动大但一劳永逸，复用给周日批 / 月度回灌）。
- **方案 C（分批）**：先落 P0-1 + P0-2，P1 后续迭代。

你拍板方向，我落地。
