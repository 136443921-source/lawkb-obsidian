## 💰 华宇元典积分治理铁律（2026-09-01 确立，两轮试错后定稿）

> 完整台账见 `知识飞轮系统/运维/元典积分台账.md`。本节只记**方法论铁律**，数值以台账为准。

1. **⛔ 禁止用「单次调用前后余额差」推算单价**。元典为**异步延迟结算**，扣费在调用后 **5–15 分钟**内陆续落账，即刻读余额会**系统性低估**。（09-01 实测：即刻读得 6 分/次，真实值高一个数量级。）
2. **✅ 唯一可靠测价方法（五步）**：① 确认上批结算已完毕（**连读两次余额一致**）→ ② 记录基线 → ③ **批量调用 N 次，期间不得夹带其他调用** → ④ 静置 **≥3 分钟** → ⑤ 再连读两次确认稳定 → ⑥ 总量差 ÷ N。
3. **`top_k` 是 `rh_ptal_search` 的计费主杠杆**：`top_k=1`≈5 分/次 vs `top_k=5`≈46 分/次，**相差 9 倍**（返回体含 `ajjbqk_content`/`llm_content`/`content`/`highlight` 四个高度重复大字段，计费与返回字符量正相关）。**D 阶段一律 `top_k=1`**。
4. **🚨 外部消耗告警的判据必须三条件同时成立**：① 静置窗口前 **≥20 分钟**无任何元典调用（确保结算完毕）；② 静置 ≥10 分钟；③ 折算速率 > 3 分/分钟。**09-01 13:17 曾因违反条件①把延迟结算误判为外部消耗**，进而过度修正撤销了有效的单价记录——同一批滞后落账若恰好落在"静置观察窗"内，会被读成背景消耗。**此为本项目已发生的真实误报案例，勿重蹈。**
5. **接口优选**：已知法规名+条号 → `rh_ft_detail`（1–2 分）；**禁用** `rh_ft_search` 探路（7–10 分，且 0 命中仍计费）；查余额 `get_user_balance` **免费**，可放心高频调用。

## ⚖️ 法条「时代校正」铁律（2026-09-01 确立）

1. **凡引用司法解释，必须核对元典 `sxx` 字段与发布年份**，不得只看条号。已踩坑两处：① 法释〔2012〕8号《买卖合同解释》整体被**法释〔2020〕17号**取代，`sxx`=已被修改；② 《劳动争议司法解释（二）》命中 **2006 年旧版已失效**版本。
2. **司法解释条号重排 + 规则上升为法律，是民法典后的常态**。已实证：《买卖合同解释》旧第18条（检验期间过短）→ **《民法典》第622条**；旧第15条（签收送货单推定检验）→ **第623条**；旧第17条→现行第12条；旧第20条→现行第14条。❗**现行第18条已改为"逾期付款违约金"，与原第18条内容完全无关** —— 沿用旧号即**硬伤级错误**。
3. **法律条号亦随修正位移**：《慈善法》2023 修正把"用途变更须备案/征得同意"由**第55条移至第56条**（新第55条改为投资条款）。**检索历史判例必须新旧条号双检索式并用**（`yyft=…第五十五条` 与 `第五十六条`）。
4. **`yyft`（援引法条）检索显著优于 `qw`（全文关键词）**：`yyft` 按"中华人民共和国XX法第X条"中文条号精确检索。实证：`qw` 两轮检索 0–1 命中，`yyft` 一次即命中直接判例。
5. **被改判的一审说理只能作"书证"，不得作"适用判例"引用**。如（2020）京03民终5349号一审援引旧版慈善法第55条，但二审以"法不溯及既往"纠正其法律适用 → 该判决可作为**旧版条号与条文书证**，引用时须表述"依《慈善法》第56条……"，**不得**表述为"某某判决认为……"。

## 🆕 2026-08-30 新增经验

1. **`run.statute(law, article)` 条号必须传整数**：传字符串（`'1222'`）会静默返回 unknown 假阴性，误判为"未登记需核验"。
2. **zsh 会对 `**` 做 glob 展开**：含 markdown 加粗的 `python -c` 内联脚本会被破坏（报 "no matches found"）。含 `**` 的文本处理一律写成 .py 脚本文件再执行。
3. **A2.5 实时库校验须三维**：年度 + 口径 + **索引指向哪个文件**。08-30 年度无滞后却查出**口径误用**型 P0 错误（贵州丧葬费误用社保全口径 87,894→43,947，正确应为非私营在岗职工 106,570÷12×6=**53,285**，单项差 9,338 元）。
4. **同省份多文件并存时索引只挂一个是重大风险**：办案按索引进入即拿到滞后/错误值。索引须显式列出文件分工。
5. **`score_article()` 返回 `(分值, 命中词)` 元组**，取 `[0]`；直接对返回值取负数会报 `TypeError: bad operand type for unary -: 'tuple'`。
6. **ingested 集合混有 dict 与 str 两种类型**，且含 `web_publicsource_*` 格式——用 `split('_')[-1][:32]` 提取会产出「2026-08-06」这类垃圾 rawid（潜在误判源）。去重脚本须做类型兼容与格式校验。
