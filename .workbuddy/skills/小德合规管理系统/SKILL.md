## 一、六域框架（两子模板共用语言）

所有合规体检、制度搭建、纠纷处理统一映射到以下六域，确保慈善与医院两套知识体系可对话、可互哺：

| 域 | 含义 | 典型覆盖 |
|---|---|---|
| **制度** | 内部治理体系、章程、内控制度 | 章程/内规手册/关联交易制度/重大决策制度 |
| **流程** | 业务流程序列合规 | 常年顾问流程/募捐流程/采购流程/信息公开流程 |
| **运营** | 日常运营活动合规 | 项目执行/资产运营/医保基金使用/投资活动 |
| **财务** | 财务核算与资金管理 | 民间非营利会计制度/预算/募捐成本/设备药品采购付款 |
| **人资** | 劳动用工与人事 | 医护人员聘用/劳务派遣/薪酬/职称/纠纷 |
| **税务** | 税务合规与优惠 | 所得税/增值税/公益性捐赠税前扣除/税收优惠备案 |

> 子模板A 按《贵州省厚德公益基金会合规管理手册（试行）（2025版）》7 章 139 条 16 领域映射；子模板B 按医院法律顾问 8 章映射。两模板共享六域口径，差异仅在行业监管规则。

  └─ 否（纯合规/非诉问题）→ 按业务类型分发：
        │
        ├─ 慈善 / 基金会 / 公益 / 募捐 / 慈善信息公开
        │     → 子模板A：慈善组织合规与纠纷处理（小德慈善合规中枢）
        │
        ├─ 医院 / 医疗机构 / 卫健 / 医护人资 / 医保基金 / 设备药品采购
        │     → 子模板B：医院合规与纠纷处理
        │
        ├─ 合同合规审查（按合同属性分流，避免双系统重叠）
        │     ├─ 本行业合同（慈善捐赠/联合劝募 / 医院设备药品采购/医护聘用等）
        │     │     → 路由见子模板A（慈善）/子模板B（医院）各自「本行业合同」分支
        │     │       （先注入行业强监管规则，再统一转「合同文书管理系统」(L0) 路由至 A 合同审查）
        │     └─ 通用商事合同（股权转让/货物采购/租赁/服务协议/技术转让/承揽等，非慈善/医院专属）
        │           → 子模板C：合同合规审查专项
        │             （注入相应行业监管规则后做合规审查；**合同起草/文本生成归「合同文书管理系统(L0)」**，本专项只做审查）
        │
        ├─ 数据合规（个人信息/数据收集/跨境）
        │     → 转「数据合规审查」技能

        └─ 税务合规（增值税/所得税/税收优惠）
              → 转「税务合规审查」技能

## 五、输出前强制动作（legal-base 最高优先级）

任何文本输出前，调用 LTI 文本监控器（v4.8.0）：
- R 维度：法条真实性（条号越界/伪造 → REJECT）
- L 维度：法理逻辑
- C 维度：金额/名称一致性（C301 硬矛盾 → REJECT）
- T 维度：溯源
- P 维度：程序合规

未通过 LTI 校验的文本**绝不输出**。
